## 卡片约定

每张公开卡必须能单独被转发，并满足：

- What / Why / How：这张卡管什么
- When / When not：什么情况下不要用
- 数字可分清：`示例场景` 与论文 / 官方实测分开写
- 有出处：关键数字和机制能指到论文、官方文档或可复核的实现

以上合计 404 张，即首页「全部卡片」的计数口径。职业与认知 11 张是独立板块，不计入。

深度专题 = 专题指南 4 篇（TG01-04）+ Agent 框架案例 16 张 + 源码拆解 7 个（SR01-07），是主干之外的延伸阅读。

「上一卡 / 下一卡」按你进来的那条路径翻，而且一律不跨模块：从先学 20 进来只在当前分组内翻（5 组各自到头就停），从主干 42 进来只在当前链路内翻（理解 LLM / 做 RAG / 跑稳 Agent / 撑上线四条；卡 14、36 同时挂在两条链路上，靠链接里的 `g=` 记住你是从哪条进来的），从全部卡片进来只在当前模块组内翻。每组的第一张没有上一卡、最后一张没有下一卡。这对链接常驻在视口右边缘，是一条窄竖条：上一卡在上、下一卡在下，不压正文，宽屏窄屏都能点；手机和小平板竖屏（窄于 980px）正文末尾再补一份带进度和卡片标题的完整版，进度里带组名（如「先学 20 · 推理为什么又慢又贵 · 第 2 / 3 张」），宽屏有了竖条就不重复放。

从卡片点「⌂ 首页」回去，首页会停在你刚点进来的那个条目上并闪一下，不用从头再找。同一张卡在不同板块算不同位置（先学 20 里的第 3 张 ≠ 全部卡片里的 N03），靠链接里的 `f=` 记住；工程问题那 72 篇问答页不带 `f=`，走 sessionStorage + referrer 兜底，效果一样。

工程问题 72 篇是独立板块（模块 / 全链路 / Agent / RAG / LLM / 工程六组），在首页接在全部卡片之后、最新更新之前，不计入上面的卡片数。每篇是一组问答，不是单个知识点：挑一组当清单过一遍，卡住了再回去翻对应的卡片。

## 仓库结构

```
index.html             学习入口：先学 20 + 42 张主干 + 目标入口 + 完整目录 + 深度专题 + 工程问题
catalog.js             完整目录数据
card-nav.js            卡片内 prev/next 导航：顺序跟随入口且只在组内翻（?p=core20&g=model 走先学 20 的某一组，?p=main42&g=rag 走主干某条链路，无参数走全部卡片的组内顺序；?f= 是首页条目锚点，返回首页时回位高亮）；右边缘常驻竖条（宽屏）+ 正文末尾完整版（窄于 980px）
qa-catalog.js          工程问题目录数据（独立于 catalog.js）
LEARNING_PATH.md       先学 20 与主干 42 的编号、链接
cards/                 按主题存放，便于维护，不是阅读顺序
cards/interview/       工程问题页
notebooks/             手撕类最小可运行片段
```
