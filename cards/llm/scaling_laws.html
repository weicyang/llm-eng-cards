L06 · Scaling Laws

大模型的"物理定律" — 参数、数据、算力与性能的可预测关系

一、Scaling Laws 概述

Scaling Laws 说的是"损失随规模按幂律下降"。它真正的实用价值不在这句结论，而在幂律有一个性质：在双对数坐标下它是一条直线。于是几个小规模实验点就能外推出大规模的结果，预训练从赌博变成了预算规划。

为什么"可预测"这三个字值那么多钱：换个坐标，曲线变直线 ── 线性坐标下看：一条不知道往哪走的曲线 ────────────── loss ▲ 4.0│● │ ● 3.0│ ● │ ●● 2.0│ ●●● │ ●●●●●● 1.0│ ●●●●●●●●●●●●●● ? ← 会趋平？会继续降？降到哪？ └──────────────────────────────────────▶ 算力 C（线性刻度） 看起来"快要到极限了"，但这只是线性坐标造成的错觉 ── 双对数坐标下看：一条直线，斜率就是幂律指数 ────────── log(loss) ▲ │ ● │ ● L(C) = a · C^(−α) │ ● 取对数后： │ ● log L = log a − α · log C │ ● ⇒ 一条斜率为 −α 的直线 │ ● │ ● │ ● ● ● │ ╲ │ ╲ ← 用小规模的这几个点拟合出直线， │ ╲ 直接外推到目标算力 └──────────────────────────────▶ log(算力 C) ↑已测量↑ ↑外推区间↑ ───────────────────────────────────────────────────────── 三个变量各自都服从幂律，且形式一致： L(N) = (Nc / N)^αN 参数量 N ── 模型有多大 L(D) = (Dc / D)^αD 数据量 D ── 喂了多少 token L(C) = (Cc / C)^αC 算力 C ── 一共算了多少 FLOPs 三者不独立：C ≈ 6 · N · D 把它们锁在一起。 于是"给定算力预算，N 和 D 各取多少最优"就成了一个有唯一解的问题 —— 这正是第三、四节要回答的事。 实践中最常用的不是外推能力，而是外推着去做否决： 在小规模上比较两条拟合直线，就能在花掉主预算之前判断 某个数据配方或架构改动值不值得放大。

三大变量的角色对照

变量增大它直接买到什么成本形态现实中的天花板
参数量 N更强的表示能力与知识容量显存与推理开销都随之上升，且每次调用都要付受单卡显存与部署成本约束；对高频调用场景尤其敏感
数据量 D同一参数量下更充分的训练只在训练时付一次，不影响推理开销高质量文本的存量有限，即所谓数据墙
算力 CN 与 D 的乘积上限（C ≈ 6ND）直接的资金与能耗支出预算、集群规模、供电与散热
推理时算力（第二个旋钮）同一模型上更高的准确率按调用次数与题目难度浮动延迟预算；对简单问题增益趋近于零

Scaling Law（缩放定律）描述的是深度学习模型性能（通常以 loss 衡量）与三大核心要素之间的幂律关系（power law）：

  • N — 模型参数量（Parameters）
  • D — 训练数据量（Dataset size, tokens）
  • C — 训练算力（Compute, FLOPs）
L(x) = a · x−α + L∞
其中 x 可以是 N、D 或 C，α 为正指数，L∞ 是不可约损失（irreducible loss）。当 x 增大，Loss 按幂律平滑下降。

背景：2020 年前的"加大有没有用"之争

2020 年之前，业界对"模型加大有没有用"存在分歧：一派认为参数加多了总会饱和，另一派主张"先加大试试"，双方都只有经验直觉、没有量化证据。Kaplan 的研究用三个发现终结了这场争论：

  • 投入产出可预测：给定算力可以提前算出最终 loss——这给了大公司投入数千万美元训练大模型的底气
  • 未见饱和点：规模一直加大到当时能训的极限，loss 仍按幂律下降，没有"再加就不动"的拐点
  • 三变量可独立分析：N、D、C 可以分别回答"加倍能降多少 loss"，为后来 Chinchilla 的联立优化打下基础

为什么可预测？

  • 在对数-对数坐标下，性能几乎呈线性下降——这是幂律的特征
  • 该关系在多个数量级（从百万到万亿参数）中保持稳定，不受模型架构细节（层数/宽度比）影响
  • 这意味着：可以用小规模实验外推大模型的最终性能，极大降低试错成本

三大变量的独立与耦合

Scaling Law 的核心发现：N、D、C 三者各自独立地影响 loss，但在固定预算下存在最优分配问题——这正是 Kaplan 与 Chinchilla 两大路线争论的焦点。

知识要点
  • Scaling Law 是幂律（power law），不是指数或线性关系
  • Loss 在对数坐标下与 N、D、C 呈近似线性关系
  • 核心价值：可预测性——小模型实验可推测大模型表现
  • 不可约损失 L∞ 反映数据本身的熵下界

二、Kaplan Scaling Law（OpenAI 2020）

这一版结论倾向于"优先把参数堆大、数据可以少给"。它后来被证明是被实验设置误导的：学习率调度没有随训练长度重新调整，导致"小模型多训"这条路线的收益被系统性低估——一个超参数细节，改写了整个行业两年的资源分配。

Scaling Laws for Neural Language Models

2020 年 OpenAI 的 Jared Kaplan 等人发表了开创性论文，首次系统化地描述了语言模型的 scaling 行为。

核心公式

L(N) ≈ (Nc / N)αN ，αN ≈ 0.076
L(D) ≈ (Dc / D)αD ，αD ≈ 0.095
L(C) ≈ (Cc / C)αC ，αC ≈ 0.050
Loss 随 N、D、C 各自按幂律下降，但指数不同。αN > αC 意味着增加参数比增加算力更高效。

参数量优先策略

Kaplan 的关键结论：在固定计算预算 C 下，应优先增大模型（N）而非增加数据量（D）。具体而言：

  • 当 C 增加 10x 时，N 应增加约 5.5x，D 仅需增加约 1.8x
  • 这意味着大模型不需要在海量数据上训练很久——用少量 epoch 的大模型优于小模型长时间训练
  • 结果导致了 GPT-3（175B 参数，300B tokens）的训练策略——模型大、数据相对少

固定预算下的最优分配

给定 FLOPs 预算 C ≈ 6ND（前向+反向），Kaplan 建议 N 的增长速度远快于 D：

Nopt ∝ C0.73 ，Dopt ∝ C0.27
即计算量翻倍时，约 73% 的"增量"应分配给增大参数，仅 27% 分配给增大数据。
知识要点
  • Kaplan 主张"参数优先"：固定预算下应尽量做大模型
  • αN ≈ 0.076 的含义：参数量每翻 10 倍，loss 下降约 0.076（对数尺度）
  • GPT-3 的训练策略就是 Kaplan Scaling Law 的实践产物
  • 后来被 Chinchilla 推翻：Kaplan 的数据采样策略导致低估了数据的重要性

三、Chinchilla Scaling Law（DeepMind 2022）

修正只有一句话：参数和数据要等比例一起长。按旧结论训出来的那批大模型不是"造得太大"，而是"喂得太少"——同样的算力，换成小一点的模型多训一些 token，效果反而更好。

Training Compute-Optimal Large Language Models

2022 年 DeepMind 的 Hoffmann 等人通过 400+ 次实验，对 Kaplan 的结论提出了根本性修正。

核心发现：参数与数据应等比例缩放

Nopt ∝ C0.50 ，Dopt ∝ C0.50
与 Kaplan 的 0.73/0.27 分配完全不同——Chinchilla 认为参数和数据应同步等比例增长。

为什么推翻了 Kaplan？

  • Kaplan 实验中未充分控制 learning rate schedule，导致大数据量的实验未被充分优化
  • Kaplan 使用了固定的训练步数（而非固定 tokens），低估了数据量增加的收益
  • 修正方法论后，数据量的边际收益与参数量几乎相等

Chinchilla 70B 的胜利

模型参数量训练 TokensFLOPs结果
Gopher280B300B≈ 5.0 × 10²³基线
Chinchilla70B1.4T≈ 5.0 × 10²³全面优于 Gopher

使用相同算力，Chinchilla 将模型缩小到 1/4，数据量增大到近 5 倍，性能反而全面超越 Gopher。这直接证明了 Kaplan 的"大模型优先"策略并非最优。

反向验证：GPT-3 的"严重欠训"

用 1:20 标尺回头看，当时几乎所有大模型都欠训，最典型的是 GPT-3：

GPT-3 实际配比：175B 参数 / 300B tokens = 1 : 1.7
Chinchilla 最优配比：1 : 20 → 数据缺口约 12 倍
按 Chinchilla，GPT-3 的参数量应配约 3.5T tokens，实际只用了 300B，差了一个数量级。这也回答了"越大越好错在哪"——它忽略了数据量这个关键变量。

Compute-Optimal Training

Chinchilla 的核心概念：对于给定 FLOPs 预算，存在唯一的 compute-optimal（计算最优）配置。偏离该配置——无论是模型过大还是数据过多——都会浪费算力。

知识要点
  • Chinchilla 结论：N 和 D 应同步等比例增长，而非 Kaplan 的参数优先
  • 经验法则：最优训练 token 数 ≈ 20 × 参数量
  • 用相同算力，70B + 1.4T tokens 优于 280B + 300B tokens
  • Kaplan 被推翻的原因：实验方法论缺陷（学习率调度、训练步数控制）
  • Chinchilla 之后，业界普遍转向"数据优先"路线

四、数据-参数-算力最优配比

20:1 是一个关于训练算力的最优比，不是关于总成本的最优比。如果模型要被调用几十亿次，把它训得比最优点更小、更久，用一次性的训练开销去换每次都要付的推理开销，总账反而更划算——这就是过训练成为主流做法的原因。

IsoFLOP 曲线：固定算力预算，为什么存在唯一的最优参数量 在算力 C 固定的约束下（C ≈ 6ND，所以 N 变大 D 必然变小）， 把最终 loss 对参数量 N 作图，得到一条 U 形曲线： 最终 loss ▲ │ ● ● │ ╲ ╱ │ ● ● │ ╲ ╱ │ ● ● │ ╲ ╱ │ ● ● │ ╲ ╱ │ ● ● │ ╲___ ___╱ │ ●●___ ___●● │ ●●●●●●●●●●● │ ▲ │ └── 计算最优点 N* └────────────────────────────────────────────────────▶ log N ← 模型太小 ──────────────────── 模型太大 → 参数不足，容量成为瓶颈： 参数够了但 D 被挤小： 数据再多也学不进去 token 不够，严重欠训 （左半边"喂得太饱、脑子太小"） （右半边"脑子够大、没喂饱"） ───────────────────────────────────────────────────────── 把不同算力预算的 U 形曲线画在一起，各自的最低点连成一条线： 最终 loss ▲ │ ╲___╱ ← C₁（最小预算） │ ● │ ╲___╱ ← C₂ │ ● │ ╲___╱ ← C₃ │ ● │ ╲___╱ ← C₄（最大预算） │ ● │ ╲ │ ● ← 各最低点的连线， └────────────────────────────▶ log N 斜率给出 N* 随 C 的增长率 拟合结果：N* 与 D* 大致按同样的速率随算力增长 ⇒ 两者之比近似恒定 ⇒ D* ≈ 20 · N* ───────────────────────────────────────────────────────── 这张图的两个用法： 正着用（训练最优）：给定算力 C ─▶ 读出 N*、D* ─▶ 照此配置去训 反着用（总成本最优）：把 N 刻意选在 N* 左侧 ⇒ 训练算力变多（离开了最低点，loss 略差） ⇒ 但推理开销永久变小 调用量越大，这个偏离就越值得。 注意 U 形底部相当平坦：在 N* 附近偏离一定倍数， loss 的代价其实很小 —— 这正是"过训练"在工程上可行的前提。
示例场景：为高频在线调用刻意偏离最优点。背景——某团队要训一个长期承载海量在线调用的模型，算力预算已经定下。问题——按 20:1 的训练最优比算出来的参数规模，虽然让训练算力用得最省，但推理开销是由参数量决定的、而且每一次调用都要重付一遍。按预期调用量粗算，几十亿次调用累积起来的推理成本，会远远超过训练本身的一次性投入——也就是说，在"训练最优"这个点上省下的钱，会在推理侧成倍还回去。方案——改成对总拥有成本做优化：把参数量压到最优点的一半以下，用远超 20:1 的 token 量（几十倍量级）把这个更小的模型一直训到收益明显递减为止。之所以可行，是因为 IsoFLOP 曲线在最优点附近相当平坦，偏离一定倍数带来的 loss 代价很小。效果——单次推理的算力和显存开销大幅下降，模型质量与最优点配置接近；训练算力确实多花了，但在预期调用量下总成本明显更低，而且更小的模型还顺带降低了部署门槛。要点：Chinchilla 最优点是关于训练算力的最优，不是关于总拥有成本的最优；调用量越大，越应该往"更小、更久"的方向偏。

D ≈ 20 × N 经验法则

Chinchilla 的实验结果给出了广泛引用的经验法则：

Dopt ≈ 20 × N
即训练一个 10B 参数模型，最优数据量约为 200B tokens。训练 70B 模型，最优数据量约 1.4T tokens。

给定 FLOPs 预算的分配

利用 C ≈ 6ND 近似公式：

  • 已知预算 C → 最优 N ≈ √(C / 120)，最优 D ≈ 20 × N
  • 例：C = 10²⁴ FLOPs → N ≈ 91B → D ≈ 1.8T tokens

实际训练中的偏离：LLaMA 过训练策略

实际中，企业往往有意偏离计算最优点：

模型参数量训练 TokensD/N 比偏离程度
Chinchilla 最优70B1.4T20x基准

为什么要过训练？

  • 推理成本：小模型推理便宜，即使训练时多花算力（过训练），长期推理节省更多
  • 部署约束：移动端/边缘设备需要小模型，但性能不能太差
  • Inference-Optimal vs Compute-Optimal：当推理需求远大于训练成本时，过训练小模型经济上更合理
  • Meta 在 LLaMA-3 论文中明确提出：关注的是给定推理预算下的最优模型，而非给定训练预算

"小参数 + 海量数据"的事实与动因

  • 标志性事实：Llama 3 8B（15T tokens）在多项基准上超过 GPT-3 175B——参数量只有其 1/22 的小模型靠数据规模取胜
  • 推理成本：8B 模型一台消费级 GPU 即可部署，175B 需要多台 H100，成本天差地别
  • 数据相对便宜：GPU 集群是真金白银（单张 H100 约 3 万美元），数据清洗虽也花钱但相对便宜——算力受限时，把算力花在"喂更多数据"比"堆更多参数"更划算
  • 注意：Chinchilla 的 1:20 是"固定训练算力下的 compute-optimal 配比"，不是"数据再多也没用"的上限——继续喂高质量 token，loss 仍会下降，只是边际收益变小
知识要点
  • D ≈ 20N 是 Chinchilla 的经验法则，但实践中常被大幅偏离
  • LLaMA 系列有意"过训练"小模型（D >> 20N），目的是降低推理成本
  • 区分 Compute-Optimal（训练最优）与 Inference-Optimal（推理最优）
  • C ≈ 6ND 是前向+反向计算量的粗略估计

五、涌现能力（Emergent Abilities）

涌现能力的争论焦点不在能力本身，而在度量方式。用"完全答对才给分"这种阶跃式指标看，能力像是突然出现；换成连续指标看，同一条曲线是平滑上升的——所以"是否存在涌现"很大程度上取决于你拿什么尺子量。

同一个模型能力的成长过程，两把尺子量出两种形状 比如任务是"算出一道 4 位数乘法"，答案必须完全正确才算对。 ── 尺子 A：精确匹配准确率（阶跃式指标）─────────────── 准确率 ▲ 60%│ ●●●● │ ●●● 40%│ ●● │ ●● 20%│ ● │ ● 0%│●───●───●───●───●───●───● └────────────────────────────────────────▶ log(规模) └──── 看起来完全没有进展 ────┘└── 突然"涌现" ──┘ ── 尺子 B：逐位正确率 / 答案的对数似然（连续指标）─────── 逐位 正确率 ▲ 90%│ ●●●●● │ ●●●●● 70%│ ●●●●● │ ●●●●● 50%│ ●●●●● │ ●●●●● 30%│●●●●● └────────────────────────────────────────▶ log(规模) └──────── 一路平滑上升，没有任何跳变 ────────┘ ───────────────────────────────────────────────────────── 两把尺子并不矛盾，把它们对起来看就明白了： 规模小时：每位数字有 30% 概率对 ⇒ 4 位全对的概率 ≈ 0.3⁴ ≈ 1% ⇒ 精确匹配几乎为 0 规模大时：每位数字有 90% 概率对 ⇒ 4 位全对的概率 ≈ 0.9⁴ ≈ 66% ⇒ 精确匹配"突然"很高 底层能力是线性爬升的，而"全对"这个要求把它取了四次方， 再加上阈值裁断 ⇒ 于是在图上表现成一条阶跃曲线。 ───────────────────────────────────────────────────────── 这个分析留下的实际结论： · 阶跃形状主要来自指标的非线性，而非模型内部发生了相变 · 但"某个规模之前该任务实际不可用"这件事是真的， 对选型和产品决策依然成立 · 因此评测设计上应同时保留连续指标 ── 否则在跨过阈值之前，你完全看不到自己有没有在进步
Emergent Abilities of Large Language Models

什么是涌现？

涌现能力（Emergent Abilities）指的是在小模型中完全不存在、但当模型规模超过某一阈值后突然出现的能力。这与 Scaling Law 的"平滑幂律"形成鲜明对比——涌现呈现出相变（phase transition）特征。

"An ability is emergent if it is not present in smaller models but is present in larger models." — Jason Wei et al., 2022

典型涌现任务

  • Chain-of-Thought (CoT) 推理：模型在 ~100B 参数后才能有效执行多步推理
  • In-Context Learning (ICL)：Few-shot 能力在大模型中才显著
  • 多步算术：三位数加法在 ~50B 参数后准确率突然从近零跳升
  • Word Unscrambling：字母重排解谜在 ~60B+ 出现
  • 代码生成：复杂编程任务需要足够规模才能完成

涌现的具体数据点

  • 多步算术（PaLM）：5 步算术应用题准确率——8B 约 0%，62B 约 5%，540B 约 60%，从"完全不会"直接跳到"会一大半"，中间没有渐进过程
  • In-Context Learning：GPT-2（1.5B）完全没有 few-shot 学习能力，GPT-3（175B）突然出现，临界点在 100B 左右
  • 跨语言泛化：GPT-3 训练数据 92% 是英文，却能直接处理中文、阿拉伯语等从未被显式教过的语言——跨语言对应关系靠大规模混合语料自己学会，100B 之后才稳定出现

涌现的临界规模集中在 50B-100B 区间。一个流行解释：模型大到一定程度，注意力头数与隐藏维度才达到"能编码复杂推理结构"的最低门槛。

涌现是否真实存在？——度量假说之争

2023 年 Schaeffer 等人发表了一篇极具争议的论文，挑战涌现的真实性：

观点核心论点代表人物
涌现真实存在某些能力确实在阈值处突然出现，反映了模型内部表示的质变Jason Wei (Google)
度量假说涌现是度量选择的产物——使用非线性/离散指标（如 exact match）会人为制造阶跃；换用线性指标（如 Brier score）则涌现消失，呈平滑提升Schaeffer et al. (Stanford)

最典型的例子是多步算术：exact match 指标下"答错任何一步即 0 分"，看到的是"小模型一直 0 分、大模型突然跳到 60%"的涌现曲线；换成部分得分指标（答对 5 步中的 4 步记 0.8 分），同样的实验数据立刻变成平滑的对数曲线，突变消失。

当前共识

  • 涌现至少部分取决于度量方式——离散指标（对/错）容易产生阶跃效应
  • 但某些任务的质变可能是真实的——模型可能确实需要"足够的内部容量"来组合多个子技能
  • 即使涌现可被解释为度量偏差，也不影响实际应用中的事实：小模型就是做不了的事，大模型能做
  • 不存在统一的"魔法涌现规模"——不同任务的临界点有早有晚，"100B 之后必然涌现"的说法不成立
知识要点
  • 涌现能力与 Scaling Law 的核心区别：幂律是平滑的，涌现是阶跃的
  • 典型涌现任务：CoT、ICL、多步算术
  • 度量假说：涌现可能是 exact match 等离散指标的产物
  • 需要展示辩证思维——承认争议，但也指出实践意义

六、Inference-time Scaling

推理时扩展打开了第二个旋钮：以前想提高准确率只能回去改训练，现在可以在推理时多花 token 去换。代价是延迟上升、且成本随题目难度浮动——从"固定单价"变成了"按难度计费"，这对容量规划的影响比对准确率的影响更大。

o1 / o3 · Test-time Compute

核心思路

传统 Scaling Law 关注训练时的资源投入（参数、数据、FLOPs）。Inference-time Scaling 则提出一个互补视角：在推理阶段投入更多计算，同样可以提升模型表现。

更多推理时间（思考步骤） → 更好的结果质量
这不是简单地重复采样，而是让模型进行深度思考——分解问题、自我验证、回溯修正。

o1/o3 的实践

  • Chain-of-Thought at Scale：o1 在回答前进行长时间的内部推理（hidden chain-of-thought），可能生成数千 tokens 的思考过程
  • 自我反思与验证：模型在推理中自我检查，发现错误后回溯重试
  • 动态计算分配：简单问题用少量思考，复杂问题用大量思考——难题获得更多推理资源
  • Test-time Compute 可调：可以通过控制推理预算（思考时间/tokens）在速度和质量间权衡

训练时 Scaling vs 推理时 Scaling

维度训练时 Scaling推理时 Scaling
资源投入时间训练阶段（一次性）每次推理（持续性）
主要手段增大 N、D、C增加思考步骤、采样次数
成本结构前期投入大，推理边际成本低每次推理都有额外成本
适用场景通用能力提升复杂推理/数学/编程
代表模型GPT-4, LLaMAo1, o3, DeepSeek-R1
收益模式幂律（power law）Log-linear 或类似幂律

Test-time Compute 的关键技术

  • Best-of-N 采样：生成 N 个回答，用验证器（reward model）选最佳——最朴素的推理时 scaling
  • Process Reward Model (PRM)：对推理的每个步骤打分，而非只看最终结果
  • MCTS / Tree Search：将推理视为搜索问题，用树搜索探索不同推理路径
  • RL-trained Reasoning：通过 RL（如 GRPO）训练模型学会何时深入思考、何时停止
知识要点
  • Inference-time Scaling 是训练时 Scaling 的互补而非替代
  • o1 的核心机制：hidden CoT + 自我验证 + 动态计算分配
  • Test-time Compute 适合可验证的任务（数学、编程）——因为可以检查答案正确性
  • 两者可以结合：大模型 + 大量推理时间 = 当前最强性能

七、Scaling 的实践意义

Scaling Laws 在工程上最有用的不是"预测最终能力"，而是"提前否决方案"：在花掉主预算之前，用几组小规模实验就能判断某个数据配方或架构改动值不值得放大。它把不可逆的赌注，变成了可以分期验证的决策。

示例场景：用不到 2% 的预算否决了一份数据配方。背景——某团队准备用一份新设计的数据配比去训一个较大的模型，主预算相当可观。新配方在直觉上更合理：提高了代码与教材类语料的占比。问题——开跑之前没人能判断它到底比现行配方好还是差，而按常规做法"训完再看"，一旦不行就是整笔预算打水漂，而且这种失败无法拆开归因——你不知道是配方的问题还是超参的问题。方案——按 Scaling Laws 的标准做法做小规模对照：在比目标小三个数量级的算力上，训四个规模递增的小模型，新旧两份配方各训一遍共八次；每次都按各自的训练长度重新调学习率调度（这一步是关键，早年正是它被忽略才导致了结论偏差）；最后把最终 loss 对算力做双对数拟合，比较两条直线的斜率和截距。效果——新配方的截距略低，也就是在小规模上确实更好看；但它的斜率明显更平，外推到目标算力时两条线交叉，新配方反而落后。于是在主预算动用之前就把它否决了，整个验证只花掉不到 2% 的算力预算。这里最容易被忽略的一点：小规模上的领先不等于大规模上的领先，要看的是斜率而不是单点分数——只测一个规模，得到的结论可能刚好是反的。
  • 做规模对照实验时至少取四个规模点，看拟合直线的斜率而不是单点分数
  • 每个规模点都按自己的训练长度重新调学习率调度，否则结论会系统性偏斜
  • 把 loss 曲线画在双对数坐标下审视，幂律偏离在这里最容易看出来
  • 评测同时保留连续指标与阈值指标，前者才能看出跨阈值之前的进展
  • 为高频调用场景刻意往"更小、更久"偏离最优点，按总成本而非训练算力优化
  • 用小规模实验先否决明显不行的方案，把主预算留给已经验证过的配方
  • 报告规模结论时把算力、token 数、参数量三者一并给出，缺一项就无法复现
  • 不要在单一规模上比较两个方案，小规模的领先可能在大规模上反转
  • 不要把 20:1 当成普适配置，它只是训练算力最优，不含推理成本
  • 不要在线性坐标下判断"是否已经到达极限"，那几乎总是错觉
  • 不要只用精确匹配类指标追踪能力成长，跨阈值之前它一直是零
  • 不要把"涌现"当作模型内部发生相变的证据，先检查指标是否连续
  • 不要在不同规模的对照实验里沿用同一套超参，尤其是学习率调度
  • 不要假设幂律可以无限外推，数据质量与数据存量都会先撞墙

小规模实验预测大模型性能

Scaling Law 最重要的实践价值在于可预测性：

  • 训练一系列小模型（如 1M → 10M → 100M → 1B 参数），在 log-log 图上拟合趋势线
  • 外推到目标规模（如 100B），获得 loss 的可靠预估
  • OpenAI 声称 GPT-4 的性能在训练前就已被小模型实验准确预测

训练前的 Loss 预测

  • 确定目标 loss → 反推所需 N、D、C → 估算硬件/时间/预算
  • 例：目标 loss = 2.5 → 需要 ~30B 参数，~600B tokens，~10²² FLOPs → ~256 A100 训练 3 天
  • 这使得大模型训练从"试错实验"变为工程规划

预算规划

  • 硬件采购：根据 Scaling Law 预测所需 GPU 数量和训练时间
  • 数据准备：根据 Dopt 决定需要多少高质量数据
  • 模型架构选择：Scaling Law 表明架构细节影响小（常数项），规模才是决定性因素
  • 风险评估：如果小规模实验的趋势线斜率不理想，可以在投入大算力之前及时调整策略

模型选型的门槛指导

  • 任务依赖涌现能力（多步推理、ICL、跨语言迁移）：最低门槛在 30B-70B 量级，再往下基本不行
  • 简单分类、抽取、摘要任务：7B-13B 完全够用，没必要硬上大模型
  • 算力有限时的分配直觉：与其训 7B + 100B tokens，不如训 3B + 250B tokens——同等算力开销下后者效果通常更好，推理还便宜
  • 选型三问：这个模型训练充分吗？数据质量如何？它是为训练算力最优设计，还是为推理成本最优设计？
知识要点
  • 核心实践价值：用小模型预测大模型——在 log-log 图上线性外推
  • GPT-4 的"可预测性"声明：训练前就预测了最终 loss
  • Scaling Law 使大模型训练变为可规划的工程问题
  • 架构细节影响常数项，规模影响指数项——规模更重要

八、Scaling 的局限

三堵墙同时在逼近：高质量文本的存量快用完了，能耗与成本非线性上升，同样幅度的 loss 下降要付出越来越多的算力。这也解释了近年的重心为什么从"堆得更大"转向"训得更巧、想得更久"。

四类局限与当前对策

局限具体表现当前主要对策残留风险
数据墙高质量文本存量有限，配比调整能腾出的空间越来越小提高筛选精度、用合成数据补分布缺口、扩展到多模态与代码等新语料合成数据反复迭代会收窄分布；新模态的质量评估体系还不成熟
收益递减幂律意味着每降低同样一点 loss，需要的算力成指数增长把投入转向后训练、推理时扩展、以及架构效率这些方向各自也有上限，且收益不像预训练那样可预测
能耗与成本集群规模、供电与散热成为实际约束，而非单纯的资金问题更高效的低精度训练、稀疏激活、提高算力利用率效率提升的空间有限，抵不过规模的指数需求
规律的适用边界在偏好对齐、强化学习、多模态上，幂律的形式与稳定性都不如预训练在各自领域重新拟合各自的规模曲线，不照搬预训练的结论这些领域的评测噪声大，拟合出的曲线可靠性更低

数据墙（Data Wall）

  • 互联网上的高质量公开文本总量有限——估计约 10-50T tokens（其中高质量英文文本约 10-15T）
  • 消耗速度：Llama 3 已用 15T，Qwen3 已用 36T——照此趋势，几年内人类历史上的公开文本就会被用完
  • 应对策略：合成数据（DeepSeek-Math、Qwen2.5-Math 都大量使用）、多模态数据（图像/视频/音频）、强化学习交互数据（DeepSeek-R1 的 RL 训练即此类）、代码与多语言数据
  • 但合成数据存在 model collapse 风险——模型训练在自身输出上会退化

能耗与成本

  • GPT-4 训练估计花费 ~1 亿美元，未来模型可能达到 10 亿美元级别
  • 能源消耗巨大，引发环保和可持续性讨论
  • 算力增长放缓：摩尔定律接近物理极限，能负担 10 万张 H100 级集群的玩家屈指可数，继续堆参数的边际成本越来越高（"算力墙"）
  • Scaling Law 的幂律特性意味着边际收益递减：loss 降低一半可能需要 ~1000x 算力

收益递减

要将 loss 从 3.0 降到 2.8（Δ=0.2）很便宜
要将 loss 从 2.2 降到 2.0（Δ=0.2）极其昂贵
幂律意味着每个等量的 loss 降低需要指数级增长的资源——这是 Scaling 路线的根本局限。

多模态/RL 的 Scaling 是否适用？

  • 视觉模型：已有研究表明 ViT 等模型也遵循类似 Scaling Law，但指数不同
  • 多模态：文本+图像的联合 Scaling 行为更复杂，目前缺乏统一的 Scaling Law
  • 强化学习：RL 的 Scaling 行为高度依赖奖励函数设计，不如语言模型的 Scaling 稳定
  • RLHF：对齐训练的 Scaling 行为尚无系统研究，可能存在"对齐税"（alignment tax）
  • Agent / Tool-use：涉及外部工具的任务，Scaling 行为可能与纯语言任务不同

Scaling 之外的方向

  • 架构创新：Mixture of Experts (MoE)、State Space Models（Mamba）等尝试打破 dense Transformer 的 Scaling 瓶颈
  • 数据质量 > 数量：Phi 系列证明高质量小数据集可以部分弥补规模不足
  • 推理时 Scaling：如第 6 节所述，在推理阶段投入计算是一条新路线
知识要点
  • 数据墙：高质量数据即将耗尽，合成数据是应对方案但有 model collapse 风险
  • 幂律 = 边际收益递减——Scaling 不可能无限持续
  • 多模态和 RL 的 Scaling 行为不如纯语言模型清晰
  • Scaling 之外还有架构创新、数据质量、推理时 Scaling 等方向

✦Q&A（10 题）

Q1：什么是 Scaling Law？它为什么重要？

Scaling Law 描述的是语言模型的 loss 与参数量 N、数据量 D、算力 C 之间的幂律关系：L(x) ∝ x−α。在对数坐标下，这三个变量各自与 loss 呈近似线性关系。

其重要性在于可预测性：可以通过训练一系列小模型，在 log-log 图上拟合趋势线，外推预测大模型的最终性能。这使得大模型训练从试错实验变为可规划的工程问题，帮助团队在投入数千万美元之前评估项目可行性。

Q2：Kaplan Scaling Law 和 Chinchilla Scaling Law 的核心区别是什么？

Kaplan（2020）认为在固定计算预算下，应优先增大模型参数量，Nopt ∝ C0.73，Dopt ∝ C0.27——即大部分预算应分配给增大模型。

Chinchilla（2022）推翻了这一结论，认为参数和数据应等比例缩放，Nopt ∝ C0.50，Dopt ∝ C0.50。经验法则为 D ≈ 20N。

Chinchilla 用 70B 参数 + 1.4T tokens（与 Gopher 280B + 300B tokens 同等算力）取得了更优性能，直接证明了数据的重要性被 Kaplan 低估。Kaplan 被推翻的技术原因是其实验未充分控制学习率调度和训练步数。

Q3：为什么 LLaMA 等模型会故意偏离 Chinchilla 最优配比？

Chinchilla 最优是训练成本最优（compute-optimal），但实践中更关注推理成本最优（inference-optimal）。原因包括：

  • 小模型的推理成本远低于大模型——在部署中每天处理数百万请求时，这个差距巨大
  • "过训练"小模型（用远超 20N 的 token）虽然训练效率不是最优，但训练成本是一次性的，推理成本是持续性的
  • LLaMA-3 8B 用 15T tokens（D/N ≈ 1875x），远超 Chinchilla 建议的 20x，在多项基准上超过 GPT-3 175B；Qwen3-0.6B 更推到 36T tokens（D/N ≈ 60000x）

总结：当推理量远大于训练量时，投入更多训练算力来获得更小但更强的模型是经济上合理的。Chinchilla 的 1:20 回答的是"固定训练算力怎么分配"，不是"数据喂到头了"。

Q4：什么是涌现能力？它与 Scaling Law 是什么关系？

涌现能力是指在小模型中完全不存在、但当模型规模超过某一阈值后突然出现的能力（如 CoT 推理、复杂算术）。这与 Scaling Law 的平滑幂律下降形成对比——涌现呈阶跃/相变特征。

两者的关系：Scaling Law 描述的是 loss（连续指标）的平滑变化，而涌现通常出现在下游任务的离散指标（如 exact match 准确率）上。Loss 可能平滑下降，但任务表现在某个阈值处突然从"不会"变为"会"。

不过，也有学者（Schaeffer 等人）认为涌现只是度量选择的产物——换用连续指标后涌现消失。这仍有争议。

Q5：涌现能力是否真的存在？请阐述两方观点。

支持涌现（Jason Wei 等人）：

  • 多个任务在不同模型家族中都表现出相同的阈值效应，不太可能是巧合
  • 某些复杂任务确实需要模型具备足够的内部容量来组合多个子技能
  • 即使度量方式有影响，也不能否认小模型无法完成而大模型能完成的客观事实

反对涌现（Schaeffer 等人，度量假说）：

  • 使用非线性/离散指标（如 exact match）会人为制造阶跃效应
  • 换用连续指标（如 Brier score、token-level accuracy），涌现消失，呈平滑提升
  • 涌现可能只是统计学上的"分辨率不足"——小模型已有微弱能力，只是被离散指标忽略了

应答建议：展示辩证思维，承认两方都有道理，强调实际影响不变（某些任务确实需要大模型）。

Q6：什么是 Inference-time Scaling？与训练时 Scaling 有何不同？

Inference-time Scaling（推理时缩放）指在推理阶段投入更多计算来提升模型表现，代表模型是 OpenAI 的 o1/o3 系列。核心机制包括：

  • 让模型在回答前进行长时间的内部推理（hidden chain-of-thought）
  • 自我验证和回溯修正
  • 动态分配推理资源——简单问题快速回答，复杂问题深入思考

与训练时 Scaling 的关键区别：训练时 Scaling 是一次性投入（训练完成后固定），推理时 Scaling 是每次推理都有额外成本。两者是互补关系——大模型 + 充足推理时间 = 当前最强。推理时 Scaling 更适合可验证的任务（数学、编程），因为模型可以检查自己的答案。

Q7：C ≈ 6ND 这个公式是怎么来的？

C ≈ 6ND 是 Transformer 训练 FLOPs 的近似估算：

  • 前向传播：每个 token 经过 N 个参数的矩阵运算，约 2N FLOPs（乘法+加法）
  • 反向传播：梯度计算约是前向的 2 倍，即 4N FLOPs
  • 总计：每个 token 约 6N FLOPs → 训练 D 个 token → C ≈ 6ND

这是一个粗略估计，忽略了 attention 的二次复杂度（序列长度影响）、embedding 层、LayerNorm 等。但在数量级上足够准确，是业界广泛使用的"背后信封计算"。

Q8：数据墙（Data Wall）问题是什么？有哪些应对方案？

数据墙指的是互联网上可用的高质量文本数据总量有限（估计 ~10-15T tokens 英文文本）。随着模型规模增大，按 Chinchilla 法则所需的训练数据量也同步增长，即将触及数据供应上限。

应对方案：

  • 合成数据（Synthetic Data）：用强模型生成数据训弱模型（DeepSeek-Math、Qwen2.5-Math 大量使用），但有 model collapse 风险
  • 强化学习交互数据：用环境交互生成训练数据，DeepSeek-R1 的 RL 训练即属此类
  • 数据质量优先：如 Phi 系列，精选高质量数据弥补规模不足
  • 多模态数据：利用图像、视频、音频等非文本数据
  • 数据增强：改写、翻译、格式变换等技术
  • 多语言数据：利用非英语语言数据扩大总量
  • 过训练策略：多 epoch 训练（但收益递减）
Q9：如何用 Scaling Law 做训练前的预算规划？

步骤如下：

  1. 确定目标 loss：基于下游任务需求，确定需要达到的 cross-entropy loss
  2. 训练小模型序列：训练 10M、50M、200M、1B 等规模的模型，记录各自的最终 loss
  3. 拟合 Scaling Law：在 log-log 图上拟合 L(N) = aN−α + L∞，得到参数 a、α、L∞
  4. 外推到目标规模：反推达到目标 loss 所需的参数量 N
  5. 计算数据和算力需求：D ≈ 20N（Chinchilla），C ≈ 6ND
  6. 转换为硬件需求：C / (GPU峰值FLOPs × MFU × 训练时长) = 所需 GPU 数量

例如：目标 N=30B，D=600B → C ≈ 1.08×10²³ FLOPs。A100 峰值 312 TFLOPS，MFU ≈ 40% → 每 GPU 约 125 TFLOPS → 需要 256 A100 训练约 3.5 天。

Q10：Scaling Law 有哪些已知的局限性？未来可能被什么打破？

已知局限：

  • 幂律 = 收益递减：每降低相同的 loss 需要指数级增加的资源
  • 数据墙：高质量训练数据即将耗尽
  • 成本与能耗：训练成本可能达到数十亿美元，引发可持续性问题
  • 不适用于所有模态：多模态、RL 的 Scaling 行为不如纯语言模型清晰
  • 下游任务不可预测：Scaling Law 预测 loss，但 loss 与具体任务表现的映射不总是线性的

可能打破 Scaling 局限的方向：

  • MoE 架构：稀疏激活使有效参数量远小于总参数量，改变 Scaling 曲线
  • 推理时 Scaling：在推理阶段投入计算，开辟新的 Scaling 维度
  • 算法突破：新架构（如 Mamba）、新训练方法可能改变 Scaling 指数
  • 合成数据生态：如果合成数据质量足够高，可以突破数据墙
