L15 · 多模态大模型

Multimodal Large Language Models — 视觉×语言×音频的融合之路

一、多模态的定义与挑战

多模态难的地方从来不是"接上一个视觉编码器"，而是让图像的连续特征和文本的离散 token 落在同一个语义空间里。模态对齐没做好，模型"看图说话"就会退化成"看图猜话"——它答得很流畅，只是和图没关系。

四类核心挑战与对应手段

挑战具体表现常用对策残留问题
表示空间不一致图像是连续特征，文本是离散 token，直接拼接后模型读不懂图用大规模图文对做对比预训练，再训一个投影层把视觉特征映射到词向量空间投影层容量有限，细粒度空间关系容易丢
信息密度差异悬殊一张图携带的信息量远超一句话，但上下文预算是按 token 算的压缩视觉 token（池化、查询式重采样），或按需只对关键区域高分辨率编码压得越狠，小字与细节丢得越多
跨模态幻觉模型描述出图里根本不存在的物体，或答案完全由语言先验生成加入否定式与对抗式训练样本；评测时专门测"图里没有的东西"语言先验太强时仍会盖过视觉证据
训练数据质量参差网络图文对的文本常是标题、水印、SEO 文案，与图像内容弱相关用模型重写图像描述，生成更长更贴合的合成描述合成描述会带上生成模型自身的偏好与错误

什么是多模态？

多模态（Multimodal）指模型能够同时处理和理解多种信息模态——包括但不限于：

  • 视觉（图像、视频）
  • 语言（文本、语音转文字）
  • 音频（语音、音乐、环境音）
  • 其他（3D 点云、传感器数据、代码等）

核心挑战

1. 模态对齐（Modal Alignment）

不同模态的数据具有不同的表示空间和信息密度。如何将一张图片与一段文字描述对齐到统一的语义空间？

  • 图像 → 高维像素/特征图（空间结构）
  • 文本 → 离散 Token 序列（时序结构）
  • 音频 → 连续波形/频谱（时频结构）

2. 跨模态表示学习

目标：学习一个共享的嵌入空间，使得语义相关的不同模态数据在空间中距离接近。

3. 信息不对称

一张图片包含的信息量远超一句话描述，如何处理这种信息量的不对称？

4. 训练数据

高质量的多模态配对数据（图文对、视频-字幕对）获取成本高。

  • 多模态 ≠ 简单拼接：核心在于跨模态语义对齐
  • 模态对齐的三个层次：特征级对齐 → 语义级对齐 → 任务级对齐
  • 信息瓶颈：视觉 Token 数量远多于文本 Token，如何高效压缩是关键

二、CLIP — 视觉-语言对齐的基石

CLIP 的训练信号极其廉价——互联网上的图配文本天然就是成对数据，不需要任何人工标注类别。它学的不是"图里有什么"，而是"这张图和哪句话更配"，于是分类问题被悄悄改写成了检索问题，类别也就不必事先定义。

对比学习框架

CLIP（Contrastive Language-Image Pre-training，OpenAI 2021）通过对比学习在 4 亿图文对上训练，学习图像与文本的对齐表示。

┌──────────────┐ ┌──────────────┐
│ Image │ │ Text │
│ Encoder │ │ Encoder │
│ (ViT/RN) │ │ (Transformer)│
└──────┬───────┘ └──────┬───────┘
│ │
[I₁,I₂,...,Iₙ] [T₁,T₂,...,Tₙ]
│ │
└───── Contrastive ─────┘
Loss (InfoNCE)

InfoNCE 损失

L = -1/N Σᵢ log[ exp(sim(Iᵢ,Tᵢ)/τ) / Σⱼ exp(sim(Iᵢ,Tⱼ)/τ) ]

sim(I,T) = (I·T) / (‖I‖·‖T‖) — 余弦相似度
τ — 可学习的温度参数

关键设计

  • Image Encoder：ViT-L/14 或 ResNet（提取图像全局特征）
  • Text Encoder：Transformer（提取文本全局特征 [EOS] token）
  • 投影层：各模态独立的线性投影到共享空间
  • 大 batch 训练：batch size = 32768，提供丰富负样本

Zero-shot 分类能力

CLIP 无需微调即可进行图像分类：

  1. 将类别名构造为文本 prompt："a photo of a {class}"
  2. 用 Text Encoder 编码所有类别文本
  3. 用 Image Encoder 编码待分类图片
  4. 计算图像与所有类别文本的余弦相似度，取最高的为预测类别

在 ImageNet 上 Zero-shot 准确率达 76.2%，媲美有监督 ResNet-50。

为什么 CLIP 是视觉-语言基石？

  • 提供了强大的视觉编码器（几乎所有多模态 LLM 都使用 CLIP ViT）
  • 证明了对比学习 + 大规模数据可以学到通用视觉表示
  • 建立了图像-文本的共享语义空间
  • Zero-shot 能力展示了语言监督的强大泛化性
  • CLIP 的核心思想：用自然语言监督视觉表示学习（而非固定类别标签）
  • InfoNCE 的对称性：同时优化 I→T 和 T→I 方向
  • 温度参数 τ 的作用：控制相似度分布的锐利程度，越小越尖锐
  • CLIP 的局限：缺乏细粒度理解（空间关系、计数、属性绑定）
  • 后续改进：SigLIP（Sigmoid Loss）、EVA-CLIP、DFN（数据过滤）

三、视觉-语言对齐架构

各种接法的差别，归根结底只有一个变量：视觉信息以多少个 token 的形式进入 LLM。token 给得多，信息保留全但上下文吃紧、延迟上升；给得少，省算力但小字和细节先丢。投影层的所有设计都在这条轴上取位置。

视觉编码器 ─▶ 投影层 ─▶ LLM：三段式拼接，以及序列长什么样 ┌─────────────────────────────────────────────────────────────┐ │ ① 视觉编码器（通常来自对比预训练，常冻结） │ │ │ │ 输入图像 336×336 │ │ │ 切成 14×14 的 patch │ │ ▼ │ │ 24 × 24 = 576 个 patch ──▶ Transformer ──▶ 576 个视觉特征 │ │ 每个维度 1024 │ └────────────────────────────┬────────────────────────────────┘ ▼ ┌─────────────────────────────────────────────────────────────┐ │ ② 投影层（几乎总是可训练，是最便宜的那个环节） │ │ │ │ 做法 A 线性层 / MLP：逐个特征做维度变换，token 数不变 │ │ 576 个特征 ──▶ 576 个 视觉 token（维度对齐到词向量） │ │ 保留最全，但吃掉 576 格上下文 │ │ │ │ 做法 B 查询式重采样：用 K 个可学习 query 去 attend 全部特征 │ │ 576 个特征 ──▶ K 个视觉 token（K 常取 32 ~ 64） │ │ 大幅压缩上下文，代价是细节被摘要掉 │ │ │ │ 做法 C 空间池化：把相邻 patch 合并后再投影 │ │ 576 ──▶ 144 个视觉 token（2×2 合一） │ │ 实现最简单，均匀丢失高频细节 │ └────────────────────────────┬────────────────────────────────┘ ▼ ┌─────────────────────────────────────────────────────────────┐ │ ③ LLM（可冻结，也可一起微调） │ │ │ │ 拼成一条序列，视觉 token 就当成普通词向量插进去： │ │ │ │ [系统提示...] [图像 token ×576] 这张图里有几只猫？ [生成...] │ │ └─ 文本 ─┘ └─── 来自投影层 ───┘ └─ 文本 ─┘ │ │ │ │ 之后每一层的自注意力里，文本 token 与视觉 token 完全平权地 │ │ 互相 attend ── 这正是它比双塔更擅长推理的原因。 │ └─────────────────────────────────────────────────────────────┘ ───────────────────────────────────────────────────────── 为什么"只训投影层"这条路走得通： 视觉编码器已经会看，LLM 已经会说，缺的只是中间那本词典。 词典参数量相比两端可以忽略 ⇒ 用很小的算力就能拿到可用能力。 它的上限也在这里： 词典再准，也没法让 LLM 看到编码器没编码进去的东西 （比如被缩放压没了的小号文字）。

如何将视觉信息「注入」LLM？三种主流方案：

方案 A：线性投影（LLaVA）

Image → ViT → Linear/MLP → LLM
  • 最简单直接
  • 将视觉 Token 通过 MLP 投影到 LLM 的词嵌入空间
  • 视觉 Token 数 = ViT patch 数（如 576）
  • 优点：简单高效，保留所有视觉信息
  • 缺点：视觉 Token 多，增加 LLM 计算负担

方案 B：Q-Former / Perceiver（BLIP-2）

Image → ViT → Q-Former → LLM
(可学习 Query Tokens 交叉注意力)
  • 引入少量可学习 Query（如 32 个）
  • Query 通过 Cross-Attention 从视觉特征中提取信息
  • 大幅压缩视觉 Token 数量
  • 优点：高效，Token 数可控
  • 缺点：可能丢失细节信息，训练复杂

方案 C：Cross-Attention 融合

LLM 每 N 层插入
Cross-Attention Layer
(attend to visual features)
  • 在 LLM 的 Transformer 层中插入交叉注意力
  • 文本 Token 直接 attend 到视觉特征
  • 代表：Flamingo、Qwen-VL
  • 优点：深度融合，信息交互充分
  • 缺点：需修改 LLM 架构，增加参数

方案对比

方案代表模型视觉 Token 数对齐模块参数信息保留
线性投影LLaVA576+~几M完整
Q-FormerBLIP-2, InstructBLIP32~64~188M压缩
Cross-AttentionFlamingo, Qwen-VL可变~数百M深度融合
  • 线性投影为何有效？视觉编码器已预对齐（CLIP 训练），投影只需做空间映射
  • Q-Former 的 Query 如何学习？通过 Image-Text Matching / Generation / Contrastive 三任务
  • 趋势：简单方案（线性投影 + 高分辨率）逐渐胜出，复杂对齐模块非必要
  • 关键权衡：视觉 Token 数 vs 信息保留 vs 计算效率

四、LLaVA 系列

这条路线最重要的贡献是证明了它可以很便宜：冻住视觉编码器和 LLM 两端，只训中间那层投影，再用一批视觉指令数据做微调，就能拿到可用的图文对话能力。它把多模态从"大厂专属"变成了"实验室可复现"。

示例场景：票据上的小号字段，模型只能靠猜。背景——某团队用一个开源多模态模型做票据信息抽取，需要读出金额、编号、日期等字段。问题——关键字段的抽取准确率只有六成左右，且错法很有规律：字号大的标题从不出错，小号字段几乎全靠蒙。根因在编码器的输入分辨率是固定的，一张 A4 尺寸的票据整体缩放进去之后，小号文字只剩几个像素，信息在编码阶段就已经不存在了——这不是 LLM 读不懂，是它根本没收到。方案——改成切图加多子图编码：把原图按网格切成若干块，每块按编码器的原生分辨率单独编码，再额外附一张全局缩略图用于保留版面关系，一并送进 LLM。效果——关键字段准确率大幅提升；但视觉 token 数随子图数量成倍增长，上下文占用和首字延迟同步上升。于是又补了一步：先用一次低分辨率推理定位到目标区域，再只对该区域做高分辨率切图。最终形态是"先粗看定位、再细看识别"两阶段，把 token 花在真正需要的地方。可复用的判据：当错误集中在小目标上时，先怀疑输入分辨率，而不是先去换更大的 LLM。

LLaVA — Visual Instruction Tuning

LLaVA（Large Language and Vision Assistant，2023）是首个证明简单架构 + 指令微调可以实现强大多模态能力的开源模型。

两阶段训练

Stage 1：预训练对齐（Feature Alignment）

  • 数据：CC3M 过滤后的 595K 图文对
  • 目标：训练投影层（MLP），冻结 ViT 和 LLM
  • 任务：给定图像，生成对应描述
  • 目的：让投影层学会将视觉特征映射到 LLM 能理解的空间

Stage 2：指令微调（Instruction Tuning）

  • 数据：158K 多模态指令数据（GPT-4 生成）
  • 目标：微调投影层 + LLM，冻结 ViT
  • 任务：多轮对话、详细描述、复杂推理
  • 目的：让模型学会遵循指令、进行视觉推理

LLaVA-1.5 改进

  • 投影层从线性层升级为 2 层 MLP
  • 视觉编码器：CLIP-ViT-L-336px（更高分辨率）
  • LLM 骨干：Vicuna-7B/13B
  • 训练数据扩充：加入 VQA、OCR、GQA 等学术数据集
  • 效果：在多个 benchmark 上超越 BLIP-2、InstructBLIP

LLaVA-NeXT / LLaVA-OneVision

  • 动态高分辨率：AnyRes 策略，将高分辨率图片分割为多个子图
  • 更强 LLM 骨干：支持 Qwen-2、LLaMA-3 等
  • 视频理解：扩展到视频多帧输入
  • OneVision：统一图像/视频/多图理解
  • LLaVA 的核心洞察：对齐模块不需要复杂，简单 MLP 足够（前提是 CLIP ViT 已预对齐）
  • 两阶段训练的必要性：Stage 1 建立视觉-语言桥梁，Stage 2 激活指令跟随能力
  • 为什么冻结 ViT？避免灾难性遗忘，保持视觉编码能力
  • 高分辨率的重要性：OCR、细粒度识别依赖高分辨率输入
  • 数据质量 > 数据数量：GPT-4 生成的高质量指令数据是关键

五、GPT-4V / GPT-4o

路线上有一个明显的转折：早期方案是"给语言模型外挂一个视觉模块"，后来的方向是让同一个模型原生处理多种模态的 token。外挂能快速见效且便宜，原生才能做到低延迟的跨模态实时交互——因为中间少了几次模态转换的往返。

GPT-4V（GPT-4 with Vision）

OpenAI 于 2023 年 9 月发布的多模态版本，首次将视觉理解能力集成到 GPT-4 中。

核心能力

  • 图像理解：场景描述、物体识别、空间关系推理
  • OCR & 文档理解：表格解析、手写识别、图表分析
  • 视觉推理：数学题解析、图表推理、因果推断
  • 多图对比：同时分析多张图片的差异和联系
  • 代码生成：从 UI 截图生成前端代码

GPT-4o — Omni 模型

2024 年 5 月发布，原生多模态模型，统一处理：

  • 文本输入/输出
  • 图像输入（未来支持输出）
  • 音频输入/输出（实时语音对话）
  • 视频输入（实时视频理解）

GPT-4o 的技术突破

  • 端到端训练：不再是分离的 ASR → LLM → TTS 管道
  • 低延迟：语音响应 ~320ms（接近人类对话速度）
  • 情感理解：能感知语气、情感、节奏
  • 统一架构：一个模型处理所有模态（减少信息损失）
  • GPT-4V 的架构推测：CLIP ViT + Cross-Attention 融合（未公开）
  • GPT-4o "原生多模态" vs "管道式多模态"的区别：端到端训练保留跨模态信息
  • Omni 模型的优势：避免级联误差、降低延迟、支持跨模态推理
  • 局限性：幻觉问题（描述图中不存在的内容）、空间推理仍有不足

六、Gemini — Google 原生多模态

原生多模态的意思是：从预训练第一步起，各模态的 token 就混在同一个序列里一起训，而不是先把文本模型训好再想办法接视觉。这个差别不体现在单项跑分上，而体现在跨模态推理和实时交互这类需要"模态之间无缝"的场景里。

核心设计理念

Gemini（Google DeepMind, 2023.12）从一开始就作为原生多模态模型训练，而非后期"接入"视觉能力。

八、视频理解

视频理解的核心矛盾只有一条：token 预算。一帧图就要几百个视觉 token，而一分钟视频有上千帧。所以这个领域的几乎所有技术都在回答同一个问题——哪些帧、哪些区域可以扔掉而不影响答案。

  • 帧级独立编码 + 时序聚合：每帧用 ViT 编码，再拼接/池化

  • 视频 Token 压缩：相邻帧特征去重/合并，减少 Token 数
  • Slow-Fast 策略：低帧率全局理解 + 高帧率局部细节

  • Token 数量爆炸：1 分钟视频 @ 1fps × 576 tokens/帧 = 34,560 tokens
  • 长时序理解：需要记住早期内容并与后期关联
  • 因果推理：理解事件的因果链和时序逻辑
  • 实时处理：在线视频理解需要流式处理能力
  • 音视频同步：语音内容与画面的对应关系

  • Gemini 1.5 Pro：100 万 Token 长视频理解
  • GPT-4o：实时视频流理解
  • 视频理解的核心瓶颈：Token 数量 × 上下文长度限制
  • 帧采样的 trade-off：采样越稀疏信息损失越大，越密集计算越贵
  • Token 压缩策略：时间维度池化、相似帧合并、关键帧选择
  • 视频 vs 图像理解的本质区别：时序推理和因果关系理解
  • 实时视频理解的要求：流式处理 + 增量更新 + 低延迟

九、多模态模型对比表

选多模态模型要把三件事分开看：输入分辨率上限决定能不能看清小字，视觉 token 数决定吃掉多少上下文预算和延迟，底座语言模型的能力决定看懂之后能不能讲清楚。三项里任何一项是瓶颈，换另外两项都没用。

示例场景：三分钟录屏问答，token 一算就超预算。背景——某团队要做操作录屏的问答，用户会问"我在第几步点错了"这类问题。问题——第一版按 1 fps 采样，3 分钟得 180 帧，每帧约 576 个视觉 token，合计约 10 万 token：既超出上下文预算，单次调用的开销也完全不可接受。而且实测发现录屏里绝大多数帧是几乎静止的——用户在读页面，画面根本没变。方案——按三级压缩重做：先用帧间差分把静止段落合并，180 帧压到约 40 个关键帧；再对每帧做 2×2 空间池化，每帧从 576 降到 144 个 token；最后给每个保留帧附上时间戳文本，保证"第几分钟"这类问题还能答。效果——视觉 token 从约 10 万降到约 6 千，落进预算内且延迟可接受，"第几步操作"类问题的正确率因为时间戳的加入反而变好了。代价说清楚——快速拖拽、一闪而过的弹窗这类内容会被合帧丢掉，所以又保留了一个"按用户指定时间段重新高密度采样"的兜底入口。
  • 先确认输入分辨率够不够看清目标，再去比较模型的推理能力
  • 把视觉 token 数当成上下文预算的一部分显式核算，而不是事后发现超了
  • 小目标场景用"先粗看定位、再对局部高分辨率细看"的两阶段做法
  • 视频按问题类型决定压时间维还是压空间维，并保留时间戳锚点
  • 评测集里专门放"图里没有的东西"，用来量化跨模态幻觉
  • 用自己的真实图片做盲评，公开榜单的图像分布与业务差别往往很大
  • 只训投影层作为起点，确认路线可行后再考虑放开更多参数
  • 不要把小目标识别失败归因于语言模型太弱，先查编码阶段有没有丢信息
  • 不要用双塔对比模型去做计数和精确空间关系，它的结构决定了做不好
  • 不要不加压缩就把视频逐帧塞进上下文，token 量会失控
  • 不要只看图像描述任务的效果，那是最容易被语言先验蒙过去的任务
  • 不要在压缩帧之后丢掉时间信息，"何时发生"类问题会直接失效
  • 不要假设加大 LLM 底座就能修好视觉端的问题，两者的瓶颈相互独立
  • 不要用模型自己生成的图像描述反复迭代训练，偏好和错误会被放大

Q&A

Q1：CLIP 是如何训练的？为什么它的视觉编码器被广泛使用？

训练方式：CLIP 在 4 亿网络图文对上进行对比学习。一个 batch 中有 N 个图文对，模型需要将正确配对的图文相似度最大化，错误配对相似度最小化（InfoNCE 损失）。

广泛使用原因：

  • 在大规模多样数据上训练，学到通用的视觉表示
  • 天然具备图文对齐能力（已在共享语义空间中）
  • Zero-shot 泛化能力强，迁移到下游任务无需微调
  • 开源且有多种尺寸可选（ViT-B/16, ViT-L/14 等）
Q2：LLaVA 的两阶段训练分别做什么？为什么需要两阶段？

Stage 1（预训练对齐）：冻结 ViT 和 LLM，只训练投影层 MLP。用图文对数据让 MLP 学会将视觉特征映射到 LLM 的文本空间。

Stage 2（指令微调）：冻结 ViT，微调投影层 + LLM。用多模态指令数据（对话、推理、描述）训练模型遵循指令。

为什么两阶段：Stage 1 建立"视觉-语言桥梁"（让 LLM 能"看懂"图片），Stage 2 激活交互能力（让 LLM 能"谈论"图片）。跳过 Stage 1 直接微调效果差，因为随机初始化的投影层会产生噪声梯度。

Q3：Q-Former 和线性投影对齐的优劣分别是什么？

Q-Former（BLIP-2 方案）：

  • 优：将数百个视觉 Token 压缩到 32 个，大幅减少 LLM 计算量
  • 劣：训练复杂（需要三阶段预训练）、可能丢失细节信息、Q-Former 本身有 188M 参数

线性/MLP 投影（LLaVA 方案）：

  • 优：简单高效、保留完整视觉信息、训练容易
  • 劣：视觉 Token 数量多（576+），增加 LLM 推理负担

结论：实践表明简单 MLP 投影 + 强视觉编码器 + 高分辨率的效果通常更好，Q-Former 的信息压缩在当前 LLM 能力下不再是必要的。

Q4：GPT-4o 的"原生多模态"和传统管道式方案有什么区别？

传统管道式：语音 → ASR 转文字 → LLM 处理 → TTS 合成语音。各模块独立，存在级联误差、信息损失（语气、情感）、高延迟。

GPT-4o 原生多模态：一个统一模型端到端处理所有模态的输入和输出。

  • 避免了级联误差（不需要中间文字表示）
  • 保留了跨模态信息（语气、情感、韵律）
  • 低延迟（~320ms 响应，接近人类对话）
  • 支持跨模态推理（同时利用视觉+语音线索）
Q5：视频理解中的 Token 爆炸问题如何解决？

一分钟视频 @ 1fps 可产生数万 Token，主要解决策略：

  • 稀疏采样：只取少量关键帧（如均匀采 8-32 帧）
  • 时间维度池化：相邻帧的视觉 Token 取平均/最大池化
  • 相似帧去重：基于特征相似度合并冗余帧
  • Token 压缩：用类似 Q-Former 的方法压缩每帧 Token
  • 长上下文模型：Gemini 1.5 Pro 直接支持 100 万 Token
  • 分层处理：先粗粒度理解全局，再细粒度分析关键片段
Q6：为什么多模态模型会产生幻觉？如何缓解？

幻觉原因：

  • LLM 的语言先验过强：倾向于生成"合理"但不基于图像的描述
  • 视觉信息不足：投影/压缩过程中丢失细节
  • 训练数据偏差：某些视觉-文本对关联不精确
  • 位置偏差：后期生成的内容受前文影响而非图像

缓解方法：

  • RLHF / DPO 针对幻觉进行对齐训练
  • 提高视觉分辨率，保留更多细节
  • 加入负样本训练（让模型学会说"图中没有"）
  • Grounding 训练：要求模型给出视觉证据（bounding box）
  • 推理时策略：让模型先描述再回答，降低幻觉
Q7：CLIP 的 InfoNCE 损失中温度参数 τ 的作用是什么？

温度参数 τ 控制 softmax 分布的锐利程度：

  • τ 较小：分布更尖锐，模型更"自信"，对相似度差异更敏感，训练信号更强但可能不稳定
  • τ 较大：分布更平滑，所有负样本的梯度更均匀，训练更稳定但学习信号弱

CLIP 中 τ 是可学习参数（初始化为 0.07），让模型自动找到最优温度。训练过程中 τ 通常会逐渐减小（分布变锐利），因为模型越来越能区分正负样本。

τ 还有正则化效果：防止模型过度自信导致过拟合。

Q8：Gemini 和 GPT-4 在多模态能力上的核心差异是什么？

训练范式差异：

  • Gemini：从头以原生多模态方式训练（所有模态同时参与预训练）
  • GPT-4V：推测是在已训练好的 GPT-4 基础上接入视觉模块

架构差异：

  • Gemini 1.5：MoE 架构，超长上下文（1M tokens）
  • GPT-4：Dense 架构（推测），上下文 128K

能力侧重：

  • Gemini 在长视频理解、多模态 CoT 上有优势
  • GPT-4V/4o 在复杂推理、指令跟随上仍领先
  • GPT-4o 在语音交互上更自然
Q9：开源多模态模型如何追赶闭源模型？关键因素是什么？

关键追赶因素：

  • 视觉编码器升级：从 CLIP ViT-L → InternViT-6B / SigLIP-SO400M
  • 高分辨率支持：动态分辨率（AnyRes）让模型看清细节
  • LLM 骨干升级：从 Vicuna-7B → LLaMA-3-70B / Qwen2-72B
  • 训练数据质量：精心构建的多阶段多任务训练数据
  • 训练策略：渐进式训练、课程学习、DPO 对齐

当前差距：在复杂推理、指令跟随、安全对齐方面仍有差距；在标准 benchmark 上差距已大幅缩小。

Q10：设计一个多模态 LLM 系统，你会如何选择各组件？

系统设计考虑：

1. 视觉编码器选择：

  • 通用：SigLIP-SO400M（强 Zero-shot + 高效）
  • 高分辨率需求：InternViT-6B 或多尺度 ViT
  • 轻量级：CLIP ViT-B/16

2. 对齐模块：

  • 推荐 2 层 MLP（简单有效，LLaVA 验证）
  • 如需 Token 压缩：Perceiver Resampler（如部署受限）

3. LLM 骨干：

  • 性能优先：Qwen2-72B / LLaMA-3-70B
  • 效率优先：Phi-3-mini / Qwen2-7B

4. 训练策略：

  • Stage 1：大规模图文对预训练对齐（冻结 ViT + LLM）
  • Stage 2：高质量指令数据微调（解冻 LLM）
  • Stage 3：DPO/RLHF 对齐（减少幻觉）

5. 推理优化：视觉 Token 缓存、KV Cache 复用、量化部署
