L20 · Temperature 与 Top-p 采样策略

大模型预测流程 → 生成分数 → Softmax 转概率 → 加权采样 → Temperature 作用 → Top-p 作用

模型的输出不是"查"出来的，而是"掷骰子"掷出来的：Temperature 调节骰子的公平程度，Top-p 决定哪些候选词有资格上桌——两个都调低，模型是严谨的会计；两个都调高，模型是奔放的诗人。

一、大模型预测下一个词的三步

大模型生成文本的方式是自回归（Autoregressive）——把已生成的内容当作下一步的输入，一个词一个词地往后"接龙"，直到生成结束标记。每预测一个词，都要走完固定的三步：

步骤操作输出
① 生成分数给词汇表中每个词打一个 Logit 分数（模型对"下一个词是它"的原始置信度，可为任意实数）每个词一个原始分数
② 转概率用 Softmax 将分数转为概率（把任意实数分数压缩到 0~1 且总和为 1 的函数）每个词一个概率值
③ 加权采样按概率随机选取输出词最终输出的词
┌────────────────────────────────────────────────┐ │ 自回归生成循环 │ │ │ │ 已有文本 ──→ 模型前向计算 ──→ Logits 分数 │ │ ▲ │ │ │ │ ▼ │ │ │ Softmax（Temperature 在此生效）│ │ │ │ │ │ │ ▼ │ │ │ Top-p 截断长尾候选词 │ │ │ │ │ │ │ ▼ │ │ └────── 加权采样出一个词 ◄───┘ │ │ │ │ 循环往复，直到生成结束符 <EOS> │ └────────────────────────────────────────────────┘

Softmax 与 Temperature 的关系

Softmax 的公式里藏着 Temperature 的位置：每个词的分数先除以温度 T，再做指数归一化。T 就是那个控制"分数差距被放大还是缩小"的旋钮。

P(i) = e^(Z_i / T) / Σⱼ e^(Z_j / T)

加权采样

将 0~100 的数轴按概率分配给各个词，生成随机数，落在哪个区间就输出哪个词。这保证了高分词有更大机会被选中，但低分词也有机会——正是这一点让模型输出带有"创造性"。

import numpy as np
logits = np.array([2.0, 1.0, 0.1])   # 三个候选词的分数
T = 0.5                              # Temperature
probs = np.exp(logits / T)
probs = probs / probs.sum()          # ≈ [0.84, 0.11, 0.05]
token = np.random.choice(3, p=probs) # 加权采样

Logit 是"评委打分"，Softmax 是"把分数换算成胜率"，加权采样是"按胜率抽奖"——模型每吐一个字，就完整跑一遍这套流程。

二、Temperature — 控制概率差距

Temperature (T) 作用于 Softmax 函数中：每个分数先除以 T 再计算概率。它不改变候选词的排名，只改变排名之间的"贫富差距"。

T 值分数变化概率分布效果
T = 1（默认）不变原始分布平衡
T = 0.1（低）分数被放大 10 倍差距拉大，赢家通吃保守、稳定、死板
T = 2.0（高）分数被缩小一半差距缩小，趋于均等多样、随机、创意

物理类比

Temperature 的命名直接借用了热力学：低温如冰，分子运动缓慢、结构稳定，对应输出保守确定；高温如蒸汽，分子活跃混乱，对应输出多样发散。这个类比精确地抓住了本质——温度衡量的就是系统的"混乱度"。

各类任务的典型温度

任务类型推荐 T 值理由
代码生成 / 数学推理0 ~ 0.3答案唯一，要求稳定可复现
事实问答 / 翻译0.3 ~ 0.7准确优先，允许措辞灵活
营销文案 / 邮件0.7 ~ 1.0自然流畅，适度变化
小说 / 头脑风暴1.0 ~ 1.3鼓励意外组合与新颖表达

Temperature 的本质：调节分数之间的差距大小。低温 → 赢家通吃 → 稳定输出；高温 → 机会均等 → 多样输出。

三、Top-p — 控制长尾截断

Top-p（核采样，Nucleus Sampling）的作用是设定一个概率阈值：从概率最高的词开始累加，凑够 p 就停止，丢弃剩余的低概率"长尾词"，再在留下的候选词里重新归一化采样。与 Temperature 改变分布形状不同，Top-p 是直接"砍掉"分布的尾部。

Top-p 值保留词数效果
p = 1.0（默认）全部保留无截断
p = 0.9保留头部 3~5 个词去掉明显不相关的词
p = 0.6只保留头部 2~3 个词更加保守稳定
Top-p = 0.9 的截断过程（按概率从高到低累加）： 词A 48% ──┐ 词B 27% ──┤ 累加：48% → 75% → 90% ✓ 凑够 0.9，关门 词C 15% ──┘ ────────────── 截断线 ────────────── 词D 6% ✗ 丢弃（长尾） 词E 3% ✗ 丢弃 词F 1% ✗ 丢弃

Top-p 的巧妙之处在于它是动态的：模型很有把握时（头部概率集中），可能只留 1~2 个词；模型不确定时（概率分散），会自动放宽到十几个词。与之相关的还有 Top-k——固定保留概率最高的 k 个词，不管概率分布长什么样，是一种"一刀切"的静态截断。

Top-p 是概率世界的"保安"：从最靠谱的词开始放行，累计放行到占 90% 概率就关门，剩下那些不靠谱的长尾词一律拦在门外——防止模型输出"自行车的维修与保养"这种离谱回答。

五、生产调参案例

案例一 · 代码补全助手降温：背景：某 IDE 代码补全插件默认 T=1.0，用户频繁反馈"补全出看似合理但跑不通的代码"。问题：高温下低概率的冷门 API 词频繁被抽中，pass@1（一次生成即通过测试的比例）只有 68%，且同一输入多次补全结果差异大，用户无法形成稳定预期。方案：仅将 Temperature 降到 0.2，Top-p 保持默认。效果：pass@1 提升到 81%，重复生成的一致性从 54% 升到 92%，用户采纳率提升约 25%。
案例二 · 营销文案批量生成升温：背景：某电商团队用模型批量生成商品卖点文案，默认参数下产出高度同质化。问题：100 篇文案去重后独特表达占比仅 31%，A/B 测试点击率平平。方案：仅将 Temperature 升到 0.95，并配合人工筛选兜底。效果：独特表达占比提升到 67%，最优文案组的点击率比原方案高 12%，且未出现事实性错误上升。
  • 按任务类型选温度：严谨任务 0~0.3，创意任务 0.8+
  • 一次只调一个参数，另一个保持默认
  • 需要可复现时固定 seed（若 API 支持）
  • 调参后用同一批测试用例回归验证效果
  • 不要同时大改 Temperature 和 Top-p
  • 不要在代码/SQL 生成任务用 T > 0.5
  • 不要以为 T=0 就 100% 可复现（浮点与批处理仍有微小差异）
  • 不要靠无限升温找创意，过高温度会输出胡话

Q&A

Temperature 和 Top-p 各自的原理是什么？有什么区别？
Temperature 作用于 Softmax 函数中，将每个词的分数先除以 T 再计算概率：T 低时分数差距被放大（赢家通吃），T 高时差距被缩小（趋于均等），但候选词一个都不会少。Top-p 设定概率阈值，从最高概率词开始累加，凑够 p 就丢弃剩余低概率词，是真正裁剪候选集。两者调高调低的方向一致（高→多样，低→稳定），但原理不同：Temperature 改变概率分布的形状，Top-p 截断概率分布的尾部。正因为作用机制重叠，OpenAI 建议只调其中一个。
大模型预测下一个词的完整流程是什么？
分三步：①生成分数——给词汇表中每个词打一个 Logit 原始分数（几万到几十万个词）；②转概率——用 Softmax 将分数转为概率，Temperature 参数在这一步生效（分数先除以 T 再做 Softmax）；③加权采样——按概率分配数轴区间，生成随机数决定输出哪个词，Top-p 在这一步之前先截断低概率长尾词。采样出的词会被追加到已有文本后面，整个流程不断重复，逐词生成直到遇到结束标记 <EOS>，这就是自回归生成。
Temperature 设为 0，输出就完全确定了吗？
理论上 T→0 等价于贪心采样（greedy），即每次都选概率最高的词，输出趋于确定。但工程上仍有微小不确定性：GPU 浮点运算在不同批次大小、不同硬件上的舍入可能有差异，当两个候选词概率极其接近时，排序可能翻转；部分 API 实现也会对 T=0 做极小值兜底。所以 T=0 能得到"高度稳定"而非"绝对可复现"，需要严格复现时还应配合固定随机种子（seed）和相同的请求参数。
Top-p 和 Top-k 有什么区别？怎么选？
Top-k 是静态截断：无论概率分布长什么样，固定只保留概率最高的 k 个词。Top-p 是动态截断：从最高概率词累加到总概率达到 p 为止，模型有把握时可能只留 1~2 个词，没把握时自动放宽到十几个词。Top-p 的优势在于能自适应分布的"尖锐"或"平坦"程度，避免 Top-k 在模型极确定时仍强行保留 k 个烂候选、或在极不确定时把 k 卡得太死的问题。主流 API 普遍提供 Top-p，Top-k 更多出现在开源模型的推理配置中。
为什么 OpenAI 官方建议只调 Temperature 和 Top-p 中的一个？
因为两者都在控制输出的随机性，作用方向一致且会互相纠缠：Temperature 改变分布形状后，Top-p 的截断点切到的词集也随之变化，两个参数同时调整时效果很难直观预测，调参变成在二维空间里盲搜。只调一个、另一个保持默认，能把问题降回一维，便于观察因果关系、积累调参经验。实践中的常见组合是：固定 Top-p=1（默认）只调 Temperature，或固定 Temperature=1 只调 Top-p。
代码生成、数学推理这类任务应该怎么设置采样参数？
这类任务答案高度收敛，正确性远比多样性重要，应该把随机性压到最低：Temperature 设为 0~0.3（很多代码助手直接用 0），Top-p 若可调则设为 0.5~0.95 收紧候选。低温让高概率的正确写法形成"赢家通吃"，避免冷门 API 和生僻语法被抽中——实测某代码补全插件把 T 从 1.0 降到 0.2 后，pass@1 从 68% 提升到 81%。如果确实需要多解（如探索多种实现方案），更好的做法是低温下多次采样（提高 n），而不是单纯升温。
调高 Temperature 是让模型"更有创意"还是"更容易胡说"？边界在哪？
两者是同一机制的一体两面：升温让低概率词有机会被选中，既带来了新颖表达，也放大了错误候选。边界取决于任务的"容错空间"——创意写作、头脑风暴容错空间大，T=0.9~1.3 的意外组合是收益；事实问答、医疗法律场景容错空间小，同样的温度就是风险。经验法则是：T 超过 1.2 后输出质量通常断崖式下滑，且升温带来的多样性收益递减；需要可控的多样性时，应优先用 Top-p 保留头部候选，而不是无限制升温。
