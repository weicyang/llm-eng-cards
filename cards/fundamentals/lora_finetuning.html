10 · LoRA / QLoRA

参数高效微调（PEFT）— 低秩分解减少 97% 参数，QLoRA 单卡微调大模型，多任务热切换与多 LoRA 生产服务

LoRA 的核心直觉：大模型微调时，权重的变化量 ΔW 本身是「低秩」的 —— 不需要调整所有参数，只需要找到那个低维子空间。用两个小矩阵的乘积去近似 ΔW，参数量从 25 万降到 8000。

一、为什么需要 LoRA？

1.1 全量微调的痛点

问题具体表现影响
参数量巨大一个 512×512 的线性层就有 ~25 万参数显存占用大、训练慢
存储成本高每个任务需要保存一份完整模型副本7B 模型 ≈ 14GB/份，10 个任务 = 140GB
灾难性遗忘微调新任务时破坏原有能力需要在所有任务上联合训练
部署不灵活不同任务的模型无法快速切换需要加载完整模型

1.2 显存账单：全量微调有多贵

传统的 Fine-tuning 需要更新模型的全部参数。以 LLaMA-2 70B 为例：

  • 模型参数量：70B，FP16 存储 ≈ 140 GB
  • 梯度（FP16）≈ 140 GB
  • Adam 优化器状态（FP32 m + v）≈ 280 GB × 2 = 560 GB
  • 总 GPU 显存需求 ≈ 840+ GB（约需 10+ 张 A100 80G）

这样的成本对绝大多数团队和个人来说是不可接受的。PEFT（Parameter-Efficient Fine-Tuning，参数高效微调）应运而生，目标是只训练极少量参数，就能达到接近全参数微调的效果。

1.3 PEFT 方法谱系

类别代表方法核心思想可训练参数占比
加法式 (Additive)Adapter、Prefix Tuning在模型中插入额外的小模块0.1% ~ 3%
软提示 (Soft Prompt)Prompt Tuning、P-Tuning v1/v2学习连续的虚拟 token 嵌入0.01% ~ 0.1%
重参数化 (Reparameterization)LoRA、DoRA、AdaLoRA低秩分解冻结权重的增量0.1% ~ 1%
选择性 (Selective)BitFit、Fish Mask只更新模型中特定子集参数0.05% ~ 0.5%
HuggingFace PEFT 库统一了这些方法的实现接口。安装：pip install peft，支持与 transformers、accelerate、bitsandbytes 无缝集成。LoRA 是重参数化类中最流行的方法，也是本文的主角。
  • PEFT 的核心动机：降低全参数微调的显存、计算和存储开销
  • 四大分类：加法式 / 软提示 / 重参数化 / 选择性 —— LoRA 属于重参数化
  • PEFT 的"免费午餐"：推理时可将额外参数合并回原模型，不增加推理延迟
  • 关键权衡：可训练参数越少 → 训练越快/省内存，但可能牺牲表达能力

二、数学原理：低秩分解

2.1 核心思想

全量微调时，权重矩阵的变化为：

全量微调: W' = W + ΔW (ΔW 是 d×d 的大矩阵) LoRA: W' = W + B × A (B 是 d×r, A 是 r×d, r ≪ d)

其中 r 是秩（rank），取值范围通常为 4~64，常用 4、8、16。这利用了线性代数中的低秩近似原理。

2.2 参数量对比

方案参数量计算方式
全量微调262,144 (25 万)512 × 512 = d²
LoRA (r=8)8,192 (~8K)512×8 + 8×512 = 2dr
LoRA (r=4)4,096 (~4K)512×4 + 4×512 = 2dr
LoRA (r=16)16,384 (~16K)512×16 + 16×512 = 2dr

以 r=8 为例，参数量减少 97%（从 25 万降到 8192）。推广到任意 d×k 线性层：全参数需 d×k 个参数，LoRA 只需 r×(d+k)；对 4096×4096 的线性层取 r=8，压缩比高达 256×（仅需原来 0.39% 的可训练参数）。

2.3 矩阵分解的直觉

原始 ΔW (512 × 512): ┌────────────────────────┐ │ │ 262,144 个参数 │ 完整的权重变化矩阵 │ 大部分信息冗余 │ │ └────────────────────────┘ 分解为 B (512 × 8) × A (8 × 512): ┌────────┐ ┌────────────────────────┐ │ │ │ │ │ 512×8 │× │ 8×512 │ 8,192 个参数 │ (B) │ │ (A) │ 信息等价 │ │ │ │ └────────┘ └────────────────────────┘ ↑ 8 = rank (秩)：捕获变化方向的维度数

2.4 为什么低秩有效：内在维度

Aghajanyan et al. (2020) 的研究发现：预训练模型的权重更新具有极低的内在维度（Intrinsic Dimensionality）：

  • 预训练已经学到了丰富的通用知识，微调只是在一个低维子空间中调整
  • ΔW 的有效秩远小于矩阵的满秩 —— 实验表明 r = 4 ~ 8 就能捕获大部分更新信号
  • 这与 NLP 中 Transformer 权重矩阵的奇异值快速衰减现象一致
微调时的权重变化 ΔW 的「有效秩」很低 —— 虽然 ΔW 是 512×512 的矩阵，但它的大部分信息可以用 8 个基向量来表达。LoRA 就是找到这 8 个基向量。

预训练模型好比一个"万能基座"，微调相当于在基座上放一个"方向盘"。方向盘的自由度（r）不需要很大，就能有效引导模型的输出方向。

三、工程实现

三个参数决定 LoRA 的成败：秩 r 决定旁路能表达多复杂的变化，缩放因子 α 决定这份变化以多大权重叠回主干，target_modules 决定改动发生在哪些层。前两个是容量旋钮，第三个才是效果差异的主要来源——注意力投影全都挂上，通常比把 r 调大更划算。

3.1 使用 PEFT 工具包

from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM

# 1. 加载预训练模型（冻结）
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b")

# 2. 配置 LoRA
lora_config = LoraConfig(
    r=8,                          # 秩：低秩矩阵的维度
    lora_alpha=32,                # 缩放因子：通常设为 4×r
    target_modules=["q_proj",     # 指定要适配的线性层
                    "v_proj",
                    "k_proj",
                    "o_proj"],
    lora_dropout=0.05,            # Dropout 防止过拟合
    bias="none",                  # 不训练偏置项
    task_type="CAUSAL_LM"
)

# 3. 封装模型 —— 自动插入 LoRA 层
model = get_peft_model(model, lora_config)

# 4. 查看可训练参数
model.print_trainable_parameters()
# 输出: trainable params: 4,194,304 || all params: 6,742,609,920 || trainable%: 0.0622%

3.2 关键参数说明

参数含义推荐值影响
r (rank)低秩矩阵的维度8~16越大表达能力越强，但参数更多
lora_alpha缩放因子4 × r控制 LoRA 更新的幅度
target_modules要适配的线性层q_proj, v_proj注意力层效果最好
lora_dropoutLoRA 层的 Dropout0.05~0.1防止小数据集过拟合

3.3 应用在哪些模块：target_modules

LoRA 可以应用到 Transformer 中任意线性层。常见选择：

目标模块参数名示例说明
Q (Query)q_proj最常用，捕获"关注什么"的变化
K (Key)k_proj与 Q 配合控制注意力模式
V (Value)v_proj影响实际信息传递
O (Output)o_proj控制多头拼接后的投影
FFN (gate/up/down)gate_proj, up_proj, down_proj参数量大，可选择性添加
实践经验：最小方案是 ["q_proj", "v_proj"]（原始论文推荐）；LLaMA 系列推荐方案为 ["q_proj", "k_proj", "v_proj", "o_proj"]；追求极限性能时再加上 FFN 的 gate_proj、up_proj、down_proj（但显存显著增加）。

3.4 缩放因子 α/r

LoRA 引入了一个缩放因子 α（lora_alpha）来控制 LoRA 更新的强度：

h = W₀x + (α / r) · BAx
  • α / r 是实际的缩放比例（类似于学习率的调节器）
  • 当 α = r 时，缩放因子为 1（等价于不缩放）
  • 常见设置：α = 2r ~ 4r（如 r=8, α=16~32），LoRA 更新被相应放大
  • α 越大 → 更新越激进；α 越小 → 更新越保守
为什么不直接调学习率？α/r 缩放使得切换不同的 r 值时，不需要重新调整学习率。例如 r 从 8 变为 16，只需 α 从 16 变为 32，学习率保持不变。这就是 α/r 的工程价值。

3.5 初始化策略

  • A 矩阵：高斯随机初始化（nn.init.kaiming_uniform_ 或正态分布）
  • B 矩阵：全零初始化（nn.init.zeros_）

这样初始化的巧妙之处：训练开始时 BA = 0，LoRA 分支的输出为零，模型行为完全等价于冻结的预训练模型。训练过程是从预训练模型出发逐步学习增量。

3.6 推理时合并

训练时: y = W·x + B·A·x (W 冻结，只训练 A 和 B) 推理时: W' = W + B·A (合并回原矩阵) y = W'·x (无额外推理开销！)

合并时会带上 α/r 缩放：W_merged = W₀ + (α / r) · BA。

# HuggingFace PEFT 合并示例
from peft import PeftModel

model = PeftModel.from_pretrained(base_model, lora_path)
merged_model = model.merge_and_unload()  # 合并 LoRA → 原始模型
merged_model.save_pretrained("merged_output")
LoRA 在推理时零开销 —— 因为可以将 B×A 合并回原始权重矩阵 W，得到新的 W'，推理速度和不微调完全相同。不合并的优势：可以动态切换/叠加多个 LoRA adapter，支持热切换（见第七章）。

四、优势特性

4.1 模块化存储

存储方式大小说明
全量微调副本~14 GB7B 模型的完整权重
LoRA 适配器~16 MB仅保存 A 和 B 矩阵

存储成本降低约 1000 倍。

4.2 原模型冻结

基础模型的参数完全不变，LoRA 只训练附加的低秩矩阵。这意味着：

  • 基础模型的通用能力不受影响
  • 可以在同一个基础模型上叠加多个 LoRA 适配器
  • 不存在灾难性遗忘的问题
  • 从 r=8 开始实验，按需调大
  • 优先适配注意力层（q_proj, v_proj）
  • lora_alpha 设为 4×r
  • 用小学习率（1e-4 ~ 3e-4）
  • 推理时合并权重以消除额外开销
  • 不要对所有层都做 LoRA（选关键层）
  • 不要在大模型上设太高的 rank（浪费参数）
  • 不要忽略 lora_alpha 的缩放效果
  • 不要在推理时忘记合并权重
  • 不要用全量微调的学习率（会过大）

五、QLoRA：4-bit 量化微调

5.1 核心思想

QLoRA (Quantized LoRA) = 量化基座 + LoRA 微调。由 Dettmers et al. (2023) 提出，核心创新是在4-bit 量化的冻结基座模型上进行 LoRA 微调，实现单张消费级 GPU 微调大模型。

5.2 三大技术创新

① NF4 (NormalFloat 4-bit) 量化

  • 专为正态分布权重设计的信息论最优数据类型
  • 将每个权重量化为 4-bit（16 个量化级别）
  • 量化级别基于正态分布的分位数选取，比均匀量化更准确
  • 比 FP4 和 INT4 在相同位宽下保留更多信息

② 双重量化 (Double Quantization)

  • 第一层量化：权重 FP16 → NF4（每 64 个权重共享一个 FP32 缩放因子）
  • 第二层量化：对缩放因子本身再做 FP32 → FP8 量化
  • 额外内存节省：约 0.37 bit/参数
  • 对 65B 模型节省约 3 GB 显存

③ 分页优化器 (Paged Optimizers)

  • 利用 NVIDIA 统一内存机制，在 GPU 显存不足时自动转移到 CPU 内存
  • 类似操作系统的虚拟内存分页
  • 处理长序列导致的显存尖峰，避免 OOM
  • 对训练速度有一定影响（CPU ↔ GPU 数据传输），但保证了可行性

5.3 显存对比

模型规模全参数 FP16LoRA FP16QLoRA NF4可用 GPU
7B~120 GB~16 GB~6 GBRTX 3060 12G
13B~200 GB~30 GB~10 GBRTX 3090 24G
33B~530 GB~70 GB~20 GBRTX 4090 24G
65B~840 GB~140 GB~40 GBA100 80G 单卡

5.4 QLoRA 代码示例

import torch
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

# 4-bit 量化配置
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",           # NF4 量化
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,       # 双重量化
)

# 加载量化模型
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    quantization_config=bnb_config,
    device_map="auto",
)
model = prepare_model_for_kbit_training(model)

# LoRA 配置
lora_config = LoraConfig(
    r=16, lora_alpha=32, lora_dropout=0.05,
    target_modules=["q_proj","k_proj","v_proj","o_proj"],
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, lora_config)
  • QLoRA 三大创新：NF4 量化（信息论最优 4-bit）、双重量化（压缩缩放因子）、分页优化器（防 OOM）
  • 梯度计算流程：前向 NF4 → 反量化为 BF16 → 计算梯度 → 只更新 LoRA 参数（FP16/BF16）
  • 实践中 QLoRA 效果与 16-bit LoRA 基本持平，精度几乎无损，但显存节省 10 倍以上

六、LoRA 变体与进阶

变体核心改进额外开销适用场景 / 效果
QLoRA4-bit 量化基础模型 + LoRA量化/反量化略降速单卡微调 65B 模型（详见第五章）
DoRA分解为方向 + 幅度两个分量极小（多一个 m 向量）更精细的权重调控，+1~3%
rsLoRA调整缩放因子为 α/√r无高 rank 时更稳定
LoRA+A 和 B 使用不同学习率无提升收敛速度，+1~2%
PiSSASVD 主成分初始化初始化时一次 SVD收敛快 + 效果好
AdaLoRA动态自适应秩分配训练略慢同参数预算下更优

6.1 DoRA — 权重分解 LoRA

DoRA (Weight-Decomposed Low-Rank Adaptation) 将权重矩阵分解为幅度 (magnitude) 和方向 (direction) 两个分量：

W' = m · (W₀ + BA) / ‖W₀ + BA‖_c
  • m：可训练的幅度向量（每列/行一个标量），BA 为低秩更新（与 LoRA 相同）
  • 灵感来自 Weight Normalization：解耦了"走多远"和"往哪走"
  • 在多个基准上比 LoRA 提升 1-3%，接近全参数微调效果

6.2 rsLoRA — 秩稳定缩放

标准 LoRA 的缩放为 α/r，但随着 r 增大，每个分量的贡献被过度缩小。rsLoRA 使用 √r 替代 r 作为分母（α/r → α/√r），保持不同秩下更新幅度的稳定性。当 r 较大（32/64）时效果改善尤为明显。已集成到 HuggingFace PEFT：use_rslora=True。

6.3 LoRA+ — 差异学习率

  • B 矩阵（零初始化）需要更大的学习率来"启动"
  • A 矩阵（高斯初始化）可以用较小的学习率
  • 建议：lr_B ≈ 2× ~ 16× lr_A，简单修改即可带来 1-2% 的性能提升

6.4 PiSSA — 奇异值分解初始化

  • 对 W₀ 进行 SVD 分解：W₀ = UΣVᵀ，用前 r 个主奇异值/向量初始化 A 和 B
  • 冻结的是"残差"部分（不重要的方向），而非原始权重
  • 收敛更快，最终效果优于随机初始化的 LoRA

6.5 AdaLoRA — 自适应秩分配

  • 使用奇异值分解参数化：W = W₀ + PΛQ
  • 训练过程中动态裁剪不重要的奇异值（设为零）
  • 重要层分配更多秩，不重要层分配更少秩，在总参数预算相同的情况下效果优于均匀分配

命名由来

LoRA = Low Rank Adaptation（低秩适配）。名称源自线性代数中的「低秩矩阵分解」—— 一个大矩阵可以被分解为两个小矩阵的乘积，只要它的秩（rank）足够低。

七、多 LoRA 服务与多任务热切换

多适配器服务的关键取舍是"合并"还是"动态加载"：合并把旁路乘回主干，推理零额外开销但一个进程只能服务一个任务；动态加载让所有任务共享同一份常驻主干、按请求挂载各自的适配器，代价是每步要多做一次小矩阵运算。请求量分散在很多任务上时，后者几乎总是更省。

7.1 多任务热切换

基础模型 (LLaMA-2-7B) ← 只加载一次 │ ├── + LoRA-客服 (16 MB) → 客服场景 ├── + LoRA-代码 (16 MB) → 代码生成 ├── + LoRA-翻译 (16 MB) → 翻译任务 └── + LoRA-医疗 (16 MB) → 医疗问答 切换任务：只需替换 16 MB 的 LoRA 权重，无需重新加载 14 GB 的基础模型

每个任务拥有独立的 LoRA adapter（仅数十 MB），共享同一份基座模型，按需加载/卸载；多租户场景中每个用户/任务可以有自己的 LoRA。adapter 还可以版本管理、快速分发、A/B 测试。相比全参数微调（每个任务一份完整模型，存储和切换成本极高），这是 LoRA 的杀手级优势。

7.2 合并 vs 动态加载

策略做法优点缺点
合并 (Merge)W = W₀ + BA，存为完整模型推理零开销；部署简单每个 LoRA 一份完整模型；无法动态切换
动态加载推理时按请求加载 LoRA adapter共享基座节省显存；支持热切换需要框架支持；有少量计算开销

还有一种融合用法：将多个 LoRA 加权合并（W' = W + α₁B₁A₁ + α₂B₂A₂），实现多能力融合。

7.3 S-LoRA：服务数千个适配器

S-LoRA (Serving thousands of LoRA adapters) 解决大规模 LoRA 服务的核心挑战：

  • 统一分页管理：将 LoRA adapter 存储在统一的内存池，按需加载到 GPU
  • 异构批处理：同一 batch 内不同请求可以使用不同的 LoRA adapter
  • 定制 CUDA 内核：高效的 batched LoRA 计算（避免逐个计算）
  • 可在单 GPU 上同时服务数千个 LoRA adapter

7.4 Punica：SGMV 内核

  • SGMV (Segmented Gather Matrix-Vector) 内核将不同 LoRA 的计算融合为一个 GPU kernel，避免多次 kernel launch
  • 每个请求映射到对应的 LoRA 参数段
  • 实现了近乎线性的吞吐量扩展

7.5 vLLM 多 LoRA 支持

vLLM 作为目前最流行的 LLM 推理框架，原生支持多 LoRA 服务：

# vLLM 多 LoRA 服务示例
from vllm import LLM, SamplingParams
from vllm.lora.request import LoRARequest

llm = LLM(model="base_model", enable_lora=True,
          max_loras=4, max_lora_rank=64)

# 不同请求使用不同 LoRA
output1 = llm.generate("Hello", sampling_params,
    lora_request=LoRARequest("adapter_1", 1, "path/to/lora1"))
output2 = llm.generate("你好", sampling_params,
    lora_request=LoRARequest("adapter_2", 2, "path/to/lora2"))
  • 支持在连续批处理（continuous batching）中混合不同 LoRA 请求
  • max_loras：GPU 同时驻留的最大 LoRA 数量；max_lora_rank：支持的最大秩
  • LoRA 权重在 GPU 显存和 CPU 内存之间按需换入换出
  • Merge 简单但笨重；动态加载灵活但需要框架支持
  • S-LoRA 用统一分页 + 异构批处理实现数千 LoRA 并发；Punica 的 SGMV 内核将多 LoRA 计算融合为单次 kernel launch
  • vLLM 支持多 LoRA + continuous batching，是生产环境首选

八、其他 PEFT 方法

8.1 Prefix Tuning

在每层 Transformer 的 Key 和 Value 前拼接一组可训练的连续前缀向量：

  • 每层都有独立的前缀参数（而非只在输入层）
  • 前缀长度通常 10 ~ 100 个虚拟 token
  • 通过一个小型 MLP 重参数化前缀，训练更稳定
  • 可训练参数极少（~0.1%），但在生成任务表现良好

8.2 Prompt Tuning 与 P-Tuning

  • Prompt Tuning（Lester et al.）：只在输入 embedding 层前拼接可训练向量，比 Prefix Tuning 更简单；随模型规模增大，效果趋近全参数微调
  • P-Tuning v1：用 LSTM/MLP 生成连续提示嵌入，弥补直接优化 embedding 的不稳定性
  • P-Tuning v2：类似 Prefix Tuning，在每层都加可训练前缀，规模更大的模型上效果更好

8.3 Adapter

在 Transformer 的 FFN 后（或注意力层后）插入小型瓶颈网络：

h = h + f(h · W_down) · W_up W_down ∈ ℝ^(d×m), W_up ∈ ℝ^(m×d), m ≪ d（瓶颈维度通常 64 ~ 256）
  • 残差连接保证初始输出不变
  • 缺点：增加了串行计算路径，有少量推理延迟，且无法合并进原始权重

8.4 IA³

  • 学习三个缩放向量（标量乘法）：分别作用于 K、V 和 FFN
  • 可训练参数极少（仅为向量），远少于 LoRA
  • 适合 few-shot 场景，但在复杂任务上表现可能不如 LoRA

九、LoRA vs 全参数微调

9.1 性能差距

  • 简单任务（分类、摘要）：LoRA ≈ 全参数微调（差距 < 1%）
  • 复杂任务（数学推理、代码生成）：LoRA 可能落后 1~3%，但通过增大 r 可以缩小差距
  • 数据量大 + 任务复杂 → 全参数微调仍有优势
  • 实践中 QLoRA 在 65B 模型上的表现可以匹敌在 16-bit 全参数微调的 ChatGPT 级别模型

生产案例

生产验证：某企业用 LoRA（r=8）微调 Llama 2 7B 做客服对话，相比全量微调：(1) 训练显存从 80GB（单卡 A100）降至 16GB（消费级 RTX 4090 即可），硬件成本降低 80%；(2) 训练时间从 3 天缩短至 4 小时（可训练参数从 7B 降至 4.2M，减少 99.94%）；(3) 推理质量：在领域对话评测上，LoRA（r=8）得分 87.3/100，全量微调 89.1/100，差距仅 2%。关键发现：r 从 4 增至 8 时质量提升显著（+5 分），但从 8 增至 16 仅提升 0.8 分 — 说明 r=8 是"甜点值"。QLoRA（4-bit 量化 + LoRA）进一步将显存需求降至 6GB，在 RTX 3060 上即可微调 7B 模型。

高频问答

LoRA 的参数量减少 97%，为什么效果不会大幅下降？
因为微调时的权重变化量 ΔW 具有低秩特性。研究表明，预训练模型已经学到了一个好的初始化点，微调只需要在少数几个方向上做小幅调整。ΔW 的有效信息集中在一个低维子空间中，用 r=8 的秩就能捕获大部分信息。实验证明，LoRA (r=8) 在大多数下游任务上能达到全量微调 95%+ 的效果。
为什么 target_modules 通常选择注意力层？
注意力层（q_proj, v_proj, k_proj, o_proj）是 Transformer 中最核心的计算组件，它们直接控制模型「看什么」和「怎么组合信息」。微调本质上是调整模型的注意力模式，因此对注意力层做 LoRA 效果最显著。原始论文的最小方案是仅对 q_proj + v_proj 做适配，推荐方案是 QKVO 四个投影全上。对 FFN 层做 LoRA 收益相对较小，但参数开销更大。如果资源充足，可以加上 gate_proj 和 up_proj 来进一步提升效果。
LoRA 推理时的额外开销是多少？
零额外开销。LoRA 的核心优势之一：训练完成后，可以将 B×A 合并回原始权重矩阵（W' = W + B×A），推理时直接使用 W' 做矩阵乘法，和不微调的模型推理完全相同。这意味着 LoRA 只在训练阶段节省了资源，推理阶段的延迟和吞吐量不受影响。
rank 设多大合适？怎么选择？
经验法则：(1) 简单任务（分类、格式化输出）r=4~8 足够；(2) 复杂任务（创意写作、多步推理）r=16~32 更好；(3) 不建议超过 64，收益递减且容易过拟合。选择方法：先用 r=8 做基线，如果效果不够，逐步增大到 16、32，观察验证集指标变化。如果 r 从 8 增到 16 效果提升很小，说明 8 已经足够。如需自动分配秩，可用 AdaLoRA：它以 SVD 形式（PΛQ）参数化 LoRA，训练中动态裁剪不重要的奇异值，自动给不同层分配不同的有效秩，在总参数预算相同的条件下比统一秩分配效果更好。使用大 r 时建议搭配 rsLoRA（α/√r 缩放）。
QLoRA 和 LoRA 有什么区别？
QLoRA = 量化（Quantization）+ LoRA。具体做法：(1) 将基础模型量化为 4-bit（NF4 量化），大幅减少显存占用；(2) 在此基础上做 LoRA 微调（LoRA 参数仍用 FP16/BF16）。QLoRA 的三大技术创新：NF4 量化（基于正态分布分位数的信息论最优 4-bit 方案，比 INT4/FP4 更匹配预训练权重分布）、双重量化（对量化缩放因子再做 FP32→FP8 量化，额外节省 ~0.37 bit/参数）、分页优化器（GPU 显存不足时自动将优化器状态分页到 CPU 内存，防止 OOM）。效果：单张 24GB 显存的 GPU 就能微调 65B 参数的模型，而全量微调需要 780GB 显存。精度损失很小（~1-2%），但显存节省 10 倍以上。
多个 LoRA 适配器能同时使用吗？
可以。因为基础模型参数冻结不变，不同的 LoRA 适配器（A₁B₁, A₂B₂...）是独立的。有两种使用方式：(1) 动态切换 —— 根据请求类型加载不同的 LoRA，基础模型只加载一次；(2) 融合使用 —— 将多个 LoRA 加权合并（W' = W + α₁A₁B₁ + α₂A₂B₂），实现多能力融合。S-LoRA（统一分页 + 异构批处理，单 GPU 服务数千 adapter）与 Punica（SGMV 内核将多 LoRA 计算融合为单次 kernel 调用）等系统已把多 LoRA 服务推向生产级；SGLang、vLLM 等推理框架也已原生支持 LoRA 动态加载。
LoRA 中 A 和 B 矩阵的初始化策略是什么？为什么这样设计？
A 用高斯随机初始化，B 用全零初始化。这样保证训练起始时 BA = 0，LoRA 分支输出为零，模型完全等价于冻结的预训练模型。训练过程是从预训练权重出发，逐步学习增量更新，避免了初始扰动导致的不稳定性。这个设计灵感类似于残差学习：学习的是"改变量"而非"完整映射"。
LoRA 的 α（lora_alpha）参数有什么作用？怎么选？
α/r 作为 LoRA 更新的缩放因子，控制更新强度。工程价值：解耦了 r 和学习率 —— 当改变 r 时，只需等比例调整 α，无需重新搜索学习率。常见设置：α = 2r ~ 4r（如 r=8, α=16~32）。α 越大更新越激进，越小越保守。rsLoRA 变体使用 α/√r 替代 α/r，在大秩场景下表现更稳定。
DoRA 和 LoRA 的核心区别是什么？
DoRA 在 LoRA 基础上引入了权重分解：将权重矩阵的更新分解为幅度 (magnitude) 和方向 (direction) 两个独立分量。公式：W' = m · (W₀ + BA) / ‖W₀ + BA‖_c，其中 m 是可训练的幅度向量。灵感来源于 Weight Normalization 技术。这种解耦使得模型可以独立调整"更新多大"和"往哪更新"，在多个基准上比标准 LoRA 提升 1~3%，接近全参数微调效果。
Adapter 和 LoRA 的主要区别是什么？各自优劣？
Adapter：在 Transformer 层中插入额外的瓶颈网络（串行路径），增加了推理延迟，不能合并到原始权重中。LoRA：在现有权重矩阵旁添加并行的低秩分支，训练后可以 merge 回原始权重，推理零开销。LoRA 的优势：可合并、无推理延迟、多任务切换方便；Adapter 的优势：结构灵活，可以加入非线性激活函数，理论表达能力更强。实践中 LoRA 因其"推理零开销"特性而成为主流选择。
Prefix Tuning 和 Prompt Tuning 有什么区别？
Prompt Tuning：只在输入 embedding 层前拼接可训练的连续向量，参数极少，简单高效。Prefix Tuning：在每一层 Transformer 的 Key 和 Value 前都拼接可训练前缀，参数更多，表达能力更强。P-Tuning v1：用 LSTM/MLP 生成输入层的连续提示，解决直接优化 embedding 的不稳定问题；P-Tuning v2：类似 Prefix Tuning，在每层加深层前缀，效果接近全参数微调。这些方法在大模型上效果接近，但都不如 LoRA 灵活（无法 merge、推理有开销）。
