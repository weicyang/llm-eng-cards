ST08 · 多意图识别工程实践

Softmax 互斥陷阱 / Sigmoid 多标签脱钩 / BCE+Focal Loss 长尾训练 / PR 曲线逐标签阈值 / 状态机+GNN 上下文管控 / 混合路由

多意图识别的难点从来不是"模型不够准"，而是"决策机制从根上错了"。Softmax 把 K 个意图塞进一场零和竞选，概率总和被钉死为 1，用户的第二、第三个诉求注定被压下去。把单选题改成 K 道独立判断题（Sigmoid 脱钩），再依次补上长尾训练（Focal Loss）、逐标签阈值校准（PR 曲线）和意图生命周期管理（状态机+GNN），多意图系统才算立起来。

一、问题定义："单选"思维的两次事故

用户在真实世界里从不出单选题。"帮我查下明天去上海的航班，顺便订个酒店"——一句话两个诉求，任何"只许输出一个答案"的机制都会系统性地丢掉一半需求，而且丢得悄无声息。

把用户一句话映射到预定义意图类别，是对话系统的入口决策，业界常称为 NLU（自然语言理解，Natural Language Understanding，负责把自由文本变成结构化指令）。早期系统默认一个前提：一句话只干一件事。这个前提对应 单标签分类——一条样本只许打一个类别，K 个意图互斥。它对应到数学上就是 Softmax 输出：所有意图的概率加起来恒等于 1。而真实流量的统计结论恰恰相反，出行、客服、车载等场景中约 15%~25% 的查询天然携带两个以上意图，这类场景属于 多标签分类（multi-label classification，一条样本可同时命中多个类别，各类别独立判定）。把多标签问题硬塞进单标签模型，就是第一类事故的根源。

用户："查明天去上海的航班，顺便把酒店也订了" ┌────────────────────── Softmax 单标签输出 ──────────────────────┐ │ │ │ 查航班 ████████████████░░░░░░░░ 0.52 ← 胜出，被执行 │ │ 订酒店 ████████████░░░░░░░░░░░░ 0.41 ← 被截断（也是真意图） │ │ 查天气 ███░░░░░░░░░░░░░░░░░░░░░ 0.07 │ │ ────────────────────────────────────────────────────────── │ │ 概率总和被强制 = 1：两个意图互相"抢分"， │ │ 第二个意图的分数被结构性压低，永远到不了执行线 │ └──────────────────────────────────────────────────────────────┘ 结果：酒店被静默漏掉 → 用户落地后才发现没订房，体验事故

这类事故有个专门的名字：漏召回——用户明确表达了某个意图，系统却没有识别出来。它的阴险之处在于不报错、不崩溃，只是"少做了一件事"，离线评测里如果被双意图样本占比稀释，整体准确率看起来还挺高，直到客服工单积累成山才暴露。

第二类事故来自矫枉过正：既然小模型搞不定，干脆全量大模型，用 Prompt 让 LLM 直接吐 JSON 意图列表。这条路在 demo 里非常顺滑，上了高并发生产线就露出三个短板：推理延迟数百毫秒到数秒，Token 成本随流量线性燃烧，输出还不可控——JSON 格式偶发错乱、多轮对话里上一轮的旧意图残留进本轮结果、后端解析直接崩溃。

🏭 生产案例一 · 漏召回的代价是怎么被发现的。某 OTA 平台语音助手上线初期用 21 类 Softmax 单标签模型，"查航班+订酒店"这类组合查询的双意图漏召回率高达 18.6%。由于漏掉的是"订酒店"这种高客单价动作，事故没有体现在 NLU 准确率日报里（整体准确率 93.2% 看起来很健康），而是三周后从客服侧引爆：每周约 2,300 通"为什么没帮我订酒店"的来电，客服补偿成本每周约 8.5 万元。复盘结论：只要输出层是 Softmax，双意图漏召回就是结构性的，换骨干网络、加训练数据都救不了。

多意图的工程盲区清单

除了输出层选型，多意图系统还有一串单标签时代不存在的工程问题：多标签头的训练样本天然是"一条样本多个标签"，标注成本更高；意图频次长尾更严重（热门意图占八成流量）；每个意图的错误代价不同（漏掉"取消订单"和漏掉"查天气"完全不是一个量级），阈值不可能一刀切；多轮对话里意图还有生命周期——被打断的意图要能挂起和恢复。这些问题分别对应后面的四道防线。

二、防线一：Sigmoid 架构脱钩

把 K 个意图的"一场竞选"拆成 K 场"独立公投"：每个意图接自己的 Sigmoid 二分类头，各判各的，互不抢分。改造只在输出层，骨干网络一行不用动。

架构脱钩的核心动作只有一处：输出层从单个 Softmax 换成 K 个独立的 Sigmoid 二分类。编码层（BERT/DeBERTa 一类预训练模型）照常输出句子向量 h，之后接 K 个独立的线性头，每个头输出一个 logits（模型输出的未归一化实数分数，尚未映射到概率），再各自过一个 Sigmoid 映射到 [0,1]。这样每个意图得到的是"这句话属于该意图的独立概率"，K 个概率之间没有任何求和约束——查航班 0.91 和订酒店 0.87 可以同时成立。

共享编码层（BERT / DeBERTa 骨干） 句子向量 h ∈ R^d │ ┌───────────────┼───────────────┐ ▼ ▼ ▼ [W_航班] [W_酒店] [W_天气] … K 个独立线性头 │ │ │ z_航班 z_酒店 z_天气 各自独立的 logits │ │ │ sigmoid sigmoid sigmoid 每个标签独立压到 [0,1] │ │ │ 0.91 0.87 0.12 │ │ │ 过阈值 θ_航班 过阈值 θ_酒店 低于 θ_天气 ▼ ▼ ✗ 查航班 ✓ 订酒店 ✓ 查天气 ✗ 要点：K 个 Sigmoid 分支共享同一份句子表示， 但判定彼此独立 —— 不存在"概率总和=1"的零和竞争

训练目标随之从交叉熵换成 BCE（Binary Cross-Entropy，二元交叉熵）：把每个标签位当成一道独立的二分类题逐位算损失，再对 K 位求和。一条"查航班+订酒店"的样本，标签向量是 [1,1,0,…]，查航班位和订酒店位各自贡献正样本损失，其余位贡献负样本损失。至此，"多意图"在数学上被彻底还原成"多个二分类"，互斥假设被连根拔掉。

注意一个常见误解：Sigmoid 脱钩不是放弃深度模型换成规则，也不是把模型换成 LLM，它只是把"输出层 + 损失函数"从单标签语义换成多标签语义。社区里关于意图分类的横向对比结论相当一致：编码器微调方案单请求推理在毫秒~百毫秒级、可 CPU 部署、可高并发；LLM 方案单请求数百毫秒起步、成本随量线性涨，但胜在零样本扩展和多轮理解。两者的分工问题留到第六节展开。

🏭 生产案例二 · 只换输出层能赚多少。某出行客服中心把 32 类 Softmax 模型改造为 32 头 Sigmoid + BCE：骨干不变、数据重新按多标签标注（双意图样本占比 17%）。改造后双意图样本召回率从 61% 提升到 94%，而误触发率维持在 1.1% 没有抬头；单请求推理延迟仍为 12ms，QPS 容量不变。整个改造的工程投入约 3 人周，其中 2 人周花在历史数据的多标签重标注上——这也说明多意图改造的第一成本是数据，不是模型。

脱钩带来的新问题

Sigmoid 解决互斥，同时引入两个新麻烦：一是 K 个二分类各自独立，如果两个意图在业务上互斥（如"下单"与"取消订单"），模型可能同时点亮两者，冲突消解必须放到后处理做；二是 BCE 对每个标签位一视同仁，高频意图的海量负样本会淹没稀有意图的学习信号——这正是第二道防线要解决的事。

三、防线二：BCE + Focal Loss 摆平长尾

意图分布永远是长尾的：前十个热门意图吃掉八成流量。普通 BCE 里，稀有意图的微弱损失信号被海量"简单负样本"的梯度冲走，模型干脆躺平不学。Focal Loss 的做法是给损失乘一个"难度调节旋钮"：已经学会的样本贡献趋近于零，学不会的样本保留全额火力。

Focal Loss 由 Lin 等人在 2017 年为解决目标检测中前景背景 1:1000 的极端不平衡而提出，其形式是在交叉熵前乘一个调制因子：

FL(p_t) = −α_t · (1 − p_t)^γ · log(p_t)　　（γ≥0，γ=0 时退化为普通交叉熵）

其中 p_t 是模型对正确类别给出的概率，γ 是聚焦参数（focusing parameter）。直觉上：当一个样本已经被模型高置信判对（p_t→1）时，(1−p_t)^γ 趋近 0，这条样本几乎不再产生梯度；而难样本（p_t→0）的调制因子趋近 1，损失原封不动。以默认 γ=2 为例，p_t=0.9 的"已学会"样本损失权重只剩 (0.1)²=1%，而 p_t=0.1 的困难样本保留 81% 权重——训练注意力被整体从"重复刷已会的题"转向"死磕不会的题"。α_t 则是类别平衡因子，给稀有标签再加一层显式权重。在多标签设定下，Focal Loss 对每个标签位独立计算再求和，与 Sigmoid + BCE 的框架无缝衔接。

γ 取值调制强度行为特征适用场景
0无退化为普通（α 加权）交叉熵类别基本平衡时的对照基线
1线性轻度聚焦，训练较稳中等不平衡（1:10~1:50）
2平方社区默认值，兼顾聚焦与稳定严重不平衡（1:100 级），首选起点
5指数级几乎只看最难样本，易抖动极端不平衡（1:10⁴ 级），需配合大 batch

不平衡工具箱：不是二选一

Focal Loss 不是孤军作战。工程上常见的组合拳是：损失侧用 Focal Loss 聚焦难样本，数据侧对稀有意图做重采样或用大模型改写扩充训练句（同一意图换说法生成新样本），评估侧改用 macro-F1（对每个意图分别算 F1 再取平均，稀有意图与热门意图权重相同，防止被高频类稀释）。三者解决的是同一问题的不同侧面：损失权重、样本数量、度量口径。

手段作用层优点风险
过采样 / 重采样数据简单直接，不动模型稀有句被重复背诵，过拟合；合成样本语义漂移
类别权重（α）损失一行配置，显式补偿稀有类权重过猛会把热门意图拉垮
Focal Loss（γ）损失按"难度"而非仅按"频次"聚焦会扭曲输出概率的校准度，阈值需重新标定
LLM 改写扩充数据零成本造出多样化说法，冷启动利器生成句可能偏离真实用户表达分布
🏭 生产案例三 · 长尾意图是怎么活过来的。某票务平台的 47 类多标签模型中，"改签""开发票""行程单补寄"三类合计流量占比不足 3%，纯 BCE 训练下这三类的平均召回只有 41%，用户只能转人工。改为 α 加权 Focal Loss（γ=2，α 按标签频次倒数归一化）+ 稀有类 2 倍过采样 + 用大模型对每类扩写 500 条同义说法后，三类长尾意图平均召回升到 83%，整体 macro-F1 从 0.72 提升到 0.83，而热门意图的 F1 只回落了 0.4 个百分点——长尾提升不是零和代价，关键是评估口径要换成 macro 才能看见。

Focal Loss 改的是"模型愿意从哪学"，不是"数据里有什么"。它变不出不存在的样本，所以极稀有意图仍然需要数据增强配合；它也会顺手扭曲概率校准，所以下一节的阈值校准必须在换损失之后重新做一遍。

四、防线三：动态阈值决策

Sigmoid 输出只是"分数"，不是"决定"。把分数变成执行动作的那条线叫阈值，而 0.5 这个默认值几乎从不最优——它假设两类错误代价相等、分布永不漂移，这两个假设在生产里同时不成立。

多标签模型的决策规则是：对每个标签位，预测概率超过该标签的阈值 θ 就点亮。阈值是训练后独立于模型的决策层配置，改阈值不动模型权重，却能整体平移精确率与召回率的权衡——阈值调高，误触发减少、漏召回增多；调低则反之。默认 0.5 只在"类别平衡且两类错误同价"的理想世界成立，而意图系统里这两条全不满足：漏掉"退票"的代价远大于误触发一次"查天气"。因此成熟系统一律采用逐标签阈值——每个意图一条 θ，各按各的业务代价定。

用 PR 曲线找每个意图的最优点

标定方法是在验证集上扫描：对每个意图画出 PR 曲线（Precision-Recall 曲线，精确率随召回率变化的轨迹，比 ROC 更适合不平衡场景），然后按目标取点。代价对称的意图取 F1 最大点；误触发代价高的意图（如直接扣款的"下单"）向精确率端偏移；漏召回代价高的意图（如"取消续费"）向召回端偏移。最终产出一张"意图→阈值"配置表，与模型版本绑定发布。

阈值漂移：为什么标定不是一次性的

阈值漂移指模型输出的概率分布随时间偏移，导致原本标好的阈值失准。触发源比想象中多：上游 ASR 换版本导致输入文本分布变化、模型重训后分数尺度改变、季节性话术迁移（节假日"订票"说法突变）。漂移不会报错，只会让误触发率或漏召回率缓慢爬升。对策是把"预测分数分布"本身纳入监控：对每个意图维护一份基线分布，线上用 KL 距离或分位数偏移做比对，超阈值即告警并触发重标定流程。更稳妥的系统还会配 置信度（confidence，模型对判断的自评分）分级策略：高分直接执行，中分向用户确认（"您是想订酒店吗？"），低分触发追问，把边界样本的决策权交还给人。

🏭 生产案例四 · 一次上游升级引发的误触发风暴。某语音助手上游 ASR 升级后，"帮我看看"这类口头禅被更完整地转写出来，"查天气"意图的预测分数整体右移，固定阈值 0.5 下误触发率一周内从 1.2% 爬升到 7.8%——系统开始在对话里莫名其妙播报天气。分数分布监控在第 25 分钟捕捉到 KL 距离越限告警，值班同学按预案用最近三天带标注样本重扫 PR 曲线，把 θ_天气 从 0.50 上调到 0.63，两小时内误触发率回落到 1.4%。这次事故的结论被写进团队规范：任何上游组件升级，必须附带下游阈值重标定检查项。

阈值是"模型世界"和"业务世界"之间的翻译层。模型只能回答"多像"，业务要的是"敢不敢执行"——这两个问题之间的汇率，就是那张逐标签阈值表，而且汇率会随行情波动。

五、防线四：意图生命周期与标签关联

单轮识别只解决"这句话想干什么"，多轮对话还要回答"上一句的意图现在算不算数"。意图不是识别完就结束，它有生命周期：待执行、进行中、已完成、已过期；标签之间也不是各自孤立，"查航班"之后大概率跟着"订酒店"，这种关联要么显式建模，要么变成事故。

多轮场景里，每一轮都可能冒出新意图、打断旧意图或恢复旧意图。研究界把意图切换归纳为三种模式：完成后切换（上一个意图收尾了才开始下一个）、完成前切换（流程走到一半被新意图打断）、不切换（继续当前意图）。若无显式状态管理，系统要么"失忆"（被打断后忘了原任务），要么"残留"（把上一轮的意图误并进本轮）。工程解法是给每个意图实例建 状态机（State Machine，用有限个状态和转移规则描述对象生命周期的建模方式），意图从被识别起就进入"待执行→进行中→完成/过期"的轨道，被打断时转入"挂起"而非销毁，用户回头时可以原地恢复。

状态机管"纵向"的时间线，标签之间的"横向"关联则需要另一层建模。真实标签体系里至少存在三类关系：正相关共现（查航班与订酒店经常一起出现）、互斥（下单与取消订单不能同时成立）、时序依赖（先改签后补差价）。大厂实践中用 GNN（Graph Neural Network，图神经网络，在图结构上做消息传递学习节点表示）把标签共现统计构成图，让模型在预测时感知"点亮 A 会抬高 B 的先验"，并在解码后处理里对互斥对做冲突消解。轻量替代方案是维护一张标签共现矩阵加一组硬规则，覆盖 80% 的关联场景。

状态机负责让系统"记得住"，关联建模负责让系统"想得到"。前者防止意图在时间线上丢失，后者利用意图之间的结构知识做主动服务——两者合起来，多意图识别才从"单轮分类器"升级成"对话理解系统"。

六、混合路由：四道防线组装成生产系统

四道防线各管一段，真正上线时还要回答一个问题：大模型放在哪？答案不是"谁替代谁"，而是分层路由——规则接高频、编码器扛主流量、大模型做兜底和冷启动，各干各最擅长的事。

生产级多意图系统的完整链路是一个三层漏斗加一条数据回流：最前面是规则快车道，用关键词/正则承接表达极固定的高频指令（毫秒内返回）；中间是 Sigmoid 编码器主力层，承担九成以上流量的多标签判定；最后是 LLM 兜底层，只在三种情况出场——全部标签概率都低于阈值（低置信）、互斥冲突无法自动消解（歧义）、遇到训练集没见过的新意图（冷启动）。LLM 的判定结果连同原始语料回流标注，成为下一轮编码器训练的增量数据，形成 数据飞轮（data flywheel，线上难样本自动沉淀为训练数据、模型迭代再反哺线上的正循环）。

遗留挑战

四道防线并非终点，仍有三块硬骨头：其一，极长尾意图（占比不足 0.1%）即使 Focal Loss + 增强也难学稳，业界在探索"大模型上下文理解 + 少样本微调"的组合，用 Few-shot（少样本学习，仅凭几条示例完成新任务识别）能力降低标注依赖；其二，意图标签体系随产品演进持续增删，增量学习与灾难性遗忘的平衡没有银弹；其三，隐含意图（"三楼连廊的灯坏了"其实是报修）需要常识推理，编码器力有不逮，只能靠 LLM 兜底层逐步消化。这些方向共同指向同一个趋势：编码器负责"快而稳"，大模型负责"广而深"，两者的边界由数据飞轮持续重画。单轮意图的完整处理流程与降级细节，可参阅姊妹篇《ST07 · 意图识别三层漏斗架构》。

判断一套多意图系统是否成熟，不用看模型多大，看三件小事：双意图样本的召回率单独统计了吗？阈值表随模型版本走了吗？被打断的意图能被捡回来吗？三件都做到，系统才算从"能识别"进化到"能托付"。

Q&A

Softmax 为什么从原理上就不适合多意图？

Softmax 的定义要求所有类别概率之和恒等于 1，这在数学上把 K 个意图变成零和竞争：任何一个意图的分数上升，必然以其他意图的分数被压低为代价。当一句话同时携带两个意图时，概率质量被分摊，两个意图都拿不到足够高的分数，排第二的意图被系统性截断，形成结构性漏召回。这不是数据不够或模型不深的问题，换骨干、加数据都无法修复，因为归一化约束写死在输出层里。正确的做法是把每个意图当成独立的二分类问题，用 Sigmoid 各自输出 [0,1] 上的独立概率，概率之间不再有求和约束，两个意图可以同时高置信成立。

Sigmoid 拆成独立二分类后，互斥意图同时点亮怎么办？

这是 Sigmoid 方案的已知代价，解法放在后处理而不是模型里。工程上做三层消解：第一层维护一张互斥关系表（如下单与取消订单），当互斥对被同时点亮时，按上下文时态线索（"我刚才下的单不要了"偏向取消）和两者置信度差值择一；第二层当置信度差距小于阈值（如 0.1）时不硬判，转入澄清流程向用户追问；第三层把冲突样本自动回流标注，作为难例进入下一轮训练。之所以不在模型内部用约束强行互斥，是因为那等于把 Softmax 的零和假设请回来——多数意图对并不互斥，只在少数业务上冲突，用后处理规则定向处理比全局约束更精准。

Focal Loss 的 γ 和 α 怎么定？会不会把概率校准搞坏？

社区默认起点是 γ=2、α 按标签频次倒数归一化，这个组合在 1:100 级别的不平衡下被反复验证有效；不平衡越极端可以把 γ 往 3~5 调，但 γ 越大训练越抖动，需要更大的 batch 和更细的学习率。α 的直觉是给稀有标签的损失直接加杠杆，注意别加太猛，否则热门意图的精度会被反噬。关于校准：Focal Loss 通过压制易样本重塑了损失地形，输出概率的校准度确实会变形，所以换用 Focal Loss 之后，基于旧概率标定的阈值表全部作废，必须在验证集上重新扫 PR 曲线标定每个标签的阈值——这一步漏掉是多意图系统上线后误触发抬头的常见原因。

逐标签阈值为什么不统一取 F1 最优点？

F1 最优点隐含一个假设：误触发和漏召回的代价相等。这个假设只对部分意图成立。涉及资金或不可逆操作的意图（下单、转账、取消续费），误触发一次的代价可能是客诉、退款甚至资损，阈值应向精确率端偏移，宁可让用户多说一遍；而信息查询类意图（查天气、查物流）误触发代价极低，漏了反而让用户觉得系统"没听懂"，阈值应向召回端偏移。所以成熟系统的阈值表是三类取点混用的：普通意图取 F1 最优点，高危意图按代价敏感取点，查询类意图放宽召回。代价表需要产品侧参与定义，这也是阈值标定不是纯算法工作的原因。

阈值漂移为什么防不住？监控应该盯什么信号？

阈值漂移的根源是"分数分布会变，而阈值是静态配置"。典型触发源有四类：上游组件升级（ASR 换版本导致转写文本分布变化）、模型重训后分数尺度整体平移、季节性与活动期话术迁移、新渠道流量接入。漂移是渐进的，单日指标曲线看不出异常，等投诉爆发往往已经积累了一两周。监控上建议盯三组信号：每个意图预测分数的分布与基线的 KL 距离或分位数偏移（最灵敏的前置指标）、线上抽样的分意图精确率/召回率（滞后但直接）、下游业务侧的反向行为率（如执行后用户立即否认的比例）。任一信号越限就触发阈值重标定流程，重标定只改配置不改模型，两小时内可完成。

为什么不干脆全用大模型做意图识别？边界在哪？

大模型做意图识别有三个硬约束：延迟（单请求数百毫秒到秒级，高并发下尾延迟更差）、成本（Token 费用随 QPS 线性增长，高峰期账单失控）、可控性（生成式输出的格式需要强校验，旧意图残留和格式错乱是偶发但必然的事故）。而编码器方案在这三点上全面占优：毫秒级推理、可 CPU 部署、输出是确定的概率向量。但大模型有编码器给不了的东西：零样本识别新意图、多轮上下文的常识推理、隐含意图理解。所以边界很清晰——稳定、高频、已知的意图走编码器，长尾、新增、模糊的流量走大模型兜底，后者的判定结果回流成前者的训练数据。生产实测中这套混合路由能把大模型承担的流量压到 10% 以内，成本与体验同时达标。

GNN 标签关联建模是不是过度设计？什么时候该上？

多数团队不该一上来就上 GNN。标签关联建模的收益前提是：标签体系足够大（几十个以上）、共现结构足够强（存在稳定的"查航班→订酒店"类链路）、且业务愿意消费这些关联（做主动推荐或冲突消解）。在这之前，一张标签共现统计矩阵加一组手写规则就能覆盖大部分场景，维护成本也低。GNN 的价值在规模化之后才显现：当标签对数量到达数百、人工规则写不过来时，用图结构让模型自动学习标签间的消息传递，能顺带改善稀有意图的预测（借相邻高频意图的信号）。判断标准很简单：如果"冲突消解规则表"已经长到没人敢动，就是该上学习式建模的信号。

全新意图一条训练数据都没有，冷启动怎么做？

冷启动的标准路径分四步。第一步让 LLM 兜底层直接上岗：新意图先不改编码器，线上命中不了任何已知标签的流量转给大模型，用少量示例描述（Few-shot）让它判定，当天就能接住新意图。第二步数据回流：兜底层的判定结果连同原始语料进入标注队列，人工抽检修正后沉淀为带标数据。第三步用大模型对少量真实样本做改写扩充，把一个意图的几十条种子句扩成数百条多样化说法。第四步增量重训编码器并把新标签头接入阈值标定流程，新意图从此走主力层。实测这套流程能把新意图接入周期从纯标注路线的两周压缩到两天左右，且冷启动期间用户体验不掉线。
