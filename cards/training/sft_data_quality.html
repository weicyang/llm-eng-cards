W07 · SFT 数据质量评估体系

困惑度过滤 / 奖励模型打分 / LLM-as-Judge / 交叉一致性检验 / 五段式清洗 / 训练中诊断

SFT 数据质量评估的本质，是给模型"只喂消化得了、有营养的食物"：先用便宜的规则洗掉沙石（格式、重复、毒性），再用昂贵的模型信号挑出好粮（PPL、奖励模型、Judge），最后在训练过程中盯着它的"消化指标"（loss 走势、分组评测、风格分布）随时纠偏。

一、为什么质量是 SFT 最重要的超参数

SFT（Supervised Fine-Tuning，监督微调）是拿"指令—回复"样本对去继续训练预训练模型的过程。它本质上是一种模仿学习：模型不是在"学知识"，而是在"学教材"。教材里写什么，它就模仿什么——教材里有错别字、有前后矛盾的例题、有风格单一的范文，模型都会忠实地照单全收。所以数据质量不是一个"预处理环节"，而是 SFT 阶段最关键的一个超参数，其影响往往大于学习率、epoch 数这些训练参数。

这里有一个容易被忽略的机制：低质量样本带来的不是"学不到东西"，而是互相矛盾的梯度信号。如果第 142 条样本告诉模型"这类输入应该答 A"，第 891 条几乎相同的输入却标注为 B，模型在两处都做了参数更新，最终学到的是一个折中的、两头不靠的行为。这种冲突在数据收集阶段完全不可见，却会在训练时转化为验证指标停滞、输出行为不稳定。数据清洗的价值，就是在这些矛盾进入梯度之前把它们拦截掉。

脏数据不是"没用"，而是"有毒"——它贡献的梯度会与好数据互相抵消。清洗数据省下的不是存储，而是后面 3~5 倍的调参排查时间。

质量优于数量：社区实验的一致结论

"数据越多越好"这个直觉在 SFT 阶段是错的。预训练需要海量文本覆盖世界知识，而 SFT 只需要几千条高质量样本就能把模型的对话格式、指令遵循、领域风格"对齐"过来。社区多组实验反复验证了这一点：

实验 / 案例数据策略结果
FineWeb-Edu（HuggingFace）用教育质量分类器从 15T token 中筛出 1.3T7B 模型下游平均分 +14.1%，远超全量未筛选的 +5.2%
DataFlow（北大 DCAI）15K 条系统治理的 SFT 样本 vs 50K 未筛选样本前者效果更好，10K 领域数据接近官方 Instruct 版本
企业领域 SFT 实践5,000 条原始数据经 IFD + PPL + 奖励模型打分取 Top，仅保留 500 条领域准确率 +25%，训练时间降为原来的 1/10
客服微调对照2,000 条未清洗直接训 vs 800 条花半天清洗后训前者 78%、调参两周无起色；后者 91%

这些数字背后的共同规律是：筛选后数据集的"信噪比"提升，比单纯堆量更能改善泛化。一个实用的经验法则是：每投入 1 小时做数据清洗，平均可以省下 3~5 小时后期的效果排查时间。当然这并不意味着数据量无关紧要——当高质量数据的供给充足时，量与质要一起抓；但在多数团队的现实约束下（标注预算有限、领域数据稀缺），先把已有的数据洗干净，性价比远高于花钱多标一批。

质量评估体系的全景架构

一套完整的 SFT 数据质量评估体系，覆盖"训练前评估 → 清洗过滤 → 训练中诊断 → 回流迭代"四个环节，且每一环节的输出都是下一环节的输入：

┌──────────────────┐ │ 原始 SFT 数据 │ 客服日志 / 人工标注 / 模型合成 / 开源数据集 └────────┬─────────┘ ▼ ┌────────────────────────────────────────────┐ │ 第一层 · 规则清洗（便宜、高召回、先跑） │ │ 格式校验 → 去重 → 异常检测 → 安全过滤 → 分布审计 │ └────────┬───────────────────────────────────┘ ▼ 典型保留率 60% ~ 70% ┌────────────────────────────────────────────┐ │ 第二层 · 模型评分（昂贵、高精度、后跑） │ │ PPL 过滤 → 奖励模型打分 → LLM-as-Judge │ │ → 交叉一致性检验 │ └────────┬───────────────────────────────────┘ ▼ ┌──────────────┐ ┌──────────────────────┐ │ 最终训练集 │ ───▶ │ SFT 训练 + 训练中诊断 │ └──────────────┘ │ loss 分离 / 任务分组 │ │ 风格固化 / 灾难性遗忘 │ └──────────┬───────────┘ ▼ 坏案例回流 → 补充标注 → 下一轮清洗

这个架构有两个设计要点。第一是成本递增、顺序固定：规则清洗几乎零成本，先跑掉大头垃圾，避免把昂贵的模型推理浪费在明显的垃圾样本上；模型评分按"便宜到贵"排序，每一层都在缩小候选集。第二是闭环：训练诊断发现的坏案例不是扔掉就完，而要回流到标注环节，成为下一轮数据迭代的输入——数据质量体系不是一次性工程，而是持续运转的飞轮。

一个反复被验证的量化结论：筛选后约 60%~70% 的高质量数据，训练效果稳定优于 100% 全量数据。某团队在千条指令数据上的对照实验中，1,000 条未筛选数据训练 3 个 epoch 的困惑度为 12.5、人工评估 6.8/10；筛掉 35% 后用 650 条同样训练 3 个 epoch，困惑度降到 9.8、人工评估升到 8.2/10。数据少了三分之一，效果反而全面更好。

二、训练前的四种自动化评分方法

规则清洗只能拦截"明显坏"的样本：格式错误、重复、乱码。但一条格式完美、内容平庸甚至暗含错误的回复，规则是抓不出来的。这就需要模型级的质量评分。主流方法有四种：困惑度过滤、奖励模型打分、LLM-as-Judge、交叉一致性检验。它们测量的东西不同、成本不同、风险也不同，实践中是组合使用而非二选一。

困惑度过滤：用"模型的熟悉程度"当筛子

困惑度 PPL（Perplexity）衡量的是模型对一段文本的"意外程度"：对回复文本逐 token 计算交叉熵损失再取指数，PPL 越高说明模型越"看不懂"这段文本。它不需要任何标注，只要一次前向推理就能对全量数据打分，是最便宜的模型级信号。

PPL(y) = exp( -1/N · Σ log p(token_i | token_<i) )

关键洞察是：最有训练价值的数据，困惑度处于中间地带。PPL 极低，说明模型对这类文本已经滚瓜烂熟，再训也没什么可学的，纯属浪费算力；PPL 极高，说明文本要么超出了模型当前的理解能力（过难的领域黑话、跨语言混杂），要么本身就是乱码、噪声、逻辑混乱的坏样本，强行喂进去反而把参数往沟里带。只有"模型能理解但尚未完全掌握"的中等 PPL 区间，才是学习的甜区。

PPL 过滤就像给学生选习题：全做会的题没有进步，全做看不懂的题只会挫败，真正提分的是"跳一跳够得着"的那部分题。

实践方案分三步：先用目标领域的基座模型对全量数据算 PPL，绘制分布直方图；再按分布定阈值——简单做法是去掉顶部 10% 和底部 10% 的极端值，稳健做法是取中位数 ±1.5 倍四分位距（IQR）作为合理区间；最后抽样人工复核两端被剔除的样本，确认阈值没有误杀。注意阈值必须跟着数据集走，不同领域、不同基座模型算出的 PPL 分布完全不同，照搬别人的绝对数值是常见错误。

奖励模型打分：比困惑度更接近人类的判断

奖励模型（Reward Model，RM）是一个在人类偏好对比数据上训练出来的打分器，输入"指令 + 回复"，输出一个标量分数。与 PPL 这种"语言模型自我视角"不同，RM 学的是"人类觉得哪个回复更好"，因此它能区分"流畅但没用"和"流畅且有用"这两种 PPL 无法区分的情况。

评估维度通常覆盖四块：有用性、准确性、安全性、格式规范。工程实现上可以为每个维度设独立分数（如指令跟随 0-3 分、回复完整性 0-2 分、领域专业性 0-2 分），其中安全性必须是一票否决项——毒性或违规内容不管其他维度多高都直接剔除。

使用 RM 需要警惕两点。第一，RM 自身有训练数据偏见：如果训练 RM 的偏好数据偏向长篇大论的回复，它会给所有长回复打高分，哪怕长只是啰嗦；第二，RM 会过时，业务数据在不断积累，建议每新增约 500 条人工标注就重新训练一次打分器，让它的判别边界跟上数据分布的变化。自建轻量 RM 的门槛并不高：用 100~200 组人工标注的优劣样本对，配对比损失即可起步。

LLM-as-Judge：最灵活但偏见最多的裁判

LLM-as-Judge 指用一个能力更强的现成大模型，按自定义评分细则（rubric）给训练样本打分。它的核心优势是维度完全可定制：准确性、完整性、指令符合度、引用规范性……业务关心什么就评什么，不需要像 RM 那样先攒偏好数据再训练。

但它带着一组著名的系统性偏见，其中最常见的是长文本偏好——裁判模型倾向于给更长的回复更高分，哪怕长只是注水。对策是在评分 prompt 中明确强调简洁性要求，例如写明"长度本身不应加分，冗长且重复的回复应扣分"，并要求裁判先给理由再给分数，抑制拍脑袋打分。此外还有位置偏见（对比评估时偏向第一个选项）和自我偏好（偏向同家族模型的输出），对比评估时交换候选顺序取平均可以缓解。

成本是另一个现实约束：用商用 API 做 Judge，百万条样本大约需要 50~100 美元。更经济的做法是分层过筛——先用本地小模型（如 7B 级别）对全量数据做粗筛，只把分数处于边缘地带的样本交给大模型裁判精判。同时要记住一条铁律：裁判的评分标准必须与你的下游业务指标对齐，如果你的真实目标是代码正确性，却让裁判按"有帮助程度"打分，筛出来的数据方向就是错的。

交叉一致性检验：用共识度衡量可靠性

标注者一致率（Inter-Annotator Agreement）指的是多个标注者（或多个模型）对同一样本给出相同判断的比例。逻辑很朴素：如果三个人对同一条回复的质量判断完全对不上，那这条样本本身就处在模糊地带，拿来训练只会引入噪声。

OpenAI 在数据工程实践中建议以 70% 一致率作为基准线：低于这条线的数据集，说明标注规范本身有歧义，应该先修规范、再补标注，而不是硬着头皮训练。交叉一致性还有第二个用途——多源数据质量对比：当你同时手握开源数据集、外包标注、模型合成三批数据时，对同一批测试指令分别看三个来源的回复被多数票认可的比例，就能客观地给数据源排名，决定配比与取舍。缺点是成本随标注人数线性增长，所以通常只对抽样数据执行，作为审计手段而非全量过滤手段。

进阶：IFD 与多信号聚合

IFD（Instruction-Following Difficulty，指令遵循难度）是近年社区常用的一个比值型指标：回复在给定指令条件下的困惑度，除以回复本身的无条件困惑度。比值接近或大于 1，说明指令没能"帮到"回复——要么指令与回复脱节，要么回复本身太难，这类样本的教学价值或可信度都值得怀疑。

IFD(x, y) = log p(y | x) / log p(y)　　；　　Q(x,y) = w₁·IFD + w₂·PPL⁻¹ + w₃·r_RM + w₄·Div

更完整的做法是把多个信号加权聚合成一个综合质量分 Q：IFD 提供指令-回复匹配度，PPL 倒数提供可学习性，RM 分数提供人类偏好对齐度，Div 项（基于 embedding 的覆盖度）防止选出来的 Top-k 全是相似样本。这个聚合分既可以用来取 Top-k 构建训练集，也可以把同一指令下分数最高与最低的回复配对，直接产出 DPO 需要的偏好对。

评分方法测量对象单条成本接近人类判断典型风险适用定位
PPL 过滤模型对文本的熟悉度一次前向推理间接误杀新颖但正确的表达全量初筛，定甜区
奖励模型有用 / 准确 / 安全偏好毫秒级中高RM 自身偏见、随时间过时有偏好标注时的主力精筛
LLM-as-Judge可定制的多维细则约 $0.0001/条起高长度偏见、位置偏见、成本高边缘样本精判、维度定制

四种方法是一条"从便宜到贵"的漏斗：PPL 用模型自己的视角做初筛，RM 用学来的人类偏好做精筛，Judge 用最强的大脑做边缘裁决，一致性检验做最后的抽样审计。贵的信号永远只花在便宜的信号搞不定的样本上。

三、训练前的五段式全流程清洗管线

评分方法解决的是"样本好不好"，清洗管线解决的是"数据干不干净、分布对不对"。一个生产级管线按固定顺序跑五段：格式清洗 → 去重处理 → 异常检测 → 安全过滤 → 分布审计。顺序不能乱——先去重再算分布，否则重复样本会污染分布统计；先格式校验再上模型打分，否则脏格式会让 PPL 计算本身失真。

原始数据 10,000 条 │ ├─① 格式清洗 ──▶ 缺字段 / 角色标记错乱 / 编码杂质 / 特殊 token 缺失 │ 典型命中 3% ~ 8% ▼ ├─② 去重处理 ──▶ 精确哈希 + MinHash 近重复（相似度 > 0.9 人工审查） │ 典型命中 5% ~ 20% ▼ ├─③ 异常检测 ──▶ 超短 / 超长回复、语言不匹配 → 人工复核保留合理短回复 │ 典型命中 2% ~ 5% ▼ ├─④ 安全过滤 ──▶ 毒性分类器 + 偏见检测 + PII 正则 │ 典型命中 1% ~ 3% ▼ └─⑤ 分布审计 ──▶ 任务类型 / 长度 / 难度分布与生产流量对齐（不做删除，做再平衡） ▼ 清洗后数据：约为原始量的 60% ~ 70%

格式清洗：自动化校验脚本是底线

格式问题是最"沉默"的一类脏数据：训练不会报错，loss 照常下降，但模型学到的是错乱的对话结构。检查项至少包括三类——系统提示词是否缺失或串位、角色标记（user/assistant 边界）是否正确闭合、特殊 token（如对话分隔符、工具调用标记）是否成对出现。此外还要清理编码杂质：HTML 残留、不可见控制字符、全半角混乱。这类问题在人工标注和爬虫数据中的命中率通常在 3%~8%，全部应该用自动化格式校验脚本批量拦截，逐条肉眼检查是不现实的。

去重处理：精确去重只是及格线

重复样本的危害不止"浪费算力"。同一条样本反复出现，会让模型对它的记忆权重不断叠加，最终表现为输出风格固化、对特定句式过拟合；更糟的是近重复但标注不一致的样本对——两个几乎相同的指令，一个标 A 一个标 B，直接制造矛盾梯度。

去重要分两层做。精确去重用哈希匹配完全重复的样本，成本极低，必须先跑。模糊去重才能抓住"换个说法的重复"：典型做法是用 MinHash（一种把文档映射为短签名、快速估算集合相似度的算法）或 embedding 余弦相似度来检测近重复，经验阈值是相似度超过 0.9 的样本对进入人工审查队列——注意是"审查"而不是"直接删"，因为有时两条相似样本的回复侧重点不同，误删会损失多样性。Llama 3.1 在更大规模上采用三级去重（URL 级、文档级 MinHash、行级高频片段剔除），思路完全一致：按粒度从粗到细逐层收紧。

去重方式机制速度能抓住什么风险
精确去重全文哈希比对极快完全相同的复制样本几乎无误伤
模糊去重MinHash / embedding 相似度 > 0.9中等换措辞、换标点的近重复可能误伤"相似但各有价值"的样本
指令级去重只对指令侧聚类归并中等同一指令的多个冗余回复配合择优保留，可直接产出偏好对

异常检测：宁可复核，不可滥删

异常检测盯三类目标：超短回复（可能是标注员偷懒或截断事故）、超长回复（可能是复制粘贴事故或日志混入）、语言不匹配（中文指令配英文回复）。处理原则要特别注意一条：超短不等于坏。"是的"、"已完成"这类回复在确认型指令下是完全正确的，所以异常检测的输出不是直接进入删除队列，而是进入人工复核队列，由复核者保留合理的短回复、剔除真正的残次品。阈值参考：指令长度 10~200 字符之外要警惕，回复长度低于指令长度 1/3 的要重点看。

安全过滤：毒性、偏见、隐私一个都不能少

安全过滤覆盖三类内容：毒性（辱骂、攻击性言论）、偏见（性别、地域、职业歧视表述）、隐私（手机号、身份证号、邮箱等个人可识别信息，即 PII）。工具组合上，毒性与偏好用开源毒性分类器批量打分，隐私用正则模式匹配（手机号、证件号格式识别率很高，不需要模型）。被安全过滤命中的样本一律剔除不做保留——这是少数没有任何商量余地的环节，因为一条漏网的毒性样本造成的线上事故，成本远高于误删十条好样本。

分布审计：清洗的最后一步是"对齐生产"

分布审计（Distribution Audit）统计清洗后数据在任务类型、长度、难度三个维度上的分布，并与线上真实流量分布做对比。这一步不删数据，做的是再平衡。审计要盯的典型问题是某类样本占比失衡——OpenAI 在早期对齐训练中曾遇到拒答类数据占比失衡的问题：拒绝回答的样本比例与真实场景不匹配，导致模型要么过度拒答、要么该拒的不拒。对垂直场景来说同理：如果线上 40% 的提问是"订单查询"，训练集里这类样本只占 5%，模型上线后必然在最常见的需求上表现最差。

生产案例 · 千条级指令数据的三重过滤：某团队对 1,000 条客服领域指令数据执行"PPL 初筛 → 奖励模型精筛 → 规则引擎终筛"的自动化管线，最终保留约 65% 的样本。效果对比：平均困惑度从 15.2 降到 12.1（-20.4%），训练收敛步数从 3,800 步降到 2,900 步（-23.7%），人工评估通过率从 68% 升到 89%。原本人工筛查 1,000 条需要 3 人天，自动化管线把同样的工作量压缩到小时级，且判断标准从"凭感觉"变成可复现的阈值。

五段清洗的顺序本身就是一套成本逻辑：先做几乎免费的格式与去重，再做需要人工介入的异常复核，安全过滤零容忍，最后用分布审计收尾——清洗管线的终点不是"数据变少"，而是"数据的形状变成线上流量的形状"。

四、训练中的数据问题诊断

清洗做得再好，也只能保证数据在"进入训练前"是合格的。分布是否匹配、样本是否被过度学习、通用能力是否被冲掉，这些问题只有在训练过程中才会现形。所以质量评估体系的第二战场是训练监控：用四类典型症状反推数据侧的病灶。

Loss 走势分离：多样性不足的第一信号

最经典的症状是训练 loss 持续下降、验证集（从训练数据中独立切出、不参与参数更新、专门用于监控泛化的一批样本）上的 loss 反而上升。两条曲线像剪刀一样张开，本质是过拟合：模型开始死记训练样本而不是学习规律。在 SFT 场景下，最常见的根因不是模型太大，而是数据多样性不足——重复率过高、风格过于单一，模型没得选，只能背。排查动作：重新统计训练集的重复率和回复风格分布（句式模板占比、开头词分布），如果确认单一，优先补数据多样性，而不是急着加正则、降学习率。

任务异常信号：按任务分组才能看见的凹陷

总体评测分数往往掩盖局部塌陷：整体通过率 85% 看起来很健康，但拆开看可能是"摘要 95%、改写 93%、表格抽取 41%"。定位方法是按任务类型分组评估，找到异常低的那一组，再回溯该类型对应的训练样本——通常是两种病灶之一：这类数据的质量差（标注错误集中），或数量不够（样本太少学不会）。处理流程是闭环的：分组评测 → 定位异常任务 → 抽取该任务训练样本人工复查 → 补充或重写 → 重新训练验证。

输出风格固化：某些样本出现频率过高的指纹

症状是模型回复里反复出现固定句式，比如每条回复都以"好的，根据您的问题"开头，或者结尾永远挂着同一句客套话。这是训练集中某些模板样本出现频率过高的直接指纹——模型把高频模式当成了"安全答案"。修正措施是调整数据分布平衡性：对高频模板做下采样，同时为同类指令补充不同风格的回复，让模型见到"同一个问题可以有多种得体的答法"。这个症状在验证集 loss 上未必有体现，必须靠输出采样检查才能发现，所以训练中定期抽生成结果做人工扫读是必要动作。

灾难性遗忘：领域能力上去了，通用能力塌了

灾难性遗忘（Catastrophic Forgetting）指模型在学习新任务分布时，原有通用能力显著退化：领域问答变好了，但常识推理、多轮对话、基础语言能力明显变差。根因是领域数据与预训练分布差异太大，梯度把通用知识"冲掉"了。标准解法是在训练数据中混入通用数据做锚定。

生产案例 · HuggingFace 的通用数据配比：早期开源 SFT 实验发现，纯领域数据微调后模型在通用基准上大幅退化。HuggingFace 团队的做法是在训练集中额外混入约 10 万条 OpenHermes 等高质量通用指令数据，让领域样本与通用样本共同构成训练分布。结果是领域能力保持住的同时，通用基准分数停止下滑——"领域数据 + 通用锚定数据"的混合配比从此成为社区标配做法。

五、生产案例与最佳实践

把前面四节的方法落到真实项目里，社区沉淀出的案例高度一致地指向同一个结论：在数据清洗上花的每一分钱，都会以训练时间缩短和效果提升的形式加倍返还。

生产案例 · 从 5,000 到 500 的极致筛选：某企业领域 SFT 项目手握 5,000 条标注数据，团队用 IFD + PPL + 奖励模型三个信号聚合成综合质量分，只取 Top 500 进入训练。结果：下游领域准确率比全量训练提升 25%，训练时间因数据量降至 1/10 而同步缩短；同一套打分排序还顺手产出了 chosen/rejected 偏好对，直接供后续 DPO 阶段使用。该团队的复盘结论是——在数据治理严格与松散的两种配置下，相同模型架构的表现差距可达 25%，"数据质量是最重要的超参数"在他们的项目里是可量化的事实。
生产案例 · 800 条干净数据打败 2,000 条脏数据：一家客服场景的团队先用 2,000 条未清洗的客服对话直接微调，测试集准确率停在 78%，随后花了两周调学习率、epoch、warmup，指标纹丝不动。后来换一条路：抽出半天时间对同批数据做格式校验、去重、标注一致性检查，剔除矛盾与残次样本后只剩 800 条，重新微调后同类测试集准确率升到 91%。差距不在模型、不在超参数，只在数据。

Do / Don't 实践清单

  • 先跑便宜的规则清洗，再花模型推理预算，漏斗顺序从便宜到贵
  • PPL 阈值每次都重新画分布图确定，安全过滤一票否决
  • 近重复样本进人工审查队列，保留合理短回复
  • 清洗后做分布审计，让训练分布对齐线上真实流量
  • 训练中按任务分组评估，定期抽读生成结果查风格固化
  • 领域训练混入通用锚定数据，防止灾难性遗忘
  • 把坏案例回流到标注环节，形成数据迭代飞轮
  • 盲目堆数据量，把未清洗的全量数据直接丢进训练
  • 照搬别的项目的 PPL 绝对阈值，不看自己的分布
  • 只用精确哈希去重，放任近重复样本制造矛盾梯度
  • 让 LLM 裁判按长度打分而不声明简洁性要求
  • 只看总体评测分数，不做任务级分组拆解
  • 一致率不足 70% 还硬训，不回头修标注规范
  • 把清洗当一次性工作，数据入库后就再也不审计

这套体系的最终产出不是一个"干净的数据集"，而是一种可复现的判断力：任何一条样本被留下或被剔除，都能说出是哪个信号、哪个阈值做的决定——可复现，才是质量工程与手工挑数据的真正分界线。

回顾全文：质量优于数量是前提（第一节），四种评分方法构成训练前的质量漏斗（第二节），五段清洗管线保证数据的干净与分布对齐（第三节），四类训练症状监控构成运行时的质量防线（第四节），阈值速查与 Do/Don't 则是把这些经验固化成团队规范（本节）。数据质量评估体系不是一个工具列表，而是贯穿"清洗—评分—训练—诊断—回流"全链路的工程纪律。

Q&A

为什么 PPL 适中的样本训练价值最高？两端各代表什么问题？
PPL 衡量模型对文本的意外程度。PPL 极低的样本，模型已经充分掌握，再训练只是在重复已知内容，贡献的梯度信息量很小，属于算力浪费；PPL 极高的样本则有两种可能：一是内容超出模型当前理解能力（生僻领域、语言混杂），二是本身就是乱码、截断、逻辑混乱的坏样本，强行学习会把参数拉偏。中间地带才是"模型能理解但尚未掌握"的学习甜区，梯度信号既有效又可吸收。实践中先画 PPL 分布直方图，再去掉顶部和底部各约 10% 的极端值，并用中位数 ±1.5 IQR 这样的稳健区间做二次确认。
奖励模型打分和 LLM-as-Judge 都更接近人类判断，该怎么选？
两者成本结构和适用面不同。奖励模型一次推理毫秒级，适合对全量数据做主力精筛，但需要先积累偏好标注来训练，且会带着自身训练数据的偏见（比如偏爱长回复），还要定期重训防止过时。LLM-as-Judge 无需训练、评分维度可随业务即时定制，但单条成本高一个数量级以上，还有长度偏见、位置偏见等系统性问题。推荐组合：有偏好标注储备时用 RM 全量打分，把分数处于边缘地带、RM 拿不准的样本交给 LLM 裁判精判；冷启动阶段没有 RM，则先用本地小模型粗筛、再用大模型裁判兜底。
数据量只有几百条的小数据集，还值得做自动化质量过滤吗？
值得，而且更值得。小数据集里每一条坏样本的占比都被放大，一条矛盾标注可能占总量的千分之五甚至更高，对参数的污染比大数据集更直接。此时过滤策略要调整：PPL 两端修剪比例从 10% 收紧到 5% 以内甚至只做人工抽查，避免误删宝贵的样本；模糊去重的相似度命中全部进人工审查而不是自动删除；LLM-as-Judge 因为总量小、总成本可控，反而可以全量跑，顺便让裁判对每条低分样本输出理由，这些理由直接指导人工修订。小数据集的正确姿势是"自动化找出嫌疑，人工做最终裁决"。
去重为什么要用 0.9 相似度这种模糊标准？只做精确去重不行吗？
精确哈希只能抓到逐字相同的复制样本，而真实数据里更常见的是"换了个说法的重复"：同一个问题被不同标注者用几乎相同的措辞写了三遍，或者同一模板批量生成的近似样本。这些近重复样本的危害有两层：一是让模型对特定模式过度记忆，引发输出风格固化；二是如果近重复样本的标注不一致，会制造互相矛盾的梯度。所以必须用 MinHash 或 embedding 相似度做模糊去重。阈值设在 0.9 左右并要求人工审查，是为了在"去重"与"保护多样性"之间留缓冲——相似度 0.92 的两条样本，回复的侧重点可能完全不同，直接删掉会误伤。
训练 loss 一直在降，怎么判断问题出在数据而不是超参数？
看三个数据侧指纹。第一看验证集：训练 loss 降而验证 loss 升（剪刀口），这是过拟合信号，在 SFT 里最常见根因是数据重复率高、风格单一，而不是学习率问题。第二做任务分组评测：总体分正常但个别任务塌陷，几乎必然是该类型样本的质量或数量缺陷，超参数不会只打一个任务。第三抽样读生成结果：固定句式高频复现是高频模板样本的直接指纹。如果三个指纹都命中，先修数据再谈调参；经验是数据问题不解决时，任何超参数调整的收益都会被淹没。
过滤比例怎么定？是不是保留得越多越稳妥？
不是。社区的对照实验反复显示，保留 60%~70% 的高分样本，效果稳定优于保留 100% 全量——多保留的那部分低质样本贡献的是噪声梯度，会稀释好样本的学习信号。但保留率也不是越低越好，过度过滤有两个风险：一是误杀新颖但正确的表达（PPL 高不等于坏），二是数据多样性被筛掉，选出来的都是"安全平庸"的样本，模型学完变得千篇一律。正确流程是：先画各信号的分布图定初始阈值，按阈值过滤后抽样人工复核两端样本，再在下游任务上对比"全量 / 保留 70% / 保留 50%"三组的实际效果，用结果而非直觉定最终比例。
如何防止 LLM-as-Judge 的长度偏见误杀简洁的好回复？
三个手段叠加。第一，在评分 prompt 中显式声明评分规则："长度本身不应加分，冗长、重复、注水的回复应扣分；在内容正确性相同的情况下，更简洁的回复得分更高"——这能显著压住裁判给长文本抬分的倾向。第二，要求裁判先输出评分理由再输出分数，强制其基于内容维度而非整体印象打分。第三，对边缘样本做交叉裁判：换一个不同的裁判模型（或交换对比顺序）重判一次，两次判断不一致的样本转人工。另外要记住，裁判的评分维度必须与业务目标对齐——如果线上考核的是回复准确率，就别用"有帮助程度"这种容易被长度污染的单一维度。
