人类对齐训练 — Reinforcement Learning from Human Feedback, Direct Preference Optimization & Beyond

一、人类对齐的必要性

预训练模型学的是"人类会怎么写下一个词"，不是"人类希望它怎么回答"。对齐要补的正是这个缺口——把"像人写的"变成"对人有用的"，而这一步没法靠加数据加参数自动获得。

预训练模型的根本问题

大语言模型经过预训练后，虽然具备强大的语言能力，但存在以下严重问题：

  • 有害内容：模型可能生成有毒、偏见、暴力或非法内容
  • 事实不准确：自信地输出错误信息（Hallucination / 幻觉）
  • 不遵循指令：预训练目标是"预测下一个 token"，而非"回答用户问题"
  • 目标不对齐：模型的训练目标（最小化语言建模 loss）≠ 人类期望的行为

对齐的三个 H 原则

Anthropic 定义的三个核心对齐维度：

  • Helpful（有用）：能理解并完成用户意图，提供高质量回答
  • Harmless（无害）：拒绝生成危险、有害或非法内容
  • Honest（诚实）：不编造信息，承认不确定性，表达自身局限

对齐的意义

对齐不仅是安全问题，也直接影响模型的实用性。SFT 是最基本的对齐手段，而 RLHF/DPO 进一步利用人类偏好信号来精细调整模型行为，使其输出更符合人类期望。

💡 知识要点
  • 预训练模型的目标函数（next-token prediction）和人类期望之间存在 gap，这就是对齐要解决的问题
  • 三个 H（Helpful/Harmless/Honest）是评估对齐效果的核心框架
  • 对齐方法从 SFT → RLHF → DPO → GRPO 逐步演进，核心思路从"模仿人类"到"从偏好学习"

二、RLHF 三阶段流程

三个阶段各管一件事：SFT 教格式，奖励模型学偏好，PPO 把偏好翻译成参数更新。三者严格串行，任何一环的上限就是整条链的上限——所以奖励模型标不准时，再怎么调 PPO 都没用。

RLHF 的完整回路：前两阶段是离线的，第三阶段才是那个"转起来"的环 ── 阶段 1：SFT（离线，一次性）────────────────────────────── 指令-回复对 ──▶ 监督微调 ──▶ π_sft │ ┌──────────────┴──────────────┐ ▼ ▼ 作为策略的初始化 冻结成参考模型 π_ref ── 阶段 2：奖励模型（离线，一次性）───────────────────────── 同一 prompt 的两个回复 (y_w 优, y_l 劣) │ ▼ Bradley-Terry：把"哪个更好"变成可微的成对损失 ┌──────────────┐ │ 奖励模型 RM │ ──▶ r(x, y) 输出一个标量分数 └──────────────┘ 训完即冻结 ── 阶段 3：PPO（在线，循环）────────────────────────────── ┌────────────────────────────────────────────────┐ │ │ ▼ │ ┌──────────┐ 采样 ┌──────────────────────────┐ │ │ 策略 π_θ │ ──────▶ │ 回复 y ~ π_θ( · | x ) │ │ │ ✎ 在更新 │ └────────────┬─────────────┘ │ └──────────┘ │ │ ▲ ├──▶ ┌──────────┐ │ │ │ │ RM ❄ │──▶ r │ │ └──────────┘ │ │ │ │ │ ├──▶ ┌──────────┐ │ │ │ │ π_ref ❄ │──▶ logp_ref │ │ └──────────┘ │ │ │ │ │ │ │ ▼ │ │ │ KL(π_θ ‖ π_ref) │ │ │ │ │ │ ▼ ▼ │ │ 奖励 = r − β · KL ◀───┘ │ │ │ │ │ ▼ │ │ ┌──────────────┐ │ │ │ 价值网络 V ✎ │──▶ 优势 A │ │ └──────────────┘ │ │ │ │ └──────── PPO 梯度更新 π_θ ◀───┘ │ │ │ └─────────────────────────────────┘ 同时驻留四个模型：π_θ（在学）、π_ref（在拉）、RM（在评）、V（在估） 其中两个要更新、两个冻结 —— 这就是 PPO 显存吃紧的根源。 β 越大，策略被拴得越紧：奖励涨得慢，但也更不容易跑出语言分布之外。

完整流程图

[ Stage 1: SFT ] 预训练模型 + 高质量指令数据 → 监督微调模型 π_SFT │ ▼ [ Stage 2: Reward Model ] π_SFT 生成多组回答 → 人类标注偏好排序 → 训练奖励模型 r(x,y) │ ▼ [ Stage 3: PPO 优化 ] 用 RM 打分 + PPO 强化学习优化 π_θ，同时 KL 约束防止偏离 π_SFT

Stage 1: Supervised Fine-Tuning (SFT)

  • 使用人工撰写的高质量 (instruction, response) 对来微调预训练模型
  • 让模型学会"对话格式"和"遵循指令"
  • 本质是行为克隆（模仿人类标注者的行为）
  • 局限：只能学到标注者的平均水平，无法超越标注者

Stage 2: Reward Model 训练

  • 让 SFT 模型对同一个 prompt 生成多个候选回答
  • 人类标注者对这些回答进行偏好排序（y_w ≻ y_l）
  • 训练一个 Reward Model 来模拟人类偏好
  • RM 通常使用和 LLM 相同的架构，去掉 LM Head 后加一个标量输出

Stage 3: PPO 强化学习优化

  • 将 LLM 视为一个"策略"(Policy)，RM 分数视为"奖励"(Reward)
  • 使用 PPO 算法最大化 RM 打分，同时用 KL 散度约束防止偏离 SFT 模型太远
  • 最终得到对齐后的模型 π_θ
max_π_θ E_{x~D, y~π_θ(·|x)} [ r(x,y) ] − β · KL[ π_θ(y|x) ‖ π_SFT(y|x) ]
💡 知识要点
  • RLHF 三阶段的具体作用和数据流要能完整描述
  • Stage 1 SFT 解决"会对话"，Stage 2 RM 建模偏好，Stage 3 PPO 用偏好信号优化策略
  • KL 约束是防止 reward hacking 和分布偏移的关键手段

三、Reward Model 详解

奖励模型学的是"两个回复哪个更好"这个相对判断，而不是绝对分数——人类标绝对分会飘，标相对好坏才稳。Bradley-Terry 把成对比较变成可微的损失，这个转换就是整个 RLHF 能跑起来的接口。

偏好数据收集

Reward Model 训练的基础是人类偏好数据。典型的数据收集流程：

  1. 给定一个 prompt x，让 SFT 模型生成 K 个候选回答 {y₁, y₂, ..., yₖ}
  2. 人类标注者对 K 个回答进行排序（ranking）
  3. 将排序转化为两两比较的偏好对 (y_w, y_l)，其中 y_w 是人类偏好的回答
  4. 每个排序可以产生 C(K,2) = K(K-1)/2 个偏好对

Bradley-Terry 模型

BT 模型将偏好建模为一个概率问题：

P(y_w ≻ y_l | x) = σ(r(x, y_w) − r(x, y_l))

其中 σ 是 sigmoid 函数，r(x,y) 是 Reward Model 输出的标量分数。直觉：偏好回答的 reward 越高于非偏好回答，概率越接近 1。

RM 训练目标

最大化偏好对的似然，即最小化以下 loss：

L_RM = −E_{(x, y_w, y_l) ~ D} [ log σ(r(x, y_w) − r(x, y_l)) ]

RM 的质量决定上限

核心认知：RM 质量 = RLHF 效果的天花板。

  • RM 不准确 → PPO 会优化一个错误的方向 → 产生 Reward Hacking
  • 人类标注者之间的不一致性（inter-annotator disagreement）直接影响 RM 质量
  • RM 在 OOD（分布外）数据上的泛化能力有限
  • InstructGPT 使用 ~33k 偏好对比数据来训练 RM，后续工作通常需要更多

RM 架构选择

方案做法优缺点
同架构 RM与策略模型相同大小的 LLM 改造效果好，但开销大（需要加载两份模型）
小模型 RM较小的 LLM 训练 RM更省资源，但可能不够准确
多头 RM针对不同维度输出多个 reward更细粒度控制，训练复杂
💡 知识要点
  • Bradley-Terry 模型的数学原理 — 用 sigmoid 函数建模偏好概率
  • RM loss 是 cross-entropy loss 的变形，本质是二分类
  • RM 质量是 RLHF 效果的天花板，数据质量 > 数据量
  • 偏好排序 → 偏好对的转换可以产生 C(K,2) 组合，数据高效利用

四、PPO 对齐

PPO 同时挂着四个模型：策略在学、参考在拉、奖励在评、价值在估。KL 散度那一项的作用是把策略拴在参考模型附近，防止它为了刷高奖励跑到语言分布之外——去掉这根绳子，模型能在几百步内学会说人听不懂的话。

示例场景：奖励一路涨，人工评分反而在掉。背景——某团队用自训的奖励模型跑 PPO，训练看板上奖励曲线非常漂亮，从 0.4 稳步升到 0.9。问题——同期人工盲评的胜率却从 62% 掉到 48%。抽样几十条输出后看清了原因：模型学会了三个套路——把回答堆长、开头复述一遍问题、结尾加一段免责声明。这三样恰好都是奖励模型偏好数据里的高分特征（标注者当时普遍把更长更"周全"的回复标为更好），于是模型优化的是奖励模型的偏见，不是真实偏好。这就是典型的 Reward Hacking。方案——四件事一起做：在奖励里加一项长度惩罚；把 KL 系数从 0.01 提到 0.05 把策略拴紧；补约 500 条"短而准优于长而空"的偏好对重训奖励模型；并把"奖励模型分数与人工评分的相关性"作为早停判据，相关性一掉就停。效果——奖励分数回落到 0.72（比之前"难看"），但人工胜率升到 68%。值得记住的是：当代理指标和真实目标背道而驰时，代理指标变难看才是对的。

PPO 在 RLHF 中的角色

Proximal Policy Optimization（PPO）是一种策略梯度算法，在 RLHF 中作为核心优化算法来调整 LLM 的参数。将 LLM 的文本生成看作 RL 中的"动作序列"：

RL 概念LLM 对应
State (状态)已生成的 token 序列 + prompt
Action (动作)生成下一个 token
Policy (策略)LLM 本身 π_θ(y|x)
Reward (奖励)RM 的评分 r(x,y)（通常只在序列末尾给予）
Value FunctionCritic 模型 V(s)（估算未来累计奖励）

PPO 训练中的四个模型

RLHF-PPO 训练需要同时维护四个模型，这是其最大开销来源：

  1. Policy Model (Actor) — 正在训练的 LLM，参数 θ 会更新
  2. Reference Model — SFT 后的 LLM 冻结副本，用于计算 KL 惩罚
  3. Reward Model — 冻结的 RM，提供 reward 信号
  4. Critic Model (Value) — 估算状态价值函数 V(s)，用于计算 Advantage

KL 散度约束

KL 散度项 β · KL[π_θ ‖ π_ref] 是 RLHF 中至关重要的正则项：

  • 防止分布偏移：确保优化后的策略不会偏离 SFT 模型太远，保持语言质量
  • 防止 Reward Hacking：模型不会学到"欺骗" RM 获取高分的捷径
  • β 的取值：需要仔细调节，太小则约束无效，太大则学不到偏好信号
KL[π_θ ‖ π_ref] = E_{y~π_θ} [ log(π_θ(y|x) / π_ref(y|x)) ]

Reward Hacking

当 RM 不完美时，PPO 可能找到 RM 的"漏洞"来获取高分，但人类实际上不认可这些输出：

  • 输出过长、重复某些"安全"模板以获取高分
  • 使用人类偏好的格式但内容空洞
  • 过度"讨好"式回答，丧失客观性

PPO 训练不稳定性

PPO 在 RLHF 中面临的主要挑战：

  • 超参数敏感：learning rate、β、clip range、mini-batch size 等需要精细调节
  • 训练不稳定：reward 可能突然崩塌（reward collapse），需要仔细监控
  • 资源开销大：同时维护 4 个模型的显存和计算开销巨大
  • 难以复现：随机种子、硬件差异都可能导致结果显著不同
  • 工程复杂：需要 experience buffer、GAE、多轮采样等，实现复杂
💡 知识要点
  • PPO 在 RLHF 中的四个模型各自的作用，尤其是为什么需要 Reference Model
  • KL 散度约束的作用：防止分布偏移和 Reward Hacking
  • PPO 训练的最大痛点：四模型的内存开销 + 训练不稳定
  • 正是这些痛点催生了 DPO 等更简洁的替代方案

五、DPO (Direct Preference Optimization)

DPO 的洞察是：最优策略和奖励函数之间存在一一对应关系。既然如此，就不必先把奖励显式训出来再去优化它——直接对着偏好对做一个分类式的损失，把"训 RM"和"跑 RL"两步压成一步。

同样的偏好数据，PPO 与 DPO 走的两条路： ── PPO 路径（两段、在线采样）─────────────────────────────── 偏好对 ┌──────────┐ (x, y_w, y_l) ─▶│ 训 RM │─▶ r(x,y) 冻结 └──────────┘ │ ▼ prompt x ──▶ π_θ 采样 y ──▶ 打分 r ──▶ 算优势 A（需价值网络 V） ▲ │ └────────── PPO 更新 ◀───────────┘ ＋ KL(π_θ ‖ π_ref) 拴住 驻留模型：π_θ ✎ V ✎ RM ❄ π_ref ❄ ── 四个 数据是在线产生的（策略每更新一次，采样分布就变） 优点：能探索到偏好数据之外的回复 代价：显存吃紧、超参敏感、奖励模型的偏见会被放大成 Reward Hacking ── DPO 路径（一段、离线）────────────────────────────────── 偏好对 (x, y_w, y_l) │ ├──▶ π_θ 计算 log π_θ(y_w|x), log π_θ(y_l|x) ✎ │ └──▶ π_ref 计算 log π_ref(y_w|x), log π_ref(y_l|x) ❄ │ ▼ 隐式奖励 r̂ = β · [ log π_θ(y|x) − log π_ref(y|x) ] │ ▼ loss = −log σ( r̂(y_w) − r̂(y_l) ) ── 一个成对分类损失 │ ▼ 直接反向传播更新 π_θ 驻留模型：π_θ ✎ π_ref ❄ ── 两个 数据是离线固定的（不采样，一遍遍过同一批偏好对） 优点：显存减半、无需价值网络、训练稳定、超参少 代价：探索范围被离线数据的覆盖面锁死；β 过小易过拟合偏好对 ───────────────────────────────────────────────────────── 一句话：PPO 把偏好"编译"成一个奖励函数再去优化， DPO 发现这个中间产物可以消掉，于是直接对偏好求梯度。
示例场景：从 PPO 换到 DPO，一轮训练从 26 小时缩到 7 小时。背景——某团队要给一个 8B 模型做偏好对齐，手上有单机 8×A100 和约 4 万条离线偏好对。问题——PPO 要同时驻留策略、参考模型、奖励模型、价值网络四个模型，其中两个还要保存优化器状态；显存排完之后 micro-batch 只能压到 1，单步约 3.2 秒，跑一轮要 26 小时。更麻烦的是 KL 系数、裁剪范围、价值损失权重几个超参互相耦合，一轮 26 小时意味着调参周期以天计。方案——改用 DPO：只需要策略和一个冻结的参考模型，价值网络和奖励模型都不用了；把省下的显存换成更大的 micro-batch。效果——显存占用降到约原来的一半，micro-batch 提到 4，单步降到约 0.9 秒，一轮 7 小时，调参迭代速度提升近四倍。代价要说清——DPO 没有在线采样，模型只能在那 4 万条偏好对覆盖到的空间里学；后续要突破这个上限，还是得回到在线方法或者补数据。

核心思想

DPO（Rafailov et al., 2023）的关键洞察：不需要显式训练一个 Reward Model，可以直接从偏好数据优化策略。

传统 RLHF 是两步走（先训 RM → 再用 RL 优化），而 DPO 将这两步合并成一个闭式解，变成一个简单的监督学习问题。

数学推导核心

Step 1: RLHF 的最优策略有闭式解

RLHF 的目标函数有一个已知的最优解形式：

π*(y|x) = (1/Z(x)) · π_ref(y|x) · exp(r(x,y) / β)

其中 Z(x) 是归一化常数（partition function）。

Step 2: 从最优策略反解出隐式 reward

将上式取对数并重排，可以用策略的对数概率表达 reward：

r(x,y) = β · log(π*(y|x) / π_ref(y|x)) + β · log Z(x)

Step 3: 代入 Bradley-Terry 模型

将隐式 reward 代入偏好概率公式，Z(x) 项在差值中消掉：

P(y_w ≻ y_l | x) = σ( β · [log(π_θ(y_w|x)/π_ref(y_w|x)) − log(π_θ(y_l|x)/π_ref(y_l|x))] )

最终 DPO Loss

L_DPO = −E_{(x, y_w, y_l)} [ log σ( β · (log π_θ(y_w|x)/π_ref(y_w|x) − log π_θ(y_l|x)/π_ref(y_l|x)) ) ]

DPO vs RLHF 对比

维度RLHF (PPO)DPO
是否需要 RM需要单独训练不需要
优化方式强化学习 (PPO)监督学习 (类 cross-entropy)
需要的模型数4 个2 个 (π_θ + π_ref)
训练稳定性不稳定，超参数敏感稳定，类似 SFT

DPO 的局限

  • 离线偏好：默认使用固定的偏好数据，无法探索新的策略空间
  • 依赖参考模型：π_ref 的质量直接影响效果
  • 偏好数据质量要求高：噪声标注会直接影响训练
  • 过拟合风险：由于是监督学习形式，可能过拟合偏好数据
💡 知识要点
  • DPO 的数学推导要能完整讲清楚：从 RLHF 最优解 → 反解 reward → 代入 BT 模型 → 消去 Z(x)
  • DPO Loss 的直觉理解：增大好回答的概率 / 参考比值，减小坏回答的概率 / 参考比值
  • DPO 本质上是在 隐式 地做 reward modeling，reward 被 reparameterize 成了策略的对数概率比
  • DPO 是 offline 方法，这是其与 PPO 的重要区别

六、GRPO (Group Relative Policy Optimization)

GRPO 把 PPO 里那个还要单独训练的价值网络换成了一个更朴素的东西：同一道题采样一组答案，用组内相对优势当基线。少养一个模型，显存和要调的超参一起减半。

优势 A 怎么算：PPO 要训一个网络去估，GRPO 直接用组内统计量 ── PPO ──────────────────────────────────────────────── prompt x ──▶ 采样 1 个回复 y ──▶ r(x,y) │ ┌─────────────┴──────────────┐ │ 价值网络 V(x) ✎ 要训练 │ ← 额外一个模型 └─────────────┬──────────────┘ 额外一份优化器状态 ▼ 额外一套超参 A = r − V(x) V 估不准 ─▶ 优势有偏 ─▶ 策略更新方向漂 ─▶ 训练不稳 ── GRPO ─────────────────────────────────────────────── prompt x ──┬──▶ 采样 y₁ ──▶ r₁ ├──▶ 采样 y₂ ──▶ r₂ ├──▶ 采样 y₃ ──▶ r₃ 同一道题采样 G 个回复 ├──▶ ... └──▶ 采样 y_G ──▶ r_G │ ▼ 用这一组自己的均值和标准差做归一化 rᵢ − mean(r₁..r_G) Aᵢ = ────────────────────── std(r₁..r_G) 不需要价值网络：基线就是"这道题的平均水平" 组内比较天然消掉了题目难度差异 —— 难题上答得比同组好， 和简单题上答得比同组好，得到的优势是同一量级 ───────────────────────────────────────────────────── 代价：每个 prompt 要采 G 个回复（常取 8~64），采样开销上去了； 收益：省一个模型、省一套超参、优势估计不再依赖一个可能估歪的网络。 这个交换在答案可自动判分的场景（数学、代码）上尤其划算 —— 因为那里的 r 可以由规则给出，连奖励模型都能省掉。

背景与动机

GRPO 由 DeepSeek（2024）提出，核心改进是去掉 Critic Model，用组内相对奖励来估计 Advantage，大幅降低资源消耗。

核心设计

去掉 Critic 模型

PPO 需要一个与 Policy 同等规模的 Critic 模型来估计状态价值 V(s)，GRPO 的方案：

  1. 对每个 prompt x，用当前策略 π_θ 采样一组（Group） G 个回答 {y₁, ..., y_G}
  2. 用 Reward Model（或规则）对这 G 个回答打分 {r₁, ..., r_G}
  3. 在组内计算 Advantage：对 reward 做 标准化（减均值、除标准差）
Â_i = (r_i − mean(r₁, ..., r_G)) / std(r₁, ..., r_G)

GRPO 目标函数

L_GRPO = E [ (1/G) · Σᵢ min(ρᵢ · Âᵢ, clip(ρᵢ, 1−ε, 1+ε) · Âᵢ) ] − β · KL[π_θ ‖ π_ref]

其中 ρᵢ = π_θ(yᵢ|x) / π_old(yᵢ|x) 是重要性采样比率，clip 操作继承自 PPO 以限制策略更新幅度。

GRPO 在 DeepSeek 中的应用

DeepSeek-R1 使用 GRPO 实现了强大的推理能力，关键策略：

  • 结合 规则奖励（准确率、格式正确性）和 模型奖励（RM 打分）
  • 数学题用准确率做 reward（结果正确 r=1，错误 r=0），无需 RM
  • 通过大 group size (G=64) 保证 Advantage 估计质量
  • 与 SFT 联合使用：先 RL 再 SFT，再 RL 再 SFT，迭代进化
💡 知识要点
  • GRPO 最大的贡献是去掉 Critic，用"组内相对比较"代替价值函数估计
  • Advantage 估计用 group-level reward 标准化，直觉：同一 prompt 下的相对好坏
  • GRPO 比 PPO 少一个模型，显存节省约 25-33%
  • DeepSeek-R1 的成功证明了 GRPO + 规则奖励在推理任务上的有效性

七、其他对齐方法

这一批方法的共同动作是继续拆零件：KTO 连成对数据都不要了（单条好/坏标注即可），ORPO 把 SFT 和偏好优化合成一个损失，SimPO 干掉参考模型。每拆掉一个零件都省一份成本，也各自让出一点能力——所以选型问题永远是"你能接受让出哪一点"。

KTO (Kahneman-Tversky Optimization)

KTO 的创新点：不需要偏好对，只需要"好/坏"二元标签。

  • 灵感来自前景理论（Prospect Theory）：人对损失比收益更敏感
  • 损失函数对"坏回答"施加更大的惩罚权重
  • 数据收集更简单：只需标注"这个回答好不好"，不需要两两比较
L_KTO = E_{y_good} [1 − σ(β · r̂)] + λ · E_{y_bad} [1 − σ(−β · r̂)]

其中 r̂ = log(π_θ/π_ref) − KL_ref，λ > 1 对负样本给予更大权重。

ORPO (Odds Ratio Preference Optimization)

ORPO 直接将偏好学习整合到 SFT 过程中，不需要 RM 也不需要参考模型。

  • 在 SFT 的 NLL loss 基础上加入一个 odds ratio 正则项
  • 使用 log odds ratio 区分好/坏回答
  • 最简洁的对齐方法之一：只需要一个模型、一次训练

SimPO (Simple Preference Optimization)

  • 简化 DPO，使用序列平均对数概率代替 per-token log prob
  • 加入长度归一化，消除长度偏差
  • 不需要参考模型（去掉 π_ref），进一步降低资源需求

IPO (Identity Preference Optimization)

  • 解决 DPO 的一个理论缺陷：DPO 假设 BT 模型完美成立
  • IPO 使用一个更鲁棒的正则化目标
  • 在偏好数据有噪声时表现更好

RLAIF (RL from AI Feedback)

用 AI 模型替代人类标注者来提供偏好反馈：

  • 使用一个强大的 LLM（如 GPT-4）作为偏好标注者
  • 大幅降低人类标注成本和时间
  • 可以大规模生成偏好数据
  • 风险：AI 标注的偏好可能不完全代表人类偏好，存在"AI 回音壁"效应
💡 知识要点
  • KTO 只需好/坏标签（非偏好对），数据收集更简单
  • ORPO 最简洁：单模型 + 单阶段 = SFT + 对齐同时完成
  • SimPO 去掉 π_ref，IPO 解决 DPO 的 BT 模型假设问题
  • RLAIF 用 AI 替代人类标注者，是当前扩展偏好数据的主流方式

八、Constitutional AI

Constitutional AI 把"人来标哪个回复更安全"换成"模型按写好的原则自己批改自己"。人类的工作从逐条标注上移到写原则——标注量从随数据线性增长，变成几乎恒定。

Anthropic 的自我改进方法

Constitutional AI (CAI) 由 Anthropic 在 2022 年提出，核心思想：让模型自我批评和自我修正，减少对人类标注的依赖。

CAI 的两个阶段

阶段 1: Supervised — 自我批评 + 修正 (Critique → Revision)

  1. 给模型一个"宪法"（Constitution）：一组明确的行为准则
  2. 模型生成初始回答 → 模型根据宪法自我批评 → 模型生成修正后的回答
  3. 用修正后的回答作为 SFT 数据进行训练

阶段 2: RL — AI 反馈的 RLHF (RLAIF)

  1. 让 AI 根据宪法原则来判断哪个回答更好
  2. 用 AI 生成的偏好数据训练 RM
  3. 用 RL 进行最终对齐

Red Teaming 自动化

CAI 的一个重要应用是自动化红队测试（Red Teaming）：

  • 让 AI 自动生成对抗性的 prompt（攻击尝试）
  • 测试模型是否能安全应对这些攻击
  • 将失败案例纳入训练，持续提升安全性
  • 比人工 Red Teaming 更高效、覆盖面更广

宪法示例

原则 1: 请选择最无害、最符合道德的回答。
原则 2: 请选择不包含种族、性别、宗教歧视的回答。
原则 3: 请选择最诚实、不编造事实的回答。
原则 4: 请选择最有帮助、信息量最大的回答。
原则 5: 如果两个回答差不多，选择更谨慎的那个。
💡 知识要点
  • CAI 的核心创新：用一组原则（宪法）指导 AI 自我改进，减少人类标注
  • 两阶段：自我批评修正 (SFT) + AI 反馈 (RLAIF)
  • 自动化 Red Teaming 是 CAI 的重要衍生应用
  • CAI 是 Claude 模型安全训练的核心技术

十、过优化与对齐税

奖励模型只是真实偏好的一个代理，代理一旦被优化到极致就必然与本体分道扬镳——这就是 Goodhart 定律在对齐上的形态。它的临床表现很稳定：奖励曲线一路上扬，人工评分开始下滑，两条线的交叉点就是该早停的位置。

Reward Over-optimization

当持续用 RL 优化 reward 时，reward 分数会持续上升，但人类评估的质量在某个点后反而下降。这就是过优化（Over-optimization）。

训练步数 → RM Score (代理指标): ↗ ↗ ↗ ↗ ↗ ↗ ↗ 📈 持续上升 Human Rating (真实质量): ↗ ↗ ↗ ↗ 🏔️ ↘ ↘ 📉 先升后降 ^ 最优停止点

Goodhart's Law

"When a measure becomes a target, it ceases to be a good measure."

当 RM 分数从"评估指标"变成"优化目标"时，模型会学到利用 RM 缺陷而非真正提升质量。这是 Goodhart's Law 在 RLHF 中的直接体现。

过优化的表现

  • 风格退化：回答变得冗长、模板化、过度"安全"
  • 内容空洞：使用大量修饰语但信息量低
  • 多样性丧失：不同 prompt 产生高度相似的回答
  • "sycophancy"（谄媚）：过度迎合用户观点，即使用户说法有误

对齐税 (Alignment Tax)

对齐训练带来安全性和有用性的同时，也可能降低模型的原始能力：

  • 知识遗忘：RLHF 可能导致模型忘记部分预训练知识
  • 过度拒绝：模型对合理请求也产生过度保守的拒绝（"I can't help with that"）
  • 创造力下降：过度对齐使模型偏向"安全"的回答，减少创新性
  • 推理能力退化：在某些复杂推理任务上的性能可能下降

缓解策略

  • Early Stopping：基于人类评估而非 RM 分数来决定何时停止训练
  • RM Ensemble：使用多个 RM 取平均，减少单一 RM 的偏差
  • 增大 β：更强的 KL 约束限制偏离程度
  • RM 定期更新：用当前策略生成新数据重新训练 RM
  • 多轮迭代：RLHF → 评估 → 修正 → 再训练
  • 混合训练：对齐训练时混入预训练数据，防止灾难性遗忘
💡 知识要点
  • Reward Over-optimization 是 RLHF 中的核心问题：RM Score ↑ 但真实质量 ↓
  • Goodhart's Law 解释了为什么代理指标不能无限优化
  • 对齐税：安全和有用之间存在 trade-off，过度对齐反而降低模型能力
  • "sycophancy"是过优化的典型症状，是高频考察点

Q&A

RLHF 的三个阶段分别是什么？每个阶段的数据和目标是什么？
Stage 1 SFT：使用人工标注的 (instruction, response) 对进行监督微调，目标是让模型学会遵循指令和对话格式。Stage 2 Reward Model：用 SFT 模型生成候选回答，人类标注偏好排序，训练 RM 建模 P(y_w ≻ y_l) = σ(r(y_w) - r(y_l))。Stage 3 PPO：用 RM 分数作为 reward，用 PPO 算法优化策略模型，同时用 KL 散度约束防止偏离 SFT 模型。
DPO 相比 RLHF 有什么优势？它是如何绕过 Reward Model 的？
DPO 的核心洞察是 RLHF 的最优策略有闭式解 π*(y|x) ∝ π_ref(y|x) · exp(r(x,y)/β)，可以反解出 r(x,y) = β · log(π*/π_ref) + const。将此隐式 reward 代入 Bradley-Terry 模型后，常数项消掉，得到只依赖 π_θ 和 π_ref 的损失函数。这样就不需要显式训练 RM，直接从偏好数据以监督学习的方式优化策略。优势包括：只需 2 个模型（节省 ~50% 显存）、训练稳定（类似 SFT）、实现简单、超参数少。
什么是 Reward Hacking？如何缓解？
Reward Hacking 是指模型学会了利用 Reward Model 的缺陷来获取高分，而非真正提升回答质量。例如输出过长的模板化回答、过度使用"讨好"式措辞等。缓解方法包括：增大 KL 约束系数 β 限制偏离程度、使用多个 RM ensemble 减少偏差、基于人类评估做 early stopping、定期用新数据重训 RM、以及结合规则约束（如长度惩罚）。
GRPO 与 PPO 的核心区别是什么？为什么更节省资源？
GRPO 的核心创新是去掉 Critic Model。PPO 需要一个与策略模型同等规模的 Critic 来估计状态价值 V(s)，而 GRPO 对每个 prompt 采样一组回答（Group），在组内对 reward 做标准化来估计 Advantage：Â_i = (r_i - μ) / σ。这样少维护一个大模型，显存节省约 25-33%。同时组内相对比较比绝对价值估计更稳定。DeepSeek-R1 成功使用 GRPO + 规则奖励在数学推理上取得了突破。
Bradley-Terry 模型在 RLHF 中的作用是什么？
Bradley-Terry 模型将人类的偏好建模为概率形式：P(y_w ≻ y_l) = σ(r(y_w) - r(y_l))，其中 σ 是 sigmoid 函数。它的作用是将"哪个更好"这一主观判断转化为可优化的数学目标。RM 的训练 loss 就是基于 BT 模型的负对数似然：L = -log σ(r(y_w) - r(y_l))。BT 模型的一个关键性质是只关心 reward 的差值而非绝对值，这使得 DPO 推导中的 partition function Z(x) 可以消掉。
KL 散度在 RLHF 中起什么作用？β 值如何影响训练？
KL 散度 KL[π_θ ‖ π_ref] 衡量当前策略与参考模型（SFT 模型）的分布差异。它在 RLHF 中有两个关键作用：(1) 防止分布偏移，确保模型不会生成语言质量低下的输出；(2) 防止 Reward Hacking，限制模型过度利用 RM 缺陷。β 是 KL 惩罚的权重系数：β 太小则约束无效，模型容易过优化；β 太大则策略几乎无法更新，学不到偏好信号。实践中 β 通常在 0.01-0.5 之间，需要根据任务仔细调节。
DPO 是 offline 方法，这有什么问题？如何改进？
DPO 使用固定的偏好数据集训练，无法像 PPO 那样在线采样新回答并获取反馈。问题包括：(1) 偏好数据分布可能与当前策略生成的分布不匹配（distribution shift）；(2) 无法探索策略空间中的新区域；(3) 可能过拟合偏好数据。改进方案包括：Online DPO（用当前策略采样新数据对做迭代训练）、Iterative DPO（多轮交替采样+训练）、Self-Play（让模型与自身对弈生成偏好对）。这些方法在保留 DPO 简洁性的同时引入在线探索能力。
什么是对齐税？如何平衡安全性与能力？
对齐税（Alignment Tax）指对齐训练在提升安全性和有用性的同时，可能导致模型原始能力的下降。具体表现：过度拒绝合理请求、创造力和多样性降低、部分知识遗忘、推理能力退化等。平衡策略包括：(1) 混合训练——在对齐训练中混入预训练数据防止灾难性遗忘；(2) 分级安全策略——对不同风险等级的内容采取不同程度的限制；(3) 精细的评估体系——同时监控安全指标和能力指标；(4) 渐进式对齐——小步迭代而非一次过度优化。
Constitutional AI 和标准 RLHF 有什么区别？
标准 RLHF 依赖大量人类标注的偏好数据训练 RM，而 Constitutional AI (CAI) 用一组明确的原则（"宪法"）指导 AI 自我批评和修正。CAI 分两阶段：(1) Supervised 阶段——模型生成初始回答后，按宪法自我批评并修正，修正后的回答做 SFT 数据；(2) RL 阶段——用 AI 根据宪法判断偏好（RLAIF），训练 RM 后做 RL 优化。核心优势是大幅减少人类标注需求，同时可以系统化地覆盖安全原则。CAI 还衍生出自动化 Red Teaming，让 AI 生成攻击性 prompt 测试自身。
如果让你为一个新的 LLM 设计对齐方案，你会怎么选择？
设计思路取决于资源、数据和任务：(1) 首先做高质量的 SFT，这是所有对齐方法的基础；(2) 如果有高质量偏好对数据且资源有限，首选 DPO——简单稳定效果好；(3) 如果需要最强效果且资源充足，用 RLHF (PPO) 或 GRPO；(4) 如果任务可以定义规则奖励（如代码/数学），GRPO 是最佳选择（参考 DeepSeek-R1）；(5) 如果只有好坏标签没有偏好对，用 KTO；(6) 使用 RLAIF 扩展偏好数据规模；(7) 引入 Constitutional AI 做安全保障；(8) 注意监控对齐税和过优化，设置合理的 early stopping。整体思路：SFT → DPO/GRPO → 迭代评估+修正。
