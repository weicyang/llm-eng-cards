S08 · LLM 推理网关

虚拟钥与项目预算 / 统一协议与供应商适配 / 熔断 fallback / 网关语义缓存的版本隔离 / 与 MCP 网关分家

推理网关不是「又一个反向代理」。它是把概率性的模型调用收成一层确定性外壳：谁能花多少钱、超时怎么切、失败切到谁、同一问句能不能复用旧答案。

整后端怎么切、限流队列怎么接消息中间件、Agent 内部怎么按难度选模型，分别见 S01、ST22、A63、ST06。本卡只讲模型调用这一跳做成产品时多出来的旋钮，以及什么时候不该做网关。

一、业务代码里的 SDK 会把密钥和账单打散

每个服务直接持有厂商 API Key，看起来少一跳延迟，三个月后一定出现：密钥无法按项目吊销、账单无法按团队切、重试策略各写各的、A 厂商挂了 B 业务跟着死。网关要收走的不是流量，而是密钥生命周期、配额、失败语义、观测字段这四样横切物。

散落在业务里收到网关后
厂商 Key 进环境变量只有网关持有；业务拿虚拟钥
各服务自己 retry/timeout按错误码分层：超时、限流、内容过滤分开
账单月底对发票按虚拟钥 / 项目 / 模型实时累计
日志格式十种统一 trace：模型、token、缓存命中、fallback 次数
收口之前 / 之后 【之前】 服务A ──Key1──► 厂商X 服务B ──Key2──► 厂商X 服务C ──Key3──► 厂商Y 吊销要改三个仓库 【之后】 服务A/B/C ──虚拟钥──► 推理网关 ──厂商Key──► X / Y 吊销虚拟钥即可；厂商 Key 轮转对业务不可见

延迟多一毫秒通常换得回来；密钥散落通常换不回来。网关的第一笔 ROI 是事故半径，不是 QPS。

二、虚拟钥、项目预算与统一协议

虚拟钥是发给业务的内部令牌：绑定项目、环境（dev/stage/prod）、允许的模型名单、日预算、是否允许流式。网关把 OpenAI 兼容表面留给业务，背后适配各家差异（工具调用字段、思考 token 计费、缓存命中折扣）。业务禁止感知「今天走的是哪一家」——感知了，fallback 就写不成。

绑定项作用绑错的后果
项目 / 环境账单与密钥隔离prod 密钥被 stage 打爆
模型白名单贵模型不能被实验流量误用一次循环 Agent 烧完月预算
日/月预算硬顶，超了失败关闭或降级只有告警没有闸
数据驻留标记合规流量禁止出域fallback 到境外模型
允许调用 = 虚拟钥有效 ∧ 模型∈白名单 ∧ 预算未爆 ∧ 驻留策略允许该 provider

统一协议的目标不是「兼容所有 SDK 特性」，而是让 90% 的调用能换厂商而不改业务代码。剩下 10% 的专有字段走显式开关，不要偷偷透传。

三、多厂商熔断、超时分层与 fallback

模型调用的失败不是一种。把所有错误都 retry 三次，会把内容过滤和余额不足打成风暴。分层：

错误分层（网关必须分开处理） 超时 / 5xx / 网络 → 对同类 provider 短重试，再 fallback 429 限流 → 按 Retry-After 排队或切备用，禁止打爆 4xx 请求错误 → 不重试，直接回业务 内容过滤 / 安全拒绝 → 不 fallback 到「更松」的模型，除非策略显式允许 余额 / 鉴权失败 → 熔断该 provider，告警人工
策略适合不要用于
同模型多区域可用性合规驻留流量
同级开源备援阅读、分类强约束的函数调用格式
降级到小模型摘要、路由高风险生成（合同、医疗）
失败关闭写操作建议、支付话术「先随便答一句」
示例场景：主厂商连续 8 分钟 5xx，三个业务方各写各的重试，聚合 QPS 把备用厂商也打到 429。网关按虚拟钥做令牌桶 + 熔断半开后，故障窗口内备用厂商错误率从 41% 回到个位数，主厂商恢复后半开探测 30s 再切回。业务代码零修改。

Fallback 是可用性工具，不是质量工具。切过去必须记录「这次答的是备援」，评测和审计才能解释为什么同一问句风格突变。

四、网关级语义缓存何时有害

网关很适合做 语义缓存：embedding 近邻命中则跳过模型。ST06 讲过收益与版本隔离。这里只强调网关层特有的坑：缓存键如果不含模型 ID、系统提示哈希、工具定义哈希、温度，就会把「旧 Prompt 跑在新模型上」的答案送给用户。

键里必须有漏了会怎样
模型版本（全名，不是别名）供应商升级后仍吐旧 completion
系统提示 / 工具 schema 哈希改了规则仍命中旧政策
租户或权限标签A 租户的答案泄漏给 B
温度与采样参数T=0 的缓存被 T=0.8 复用

什么问句不该进语义缓存：带时间的事实、带用户私有数据、工具结果刚变过的后续轮。命中率不是 KPI；错误命中才是事故。

示例场景：客服网关语义缓存命中率做到 38%，token 账单明显下降。一次系统提示修订「退货窗口从 7 天改为 15 天」后，因为键里没有提示哈希，三天内约 1/5 的命中仍在引用 7 天。加上提示哈希并在发布时主动使该前缀失效后，错误命中在灰度中降到可忽略，命中率回落到 31%——这是正确的，少掉的那 7 个点本来就不该命中。

缓存的正确性条件比命中率重要一个数量级。宁可 20% 命中全对，不要 50% 命中里掺政策错误。

Agent 决定「要不要思考」；推理网关决定「思考调用能不能花这笔钱、挂了切哪家」；工具网关决定「这只手能不能碰付款按钮」。

六、落地顺序与关闭条件

先收密钥与预算，再做 fallback，最后才做语义缓存。

虚拟钥按环境拆；prod 禁止共用 dev 预算。

fallback 写入 trace，评测按「实际模型」切片。

不要让业务 SDK 直连厂商「再抄一份到网关」双轨长期并存。

不要对内容安全拒绝做跨厂商重试。

不要把工具调用重试策略套用到模型调用上，或反过来。

什么时候不要上：单厂商、单应用、QPS 很低、合规也不要求密钥集中。多一个网关就多一个故障域。出现第二个厂商、第二个团队抢同一把 Key、或账单开始说不清时，再收口。

观测字段最小集：虚拟钥、项目、请求 ID、实际模型版本、prompt/completion token、缓存命中、fallback 次数与原因、驻留策略是否拒绝。缺「实际模型」时，EV09 的在线分无法按供应商切片，故障会记在「模型变笨」而不是「切到了备援」。

网关自身要有失败关闭：网关挂了不能让业务自动改回直连厂商 Key。直连是逃生舱，应走一次性破玻流程，而不是藏在 SDK 默认配置里。

容量上把「网关 CPU」和「下游 TPM」分开告警。网关被自己的 JSON 日志或同步鉴权拖死时，下游看起来还很空，业务却全超时。扩模型副本解决不了这一层。

Q&A

S01 已经有 API Gateway，为什么还要 LLM 推理网关？
S01 的网关是通用流量门：鉴权、限流、SSE。LLM 推理网关多出来的是模型协议适配、思考 token 与缓存命中的计费口径、按模型的熔断、语义缓存键。用 Nginx 也能转发 HTTPS，但不会帮你在 Prompt 变更时主动失效缓存，也不会把「内容过滤」从「可重试 5xx」里拆出来。
虚拟钥泄漏了怎么办？
吊销这一把，厂商主 Key 不用动。这就是收口的意义。虚拟钥还应绑 IP / 工作负载身份、短 TTL 轮转。泄漏后看该钥的预算消耗曲线，能把爆炸半径限制在一个项目而不是全公司。
Fallback 会不会让评测失效？
会，除非 trace 记录实际命中的模型版本。在线评测（EV09）必须按实际模型切片，否则「主模型变差」会被备援的稳定发挥掩盖，或反过来。Fallback 是运维动作，要当实验因素，不当噪音滤掉。
语义缓存在多轮对话里能做吗？
仅当键包含截至本轮的对话哈希或明确的「可缓存前缀」。多轮里用户纠正了上一句，近邻命中上一轮答案是事故。实操是：只缓存单轮、无工具、无个性化的 FAQ 类；带工具或带记忆的请求默认不走语义缓存。
自建 vLLM 还要不要这层网关？
要，只要你还有云 API 或第二集群。网关对内把自建当成又一个 provider：健康检查、排队、与云 API 的 spillover。纯内网单集群可以先做薄适配（虚拟钥+预算），不必上语义缓存。
和 ST03 的 API 稳定性是重复的吗？
ST03 讲调用方怎么做重试、熔断、结果缓存。本卡讲这些策略作为共享基础设施如何按厂商错误码统一落地，避免每个服务抄一遍抄歪。应用仍要处理网关返回的业务错误；瞬时重试不应再写在每个服务里。
延迟敏感的语音链路能过网关吗？
能，但要单独的低延迟池：禁语义缓存、禁长队列、超时比文字更短，必要时旁路到就近推理。不要和批处理摘要共用一个令牌桶。语音的正确性对延迟过敏，见 A74。
网关要不要做内容安全过滤？
输入输出的基础过滤可以做，但不要替代业务策略。网关过滤应失败关闭并留下原因码；不要把过滤失败 fallback 到「更松的模型」。高风险域把最终策略放在业务 PEP，网关只做明显违规的第一刀。
虚拟钥按人发还是按服务发？
按工作负载发：每个服务一个钥，人的身份走业务鉴权。按人发会让桌面调试钥流进生产。需要到人的账单时，在请求头传 actor，由网关记日志，不要把人当 provider 客户。
