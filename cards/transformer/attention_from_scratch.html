T06 · Attention：从零实现缩放点积注意力

Q/K/V 线性投影 / QKᵀ 相似度打分 / √d_k 缩放 / softmax 归一化 / 加权聚合 V / NumPy 逐步 shape 追踪

Attention 的本质只有一句话：让每个 token 给句子里所有 token 打分，把分数变成概率，再按概率把别人的信息加权搬运回自己手里。整个过程就是三次矩阵乘法，没有任何循环，天然并行。

一、Attention 在做什么

先看一个例子：「小李说他昨天终于看懂了 Transformer」。当模型处理「他」这个字时，必须判断「他」指的是谁。此时「他」这个位置需要环顾整个句子：「小李」的相关性最高，「昨天」「看懂了」有一定参考价值，「了」这类虚词几乎无关。Attention 做的就是这件事——动态路由，即每个位置根据语义相关性，动态决定从哪些位置取多少信息，而不是像 CNN 那样只看固定邻域。

把这件事拆成三个动作，就是 Attention 的全部核心：

步骤做什么数学操作输出形状
① 计算相关性当前词和所有词的匹配分数Q @ Kᵀ(L, L)
② 归一化把分数转成和为 1 的概率分布softmax（逐行）(L, L)
③ 加权聚合用概率对信息做加权求和weights @ V(L, d_v)

用一个极简句子「远方有颗苹果树」做全程演示：L=7 个 token，每个 token 经 embedding 后是 4 维向量（真实模型常用 512、1024 甚至更大，这里取 4 纯粹方便肉眼验证）。输入就是一个普通的二维矩阵：

import numpy as np
L, d_model = 7, 4              # 序列长度 7，embedding 维度 4
np.random.seed(42)
X = np.random.randn(L, d_model)  # 模拟 embedding 层输出
print(X.shape)                 # (7, 4)：7 行 token × 4 列特征

(7, 4) 的含义是：7 行代表 7 个 token，4 列代表每个 token 的向量表示。从这里出发，所有 Attention 操作都是对这个矩阵的线性变换与乘法组合。完整数据流如下：

输入 X (L, d_model) │ ├── @ W_Q ──→ Q (L, d_k) ──┐ ├── @ W_K ──→ K (L, d_k) ──┼──→ Q @ Kᵀ ──→ scores (L, L) └── @ W_V ──→ V (L, d_v) ──┘ │ ÷ √d_k ← 缩放，压住数值 │ softmax（逐行归一化） │ weights (L, L)，每行和为 1 │ weights @ V ▼ output (L, d_v)，与输入同形

Attention 不是「查找」而是「软查找」：普通字典是 key 精确匹配命中一条，Attention 是所有 key 都按匹配度参与，匹配度高的多拿信息、匹配度低的少拿，全程可导，所以能端到端训练。

二、Q/K/V：一个输入的三副面孔

Q（Query） 表示「我想找什么信息」，K（Key） 表示「我能被什么样的查询找到」，V（Value） 表示「找到我之后实际取走的内容」。三者都来自同一个输入 X，只是分别乘了三个不同的可学习权重矩阵：

d_k = d_v = 4
W_Q = np.random.randn(d_model, d_k)   # 可学习参数，真实训练中由梯度更新
W_K = np.random.randn(d_model, d_k)
W_V = np.random.randn(d_model, d_v)
Q = X @ W_Q    # (7,4) @ (4,4) = (7,4)
K = X @ W_K
V = X @ W_V

为什么同一个 X 要变换三次，而不是直接拿 X 既打分又当内容？因为同一个词在不同角色下需要呈现不同的侧面。以「苹果」为例：作为 Query 时它关心「我需要什么上下文」（水果？公司？）；作为 Key 时它要亮出「我的索引特征」供别人匹配；作为 Value 时它承载实际要传递的语义内容。三个独立的权重矩阵给了模型三个可以自由学习的视角，如果共用一个矩阵，这三种角色就被强行绑死，表达能力大打折扣。

角色类比（图书馆检索）参与哪一步维度
Query你脑中的检索需求与 K 点积打分d_k
Key每本书封面上的索引标签被 Q 匹配打分d_k
Value书的正文内容被权重加权聚合d_v

Q/K 负责「决定看谁」，V 负责「看到什么」。打分系统和内容系统解耦，模型才能学到「虽然这个词跟我不太像，但它对我很有用」这种复杂依赖。

三、QKᵀ 与 (L,L) 注意力矩阵

有了 Q 和 K，下一步计算所有位置两两之间的相关性。为什么用点积？因为两个向量方向越接近、点积越大，点积天然就是「相似度」的度量，而且一次矩阵乘法就能把 L×L 个配对全部算完：

# Q @ Kᵀ: (7,4) @ (4,7) = (7,7)
scores = Q @ K.T
print(scores.shape)   # (7, 7)

得到的这个 (7, 7) 矩阵就是全文最重要的中间产物——注意力分数矩阵。它的读法有明确约定：行代表发起查询的位置（谁的视角），列代表被查看的位置（看谁），元素 [i, j] 表示第 i 个 token 对第 j 个 token 的关注分数。例如 scores[2, 0] 就是「有」这个字对「远」这个字的原始打分。

被看的位置 j（Key） 远 方 有 颗 苹 果 树 查询方 i 远 ┌ · · · · · · · ┐ (Query) 方 │ · · · · · · · │ 有 │ · · · · · · · │ ← scores[i,j] = 颗 │ · · · · · · · │ Q[i] · K[j] 苹 │ · · · · · · · │ 果 │ · · · · · · · │ 树 └ · · · · · · · ┘ 行 = 谁在问；列 = 看谁；每行之后会归一化成和为 1 的分布
观察角度含义工程用途
某一行一个 token 对所有位置的关注度分布softmax 后逐行和为 1
某一列一个位置被全体 token 关注的程度发现「sink token」等汇聚现象
对角线每个位置对自己的关注通常较高，起残差保底作用
矩阵整体L×L 个打分，规模随 L 平方增长长序列显存的主要瓶颈

(L, L) 矩阵就是整个序列的「关系全景图」：把每一行单独拎出来看，就是一个 token 的注意力分配方案。很多可解释性工作（注意力热力图、指代分析）本质上都是在可视化这张表。

四、为什么要除以 √d_k

缩放点积注意力（Scaled Dot-Product Attention）里的「缩放」指的就是这一步：把 scores 整体除以 √d_k。这是论文中一个看似微小、实则决定训练能否正常进行的关键操作：

scaled = scores / np.sqrt(d_k)
print(scores.min(), scores.max())   # 缩放前: -4.23 ~ 3.87
print(scaled.min(), scaled.max())   # 缩放后: -2.12 ~ 1.94

道理要从点积的统计性质说起。假设 Q、K 的每个分量都是均值 0、方差 1 的独立随机变量，那么 d_k 个分量乘积之和的方差就是 d_k，标准差是 √d_k。d_k=4 时标准差只有 2，看不出问题；但真实模型 d_k=64 甚至 128，点积的标准差会达到 8~11，个别打分动辄 ±30。这么大的数送进 softmax 会发生什么？指数函数会把差距无限放大：最大值 softmax 后逼近 1，其余位置逼近 0，分布退化成 one-hot。

softmax 饱和示意（同一组打分，缩放前 vs 缩放后） 缩放前 scores ≈ [-28, 31, -12, 5, ...] d_k=512, std≈22.6 softmax → [0.000, 0.999, 0.000, 0.001] ← 近似 one-hot，已饱和 ∂softmax/∂x ≈ 0 → 梯度消失，参数几乎不更新 缩放后 scores ≈ [-1.2, 1.4, -0.5, 0.2, ...] 除以 √512≈22.6 softmax → [0.07, 0.55, 0.08, 0.16, ...] ← 平滑分布，梯度健康
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
状态打分范围（d_k=512）softmax 分布形态梯度情况训练结果
不缩放±30 以上常见近似 one-hot，饱和梯度趋近 0loss 停滞，学不动
除以 √d_k压回 ±2 左右平滑的概率分布梯度量级正常稳定收敛
生产案例 1 · 漏掉缩放导致的训练事故（典型场景）：某团队复现一个多语言翻译模型，d_k=512，实现时遗漏了缩放步骤。训练日志显示打分标准差高达 22.4，softmax 后最大权重平均 0.97，注意力分布几乎全是 one-hot；梯度范数跌到 1e-5 量级，loss 卡在 9.8 连续 2 个 epoch 纹丝不动。补上 / np.sqrt(d_k) 一行后，同样的数据与初始化，loss 在 3 个 epoch 内降到 2.3，最终 BLEU 提升 4.2 分。一行代码，决定训练成败。

√d_k 是 softmax 的「空调」：维度越高，点积越容易「过热」，除以 √d_k 把温度调回舒适区，softmax 才有分辨力，梯度才有信号。

五、softmax 归一化与加权聚合

缩放之后，逐行做 softmax，把每一行打分转成和为 1 的概率分布。注意实现细节：先减去该行最大值再做指数，这是防止 数值溢出 的标准手法——exp(1000) 会直接得到 inf，而减去最大值不改变 softmax 结果（分子分母同乘一个常数会约掉），却能把所有指数项压到 (0, 1] 区间：

def softmax(x):                     # 逐行 softmax，数值稳定版
    e = np.exp(x - np.max(x, axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

weights = softmax(scaled)           # (7, 7)，每一行和恰好为 1

此时的 weights 矩阵有了完整的概率解释：第 i 行是第 i 个 token 的注意力预算分配方案，数值越大说明该位置越值得看。最后一步，用这组权重对 V 做加权求和，完成信息聚合：

output = weights @ V    # (7,7) @ (7,4) = (7,4)
print(output.shape)     # (7, 4)，与输入 X 完全同形

注意观察最终结果：输出形状和输入一模一样，都是 (L, d_model)，但每个 token 的向量已经不是它自己了——它是全句信息的加权混合，混合比例正是刚才算出的注意力分布。这个「输入输出同形」的性质极其重要，它意味着 Attention 可以像积木一样任意堆叠，这也是 Transformer 能一层层加深的基础。

实现方式写法7 token 没问题L=8192 时的表现
Python 双重循环for i, for j 逐对点积能跑慢到无法使用（L² 次 Python 调用）
NumPy 矩阵乘法Q @ K.T 一步到位快单次 BLAS 调用，但仍要物化 L×L 矩阵
框架融合算子FlashAttention 等快不落地 L×L，显存 O(L)，速度快 2~4 倍
生产案例 2 · 长上下文下的 O(L²) 显存墙（典型场景）：某客服对话系统把上下文窗口从 2K 扩到 32K。按朴素实现，单层注意力分数矩阵在 32 头、fp16 下的显存为 L² × 32 × 2 字节：L=2048 时约 268MB，L=32768 时暴涨到约 64GB——单层就把 H100 80GB 吃掉大半，堆叠几十层完全不可能。团队改用 FlashAttention 后，L×L 矩阵不再写入显存而是分块在片上计算，注意力部分显存从 O(L²) 降到 O(L)，单卡可服务并发数提升约 2.2 倍，首 token 延迟从 1.9s 降到 0.8s。

softmax 给每个 token 发了一张「注意力预算表」，加权求和就是按预算表去各个位置采购信息——预算总和恒为 1，所以谁都不能无限索取，模型必须学会取舍。

六、全景：shape 流转与工程要点

把五步串起来，就得到了完整的缩放点积注意力函数。核心不到 10 行，但每一行都对应前面讲过的一个机制：

def scaled_dot_product_attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = Q @ K.T                   # ① 相似度打分 → (L, L)
    scores = scores / np.sqrt(d_k)     # ② 缩放，防止 softmax 饱和
    e = np.exp(scores - scores.max(axis=-1, keepdims=True))
    weights = e / e.sum(axis=-1, keepdims=True)   # ③ 逐行 softmax
    return weights @ V, weights        # ④ 加权聚合 V → (L, d_v)

全程 shape 变化一张表看清。注意中间出现 (L, L)、首尾保持 (L, d_model) 这两个特征，它们是理解一切 Attention 变体的钥匙：

步骤操作形状变化语义
输入embedding 输出 X(L, d_model)L 个独立 token
投影@ W_Q / W_K / W_V(L, d_model) → (L, d_k)/(L, d_v)生成三种视角
打分Q @ Kᵀ(L, d_k) → (L, L)两两相关性
缩放+softmax÷√d_k，逐行归一化(L, L) → (L, L)分数变概率
聚合weights @ V(L, L)×(L, d_v) → (L, d_v)信息加权混合
shape 流转全景（L=7, d_model=4, d_k=d_v=4） X (7,4) ──→ Q,K,V 各 (7,4) ──→ scores (7,7) ──→ 缩放 (7,7) │ output (7,4) ←── weights @ V ←── weights (7,7) ←──┘ │ 每行和=1 └─ 与输入同形 → 可堆叠、可加残差、可进 LayerNorm
生产案例 3 · 用注意力矩阵定位线上 Bad Case（典型场景）：某文档问答系统上线后答案引用错误率偏高。团队抽取 500 条 bad case 绘制注意力热力图，发现 62% 的错误源于模型把 70% 以上的注意力压在文档开头摘要段，正文关键证据几乎零权重（典型的「头重脚轻」偏置）。针对性地在训练数据中下采样纯摘要可回答的样本、并对正文证据段做位置增强后，答案引用准确率从 61% 提升到 79%，人工抽检返工量下降约一半。注意力矩阵不只是中间变量，它是最直接的调试探针。
  • softmax 永远写成「先减行最大值」的数值稳定版
  • 缩放因子用 1/√d_k 预乘，或直接乘倒数，避免逐次除法
  • 学习/调试时打印每一步 shape，用形状断言提前抓 bug
  • 需要屏蔽未来位置或 padding 时，在 softmax 前给对应分数加 −∞（实践中用 -1e9）
  • 不要省略缩放：d_k 一大，训练直接饱和崩溃
  • 不要用 Python 循环算两两分数，L² 次调用会被拖死
  • 不要直接 np.exp(x) 裸算，fp32 下 x>88 就溢出
  • 不要把注意力权重当成严格的「可解释性证明」，它是相关线索而非因果证据

整篇文章浓缩成一句话：三个矩阵乘法（投影、打分、聚合）加一个 softmax，就让每个位置「看到」了全局并把有用信息搬了回来——这就是现代大模型全部注意力能力的地基。

Q&A

为什么用点积算相似度，而不是余弦相似度或小型 MLP？
点积的最大优势是可以写成一次矩阵乘法，L² 个配对能在 GPU 上并行算完，硬件利用率极高；余弦相似度需要逐对归一化，难以融合成单次 matmul，而且 W_Q/W_K 可学习，模型能自己调出比固定余弦更好的度量。用 MLP 打分（如早期的 Bahdanau attention）表达力虽强，但无法批量并行，序列一长就慢得无法接受。工程上的折中是：用可学习投影 + 点积，把表达力交给 W_Q/W_K，把速度交给矩阵乘法。
为什么输出形状和输入完全一样？这有什么深层意义？
输出 (L, d_model) 与输入同形不是巧合，而是刻意设计。它意味着 Attention 层的输出可以直接与输入做残差相加，再过 LayerNorm 后送入下一层，整个网络的宽度在全程保持一致，堆叠多少层都不会改变张量规格。如果输出维度变了，每层之间就要额外加适配矩阵，参数量和工程复杂度都会上升。同形设计让 Transformer Block 变成了真正的「标准积木」，这也是后来各种深度模型能简单堆叠到上百层的前提。
softmax 后的注意力分布是越尖锐越好吗？
不是，两种极端都有问题。分布过尖锐（接近 one-hot）意味着每个 token 只听一个位置的信息，等价于硬选择，容错差且梯度接近零，训练信号消失；分布过平均（接近均匀分布）则说明模型对谁都一样关注，等于没有筛选能力，输出退化成全体 V 的简单平均。健康的分布应当随任务自适应：需要精确对齐时（如翻译中的词对齐）偏尖锐，需要综合全局时（如情感判断）偏平滑。缩放因子、温度、训练数据都会影响最终的尖锐程度。
softmax 里减去最大值是必须的吗？不减会怎样？
从数学上看不减也「正确」——softmax 对输入整体加常数不敏感，减不减结果相同；但从数值上看不减会出事故。指数函数增长极快，fp32 下 exp(89) 左右就溢出成 inf，而注意力打分在长维度下轻松超过这个量级，一旦某行出现 inf，整行归一化结果变成 nan，训练直接崩掉。减去行最大值保证最大的指数项恰好是 exp(0)=1，其余都小于 1，永远不溢出。这是零成本的防御性写法，任何生产实现都应默认带上。
这套实现只能处理文本吗？图像和音频能用吗？
完全可以。Attention 对输入的唯一要求是「一串向量」，至于向量来自哪里它并不关心。视觉 Transformer（ViT）把图像切成 16×16 的 patch，每个 patch 线性投影成一个 token，之后走的流程和本文完全一致；音频模型把梅尔频谱切成帧当作 token 序列；多模态模型甚至把图像 patch、文本 token、音频帧拼在同一条序列里做联合注意力。所以本文的 NumPy 实现换个输入来源就能直接复用，这正是 Attention 成为通用序列建模原语的原因。
自注意力和编码器-解码器之间的交叉注意力有什么区别？
区别只在 Q/K/V 的来源。自注意力中 Q、K、V 全部来自同一条序列 X，每个位置在句内互相看；交叉注意力中 Q 来自一条序列（如解码器当前状态），K 和 V 来自另一条序列（如编码器输出），实现的是「拿着我的问题去你的内容里检索」。本文的 scaled_dot_product_attention 函数两种场景都能用，因为函数只接收 Q、K、V 三个参数，不关心它们从哪来——这也是把打分与内容解耦带来的额外好处。
序列长度翻 4 倍，注意力的计算量和显存分别怎么变？
都按平方增长，因为打分矩阵是 (L, L) 的。L 翻 4 倍，Q @ Kᵀ 和 weights @ V 两次矩阵乘法的 FLOPs 都变成 16 倍，注意力分数矩阵占用的显存也变成 16 倍。举例：32 头、fp16 下 L=2048 的单层分数矩阵约 268MB，L=8192 时就是约 4.3GB。这就是长上下文模型必须上 FlashAttention（不物化 L×L）、稀疏注意力或线性注意力等优化的根本原因，也是上下文窗口大小与推理成本之间的核心矛盾。
