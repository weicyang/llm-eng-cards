Transformer Architecture Deep Dive — 从论文到工程实现的全面解析

一、 "Attention Is All You Need" 论文背景

Transformer 的贡献不是发明了注意力，而是证明「去掉循环结构之后模型反而更强」——因为能并行，才拿得到通往规模化的门票。

1.1 历史动机

2017 年，Google Brain 团队（Vaswani et al.）发表论文 "Attention Is All You Need"，正式提出 Transformer 架构。这篇论文的核心目标是完全摆脱循环结构（RNN/LSTM），仅依靠注意力机制来建模序列关系。

1.2 为什么要摆脱 RNN？

问题RNN/LSTM 的困境Transformer 的方案
并行性时间步必须顺序计算，无法并行所有位置同时计算 Attention
长距离依赖信息随步数衰减，梯度消失/爆炸Attention 直接连接任意两个位置，路径长度 O(1)
训练速度受限于序列长度，训练慢GPU 高度并行，训练速度大幅提升
可扩展性难以有效 scale up参数和数据可按 Scaling Laws 持续扩展

1.3 论文核心贡献

  • Self-Attention 机制：用缩放点积注意力替代循环计算
  • Multi-Head Attention：多个注意力头并行捕获不同子空间的信息
  • Positional Encoding：用正弦/余弦函数为序列注入位置信息
  • Encoder-Decoder 架构：经典的序列到序列范式
  • 在 WMT 翻译任务上取得 SOTA，训练时间仅为此前最优模型的一小部分
  • Transformer 并非「发明了 Attention」，而是证明了仅用 Attention 就够了（不需要 RNN/CNN）
  • 关键突破：可并行化 → 可利用 GPU → 可 scale → 催生 GPT/BERT 等大模型
  • 论文标题就是核心观点：Attention is ALL you need

二、 整体架构

Encoder 把整句话压成一份"可查阅的资料"，Decoder 一边写一边回头查这份资料——Cross-Attention 就是那次查阅动作。

2.1 Encoder-Decoder 结构全景

原始 Transformer 采用经典的 Encoder-Decoder 结构：

  • Encoder：将输入序列 (x₁, x₂, …, xₙ) 映射为连续表示 (z₁, z₂, …, zₙ)
  • Decoder：基于 Encoder 输出，自回归地生成目标序列 (y₁, y₂, …, yₘ)
  • Encoder 和 Decoder 各堆叠 N=6 层（原始论文设定）

2.2.1 张量形状的流转

把上面的方框图换成张量视角，更容易看清每一步到底在变什么（B = batch，n = 源长度，m = 目标长度，d = d_model，h = 头数，V = 词表大小）：

tokens [B, n] │ Token Embedding (V x d) ▼ X [B, n, d] │ + Positional Encoding (n x d，按 batch 广播相加) ▼ ┌── Encoder Layer x 6 ───────────────────────────────────┐ │ Q,K,V = X·W_Q / X·W_K / X·W_V [B, h, n, d/h] │ │ scores = Q·Kᵀ / sqrt(d_k) [B, h, n, n] │ ← O(n²) 的来源 │ ctx = softmax(scores)·V [B, h, n, d/h] │ │ concat(h 个头) · W_O [B, n, d] │ │ FFN: d → 4d → d [B, n, d] │ └────────────────────────┬───────────────────────────────┘ ▼ Z (memory，Encoder 最终输出) [B, n, d] │ 整个解码过程中不变，K/V 只投影一次 ┌── Decoder Layer x 6 ───┼───────────────────────────────┐ │ Masked Self-Attn │ [B, h, m, m] │ 上三角填 -inf │ Cross-Attn: Q←Decoder, K/V←Z ◄─────── [B, h, m, n] │ │ FFN: d → 4d → d [B, m, d] │ └────────────────────────┬───────────────────────────────┘ ▼ Linear (d x V) + Softmax [B, m, V] ▼ next-token 概率分布

值得注意的是 [B, h, n, n] 这一步——它是唯一一个和序列长度成平方关系的中间张量，长文本场景的显存与算力压力几乎全部来自这里。

2.3 数据流（以翻译任务为例）

  1. 输入端：源语言 token → Input Embedding → 加 Positional Encoding
  2. Encoder：经过 6 层 Encoder Layer，每层包含 Self-Attention + FFN，输出上下文表示 Z
  3. Decoder 输入：目标语言 token（shifted right）→ Output Embedding → 加 Positional Encoding
  4. Decoder：经过 6 层 Decoder Layer，每层包含 Masked Self-Attention + Cross-Attention + FFN
  5. 输出端：Linear 投影到词表大小 → Softmax 得到概率分布 → 选取 next token
  • Encoder 的每一层都能"看到"整个输入序列（双向 Attention）
  • Decoder 的 Self-Attention 是 causal（因果的），只能看到已生成的 token
  • Cross-Attention 让 Decoder 的每个位置都能关注 Encoder 的完整输出

三、 Encoder 层详解

Encoder 的一层只做两件事：先让所有词互相"交换情报"（Attention），再让每个词各自"消化情报"（FFN），剩下的残差与归一化都是为了让这两件事能安全地叠上几十层。

3.2 各子层作用

子层作用核心机制
Multi-Head Self-Attention捕捉序列内部所有位置之间的依赖关系每个 token 对所有其他 token 计算注意力权重
Add & Norm（第一个）残差连接 + 层归一化，稳定训练output = LayerNorm(x + SubLayer(x))
Feed-Forward Network对每个位置独立做非线性变换，增加模型表达力两层全连接网络，中间用 ReLU/GELU 激活
Add & Norm（第二个）同上，残差连接 + 层归一化output = LayerNorm(x + FFN(x))

3.3 Self-Attention 计算过程

Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V

其中 Q、K、V 分别由输入 X 经过不同的线性投影得到：

Q = XW_Q, K = XW_K, V = XW_V
W_Q, W_K ∈ ℝ^{d_model × d_k}, W_V ∈ ℝ^{d_model × d_v}

3.4 Multi-Head 机制

MultiHead(Q,K,V) = Concat(head₁, head₂, …, headₕ) · W_O
其中 headᵢ = Attention(QWᵢ_Q, KWᵢ_K, VWᵢ_V)
h = 8 (论文默认), d_k = d_v = d_model / h = 512/8 = 64
  • 为什么要除以 √d_k？防止点积值过大导致 softmax 梯度消失（进入饱和区）
  • Multi-Head 相当于在多个不同的表示子空间中并行执行 Attention
  • Encoder 的 Self-Attention 是双向的，每个 token 可以看到整个输入序列

四、 Decoder 层详解

Decoder 比 Encoder 多的那一层 Cross-Attention，本质是把"我现在想写什么"（Q）拿去和"原文说了什么"（K/V）做匹配。

4.2 为什么需要 Masked Attention？

训练阶段：Decoder 同时接收完整的目标序列（Teacher Forcing），但每个位置 i 只能依赖 ≤ i 的位置信息，否则就是「偷看答案」。

实现方式：在 Attention Score 矩阵的上三角区域填充 -∞，经过 softmax 后这些位置的权重变为 0。

Mask 矩阵示例 (4×4):
┌───┬───┬───┬───┐
│ 0 │-∞ │-∞ │-∞ │   position 0 只看自己
├───┼───┼───┼───┤
│ 0 │ 0 │-∞ │-∞ │   position 1 看 0,1
├───┼───┼───┼───┤
│ 0 │ 0 │ 0 │-∞ │   position 2 看 0,1,2
├───┼───┼───┼───┤
│ 0 │ 0 │ 0 │ 0 │   position 3 看 0,1,2,3
└───┴───┴───┴───┘

4.3 Cross-Attention

Cross-Attention 是 Decoder 与 Encoder 交互的桥梁：

  • Q：来自 Decoder 当前层的输出（代表「我想查询什么」）
  • K, V：来自 Encoder 最后一层的输出（代表「源序列的信息」）
  • 每个 Decoder 位置都能关注整个源序列，实现源→目标的信息传递

4.4 自回归生成过程

  1. 输入起始符 <BOS>
  2. Decoder 生成第一个 token y₁
  3. 将 y₁ 拼接到输入，生成 y₂
  4. 重复，直到生成 <EOS> 或达到最大长度

这就是为什么叫「自回归」——每一步的输出成为下一步的输入。

  • Masked Attention 保证训练时的因果性，和推理时的行为一致
  • Cross-Attention 的 K、V 来自 Encoder，在整个 Decoder 生成过程中保持不变（只需计算一次）
  • 自回归生成是串行的 → 这是 GPT 类模型推理慢的根本原因

五、 残差连接 (Residual Connection)

残差连接的价值不在于"加了一条边"，而在于给梯度留了一条不经过任何变换的直达通道——层数越深，这条通道越值钱。

作用：借鉴自 ResNet，为堆叠数十上百层的网络提供「梯度高速公路」（梯度路径长度 O(L)→O(1)，缓解梯度消失），并保证最坏情况下网络退化为恒等映射而不失效。写法分两种：output = x + SubLayer(x)（Post-Norm）与 output = x + SubLayer(Norm(x))（Pre-Norm）。

关键结论：Post-Norm（原始 Transformer/BERT）调参到位时最终性能可能略好，但对学习率敏感、深层（>24 层）需精心 warm-up；Pre-Norm 训练更稳定、可用更大学习率，是 GPT-2 以后所有现代 LLM（LLaMA、DeepSeek）的标配，代价是最后一层需额外加 Final LayerNorm。

Post-Norm（原始 Transformer / BERT） Pre-Norm（GPT-2 之后 / LLaMA / DeepSeek） x ──────────────┐ x ──────────────┐ │ │ 残差 │ │ 残差 ▼ │ ▼ │ [ SubLayer ] │ [ LayerNorm ] │ │ │ │ │ ▼ │ ▼ │ (+)◄─────────────┘ [ SubLayer ] │ │ │ │ ▼ ▼ │ [ LayerNorm ] (+)◄────────────┘ │ │ ▼ ▼ 输出 输出 （末尾另需 Final LayerNorm） 梯度回传路径：每退一层都要穿过 LN 梯度回传路径：沿残差直达底层，不被 LN 缩放 深层（>24 层）需精心 warm-up 可用更大学习率，深到上百层仍稳定

Pre-Norm/Post-Norm 的完整对比与 Block 内组合方式，详见 T16 · Decoder-Only Transformer 全貌。

六、 Feed-Forward Network (FFN)

作用：FFN 对每个 token 独立执行两层全连接非线性变换 FFN(x) = W₂·σ(W₁x + b₁) + b₂。Attention 负责「位置间信息交换」（近似线性），FFN 负责「位置内特征变换」，提供关键的非线性能力，并充当「键值记忆网络」存储事实知识——参数量约占总参数的 2/3。

关键结论：标准设定 d_ff = 4×d_model（Transformer-Base 512→2048，GPT-3 12288→49152）；现代 LLM 普遍用 SwiGLU 门控激活（有 W₁/W_gate/W₂ 三个矩阵，多 50% 参数），因此 d_ff 缩小到 ≈2.68×d_model 保持参数量平衡（LLaMA-7B：4096→11008）。

SwiGLU/GeGLU 等 GLU 变体公式与 FFN 在 Block 中的角色细节，详见 T16 · Decoder-Only Transformer 全貌。

七、 Layer Normalization

作用：沿 feature 维度做归一化 LayerNorm(x) = γ·(x-μ)/√(σ²+ε) + β，稳定深层网络训练。相比 BatchNorm，它不依赖 batch 统计量、天然支持变长序列、训练与推理行为一致，因此成为 NLP 标配（BatchNorm 的痛点正是变长序列 + 小 batch）。

关键结论：RMSNorm 是 LayerNorm 的简化版——去掉均值中心化与偏置项（RMSNorm(x) = γ·x/RMS(x)），归一化开销减少约 10-15% 且效果相当，是当前主流 LLM 标配（LLaMA/DeepSeek/Gemma 均为 RMSNorm + Pre-Norm；GPT-2/3 为 LayerNorm + Pre-Norm）。

归一化方案在 Block 中的位置与完整演进对比，详见 T16 · Decoder-Only Transformer 全貌。

8.2 为什么 LLM 主流走向 Decoder-Only？

  • 做分类、NER、句向量这类判别任务时，仍优先考虑 Encoder-Only：同等效果下参数量可以小一到两个数量级
  • 需要生成时统一走 Decoder-Only，把"任务"编码进 prompt，而不是为每个任务改架构
  • 跨模态或明确的 seq2seq 场景（语音转写、OCR 后处理）保留 Encoder-Decoder，源端双向理解确实有收益
  • 先明确"输入是否固定、输出是否要生成"，再选架构；架构选型比后续调参影响大得多
  • 不要因为"Decoder-Only 是主流"就用它做纯分类，白白付出自回归解码的推理成本
  • 不要指望给 BERT 接一个解码头就能得到好的生成模型，MLM 预训练没有教会它续写
  • 不要在 Encoder-Decoder 上盲目堆参数，两套 KV Cache 会让长上下文推理的显存翻倍
  • 不要把"双向注意力"当成理解能力的必要条件，规模上去之后单向的差距会被抹平
  1. 统一的训练目标：Next-Token Prediction 是最简单、最通用的训练目标，适用于各种任务
  2. Zero-shot / Few-shot 能力：Decoder-Only 天然支持通过 prompt 进行 in-context learning
  3. Scale 效率：同等参数量下，Decoder-Only 不需要分配参数给 Encoder 和 Decoder 两部分
  4. KV Cache 友好：推理时可利用 KV Cache 实现增量解码，Encoder-Decoder 需要两套 Cache
  5. 工程简洁：只有一个统一的 Transformer block，代码更简单、更容易优化
  6. 实证结果：GPT-3 → ChatGPT → GPT-4 路线的巨大成功，形成了社区惯性
  • Encoder-Only 模型（BERT）不适合生成任务，但在 NLU 任务上仍有优势
  • Decoder-Only 的「劣势」（单向 Attention）通过增大模型规模已经不明显
  • 高频问题：「为什么 GPT 不用 Encoder-Decoder？」→ 简单 + 通用 + scale 高效

九、 为什么 Transformer 能 Scale

Transformer 能 scale，不是因为它更聪明，而是因为它把序列建模改写成了矩阵乘法——而矩阵乘法正是 GPU 唯一真正擅长的事。

9.1 并行化能力

模型时间复杂度（每层）可并行性最长路径
RNNO(n · d²)O(n) — 顺序O(n)
CNNO(n · k · d²)O(1) — 并行O(log_k(n))
TransformerO(n² · d)O(1) — 并行O(1)

其中 n = 序列长度，d = 模型维度，k = 卷积核大小。

9.2 Scaling Laws

Kaplan et al. (2020) 和 Chinchilla (Hoffmann et al., 2022) 发现 Transformer 的性能遵循幂律关系，这组经验规律通常被称为 Scaling Laws：

L(N, D) ≈ A/N^α + B/D^β + E

L = 损失, N = 参数量, D = 数据量
α ≈ 0.076, β ≈ 0.095 (Chinchilla 修正值)
  • 可预测：给定预算可预测最优模型大小和数据量
  • 无饱和：在目前观测范围内，增加 N 和 D 总能带来收益
  • 计算最优：Chinchilla 最优比例 ≈ 20 tokens per parameter

示例场景：一个团队原本用 12 层 BiLSTM 做文档分类，单卡训练一轮 8 小时，序列截断到 256 token 才勉强跑得动。

问题：时间步串行导致 GPU 利用率长期只有 20% 左右，加卡几乎没有收益——瓶颈不在算力而在依赖链。

方案：换成 6 层 Transformer Encoder，d=768、h=12，序列放宽到 512，batch 从 16 提到 96。

效果：GPU 利用率升到 85% 上下，单轮训练时间降到约 50 分钟（约 9.6 倍），验证集准确率还因为上下文变长提升了约 2 个百分点。这个提升里几乎没有"模型更聪明"的成分，全部来自可并行。

9.3 与 RNN/CNN 的本质区别

维度RNNCNNTransformer
序列建模隐状态递推局部窗口卷积全局注意力

  • Transformer 能 Scale 的关键：并行化 + 全局依赖 + 可预测的 Scaling Laws
  • O(n²) 的 Attention 复杂度是 Transformer 的主要瓶颈 → 催生了各种高效 Attention 变体
  • 高频问题：「Transformer 和 RNN 最大的区别？」→ 并行性 + 全局依赖建模 + 可扩展性

十、 Transformer 的参数量计算

记住一个数就够了：每层约 12d²。剩下的 Embedding、LayerNorm、bias 在大模型里都属于零头。

10.1 各组件参数量公式

假设模型有 L 层，模型维度 d，FFN 隐层维度 d_ff，注意力头数 h，词表大小 V：

组件参数量说明
Token EmbeddingV × d词表大小 × 模型维度
Position Embeddingmax_len × d最大长度 × 模型维度（可学习时）

FFN W₁（每层）d × d_ff升维矩阵
FFN W₂（每层）d_ff × d降维矩阵

当 d_ff = 4d 时：每层参数 ≈ 4d² + 8d² = 12d²
总参数 ≈ L × 12d² + V × d (Embedding)

简化估算（忽略 bias 和 LN）：
P ≈ 12 × L × d² (不含 Embedding)

示例场景：要在一张 24GB 显存的卡上做全参数微调，先得判断多大的模型放得下。

问题：只按"参数量 × 2 字节"估算，觉得 7B 模型占 14GB、还剩 10GB 富余，实际一跑就 OOM。

方案：按训练态完整口径重算——bf16 权重 2 字节 + bf16 梯度 2 字节 + Adam 的一阶/二阶动量各 4 字节（fp32），合计每个参数约 12 字节，再加上激活值。

效果：7B 模型光是权重加优化器状态就要约 84GB，24GB 卡上全参微调根本不成立；换成 LoRA 只训练约 0.1% 的参数，优化器状态降到不足 100MB，24GB 卡轻松容纳。用 P ≈ 12Ld² 先估参数量、再乘上"每参数字节数"，是选型时最省事的一次心算。

🔥 Q&A Top 10

Q1: Transformer 为什么要用 Self-Attention 而不是 RNN？

核心答案：三大优势——

  • 并行化：Self-Attention 可以同时计算所有位置之间的关系，而 RNN 必须逐时间步串行计算
  • 长距离依赖：Self-Attention 中任意两个位置的路径长度为 O(1)，RNN 为 O(n)，长距离信息容易丢失
  • 可扩展性：并行化 + GPU → 更大模型 + 更多数据 → Scaling Laws 带来的可预测提升

代价：Attention 的计算复杂度为 O(n²·d)，对长序列不友好。

Q2: 为什么 Attention 要除以 √d_k？

核心答案：

  • 当 d_k 较大时，Q·Kᵀ 的点积结果方差为 d_k，量级较大
  • 大的点积值会使 softmax 进入梯度饱和区（接近 one-hot），梯度接近 0
  • 除以 √d_k 将方差缩放回 1，使 softmax 输出更平滑，梯度更稳定

数学推导：假设 Q、K 各分量独立同分布，均值 0，方差 1，则 QKᵀ 的方差 = d_k，标准差 = √d_k。

Q3: Multi-Head Attention 的意义是什么？为什么不用单头？

核心答案：

  • 不同的头可以关注不同的表示子空间，捕获不同类型的依赖（语法、语义、位置等）
  • 单头 Attention 会让所有信息被平均化，表达力不足
  • Multi-Head 的计算量与同等维度的单头相当（因为每个头的维度 = d_model/h），但效果更好
  • 类比 CNN 的多通道/多 filter：同一层学习不同模式
Q4: Masked Attention 的作用和实现方式？

核心答案：

  • 作用：保证自回归性质，位置 i 只能看到 ≤i 的信息，防止训练时「偷看未来」
  • 实现：在计算 Attention Score 后、softmax 之前，将上三角区域设为 -∞
  • softmax(-∞) = 0，因此未来位置的权重为 0
  • 训练时用 mask 保证因果性；推理时因为是自回归生成，天然满足因果性
Q5: Pre-Norm 和 Post-Norm 的区别？为什么现代 LLM 都用 Pre-Norm？

核心答案：

  • Post-Norm：LN(x + SubLayer(x)) — 原始 Transformer，理论上最终性能略好
  • Pre-Norm：x + SubLayer(LN(x)) — GPT-2 以后的主流
  • Pre-Norm 训练更稳定的原因：残差分支的输入已归一化，梯度不会因层数增加而爆炸
  • Post-Norm 深层时（>24 层）需精心设计 warm-up 和学习率，否则容易发散
  • 对 100B+ 规模的模型，训练稳定性 >> 理论性能微小差距
Q6: FFN 在 Transformer 中的角色？为什么不能去掉？

核心答案：

  • 功能分工：Attention 负责「位置间信息交换」，FFN 负责「位置内特征变换」
  • Attention 本质上是加权平均（近似线性），FFN 提供关键的非线性变换能力
  • 研究表明 FFN 充当键值记忆网络，存储了大量事实知识
  • 去掉 FFN 会导致模型退化为纯线性映射的叠加，表达力严重下降
  • FFN 的参数量占总参数的约 2/3，是模型知识的主要「仓库」
Q7: 为什么 LLM 主流选择 Decoder-Only 而非 Encoder-Decoder？

核心答案：

  • 统一目标：Next-Token Prediction 一个训练目标覆盖所有任务
  • In-Context Learning：Decoder-Only 天然支持 few-shot prompt，不需要为每个下游任务微调
  • 参数效率：同等参数量全部用于一个统一模型，不需要拆分给 Encoder 和 Decoder
  • 工程简洁：一种 Block 堆叠，代码简单、优化方便、推理用 KV Cache
  • 实证驱动：GPT-3/4 的巨大成功验证了这条路线
Q8: RMSNorm 相比 LayerNorm 的优势是什么？

核心答案：

  • RMSNorm 去掉了均值中心化（减均值）操作，只做缩放归一化
  • 计算更快（省去 mean 计算和减法），训练/推理速度提升约 10-15%
  • 研究表明 re-centering 对 Transformer 性能影响很小，归一化的核心是控制量级
  • LLaMA、DeepSeek、Gemma 等主流模型均采用 RMSNorm
Q9: Transformer 的参数量如何快速估算？

核心答案：

  • 快速公式：P ≈ 12 × L × d²（不含 Embedding 和 bias，标准 FFN 即 d_ff=4d）
  • Attention 每层：4d²（QKV + Output），FFN 每层：8d²（d×4d + 4d×d），LN 忽略不计
  • SwiGLU FFN：改为 3 × d × d_ff（3 个权重矩阵）
  • Embedding 参数：V × d（若不共享 LM Head，则还有 V × d）
  • 例：LLaMA-7B → 32 × 12 × 4096² ≈ 6.4B + Embedding ≈ 7B ✓
Q10: Transformer 的 O(n²) 复杂度有哪些解决方案？

核心答案：

  • 稀疏 Attention：只计算部分位置对的 Attention（如 Longformer 的局部+全局模式）
  • 线性 Attention：用核函数近似 softmax，将复杂度降到 O(n)（如 Linear Transformer）
  • FlashAttention：算法不变但利用 GPU 内存层次结构优化 IO，实际速度大幅提升
  • 分组查询注意力 (GQA)：减少 KV Head 数量（LLaMA-2 70B 使用）
  • Multi-Query Attention (MQA)：所有 Query Head 共享同一组 KV（PaLM 使用）
  • 滑动窗口 Attention：只关注固定窗口内的 token（Mistral 使用）
  • 状态空间模型 (SSM)：如 Mamba，从根本上用线性递推替代 Attention

实践中 FlashAttention + GQA/MQA 是目前最主流的组合方案。
