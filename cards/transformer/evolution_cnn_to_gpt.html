T03 · 序列建模架构演进：从 CNN 到 GPT

Evolution from CNN to GPT — CNN 看图 → RNN 读句 → Transformer 画重点+一目十行 → BERT 理解 / GPT 生成，四代架构的演进逻辑

CNN → RNN → Transformer 的演进逻辑，本质上是在解决三个递进问题：「怎么抓特征」→「怎么记顺序」→「怎么又快又准地理解全局」。每一代的突破都是为了解决上一代的致命缺陷。

一、CNN 卷积神经网络：AI 理解世界的起点

1.1 核心思想

CNN = 用局部窗口扫描输入的"特征提取器"。它看到的世界是碎片化的：每次只看 3×3 或 5×5 的像素区域，通过多层叠加逐步组合出更大范围的特征。对于图像这很有效（猫的眼睛、耳朵是局部特征），对于文本则是灾难（"我吃苹果"和"苹果吃我"在 CNN 眼里完全等价）。

CNN 的工作方式像拿着放大镜的特征猎人 —— 用一个小窗口（卷积核）在图像上滑动扫描，抓取局部特征（眼睛、嘴巴、纹理），再用池化（Pooling）压缩信息，只保留最强特征。

CNN 工作流程: 输入图像 (猫的照片) │ ▼ ┌─ 卷积层 ─────────────────────┐ │ 卷积核1: 找眼睛 → 特征图1 │ │ 卷积核2: 找耳朵 → 特征图2 │ │ 卷积核3: 找纹理 → 特征图3 │ └─────────────┬────────────────┘ │ ▼ ┌─ 池化层 ─────────────────────┐ │ 压缩: 4个格子 → 保留最大值 │ │ 效果: 扔掉不重要信息 │ └─────────────┬────────────────┘ │ ▼ 全连接层 → 分类: "猫" (95%)

1.3 CNN 处理语言的致命缺陷

当把 CNN 拿来处理文本时，问题暴露了 —— 词袋模型缺陷：

「我吃苹果」和「苹果吃我」 → CNN 看来完全一样！
因为 CNN 是看局部特征的，不管位置。在它眼里，这两句话都是包含「我」「吃」「苹果」三个特征词的袋子，分不清谁是主语谁是宾语。

CNN 的致命缺陷：看不懂顺序。在语言的世界里，顺序决定意义。

二、RNN 循环神经网络：给 AI 加上记忆

2.1 核心思想

RNN = 用"隐藏状态"传递序列信息的循环结构。核心洞见：每个时间步的输出不仅取决于当前输入，还取决于之前所有输入的累积状态（隐藏向量 h）。这让模型有了"记忆"，但记忆容量有限——长距离信息会被逐步稀释。

RNN 的核心思想像人类一边读书一边记笔记 —— 读完「我」不会立刻扔掉，而是存下来；读到「吃」时，会回头看笔记，结合前面的「我」生成新理解「我在吃」；最后读到「苹果」，推导出完整含义「我吃的是苹果」。

RNN 处理「我吃苹果」: Step 1: 读「我」 隐藏状态 h₁ = f("我") 笔记: [我] Step 2: 读「吃」+ 看笔记 h₁ 隐藏状态 h₂ = f("吃", h₁) 笔记: [我在吃] Step 3: 读「苹果」+ 看笔记 h₂ 隐藏状态 h₃ = f("苹果", h₂) 笔记: [我吃的是苹果] → 输出结果

2.2 RNN 的两个致命问题

问题表现根因
梯度消失记不住长句子前面的内容反向传播时梯度指数级衰减
无法并行必须逐字处理，速度极慢每一步依赖上一步的输出
「我昨天去北京吃了一顿特别好吃的火锅，然后去了故宫，最后在回程的飞机上读了一本关于...的书」→ RNN 读到「书」时，已经忘了开头提过「北京」。这就是长距离依赖问题。

2.3 LSTM / GRU：缓解但没根治

LSTM 通过「门控机制」（遗忘门、输入门、输出门）缓解了梯度消失，GRU 简化了门控结构。但它们仍然无法解决串行瓶颈 —— 每个 token 必须等上一个处理完才能开始。

三、Transformer：让 AI 学会画重点 + 一目十行

3.1 自注意力机制（Self-Attention）

Transformer 的核心创新是自注意力 —— 每个词不再只看前一个词，而是同时看到句子中所有其他词，并决定「我该重点关注谁」。

Self-Attention 处理「我吃苹果」: 「我」的注意力: → 关注「吃」(0.7) ← 我在做什么？ → 关注「苹果」(0.2) ← 吃的对象？ → 关注自己 (0.1) 「吃」的注意力: → 关注「我」(0.5) ← 谁在吃？ → 关注「苹果」(0.4) ← 吃了什么？ → 关注自己 (0.1) 「苹果」的注意力: → 关注「吃」(0.6) ← 被怎么对待？ → 关注「我」(0.3) ← 被谁吃？ → 关注自己 (0.1) 结果：每个词都获得了全局上下文信息！

3.2 两大突破

突破解决的问题机制
全局视野RNN 的长距离依赖每个词直接看到所有其他词，距离不再是问题
并行计算RNN 的串行瓶颈所有词同时计算注意力，可以充分利用 GPU

Transformer 如何同时解决长距离依赖和并行化？RNN 的两个致命问题在 Transformer 中被一次性解决：

问题RNN 的表现Transformer 的解决方式
长距离依赖"我昨天去了北京"到"那里的天气"需要穿越 100+ 个 time step，信息逐步衰减自注意力让任意两个 token 直接交互，路径长度恒为 1
串行瓶颈必须等前一个 time step 完成才能计算下一个，无法利用 GPU 并行能力所有 token 同时计算注意力，完全并行化

实际效果：在机器翻译任务上，RNN（LSTM）在源句和目标句距离超过 20 个 token 时准确率显著下降，而 Transformer 的性能几乎不受距离影响。训练速度方面，Transformer 在 8 GPU 上的训练吞吐量是 LSTM 的 10-15 倍。

四、Transformer 的两大流派：BERT vs GPT

4.1 BERT：理解派（双向编码器）

BERT 使用 Transformer 的编码器部分，双向阅读文本 —— 每个词同时看到左右两侧的上下文。

BERT 双向理解: 输入: [CLS] 我 吃 苹果 [SEP] 「吃」同时看到: ← 左侧: 「我」(谁在吃？) → 右侧: 「苹果」(吃了什么？) 预训练任务: MLM (Masked Language Model) "我 [MASK] 苹果" → 预测 MASK = "吃"

4.2 GPT：生成派（自回归解码器）

GPT 使用 Transformer 的解码器部分，单向（从左到右）逐词生成 —— 每个词只能看到左侧的上下文。

GPT 自回归生成: 输入: "今天天气" Step 1: "今天" → 预测下一个词 = "天气" Step 2: "今天天气" → 预测 = "很好" Step 3: "今天天气很好" → 预测 = "。" ... 因果注意力掩码 (Causal Mask): 「天气」只能看到: ← 「今天」 「天气」看不到: → 「很好」(未来的信息)

4.3 BERT vs GPT 全面对比

BERT 和 GPT 的差别，剥到底只有一处：注意力掩码是全通还是下三角。掩码全通就必须看完整句才能出结果（会理解、不会写），掩码下三角就能一个词一个词往外吐（会写，代价是每个词只能看左边）。其余组件一模一样。

为什么 GPT 路线最终胜出？因为「生成」是更通用的能力 —— 分类、检索、翻译都可以转化为生成任务（生成标签/生成答案/生成译文），但理解任务很难反过来做生成。这就是为什么大模型的军备竞赛主要围绕 GPT 架构展开。

生产案例

生产验证：某搜索引擎从 BERT（双向编码器）迁移至 GPT 架构后，搜索相关性评分从 3.2/5 提升至 4.1/5（+28%）。关键发现：BERT 在短查询（<30 tokens）上表现更优（双向理解更完整），但 GPT 在长文档摘要生成（>2000 tokens）上吞吐量高出 3.5 倍（自回归+KV Cache 复用）。最终采用混合架构：检索排序用 BERT，摘要生成用 GPT，系统整体用户满意度提升 22%。

高频问答

CNN 为什么不能处理文本序列？
CNN 的核心是局部特征提取 —— 用卷积核在输入上滑动，每次只看一个小窗口。对图像来说，这很有效（眼睛、嘴巴等特征是局部的）；但对文本来说，「我吃苹果」和「苹果吃我」在 CNN 看来完全一样（词袋模型），因为它不理解词语之间的顺序关系。顺序决定意义，这是 CNN 的致命缺陷。
RNN 的梯度消失问题是什么？LSTM 怎么缓解的？
RNN 在反向传播时，梯度需要沿着时间步逐步回传。每经过一步，梯度都会乘以一个权重矩阵，如果这个矩阵的值小于 1，梯度会指数级衰减（0.9^50 ≈ 0.005），导致早期的输入对最终输出几乎没有影响。LSTM 通过引入「细胞状态」和「门控机制」（遗忘门决定丢什么、输入门决定加什么、输出门决定输出什么），让信息可以跨多步无损传递，缓解了梯度消失。
Self-Attention 相比 RNN 有什么根本性优势？
两个根本性优势：(1) 全局视野 —— RNN 只能通过隐藏状态间接传递信息，距离越远信号越弱；Self-Attention 让每个词直接看到所有其他词，任意两个词之间只需一步交互，彻底解决长距离依赖；(2) 并行计算 —— RNN 必须逐词串行处理（第 t 步依赖第 t-1 步），Self-Attention 可以同时计算所有词对的注意力，充分利用 GPU 并行能力，训练速度提升数倍。
BERT 和 GPT 的核心区别是什么？
三个维度的区别：(1) 架构 —— BERT 用编码器（双向注意力），GPT 用解码器（单向因果注意力）；(2) 预训练 —— BERT 做填空（MLM: 预测被遮住的词），GPT 做续写（Next Token Prediction）；(3) 擅长 —— BERT 擅长理解（分类、检索、NER），GPT 擅长生成（对话、写作）。GPT 路线胜出的原因：生成是更通用的能力，理解任务可以转化为生成任务。
Transformer 的位置编码（Positional Encoding）为什么是必要的？
因为 Self-Attention 本身是置换不变的（Permutation Invariant）—— 它不关心词的顺序。「我吃苹果」和「苹果吃我」在 Self-Attention 看来完全等价（只是注意力权重的排列不同）。位置编码为每个位置注入唯一的向量信号，让模型能区分不同位置的词。没有位置编码，Transformer 就退化为高级词袋模型。
为什么 GPT 路线最终胜过了 BERT 路线？
核心原因：生成是更通用的能力。分类、检索、翻译等「理解任务」都可以转化为生成任务（生成标签、生成答案、生成译文），但反过来很难。此外，GPT 展示了 Scaling Law —— 模型越大、数据越多、性能越好的幂律关系，这使得工业界愿意投入更多资源。而 BERT 的填空预训练在规模增大后收益递减。In-context Learning（不微调也能做任务）也是 GPT 独有的涌现能力。
