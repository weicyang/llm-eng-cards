T07 · Multi-Head Attention：从单头扩展到多头

五步流程 / 拆头 reshape+transpose / 并行 Attention / concat 合并 / W_O 输出投影 / shape 逐步追踪

多头注意力不是「加参数堆算力」，而是把一个宽向量切成多个子空间，让每个头在各自的子空间里独立理解句子，再把结论拼起来——参数量几乎不变，视角却从 1 个变成 h 个。

一、单头的瓶颈：为什么要多头

回顾单头 Attention 的流程：X → (W_Q, W_K, W_V) → Q, K, V → Attention → 输出。它能跑，但有一个结构性缺陷：一次 softmax 只能产生一种注意力分布。而语言中同时存在多种关系——「他」要解决指代关系（指向「小李」），「看懂」要寻找受事关系（宾语「Transformer」），「昨天」要建立时间修饰关系。单头的权重矩阵只有一套，所有关系被迫挤在同一次打分里互相妥协，就像让一个人同时用红蓝绿三支笔画画却只给一支笔。

Multi-Head Attention（多头注意力）的解法非常直接：把 d_model 维度切成 h 份，每份独立做 Attention，相当于给模型配 h 支不同颜色的笔。相比单头，多头只多出四个动作：

环节单头 AttentionMulti-Head Attention
线性映射X → Q, K, V相同：X → Q, K, V
拆头无reshape + transpose 切成 h 份
注意力计算1 次 Attentionh 个头并行，各跑 1 次
合并无concat 拼接 h 个头的输出
输出投影无乘 W_O 混合头间信息
单头 vs 多头数据流对比 单头: X ──→ Q,K,V ──────────────→ Attention ──→ out 多头: X ──→ Q,K,V ──→ 拆成 h 份 ──┬→ Head 0 Attention ─┐ ├→ Head 1 Attention ─┼→ concat ──→ @ W_O ──→ out └→ Head h-1 Attention ┘ 同样的输入宽度，h 个并行的「理解视角」

多头 = 同一次考试出 h 套评分标准：语法头看结构、语义头看含义、位置头看距离，各打各的分，最后加权综合——单一评分标准永远比不过评委团。

二、步骤①②：线性映射与拆头

① 线性映射：和单头完全一样

输入 X 仍然乘三个权重矩阵得到 Q、K、V，形状也仍然是 (L, d_model)。以 d_model=8、h=2 的迷你配置演示（真实模型 d_model 常用 512/768/1024+，h 常用 8/12/16，原理完全一致）：

L, d_model, h = 7, 8, 2        # 序列长 7，隐层维 8，2 个头
d_k = d_model // h             # 每头分到 8 // 2 = 4 维
X = np.random.randn(L, d_model)             # (7, 8)
W_Q = np.random.randn(d_model, d_model)     # (8, 8)
W_K = np.random.randn(d_model, d_model)
W_V = np.random.randn(d_model, d_model)
Q, K, V = X @ W_Q, X @ W_K, X @ W_V         # 均为 (7, 8)

② 拆头：reshape + transpose 两连招

这是多头与单头最关键的差异。要把 (7, 8) 的 Q 切成 2 个头：先 reshape 成 (7, 2, 4)，语义变成「7 个 token × 2 个视角 × 每视角 4 维」；再 transpose 把头的维度提到最前面，变成 (2, 7, 4)，语义变成「2 个头 × 各自看 7 个 token × 4 维」，这样每个头就能独立并行了：

def split_heads(M):            # (L, d_model) → (h, L, d_k)
    return M.reshape(L, h, d_k).transpose(1, 0, 2)

Q_h, K_h, V_h = split_heads(Q), split_heads(K), split_heads(V)
print(Q_h.shape)               # (2, 7, 4)

注意这两个操作都只是视图变换（view），改变的是数据的组织方式，不发生任何实际计算，成本几乎为零。reshape 决定「哪些维度归同一个头」——它是按列顺序连续切块的，即 Q 的第 0~3 列归 Head 0、第 4~7 列归 Head 1。由于 W_Q 是学出来的，切哪几列并不重要，模型会自己让每列各就各位。

阶段形状三个维度的含义
映射后(7, 8)7 个 token × 8 维整体表示
reshape 后(7, 2, 4)7 个 token × 2 个视角 × 4 维子空间
transpose 后(2, 7, 4)2 个头 × 7 个 token × 4 维，头在最前便于并行
拆头细节：(7, 8) → (7, 2, 4) → (2, 7, 4) token: 远 方 有 颗 苹 果 树 每个 token 的 8 维 │ │ │ │ │ │ │ 按列切成两段 ▼ ▼ ▼ ▼ ▼ ▼ ▼ Head0 ← [x x x x | x x x x] → Head1 前 4 维 → 头 0 │ 后 4 维 → 头 1 ▼ Head0: (7,4) 一整句 Head1: (7,4) 同一整句 （同一句话，两个不同的 4 维子空间视角）

拆头不产生新计算，它只是「换座位」：把一张 8 列宽的大桌子改成 2 张 4 列的小桌子，客人（数据）还是那些人，只是分开坐了，方便各自讨论。

三、步骤③：各头并行 Attention

拆好之后，每个头内部的计算和上一篇讲的单头 Attention 一模一样：QKᵀ 打分 → 除以 √d_k 缩放 → softmax → 加权 V。唯一的区别是此时的 d_k 变小了——从 d_model=8 变成了每头 4 维，缩放因子也相应变成 √4=2：

def single_head_attention(Q, K, V):
    scores = Q @ K.T / np.sqrt(Q.shape[-1])      # (L, L)，缩放用头内维度
    e = np.exp(scores - scores.max(axis=-1, keepdims=True))
    return (e / e.sum(axis=-1, keepdims=True)) @ V

outs = [single_head_attention(Q_h[i], K_h[i], V_h[i])
        for i in range(h)]                       # 每头输出 (7, 4)

2 个头各自输出一个 (7, 4) 矩阵。关键点在于：两个头看到的是同一句话，但由于各自只拿到 Q/K/V 的不同列段，它们在不同的 4 维子空间里理解这句话，算出的注意力分布通常截然不同。一个头可能学会紧盯相邻词捕捉局部语法，另一个头可能学会跨距离追踪指代。这种头间分工不是人为指定的，而是训练中由梯度自然涌现的——不同的随机初始化让各头走上不同的优化路径。

关注点单头（d_k=8）多头每头（d_k=4）
打分维度8 维一次打完各头在自己 4 维子空间打分
缩放因子√8 ≈ 2.83√4 = 2（用头内维度，不是 d_model）
注意力分布只有 1 套h 套，各头独立
表达的关系多种关系互相妥协每头专注一类关系
生产案例 1 · 论文消融实验的量化证据：《Attention is All You Need》在原论文的消融实验中对比了不同头数的效果（WMT 英德翻译，BLEU）：基线 h=8 得 25.8；砍成单头 h=1 直接掉到 24.9（-0.9），是所有消融项中跌幅最大的一档；而把 h 加到 16 也仅得 25.1，反而略降。这组数字说明两件事：单头确实损失显著，但头数也不是越多越好，h 大到每头维度太小时，单头表达能力不足会反过来拖累整体。

每头维度 d_k = d_model / h 是多头设计的灵魂：头越多，单头越「近视」。多头不是免费午餐，它是「视角数量」与「每头深度」之间的资源分配问题。

四、步骤④⑤：Concat 与 W_O 投影

④ Concat：把头拼回原宽度

h 个头各自输出 (L, d_k)，合并思路是沿最后一维横向拼接：先 stack 成 (h, L, d_k)，transpose 回 (L, h, d_k)，再 reshape 成 (L, d_model)。拼接后宽度恢复到 8 维，与输入 X 完全一致：

# (h,L,d_k) → (L,h,d_k) → (L,d_model)
concat = np.stack(outs, axis=0).transpose(1, 0, 2)
concat = concat.reshape(L, d_model)
print(concat.shape)            # (7, 8)，前 4 列来自头 0，后 4 列来自头 1

⑤ W_O 输出投影：让多头真正「融合」

拼接之后还差临门一脚。此时的 8 维向量前 4 维来自 Head 0、后 4 维来自 Head 1，两段是各算各的，彼此从未交流过——如果直接输出，多头就只是物理上并排而坐、化学上毫无反应。乘上输出投影矩阵 W_O，不同头的特征才能线性组合、互相混合，形成统一表示交给后续 FFN 子层：

W_O = np.random.randn(d_model, d_model)   # (8, 8)
final = concat @ W_O                      # (7, 8)
print(final.shape == X.shape)             # True，与输入同形
concat + W_O 的数据流 Head0 输出 (7,4) ─┐ ├─ concat → (7,8) ──→ @ W_O ──→ (7,8) 最终输出 Head1 输出 (7,4) ─┘ 前4列=头0 W_O 的每一行都是 后4列=头1 对 8 列的加权组合 → 头间信息在此混合
方案头间信息参数量效果
只 concat，不用 W_O零交流，各头特征硬拼接省 d_model² 参数下游层要自己学混合，表达受限
concat + W_O线性混合，头间可互补/抑制+d_model²（占比不大）标准做法，论文默认配置
对头输出取平均代替 concat粗暴平均更省丢失各头差异化信息，不推荐

W_O 是多头的「圆桌会议」：concat 只是把各头的报告收上来订成一本册子，W_O 才是会议本身——它在所有头的结论之间做加权综合，产出一份统一决议。

五、shape 全景与完整实现

五步流程的 shape 变化一张表收拢。全程输入输出都是 (L, d_model)，中间经历一次「分家再合并」，整体维度始终守恒——这正是 Transformer Block 能无限堆叠的前提：

步骤操作输入形状输出形状
① 线性映射X @ W_Q / W_K / W_V(L, d_model)(L, d_model)
② Head 拆分reshape + transpose(L, d_model)(h, L, d_k)
③ 并行 Attention每头独立 QKᵀ/√d_k/softmax/@V(h, L, d_k)(h, L, d_k)
④ Concat 拼接transpose + reshape(h, L, d_k)(L, d_model)
⑤ 输出投影@ W_O(L, d_model)(L, d_model)

把五步打包成一个函数，核心逻辑不到 30 行。实际运行时五步的 shape 打印依次为 (7,8) → (2,7,4) → (7,4)×2 → (7,8) → (7,8)：

def multi_head_attention(X, W_Q, W_K, W_V, W_O, h):
    L, d_model = X.shape
    d_k = d_model // h
    Q, K, V = X @ W_Q, X @ W_K, X @ W_V              # ① (L, d_model)
    split = lambda M: M.reshape(L, h, d_k).transpose(1, 0, 2)
    Q_h, K_h, V_h = split(Q), split(K), split(V)     # ② (h, L, d_k)
    outs = [single_head_attention(Q_h[i], K_h[i], V_h[i])
            for i in range(h)]                       # ③ h × (L, d_k)
    concat = np.stack(outs, 0).transpose(1, 0, 2).reshape(L, d_model)  # ④
    return concat @ W_O                              # ⑤ (L, d_model)
shape 流转全景（L=7, d_model=8, h=2, d_k=4） X (7,8) ├→ Q,K,V (7,8) ──reshape/transpose──→ (2,7,4) │ │ │ 每头: scores (7,7) → weights (7,7) → out (7,4) │ │ └──────────────── concat (7,8) ←─────────┘ │ @ W_O ▼ output (7,8) ← 与 X 同形，可接残差+LayerNorm

工程实现上，「for 循环逐头计算」只适合学习原理。生产框架会把 h 个头的打分合并成一次批量矩阵乘法（把 batch 和 head 维度都放进 matmul 的前导维度），效率差异巨大：

实现方式写法核心并行度适用场景
Python for 循环逐头调 single_head_attentionh 次串行小矩阵乘学习原理、调试
批量 matmul把 (h, L, d_k) 直接送入广播矩阵乘一次 kernel 算完所有头生产训练/推理标配
einsum 一行式einsum('bhlk,bhsk->bhls', Q, K)同批量 matmul，可读性好研究代码常见
生产案例 2 · 逐头循环 vs 批量 matmul 的推理延迟（典型场景）：某搜索排序模型把注意力模块从逐头 for 循环改为批量 matmul 后（d_model=256、h=8、序列长 64、batch=512），GPU 利用率从 21% 提升到 74%，单步推理延迟从 14.2ms 降到 4.9ms，线上 QPS 从 4200 提升到 9800。计算总量一分没变，变的只是把 8 次小 kernel 合并成 1 次大 kernel——GPU 不怕算得多，就怕 kernel 启动次数多。

shape 守恒是多头的隐形契约：无论中间怎么分家，进出都是 (L, d_model)。看懂这张 shape 表，任何 MHA 变体（MQA、GQA、滑动窗口）都只是在这条流水线上的局部改造。

六、多头 vs 单头：效果与代价

多头最反直觉的一点是：参数量和计算量与单头几乎相同。单头若用 d_k=d_model=512，Q/K/V/O 四个投影共 4×512² 个参数；8 头版本每头 d_k=64，但投影矩阵总宽度仍是 512，参数量同样约 4×512²。注意力打分部分，单头算一个 (L, 512) 的大点积，多头算 8 个 (L, 64) 的小点积，总 FLOPs 一样。多头买到的表达力，几乎是「免费」的：

维度单头（d_k=d_model）多头（h=8, d_k=d_model/8）
投影参数量4 × d_model²4 × d_model²（完全相同）
打分 FLOPsL² × d_modelh × L² × (d_model/h) = L² × d_model
注意力分布数1 套h 套并行
单头表达深度全维度，深d_model/h，浅
可解释性一张热力图h 张热力图，可分工分析

真实模型的配置验证了「d_k 通常落在 64~128」这一工程共识：

模型d_model头数 h每头维度 d_k说明
Transformer base（原论文）512864多头注意力的开山配置
Transformer big（原论文）10241664加宽加深，d_k 保持 64
GPT-27681264d_k 仍为 64
GPT-3 175B1228896128超大模型把 d_k 提到 128
Llama-2 7B409632128d_k=128 已成主流
生产案例 3 · 搜索意图识别的头数选型（典型场景）：某电商搜索团队在查询意图分类任务上做头数消融（BERT-style 编码器，d_model=256，序列长 32）：h=1 准确率 91.2%，h=4 提升到 93.1%，h=8 达到 93.8%，h=16 时 d_k 只剩 16，准确率回落到 93.3%。推理侧 h=1→8 的延迟增幅约 7.7%（QPS 4200→3900），完全可接受；最终选 h=8 上线，搜索点击率提升 0.6 个百分点。结论：在 d_k≥64 的前提下加头，收益显著且成本可控。
生产案例 4 · 头数设计延伸到推理成本：KV Cache 优化（典型场景）：头数还直接影响推理显存。某 13B 对话模型（d_model=5120、40 层、40 头）推理时每个请求的 KV Cache 为 2×d_model×2 字节×40 层×2048 token ≈ 1.6GB，单张 80GB 卡并发上不去。团队改用分组查询注意力（GQA，把 40 个 Q 头共享 8 组 K/V 头）后，KV Cache 降到约 320MB，缩小 5 倍，单卡并发请求数从 24 提升到 100+，首 token 延迟基本不变。「头怎么分」从此不只是效果问题，更是成本问题。
  • 保证 d_model 能被 h 整除，让每头维度 d_k 相等
  • 把逐头循环改写成批量 matmul / einsum，吃满 GPU
  • 缩放因子用头内维度 √d_k，而不是 √d_model
  • 调试时逐头可视化注意力热力图，确认各头学到了不同模式
  • 不要盲目堆头数：d_k 小于 32~64 后单头表达力崩，收益转负
  • 不要省掉 W_O，头间信息不混合等于白拆
  • 不要在 reshape 前做逐 token 的非线性操作，会打乱拆头的列对应关系
  • 不要把「某个头负责某种关系」当成绝对结论，头的分工是统计倾向而非硬编码

多头的精髓一句话：用同样的参数量，把「一次大而全的理解」换成「多次小而专的理解再加综合」——宽度换视角，综合保深度。

Q&A

多头注意力比单头多了这么多步骤，参数量是不是也变多了？
基本没有变多。单头版本若保持 d_k=d_model，Q/K/V/O 四个投影的参数总量是 4×d_model²；多头版本把它切成 h 个 d_k=d_model/h 的小投影，拼起来的总宽度仍是 d_model，参数总量同样是 4×d_model²。计算量也一样：单头算一次 L²×d_model 的点积，多头算 h 次 L²×(d_model/h)，总和不变。多头真正的开销只在 reshape/transpose 的访存和更多的小矩阵调度上，而这些在批量实现下可以忽略。所以多头是典型的「免费表达力升级」。
为什么不同头能学到不同的注意力模式？是人为设计的吗？
不是人为指定的，而是训练中自然涌现的。各头的 W_Q/W_K 从不同随机初始化出发，在梯度下降中走上不同的优化路径；由于 concat 之后各头输出要共同服务于最终损失，模型会自动让各头「分工」以覆盖更多有用的关系，否则两个完全重复的头就是对参数预算的浪费。实证研究中确实观察到有的头追踪相邻词、有的头跨距离抓指代、有的头偏向标点和结构词。但要注意这种分工是统计倾向，不等于可以精确指认「第 3 号头就是语法头」。
concat 已经把各头拼起来了，为什么还需要 W_O？
因为 concat 只是物理拼接，不发生任何信息交换：拼接后向量的前 d_k 维完全来自头 0、后 d_k 维完全来自头 1，各头结论互不知情。W_O 是一个 (d_model, d_model) 的矩阵，它的每一行都是对全部 d_model 维的加权组合，等价于让所有头的特征做一次线性混合——某个头发现的语法信号可以放大或抑制另一个头提取的语义信号。没有 W_O，整合各头结论的负担就全部推给后面的 FFN，而且失去了在注意力出口处做精细融合的机会。消融实验中去掉 W_O 通常会造成可观的效果下降。
d_model 不能被 h 整除怎么办？
标准做法是让 d_model 被 h 整除，几乎所有主流模型在设计宽度时就把这一点考虑进去了（512/8、768/12、1024/16、4096/32 都是整除关系）。如果确实不整除，工程上有两种处理：一是给最后一个头分配余数维度，让各头 d_k 不等长，实现上比较麻烦且不利于批量 matmul；二是干脆调整 d_model 或 h 让它们整除，这是实践中更常见的选择。逐头维度不等还会让缩放因子逐头不同，进一步增加实现复杂度，所以「先保证整除」是默认约束。
头数是越多越好吗？应该怎么选？
不是。原论文消融显示 h=1 掉点明显（25.8→24.9 BLEU），但 h=16 也不如 h=8，说明存在最优点。内在机制是权衡「视角数量」与「每头深度」：h 越大，每头分到的 d_k=d_model/h 越小，单个头的打分空间太窄会丧失表达力，同时头太多还会出现冗余和相互干扰。工程经验是让 d_k 保持在 64~128 区间，再据此确定 h=d_model/d_k；小模型（d_model≤256）通常 4~8 头即可，盲目加头只会增加延迟。选型时应以消融实验为准，而非套公式。
拆头时为什么必须 transpose？直接按 (L, h, d_k) 循环不行吗？
功能上可以，工程上不行。把头的维度提到最前（或配合 batch 维度放在前面）之后，h 个头的打分可以合并成一次批量矩阵乘法：GPU 对一个大 matmul 的利用率远高于对 h 个串行小 matmul，因为省掉了 h-1 次 kernel 启动开销，访存也更连续。典型场景下，逐头循环的 GPU 利用率只有 20% 左右，改批量 matmul 后能到 70% 以上，延迟可降 2~3 倍。所以 transpose 本身几乎零成本（只是视图变换），却为后续的批量并行铺平了道路，是「形状服务于算力」的典型例子。
MHA、MQA、GQA 是什么关系？为什么新模型爱用 GQA？
三者是同一流水线的变体，区别只在 K/V 的头数。MHA 是本文实现：h 个 Q 头各有独立的 K/V 头；MQA（Multi-Query）走另一个极端，所有 Q 头共享 1 组 K/V；GQA 折中，把 h 个 Q 头分成 g 组，每组共享 1 组 K/V。Q 头数量不变意味着效果基本不降，而 K/V 头减少直接压缩了推理时的 KV Cache——例如 40 个 Q 头改用 8 组 KV，KV Cache 缩小 5 倍，单卡并发能提升数倍。所以 GQA 成为 Llama-2/3、Mistral 等主流开源模型的默认选择，本文的五步骨架只需在拆头后对 K/V 做广播即可扩展过去。
