T22 · Transformer 架构快速入门

Token 与向量 → QKV 三向量 → 注意力计算 → 多头注意力 → 编码器 → 解码器 → 翻译原理

Transformer 的本质是一台"全局查字典"的机器：每个词同时向全句提问（Q）、被全句检索（K）、再按相关度加权吸收信息（V）——一次并行计算看清整句话，彻底告别 RNN 的逐词串行。

一、Token 与向量：模型的"输入语言"

计算机只认识数字，文本要进入模型必须先数字化。最朴素的做法是按 Unicode 这类字符编码把每个字映射成一个编号，但编号只是身份标识，承载不了语义——"猫"的编号是 29483 还是 97 没有任何区别。于是模型采用 Embedding（向量嵌入）：把每个 Token（分词后的最小语义单元，可以是一个字、一个词或一个子词）映射到高维坐标系中的一个点，让"含义"变成可以计算的几何距离。

  • 语义相近的词在向量空间中靠得很近，比如"货拉拉"和"物流平台"；
  • 向量之间可以通过数学运算捕捉语义关系，经典的例子是：国王 - 男人 + 女人 ≈ 王后；
  • 向量的每一维没有直观含义，但整体组合起来能编码词性、情感、正式程度等细微差别。

Embedding 就是给每个词发一张"语义身份证"：身份证号（编号）只用来区分你是谁，身份证上的地址和照片（向量各维度）才描述你是一个什么样的人。

1.1 三代编码方式对比

编码方式形式能否表达语义问题
Unicode / 整数编号一个词 → 一个整数❌编号大小无语义，无法比较相似性
One-hot 独热一个词 → 超长 0/1 向量❌任意两词距离相同，词表多大向量就多长，维度爆炸
Embedding 稠密向量一个词 → 512/768/12288 维浮点向量✅需要大量语料训练才能得到好向量

1.2 位置信息：告诉模型词的顺序

注意力计算是"全局一眼看完"的，本身不区分先后顺序——"狗咬人"和"人咬狗"如果没有顺序信息，在模型眼里完全一样。所以 Transformer 在 Embedding 之上叠加 位置编码（Positional Encoding），用一组随位置变化的数值为每个 Token 标注"我坐在第几个座位"，让向量同时包含"是什么"和"在哪儿"两层信息。原论文用不同频率的正余弦函数生成位置编码，后来的模型改用可学习位置编码或 RoPE 旋转位置编码，以支持更长的上下文外推。

模型向量维度位置编码方案
原始 Transformer (2017)512正余弦固定编码
BERT-base768可学习位置编码（上限 512）
GPT-312288可学习位置编码（上限 2048）
LLaMA 系列4096+RoPE 旋转位置编码（支持长度外推）

二、QKV 与注意力计算：全局查字典

一个词往往多义：单独看"拉"字，可能是"拉货"也可能是"拉扯"，必须结合上下文才能确定含义。RNN 靠按顺序逐个读词来积累上下文，速度慢且长距离记忆差；Transformer 的解法是 注意力机制（Attention）——让每个 Token 一次性环顾全句，自己决定该重点看谁。

这套机制靠三个向量完成，它们由每个 Token 的原始向量分别乘以三个可训练的权重矩阵 Wq、Wk、Wv 变换而来，各司其职：

向量英文作用类比
QQuery这个 Token 想关注什么图书馆检索时输入的查询条件
KKey这个 Token 能提供什么信息每本书封面上的索引标签
VValue这个 Token 背后的真正含义书的正文内容

注意力计算就是一次图书馆借书：你带着问题（Q）去比对每本书的索引标签（K），算出每本书与问题的相关度，然后按相关度比例把各本书的正文（V）揉成一份属于你自己的读书笔记。

2.1 四步计算流程

Token 向量 x │ ├──×Wq──→ Q ┐ ├──×Wk──→ K ├──→ ① Q·Kᵀ 点积 （每个 Q 与所有 K 逐一算相关度） └──×Wv──→ V │ │ │ ▼ │ ② ÷ √d_k 缩放 （防止点积过大让 softmax 饱和） │ │ │ ▼ │ ③ softmax 归一化 （相关度 → 权重，总和为 1） │ │ └─────────→④ 权重 × V 加权求和 │ ▼ 融合了全句上下文的新向量
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
步骤操作目的
① Q·K 点积计算 Q 与所有 K 的点积点积越大方向越一致，衡量"有多相关"
② Scale 缩放除以 √d_k（向量维度的平方根）维度高时点积数值会很大，softmax 被推向极端值会导致梯度消失
③ Softmax转为概率分布（权重和为 1）得到可解释、可训练的注意力权重
④ 加权 V用权重加权所有 V 并求和按相关度融合上下文信息

2.2 为什么必须除以 √d_k

点积的数值大小与向量维度成正比：维度 d_k 越大，点积结果的绝对值越大。如果直接送进 Softmax（把任意实数向量压缩为概率分布的函数），巨大的输入会把概率推向接近 0/1 的极端分布——模型会"武断"地只盯住一个词，而且 softmax 在饱和区梯度几乎为零，训练根本学不动。除以 √d_k 相当于把数值拉回温和区间，这套组合因此被称为缩放点积注意力（Scaled Dot-Product Attention）。

生产案例 · 注意力机制的成名之战：2017 年 Google 发表《Attention is All You Need》。背景是当时机器翻译主流是 RNN/LSTM，训练必须逐词串行，一个模型动辄训几周；问题在于序列越长信息衰减越严重，且完全用不上 GPU 的并行能力。方案是彻底抛弃循环结构，只用注意力 + 前馈网络搭建 Transformer。效果：在 WMT 2014 英德翻译任务上 BLEU 达到 28.4，超过此前所有模型（含集成模型）2.0 分以上；英法任务 BLEU 41.0，而训练只用了 8 块 P100 GPU 跑 3.5 天——翻译质量与训练成本同时碾压，这正是它多年后仍是所有大模型底座的原因。

三、多头注意力：一句话值得多角度解读

词与词之间的关系是多样的：有的词在语法上依赖主语，有的词在语义上呼应前文实体，还有的词只是位置相邻。如果只做一次注意力，相当于只允许模型从一个角度理解句子，信息必然有损。Transformer 的做法是多头注意力（Multi-Head Attention）：把 Q、K、V 各自切成 h 份，让 h 组注意力并行计算，每组聚焦不同的关系侧面，最后把 h 份结果拼接起来，再乘一个输出矩阵融合。

输入向量 (d = 512 维) │ ┌──────────┼──────────┐ ▼ ▼ ▼ ┌───────┐ ┌───────┐ ┌───────┐ │ 头 1 │ │ 头 2 │ │ 头 h │ 每个头独立做 │ Q₁K₁V₁│ │ Q₂K₂V₂│ │ QₕKₕVₕ│ 一次注意力计算 │ 看语法│ │ 看语义│ │ 看位置│ （各占 512/h 维） └───┬───┘ └───┬───┘ └───┬───┘ └──────────┼──────────┘ ▼ Concat 拼接 (回到 512 维) │ × W_o ▼ 多头融合后的输出

研究发现，训练后的不同头确实会分化出分工：有的头专门追踪主语-动词一致，有的头负责指代消解（"它"指的是谁），有的头关注相邻位置。这种分工不是人工设计的，而是多头并行竞争下自然涌现的结果。

对比项单头注意力多头注意力
观察角度单一角度，一次加权平均h 个角度并行，各自捕捉不同关系
单头维度完整 d 维d/h 维（总计算量与单头基本持平）
表达能力容易顾此失彼语法、语义、位置关系可同时建模
典型配置—原始论文 8 头；GPT-3 96 头（每头 128 维）

多头注意力像一场案件讨论会：刑侦、法医、痕迹、心理各派一名专家（每个头）同时看同一份卷宗，各自给出侧重不同的判断，最后汇总成一份完整结论——而不是让一个人包办所有视角。

四、编码层与编码器：语义的千层饼

一次注意力只能完成一轮"信息交换"，要形成对句子的深刻理解，需要反复多轮。Transformer 把一套标准组件打包成一个编码层，再堆叠 N 层（原论文 N=6）构成编码器（Encoder），让语义像千层饼一样逐层加深。

输入: "我 爱 自然 语言 处理" → Embedding + 位置编码 │ ▼ ┌─ 编码层 ×N（原论文 N=6，GPT-3 N=96）─────────────┐ │ │ │ 多头自注意力 ← 全句信息交换 │ │ │ │ │ Add（残差连接: 输出 + 原始输入，信息保底） │ │ │ │ │ Norm（层归一化: 稳定数值范围） │ │ │ │ │ FFN 前馈网络（512 → 2048 → 512，引入非线性） │ │ │ │ │ Add + Norm（再来一次保底与稳定） │ │ │ └───────────────────┬───────────────────────────────┘ ▼ 输出: 每个 Token 都融合了全句语义的向量序列
组件作用没有它会怎样
多头注意力融合上下文语义信息每个词只能看到自己，无法理解语境
Add（残差连接）将子层输出与原始输入相加，保证信息保底层数一深，原始信号被逐层覆盖，训练崩溃
Norm（层归一化）统一调整数值范围，防止多层计算后失控数值指数级膨胀或消失，梯度无法传播
FFN 前馈网络两层全连接 + 激活函数，引入非线性变换多层线性运算等价于一层，表达能力受限
Add + Norm（再次）FFN 之后再次保底与稳定同上，深层训练难以收敛

残差连接（Add）是"原件备份"：每层加工时都留一份原始输入，加工失败至少还有原件兜底；层归一化（Norm）是"稳压器"：保证信号在几十上百层传递中既不过载也不熄火。这两件事让"堆层数"从冒险变成了常规操作。

4.1 FFN：被低估的"知识仓库"

前馈网络（FFN）对每个 Token 独立做两层全连接：先把维度从 512 扩张到 2048（4 倍），经过激活函数，再压回 512。注意力负责"词与词之间交换信息"，FFN 则负责"对每个词的信息做深度加工"——后续研究甚至发现，模型记住的大量事实知识就存储在 FFN 的权重里。GPT 系列把激活函数从 ReLU 换成更平滑的 GELU / SwiGLU，进一步提升了训练效果。

4.2 Post-LN 与 Pre-LN：归一化的位置之争

方案归一化位置特点使用者
Post-LN先 Add 再 Norm（原论文）最终表征质量好，但深层训练不稳，需精心设计学习率预热原始 Transformer、BERT
Pre-LN先 Norm 再进子层梯度传播更稳，可轻松堆到几十上百层GPT-2/3、LLaMA 等几乎所有现代大模型

五、解码器与翻译：成语接龙式生成

翻译任务需要"读一句中文，写一句英文"。负责"写"的就是解码器（Decoder）：它在编码层的基础上增加了两种注意力，一边参考中文原句，一边保证英文逐词生成时前后连贯。

编码器输出 (中文语义向量) │ 已生成的英文: "I love" │ │ │ ▼ │ ┌─ 掩码自注意力 ──┐ │ │ Q: 当前英文词 │ │ │ K/V: 已生成英文 │ ← 掩码遮住未来词 │ └────────┬────────┘ 防止"偷看答案" │ ▼ │ ┌─ 交叉注意力 ────┐ └────────────────→│ Q: 当前英文词 │ (提供 K 和 V) │ K/V: 中文语义 │ ← 回看原句找对应 └────────┬────────┘ ▼ FFN + Add + Norm ▼ softmax → 预测下一个词 "natural" │ └──→ 拼回输入, 循环直到生成 <结束>
注意力类型Q 来源K/V 来源作用
带掩码的自注意力当前英文词已生成的英文保证英文衔接连贯，且只能看到过去、看不到未来
交叉注意力当前英文词编码器输出（中文理解）生成每个词时回看原句，找到该翻译哪一部分

掩码（Mask）是解码器的关键设计：生成第 3 个词时，第 4 个词还不存在，如果允许它参与注意力计算，模型就会"作弊"抄答案。掩码把未来位置的注意力得分强制设为负无穷，softmax 之后权重归零。生成过程因此像成语接龙：每一步都在"已有译文 + 中文原句"的基础上预测下一个最合理的词，直到输出结束符。

解码器是一个"边查字典边写作文"的学生：掩码自注意力确保他只读自己已经写下的句子（不能偷看后文），交叉注意力让他每写一个词都抬头看一眼原文（不能跑题），两个动作交替进行直到写完全文。

5.1 自回归生成与 KV Cache

这种"用已生成的内容预测下一个词"的方式叫自回归生成（Autoregressive Generation）。它带来一个工程问题：生成第 n 个词时，前 n-1 个词的 K、V 其实上一轮已经算过，重复计算浪费巨大。现代推理引擎普遍引入 KV Cache——把每一层已算好的 K、V 缓存下来，每步只计算新词的部分。以一个 65B 参数、64 个注意力头的模型为例，2048 长度的 KV Cache 约占 5GB 显存，上下文翻 4 倍显存就翻 4 倍——用空间换时间，长文本生成可获得数倍加速，但显存账必须提前算好。

六、三大架构变体：从 BERT 到 ChatGPT

原始 Transformer 是"编码器 + 解码器"的完整结构，为翻译而生。但后续研究发现，把其中一半拆出来单独用，反而在各自领域更强：

架构组成注意力可见范围擅长代表模型
仅编码器Encoder ×N双向，一眼看全句理解：分类、情感分析、检索BERT、RoBERTa
仅解码器Decoder ×N（去掉交叉注意力）单向，只能看左侧生成：对话、写作、代码GPT 系列、ChatGPT、DeepSeek、LLaMA
编码器+解码器完整结构编码双向 + 解码单向序列到序列：翻译、摘要T5、BART、原始 Transformer
你的任务是什么？ │ ┌──────────────┼──────────────┐ ▼ ▼ ▼ 需要"理解" 需要"生成" 输入→输出转换 (分类/抽取/ (对话/续写/ (翻译/摘要/ 语义检索) 代码生成) 问答改写) │ │ │ ▼ ▼ ▼ 仅编码器 仅解码器 编码器+解码器 (BERT 路线) (GPT 路线) (T5 路线) │ ▼ 今天的大模型几乎都走这条路: 预训练一个超大规模解码器, 理解与生成任务一并吃下

三条路线的取舍其实只有一句话：编码器"读得全"（双向注意力，理解深），解码器"接得住"（自回归生成，天然会说话）；而 GPT 路线证明，只要规模足够大，一个只会"往后接话"的解码器连理解任务也能顺手做掉。

生产案例 · 解码器路线的工业化胜利：2020 年前后，业界主流还是 BERT 式"预训练 + 针对每个任务微调"，背景是每接一个新业务就要标注数据、重训模型，交付周期以周计；问题在于任务越多维护成本越高，小模型的能力天花板也明显。OpenAI 的解法是押注仅解码器架构：GPT-3 用 175B 参数、96 层、12288 维、96 个注意力头、约 300B token 的语料训练出一个通用底座，靠 In-context Learning 在提示词里给几个例子就能直接做翻译、问答、算术。效果：一个新任务从"标注 + 微调两周"变成"写一段提示词几分钟"，直接催生了 ChatGPT 和整个大模型应用生态——今天你用的几乎所有对话模型，都是这张架构图的产物。

6.1 复杂度视角：为什么 Transformer 能赢

架构单层计算复杂度最长路径（信息传递步数）并行性
RNNO(n·d²)O(n) — 信息要逐词传递❌ 必须串行
LSTM / GRUO(n·d²)O(n)❌ 必须串行
Transformer 自注意力O(n²·d)O(1) — 任意两词直连✅ 全句并行

n 是序列长度，d 是向量维度。当 n 小于 d 时（早期典型场景），自注意力不仅算得更快，而且任意两个词之间一步直达，长距离依赖不再衰减——这就是论文标题"Attention is All You Need"的底气。当然 n² 的代价在超长文本时会反噬，这也是后来各种稀疏注意力、线性注意力优化的由来。

  • 先建立"Q 提问、K 被检索、V 被吸收"的直觉，再去读公式和代码
  • 用注意力权重可视化工具（如 BertViz）观察模型到底在看哪里
  • 选型时先判断任务偏理解还是偏生成，再决定编码器/解码器路线
  • 关注序列长度：n² 复杂度意味着 4 倍长度 = 16 倍注意力开销
  • 不要死记公式而忽略"加权平均"这个核心直觉
  • 不要以为多头注意力是"多次重复计算"——它是并行的多视角分工
  • 不要忽略位置编码：去掉它，模型连"狗咬人"和"人咬狗"都分不清
  • 不要在长文本场景无视 KV Cache 的显存占用，它会先于计算打爆显存

Q&A

QKV 三个向量分别代表什么？注意力机制是如何使用它们的？
Q（Query）代表这个 Token 想关注什么，K（Key）代表它能提供什么信息，V（Value）代表它背后真正的含义，三者由原始向量分别乘 Wq、Wk、Wv 三个权重矩阵变换而来。计算分四步：先让每个 Q 与所有 K 做点积，得到两两之间的相关度；再除以 √d_k 缩放，防止数值过大让 softmax 饱和；接着用 softmax 把相关度归一化为总和为 1 的注意力权重；最后用权重对所有 V 加权求和，得到融合了全句上下文的新向量。整个过程让每个 Token 都能根据当前语境，自动决定重点吸收哪些其他 Token 的信息。
为什么点积之后要除以 √d_k？不除会怎样？
点积结果的量级会随向量维度 d_k 增大而增大，维度越高，点积的绝对值越大。如果直接把这些大数送进 softmax，输出会被推向接近 one-hot 的极端分布，模型等于"武断地只盯住一个词"，丢失了软加权的能力。更严重的是，softmax 在饱和区的梯度几乎为零，反向传播学不到东西，训练会停滞。除以 √d_k 把数值拉回温和区间，让梯度保持在有效范围，这就是"缩放点积注意力"中"缩放"二字的来历。它是一个零成本但不可或缺的稳定化操作。
多头注意力相比单头注意力强在哪里？
单头注意力对全句只做一次加权平均，相当于只允许模型从一个角度理解句子，语法关系、语义呼应、位置邻近这些不同性质的联系会被压缩进同一组权重，顾此失彼。多头注意力把 Q、K、V 各切成 h 份并行计算，每个头在 d/h 维子空间里各自捕捉一种关系，最后拼接融合。研究发现训练后的头会自然分工，比如有的头专管主谓一致，有的头负责指代消解。总计算量与单头大体相当（因为每个头的维度缩小了），表达能力却显著增强，这就是 GPT-3 用到 96 个头的原因。
Add（残差连接）和 Norm（层归一化）各自解决什么问题？
Add 是残差连接，把子层的输出与它的原始输入相加，作用是给信息留一条"保底通道"：即使某一层的变换学坏了，原始信号也能原样传下去，梯度同样可以沿这条路直达浅层，这让网络能稳定地堆到几十上百层。Norm 是层归一化，把每个样本的数值统一调整到稳定范围，防止多层计算后数值指数级膨胀或消失。两者的组合是深层 Transformer 能训得动的地基：没有残差，层数一深信号就被逐层覆盖；没有归一化，数值范围失控会让训练直接发散。现代大模型普遍采用 Pre-LN（先归一化再进子层）以获得更好的深层稳定性。
解码器为什么要用掩码？它是怎么防止"偷看未来"的？
解码器是自回归生成的：训练时为了并行，一整句目标文本会一次性喂进去，但生成第 3 个词时，模型不应该看到第 4 个及以后的词，否则它学到的不是"预测"而是"抄写"。掩码的实现很直接：在注意力得分矩阵上，把所有"未来位置"的得分强制设为负无穷，经过 softmax 后这些位置的权重变成零，当前词就只能注意到自己和之前的词。推理时本来就是逐词生成，掩码保证了训练和推理的行为一致。可以说没有掩码，解码器就退化成了一个会作弊的复读机。
编码器、解码器、编码器+解码器三种变体该如何选型？
选型看任务的信息流向。纯理解任务（文本分类、情感分析、实体抽取、语义检索）选仅编码器架构如 BERT，双向注意力让它能一眼看全句，理解最深。纯生成任务（对话、续写、代码）选仅解码器架构如 GPT，自回归机制天然适合"往后接话"。输入到输出的转换任务（翻译、摘要）传统上选编码器+解码器如 T5，编码器负责吃透输入，解码器负责生成输出。不过近年的趋势是解码器一家独大：只要预训练规模足够大，GPT 类模型靠提示词就能同时覆盖理解和生成，所以今天的主流大模型几乎清一色是仅解码器架构。
Transformer 为什么能取代 RNN 成为主流？
核心原因有两个：并行性和长距离依赖。RNN 必须按时间步逐词串行计算，序列有多长就要走多少步，GPU 的并行能力完全用不上，训练一个模型动辄数周；而且信息要像传话一样一站站传递，距离一远就衰减殆尽。Transformer 的自注意力让任意两个词一步直达（最长路径 O(1)），全句所有位置同时并行计算，训练速度提升了一个量级。原论文在 WMT 2014 翻译任务上用 8 块 GPU 训 3.5 天就刷新了纪录，就是这种架构优势的证明。代价是 O(n²) 的注意力复杂度，在序列长度超过维度后开销陡增，这也是后续长上下文优化的主战场。
