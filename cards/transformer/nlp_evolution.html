T02 · NLP 文本表示演进：从 One-Hot 到 Transformer

NLP Evolution — 三个阶段的技术跃迁：向量化 → 词嵌入 → 动态语境化

演进本质：从文字数字化（计算机"看见"）→ 语义理解（计算机"理解"）→ 认知升级（从静态映射到情境感知）。

一、阶段一：基础向量化

维度说明
代表技术One-Hot 编码、TF-IDF
核心原理高维稀疏矩阵（万维向量）为词汇分配唯一标识
向量密度高维稀疏（万维）
语义处理无关联（所有词向量正交）

局限性

  • 维度灾难：词表扩大导致计算资源激增
  • 语义缺失：所有词向量正交，无法表达语义关联（"猫"与"狗"的相似度为 0）

生产案例：早期搜索引擎的语义瓶颈

背景：2000 年代初期的搜索引擎使用 TF-IDF 构建文档向量，每个文档是 50K-100K 维的稀疏向量。

问题：搜索"汽车"时无法匹配"轿车"，搜索"开心"时无法匹配"高兴"。语义召回率仅 40-60%，大量相关内容被漏掉。

根因：One-Hot/TF-IDF 将所有词视为独立符号，无法捕捉同义词、近义词关系。"汽车"和"轿车"的向量余弦相似度 = 0。

修复：引入同义词词典 + 查询扩展（用户搜"汽车"时自动加上"轿车""车辆"）。但这依赖人工维护，覆盖率有限。

二、阶段二：静态词嵌入革命

维度说明
代表技术Word2Vec、GloVe
核心创新低维稠密向量（128-1024 维），基于分布假说
语义能力支持语义运算（"国王-男+女≈女王"）
计算方式预训练模型

突破

  • 低维稠密向量：从万维降到 128-1024 维
  • 分布假说：上下文相似的词向量相近
  • 支持语义运算

现存问题

  • 一词多义困境："苹果"在不同语境含义固定——因为每个词只有一个预训练好的向量，无法区分"苹果"是水果还是公司
  • 无法处理未登录词（OOV = Out-Of-Vocabulary，训练时没见过的词，模型完全不知道怎么表示）

三、阶段三：动态语境化时代

维度说明
代表技术Transformer（BERT / GPT）
核心创新注意力机制动态生成词向量
上下文感知同一词在不同语句中生成不同向量
OOV 解决子词切分技术（Subword）
计算方式实时动态生成
关键突破：Transformer 的注意力机制让词向量上下文感知——"苹果"在"乔布斯发布苹果新品"和"这个苹果很好吃"中生成完全不同的向量。同时子词切分（Subword）解决了 OOV 问题。

生产案例：电商搜索的语义升级

背景：某头部电商平台（2019）商品搜索系统原先基于 BM25（TF-IDF 的改进版）做文本匹配，用户搜索"透气跑鞋"时无法召回标题为"轻便运动鞋 网面通风"的商品，搜索无结果率高达 18%。

方案：上线 BERT-base 做查询-商品的语义匹配（双塔模型），将查询和商品标题分别编码为 768 维向量，用余弦相似度做召回排序。

效果：搜索无结果率从 18% 降至 6.2%（-65%），点击率（CTR）提升 12.3%，GMV（成交总额）提升约 4.8%。核心收益来自同义词泛化（"透气" ≈ "通风" ≈ "网面"）和意图理解（"跑鞋" ≈ "运动鞋"在运动场景下）。

为什么 BERT 能碾压传统检索？BM25 只能做精确词匹配，"透气跑鞋" 和 "轻便运动鞋 网面通风" 的 BM25 得分为 0（没有任何共同词）。BERT 通过上下文感知的向量表示，让语义相近的查询和文档在向量空间中靠近，实现了从"词匹配"到"语义匹配"的本质跃迁。

六、深度学习桥梁：RNN → LSTM → Transformer → GPT

在词嵌入和动态语境化之间，存在一条被低估的技术演进线——序列建模架构的迭代。这条线决定了模型如何"阅读"句子，是理解 NLP 完整进化图的关键拼图。

6.1 RNN（1990）：序列建模的起点

RNN（循环神经网络）首次引入"隐藏状态"概念，让模型在处理序列时保留历史信息。但梯度消失问题严重限制了长距离依赖的学习能力——超过 10-15 个时间步后，梯度趋近于零，模型"遗忘"了早期输入。

6.2 LSTM（1997）：记忆门的突破

LSTM（长短期记忆网络）通过三个门控机制（遗忘门、输入门、输出门）解决了梯度消失问题，将有效上下文窗口扩展到 100+ 步。但仍然是严格顺序处理——必须从左到右逐词计算，无法并行。

6.3 Transformer（2017）：注意力的革命

Transformer 完全抛弃循环结构，用自注意力机制（Self-Attention）实现所有位置间的直接信息交互。关键优势：① 全并行——序列中每个位置同时关注所有其他位置；② 长距离无衰减——任意两个位置之间的信息传递只需一步。

6.4 GPT / BERT（2018）：预训练范式

基于 Transformer，GPT（自回归生成）和 BERT（双向理解）分别开辟了生成和理解两条路线，确立了"预训练 + 微调"的标准范式。

┌──────────────────────────────────────────────────────────────────────┐ │ 序列建模架构演进：从 RNN 到现代 LLM │ ├──────────────────────────────────────────────────────────────────────┤ │ │ │ 1990 RNN ──── 隐藏状态 + 梯度消失（有效窗口 ≤15 步） │ │ │ │ │ 1997 LSTM ─── 门控机制解决消失（窗口 → 100+ 步） │ │ │ 但仍为严格顺序处理，无法并行 │ │ │ │ │ 2014 GRU ──── 简化版 LSTM（2 个门，参数减少 25%） │ │ │ │ │ 2017 Transformer ── 自注意力机制，全并行，长距离无衰减 │ │ │ "Attention Is All You Need" │ │ │ │ │ 2018 ┌─┴─┐ │ │ BERT GPT │ │ (双向) (自回归) │ │ │ │ │ │ │ GPT-2/3/4 ──→ 现代 LLM（Claude, Gemini, Llama） │ │ │ │ │ RoBERTa, DeBERTa, ELECTRA（理解方向优化） │ │ │ │ 核心趋势：顺序 → 并行 │ 局部 → 全局 │ 固定表示 → 动态上下文 │ └──────────────────────────────────────────────────────────────────────┘

6.5 Transformer vs LSTM 深度对比

维度LSTMTransformer
计算方式严格顺序（逐 token 计算）全并行（自注意力一次完成）
训练速度慢（无法利用 GPU 并行）快（矩阵乘法高度并行化）
长距离依赖有衰减（100+ 步后信息损失）无衰减（任意位置一步直达）
上下文窗口理论无限但实际 ~200 步固定（512-8K tokens，可扩展至 128K+）

典型应用小型设备端模型、时序预测大语言模型、机器翻译、多模态
工程数据：Google 内部测试（2017）显示，在 WMT 英德翻译任务上，Transformer（Big）达到 28.4 BLEU，超越当时最好的 LSTM 集成模型（26.36 BLEU）超过 2 个点，同时训练时间从 数周（LSTM 在 8 卡 P100 上）缩短到 3.5 天（Transformer 在 8 卡 P100 上）。这一效率差距直接宣告了 LSTM 在大规模 NLP 任务上的淘汰。

规模定律的胜出：LSTM 并非"差"技术——在短序列（<50 tokens）、资源受限（移动端、嵌入式）场景下仍然实用。但 Transformer 的致命优势在于可扩展性（Scalability）：模型越大、数据越多、性能越好的规律（Scaling Law）在 Transformer 上体现得淋漓尽致，而在 LSTM 上很早就遇到了天花板。这就是为什么 2020 年之后几乎所有前沿大模型都选择了 Transformer 架构。

LSTM 像一个认真但慢速的读者——逐词阅读、记住重点；Transformer 像一个速读高手——同时扫视整段文字、瞬间建立全局理解。这就是为什么 Transformer 能扩展到数千亿参数，而 LSTM 在百亿参数级别就已力不从心。

七、Benchmark 性能跃迁：GLUE 与 SuperGLUE

GLUE（General Language Understanding Evaluation，2018）是 NLP 领域的标准多任务评测基准，涵盖 9 项语言理解任务（文本蕴含、语义相似度、问答等）。当模型迅速超越人类基线后，SuperGLUE（2019）作为更难版本推出，包含 8 项需要深层推理的任务。

关键数据：2018 年 BERT-Large 在 GLUE 上拿到 82.1 分，仅比人类基线（87.1）低 5 分，震惊 NLP 界。一年后 RoBERTa（88.5）首次超越人类非专家水平，GLUE 基准被"打爆"。2019 年推出的 SuperGLUE 更难——BERT 基线仅 69.9 分（人类 89.8），但到 2022 年，ST-MoE-32B（91.2）和 Vega v2（91.3）均超越人类基线。此后 SuperGLUE 排行榜实质上"退役"，前沿 LLM（GPT-4、Claude、Gemini）转向 MMLU、GPQA、BIG-Bench Hard 等新基准。

Benchmark 的"饱和—换代—再饱和"循环本身就是 NLP 进步的最好证据：每当模型追上人类水平，研究者就设计更难的测试。从 GLUE（2018）→ SuperGLUE（2019）→ MMLU/HELM（2023+），评测标准的进化速度甚至跟不上模型能力的增长。

生产案例

生产验证：早期搜索引擎（2010-2015 年）使用 One-Hot + TF-IDF 做文本检索，"苹果手机价格"无法匹配到"iPhone 售价"（语义鸿沟），搜索相关性仅 0.31（人工标注基准）。切换 Word2Vec 后提升至 0.52（+68%），因为"苹果"和"iPhone"的余弦相似度达 0.82。2018 年 BERT 上线后进一步飙升至 0.89（上下文感知：区分"苹果"是水果还是手机）。Word2Vec 的经典发现：king - man + woman ≈ queen（向量运算捕捉语义关系），但无法处理多义词（"bank"的向量是"银行"和"河岸"的平均，两者混淆）。

NLP 表示方法的进化主线：从静态符号（One-Hot）→ 分布式向量（Word2Vec）→ 上下文动态表示（Transformer），每一次跃迁都带来语义理解能力的质变。选型时根据任务需求匹配对应层级的表示方法。

选型黄金法则：先确定任务需要的语义能力层级（精确匹配 → 静态语义 → 动态语境），再根据延迟和成本约束选择合适的模型。大多数生产场景中，80% 的任务不需要最大的模型——DistilBERT 在 SST-2 情感分类上达到 90.7%，仅比 BERT-Large（92.7%）低 2 个点，但推理速度快 60%、参数量少 40%。

生产案例：某内容平台（2022）内容审核系统，原方案为 BERT-Large（340M 参数）做 12 类违规分类，单条推理延迟 45ms，日均处理 2000 万条文本。切换 DistilBERT（66M 参数）后，F1 从 94.2 微降至 92.8（-1.5%），但推理延迟降至 12ms（-73%），GPU 成本节省约 60%，年化节约超 200 万元。
  • 根据任务选型：分类/NER → BERT，生成 → GPT，通用 → T5
  • 预训练 + 微调范式：用大规模无标注数据预训练，小量标注数据微调
  • Embedding 用于语义搜索时，优先选对比学习训练的模型（如 BGE）
  • 不要用 One-Hot 做语义任务（完全无法捕捉词义关系）
  • 不要混淆 BERT（双向理解）和 GPT（单向生成）的适用场景
  • 不要忽视 Word2Vec 的多义词缺陷（"bank" = 银行 + 河岸的平均）

高频问答

One-Hot 和 Word2Vec 的核心区别是什么？

One-Hot 是高维稀疏向量（万维），所有词向量正交，无法表达语义关联（"猫"和"狗"相似度为 0）。Word2Vec 是低维稠密向量（128-1024 维），基于分布假说（上下文相似的词向量相近），支持语义运算如"国王-男+女≈女王"。本质是从"无关联"到"静态语义关联"的跃迁。

Word2Vec 为什么无法处理一词多义？

Word2Vec 为每个词生成固定的向量，不管上下文如何。"苹果"在"乔布斯发布苹果新品"和"这个苹果很好吃"中是同一个向量。Transformer 通过注意力机制动态生成词向量，同一词在不同语句中生成不同向量，解决了这个问题。

Transformer 相比 Word2Vec 有哪些突破？

① 上下文感知：注意力机制动态生成词向量，同一词在不同语境含义不同。② OOV 解决：子词切分技术（Subword）将词拆为子词单元，未登录词也能处理。③ 长距离依赖：注意力机制可以捕捉长距离语义关系，不受 RNN 梯度消失限制。

Subword 是怎么解决 OOV 问题的？

Subword 将词拆分为更小的子词单元。例如"unbelievable"拆为"un"+"believ"+"able"。即使遇到未登录词，只要其子词单元在词表中，就能组合出向量表示。BPE（Byte Pair Encoding）和 WordPiece 是常用的子词切分算法。

Word2Vec 的"国王-男+女=女王"是怎么做到的？

Word2Vec 通过分布假说（Distributional Hypothesis）学习到词的语义关系。在训练过程中，"国王"和"女王"出现在相似的上下文中（如"XX 统治国家""XX 加冕"），所以它们的向量相近。"国王-男+女"的向量运算结果会落在"女王"的向量附近。这个性质叫做向量空间的线性结构。类似的还有"巴黎-法国+意大利 ≈ 罗马"。

LSTM 解决了 RNN 的梯度消失，为什么还被 Transformer 取代？

LSTM 虽然通过门控机制缓解了梯度消失，将有效上下文窗口从 ~15 步扩展到 100+ 步，但存在两个根本限制：① 顺序处理瓶颈——必须从左到右逐词计算，无法并行化，训练速度受限于序列长度；② 长距离依赖衰减——虽然有记忆门，但信息仍需经过多个门控传递，100+ 步后仍有衰减。Transformer 的自注意力机制同时解决了两个问题：所有位置间一步直达，且支持全并行计算。这使得训练效率提升了一个数量级，也使得模型能够扩展到数千亿参数。

GLUE 和 SuperGLUE 基准是怎么体现 NLP 进步的？

GLUE（2018）首次为 NLU 提供了统一的多任务评测框架。BERT-Large 拿到 82.1 分，一年内 RoBERTa（88.5）超越人类基线（87.1），GLUE 被"打爆"。于是推出更难的 SuperGLUE（2019），BERT 基线仅 69.9 分，与人类 89.8 差距 20 分。到 2022 年 ST-MoE-32B（91.2）再次超越人类基线。这个"饱和→换代→再饱和"的循环推动了评测标准从 GLUE → SuperGLUE → MMLU/HELM 的持续演进，也是 NLP 飞速进步的最佳注脚。

BERT 和 GPT 都基于 Transformer，为什么一个擅长理解、一个擅长生成？

关键区别在于注意力掩码的设计：BERT 使用双向注意力（每个 token 能看到所有上下文），预训练任务是 Masked Language Model（随机遮盖词，让模型从上下文推断），天然适合理解类任务（分类、NER、问答）。GPT 使用因果注意力（每个 token 只能看到之前的内容），预训练任务是自回归（从左到右逐词预测下一个 token），天然适合生成类任务（文本创作、翻译、对话）。这体现了 Transformer 架构的灵活性——同一架构，不同掩码策略，催生截然不同的能力。
