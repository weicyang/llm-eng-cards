Efficient Attention — 从 O(n²) 到线性，解锁长上下文推理

一、标准注意力的瓶颈

注意力真正贵的地方不是乘法做不完，而是那张 n×n 的中间表来回搬运——GPU 的算力早就过剩了，缺的是内存带宽。

O(n²) 复杂度分析

标准 Scaled Dot-Product Attention 的计算公式：

Attention(Q, K, V) = softmax(QKT / √dk) · V

其中 Q、K、V 的形状为 [n, d]（n = 序列长度，d = 头维度），关键矩阵 QKT 的形状为 [n, n]。

指标复杂度说明
时间O(n² · d)QKT 矩阵乘法 + softmax + AV 乘法
内存O(n²)需要存储完整的 n×n 注意力权重矩阵

为什么 n² 是长上下文的核心挑战

  • GPT-4 支持 128K token → 注意力矩阵 128K × 128K = 160 亿个元素（FP16 约 30GB）
  • 序列长度翻倍 → 计算量和显存都增长 4 倍
  • 训练和推理都受限：长序列 batch size 必须缩小

Memory-Bound Problem

现代 GPU（如 A100）算力极强（312 TFLOPS FP16），但内存带宽有限（2 TB/s）。标准注意力的算术强度（Arithmetic Intensity）较低：

  • 计算量：O(n²d) FLOPs
  • 数据搬运量：需要反复读写 n×n 的中间矩阵（从 HBM ↔ SRAM）
  • 实际瓶颈不是「算不过来」，而是「搬不动数据」— 这就是 memory-bound
  • 回答"注意力瓶颈"时必须提到 O(n²) 时间 + O(n²) 内存，以及 memory-bound 的本质
  • 能用数字举例说明（如 128K context 下的显存需求）会加分
  • 理解 arithmetic intensity 是后续理解 FlashAttention 的前提

二、Multi-Query Attention (MQA)

核心思想

标准 Multi-Head Attention (MHA) 中，每个注意力头拥有独立的 Q、K、V 投影。MQA 的改动：

  • 所有 head 共享同一组 K 和 V（只有 Q 保持 per-head 独立）
  • KV 投影从 h 组 → 1 组（h = head 数量）
MHA: Qi, Ki, Vi (i=1..h)
MQA: Qi (i=1..h), Kshared, Vshared

推理速度提升

  • KV Cache 大小减少为原来的 1/h（例如 h=32 时减少 32 倍）
  • 自回归推理时的内存带宽需求大幅降低 → 推理速度提升显著
  • 训练阶段加速不明显（因为训练不是 memory-bound）

精度代价

  • 由于多个 head 共享 KV，模型表达能力下降
  • 对大模型影响较小，对小模型可能有明显精度损失
  • 通常需要更多训练步数来弥补

代表模型

PaLM Falcon-40B StarCoder

  • MQA 的核心一句话：所有 head 共享一组 KV，Q 保持独立
  • 主要收益在推理阶段（KV Cache 缩小 → 内存带宽需求降低）
  • 高频问题：MQA 和 MHA 的 KV Cache 大小对比

三、Grouped-Query Attention (GQA)

MHA 到 MQA 不是二选一，而是一根滑杆：把 KV 头数从 h 一路调到 1，精度和 KV Cache 体积成对下降，GQA 就是停在中间的那一档。

MHA 与 MQA 的折中

GQA 将 h 个 head 分为 g 组，每组共享一组 KV：

g = h → MHA（每个 head 独立 KV）
g = 1 → MQA（所有 head 共享 KV）
1 < g < h → GQA（分组共享）

分组数量选择

  • LLaMA-2 70B：h=64, g=8（每 8 个 head 共享一组 KV）
  • LLaMA-3：同样采用 GQA
  • 分组数 g 通常选择能整除 h 的值：2, 4, 8 等
  • g 越大越接近 MHA（精度高，速度慢）；g 越小越接近 MQA（精度低，速度快）

MHA vs MQA vs GQA 对比

MQA12 × n × 1 × d略有下降最快PaLM, Falcon

从 MHA 转换为 GQA

论文提出可以通过对已训练好的 MHA 模型的 KV head 做 mean-pooling 来初始化 GQA，再用少量数据微调即可恢复精度。

  • GQA 是 MHA 和 MQA 的连续谱，通过调节 g 控制精度-速度权衡
  • LLaMA-2 70B 选择 g=8 是因为在精度和推理效率间取得最佳平衡
  • 必背：MHA / GQA / MQA 的 KV Cache 公式及对比
  • 能提到 "uptraining" 从 MHA 转 GQA 的方法会加分

四、FlashAttention

核心思想

FlashAttention（Dao et al., 2022）不改变注意力的数学计算，而是通过IO-Aware的算法设计避免在 HBM 中存储 n×n 注意力矩阵：

  • Tiling（分块计算）：将 Q、K、V 分成小块，在 SRAM 中完成注意力计算
  • 避免物化 n×n 矩阵：不将完整的 attention score 矩阵写回 HBM
  • 精确计算：结果与标准注意力完全一致（不是近似方法）
FlashAttention Tiling 示意（分块计算，避免物化 n×n 矩阵）： HBM (慢, 大) SRAM (快, 小) ┌──────────────┐ ┌─────────────┐ │ Q [n × d] │── load Q_tile ──▶ │ Q_tile │ │ K [n × d] │── load K_tile ──▶ │ K_tile │ ─▶ S_tile = Q_tile · K_tile^T │ V [n × d] │── load V_tile ──▶ │ V_tile │ ─▶ P_tile = softmax(S_tile) │ │ │ │ ─▶ O_tile += P_tile · V_tile │ │◀── write O_tile ── │ O_tile │ └──────────────┘ └─────────────┘ 关键：n×n 的 P 矩阵从未写入 HBM！只在 SRAM 中逐块计算并累加到 O。

FlashAttention 一个浮点数都没少算，它只是不再把中间结果写回显存——省的全是搬运时间，所以结果和标准注意力逐位相同。

GPU 内存层次

存储容量带宽特点
SRAM (片上)~20 MB (A100)~19 TB/s快但小
HBM (显存)40/80 GB (A100)~2 TB/s大但慢

FlashAttention 的核心洞察：将计算尽量放在 SRAM 中，减少 HBM 读写次数。

Online Softmax 技巧

分块计算的难点：softmax 需要整行的全局最大值和求和。解决方案：

  • 维护 running max 和 running sum
  • 每处理一个新 tile，用 correction factor 修正之前的部分结果
  • 最终结果与一次性计算完全一致
mnew = max(mold, max(current_tile))
correction = exp(mold - mnew)
lnew = correction × lold + sum(exp(current_tile - mnew))

收益

指标标准注意力FlashAttention
HBM 内存O(n²)O(n)（不存 n×n 矩阵）
HBM 读写O(n² + nd)O(n²d / M)（M = SRAM 大小）
速度（端到端）1×2-4× 提升
数学精确性精确精确（完全一致）
生产数据：FlashAttention 在 A100 上相比 PyTorch 标准实现，序列长度 128~2048 时实测 3× 加速；FA-2 进一步达到 230 TFLOPS/s（理论峰值 312 TFLOPS 的 ~73%），端到端训练 GPT 模型时可达 225 TFLOPS/s（72% MFU）。FA-3 在 H100 上 BF16 达到 ~800 TFLOPS/s，FP8 达到 1.3 PFLOPS/s。（来源：Stanford CRFM Blog / GTC 2025）
  • FlashAttention 三个关键词：IO-Aware、Tiling、Online Softmax
  • 它是精确计算（不是近似），只是改变了计算顺序和内存访问模式
  • 核心贡献：将注意力从 memory-bound 优化为更接近 compute-bound
  • 要能解释为什么节省内存（不物化 n×n 矩阵）以及 online softmax 的原理

五、FlashAttention-2 / FlashAttention-3

FlashAttention-2 (2023) 优化

  • 更好的并行化：FA-1 在 batch 和 head 维度并行，FA-2 额外在序列长度维度并行
  • 减少非矩阵运算：将 softmax rescaling 等操作合并，减少 warp 间同步
  • 优化 work partitioning：在 thread block 内部更均匀地分配计算
  • 实测：相比 FA-1 速度提升约 2×，达到理论峰值 FLOPS 的 50-73%

FlashAttention-3 (2024) 优化

  • 针对 Hopper 架构（H100）的硬件特性优化
  • 利用 Tensor Core 异步执行：WGMMA（Warp Group Matrix Multiply-Accumulate）
  • Ping-pong scheduling：让不同 warp group 交替执行，隐藏延迟
  • FP8 支持：通过 incoherent processing 降低量化误差
  • 性能：在 H100 上达到 740 TFLOPS（FP16），接近理论极限的 75%

六、PagedAttention

KV Cache 的浪费不是算法问题而是内存管理问题——按最长可能长度预留连续显存，就像给每个进程预留最大内存一样荒唐，分页正是操作系统三十年前给出的答案。

vLLM 的核心创新

PagedAttention（Kwon et al., 2023）解决 LLM 推理服务中的 KV Cache 内存碎片化问题：传统方案按最大序列长度预分配连续显存，内部碎片 + 外部碎片导致利用率仅 20-40%。它把操作系统的虚拟内存分页机制搬到 GPU 显存——将 KV Cache 切成固定大小的 Block（如 16 token/block），用 Block Table（页表）映射逻辑位置 → 物理 Block，按需分配、无需物理连续；并借助 Copy-on-Write 让 beam search / 并行采样共享前缀 KV Block。

关键收益：KV Cache 利用率从 20-40% 提升至接近 100%（浪费 <4%），吞吐量提升 2-4×，可支撑的并发请求数大幅增加。

七、Sliding Window Attention

Mistral 的做法

Sliding Window Attention (SWA) 限制每个 token 只关注局部窗口内的 token：

Attention(i) = softmax(Qi · K[i-w, i]T / √d) · V[i-w, i]
其中 w = 窗口大小（如 Mistral-7B 中 w = 4096）

滑动窗口把"每个词都要看全文"换成"每个词只看邻居"，全局信息则交给层数去传递——本质是用深度换宽度。

复杂度优势

方法时间复杂度KV Cache 大小
标准注意力O(n² · d)O(n · d)
Sliding WindowO(n · w · d)O(w · d)（固定）

当 n >> w 时，计算和内存都显著降低，且 KV Cache 大小恒定（不随序列增长）。

通过多层实现"全局感知"

虽然单层只看 w 个 token，但信息通过多层传递可以覆盖更远距离：

  • 第 L 层的有效感受野 = L × w
  • Mistral-7B：32 层 × 4096 窗口 = 理论感受野 131,072 token
  • 高层的 token 间接"看到"了低层的全部信息

与全注意力的结合

实践中常与全注意力交替使用（如 Mixtral 部分层用全注意力），或在最后几层使用全注意力汇总全局信息。

  • SWA 的核心优势：KV Cache 大小恒定（不随序列长度增长）
  • 必答：如何实现全局感知？→ 多层堆叠，有效感受野 = 层数 × 窗口大小
  • Mistral-7B 的具体参数：w=4096, 32层
  • 局限性：对于需要跨越很远距离的推理任务，可能信息传递有损

八、Ring Attention

分布式长序列训练

Ring Attention（Liu et al., 2023）解决单设备显存无法容纳超长序列的问题：

核心思想

  • 将序列分割到多个设备上，每个设备持有一段 Q 和对应的 KV
  • 设备排列成逻辑环
  • 每个设备计算本地 Q 与当前 KV 块的注意力
  • 然后将 KV 块传递给环中的下一个设备（环形通信）
  • 重复直到所有设备都见过所有 KV 块

环形通信重叠计算

Step 1: Device i 计算 Attention(Qi, Ki, Vi)，同时发送 KVi → Device (i+1) % N
Step 2: Device i 计算 Attention(Qi, Ki-1, Vi-1)，同时发送 KVi-1 → 下一设备
... 重复 N-1 次 ...
  • 关键：通信与计算重叠（overlap），通信几乎被完全隐藏
  • 使用 Online Softmax（同 FlashAttention）逐块累积注意力结果

可扩展性

设备数 N每设备序列长度总序列长度
8128K1M
64128K8M
256128K32M

理论上可以支持无限长序列（受限于设备数量而非单设备内存）。

  • Ring Attention = 序列并行 + 环形通信 + 计算/通信重叠
  • 核心前提：通信时间 ≤ 计算时间（才能完全隐藏通信开销）
  • 与 FlashAttention 互补：单设备用 FlashAttention 优化，多设备用 Ring Attention 扩展
  • 加分项：能提到与 Sequence Parallelism、Tensor Parallelism 的区别
Ring Attention 完整数据流：Q 固定于本卡，KV chunk 沿环顺时针轮转；每轮用本地 Q 与当前 KV 块计算局部注意力，以 Online Softmax 增量累积 (m, l, O) 三元组状态；KV 经 NVLink/InfiniBand 传递，通信与计算重叠隐藏。

九、稀疏注意力

核心动机

实证发现：标准注意力矩阵中大量权重接近 0，真正重要的注意力连接是稀疏的。因此可以设计固定或可学习的稀疏 pattern，跳过不重要的位置对。

Sparse Transformer (2019)

  • OpenAI 提出的早期稀疏注意力方案
  • 使用固定稀疏 pattern：局部（stride）+ 全局（fixed）
  • 复杂度：O(n√n)

Longformer (2020)

  • 局部窗口：每个 token 关注邻近 w 个 token（类似 SWA）
  • 全局 token：少数特殊 token（如 [CLS]）关注所有位置
  • 结合局部 + 全局，在长文档任务中表现优异
  • 复杂度：O(n × w + n × g)，其中 g = 全局 token 数（通常很小）

BigBird (2020)

Google 提出，在 Longformer 基础上增加随机注意力：

  • 局部窗口 + 全局 token + 随机连接
  • 理论证明：这种组合可以模拟任意图灵机（universal approximation）
  • 随机连接帮助信息在远距离间快速传递

稀疏 Pattern 设计对比

方法Pattern复杂度特点
Sparse TransformerStride + FixedO(n√n)固定 pattern
LongformerLocal + GlobalO(n·w)针对文档任务
BigBirdLocal + Global + RandomO(n·w)理论可证明通用性
  • 稀疏注意力的共同思想：大多数 attention 权重不重要，可以跳过
  • Longformer 的两个关键设计：局部窗口 + 全局 token
  • BigBird 增加随机连接的意义：保证理论上的 universal approximation
  • 局限性：固定 pattern 可能错过动态重要的长距离依赖

十、线性注意力

核心思想

标准注意力中 softmax 导致 O(n²)，线性注意力通过去掉 softmax 来降低复杂度：

标准: Attention = softmax(QKT) · V → O(n²d)
线性: Attention = φ(Q) · (φ(K)T · V) → O(nd²)

关键：先计算 φ(K)T · V（形状 d×d），再左乘 φ(Q)。当 d << n 时，复杂度从 O(n²d) 降到 O(nd²) ≈ O(n)。

核函数近似

  • 用核函数 φ 替代 softmax：softmax(qkT) ≈ φ(q)T · φ(k)
  • 常见选择：ELU+1、Random Fourier Features、正交随机特征

Performers (2020)

  • Google 提出 FAVOR+ (Fast Attention Via positive Orthogonal Random features)
  • 使用正交随机特征近似 softmax kernel
  • 理论上可以无偏近似标准注意力
  • 实测：在某些任务上精度接近标准注意力，但在语言建模上仍有差距

Random Feature Attention (RFA)

  • 使用随机傅里叶特征近似 softmax
  • 支持 causal masking（通过 prefix sum 实现）

为什么没有大规模采用？

  • 精度差距：核函数近似在长序列语言建模上与 softmax 差距明显
  • 训练不稳定：去掉 softmax 后注意力权重缺乏归一化，易发散
  • FlashAttention 的出现：精确计算 + IO 优化已足够高效，动力减少
  • 表达能力受限：d×d 的隐式状态无法完整压缩 n×n 的注意力信息
  • 最新方向：Mamba/State Space Model 从不同角度解决线性复杂度问题

Linear TransformerELU+1 核：φ(x) = elu(x) + 1最简单的线性化，实现容易困惑度差距约 5-15%
Performer随机特征核（FAVOR+）无偏估计 softmax，理论保证强困惑度差距约 2-8%
RetNet指数衰减 + 门控机制支持并行训练 + 递归推理，微软提出接近标准 Attention，差距约 1-3%
Mamba (SSM)状态空间模型（非注意力）选择性扫描，硬件感知实现部分任务超越 Attention，NLU 任务仍弱 2-5%

何时选择线性注意力：(1) 序列长度超过 32K 且延迟敏感的场景；(2) 端侧/嵌入式部署，无法承受 O(N²) 开销；(3) 作为混合架构的一部分——底层用线性注意力处理长距离依赖，顶层用标准注意力精修局部信息。

  • 默认先开 FlashAttention：它是精确算法，开了没有精度风险，收益却是实打实的两到四倍
  • KV Cache 撑不住时按顺序试：先 GQA，再量化 KV（int8/fp8），最后才考虑改注意力结构
  • 用 PagedAttention 类的推理引擎接管显存分配，不要自己按 max_len 预分配
  • 换成滑动窗口或稀疏注意力之前，先用真实业务样本量出"需要跨多远做推理"，再定窗口大小
  • 线性注意力优先考虑混合架构而非全量替换，两到三成的标准注意力层通常就能保住大部分质量
  • 不要拿 MQA 当免费午餐用在小模型上：头数本来就少，再共享 KV 精度掉得很明显
  • 不要把 FlashAttention 的加速比直接当成端到端加速比，注意力常常只占总时间的三到四成
  • 不要用"有效感受野 = 层数 × 窗口"来证明滑动窗口无损，多跳传递是有信息衰减的
  • 不要在训练期用全注意力、推理期换滑动窗口，两边的注意力模式必须一致
  • 不要为了追新直接上纯线性注意力做通用语言模型，长文本困惑度上的差距至今没有被完全抹平

混合架构：标准注意力与线性注意力/SSM 交替堆叠

纯线性注意力在质量上仍有差距，纯标准注意力在长文本上代价太大。2024-2025 年的前沿趋势是混合架构——将线性注意力（或 SSM）与标准注意力交替堆叠，通过分层策略兼顾两者优势：

混合方案架构设计序列长度效果
Jamba（AI21 Labs）每 5 层 Mamba 配 1 层标准 Attention256K接近 Llama 2 70B 质量，推理快 3x
Zamba（Zyphra）共享 Attention 层 + 独立 Mamba 层交替128K参数量仅 7B，长文本质量接近同规模 Transformer
Griffin（Google DeepMind）门控线性循环 + 局部滑动窗口 Attention64K+训练效率提升 40%，质量与标准 Attention 持平

核心取舍：混合架构的本质是在"全局信息检索精度"和"序列处理效率"之间找平衡点。标准注意力层负责精确的局部信息交互（类似"精读"），线性注意力/SSM 层负责高效的长距离信息压缩（类似"泛读"）。实验表明，仅需 20-25% 的标准注意力层即可保留大部分质量优势。这条路线可能成为下一代长文本模型的主流方案。

  • 线性注意力的核心 trick：改变矩阵乘法顺序 (QKT)V → Q(KTV)
  • 为什么不流行的答案：精度差距 + FlashAttention 足够好 + SSM 更有前途
  • 如果提到线性注意力，通常会被追问"为什么没有取代标准注意力"
  • 了解 Performers 的 FAVOR+ 机制即可，不需要深入推导

Q&A（10 题）

Q1: 标准注意力的时间和空间复杂度分别是多少？为什么是长上下文的瓶颈？

答：时间复杂度 O(n²d)，空间复杂度 O(n²)（需要存储 n×n 注意力矩阵）。序列长度翻倍时，计算和内存都增长 4 倍。对于 128K token 的序列，n×n 矩阵约需 30GB（FP16），远超单块 GPU 显存。此外，标准注意力是 memory-bound 的——算力不是瓶颈，数据搬运（HBM ↔ SRAM）才是真正的性能瓶颈。

Q2: MQA 和 GQA 的区别是什么？LLaMA-2 用的是哪种？

答：MQA 让所有 attention head 共享同一组 KV（KV head=1），GQA 是 MHA 和 MQA 的折中——将 h 个 head 分为 g 组，每组共享一套 KV。LLaMA-2 70B 采用 GQA（h=64, g=8），在保持接近 MHA 精度的同时将 KV Cache 减少 8 倍，实现推理加速。

Q3: FlashAttention 为什么能加速注意力计算？它是近似计算吗？

答：FlashAttention 不是近似方法，它与标准注意力的数学结果完全一致。加速原因：(1) 通过 Tiling 将计算分块放在快速的 SRAM 中进行；(2) 避免在慢速 HBM 中物化 n×n 注意力矩阵；(3) 使用 Online Softmax 技巧支持分块计算。本质是将 memory-bound 问题转化为更接近 compute-bound 的问题。

Q4: FlashAttention 中 Online Softmax 是怎么工作的？

答：分块计算 softmax 的难点在于 softmax 需要整行的全局 max 和 sum。Online Softmax 的解决方案：维护 running max (m) 和 running sum (l)。每处理一个新 tile 时，更新 m_new = max(m_old, tile_max)，然后用 correction factor exp(m_old - m_new) 修正之前的部分和。这样最终结果与一次性计算完全一致。

Q5: FlashAttention-2 相比 FlashAttention-1 有哪些改进？

答：三个主要改进：(1) 在序列长度维度增加并行化（FA-1 只在 batch×head 维度并行）；(2) 减少非矩阵运算（合并 softmax rescaling，减少 warp 间同步）；(3) 更优的 thread block 内工作分配。结果：在 A100 上达到理论峰值的 50-73%，相比 FA-1 速度提升约 2 倍。

Q6: PagedAttention 解决了什么问题？原理是什么？

答：解决 LLM 推理时 KV Cache 的内存碎片化问题。传统方案预分配最大长度的连续内存，利用率仅 20-40%。PagedAttention 借鉴 OS 虚拟内存思想：将 KV Cache 分成固定大小的 Block，用 Block Table 映射逻辑地址到物理地址，按需分配，支持 Copy-on-Write。这将 KV Cache 利用率提升到接近 100%，吞吐量提升 2-4 倍。

Q7: Sliding Window Attention 如何在有限窗口内实现全局感知？

答：单层只关注局部 w 个 token，但通过多层堆叠实现全局感知。第 L 层的有效感受野 = L × w。以 Mistral-7B 为例：32 层 × 4096 窗口 = 131,072 的理论感受野。高层 token 通过低层的逐步传递间接获得了全局信息。额外优势：KV Cache 大小恒定（仅需存储 w 个 token 的 KV），不随序列增长。

Q8: Ring Attention 如何实现分布式超长序列训练？

答：将序列分割到 N 个设备上，设备排列成逻辑环。每个设备持有一段 Q，KV 块在设备间环形传递。关键优化：计算与通信重叠——设备在计算当前 KV 块的注意力时，同时将 KV 块发送给下一个设备。使用 Online Softmax 逐块累积结果。只要通信时间 ≤ 计算时间，通信开销就能被完全隐藏。

Q9: Longformer 和 BigBird 在稀疏注意力设计上有什么区别？

答：Longformer = 局部窗口 + 全局 token（[CLS] 等少数 token 关注所有位置）。BigBird 在 Longformer 的基础上增加了随机连接（每个 token 随机关注一些远距离 token）。BigBird 的随机连接有理论意义：Google 证明 Local + Global + Random 的组合具有 Turing completeness。两者复杂度都是 O(nw)，但 BigBird 的随机连接有助于远距离信息传递。

Q10: 线性注意力为什么没有大规模取代标准注意力？

答：四个原因：(1) 精度差距——核函数近似在长序列语言建模上与 softmax 有明显差距；(2) 训练不稳定——缺乏 softmax 归一化容易发散；(3) FlashAttention 的出现使精确 attention 足够高效，减少了近似方法的需求；(4) 表达能力受限——d×d 隐式状态无法完整压缩 n×n 信息。当前趋势：SSM（如 Mamba）从不同角度解决线性复杂度问题，逐步替代了线性注意力的定位。
