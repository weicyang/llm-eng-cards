T12 · FFN：Transformer 前馈网络代码实现

升维 → 激活 → 降维 / 两层线性=一层线性的陷阱 / 4 倍扩展的参数账本 / FFN 知识存储 / 类封装实现

FFN 的本质是一个"先摊开再收拢"的非线性加工车间：把每个 Token 的向量摊开到 4 倍宽的高维空间里，让激活函数做精细的非线性筛选，再压缩回原维度。Attention 负责让 Token 之间互通信息，FFN 负责让每个 Token 独立消化这些信息。

一、FFN 结构总览：小→大→小三步流程

FFN（Feed-Forward Network，前馈网络）是 Transformer Block 里紧跟在注意力之后的子层。所谓"前馈"，指信号只朝一个方向流动——输入进去、输出出来，没有循环、没有反馈，这也是它和 RNN 最直观的区别。它在每个 Token 的位置上独立作用：序列里有 7 个 Token，它就并行地做 7 次完全相同的变换，Token 之间互不干扰。

结构上它简单得出奇：两层线性变换，中间夹一个激活函数。公式一行就能写完：

FFN(x) = Activation(x · W₁ + b₁) · W₂ + b₂

拆开就是三步：第一层把 d_model（模型的统一表示宽度，原始论文取 512）升维到 d_ff（中间层宽度，原始论文取 2048）；中间过激活函数引入非线性；第二层再降回 d_model。整个过程形状变化是"小 → 大 → 小"：

FFN 三步流水线（L=7 个 Token，d_model=8，d_ff=32） 输入 x (7, 8) │ ▼ ① 升维：x · W₁ + b₁ W₁: (8, 32) hidden (7, 32) ← 维度膨胀 4 倍 │ ▼ ② 激活：ReLU / GELU 形状不变，数值分布被改写 hidden (7, 32) ← 负值被截断/平滑压缩 │ ▼ ③ 降维：h · W₂ + b₂ W₂: (32, 8) 输出 (7, 8) ← 形状与输入完全一致 进什么形状，出什么形状 —— 所以 FFN 可以在每个 Block 里无限堆叠。

用代码把输入造出来（模拟 Attention 子层的输出）：

import numpy as np
L, d_model, d_ff = 7, 8, 32   # 序列长度 / 模型宽度 / 中间层宽度
np.random.seed(42)

x = np.random.randn(L, d_model)      # Attention 的输出作为 FFN 输入
print(f"FFN 输入: {x.shape}")        # (7, 8)

升维只需要一个矩阵乘法：

W1 = np.random.randn(d_model, d_ff)  # (8, 32)
b1 = np.random.randn(d_ff)           # (32,)
hidden = x @ W1 + b1
print(f"[升维后] hidden: {hidden.shape}")   # (7, 32)

每个 Token 从 8 维膨胀到 32 维。注意此时还只是线性变换，没有引入任何"新东西"——真正的魔法发生在激活函数那一步。

FFN 与 Attention 的分工：Attention 是"横向交流"，让 Token 互相看见、加权搬运信息；FFN 是"纵向深化"，每个 Token 关起门来独立做非线性加工。一个管信息流通，一个管信息消化。

三步流程速查表

步骤操作输入形状输出形状角色
① 升维x · W₁ + b₁(L, d_model)(L, d_ff)摊开到高维空间
② 激活ReLU / GELU(L, d_ff)(L, d_ff)非线性筛选
③ 降维h · W₂ + b₂(L, d_ff)(L, d_model)压缩回原宽度

二、为什么必须有激活函数

FFN 里最关键、也最容易被当作"例行公事"的一步，就是中间的激活函数——一个逐元素作用的非线性函数。它的存在不是装饰，而是逻辑上的必需：如果把它拿掉，两层线性变换叠加后仍然只是一个线性变换：

(x·W₁)·W₂ = x·(W₁W₂) = x·W′　—— 两层线性 = 一层线性，白干了

矩阵乘法满足结合律，中间的括号可以随意挪动。这意味着无论堆多少层"纯线性 FFN"，表达能力都等价于单层线性映射，模型永远学不到"特征组合"这类复杂模式。插入一个非线性函数后，这个等价关系被打破，网络才具备逼近任意复杂函数的潜力。

以 ReLU 为例，它做的事极简：负数清零、正数保留。

def relu(x):
    return np.maximum(0, x)

hidden_activated = relu(hidden)
print(f"[激活后] shape 不变: {hidden_activated.shape}")  # (7, 32)
print(f"激活前负数个数: {(hidden < 0).sum()}")            # 112
print(f"激活后负数个数: {(hidden_activated < 0).sum()}")  # 0

形状没变，但数值分布被彻底改写：112 个负值被截成 0。这种"逐元素的条件行为"是线性变换做不到的——它让不同的输入走不同的计算路径，这正是非线性的价值。

没有激活函数的深层网络，就像 10 级齿轮组却没有离合器——无论多少级，传动比永远是一个固定值。激活函数是那个让系统"分段响应"的离合器。

有无激活函数的直接对比

维度无激活函数有激活函数
数学本质两层线性的复合仍是线性分段/平滑的非线性映射
表达能力等价于单层线性层可逼近复杂特征组合
深度收益堆再多层也无增益深度带来表达力跃升
对 Attention 的意义无法弥补注意力"只做线性加权"的短板为模型注入非线性加工能力

顺带一提：Self-Attention 的核心运算是加权求和，本质上是对 Value 向量的线性组合。如果 FFN 也是纯线性的，整个 Transformer 从头到尾都是线性运算，深度将毫无意义。FFN 的非线性是整个架构里"深度换能力"的主要来源。

三、为什么偏偏扩 4 倍

d_ff = 4 × d_model 这个比例从 2017 年沿用至今，它不是玄学，而是两股力量平衡的结果。

表达力视角：非线性需要足够宽的舞台

激活函数是在 d_ff 维空间里做筛选的。中间层太窄，能表达的特征组合数量受限，激活函数"英雄无用武之地"；太宽则参数量和计算量暴涨，训练变慢且容易过拟合。经验上 4 倍提供了足够的表达空间，又不至于让成本失控。

计算平衡视角：一层 Block 内的参数账本

数一数一层 Transformer Block 里两大组件的参数量（忽略偏置，d 记 d_model）：

一层 Block 的参数账本（d_ff = 4d） Attention 部分 FFN 部分 ┌────────────────────┐ ┌────────────────────┐ │ Wq: d×d │ │ W₁: d × 4d │ │ Wk: d×d │ │ W₂: 4d × d │ │ Wv: d×d │ │ │ │ Wo: d×d │ │ │ ├────────────────────┤ ├────────────────────┤ │ 合计: 4d² │ │ 合计: 8d² │ └────────────────────┘ └────────────────────┘ FFN 参数量 = 8d² = 2 × Attention 的 4d²
组件参数矩阵参数量（d_model=512）占比
AttentionWq / Wk / Wv / Wo 各 512×5124 × 512² ≈ 105 万约 1/3
FFN512×2048 + 2048×5128 × 512² ≈ 210 万约 2/3

当 d_ff 取 4 倍时，FFN 参数量恰好是 Attention 的 2 倍，两者在量级上"门当户对"。若取 2 倍，FFN 表达力不足；取 8 倍、16 倍，参数倾斜到 FFN 一侧，注意力的信息路由能力就成了短板，整体收益递减。

4 倍是一个"表达力够用、成本可承受"的工程甜点——就像高速公路修 4 车道：2 车道太堵，8 车道浪费地皮，4 车道在大多数流量下性价比最高。

扩展倍数的取舍

d_ff 倍数表达力参数/计算成本典型用途
2×受限，特征组合空间小低极限压缩的蒸馏小模型
4×充分适中，与 Attention 平衡原始 Transformer / 多数经典模型
8/3×（配 SwiGLU）充分（门控补偿宽度损失）与 4× ReLU 版参数总量持平Llama 等现代开源模型
8× 及以上边际收益递减高，训练显著变慢MoE 中每个专家的中间层
生产案例 · FFN 是部署优化的主战场：某在线客服平台部署 7B 对话模型（FP16 权重约 14GB）。由于 FFN 占全模型参数约 2/3（约 46 亿参数、9.2GB），团队只对 FFN 权重做 INT8 量化、注意力权重保持 FP16。结果模型体积从 14GB 降到约 9.3GB，单卡显存占用从 18.6GB 降到 13.1GB，解码延迟从 41ms/token 降到 32ms/token，而内部评测集上的回复质量分只下降 0.3 分（满分 100）。理解"参数大头在 FFN"，才能把量化刀用在刀刃上。

四、FFN 是模型的知识仓库

FFN 看起来只是两层全连接，但它承载了模型的绝大部分参数——这正是 2021 年 Geva 等人在 EMNLP 论文《Transformer Feed-Forward Layers Are Key-Value Memories》中深挖的问题：这 2/3 的参数到底存了什么？

答案：键值记忆。把 FFN 的公式换个写法 FFN(x) = f(x·Kᵀ)·V，第一层矩阵的每一行是一个"键"，负责检测某种输入模式；第二层矩阵的每一行是一个"值"，对应一段输出倾向。输入先和所有键做相似度匹配（点积 + 激活），得到的系数再对值做加权求和——这与字典的"查键取值"完全同构。

FFN 作为键值记忆（以"The capital of France is ___"为例） 输入 x（最后一个 Token 的隐状态） │ ▼ 与 W₁ 的每一行（键）做点积 + 激活 ┌─────────────────────────────────────────────┐ │ 键 1: "国家+首都"模式 → 激活系数 0.87 ★ │ │ 键 2: 日期表达模式 → 激活系数 0.02 │ │ 键 3: 否定语义模式 → 激活系数 0.01 │ │ ... 共 d_ff 个键 │ └─────────────────────────────────────────────┘ │ 系数对 W₂ 的行（值）加权求和 ▼ 值 1 占主导 → 输出分布把概率集中到 "Paris" 低层的键捕捉表层模式（n-gram、句法模板），高层的键捕捉语义主题。

这个解释不是比喻，而是可测量、可复现的机制：研究者能在 GPT-2、Llama 等模型里定位到具体的键值对。后续工作进一步证明知识不仅"存在 FFN 里"，而且高度局部化——Dai 等人的 Knowledge Neurons 发现，一条事实（如"但丁出生在佛罗伦萨"）往往只由 FFN 中不到十几个神经元承载；Meng 等人的 ROME/MEMIT 则直接对中间层 FFN 的第二层矩阵做秩一更新，无需重训就能改写模型记忆的事实。

Attention 决定"看哪里"，FFN 决定"想起来什么"。模型的百科知识不是均匀撒在全网的，而是成地址地存放在 FFN 的值矩阵里——这也是知识编辑、模型剪枝都瞄准 FFN 的原因。

生产案例 · 用 FFN 局部更新代替全量重训：某金融客服团队的 13B 模型需要每季度更新约 600 条事实（利率、费率、产品条款）。全量增量预训练需要 8 张 A100 跑 96 小时（约 768 卡时），且容易遗忘旧能力。改用"定位中间层 FFN（32 层中的第 12–20 层）知识神经元 + 局部权重更新"的方案后，单轮更新耗时降到 1.5 小时，抽检事实准确率从 61% 提升到 89%，通用能力回归测试下降不足 1 分。FFN 的知识仓库属性，把"改知识"从训练问题变成了编辑问题。
视角FFN 的角色对应证据
参数分布承载约 2/3 模型参数Geva et al. 2021 论文明确给出该比例
功能定位键值记忆：键检测模式、值注入知识键的激活模式人类可解释，低层浅层模式、高层语义模式

五、ReLU vs GELU vs SwiGLU

激活函数的选型随时代演进：原始 Transformer 用 ReLU，BERT / GPT 系列换成 GELU，Llama 等现代开源模型则用上了 SwiGLU。三者的差别在于"非线性做得多精细"。

GELU 的直觉是"按概率保留"：不是 ReLU 那样一刀切地清零负值，而是让一个接近 0 的负值仍有机会部分通过。NumPy 实现只有两行：

def gelu(x):
    return 0.5 * x * (1 + np.tanh(
        np.sqrt(2/np.pi) * (x + 0.044715 * x**3)))
三种激活函数的响应曲线（横轴输入，纵轴输出） ReLU GELU SwiGLU（门控） y y 输出 = Swish(xW₁) ⊙ (xW₃) │ / │ _-- 两路并行： │ / │ _- 一路过 Swish 激活当"阀门" │ / │ _/ 另一路做线性变换当"货物" ┼──┼─── x ┼~~─── x 阀门逐元素控制货物通过量 │ 硬折角 平滑过渡 ⊙ = 逐元素相乘（门控） 负值=0 一刀切 负值小幅衰减 比单纯激活表达力更强
激活函数行为特点主要弱点代表模型
ReLU负值清零、正值直通，计算最省硬折角 + 神经元死亡风险原始 Transformer
GELU平滑的按概率保留，0 附近渐变计算略贵（tanh/erf）BERT、GPT-2、GPT-3
SwiGLU门控结构，多一路线性投影做调制多一个权重矩阵，需缩小 d_ff 抵消Llama、PaLM、Mistral

神经元死亡是 ReLU 的经典病灶：某个中间神经元的输入若长期为负，输出恒为 0，梯度也恒为 0，这个神经元就永久"死掉"了。当学习率偏大或初始化不佳时，FFN 中间层可能成片死亡，等价于模型悄悄变窄。

生产案例 · 死 ReLU 诊断与激活函数切换：某团队预训练一个 3 亿参数的中文模型，训练到 40% 进度时发现验证集困惑度停滞在 24.6。逐层探针显示，第 8 层 FFN 的 32 个中间神经元里有 10 个（31%）在 99.5% 的样本上输出恒为 0——典型的死 ReLU。团队从检查点切换为 GELU 版 FFN 继续训练 2000 步后，困惑度降到 22.9 并恢复下降趋势，单步耗时仅增加 2%。此后该团队把"FFN 中间层零激活率"列入训练监控面板，阈值设在 15%。

激活函数的进化史，就是"把一刀切变成精细调控"的历史：ReLU 是电灯开关，GELU 是调光旋钮，SwiGLU 直接给每个通道装了个智能阀门。

注意 SwiGLU 的工程细节：它多出一个权重矩阵，为了不让参数量膨胀，Llama 把 d_ff 从 4×d_model 缩到约 8/3×d_model，最终总参数与 4× ReLU 版基本持平。这再次印证：4 倍的本质不是常数信仰，而是"给非线性留足空间，同时管住成本"。

六、代码实现：把 FFN 封装成类

把四步流程打包成可复用的类。初始化时要注意两点：权重用 0.01 缩放的高斯分布（避免初期数值爆炸），偏置置零。

class FeedForwardNetwork:
    def __init__(self, d_model, d_ff, activation='relu'):
        self.W1 = np.random.randn(d_model, d_ff) * 0.01
        self.b1 = np.zeros(d_ff)
        self.W2 = np.random.randn(d_ff, d_model) * 0.01
        self.b2 = np.zeros(d_model)
        self.activation = activation

激活函数抽成私有方法，支持 ReLU / GELU 切换：

    def _activate(self, x):
        if self.activation == 'relu':
            return np.maximum(0, x)
        return 0.5 * x * (1 + np.tanh(
            np.sqrt(2/np.pi) * (x + 0.044715 * x**3)))

前向传播就是三步流水线，每步打印 shape 便于验证：

    def forward(self, x):
        hidden = x @ self.W1 + self.b1        # ① 升维
        print(f"[①升维] {x.shape} -> {hidden.shape}")
        hidden = self._activate(hidden)        # ② 激活
        output = hidden @ self.W2 + self.b2    # ③ 降维
        print(f"[③降维] {hidden.shape} -> {output.shape}")
        return output

运行验证：

x = np.random.randn(7, 8)
ffn = FeedForwardNetwork(d_model=8, d_ff=32, activation='gelu')
out = ffn.forward(x)
# [①升维] (7, 8) -> (7, 32)
# [③降维] (7, 32) -> (7, 8)
print(f"形状一致: {x.shape == out.shape}")   # True

输入 (7, 8)、输出 (7, 8)，形状完全一致——这就是 FFN 能嵌进每一层 Block 的原因：它不改变数据的"外形"，只改写内在的信息含量。

判断 FFN 实现是否正确的第一标准不是 loss，而是形状：进 (L, d_model)，出 (L, d_model)，中间膨胀到 (L, d_ff)。形状对了，数据流就对了。

实现中容易踩的坑

坑后果正确做法
b1 / b2 忘记广播维度形状错误或与错误维度相加b1 形状 (d_ff,)、b2 形状 (d_model,)，靠广播作用到每个 Token
W1 / W2 形状写反矩阵乘报错或维度倒挂W1: (d_model, d_ff)，W2: (d_ff, d_model)，与 @ 的左右顺序匹配
权重初始化过大升维后数值爆炸，softmax/归一化失效小方差初始化（如 ×0.01）或 Xavier/He 初始化
激活函数放在降维之后非线性作用在原维度，表达空间被压缩严格放在两次线性变换之间
  • 先打印每一步 shape，确认 小→大→小 的形状轨迹
  • 把激活函数做成可配置参数，方便 ReLU / GELU 对比实验
  • 训练时监控 FFN 中间层的零激活率，及早发现死神经元
  • 量化/剪枝部署时优先对 FFN 下手，它是参数大头
  • 不要去掉激活函数——两层线性等于一层线性
  • 不要盲目加大 d_ff，超过 4 倍后收益递减、成本暴涨
  • 不要用大学习率配 ReLU，死神经元风险陡增
  • 不要在 Token 维度上做 FFN 变换——它是逐位置独立的

Q&A

FFN 为什么要在每个 Token 上独立作用，不做 Token 间交互？
这是 Transformer 明确分工的结果：Token 间的信息交互已经由 Self-Attention 完成，每个 Token 的向量里已经融合了上下文信息。FFN 的职责是对这些融合后的向量逐个做非线性深加工，如果它也做交互，就和 Attention 功能重叠且计算更贵。逐位置独立还带来工程红利：FFN 可以表示为两个大矩阵乘法，GPU 利用率极高，也方便按 Token 并行与量化优化。
把 d_ff 从 4 倍改成 2 倍或 16 倍会发生什么？
改成 2 倍时，中间层表达空间变窄，激活函数能捕捉的特征组合受限，同等训练量下困惑度通常更高，只在极限压缩的小模型里才这么用。改成 16 倍时，参数量和单步计算量暴涨，但表达力收益递减，还更容易过拟合、拖慢训练。实践中 4 倍附近是甜点区；现代模型用 SwiGLU 时取约 8/3 倍，靠门控机制补偿宽度损失，总参数量与 4 倍 ReLU 版持平。
为什么说"两层线性等于一层线性"？这对网络设计意味着什么？
矩阵乘法满足结合律，(x·W₁)·W₂ = x·(W₁W₂)，两个线性映射的复合仍是一个线性映射，可合并成单个矩阵 W′。这意味着纯线性网络无论堆多深，决策能力都等价于单层，深度带来的表达力增益为零。设计上的推论是：任何想靠"堆深度"变强的架构，层与层之间必须有非线性（激活函数、softmax、归一化后的调制等），否则深度只是计算浪费。
为什么知识主要存在 FFN 里，而不是 Attention 里？
从结构看，FFN 是逐位置的大容量查表结构：第一层矩阵的每行像一个模式检测器（键），第二层矩阵的每行像一段可注入的内容（值），天然适合存储"看到什么模式就补什么信息"的关联记忆；而 Attention 的职责是动态路由，决定当前 Token 该从上下文哪些位置取信息，它的参数描述的是"怎么找"，而不是"存了什么"。从证据看，FFN 占全模型约 2/3 参数，Knowledge Neurons 和 ROME/MEMIT 等工作把具体事实定位到中间层 FFN 的少量神经元，并通过修改 FFN 权重直接改写事实。
现代模型为什么选 SwiGLU 而不是更简单的 ReLU？
ReLU 有两个硬伤：0 点的硬折角让优化景观不平滑，负区梯度恒为 0 会引发神经元死亡，成片的死神经元等于模型悄悄变窄。SwiGLU 用门控结构解决这些问题：一路输入过 Swish 激活充当平滑的"阀门"，另一路做线性变换充当"货物"，阀门逐元素控制通过量，既无死区又保留了更强的条件表达能力。代价是多一个权重矩阵，所以 Llama 把 d_ff 缩到约 8/3×d_model 抵消参数膨胀，整体规模不变而效果更好。
FFN 里的偏置项 b1、b2 重要吗？去掉会怎样？
偏置的作用是为每个中间神经元提供可学习的激活阈值，让"什么样的输入才算命中该模式"可以平移调整，对表达能力是有益补充。但它的参数量极小（d_ff + d_model），相对数百万的权重矩阵几乎可以忽略。实践中，Llama 等现代模型确实去掉了 FFN 偏置，配合 SwiGLU 与归一化结构，效果未见明显损失，还能简化推理内核。经典实现（原始 Transformer、BERT、GPT-2）则保留偏置。结论是：保留偏置是稳妥默认，去掉偏置在现代架构下是安全的简化。
FFN 和 MoE（混合专家）是什么关系？
MoE 本质上是对 FFN 的横向扩展：把每个 Block 里的单个 FFN 换成多个并行的"专家 FFN"，再用一个路由器（门控网络）为每个 Token 挑选 Top-K 个专家参与计算。这样总参数量大幅增加（知识容量变大），但每个 Token 只经过少数专家，单 Token 计算量基本不变。理解 FFN 是理解 MoE 的前提——每个专家就是一个标准的"升维→激活→降维"结构，MoE 只是把"一个车间"扩建成了"多个专业车间 + 调度台"。
