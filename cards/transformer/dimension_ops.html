T11 · Transformer 升维与降维原理

Dimension Operations — 降维压缩 / 升维展开 / FFN 4倍扩展 / 非线性激活 / KV Cache 维度权衡

维度变化是手段，信息保持与提取才是目的。Transformer 中每一次升维都在"展开地图让隐藏关系显现"，每一次降维都在"压缩行李只保留最重要的东西"。

一、为什么需要维度操作

效率与性能的平衡术

模型不能无限大。维度操作的本质是在"特征表达力"和"计算成本"之间寻找最优解。

Transformer 模型参数量动辄数十亿，每一次矩阵乘法的计算量与维度直接相关。d_model（模型隐藏维度）决定了信息在层与层之间传递时的"车道宽度"——太窄会丢失信息，太宽会撑爆算力和内存。维度操作正是为了在有限资源下让模型"该宽的地方宽、该窄的地方窄"。

具体来说，维度操作解决三个核心矛盾：

  • 表达力 vs 计算量：d 维特征需要 O(d²) 的矩阵乘法，升 4 倍就是 16 倍计算量
  • 信息密度 vs 噪声：高维空间有更多"自由度"来编码复杂关系，但也更容易过拟合
  • 层间一致性 vs 层内灵活性：残差连接要求输入输出维度一致，但中间过程需要自由扩展
核心结论：维度操作不是 Transformer 的"可选优化"，而是架构设计的基石。没有升维就没有非线性表达力，没有降维就无法堆叠更多层。

二、降维的本质：压缩信息，保留精华

降维 = 有损压缩

降维就像 JPEG 压缩——丢掉人眼不敏感的高频细节，保留画面主体。好的降维丢掉的是噪声，留下的是信号。

在 Transformer 中，降维出现在多个关键环节。每一次降维都意味着模型在做"信息取舍"——选择保留什么、丢弃什么。这种取舍能力正是模型学到"什么是重要的"的体现。

降维方法原理在 Transformer 中的体现信息损失特征
线性投影矩阵乘法 W·x，W 为 d_out × d_in（d_out < d_in）FFN 第二层：4d → d线性组合，保留主要方向
注意力加权用 softmax 权重对 value 做加权求和Self-Attention 输出动态选择，丢弃低权重 token
池化（Pooling）对局部区域做平均或取最大值分类任务的 [CLS] token 提取局部压缩，丢失细粒度信息
非线性激活ReLU 将负值归零，等效降维FFN 中间层约 50% 神经元被"杀死"

ReLU 的"隐性降维"效应

ReLU 激活函数虽然不改变张量的名义维度，但它将约 50% 的神经元输出置零。从信号处理的角度看，这等于把信息量砍掉一半。如果 FFN 中间层是 4d 维，经过 ReLU 后有效信息只剩约 2d 维——这就是为什么 FFN 需要升 4 倍而不是 2 倍的原因。

FFN(x) = W₂ · ReLU(W₁ · x + b₁) + b₂
其中 W₁: d → 4d, W₂: 4d → d
ReLU 后有效维度 ≈ 2d → 经 W₂ 压缩回 d（信息恰好守恒）

三、升维的本质：展开空间，暴露关系

升维让线性不可分变为可分

升维的核心价值在于增加特征空间的自由度。d 维空间中，一个向量只有 d 个自由度来编码信息；扩展到 4d 维后，同一个特征向量获得了 4 倍的"表达空间"，原本纠缠在一起的特征模式可以在更高维空间中被线性分离。

升维方法原理特点典型场景
线性扩展W·x，W 为 d_out × d_in（d_out > d_in）纯线性，不增加非线性FFN 第一层 d → 4d
前馈网络线性扩展 + 非线性激活同时升维和引入非线性FFN 完整流程
上采样重复或插值扩展维度信息冗余度高解码器维度恢复
关键洞察：纯线性升维不会增强表达能力——无论你把 d 维扩展到多少维，如果只是线性变换，它依然只能表达线性关系。升维必须配合非线性激活函数（如 GELU、ReLU）才能真正提升模型的表达力。

升维为什么能让"分不开"变成"分得开"

数据流解读：输入以 d 维进入 Attention 子层，Attention 内部将 Q/K/V 按头切分（每头 d/h 维），注意力加权本身就是一种"动态降维"——用 softmax 权重选择性地聚合信息。多头拼接后恢复 d 维。随后进入 FFN 子层，先线性扩展到 4d，经过非线性激活后有效信息约 2d，最后线性压缩回 d 维。整个过程保证了输入输出维度一致，使得 Block 可以无限堆叠。

五、FFN 为什么先升 4 倍再降回来

信号补偿：ReLU 吃掉了一半信息

FFN 升 4 倍的本质原因：ReLU 会"杀死"约 50% 的神经元，所以需要 4 倍扩展来补偿——确保经过激活和降维后，仍有 d 维有效信息流出。

从信号处理视角推导这个"4 倍"的由来：

  1. 输入 d 维特征，线性扩展到 4d 维
  2. 经过 ReLU：约 50% 的神经元输出被置零，有效信息从 4d 降到约 2d
  3. 线性降维：从 2d 有效维度投影到 d 维输出
  4. 最终输出恰好保留 d 维有效信息——信息守恒

如果只升 2 倍呢？

  • 扩展到 2d → ReLU 后有效约 d → 再降维到 d → 有效信息只剩 0.5d
  • 信息衰减一半，模型表达能力严重不足
信息守恒链: d →(×4)→ 4d →(ReLU,×0.5)→ 2d →(÷2)→ d ✅
若 2 倍扩展: d →(×2)→ 2d →(ReLU,×0.5)→ d →(÷1)→ 0.5d ❌ 信息不足

GELU 激活：比 ReLU 更"温柔"的非线性

GELU 不像 ReLU 那样"一刀切"地置零，而是用平滑曲线让接近零的值"逐渐衰减"——信息损失更小，梯度更稳定。

现代 Transformer（如 GPT、BERT）普遍用 GELU（Gaussian Error Linear Unit）替代 ReLU。GELU 的公式为 GELU(x) = x · Φ(x)，其中 Φ(x) 是标准正态分布的累积分布函数。它的核心差异在于：

特性ReLUGELU
负值处理完全置零（硬截断）平滑衰减（软抑制）
信息损失约 50% 神经元死亡约 30-40%（更少）
梯度连续性零点不可导处处可导
训练稳定性可能出现 dead neuron更稳定
计算开销极低（max 操作）略高（需要计算 Φ）

正因为 GELU 的信息损失比 ReLU 少，使用 GELU 的模型在理论上可以用更小的升维倍数（如 3 倍），但实践中 4 倍仍是主流选择，因为它提供了更充裕的"表达余量"。

记忆系统视角：FFN 是 Transformer 的长期记忆

这个视角由 Geva et al. (2021) 提出，揭示了 FFN 第一层的权重矩阵充当"键"（用于模式匹配），第二层权重充当"值"（用于信息注入）。训练过程中，模型将事实知识"写入"这些权重中。这也解释了为什么 FFN 通常占模型参数的约 2/3——它需要足够的容量来存储知识。

六、KV Cache 中的维度权衡

推理加速的维度瓶颈

KV Cache 的本质是用空间换时间——缓存历史 token 的 K 和 V 向量，避免重复计算。而缓存大小直接由维度决定：维度越大，缓存越吃内存。

在自回归推理时，每生成一个新 token 都需要与之前所有 token 做注意力计算。KV Cache 将已计算的 Key 和 Value 矩阵缓存起来，新 token 只需要计算自己的 Q/K/V，然后与缓存做点积。但缓存的内存占用与维度直接相关：

KV Cache 内存 = 2 × n_layers × n_heads × seq_len × d_head × sizeof(float16)
例：LLaMA-7B, 32层, 32头, d_head=128, seq_len=2048
= 2 × 32 × 32 × 2048 × 128 × 2B ≈ 1.07 GB

当序列长度增长到 32K 甚至 128K 时，KV Cache 的内存开销会线性甚至超线性增长，成为长文本推理的核心瓶颈。

自回归解码时 KV Cache 只增不减（LLaMA-7B：32 层 / 32 头 / d_head=128 / fp16） step 1 产出 t1 Cache: [K1 V1] step 2 产出 t2 Cache: [K1 V1][K2 V2] step 3 产出 t3 Cache: [K1 V1][K2 V2][K3 V3] ... └────── 随 seq_len 线性膨胀，无法回收 ──────┘ 单 token 单层 = 2(K与V) × 32 头 × 128 维 × 2 字节 = 16 KB 单 token 全模型 = 16 KB × 32 层 = 512 KB 2048 token → 2048 × 512 KB ≈ 1.07 GB 32768 token → 32768 × 512 KB ≈ 17.2 GB ← 已经超过 7B 权重本身 压缩动的是哪一维（每 token 每层）： MHA Q 32 头 K/V 32 头 ████████████████████████████████ 16.0 KB GQA Q 32 头 K/V 8 头 ████████ 4.0 KB MQA Q 32 头 K/V 1 头 █ 0.5 KB ↑ Q 那一侧从来不压，被压的永远是需要缓存的 K/V

这催生了两种维度压缩策略：

方案维度策略原理效果
MQA（Multi-Query Attention）K/V 头数 → 1所有 Q 头共享同一组 K/VKV Cache 缩小 h 倍（如 32 倍）
GQA（Grouped-Query Attention）K/V 头数 → g（如 8）每 g 个 Q 头共享一组 K/VKV Cache 缩小 h/g 倍（如 4 倍）
PagedAttention分块管理类似操作系统的虚拟内存分页消除内存碎片，利用率 → ~100%
维度权衡的核心矛盾：更多的 K/V 头数 = 更强的注意力表达力 = 更大的 KV Cache。MQA 把 K/V 压到 1 个头，GQA 折中到 g 个头，都是在"表达力"和"推理内存"之间做 trade-off。GPT-4 级别的模型普遍采用 GQA（如 g=8），在几乎不损失质量的前提下将 KV Cache 压缩 4 倍。

七、降维与升维的应用场景

何时降维、何时升维

需要压缩信息时降维，需要发现复杂关系时升维，需要跨模态转换时先降后升。

场景操作原因实例
文本分类降维将 seq_len × d 压缩为单一向量做分类[CLS] token → Linear(d → num_classes)
特征交叉升维低维空间中特征纠缠，高维才能分离FFN 的 d → 4d → 非线性变换
跨模态对齐先降后升不同模态维度不同，需要在公共空间对齐CLIP：图像/文本各降到 512 维再对比
序列压缩降维减少 token 数量降低 Attention 复杂度PoolingFormer, Perceiver
知识蒸馏降维将大模型知识压缩到小模型Teacher d=4096 → Student d=1024

生产案例：文本分类系统的维度设计

背景：某内容平台的智能审核系统需要将用户评论（平均 50 token）分类为 10 个违规类别。早期方案直接对每个 token 做 10 分类，计算量巨大。

问题：对 seq_len=50 的每个位置都做分类，等价于 50 次独立的 d→10 线性变换，不仅计算冗余，而且各位置预测互相矛盾（同一句话被同时标记为"正常"和"违规"）。

改造：引入"降维漏斗"设计——

  • Step 1：Self-Attention 让 50 个 token 互相交流（维度不变 d=768）
  • Step 2：取 [CLS] token 的 d=768 维向量（从 50×768 降到 768）
  • Step 3：FFN 升维 768→3072→768（非线性特征提取）
  • Step 4：Linear 768→10（最终分类）

效果：计算量从 50×768×10 = 384K 降到 768×10 = 7.68K（减少 98%），分类一致率从 71% 提升至 94%，误判投诉下降 85%。

  • FFN 保持 4 倍扩展比，确保信息守恒
  • 用 GELU 替代 ReLU 减少信息损失
  • 长序列推理用 GQA 压缩 KV Cache
  • 分类任务用 [CLS] + 降维漏斗
  • 跨模态对齐时先降到公共维度空间
  • 盲目增大 d_model 而不考虑计算成本
  • 只用 2 倍扩展（信息衰减至 0.5d）
  • 在 Attention 层用 ReLU（应该用 softmax）
  • 忽略残差连接的维度一致性约束
  • 长文本推理不管理 KV Cache 内存

Q&A（8 题）

FFN 层为什么是 4 倍扩展而不是 2 倍或 8 倍？
4 倍是信息守恒的数学结果。ReLU 会置零约 50% 的神经元，如果只扩展 2 倍（d→2d），经过 ReLU 后有效维度只剩 d，再投影回 d 维时有效信息只有 0.5d。扩展 4 倍（d→4d）经过 ReLU 后有效 2d，投影回 d 时刚好保留 d 维有效信息。8 倍虽然信息更充裕，但计算量是 4 倍的 4 倍（O(d²) 随维度平方增长），收益递减。4 倍是"刚好够用"与"计算可接受"的平衡点。
Attention 层用 softmax，FFN 层用 GELU/ReLU，为什么不能互换？
两者目的完全不同。Attention 中的 softmax 是在 token 维度上做归一化（所有 token 的权重之和为 1），实现"注意力分配"——决定每个 token 应该关注其他 token 的多少信息。FFN 中的 GELU/ReLU 是在特征维度上做非线性变换，让模型学到更复杂的特征组合。如果把 softmax 用在 FFN，所有特征维度的值之和会被约束为 1，严重限制表达能力；如果把 ReLU 用在 Attention，注意力权重可能出现负数，物理含义不对。
KV Cache 的内存为什么和维度成正比？有什么优化方案？
KV Cache 需要为每个 token 的每层每头存储 K 和 V 两个矩阵，总量 = 2 × 层数 × 头数 × 序列长度 × 每头维度。LLaMA-7B 在 seq_len=2048 时约 1GB，seq_len=32K 时约 16GB。优化方案有：MQA（所有 Q 头共享 1 组 K/V，Cache 缩小 h 倍），GQA（g 个 Q 头共享 1 组 K/V，Cache 缩小 h/g 倍），PagedAttention（分块管理消除碎片），以及量化（FP16→INT8 减半）。GQA 是当前主流方案，GPT-4 级别模型普遍采用。
为什么说纯线性升维不会增强表达能力？
线性变换的复合仍然是线性变换。无论你串联多少个线性层 W₁·W₂·...·Wₙ，其效果等价于单个矩阵 W=W₁·W₂·...·Wₙ。这意味着纯线性模型只能学到输入的线性组合，无法拟合非线性函数（如 XOR 问题）。升维必须配合非线性激活函数（GELU、ReLU 等），才能让模型在高维空间中做"非线性切割"，从而表达更复杂的特征关系。这也是为什么 Transformer 的每一层都同时包含线性变换和非线性激活。
残差连接为什么要求输入输出维度一致？
残差连接的公式是 output = LayerNorm(x + Sublayer(x))，其中 x + Sublayer(x) 要求两个张量可以直接相加，这意味着它们必须具有完全相同的 shape。如果 Attention 子层改变了维度，就无法与原始输入做逐元素加法。这就是为什么 Transformer 每个 Block 的输入输出维度都严格保持 d_model 不变——维度变化只发生在 Block 内部（如 FFN 的 d→4d→d），进出 Block 时维度必须恢复。如果不一致，就需要额外的投影矩阵来对齐维度，增加参数量和计算量。
GELU 和 ReLU 在 FFN 中的效果差异有多大？
GELU 对负值做平滑衰减而非硬截断，信息损失约 30-40%（vs ReLU 的 50%），梯度处处连续可导。在 BERT 的原始实验中，GELU 相比 ReLU 在 GLUE 基准上提升约 0.5-1 个百分点。差异看似不大，但在大模型规模下（数十亿参数、数千亿 token 训练），这 0.5% 的提升会累积为生成质量的显著差异。此外 GELU 不会出现 "dead neuron" 问题（神经元永久失活），训练更稳定。计算开销略高（需要计算高斯 CDF），但在 GPU 上有高效近似实现。
多头注意力中，每个头的维度是怎么分配的？
d_model 被均分给 h 个头，每头维度 d_k = d_model / h。例如 GPT-2 Medium 的 d_model=1024，h=16 头，每头 d_k=64。每个头独立做 Q/K/V 投影和注意力计算，最后将 h 个头的输出拼接（h × d_k = d_model）再通过一个线性层。多头的设计让模型在不同"子空间"中同时关注不同类型的关系——有的头关注语法结构，有的关注语义相似性，有的关注位置关系。这也是为什么不能简单减少头数来降维：头数减少意味着"视角"减少。
图像识别中也有类似的升维降维操作吗？
CNN 和 ViT 中都有。CNN 的经典模式是：每个卷积块先通过 1×1 卷积降维（减少通道数以降低后续计算量），再通过 3×3 卷积提取特征，最后通过 1×1 卷积升维恢复通道数——这正是 ResNet Bottleneck 的设计。ViT（Vision Transformer）将图像切成 patch 后直接送入标准 Transformer Block，其中的 FFN 同样执行 d→4d→d 的升维降维循环。Vision Transformer 的实践表明，FFN 的 4 倍扩展对视觉任务同样有效，但 ViT 通常需要更大的 d_model（如 1024）来补偿图像信息的高维度特性。
