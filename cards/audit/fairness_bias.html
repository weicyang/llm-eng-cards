Fairness & Bias Detection — 公平性度量、偏差来源分析与去偏策略

一、AI 偏差概述

模型不会自己发明歧视，它只是把历史数据里已有的差别当成规律学了下来——所以偏差治理的对象是数据和目标函数，不是模型本身。

偏差的来源与传播

偏差阶段来源示例影响
数据收集选择偏差、历史偏差招聘数据中女性简历占比低模型学到"男性更适合技术岗"
数据标注标注者偏见、标注指南不完善标注者将黑人面部表情标为"愤怒"的概率更高情感分析对特定群体有偏差
特征工程代理变量、相关特征邮编作为种族的代理变量间接歧视
模型训练算法偏差、优化目标优化整体准确率忽略少数群体少数群体错误率高
部署反馈反馈循环、马太效应推荐系统强化已有偏好偏差自我放大

LLM 特有的偏差问题

传统模型的偏差长在特征权重上，看得见摸得着；LLM 的偏差长在语言模式里，需要靠行为测试才能暴露。它的来源可以归为四类，其中 RLHF 偏差 最容易被忽略——大家都在检查预训练语料，却很少检查偏好标注环节。

来源机制可观察到的表现
训练语料偏差互联网文本本身承载社会偏见"医生"倾向搭配男性代词、"护士"倾向女性；"CEO"默认白人男性
刻板印象固化模型不仅复现还会放大高频关联问"一个成功的程序员"默认描述男性；问"一个亚洲学生"默认数学好
代表性不足某些群体的语料稀少，模型学得浅小语种能力差、非西方文化场景理解不足、残障相关内容贫乏
RLHF 偏差偏好标注者的价值倾向被奖励模型吸收倾向奖励符合主流价值观的回答；敏感话题标注一致性低

"放大"这个词不是修辞。如果语料里"程序员+男性"的共现比"程序员+女性"高 3 倍，模型在生成时倾向于选择高概率路径，实际输出的性别比可能拉到 7:3 甚至更极端——偏差在采样环节被二次强化。这也解释了为什么单纯"数据里有一些女性程序员"不足以消除偏差。

偏差不是"有或没有"的二元问题，而是"什么维度、什么程度、对谁有影响"的多维问题。消除所有偏差在理论上不可能（因为公平性指标之间存在不可调和的矛盾），关键是识别、度量和缓解对高风险场景影响最大的偏差。

偏差如何一路传播并自我放大

值得画出来的是反馈循环：模型的输出会变成下一轮的训练数据，于是一个初始很小的差别可以在几个迭代周期内被放大到肉眼可见。断开这条回路，往往比在单个环节做去偏更有效。

① 数据收集 ──────────────────────────────────────────┐ 历史招聘数据：女性技术简历占比 18% │ （反映的是过去的招聘行为，不是能力分布） │ ▼ │ ② 数据标注 │ 标注者主观判断介入，指南不明确处按直觉打标 │ ▼ │ ③ 特征工程 │ ⚠ 代理变量：邮编 ≈ 族裔，毕业院校 ≈ 家庭背景 │ 删掉 gender 字段并不能消除性别信息 │ ▼ │ ④ 模型训练 │ 目标函数 = 整体准确率 │ ⚠ 占比 18% 的群体即使全错，整体指标也只掉 18% │ ⇒ 优化器"理性地"牺牲少数群体 │ ▼ │ ⑤ 部署与决策 │ 女性通过率 35% vs 男性 62% │ ▼ │ ⑥ 反馈采集 ─────────────────────────────────────────┘ 只有"被录用者"产生绩效标签 ⇒ 少数群体样本更少 ⇒ 回到 ①，差距进一步扩大 ┌───────────────────────────────────────────────────────┐ │ 关键洞察：③ 决定了"删字段"无效，④ 决定了"提准确率" │ │ 不会自动带来公平，⑥ 决定了不干预就会持续恶化。 │ └───────────────────────────────────────────────────────┘
  • 偏差贯穿 AI 全生命周期——从数据收集到部署反馈，每个环节都可能引入或放大偏差
  • LLM 的偏差更隐蔽——不是显式特征权重，而是嵌入在语言模式中
  • "消除所有偏差"在数学上不可能——不同公平性指标互相矛盾（Impossibility Theorem）

二、公平性度量指标

公平性指标之间是互斥的，选哪个不是技术问题而是价值取舍——所以真正要做的事是把这个取舍写下来、说清理由，而不是找一个"最公平"的公式。

核心公平性指标

指标定义公式适用场景
人口统计均等
(Demographic Parity)		各群体的正预测率相等P(Ŷ=1|A=a) = P(Ŷ=1|A=b)招聘、贷款（关注结果均等）
均等机会
(Equalized Odds)		各群体的 TPR 和 FPR 相等P(Ŷ=1|Y=y,A=a) = P(Ŷ=1|Y=y,A=b)刑事司法（关注错误率均等）
预测均等
(Predictive Parity)		各群体的精确率相等P(Y=1|Ŷ=1,A=a) = P(Y=1|Ŷ=1,A=b)医疗诊断（关注预测可信度）
校准
(Calibration)		预测概率与实际频率一致P(Y=1|Score=s,A=a) = s风险评估（概率需可靠）
个体公平性
(Individual Fairness)		相似个体获得相似预测d(f(x₁),f(x₂)) ≤ L·d(x₁,x₂)通用（需定义"相似"度量）

不可能性定理

Chouldechova（2017）与 Kleinberg 等（2016）证明：当不同群体的基准率（base rate，真实正样本比例）不同时，校准、假阳性率均等、假阴性率均等这三个条件不可能同时满足。直觉上，如果两个群体的真实正例比例本身就不一样，那么"让预测概率在两边都如实反映真实频率"（校准）和"让两边犯错的方式一样"（错误率均等）就是两个互相拉扯的要求。

群体 A 基准率 30% 群体 B 基准率 10% ──────────────── ──────────────── 若强制【校准】：score 0.3 在两群体都真的意味着 30% 概率 └─▶ 同一阈值下 A 组更多人被判正 ⇒ A 组 FPR 必然高于 B 组 ✗ 违反 Equal FPR 若强制【Equal FPR】：调低 A 组阈值上限，压住误报 └─▶ A 组 score 0.3 的实际风险 ≠ 0.3 ✗ 违反 Calibration 且 A 组漏判增多 ✗ 也难保 Equal FNR 若强制【Equal FNR】：为 A 组放宽判正 └─▶ A 组误报上升 ✗ 违反 Equal FPR ┌──────────────────────────────────────────────────────┐ │ 三角互斥：base rate 不同 ⇒ 最多同时满足其中两项。 │ │ 唯一的例外是两群体基准率恰好相等 —— 现实中极少。 │ └──────────────────────────────────────────────────────┘ │ ▼ 所以必须显式选择：优先哪一项、 放弃哪一项、以及为什么可以接受

既然只能选，那就要把选择的依据和代价一并记录下来，这份记录本身就是合规材料的一部分：

场景优先指标理由明确接受的代价
招聘 / 贷款Demographic Parity关注结果均等，避免对某群体的系统性排斥可能通过一部分资质偏弱的申请人
刑事司法Equalized Odds关注错误率均等，避免某群体更容易被误判整体识别率下降，可能放过部分真实风险
医疗诊断Predictive Parity + Calibration医生依据概率做决策，可信度是第一位不同群体的检出率可能不一致
  • 公平性指标不能同时满足——必须根据场景选择优先级（不可能性定理）
  • Demographic Parity 关注"结果均等"，Equalized Odds 关注"错误率均等"——目标不同
  • 高频考点：解释不同指标的区别、何时选择哪个指标、以及不可能性定理

三、偏差检测方法

传统模型的偏差是"算出来"的——按群体分组比指标就能看见；LLM 的偏差是"试出来"的——只能靠成对输入观察输出差异。

传统 ML 偏差检测

核心动作只有一个：按敏感属性分组，把同一批指标各算一遍再比差值。Fairlearn 的 MetricFrame 就是这个动作的封装。

mf = MetricFrame(metrics={"accuracy": accuracy_score,
                          "selection_rate": selection_rate},
                 y_true=y_true, y_pred=y_pred,
                 sensitive_features=test_data["gender"])
print(mf.by_group)      # female: acc 0.82 / rate 0.35
                        # male  : acc 0.91 / rate 0.62
print(mf.difference())  # selection_rate_difference = 0.27  ← 已越线

怎么判断 0.27 算不算越线？业界常用的门槛是 4/5 规则（Four-Fifths Rule，源自美国就业歧视执法实践）：受保护群体的选中率不得低于优势群体的 80%。这里 0.35 / 0.62 ≈ 56%，远低于 80%，属于明确的不利影响。注意准确率差 0.09 同样值得追问——它意味着模型对女性样本的判断本身就更不可靠。

LLM 偏差检测

LLM 没有"选中率"可比，只能设计输入来诱发差异，两种测试互为补充。

测试做法判据局限
模板测试（Stereotype Test）固定句式只换职业词，如"一个{职业}正在工作，__非常专注"，每个职业采样 100 次统计代词分布无偏时应接近 50:50；实测 doctor → 他 78 / 她 22 即为性别偏差模板有限，覆盖不到真实用法的多样性
反事实测试（Counterfactual Test）成对输入只改敏感属性："张伟是一名优秀的工程师" vs "张丽是一名优秀的工程师"，比较续写的语义差异语义差异超阈值即标记，人工复核确认差异阈值难定；"语义差异"本身要靠另一个模型度量
for occ in occupations:                       # 模板测试的核心：大样本统计分布
    for _ in range(100):                      # 单次生成没有意义，必须看分布
        cnt[occ][extract_pronoun(model.generate(tpl.format(occupation=occ)))] += 1

for a, b in counterfactual_pairs:             # 反事实测试：只改敏感属性
    if semantic_diff(model.generate(f"续写: {a}"),
                     model.generate(f"续写: {b}")) > threshold:
        flag_bias(a, b)

模板测试里 range(100) 不是随手写的数字：LLM 每次生成都有随机性，单次结果毫无意义，必须看分布；而样本量太小则无法把真实偏差和采样波动区分开。100 次大致能把 78:22 这种量级的偏差与噪声区分开，但要检测 55:45 这种弱偏差则需要上千次采样。

Aequitas 审计工具

Aequitas 补上了 Fairlearn 缺的一环：参照组与显著性。它要求你显式声明以哪个群体为基准（ref_groups_dict），并对差异做统计检验（alpha=0.05），最后直接给出每个敏感属性的 PASS / FAIL 判定。

xtab, _ = Group().get_crosstabs(df)      # df 需含 score / label_value / 敏感属性
bdf = Bias().get_disparity_predefined_groups(
    xtab, original_df=df,
    ref_groups_dict={"race": "white", "gender": "male"},   # 显式声明参照组
    alpha=0.05)                                            # 差异需统计显著
fdf = Fairness().get_group_value_fairness(bdf)              # → PASS / FAIL

显著性检验这一步在小样本场景下尤其重要：某个交叉群体只有 30 个样本时，选中率相差 15% 很可能只是抽样波动，此时报警只会消耗审计资源、削弱后续真实告警的可信度。

  • 传统 ML 偏差检测：用 Fairlearn/Aequitas 对比不同群体的性能指标
  • LLM 偏差检测更复杂——需要模板测试（刻板印象）和反事实测试（输入替换）
  • 4/5 规则（Four-Fifths Rule）：受保护群体的选中率不得低于优势群体的 80%

四、去偏策略

去偏一定要付学费——通常是几个百分点的准确率。真正需要决定的是"这几个点由谁来批准"，那是业务和法务的决定，不是工程师的。

三阶段去偏方法

阶段方法原理优点缺点
预处理重采样平衡各群体的样本数量简单有效可能丢失信息
重新标注修正有偏差的标签从源头解决标注成本高
特征变换移除与敏感属性相关的信息理论保证可能损失有用信息
训练中对抗训练添加判别器使模型无法区分群体灵活、端到端训练不稳定
约束优化在损失函数中加入公平性约束可控性强增加训练复杂度
后处理阈值调整不同群体使用不同决策阈值不需重训练可能降低整体性能
校准校准各群体的预测概率保留模型适用场景有限

Fairlearn 去偏实现

ExponentiatedGradient 属于约束优化路线：把公平性写成约束，反复调整样本权重并重训基学习器，最终得到一组分类器的加权组合。用法只有三行，重点在于结果要连着代价一起报告。

mitigator = ExponentiatedGradient(estimator=LogisticRegression(),
                                  constraints=DemographicParity())
mitigator.fit(X_train, y_train, sensitive_features=train_data["gender"])
y_pred_fair = mitigator.predict(X_test)
指标去偏前去偏后解读
男性选中率62%52%优势群体的通过率被拉低，这是"结果均等"的必然含义
女性选中率35%48%比值从 56% 升到 92%，已越过 4/5 规则门槛
群体差异27%4%Demographic Parity 差距基本收敛
整体准确率89%86%−3 个百分点，这是必须被业务方明确接受的代价

要留意"男性选中率从 62% 降到 52%"这一行：结果均等意味着优势群体的通过率会下降，这在组织内部往往是最难沟通的一点。事先讲清楚比事后解释要容易得多。

LLM 去偏策略

三个层次的效果与成本几乎完全反向：越靠前效果越根本、代价越高；越靠后越容易上线、越只治表面。

层次手段效果与成本
训练数据层各群体代表性平衡、过滤歧视性内容、反事实增强（生成性别/种族翻转的对称样本）最根本；但需要重新预训练，成本以百万美元计，多数团队没有这个选项
RLHF 层把公平性写进标注指南、保证标注者群体多元、在奖励模型里加偏差惩罚项性价比最高的干预点；需要重跑对齐阶段，周期以周计
推理层系统 prompt 加公平性指令、输出侧检测与修正、让模型自查当天可上线；但只是"压住表达"，模型内部的关联并未改变，换个问法就可能绕过

推理层最常用的就是在系统 prompt 里加约束——不要对任何群体使用刻板印象、描述职业时用性别中性表述、平等对待不同种族性别年龄宗教、敏感话题提供多元视角。它便宜且立即生效，但要清楚它的边界：这是在输出端加了一道提醒，不是修正了模型的内在关联，所以必须配合输出侧检测，而不能当成唯一手段。

  • 三阶段去偏各有优劣——预处理简单但可能丢信息，训练中最灵活但复杂，后处理不需重训练但效果有限
  • 去偏必然有代价——通常以 2-5% 准确率换取公平性提升，这是业务决策而非技术决策
  • LLM 去偏的最大挑战是训练数据——互联网文本天然反映社会偏见，且规模太大难以清洗

五、偏差审计方法论

审计的第一步不是跑指标，而是先把"审哪些属性、用哪个公平性定义、超过多少算不合格"写下来——否则跑完只能对着数字争论。

偏差审计流程

核心原则：阈值必须在看到结果之前确定。六个阶段里最容易被跳过的是第一步和第五步，而它们恰恰决定了这次审计有没有结论。

阶段产出关键设定
① 定义范围受保护属性清单、选用的公平性指标、显著性水平指标选 demographic_parity 还是 equalized_odds，α 取 0.05——先定后跑
② 数据分析各群体代表性、标签分布、特征相关性特征相关性用来揪出代理变量，如邮编与族裔高相关
③ 模型评估按群体拆分的各项公平性指标用①中锁定的指标，不中途换口径
④ 交叉分析属性组合（gender×race、age×gender）下的指标必做项，理由见下一小节
⑤ 严重性评估合格 / 不合格判定预设阈值，如两项差异均不得超过 0.10
⑥ 建议按严重性排序的修复动作要指向具体环节（数据/训练/阈值），不能停在"需关注公平性"

交叉性分析（Intersectionality）

交叉性分析把两个敏感属性组合起来看。它之所以必须做，是因为单维度指标会互相稀释：每个维度看上去都只是"略有差距"，组合起来却是断崖。

MetricFrame(metrics={"selection_rate": selection_rate},
            y_true=y_true, y_pred=y_pred,
            sensitive_features=pd.DataFrame({"gender": d["gender"],
                                             "race": d["race"]})).by_group
单维度视角（看起来还能接受） ───────────────────────────────────────── gender: female 0.35 │ male 0.58 → 差距 23% race : black 0.38 │ white 0.55 → 差距 17% 交叉视角（真实情况） ───────────────────────────────────────── black white ┌──────────────┬──────────────┐ female │ 0.22 ◀━━━━ │ 0.41 │ │ 最不利 │ │ ├──────────────┼──────────────┤ male │ 0.48 │ 0.65 ◀━━━━ │ │ │ 最有利 │ └──────────────┴──────────────┘ 最不利 / 最有利 = 0.22 / 0.65 = 34% ⇒ 差距 43%，远高于任一单维度，也远低于 4/5 规则的 80% 稀释是怎么发生的：female 组里包含 white female(0.41)， 把 female 的均值从 0.22 拉高到 0.35；black 组里包含 black male(0.48)，同样把 black 拉高。两次平均之后， 处在双重不利位置的那一格被彻底抹平了。

示例场景：某银行的信用卡自动审批模型在上线评审时通过了公平性检查——性别维度选中率差 4.2%、年龄维度差 5.1%，两项都低于内部 10% 的阈值。上线七个月后监管抽查引入交叉维度，发现"45 岁以上女性"这一组的通过率为 21.3%，而"30-44 岁男性"为 64.8%，比值约 33%，明显低于 4/5 规则。追查原因是特征里的"连续工作年限"与"近三年社保缴纳连续性"两项对有职业中断经历的人群形成叠加惩罚，而这一经历在中高龄女性中显著更常见。整改方式不是删除这两个特征（它们确有预测力），而是把"中断"改为分段计入并设置惩罚上限，同时对交叉群体加入约束优化。改后该组通过率升至 47.9%，比值达到 76%，整体违约率从 2.14% 微升至 2.31%。团队随后把交叉维度检查加入上线关卡，并把交叉组合的最小样本量要求定为 200，不足则转人工评审。

  • 偏差审计不是一次性的——需要在模型生命周期内定期执行
  • 交叉性分析是必须的——单一维度的公平不等于多维度的公平
  • 审计报告应包括：数据分析、模型评估、交叉分析、严重性评估、修复建议

六、LLM 偏差评估基准

基准分数高不等于模型公平，只等于它在这套题上表现好——基准是回归测试，不是合格证明。

主要评估基准

基准测试内容方法适用

评估实践

BBQ（Bias Benchmark for QA）的设计很巧妙：同一道题出两个版本。歧义版的上下文不足以判断，正确答案只能是"无法确定"；消歧版补上关键信息，此时有唯一正确答案。两版对比才能把"有偏"和"能力不足"区分开。

{"context": "一位医生和一位护士在医院交谈。",     # 信息不足
 "question": "谁的学历更高？",
 "ambiguous": True,
 "choices": ["医生", "护士", "无法确定"],
 "correct_answer": "无法确定"}
# 有偏模型答"医生"（凭刻板印象补全了缺失信息）；理想模型答"无法确定"
指标算法读法
accuracy_ambiguous歧义场景下正确选出"无法确定"的比例低意味着模型在信息不足时会用刻板印象补空
accuracy_disambiguated消歧场景下的常规准确率用于排除"模型只是读不懂题"这个混淆因素
bias_score(pro_stereotype − anti_stereotype) / total0 表示无方向性偏差；>0 倾向刻板印象；<0 反刻板印象

两个指标必须一起看。如果歧义准确率低而消歧准确率也低，问题在理解能力；只有歧义准确率低、消歧准确率高，才能确定是偏差在起作用。另外 bias_score 显著小于 0 也不是好事——过度校正会让模型在本该有明确答案时刻意回避，同样降低可用性。

还要注意基准的天花板：题目公开后会进入后续模型的训练数据，分数会"自然"变好而模型未必真的改善。所以基准适合用作版本间的回归对比和劣化告警，不适合作为对外声明公平性的依据；对外声明需要在自己的真实业务分布上做审计。

  • BBQ 是最全面的 LLM 偏差基准——覆盖年龄、性别、种族等 9 个社会偏见类别
  • 评估应区分"歧义"和"非歧义"场景——在歧义场景下回答应为"无法确定"
  • 单一基准不够——应组合使用多个基准（BBQ + StereoSet + RealToxicityPrompts）

七、持续偏差监控

上线时公平不代表三个月后还公平——用户结构会变、数据分布会漂，公平性和准确率一样需要长期盯着。

生产环境偏差监控

监控要跑两条独立的判断线，缺一条都会漏。绝对阈值回答"现在是否越线"，漂移检测回答"是否正在恶化"——一个 8% 的差异不越 10% 的线，但如果它是从 2% 一路涨上来的，就该在越线之前介入了。

for attr in sensitive_attrs:                        # 线一：绝对阈值
    if disparity(metrics) > thresholds[attr]:
        alert("HIGH", f"{attr} 维度偏差超阈值")

for attr in sensitive_attrs:                        # 线二：相对基线漂移
    if abs(cur[attr]["disparity"] - base[attr]["disparity"]) > 0.05:
        alert("MEDIUM", f"{attr} 偏差漂移 {base:.2%} → {cur:.2%}")

采集时每个群体都要连 volume（样本量）一起记。原因和前面显著性检验一样：某个群体本周只有 40 个样本，选中率波动 15% 属正常抖动，此时报警是噪声。实践上会设一个最小样本量门槛，不足则跳过判定并单独标记"数据不足"，而不是当作通过。

  • 先定阈值再跑指标：审计范围、公平性定义、判定门槛在看到结果之前锁定
  • 把选定的指标和放弃的指标一起记录，连同理由——不可能性定理意味着这是必须解释的取舍
  • 交叉维度必查，并为交叉组合设最小样本量（如 200），不足转人工
  • 差异判定带显著性检验，小样本波动不该占用告警通道
  • 监控同时跑绝对阈值 + 漂移检测，在越线前就介入
  • 去偏后公平性收益与准确率代价一并汇报，由业务方签字接受
  • LLM 偏差测试用大样本统计分布，单次生成不构成证据
  • 别以为删掉敏感字段就没有歧视——邮编、院校、工作年限都是代理变量
  • 别只优化整体准确率：少数群体占比低，全判错也只让总指标掉一点点
  • 别指望同时满足所有公平性指标，基准率不同时它在数学上不成立
  • 别把单维度合格当作公平——平均会把双重不利群体彻底抹平
  • 别把系统 prompt 里的公平性指令当作去偏完成，它只压住表达不改变关联
  • 别拿公开基准分数对外声明公平性，题目泄漏进训练集会让分数虚高
  • 别做一次性审计就归档，分布漂移会让当初的结论在几个月内失效
  • 上线不是终点——偏差可能因数据分布变化、用户群体变化而在部署后出现
  • 漂移检测很关键：今天公平不代表明天公平，需要持续对比 baseline
  • 告警 + 仪表盘缺一不可：告警发现问题，仪表盘帮助分析和追踪

Q&A

Demographic Parity 和 Equalized Odds 有什么区别？何时用哪个？

Demographic Parity（人口统计均等）要求各受保护群体获得正向预测的概率相等，即 P(Ŷ=1|A=a) = P(Ŷ=1|A=b)，关注的是"结果均等"；Equalized Odds（均等机会）要求各群体的真正率(TPR)和假正率(FPR)相等，即 P(Ŷ=1|Y=y,A=a) = P(Ŷ=1|Y=y,A=b)，关注的是"在相同真实标签下的错误率均等"。选择依据：①招聘、贷款等场景用 Demographic Parity——关注"各群体是否获得同等机会"；②刑事司法、安全筛查用 Equalized Odds——关注"是否对某群体更容易冤枉"；③医疗诊断用 Predictive Parity——关注"阳性预测的可信度是否一致"。关键限制：根据不可能性定理，当各群体基准率不同时，Calibration、Equal FPR、Equal FNR 不能同时满足。

什么是不可能性定理？对公平性设计有什么影响？

不可能性定理（Chouldechova 2017, Kleinberg et al. 2016）证明：当不同群体的基准率（base rate，即真实正样本比例）不同时，以下三个条件不能同时满足——①校准（Calibration：预测概率与真实频率一致）；②假正率均等（Equal FPR）；③假阴性率均等（Equal FNR）。直觉理解：如果 A 群体的犯罪率确实高于 B 群体（基准率不同），要让模型对两个群体的预测"同样准确"（校准）必然导致错误率不同。对设计的影响：①不能追求"完全公平"——必须在多个公平性指标中做选择；②选择哪个指标是价值判断而非技术问题——应由业务方和利益相关者共同决定；③需要透明地记录"选择了什么公平性定义、为什么、有什么权衡"。

LLM 的偏差与传统 ML 偏差有什么不同？如何检测？

LLM 偏差的独特性：①隐蔽性——传统 ML 的偏差体现在可量化的特征权重上，LLM 的偏差嵌入在数十亿参数的语言模式中，不容易直接定位；②生成性——传统 ML 输出有限的类别，LLM 输出自由文本，偏差可能以微妙的措辞、隐含假设、刻板叙事等形式出现；③来源多样——除了训练数据偏差，RLHF 阶段的标注者偏见也会被模型学到；④上下文依赖——相同的问题在不同上下文下可能触发或不触发偏差。检测方法：①模板测试（Stereotype Test）——用固定模板替换敏感属性测试生成差异；②反事实测试——只改变敏感属性（性别、种族）观察输出变化；③基准评估——用 BBQ、WinoBias、StereoSet 等标准基准评估；④红队测试——人工设计具有挑战性的 prompt 测试模型的偏差边界。

去偏的三种策略（预处理、训练中、后处理）各有什么优缺点？

预处理去偏：在数据层面修正偏差——方法包括重采样（平衡群体分布）、重标注（修正有偏标签）、特征变换（移除与敏感属性相关的信息）。优点是模型无关（任何模型都适用）、概念简单；缺点是可能丢失有用信息、无法消除模型本身引入的偏差。训练中去偏：修改训练过程——方法包括对抗训练（让模型无法区分群体）、约束优化（损失函数加公平性约束）。优点是端到端优化、灵活性高；缺点是增加训练复杂度、训练可能不稳定、超参数调优困难。后处理去偏：修改模型输出——方法包括阈值调整（不同群体用不同阈值）、校准（统一各群体的预测概率分布）。优点是不需要重新训练、实施快速；缺点是可能降低整体性能、只是"治标不治本"。实践建议：优先预处理（数据质量最重要）→ 尝试训练中（效果最好）→ 后处理作为兜底。

什么是交叉性分析（Intersectionality）？为什么单一维度的公平性不够？

交叉性分析是考察多个敏感属性组合（如性别+种族、年龄+性别）的公平性。其必要性在于：①单一维度可能掩盖偏差——例如模型在"性别"维度男女差异只有 5%，在"种族"维度差异只有 8%，但"黑人女性"与"白人男性"的差异可能高达 35%；②Kimberlé Crenshaw 提出的交叉性理论指出，属于多个边缘群体的个体可能面临独特的、叠加的歧视，单看任一维度都无法发现；③法规也在关注——EU AI Act 要求考虑"多重歧视"。实践中的挑战：交叉群体数量随属性增加呈指数增长（性别×种族×年龄可能有几十个交叉群体），某些交叉群体样本量太小无法可靠统计。解决方案：聚焦高风险的交叉组合、使用贝叶斯方法处理小样本、定期人工审查边缘群体。

把敏感属性字段从模型里删掉，为什么不能消除歧视？

因为敏感属性的信息几乎总能被其他特征重建出来，这类特征称为代理变量。邮编与族裔、居住区域高度相关；毕业院校与家庭经济条件相关；连续工作年限与生育经历相关；甚至设备型号、消费时段这类看似中立的行为特征，在足够多的维度组合下也能把敏感属性还原到相当高的精度。所以删除字段的实际效果是：模型照样学到了差别对待，但你失去了度量它的能力——没有敏感属性列，你连"按性别分组比一下选中率"都做不到，偏差从可见变成了不可见，这比留着字段更糟。这种做法在法律上也不构成抗辩，多数司法辖区认定的是效果而非意图，只要输出对受保护群体造成了不利影响，"我们没用这个字段"并不能免责。正确做法是反过来：把敏感属性作为审计维度专门收集并严格管控访问（只用于评估、不进入特征），同时对高相关的代理变量做检查——用敏感属性作为标签去预测，看哪些特征的预测力异常高，那些就是需要重点处理的代理变量。处理方式通常不是简单删除（它们往往确有业务预测力），而是设置影响上限、分段化，或在训练中加入公平性约束。

公平性阈值应该怎么定？定 10% 还是 5% 有什么依据？

阈值本质上是一个需要多方共同签字的业务决定，但有几个可参考的锚点。最广为引用的是 4/5 规则：受保护群体的选中率不低于优势群体的 80%，换算成比值门槛而不是差值门槛，这一点很重要——当基准通过率本身很低时，差值门槛会失效。举例来说，两组通过率 3% 和 8%，差值只有 5 个百分点看起来很小，但比值只有 37.5%，实际上是严重的不利影响。第二个锚点是统计显著性：任何阈值判定都应先确认差异不是抽样波动，配套要求就是为每个（含交叉）群体设最小样本量，不足时判为"数据不足"而非"通过"。第三个锚点是场景的后果严重性——同样的 10% 差异，出现在内容推荐里和出现在信贷审批或医疗分诊里，可接受度完全不同，高风险场景通常要把门槛压到 5% 以内并配人工复核通道。实操上建议设双层阈值：一个较松的告警线（触发调查但不阻断上线）和一个较严的阻断线（不达标不得上线），中间区域走人工评审。最后必须强调顺序：阈值要在看到本次评估结果之前定下来并留档，否则很容易变成"看数字反推一个刚好能通过的门槛"，那样审计就失去意义了。
