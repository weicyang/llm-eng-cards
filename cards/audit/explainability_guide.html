U04 · 模型可解释性

Model Explainability — SHAP、LIME、Attention 可视化与 LLM 推理链解释

一、可解释性概述

解释不是为了让模型变透明，是为了在出事时能对监管、对用户说清楚"这一次"的判断依据是什么。

为什么需要可解释性

驱动因素说明示例
合规要求EU AI Act 要求高风险 AI 决策可解释信贷审批拒绝时必须解释原因
信任建立用户需要理解 AI 的推理过程医疗诊断建议附带推理依据
调试优化理解模型错误的原因发现模型过度依赖某个无关特征
安全审计验证模型没有学到有害模式检测模型是否对特定群体有偏差

可解释性分类体系

全局解释回答"这个模型整体上依赖什么"，局部解释回答"这一条预测为什么是这个结果"。合规场景要的几乎总是后者——监管问的是某位申请人被拒的原因，不是模型的平均特征重要性。

维度分类说明代表方法
范围全局解释理解模型整体行为特征重要性、决策规则
局部解释解释单个预测SHAP、LIME
时机固有可解释模型本身可解释线性模型、决策树
事后解释对黑盒模型做事后解释SHAP、LIME、Grad-CAM
依赖性模型无关适用于任何模型SHAP(KernelSHAP)、LIME
模型特定利用模型内部结构TreeSHAP、Attention、梯度

可解释性与准确性之间存在权衡：越复杂的模型（如 LLM）越难解释。实践中的策略是"分层解释"——对终端用户用自然语言解释，对技术团队用特征归因，对审计员用完整的决策链。

方法选型决策路径

面对"这个预测要怎么解释"，先问三个问题：模型内部权重能不能拿到、输入是表格还是序列、解释是给人看还是给审计留证。这三个答案基本就锁定了方法。

要解释一次预测 │ ┌───────────┴───────────┐ 拿不到权重 拿得到权重 （黑盒 API） （自有模型） │ │ KernelSHAP / LIME ┌───────┴────────┐ 反事实扰动 树模型 神经网络 │ │ │ │ TreeSHAP ┌──────┴──────┐ │ （精确·最快） 表格/文本 图像 │ │ DeepSHAP Grad-CAM │ │ Integrated SmoothGrad │ │ Gradients │ └────────────────────┴────────────┬────────────┘ ▼ 归因结果 + 模型版本 + 输入快照 写入决策日志 │ ┌─────────────────────┼─────────────────────┐ ▼ ▼ ▼ 终端用户看的 分析师看的 审计员看的 自然语言理由 SHAP 图表 完整证据链
  • 可解释性的四大驱动力：合规（法规强制）、信任（用户接受度）、调试（改进模型）、安全（发现偏差）
  • 全局 vs 局部、固有 vs 事后、模型无关 vs 模型特定——三个正交的分类维度
  • LLM 的可解释性特别难——参数量巨大、行为非线性、输出空间无限

二、SHAP — SHapley Additive exPlanations

把一次预测看成一笔团队奖金，SHAP 做的是"按每个特征的实际贡献分账"，而且分完的账加起来必须正好等于这次预测偏离平均值的那部分。

Shapley 值的数学原理

SHAP 基于合作博弈论中的 Shapley 值，将每个特征视为"参与者"，计算其对预测结果的边际贡献。公式 φ_i = Σ_{S⊆N\{i}} [|S|!(|N|-|S|-1)!/|N|!] × [f(S∪{i}) − f(S)]，读法是：遍历所有不含特征 i 的特征子集 S，看"把 i 加进去后预测变了多少"，再按子集大小加权平均。

为什么这个绕圈子的定义值得算：它是唯一同时满足下面三条公理的归因方式，这三条正好对应审计场景最在意的三个问题。

公理含义缺了它会怎样
局部准确性所有特征归因之和 = 本次预测 − 基线预测解释和结论对不上账，审计追问"剩下那部分是谁贡献的"答不出
一致性特征在新模型里贡献更大，归因值不会反而变小模型迭代后归因排序乱跳，无法做版本间对比
缺失性取值缺失的特征归因必为 0没填的字段也被算成拒贷理由，客户投诉直接成立

调用面很薄，真正的工程量在采样基线（background）的选择上——基线代表"平均客户"，选错了整份归因都会系统性偏移。

import shap
explainer = shap.TreeExplainer(model, data=X_background)   # 基线=代表性样本集
sv = explainer.shap_values(X_test)

shap.force_plot(explainer.expected_value, sv[0], X_test.iloc[0])  # 单条决策依据
shap.summary_plot(sv, X_test)                                     # 全局特征重要性

SHAP 变体对比

变体适用模型时间复杂度精确性
KernelSHAP任何模型（模型无关）O(2^M) 近似近似
TreeSHAP树模型（XGBoost/RF/LightGBM）O(TLD²)精确
DeepSHAP深度神经网络O(单次前向传播)近似
PartitionSHAP文本/图像数据O(特征组数)近似

文本数据不能按单 token 拆——token 之间高度相关，逐个遮蔽会得到毫无意义的归因。PartitionSHAP 的做法是按层级把相邻 token 聚成块再遮蔽，代价是归因粒度变粗（落在短语而非字上），换来的是可接受的计算量。

explainer = shap.Explainer(sentiment_model, masker=shap.maskers.Text(tokenizer))
sv = explainer(["这家餐厅的食物非常美味，服务也很周到"])
shap.text_plot(sv)   # "美味" +0.32 / "周到" +0.28 / "非常" +0.15；红=正向 蓝=负向

示例场景：某消费金融团队用 XGBoost 做预授信额度，风控要求每笔拒绝都要给出前三大原因。最初用 KernelSHAP，单条解释 4.2 秒，日均 30 万次调用下解释服务成了整条链路的瓶颈，P99 延迟从 180ms 涨到 4.5s。问题在于 KernelSHAP 把树模型当黑盒采样。改用 TreeSHAP 后利用树结构精确计算，单条降到 6 毫秒，同时归因由近似变精确；再把 background 从全量训练集换成 200 条 K-means 聚类中心，内存占用从 3.1GB 降到 40MB。最终解释接口 P99 稳定在 11ms，拒绝理由随决策同步落库。

  • SHAP 的理论优势：唯一同时满足局部准确性、一致性、缺失性三个公理的归因方法
  • TreeSHAP 是实践中最常用的——精确且高效，但限于树模型
  • 对 LLM 的局限：输入是高维 token 序列，计算完整 Shapley 值不可行，通常用 PartitionSHAP 近似

三、LIME — Local Interpretable Model-agnostic Explanations

再复杂的决策边界，放到一个样本的极小邻域里看都近似是一条直线——LIME 就是在那一小块地方拟合这条直线，然后用直线的斜率当解释。

LIME 核心思想

在预测点附近生成扰动样本（随机开关部分特征或遮蔽部分词），用原模型给这些样本打分，再按"离原样本多近"加权拟合一个线性模型；线性模型的系数就是特征重要性。它完全不看模型内部，因此对黑盒 API 也适用。

原样本 x "食物美味，但服务态度很差" │ ▼ ① 邻域扰动（随机遮蔽词/特征） ┌──────────────────────────────────┐ │ x₁ "食物美味，但____很差" │ │ x₂ "____，但服务态度很差" │ │ x₃ "食物美味，但服务态度____" │ │ ... 共 N=5000 条 │ └──────────────────────────────────┘ │ ▼ ② 原模型逐条打分（黑盒即可，只要能调 predict） y₁=0.61 y₂=0.12 y₃=0.88 ... │ ▼ ③ 按与 x 的距离加权（近的样本权重大） w = exp(−d(x,xᵢ)² / σ²) │ ▼ ④ 加权线性回归拟合局部代理模型 g(z) = β₀ + β₁z₁ + ... + βₘzₘ │ ▼ ⑤ 取 |β| 最大的 top-k 作为解释 "很差" −0.38 │ "美味" +0.25 │ "服务态度" −0.12 ⚠ N 和 σ 都是超参：改一次，解释就可能换一副样子
explainer = LimeTextExplainer(class_names=["负面", "正面"])
exp = explainer.explain_instance(
    "这家餐厅的食物非常美味，但服务态度很差",
    classifier.predict_proba, num_features=10, num_samples=5000)
exp.show_in_notebook()   # "很差" -0.38 / "美味" +0.25 / "服务态度" -0.12

把 num_samples 从 5000 降到 500 通常能让解释快 10 倍，但同一个样本连跑三次可能给出三份不同的 top-3。合规场景里这是硬伤：客户两次查询同一笔拒绝，看到的理由不一致。

SHAP vs LIME 对比

维度SHAPLIME
理论基础Shapley 值（博弈论，有公理保证）局部线性近似（无理论最优保证）
一致性满足（相同模型相同解释）不保证（随机采样导致结果波动）
计算效率TreeSHAP 快，KernelSHAP 慢中等（取决于采样数）
全局解释支持（聚合局部 SHAP）不直接支持
适用性表格、文本、图像表格、文本、图像
稳定性高（确定性计算）低（采样随机性）
  • LIME 的优势是直觉简单——"在局部用简单模型解释复杂模型"
  • LIME 的最大弱点是不稳定性——多次运行可能得到不同解释
  • 实践选择：有树模型用 TreeSHAP（精确+快），其他模型优先 KernelSHAP（有理论保证），LIME 作为快速探索工具

四、Integrated Gradients 与梯度方法

只看当前点的梯度等于只问"再多一点会怎样"，而模型早就饱和了、答案是"没什么变化"；Integrated Gradients 改问"从空白一路加到现在，这个特征一共贡献了多少"。

Integrated Gradients 原理

公式 IG_i(x) = (x_i − x'_i) × ∫₀¹ ∂F(x' + α(x−x'))/∂x_i dα，其中 x' 是基线输入。实现上就是把基线到输入的直线切成 n_steps 段，每段求一次梯度再取平均——所以成本约等于 n_steps 次前向+反向，n_steps=50 是常用起点。

ig = IntegratedGradients(model)
baseline = torch.zeros_like(input_ids)          # 文本常用 [PAD] embedding
attr = ig.attribute(input_ids, baselines=baseline, target=1, n_steps=50)
# "精彩" 0.45 / "非常" 0.22 / "电影" 0.08

基线不是随便选的。IG 的语义是"相对基线的增量贡献"，基线代表"什么都没有的状态"。图像用全黑会让黑色物体的归因塌成 0，此时改用模糊图或高斯噪声基线更稳；文本用全零 embedding 在有些模型里落在一个语义奇怪的点上，用 [PAD] 或 [MASK] 的 embedding 更可靠。工程上常做的是多基线取平均，牺牲一倍算力换掉基线敏感性。

梯度方法家族

方法原理优点缺点
Vanilla Gradient∂y/∂x，直接计算输出对输入的梯度最快梯度噪声大、饱和问题
Gradient × Input梯度 × 输入值简单改进仍有噪声
Integrated Gradients路径积分梯度有公理保证、稳定需要选择基线
SmoothGrad多次加噪声求梯度平均视觉上更清晰计算量大
Grad-CAM用最后一层卷积的梯度加权CNN 可视化标准仅限 CNN

Captum 工具库与层级归因

Captum 是 PyTorch 生态的标准归因库。除了对输入做归因，它还能对中间层做归因——LayerConductance 把 IG 的思路搬到某一层的神经元上，回答"这一层的哪些单元在为最终判断出力"。

lc = LayerConductance(model, model.transformer.layer[11])
layer_attr = lc.attribute(input_ids, baselines=baseline, target=1)
# 逐层扫一遍后典型结论：第 8-10 层贡献最大 → 情感语义主要在这几层成形
归因层次回答什么问题典型用途
输入归因（IG / DeepSHAP）哪个 token、哪个字段推动了这次判断对外出解释、写决策日志
层归因（LayerConductance）信息在第几层成形，哪层贡献最大决定剪枝/蒸馏保留哪些层
神经元归因（NeuronConductance）某个具体单元编码了什么概念排查模型是否学到敏感属性代理特征
  • Integrated Gradients 是唯一同时满足"敏感性"和"实现不变性"公理的梯度方法
  • 基线选择很关键——文本用全零/padding embedding，图像用全黑/全灰
  • Captum 是 PyTorch 生态的标准可解释性工具——支持 IG、Layer Conductance 等多种方法

五、Attention 可视化

注意力告诉你模型"往哪儿看了"，但看了不等于据此决策——它是探索工具，不是能拿去应付审计的证据。

Attention 权重的可解释性争议

观点论据代表论文
Attention ≈ 解释高注意力权重表示模型"关注"该 token早期 Transformer 工作
Attention ≠ 解释注意力权重和梯度归因不一致，随机注意力也能保持性能Jain & Wallace, 2019
条件性解释某些 head 的注意力有语义含义，但不是所有Clark et al., 2019

Attention 可视化实现

拿注意力只需要加载模型时开 output_attentions=True，拿到形状 (层, batch, head, seq, seq) 的张量，再用 BertViz 的 model_view（全层全 head 全景）或 head_view（单 head 细节）渲染。

model = AutoModel.from_pretrained("bert-base-chinese", output_attentions=True)
att = model(**tokenizer("北京是中国的首都", return_tensors="pt")).attentions
model_view(att, tokens)   # 全景：哪些 head 有结构
head_view(att, tokens)    # 细节：单个 head 的注意力模式

扫一遍全景图会看到几类反复出现的模式，认识它们能避免把机械模式当成语义发现：

注意力模式视觉特征实际含义
语义关联 head特定词对之间的亮点，如"北京"↔"首都"少数确实编码了语言学关系，值得深挖
对角线 head沿主对角线的亮带只在看邻近位置，是位置信息的副产物，无解释价值
汇聚 head整列都指向 [CLS] 或句首 token"注意力沉降"，模型无处可看时的默认行为，纯噪声

Attention Rollout — 跨层追踪

单层注意力只说明"这一层里 token 之间怎么看"，但一个 12 层模型的信息早已被层层搬运。Attention Rollout 把各层矩阵连乘起来，还原从输入 token 到输出的整体信息流，关键是不能忘了残差连接——残差相当于每层都有一条"信息原地不动"的通路，忽略它会严重高估注意力的搬运量。

单层视角（不可靠） Rollout 视角（考虑残差） Layer 12 A₁₂ A_eff = Ã₁₂ · Ã₁₁ · ... · Ã₁ ↑ 只看这一层 其中 Ã = 0.5·A + 0.5·I Layer 11 A₁₁ └─ 残差恒等通路 ↑ 再按行归一化 Layer 1 A₁ ↑ ┌──────────────────────────┐ 输入 token │ 输入 token → 输出的 │ │ 有效贡献路径（可累计） │ ❌ 忽略了 11 层的搬运 └──────────────────────────┘ ❌ 忽略了残差旁路 ✅ 端到端可读的注意力流
rollout = torch.eye(n)
for A in [a.mean(dim=1) for a in attentions]:      # 先按 head 取均值
    A = 0.5 * A + 0.5 * torch.eye(n)               # 关键：并入残差恒等映射
    A = A / A.sum(dim=-1, keepdim=True)            # 行归一化
    rollout = A @ rollout                          # 逐层滚动连乘
  • Attention 权重作为解释有争议——不能简单地说"模型看了哪里就是靠哪里做决策"
  • Attention Rollout 比单层 Attention 更可靠——它考虑了跨层的信息流和残差连接
  • 实践中推荐组合使用：Attention 用于探索性分析，SHAP/IG 用于严格的特征归因

六、LLM 推理链解释

LLM 写出来的推理步骤是一份"供人阅读的说明"，不是它内部的计算记录——它足够拿去解释给用户，但不足以证明模型真的这么想。

LLM 可解释性的独特挑战

挑战说明现有方案
规模数十亿参数，无法逐个分析探针（Probing）、稀疏自编码器
输出空间输出是自由文本而非类别Chain-of-Thought、自我解释
涌现行为大模型出现小模型没有的能力机制解释性（Mechanistic Interpretability）
黑盒 API商用模型无法访问内部权重输入扰动、对比解释

Chain-of-Thought 作为解释

让模型先分步推理再给结论（"Q3 收入 0.9 亿比 Q2 的 1.2 亿下降 25% → 连续下降是负面信号 → 但缺季节性与利润率数据 → 结论：不建议，需补充维度"），这份链条对用户是最容易读懂的解释形式。但它的忠实性——即推理链是否真的对应模型内部的计算路径——是无法验证的。

判断一份 CoT 能拿来干什么，可以看它在三个用途上的成色：

用途CoT 够不够用原因
给用户解释"为什么是这个结果"够，且目前最好自然语言比 SHAP 数值可读性高一个量级
发现明显的逻辑错误基本够算错百分比、前提自相矛盾这类问题会暴露在链条上
作为"模型确实这么推理"的证据不够模型可能先出结论再补理由，链条是事后合理化

因此工程上的定位是：CoT 与结论一起落库供追溯，但不把它当作模型行为的技术证据；后者仍要靠归因方法和扰动测试。

反事实解释（Counterfactual Explanations）

反事实解释回答的是"要改什么，结果才会不一样"，形式上比归因更贴近人的直觉，也更贴近合规要求的"可操作建议"——告诉客户"负债率降到 55% 以下即可通过"，远比告诉他"debt_ratio 的 SHAP 值是 −0.31"有用。做法是搜索能翻转预测的最小输入改动。

# 核心就是这个搜索：找编辑距离最小的翻转点
for i, tok in enumerate(tokens):
    for alt in alternatives(tok):
        cand = tokens[:i] + [alt] + tokens[i+1:]
        if model.predict(detokenize(cand)) != prediction:
            yield {"pos": i, "from": tok, "to": alt, "dist": 1}
# "食物非常[美味]"→正面；改成"[难吃]"→负面 ⇒ "美味"是本次判断的关键词
反事实的约束为什么必须加实现要点
可行性"把年龄改成 25 岁就能通过"不是客户能执行的建议把不可变特征标为冻结，不参与搜索
稀疏性同时改 8 个特征的建议无法执行限制编辑距离，优先返回单特征改动
数据分布内翻转点若落在训练分布外，模型在那里的预测本身不可信用密度估计过滤离群反事实
算力上限朴素搜索是 特征数 × 候选值 次推理，长文本直接爆先用归因排序，只搜 top-k 特征
  • CoT 是最实用的 LLM 解释方式，但要意识到其局限——可能是"事后合理化"而非真实推理过程
  • 反事实解释对用户最直观："如果X不同，结果会是Y"——但计算成本高
  • LLM 的"真正可解释性"仍是开放问题——机制解释性（Mechanistic Interpretability）是前沿方向

七、可解释性与性能权衡

不要追求"一份解释满足所有人"——客户要的是能照着做的理由，分析师要的是能对比的数值，审计要的是能复现的证据链，三者的粒度天然不同。

实践策略 — 分层解释

核心原则：同一次决策产出四份粒度不同的解释，共享同一个模型版本号与输入快照，从而互相印证。用户看到的理由必须能在审计层的证据链里找到对应的归因数值，否则一旦客户投诉，就会出现"客服说的原因"和"日志里的原因"不一致的尴尬局面。

示例场景：某银行信用卡审批模型上线后收到监管问询，要求对近 6 个月 1.4 万笔拒绝逐笔说明理由。团队当时只存了最终评分和"综合评估未通过"的模板话术，归因是查询时实时重算的——但模型已迭代过两个版本，特征工程也改过，重算结果与当初决策口径不一致的比例达到 23%。整改方案是把解释从"查询时计算"改为"决策时固化"：决策事务里同步写入模型版本、特征快照、TreeSHAP 前五项归因与命中阈值，存储成本增加约每笔 1.8KB、日均 340MB。此后逐笔理由的可复现率为 100%，同类问询的响应时间从两周降到按需导出。

  • 可解释性和性能的权衡是核心设计决策——不是越可解释越好
  • 分层解释策略：不同受众需要不同粒度和形式的解释
  • 高风险场景（医疗、金融、法律）可解释性优先级高于性能

Q&A

SHAP 和 LIME 的核心区别是什么？各自的优缺点？

核心区别在理论基础：SHAP 基于合作博弈论的 Shapley 值，是唯一同时满足局部准确性、一致性、缺失性三个公理的归因方法，保证了理论上的最优性和唯一性；LIME 基于"局部线性近似"，在预测点附近用简单模型拟合，没有理论最优保证。SHAP 优点：结果稳定（确定性计算）、有全局解释能力（聚合局部值）、理论保证强；缺点：KernelSHAP 计算慢（指数级复杂度），TreeSHAP 限于树模型。LIME 优点：实现简单、直觉清晰、模型无关；缺点：结果不稳定（依赖随机采样）、超参数敏感（采样数、邻域大小）、不支持全局解释。实践建议：树模型用 TreeSHAP，深度模型用 DeepSHAP 或 IG，快速探索用 LIME。

Attention 权重能否作为模型解释的依据？

这是一个有争议的问题：①反对方（Jain & Wallace, 2019）指出注意力权重与梯度归因不一致，且随机替换注意力权重不显著影响性能，说明注意力权重不可靠地反映特征重要性；②支持方认为某些 attention head 确实捕获了有意义的语言学模式（如语法依赖、共指消解）；③折中观点：Attention 可以作为探索性分析工具，但不能作为严格的因果解释。最佳实践：使用 Attention Rollout（跨层追踪注意力流，考虑残差连接）比单层 attention 更可靠；将 Attention 与 Integrated Gradients 等梯度方法结合使用；在需要合规级解释的场景中，不依赖 Attention 作为唯一证据。

Integrated Gradients 的原理和优势是什么？

Integrated Gradients（IG）的核心思想是：从一个"基线输入"（如全零向量）到实际输入，沿直线路径积分梯度，得到每个特征的贡献度。公式：IG_i(x) = (x_i - x'_i) × ∫₀¹ ∂F(x'+α(x-x'))/∂x_i dα。直觉理解：不是看"当前点的梯度"（瞬时变化率），而是看"从无到有的整个变化过程"。优势：①满足两个关键公理——敏感性（如果某特征改变导致预测变化，其归因值非零）和实现不变性（功能相同的模型给出相同归因）；②唯一满足这两个公理的梯度方法（Vanilla Gradient 不满足敏感性，因为梯度可能为零）；③计算高效——只需要前向和反向传播，不需要采样。局限：需要选择合适的基线，且基线的选择会影响结果。

LLM 的 Chain-of-Thought 是否等于真正的可解释性？

CoT 不等于真正的可解释性，但它是当前最实用的 LLM 解释方式。原因分析：①CoT 可能是"事后合理化"——模型先得出结论，再生成看似合理的推理步骤（类似人类的认知偏差），研究表明 CoT 步骤和模型内部计算过程并不完全一致；②CoT 可能"编造推理"——模型生成的推理链可能包含看似合理但实际错误的逻辑步骤（幻觉延伸到推理过程）；③CoT 的忠实性无法验证——我们无法确定 CoT 步骤真正反映了模型的"思考过程"。但 CoT 的实际价值：①对用户最直观——自然语言解释比 SHAP 数值更易理解；②可发现逻辑错误——即使 CoT 不完全忠实，暴露的推理链也有助于发现明显的逻辑缺陷；③可审计——CoT 提供了可记录、可检查的"决策依据"。正确做法：将 CoT 视为"用户可理解的解释"而非"真实的模型内部机制"。

如何在高风险场景中平衡可解释性和模型性能？

三种策略：①分层解释——用高性能黑盒模型做预测，用可解释方法提供事后解释。例如用 GPT-4 做信贷评估，同时用 SHAP 提供特征重要性解释，用 CoT 提供自然语言解释；②可解释代理——训练一个简单的可解释模型（如决策树）模拟黑盒模型的行为，当两者一致时用黑盒结果+简单模型解释，不一致时触发人工审核；③混合架构——关键决策因素用可解释模型（逻辑回归/决策树），辅助分析用复杂模型。例如信贷审批：基础规则（负债率、收入比）用可解释模型决定"通过/拒绝"边界，模型只在边界附近的"灰区"发挥作用。合规建议：EU AI Act 要求高风险 AI 决策"可以向受影响者解释"——不是要求模型内部完全透明，而是要求能给出有意义的、可理解的解释。

解释应该在决策时固化还是在被问到时重算？为什么？

应该在决策时固化，理由是可复现性。归因结果依赖三样东西：模型权重、特征工程逻辑、基线样本集。这三样任何一样在事后发生变更，重算得到的解释就不再是当初那次决策的依据。模型迭代通常以周为单位，而监管问询、客户投诉、诉讼取证往往发生在几个月甚至一两年之后，届时几乎不可能还原当时的完整环境。固化的具体做法是把解释纳入决策事务：写入模型版本号、输入特征快照、归因值 top-k、命中的阈值、以及对外展示的理由文本，与决策结果同生共死。代价是存储——按每笔一两 KB 估算，日均百万次决策约增加 1-2GB/天，可以按留存期做冷热分层。反过来，"查询时重算"唯一的好处是省存储，但它把一个确定性的合规义务变成了赌运气，通常不划算。

怎么验证一份特征归因本身是可信的，而不是看起来合理？

归因方法自己不会报错，输出的数值总是"看起来像那么回事"，所以需要独立的验证手段。最常用的是删除测试（deletion test）：按归因值从高到低依次遮蔽特征，记录预测置信度的下降曲线。如果归因可信，遮蔽 top-k 应该让预测迅速崩塌；如果曲线平缓，说明归因排序没抓住真正起作用的特征。对应的是插入测试（insertion test）——从空白输入开始按归因顺序逐个加回特征，看预测多快恢复。第二类手段是随机化对照：把模型权重随机重置后重跑同一套归因，如果输出的热力图和原来长得差不多，说明这个方法主要在反映输入的表面结构而非模型行为，属于典型的失效信号。第三类是一致性交叉验证：用两种独立方法（如 TreeSHAP 与 Integrated Gradients）对同一批样本归因，统计 top-3 特征的重合率，重合率长期低于某个水位就要怀疑其中一方的配置有问题（最常见的是基线选错）。这些测试成本不高，适合作为模型上线前的固定关卡跑一遍并留档。
