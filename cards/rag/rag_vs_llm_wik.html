RAG 是"边查边答"——推理时实时检索外部知识库，知识可以随时更新。参数化知识 是"提前学进脑子"——预训练时把知识压缩进模型参数，更新需要重新训练。选哪个取决于三个问题：知识更新频率高吗？需要溯源吗？对延迟敏感吗？

一、技术原理深度对比

1.1 RAG — 推理时实时检索

RAG 的核心思想：让 LLM 不需要"记住"所有知识，而是在需要时"查阅"知识。知识存储在外部，模型只负责理解和生成。

原理：RAG（Retrieval-Augmented Generation，检索增强生成）在推理时将用户 query 向量化后检索外部知识库（通常是向量数据库），将检索到的 Top-K 文档拼接到 prompt 中作为上下文，LLM 基于这些上下文生成回答。模型本身不需要"知道"这些知识——它只需要理解上下文并组织语言。

机制：Query → Embedding → 向量库 ANN 检索 → Top-K 文档 → 拼接到 Prompt（System + Context + Query） → LLM 生成回答 → 附带来源引用。整个检索过程增加约 200-500ms 延迟。

效果：知识更新只需修改向量库中的文档（秒级~小时级），不需要重新训练模型。每个回答可以追溯到具体的来源文档，可解释性高。幻觉率低——LLM 被 prompt 中的上下文"约束"，不容易编造。

1.2 参数化知识 — 预训练时学入

原理：参数化知识（Parametric Knowledge，即预训练阶段压缩进模型参数的知识）是通过预训练阶段将海量文本数据（通常数万亿 token）"压缩"进模型参数中。推理时模型通过注意力机制从参数中"回忆"相关知识，不需要外部检索。知识以分布式方式存储在数十亿参数中——没有任何一个参数单独存储一条知识。

机制：预训练（TB 级文本 → 梯度下降 → 参数更新） → 推理时 Query → 模型直接从参数中提取相关知识 → 生成回答。没有外部检索步骤，推理延迟最低。

效果：推理速度最快（无检索开销），但知识更新需要重新训练或微调模型（天级~周级，成本极高）。无法追溯知识来源（黑盒回忆），幻觉风险较高——模型可能在记忆模糊时"编造"看起来合理但实际错误的内容。

把两者的差异归到一句话：RAG 把知识放在参数外部，改一份文档就等于改一次"记忆"；参数化知识 把知识压进参数内部，任何一条知识的修正都要经过梯度下降。这条分界线决定了后面所有的成本、延迟与可溯源性差异。

核心结论：RAG 和 参数化知识 不是互斥的选择，而是互补的能力。RAG 擅长"精准、可更新、可溯源"的知识获取；参数化知识 擅长"通用常识、逻辑推理、语言理解"。实际生产中，最佳方案是组合使用——LLM 先用自身知识理解问题和组织回答，RAG 补充专业知识和最新信息。

二、适用场景与选型决策树

选型核心问题：知识更新频率高吗？需要溯源吗？对延迟敏感吗？三个问题中有两个回答"是"→ 用 RAG；三个都回答"否"→ 参数化知识 足够。

2.2 生产案例

生产案例：某医疗 AI 系统最初纯靠 参数化知识 回答患者问题，幻觉率达 12%（每 100 个回答中有 12 个包含错误医学信息）。引入 RAG 检索最新临床指南后，幻觉率降至 1.5%（-87.5%），同时 95% 的回答可以追溯到具体的指南文档。但通用问题（如"什么是感冒？"）仍由 参数化知识 回答，避免不必要的检索延迟。

三、RAG + 参数化知识 组合使用策略

组合使用的核心挑战不是"怎么用两种"，而是"当两者矛盾时信谁"。知识冲突处理策略的选择直接影响系统的可信度。

3.3 冲突检测机制

使用 NLI（Natural Language Inference）模型检测 RAG 检索文档与 LLM 生成回答之间的关系。NLI 将文本对分为三类：蕴含（entailment，RAG 文档支持 LLM 回答）→ 一致，可放心输出；矛盾（contradiction，RAG 文档与 LLM 回答冲突）→ 触发冲突处理策略；中性（neutral，两者无关）→ LLM 回答可能基于自身知识，需要额外验证。

生产建议：在医疗/法律/金融等高风险场景中，检测到矛盾时应强制以 RAG 为准（RAG 优先策略），并在回答中明确标注来源文档。在通用场景中，可以使用融合输出并标注"存在不同观点"。NLI 检测的额外延迟约 10-20ms（使用 DeBERTa-v3 小模型），对用户体验影响可忽略。

四、成本与性能全面对比

选型不能只看技术优劣，还要看成本结构。RAG 的运营成本主要在检索（Embedding API + 向量库），参数化知识 的成本主要在训练（GPU 集群）。两者成本模型完全不同。

Q&A

为什么 RAG 的可解释性比 参数化知识 高？这在什么场景下是决定性因素？
RAG 的每个回答都可以追溯到具体的检索文档（"这个回答来自 XX 文档第 3 段"），用户可以点击链接验证来源。参数化知识 的知识存储在数十亿参数中，无法指出"这个知识来自哪篇训练数据"，是一个黑盒。在医疗、法律、金融等需要"有据可依"的场景，可解释性是硬需求——医生需要知道用药建议来自哪个临床指南，律师需要知道法律意见引用了哪个法条。这些场景下，RAG 几乎是唯一选择。
RAG 的 200-500ms 延迟在实际体验中影响大吗？有什么优化手段？
取决于场景。对话式应用中，500ms 的额外延迟用户几乎感知不到（总响应时间 2-3 秒中的一部分）。但在实时交互场景（如语音助手、交易决策）中，每一毫秒都很关键。优化手段包括：① 向量库预加载热点文档的向量到内存（-30% 检索延迟）；② 检索结果缓存（相同 query 直接返回缓存，命中率可达 20-30%）；③ 并行执行检索和流式生成（边检索边生成，-200ms 端到端延迟）；④ 使用更快的 ANN 算法（如 HNSW 替代 IVF）。
参数化知识 的幻觉问题有办法缓解吗？能否降到和 RAG 同等水平？
有三种主要缓解方法：① RLHF（人类反馈强化学习），通过人类标注减少幻觉输出，可降低幻觉率约 30-40%；② Chain-of-Thought，让模型展示推理过程，暴露幻觉环节，可检测出约 50% 的幻觉；③ Self-Consistency，多次采样取一致答案，不一致时标记为"不确定"。但这些方法只能降低幻觉率（从 10-15% 降到 5-8%），不能根除。对于零容错场景，RAG 仍是更可靠的选择（幻觉率可降到 2-5%）。
什么时候应该选择"RAG 优先"而非"LLM 优先"？有量化的判断标准吗？
一个简单的判断规则：如果回答需要引用来源 → RAG 优先；如果回答靠推理 → LLM 优先。量化标准可以用 RAG 检索的最高相似度分数作为信号：Top-1 相似度 > 0.80 → RAG 优先（检索到高质量文档）；Top-1 相似度 < 0.60 → LLM 优先（检索质量低，不如用 LLM 自身知识）；0.60-0.80 之间 → 融合输出（两者互补）。这个阈值需要根据业务场景调优——高风险场景的"RAG 优先"阈值可以降低到 0.70。
RAG 和 参数化知识 的知识冲突怎么检测？检测准确率够用吗？
使用 NLI（Natural Language Inference）模型检测冲突：将 RAG 检索的文档和 LLM 生成的回答分别编码，判断两者之间的关系（蕴含 / 矛盾 / 中性）。主流 NLI 模型（如 DeBERTa-v3-large 在 MNLI 上微调）的三分类准确率在 88-92% 之间。对于 RAG 场景，主要判断"生成内容是否与 context 矛盾"这个二分类任务更简单，实际准确率可达 90-95%。对于要求更高的场景，可以用 LLM-as-Judge 替代 NLI（准确率 95%+），但每次调用成本增加 5-10 倍。
如果模型通过微调（fine-tuning）更新知识，算 RAG 还是 参数化知识？
微调属于 参数化知识 的范畴——知识被编码进模型参数中。但微调的知识更新成本远低于全量预训练：全参数微调需要数百 GPU 小时，LoRA 微调仅需数十 GPU 小时。微调适合"教模型新知识模式"而非"注入大量事实知识"——研究表明，微调后模型对注入知识的回忆准确率仅 60-70%，远低于 RAG 的 90%+。因此，大量事实性知识更新仍推荐 RAG，微调更适合教模型"如何回答"而非"回答什么"。
