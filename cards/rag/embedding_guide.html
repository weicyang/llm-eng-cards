Text Embedding Guide — 从词向量到句向量的完整指南

一、词向量的历史演进

从 One-Hot 到分布式表示

方法年份原理局限
One-Hot-每个词一个独热向量维度爆炸、无语义信息
Word2Vec2013CBOW/Skip-gram，预测上下文静态向量、一词一义
GloVe2014全局共现矩阵分解静态向量、一词一义
FastText2016子词 n-gram，处理 OOV仍是静态表示
ELMo2018BiLSTM 上下文表示计算开销大
BERT2018Transformer，动态上下文 embedding不适合直接做句向量

这条演进线的主轴是从"符号"到"语义"：One-Hot 只是词的编号，维度爆炸且任意两词距离相同，毫无语义信息；分布式表示用低维连续向量承载语义，让"相近的词在空间中靠近"。Word2Vec 证明了这种表示可以从海量语料中自动学出来，BERT 则进一步让向量随上下文动态变化，"bank"在河岸与银行两种语境下终于有了不同的向量。

Word2Vec 核心思想

Word2Vec 的本质是用预测任务训练词向量：CBOW 用上下文预测中心词，Skip-gram 反过来用中心词预测上下文。以 "The cat sat on the mat" 为例，取中心词 "sat"，训练目标是最大化它生成邻近词（"cat"、"on"）的概率 P(context | center_word) = softmax(W_context · W_center)。预测行为"副产品"的词向量，自然编码了词的分布语义。

直接对全词表做 softmax 代价太高，Negative Sampling 将其转化为二分类：只对正样本 + K 个负样本计算损失 loss = -log(σ(v_pos · v_center)) - Σ log(σ(-v_neg · v_center))，训练成本大幅下降。

概念说明
Skip-gram中心词 → 预测上下文词，低频词效果更好
CBOW上下文 → 预测中心词，训练更快
训练目标最大化 P(context | center_word)，softmax 输出
Negative Sampling免算全词表 softmax，只对正样本 + K 个负样本计损失

Word2Vec 的革命性发现：向量算术捕获语义关系。king - man + woman ≈ queen

分布式表示的全部秘密是"看邻居"：一个词的含义不写在它自己身上，而写在它周围经常出现的那些词里，所以只要让模型反复做"根据上下文猜词"这道题，词向量就是解题时被迫学出来的副产品。

  • Word2Vec vs GloVe：Word2Vec 基于局部上下文窗口（predictive），GloVe 基于全局共现矩阵（count-based），效果相近
  • 静态词向量的根本问题："bank"在"river bank"和"bank account"中得到相同向量
  • 为什么 BERT 的 [CLS] token 不能直接做句向量？— 未经对比学习训练，各向异性严重

SBERT 架构

Sentence-BERT 采用孪生网络（Siamese Network）结构：两个句子分别通过权重共享的 BERT 编码器，各自做 mean pooling 得到定长句向量；训练时用对比学习——相似句对拉近、不相似句对推远。推理时两句话的相似度只需一次向量点积，彻底摆脱 cross-encoder 的 O(n²) 开销，这也是句向量能支撑大规模检索的前提。

调用只需两行：用 SentenceTransformer 加载模型，encode 一批句子即得向量。

from sentence_transformers import SentenceTransformer
model = SentenceTransformer('all-MiniLM-L6-v2')
embeddings = model.encode(["RAG 是什么？", "检索增强生成的定义"])
# cosine_similarity(embeddings[0], embeddings[1]) ≈ 0.85

E5 / BGE 的 Instruction-Following

检索场景中 query 与 passage 的语义角色不对等（一短一长、一问一答），E5 与 BGE 的做法是给文本加指令前缀，让模型明确知道当前编码的是"待检索的短查询"还是"候选文档"，这是 Instruction-Following Embedding 的核心设计。E5 使用固定的 "query: " / "passage: " 前缀；BGE 支持可自定义的中文 instruction（如"为这个句子生成表示以用于检索相关文章："），调用时查询侧走 encode_queries()、文档侧走 encode()。

模型前缀约定关键 API
E5查询加 query:，文档加 passage:encode 前自行拼接前缀
BGEquery_instruction_for_retrieval 自定义指令FlagModel 的 encode_queries() / encode()
from FlagEmbedding import FlagModel
model = FlagModel('BAAI/bge-large-zh-v1.5',
                  query_instruction_for_retrieval="为这个句子生成表示以用于检索相关文章：")
q_emb = model.encode_queries(["什么是RAG？"])
p_emb = model.encode(["RAG是检索增强生成..."])

句向量能撑起大规模检索，靠的不是精度更高，而是"把两句话的比较拆成了各自独立的编码"——只要编码不依赖对方，全库的向量就能提前算好存起来，检索时只剩一次点积。

  • MTEB (Massive Text Embedding Benchmark) 是评估 embedding 模型的标准基准
  • 选模型看场景：中文用 BGE/GTE，英文用 E5/Cohere，多语言用 multilingual-e5
  • 维度越高不一定越好：512-1024 维是主流，过高维度增加存储和检索成本

三、对比学习训练方法

核心思想

对比学习（Contrastive Learning）：通过拉近正样本对（语义相似）、推远负样本对（语义不同）来学习有效表示。

句向量训练为什么离不开对比学习？直接拿 BERT 的 [CLS] 向量算相似度会遭遇严重的各向异性——所有句子挤在向量空间的一角，区分度极差。对比学习在正负样本对上反复"拉近-推远"，等于强行把向量空间撑开，让每个句子都占据有判别力的方向。因此可以说，现代句向量模型 = 预训练编码器 + 对比学习校准。

对比学习的一个训练 step：向量空间是被"拉近"和"推远"硬撑开的 训练批次 batch_size = 256 (q₁, p₁) (q₂, p₂) 每行一个 query 与它配对的正样本 passage ... (q₂₅₆, p₂₅₆) │ 共享编码器分别编码 query 侧与 passage 侧 ▼ Q 矩阵 [256, d] P 矩阵 [256, d] └───── 相似度矩阵 S ＝ Q · Pᵀ ─────► [256, 256] │ ▼ 对角线 S[i][i] ＝ 正样本对 ──► 拉近（进分子） 非对角 S[i][j] ＝ In-batch Negatives ──► 推远（进分母） 每个 query 白拿 255 个负样本，不额外标注 │ ▼ 除以温度 τ（取 0.05~0.1）后按行做交叉熵 InfoNCE ＝ -log( exp(S[i][i]/τ) ／ Σⱼ exp(S[i][j]/τ) ) │ ▼ 梯度更新：正样本方向靠拢，负样本方向散开 ──► 原本挤在一角的向量被撑开，各向异性缓解 可选注入 Hard Negatives（BM25 召回尾部 / 模型自身排名 10~30 / Cross-Encoder 筛例） ──► 拼进 P 矩阵，把"表面很像、语义不同"的方向也一并推开

关键损失函数

损失函数公式思想应用
InfoNCE从 N 个负样本中识别正样本（softmax形式）SimCLR, CLIP, 句向量

InfoNCE Loss 详解

InfoNCE（Noise Contrastive Estimation）把对比学习建模为一道"N 选 1"的识别题：给定 query q、一个正样本 k+ 和 N 个负样本，损失为 L = -log(exp(sim(q, k+)/τ) / Σ exp(sim(q, kᵢ)/τ))，本质是 N 分类交叉熵——让正样本在所有候选中相似度占比最大。它配合 In-batch Negatives 使用：batch 内其他样本的正样本直接充当负样本，batch_size=256 时每个 query 免费获得 255 个负样本。

要素说明
损失公式L = -log(exp(sim(q, k+)/τ) / Σ exp(sim(q, kᵢ)/τ))，N 选 1 的 softmax 交叉熵
温度 τ控制分布锐利程度：τ 小 → 更尖锐，对困难负样本更敏感；τ 大 → 更平滑，训练更稳定；实践取 0.05~0.1
In-batch Negativesbatch 中其他样本的正样本即负样本；batch_size=256 → 255 个免费负样本

Hard Negative Mining

困难负样本（Hard Negative）指与 query 表面高度相似、语义却不同的样本——比随机负样本更有信息量，能逼着模型学会细粒度语义区分。挖掘的核心思路是"找那些最容易混淆的错答案"：既不能太容易（无训练信号），也不能是假负样本（实为正样本），通常从检索结果的排名中段取样。

挖掘策略做法要点
BM25 挖掘关键词检索召回后取排名靠后的结果关键词匹配但语义不同，廉价易得
模型自身挖掘用当前模型检索，取排名 10~30 区间的"错误"结果针对模型当前弱点，随训练迭代更新
Cross-Encoder 标注用 Cross-Encoder 给候选打分，取分数中等的样本过滤假负样本，保留"似是而非"的难例
  • In-batch Negatives 是最重要的技巧：batch 越大负样本越多，效果越好（需要大 batch / gradient accumulation）
  • Temperature τ 通常取 0.05~0.1，太小训练不稳定，太大区分度不够
  • Hard Negatives 对效果提升巨大（+5~10% 性能），但挖掘成本高
  • 训练数据金字塔：弱监督大量数据预训练 → 高质量标注数据 fine-tune

对比学习真正在做的是"造对比度"：In-batch Negatives 负责把所有方向粗粗推开，Hard Negative 负责在最容易混淆的那几度夹角上补刀，缺了后者模型只学会区分"猫和汽车"，学不会区分"退款政策和换货政策"。

延伸阅读：对比学习若负样本不足或损失设计不当，反而会令向量空间失去区分能力（训练坍塌）——Loss 在降但 Recall 暴跌。坍塌的三种形态、有效秩监控与工业级防御方案见 G27 · Embedding 向量坍塌解析。

四、向量相似度度量

三种主要距离度量

度量公式范围特点适用场景
Cosine Similaritycos(θ) = (A·B)/(||A||·||B||)[-1, 1]方向相似度，忽略长度最常用，归一化后的向量
Dot ProductA·B = Σ(a_i × b_i)(-∞, +∞)考虑方向+大小向量已归一化时等价于 cosine
Euclidean (L2)||A-B||₂ = √Σ(a_i-b_i)²[0, +∞)空间距离聚类、KNN
一对向量，三种度量各自在量什么 ▲ │ B ── 模长 2.0（未归一化） │ ╱ │ ╱ │ ╱ · B' ── B 归一化后落到单位圆上 │ ╱ ╱ │╱ ╱ θ ＝ 夹角 └──────────────────► A ── 模长 1.0 单位圆：所有 L2 归一化后的向量都落在半径 1 的圆周上 Cosine 只量夹角 θ cosθ ＝ (A·B) ／ (‖A‖·‖B‖) 范围 [-1, 1] Dot Product 量夹角 ＋ 量模长 A·B ＝ ‖A‖·‖B‖·cosθ 范围 (-∞, +∞) Euclidean 量两点间直线距离 ‖A － B‖₂ 范围 [0, +∞) 一旦 ‖A‖ ＝ ‖B‖ ＝ 1（主流 embedding 模型的默认输出）： Dot Product ＝ Cosine Euclidean² ＝ 2 － 2 × Cosine ──► 三者给出的排序完全一致，Top-K 结果一模一样 所以"该用哪个度量"只有一个先决问题：这批向量到底归一化了没有。

选择指南

度量选择其实只有一个关键问题：模型输出的向量是否已归一化。大多数现代 embedding 模型输出 L2 范数为 1 的单位向量，此时 cosine 与 dot product 完全等价，选哪个都一样；未归一化且向量大小有语义（如 TF-IDF 权重）时用 dot product；聚类、KNN 这类需要"绝对距离"的场景用 euclidean。归一化后三者存在简洁的换算关系：cosine_sim = dot_product，euclidean² = 2 - 2×cosine_sim。

情况建议度量原因
模型输出已归一化（主流情况）cosine / dot product 均可二者数值完全等价
未归一化且向量大小有意义dot product同时考虑方向与模长
需要绝对距离概念euclidean聚类、KNN 等几何任务

不确定是否归一化时，一行 numpy 即可验证——L2 norm ≈ 1.0 即已归一化：

import numpy as np
embedding = model.encode("test")
norm = np.linalg.norm(embedding)
print(f"L2 norm: {norm}")  # ≈1.0 则已归一化

高维空间中的"维度诅咒"

在高维空间中，所有点之间的距离趋于相同（集中在均值附近），这使得区分"近"和"远"变得困难。

  • 1000维空间中随机两点的 cosine similarity 集中在 0 附近
  • 解决方法：良好的训练让有意义的向量分布在特定方向，而非均匀分布
  • Matryoshka Representation Learning: 支持截断到低维仍保持良好性能

高维空间里"距离"本身不值钱——随机两点的相似度几乎恒等于 0，能区分远近的从来不是维度，而是训练把有意义的语义压到了少数几个方向上，这也是各向异性未校准的模型算不出可用相似度的原因。

  • 常见疑问：cosine vs dot product 区别？— 归一化后完全等价；未归一化时 dot product 考虑向量长度
  • 为什么 RAG 中几乎都用 cosine？— embedding 模型通常输出归一化向量，且方向比大小更有语义意义
  • 向量数据库中实际使用 Inner Product (IP) 或 L2 作为索引度量，cosine 通过预归一化转为 IP

六、Fine-tuning Embedding 模型

为什么要 Fine-tune？

通用 embedding 模型可能对特定领域（医学、法律、代码）的术语和语义理解不够准确。通过 fine-tune 可以让模型更好地理解领域内的语义相似性。

训练数据准备

sentence_transformers 支持三种训练数据格式，分别对应不同的损失函数。最简单的是 Pair（正样本对），如 ("什么是RAG？", "RAG是检索增强生成技术...")；需要显式负样本时用 Triplet，如 ("RAG原理", "检索增强生成的工作流程", "强化学习的基本概念")；有标注相似度分数时用 Scored Pairs，如 ("RAG 是什么", "检索增强生成介绍", 0.9)。

格式结构适配损失
Pair(text_a, text_b) 正样本对MNR（batch 内互为负样本）、CosineSimilarityLoss
Triplet(anchor, positive, negative)TripletLoss（显式负样本 + margin）
Scored Pairs(text_a, text_b, score) 带相似度分数CosineSimilarityLoss（回归式拟合）

Fine-tune 流程

整个 fine-tune 流程围绕 sentence_transformers 的四个关键 API 展开：先用 SentenceTransformer 加载基座模型（如 BAAI/bge-base-zh-v1.5），再把训练样本包装为 InputExample（texts 传文本列表、label 传相似度标签）并封进 DataLoader，然后挑选损失函数——首选 MultipleNegativesRankingLoss（MNR，batch 内自动获得负样本），也可换 CosineSimilarityLoss 或 TripletLoss，最后调用 model.fit() 训练 2~5 个 epoch 并保存。注意用小学习率（1e-5~5e-5）防止灾难性遗忘。

关键 API作用
SentenceTransformer('BAAI/bge-base-zh-v1.5')加载基座模型，fine-tune 的起点
InputExample(texts=[...], label=...)训练样本的统一封装格式
losses.MultipleNegativesRankingLossMNR 损失：batch 内互为负样本，无需显式负样本标注
model.fit(train_objectives=[(loader, loss)], ...)启动训练；配 warmup 与 output_path 保存产物

最小可运行的训练骨架如下：

model = SentenceTransformer('BAAI/bge-base-zh-v1.5')
examples = [InputExample(texts=["query", "positive"], label=1.0)]
loader = DataLoader(examples, shuffle=True, batch_size=32)
loss = losses.MultipleNegativesRankingLoss(model)
model.fit(train_objectives=[(loader, loss)], epochs=3)

数据来源策略

  • 用户搜索日志：query + 点击文档 = 正样本对
  • LLM 合成：给文档让 GPT-4 生成对应问题
  • Hard negative mining：BM25 召回 + Cross-Encoder 过滤
  • 跨语言迁移：用翻译数据做多语言对齐

数据质量优先于数量：真实搜索日志优于 LLM 合成，合成优于纯人工构造；无论哪种来源，都应过一遍 Cross-Encoder 打分或人工抽检，剔除标签噪声——一条错误正样本对向量空间的破坏，远大于少一千条数据。

示例场景：一个内部工单检索系统，知识库 8 万条 chunk，用通用中文 embedding 模型上线后 Recall@5 只有 61%。排查发现失败 query 集中在业务缩写上——用户搜"退单流程"，文档里写的是"逆向订单处理规范"，二者在通用向量空间里几乎不相似。方案是从半年搜索日志里抽 6000 条"query + 被点击工单"作为正样本对，再用 BM25 召回尾部挖 3 条 hard negative/条，以 MNR Loss、lr 2e-5 训 3 个 epoch。结果 Recall@5 从 61% 升到 84%，同时在通用评估集上只掉了 1.2 个点，代价是每次知识库大改后要重跑一次 4 小时的微调 + 重建索引。

微调 embedding 不是让模型"更懂语义"，而是把你业务里那些"字面不像但其实是一回事"的说法在向量空间里强行拉到一起——所以真实搜索日志的价值远高于任何合成数据，因为只有它记录了用户真的怎么问。

  • Fine-tune 通常只需 1000-10000 对训练数据即可看到明显提升
  • MNR Loss（Multiple Negatives Ranking）是目前最流行的训练方式——batch 内互为负样本
  • 评估方式：在 hold-out set 上计算 Recall@K 和 MRR，与 baseline 对比
  • 避免灾难性遗忘：learning rate 要小（1e-5~5e-5），epoch 不要太多（2-5）

七、多语言 Embedding

多语言模型解决的是一个很具体的工程问题：同一份知识库里既有中文工单也有英文文档，用户却只用中文提问。它靠跨语言对齐把两种语言压进同一套坐标系，让"语种"这个维度在检索时彻底消失。

多语言模型对比

模型支持语言特点
multilingual-e5-large100+微软出品，跨语言检索强
BGE-M3100+多功能（Dense + Sparse + ColBERT）
Cohere multilingual-v3100+商业 API，质量最高之一
paraphrase-multilingual-MiniLM50+轻量级，适合边缘部署

多语言模型的共同底座是统一的跨语言向量空间：所有语言被映射到同一坐标系，语义相同则向量相近。这让"中文提问、英文文档命中"成为开箱即用的能力，代价是训练语料与算力需求更高，且在冷门语言对上可能弱于专用双语模型。

跨语言检索原理

多语言 embedding 把不同语言映射到同一个向量空间：语义相同的句子无论语种，向量都彼此接近（"What is RAG?" 与 "什么是RAG？" 的 cosine 相似度可达 0.9+）。由此天然支持跨语言检索——中文 query 可以直接命中英文文档，无需先翻译。注意 E5 系列编码 query 时仍需加 "query: " 前缀。

典型模型intfloat/multilingual-e5-large（100+ 语言）

BGE-M3: 多功能多语言模型

BGE-M3 的"多功能"体现在一次 encode 同时返回三种表示：dense_vecs（1024 维密集向量，语义匹配）、lexical_weights（稀疏权重，类似可学习的 BM25，负责精确词项匹配）、colbert_vecs（token 级多向量，支持细粒度 late interaction）。混合检索时将三路分数加权融合：score = w1×dense + w2×sparse + w3×colbert，兼顾语义泛化与关键词精确命中。

Q&A

为什么 BERT 的 [CLS] token 不能直接用作句向量？SBERT 如何解决这个问题？

BERT 的 [CLS] 向量问题：①BERT 预训练目标是 MLM 和 NSP，[CLS] 向量并未被训练来代表整句语义②向量空间各向异性（anisotropic）严重，所有句子的向量集中在很小的区域，cosine 相似度区分度差③如果用 BERT 计算两个句子的相似度需要将它们一起输入（cross-encoder），计算量是 O(n²)。SBERT 的解决方案：①孪生网络架构：两个句子分别独立编码（bi-encoder），计算量降为 O(n)②Mean Pooling：取所有 token 的平均值作为句向量（比 [CLS] 效果好）③对比学习训练：用 NLI 数据集（蕴含/矛盾/中立）训练，让语义相似的句子向量接近。

InfoNCE 损失是什么？Temperature 参数的作用？

InfoNCE 是对比学习中最广泛使用的损失函数。给定 query q 和一个正样本 k+，以及 N-1 个负样本，目标是让 q 与 k+ 的相似度在所有候选中最大：L = -log(exp(sim(q,k+)/τ) / Σexp(sim(q,ki)/τ))。本质是 N 分类的交叉熵。Temperature τ 的作用：①τ 越小分布越尖锐，模型对困难负样本（与 query 相似但不是正样本的）越敏感，梯度更集中②τ 越大分布越平滑，训练更稳定但区分度下降。实践中 τ=0.05~0.1 效果最好。有些框架将 τ 设为可学习参数（如 CLIP）。In-batch negatives 技巧：batch 中的其他正样本自动作为负样本，batch_size=256 就有 255 个免费负样本。

Cosine similarity、Dot product、Euclidean distance 三者的区别和适用场景？

Cosine：衡量方向相似度（角度），范围[-1,1]，忽略向量长度，最常用于文本检索因为语义方向比大小更重要。Dot product：衡量方向+大小的综合相似度，范围(-∞,+∞)，当两个向量都归一化为单位向量时 dot product = cosine。Euclidean：衡量空间距离，范围[0,+∞)，距离越小越相似，对向量大小敏感。关系：对归一化向量，三者等价（||A-B||²=2-2cos(A,B) when ||A||=||B||=1）。选择建议：①大多数 embedding 模型输出已归一化→用 cosine 或 IP 均可②向量数据库中通常用 IP 索引（cosine 通过预归一化转化）③如果向量大小有意义（如 TF-IDF 权重）→用 dot product。

如何为特定领域 Fine-tune embedding 模型？需要多少数据？

步骤：①选基座模型（如 BGE-base-zh）②准备训练数据：(query, positive_passage) 对，最好加 hard negatives③选损失函数（推荐 MNR Loss）④小 lr（1e-5~5e-5），2-5 epochs，batch_size 尽量大⑤在 hold-out set 评估 Recall@K。数据量建议：1000 对可见明显提升，5000-10000 对效果饱和。数据来源：搜索日志（query+点击）、LLM 合成（给文档生成问题）、人工标注。关键技巧：①Hard negative mining 比增加数据量更有效②不要过拟合：加 validation set 做 early stopping③评估时与通用模型对比在领域数据上的 Recall@K。风险：Fine-tune 可能降低通用能力（灾难性遗忘），需要在通用 benchmark 上也验证。

E5 / BGE 为什么要给文本加 "query:" / instruction 前缀？漏加会发生什么？

检索里 query 和 passage 的语义角色是不对称的：query 通常是一句很短的疑问，passage 是一段陈述性长文本，两者的表面形态差异远大于语义差异。如果用同一套编码方式，模型很容易把"短问句"和"短问句"判为相似，而不是把"问句"和"能回答它的段落"判为相似。E5 的做法是训练时就给两侧分别加上固定前缀 query: 和 passage:，让同一个编码器根据前缀切换成两种模式；BGE 走得更远，允许用自定义中文 instruction 描述任务（如"为这个句子生成表示以用于检索相关文章："），本质是把任务描述也当作输入的一部分。漏加前缀的后果不是报错而是静默掉点：向量照样算得出来，只是落在了模型训练时没见过的分布上，Recall 通常掉几个百分点，很难从日志里看出来。更隐蔽的错误是两侧前缀加反了，或者建库时加了、线上查询时忘了加——这类不对称最容易在换人维护、换调用入口时引入。稳妥做法是把加前缀的逻辑封在编码函数内部，禁止业务代码直接调用裸 encode。
