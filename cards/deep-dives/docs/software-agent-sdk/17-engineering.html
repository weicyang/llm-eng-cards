3. 核心概念

Unit / domain test

在 tests/sdk、tests/tools、tests/workspace、tests/agent_server 内证明单包或单域行为。

Cross test

tests/cross 证明包之间或真实 FastAPI HTTP/WS 栈的组合契约，不等同于真模型评测。

Integration / Behavior

t* 是必需的任务完成测试；b* 是非阻塞行为质量测试；两者共享评测基础设施。

Condenser / malformed history

c* 由 integration runner 归类为 condenser；a* 畸形历史案例不在该 runner 的 [tbc]* 自动发现集合中。

Compatibility gate

针对已发布消费者或持久数据的比较，不是普通单元测试：Python API、Field default、Settings、REST 各有不同规则。

Observability surface

供人或系统理解运行状态的表面；事件、日志、metrics、diagnostic telemetry 与健康端点用途不同，不能互相替代。

Integration runner 只发现 t/b/c 前缀，并把只有 integration 标记为 required。 tests/integration/run_infer.py:38-46 tests/integration/run_infer.py:67-99

4.1 论文 §5 的四层实证

MLSys 2026 论文把架构验证分成生产可靠性、Event Sourcing 系统开销、持续质量保障和 多模型 benchmark 四层。这些是论文版本对应的历史实证，不是当前仓库的 SLA，也不能由 本章列出的 CI 配置自动推导。来源： arXiv:2511.03690 §5。

论文证据样本与结果可支持结论不可外推
§5.1 生产可靠性V0/V1 同时服务用户的 15 天 rollout；system-attributable errors 从 78.0 降至 30.0 / 千会话，论文报告相对下降 61%该观察窗口内，V1 的系统归因故障率更低不是长期故障率、SLA 或因果实验；排除了外部 LLM provider errors，论文未在正文给出会话总数与置信区间
§5.2 Event Sourcing433 个 SWE-Bench Verified 会话、39,870 个事件；本地机器重放生产 LocalFileStore 路径该 trace 与固定部署配置下，持久化相对 1–30 秒 LLM 往返很小，存储随事件数近线性增长不是远程文件系统、Windows、NFS、多租户并发或任意事件尺寸的性能承诺
§5.3 三层 QA每次提交的 programmatic tests；daily/按需的真实 LLM integration/examples；按需 academic benchmark论文版本采用“快且便宜 → 真模型行为 → 高成本能力评测”的分层策略论文中的模型、频率、耗时和成本是发表快照；当前触发条件以 workflow 源码为准
§5.4 多模型评测14 个模型，覆盖 Issue Resolution、Greenfield、Frontend、Testing、Information Gathering 五类任务论文评测覆盖 SWE-Bench Verified、Commit0、SWE-Bench Multimodal、SWT-Bench、GAIA 五类 benchmark不能外推到未测模型、后续模型版本、生产可靠性或所有软件工程任务；持续更新的 Index 也不等于论文静态结果
