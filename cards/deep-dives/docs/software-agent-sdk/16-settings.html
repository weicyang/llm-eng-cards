3. 核心概念

  • 规范 Settings payload：模型 model_dump() 的直接形状，顶层含 schema_version，不增加 wrapper。
  • 判别联合：agent_kind 选择 openhands 或 acp；缺失时按历史默认归为 openhands。openhands-sdk/openhands/sdk/settings/model.py:1845-1867
  • 导出 schema：面向设置界面的中立描述，不等于 Pydantic JSON Schema，也不含 required；可空性应从 Python typing 判断。openhands-sdk/openhands/sdk/settings/model.py:102-143
  • Runtime-only 字段：workspace、conversation_id、plugins 等参与请求构造，但设置了 exclude=True，不进入持久化。openhands-sdk/openhands/sdk/settings/model.py:940-1008
  • Golden baseline：按 schema 版本保存的历史 JSON；__expected__ 是检查元数据，不是运行时 payload，用 dotted path 防止迁移静默丢值。.github/scripts/check_persisted_settings_compat.py:392-442
  • PyPI baseline：从已发布版本生成真实 payload，再由当前 loader 加载；与只覆盖特定历史形状的 golden 互补。
  • Redaction（遮蔽）：默认输出 **********，不可逆；它不是加密文本，也不能被当成有效 Secret 回写。
  • LookupSecret：保存“到哪里取值”的引用与鉴权 header，值在使用时通过同步 HTTP 获取，不把远端明文提前搬入 SDK 客户端。

5. 完整运行流程

5.1 正常成功：保存、重载并构造运行对象

  1. 客户端通过 Python 构造模型，或向 PATCH /api/settings 发送稀疏 diff；REST 请求由 SettingsUpdateRequest 校验。openhands-sdk/openhands/sdk/settings/api_models.py:194-218
  2. 同变体 Agent diff 使用 RFC 7386 递归合并；切换 agent_kind 时从目标变体的新鲜 base 开始，避免混合两个模型的字段。openhands-sdk/openhands/sdk/settings/model.py:1915-1968
  3. PersistedSettings.update() 先同时验证 Agent 与 Conversation 新值，再修改内存对象；router 的 Store 更新由文件锁包围。openhands-agent-server/openhands/agent_server/persistence/models.py:183-279
  4. 落盘时 Secret 根据 context 加密；重载时顶层模型调用 validate_agent_settings() 与 ConversationSettings.from_persisted()。
  5. OpenHandsAgentSettings.create_agent() 解析默认 tools、subscription LLM、condenser 与 critic；ConversationSettings.create_request() 生成启动请求。openhands-sdk/openhands/sdk/settings/model.py:1316-1355

5.2 拒绝/提前结束：无效 payload 或缺少加密能力

  1. 未来版本 schema_version 高于当前版本时立即拒绝，不尝试猜测向后读取。openhands-sdk/openhands/sdk/settings/model.py:529-576
  2. 迁移链缺步骤、版本不前进或类型不是整数时失败；无效 REST diff 被清理异常细节后返回 400，避免 Pydantic 错误泄露 Secret。
  3. 请求 encrypted 输出但 context 无 cipher 时抛出 MissingCipherError，服务器转换为服务不可用，而不是回退明文。openhands-sdk/openhands/sdk/utils/pydantic_secrets.py:48-82

5.3 恢复/迁移：旧 AgentSettings 进入 v5

9. 并发、性能与资源

  • 模型迁移和 schema 导出是同步 CPU 操作；Agent Server 用 lru_cache(maxsize=1) 缓存两份 schema，避免每次请求遍历模型。openhands-agent-server/openhands/agent_server/settings_router.py:59-83
  • PersistedSettings.update() 自身不是线程安全容器；router 必须经 Store 的文件锁更新。它采用“先验证全部，再赋值”避免一半成功，但不宣称跨进程数据库事务。openhands-agent-server/openhands/agent_server/persistence/models.py:204-215
  • LookupSecret.get_value() 是同步 httpx.get，超时固定为 30 秒。调用方若位于 async event loop，必须在线程边界执行，避免 loopback 请求自锁。openhands-sdk/openhands/sdk/secret/secrets.py:79-82
  • Settings 模块没有队列、背压或自动重试。HTTP 错误通过 raise_for_status() 直接传播；是否重试由调用方决定。
  • tool_concurrency_limit 是配置字段而非本模块并发机制；值大于 1 会让下游工具共享 Conversation 和文件系统，风险在 Agent 执行模块。

10. 安全与信任边界

10.1 Secret 三态序列化

resolve_expose_mode() 把 context 解析为 plaintext、encrypted 或 redact： 显式 plaintext 优先；显式 encrypted 或存在 cipher 走加密；其他情况保持 Pydantic 的 SecretStr 遮蔽。 已加密且可由同一 cipher 解开的 token 不重复加密。openhands-sdk/openhands/sdk/utils/pydantic_secrets.py:24-37 openhands-sdk/openhands/sdk/utils/pydantic_secrets.py:48-82

反序列化把空白和 canonical redaction sentinel 变成 None；只对带 Fernet 前缀且提供 cipher 的值解密， 普通字符串保留为旧版明文或 PATCH 输入。openhands-sdk/openhands/sdk/utils/pydantic_secrets.py:85-126

10.2 LookupSecret 信任模型

hostless URL 在模型构造时相对 OH_INTERNAL_SERVER_URL 解析；Agent Server 启动时按实际 host/port 注入该变量， wildcard bind 被改写为 loopback。openhands-sdk/openhands/sdk/secret/secrets.py:22-32 openhands-agent-server/openhands/agent_server/__main__.py:51-71

headers 仅对被 is_secret_key() 判断为敏感的值加密或遮蔽，普通 header 原样保存； redacted 敏感 header 在反序列化时删除。openhands-sdk/openhands/sdk/secret/secrets.py:84-132

部署信任边界：GET /api/settings 没有基于角色区分 plaintext/encrypted 权限。 配置 session API key 时，所有通过认证的客户端处于同一信任域；未配置时 /api 可开放。 因此生产环境必须使用鉴权与网络隔离，前端应使用 encrypted 或 redacted。 openhands-agent-server/openhands/agent_server/settings_router.py:123-141

10.3 与 Settings/pydantic secret serialization 的分层

SecretRegistry 负责“本会话有哪些凭据、何时解析、哪些已解析值需要遮罩”； SecretSource 负责“值从何处取得”；通用 pydantic helper 只负责模型边界上的 明文、密文与遮蔽三态。Settings 与 Agent Server store 可以复用同一 helper，但不因此拥有 Conversation 的运行时 registry。反过来，registry 也不负责用户身份、角色授权、外部 Vault 生命周期或租户级策略。 openhands-sdk/openhands/sdk/utils/pydantic_secrets.py:24-82 openhands-sdk/openhands/sdk/utils/pydantic_secrets.py:85-126

15. 设计权衡与已知限制

问题当前选择收益成本/失败模式重评条件
多 Agent 形状判别联合 + 变体标签 schema单一加载入口且保持类型精确切换变体必须重建 base，schema 合并更复杂出现需要独立发布的第三方变体协议
UI schema 所有权SDK 只输出中立语义多客户端可复用，不绑定组件库required/nullability 需客户端读 typing 或另有契约跨客户端确有稳定、产品中立的新语义
显式 settings migration顶层版本 + 逐步函数历史行为可审计、可测试每次不兼容变化需维护 fixture 和链迁移规模大到需要独立格式或离线工具
Secret context 序列化同一模型按 context 输出三态存储、后端、前端共用模型错误 context 可能造成不可用或过度暴露需要角色级 Secret 授权或独立 vault token 协议
LookupSecret 同步拉取简单同步 HTTP + 30 秒 timeoutSecretSource 接口简单，值延迟获取async loop 中可能阻塞；无内建重试大量并发 lookup、异步 provider 或缓存/刷新需求
REST settings 使用 dict运行时手动控制 Secret context，OpenAPI 用附加 contract避免 FastAPI 自动序列化丢 context运行时类型与 OpenAPI 描述需保持同步框架可安全传递字段级 serialization context

当前限制还包括：Settings GET 的已认证客户端没有角色分级；LookupSecret 没有内建 retry/cache； schema exporter 不表达 required；本次本机无 Git CLI，无法把工作区内容绑定到 SHA。 这些是已观察到的边界，不代表计划或完成度承诺。

17. 术语表

ACP（Agent Client Protocol）
Agent 客户端协议；本模块中的 ACP settings 构造委托给外部 ACP 子进程的 Agent。
AgentSettingsConfig
当前 Agent settings 的 Pydantic 判别联合；不是一个可直接实例化的模型类。
Canonical shape（规范形状）
当前模型序列化和运行时消费共同认可的唯一正常形状；旧形状只在 migration 边界接受。
Discriminator（判别字段）
用于选择联合成员的字段；这里是 agent_kind。
Field default
Pydantic 字段省略时采用的值；改变它不会移除 API，但会改变既有调用方行为。
Golden baseline / fixture
检入仓库的历史 JSON 样本，用来稳定重现特定 schema 版本的迁移。
PyPI baseline
从最新适用的已发布 Python 包实际构造出的比较基线。
JSON Merge Patch（RFC 7386）
对象递归合并、null 删除 key、其他值覆盖的补丁语义；Agent settings diff 在同变体内使用。
Migration（迁移）
把一个持久化 schema 版本确定性转换到下一版本的函数；必须推进版本且不能静默丢失约定值。
OpenAPI / oasdiff
REST 契约描述及其差异检查工具；不覆盖 WebSocket/SSE。
Redaction（遮蔽）
用固定 sentinel 隐藏 Secret 的不可逆显示方式；不同于可解密的 ciphertext。
Runway（弃用缓冲期）
从声明弃用到允许移除之间的版本窗口；公共 Python API 与 REST breaking removal 均要求至少 5 个 minor。
SecretStr
Pydantic 的敏感字符串类型，默认序列化表现为遮蔽值。
LookupSecret
持有 URL 与请求 header、在使用时才同步取回明文的 SecretSource。
SecretRegistry
ConversationState 拥有的会话作用域注册表；管理 SecretSource、延迟解析、已解析值遮罩和运行中更新，不等于 Settings、外部 Vault 或 IAM。
__expected__
Golden fixture 顶层的测试专用映射，以 dotted path 指定迁移后必须保留的值；不会传给运行时 loader。
