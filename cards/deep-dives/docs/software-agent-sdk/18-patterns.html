3. 核心概念

Event Sourcing Lite

事件是可重放历史，base_state.json 是当前字段快照，二者共同恢复。 它不是“只由事件推导全部状态”的纯 Event Sourcing，也不是数据库中心模型。

Ports and Adapters

核心依赖抽象端口，具体 I/O 由 adapters 实现。边界价值在可替换和测试，不在增加层数。

Registry

用稳定名称把持久化规格解析为运行时实现，推迟重型初始化，并集中冲突与可用性规则。

State Machine

ConversationExecutionStatus 和 init state 显式约束可进入、暂停、确认、完成与失败阶段。

Bulkhead

舱壁隔离通过每个 Agent 的 executor、每个 executor 的线程池/资源锁、每个 EventService 的 run task/lock，将局部阻塞限制在较小故障域。

Layered Recovery

从 transport retry、备用模型、纠正消息、压缩恢复到硬错误，按副作用和信息损失逐层升级。

模式不是互斥标签

一次工具调用同时穿过多个模式：Tool 名称先经 Registry 解析成 adapter；Conversation 的 State Machine 把 Action 持久化并做准入；ParallelToolExecutor 以 Bulkhead 和资源锁执行； Observation 回写 EventLog；失败再由 Layered Recovery 决定是结构化 Observation、重试、 压缩还是 ERROR。单独实现其中一层而绕过其余层，通常就是本章所称的反模式。

5. 完整运行流程

5.1 成功路径：注册工具到可恢复 Observation

  1. 扩展包注册 ToolDefinition 子类；registry 保存 resolver 与 is_usable() checker。类型必须实现具体 create，创建结果必须是 Sequence[ToolDefinition]。 openhands-sdk/openhands/sdk/tool/registry.py:67-92
  2. Conversation 首次 send_message()/run() 执行线程安全懒初始化： plugins → file agents → Agent tools/MCP → state → LLM registry。构造器不做这些易失败 I/O。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1455-1521
  3. LLM tool calls 先形成 ActionEvent 并进入事件回调；安全分析、确认与 PreToolUse hook 决定是否可执行。可执行 batch 交给 ParallelToolExecutor。
  4. executor 按 DeclaredResources 选择无锁、具体资源锁或工具级互斥； 结果虽然并发计算，仍按输入 Action 顺序收集和发出。 openhands-sdk/openhands/sdk/agent/parallel_executor.py:67-126 openhands-sdk/openhands/sdk/agent/agent.py:312-329
  5. Observation 与 Action 配对后写 EventLog；独立事件文件支持按索引/ID读取，HEAD 推进， View 增量投影活跃分支。 openhands-sdk/openhands/sdk/conversation/state.py:315-381

5.2 拒绝路径：PreToolUse 阻止副作用

  1. ActionEvent 已存在，HookEventProcessor 按工具名运行 PreToolUse hooks。
  2. hook deny 时把 action_id → reason 写入 ConversationState，而不是删除 Action； HookExecutionEvent 仍用于观测。 openhands-sdk/openhands/sdk/hooks/conversation_hooks.py:126-176
  3. Agent 准备 batch 时弹出 blocked reason，不把该 Action 交给 executor，转而生成 UserRejectObservation(rejection_source="hook")，维持 Action–Observation 配对。 openhands-sdk/openhands/sdk/agent/agent.py:240-266 openhands-sdk/openhands/sdk/agent/agent.py:312-329
  4. 最终状态继续由 run loop 决定；拒绝不是未记录异常，也不应被重试器重新执行。

6.2 为什么不是完整 Event Sourcing

execution_status、stats、SecretRegistry、blocked actions、Agent 配置等公共字段会自动写入 base snapshot；事件本身不嵌入 snapshot。恢复先读 base，再挂载 EventLog、重建 View，并允许替换 LLM/context/condenser，但 persisted tools 必须与运行时 Agent 兼容。 openhands-sdk/openhands/sdk/conversation/state.py:420-442 openhands-sdk/openhands/sdk/conversation/state.py:444-552 这减少了“从创世事件重放全部可变字段”的成本，也意味着不能只复制 events 目录就声称得到完整会话。

6.3 锁与持久化事务边界

ConversationState 使用同步 FIFOLock；context manager 内的多个字段变更延迟到退出时合并一次 base_state 写入，但一次 event append 与一次 base snapshot 仍是不同文件操作，不构成跨文件事务。 openhands-sdk/openhands/sdk/conversation/state.py:253-257 openhands-sdk/openhands/sdk/conversation/state.py:580-607 因而恢复逻辑必须容忍“事件已写、某些派生字段尚未写”的边界，并从事件重建 View/HEAD 相关语义。

9.2 状态锁与事件循环

ConversationState 的锁是同步 FIFOLock。Agent Server 创建订阅 snapshot、发送消息和需要等待该锁的 操作必须越过 worker-thread boundary；EventService 也只有在 Conversation 与 Agent 都提供真正 async override 时才原生 await arun()，否则把 sync run 放入专用 executor。 openhands-agent-server/openhands/agent_server/event_service.py:1171-1198 在 async route 上直接 with conversation._state 可能冻结整个 FastAPI event loop， 这不是局部性能问题，而是破坏服务舱壁。

9.3 背压与有意未承诺的指标

源码证明了线程池上限、资源锁超时、初始 subscriber push 超时和 remote run 总超时； 没有证据支持固定吞吐、延迟、队列容量或 SLA。扩展作者应把压测阈值放入 stress budget， 不应把开发机观测写成运行时保证。

10. 安全与信任边界

10.1 防护链的位置

不可信用户/模型输入
  → Pydantic Action schema
  → 构造 ActionEvent
  → PreToolUse hook（组织策略）
      └─ deny：不写入 EventLog
  → 放行的 ActionEvent 持久化
  → SecurityAnalyzer（风险）
  → ConfirmationPolicy（是否询问）
  → ToolExecutor（在当前执行环境产生副作用）
  → PostToolUse hook + ObservationEvent

SecurityAnalyzer 负责把 Action 评估为 SecurityRisk；分析器批处理时单项异常降为 HIGH， 避免异常悄悄放行。ConfirmationPolicy 是独立策略：AlwaysConfirm、NeverConfirm 或按阈值且默认确认 UNKNOWN 的 ConfirmRisky。 openhands-sdk/openhands/sdk/security/analyzer.py:85-111 openhands-sdk/openhands/sdk/security/confirmation_policy.py:27-61

10.2 Adapter 不等于可信边界

  • Tool schema/annotations 是提示与验证，不等于沙箱；真正副作用权限由 Workspace/进程/容器决定。
  • RemoteWorkspace 的 API key 进入 X-Session-API-Key；wire path 统一为 POSIX， 不应把 host-native Path 直接拼入 URL。 openhands-sdk/openhands/sdk/workspace/remote/remote_workspace_mixin.py:18-65
  • Agent Server 的普通 /api/* 同时应用 session-key auth 与 deferred-init gate； /api/init 单独使用 bootstrap auth，workspace 静态资源有 cookie/header 二选一边界。 openhands-agent-server/openhands/agent_server/api.py:403-466
  • Secret 在无 cipher 的 snapshot 中被掩码且恢复丢失；不要在自定义 serializer 中自行实现另一套掩码。 openhands-sdk/openhands/sdk/conversation/state.py:420-436
禁止把旁路当等价调用
直接调用 executor、Workspace 或程序化 execute_tool 可能跳过 Agent loop 的确认、 Hooks、Action 持久化和 Observation 配对。若业务需要受信任的管理旁路，应在 API 名称、鉴权、 审计和文档中明确它是不同安全契约，不能复用“Agent 已检查”的假设。

10.3 多租户安全不是现有组件的自动推论

论文 §7 指出，独立容器、每会话事件日志、会话级 SecretRegistry 与 Agent Server session authentication 只是多租户隔离和访问控制的基础。共享 LLM API key、MCP server、 secret registry 后端与基础设施资源仍需要租户身份、授权、配额、审计和密钥边界；论文明确把 完整多租户安全审计列为未来工作。当前源码可以证明 session-key auth、 Conversation/Secret 的作用域和可选容器化，不能据此声称完成 tenant-aware IAM 或端到端审计。 openhands-agent-server/openhands/agent_server/api.py:403-466 openhands-sdk/openhands/sdk/conversation/state.py:197-201 来源：arXiv:2511.03690 §7 “Multi-Tenant Deployment”。

14.5 Security 二开步骤

  1. Analyzer 只返回风险，不决定 UI 或执行；Policy 只把风险映射为确认决定。
  2. 明确基础设施错误、解析不确定和真实高风险的映射；默认不能静默放行。
  3. 需要组织策略时使用 Hooks，并保留 HookExecutionEvent；PreToolUse deny 仍必须形成拒绝 Observation。
  4. 验证程序化旁路是否需要独立鉴权和审计，不要假定所有 executor 调用都经过安全链。

14.6 Workspace 二开步骤

  1. 选择 BaseWorkspace（直接实现）或 RemoteWorkspace（通过 Agent Server 协议）作为 port。

  4. 为命令、上传/下载、Git、pause/resume、timeout 和 auth 写聚焦测试；外部进程可 patch executor。

14.7 Server 二开步骤

  1. 路由只做 HTTP 校验与状态码映射，运行所有权放 ConversationService/EventService。
  2. 把新 /api/* 路由置于 session auth + deferred-init dependency 下；例外需要显式独立信任模型。
  3. 同步 state lock 和阻塞 I/O 移入 worker executor；网络 await 不应持有同步锁。
  4. REST 变更优先 additive；破坏变更走 OpenAPI deprecation 和 5 minor runway，并更新 Remote client/live server test。

典型反模式清单

  • 状态复制：在 Agent、Tool 或 Remote client 另存一份可变会话权威状态。
  • 全量事件即上下文：把 EventLog 直接发送给 LLM，绕过 active branch、View 和 Condenser。
  • 按名字硬编码：在 Agent/Server 主链写 if tool_name == ... 或 provider 特例。
  • 假并行安全：把 readOnlyHint 当锁声明，或为有副作用工具返回显式空 resources。
  • 构造器 I/O：Agent/Conversation/Workspace model 构造时下载 plugin、连接 MCP 或启动容器。
  • 错误归一化过度：把 malformed history、overflow、权限失败和网络失败都包装成同一重试异常。
  • 安全旁路伪装：直接调用 executor 后仍宣称执行经过 confirmation/Hooks。
  • async 阻塞：在 FastAPI event loop 直接等待同步 FIFOLock、subprocess 或同步 HTTP。
  • 兼容策略混用：删除永久 Event handler，或用 Python warning 代替 REST OpenAPI deprecation。
  • 双向路径混淆：用 Windows host Path 拼远程 URL，或在 POSIX 本地写入中接受 Windows drive path。
  • 全局 registry 偷偷覆盖：依赖 import 顺序解决名称冲突而不测试各 registry 的明确规则。

15.3 论文限制与论文之后的能力

多 Agent 协调仍不是完整编排平台
论文 §7 以“当前实现聚焦单 Agent conversation”为发表时限制。当前源码已经加入文件/插件 subagent registry、独立 LocalConversation、可恢复 Task 与并行工具执行等后续能力； 这些能力不应倒写成论文已评测结论。现有 TaskExecutor 仍是 blocking-only， TaskManager.start_task() 同步运行单个子会话；动态调度、异步编排、跨 Agent 共享状态一致性、容错恢复和完整协作协议仍需额外设计。 openhands-tools/openhands/tools/task/impl.py:1-38 openhands-tools/openhands/tools/task/manager.py:95-201 openhands-tools/openhands/tools/task/manager.py:295-330
  • 多租户：论文明确说完整安全审计仍是未来工作；当前 session auth、容器与会话级 Secret 不能替代 tenant-aware authorization、共享资源审计和隔离验证。
  • 安全分析：论文同时限定 LLM-based security analysis 可能受对抗提示和分类不一致影响；确认、Hook 与 sandbox 是分层防护，不构成绝对安全保证。
  • 论文后续能力：本章的 Event Sourcing Lite、FULL_STATE 完成信号、deferred init、resource-aware tool concurrency、plugin/file agents 与 TaskManager 均以当前源码为准；除论文明确覆盖者外，不归因于论文 §7。
何时应新增抽象
只有当两个以上真实实现需要共享同一不变量，并且现有 port/strategy/registry 无法表达时才增加抽象。 单一 provider、单一工具或单一部署的临时差异优先留在聚焦 adapter；不要把假设性的未来能力提升为核心层。

17. 术语表

术语本章含义易混点
Event Sourcing Lite事件文件保存历史，base snapshot 保存当前公共字段，View 从活跃分支投影不是仅靠事件重放全部状态的纯 Event Sourcing
Port核心需要的稳定能力接口，如 Workspace、ToolExecutor、SecurityAnalyzer不是 HTTP port，也不必都是 Python Protocol
Adapter把 port 映射到具体 I/O 的实现，如 DockerWorkspace、RemoteWorkspace、provider transportadapter 负责边界转换，不应拥有 Agent 决策
Registry以稳定 key/name 解析实现或有序组合 section 的注册表不同 registry 的 duplicate/precedence 语义不同
State Machine显式状态及允许转换；包括 Conversation execution status 和 deferred init stateEnum 只是状态集合，真实转换还在 run/service 逻辑
Bulkhead舱壁隔离；用独立 executor、任务、锁和 subscriber 边界限制故障传播不等于所有操作都并行
Layered Recovery按成本和信息损失逐层升级的 retry、fallback、nudge、condensation、hard error副作用后的失败不能机械重试
Frozen AgentAgent Pydantic 字段禁止原地赋值，配置变更产生副本不保证嵌套对象图深冻结；PrivateAttr 仍有运行时生命周期
PrivateAttrPydantic 不进入普通序列化字段的运行时属性，如 tool map、executor、locks不是“无状态”的反证；关键在它不成为会话权威业务状态
EventLog按文件持久化、可按 index/ID 读取的完整事件日志不同于活跃分支 View 和 RemoteEventsList 镜像
View当前事件树活跃分支经过语义约束的 LLM 输入投影不是 EventLog 副本，也不持久化
HEAD / leaf_event_idConversation 事件树中下一事件的父节点，即当前活跃分支叶物理文件尾部可以属于废弃分支或 state artifact
Action–Observation pairing每个工具 Action 必须有对应结果，包括失败、拒绝和中断合成错误拒绝不等于删除 Action
DeclaredResources工具对当前 Action 所访问共享资源的声明空且 declared=true 表示确认无共享资源；declared=false 表示未知并保守互斥
Fallback主 LLM 在 retry 后因瞬时故障改试有序备用 profile不是每次请求的负载均衡，也不处理所有异常
Nudge框架写入的纠正性 user-role MessageEvent，引导模型下一轮修复输出不是 transport retry，会改变事件历史
Condensation压缩/摘要活跃历史以恢复上下文窗口或结构问题不删除 EventLog 原始事件；改变的是 View 语义
FULL_STATEAgent Server 发送的完整 ConversationStateUpdateEvent snapshotarmed 后 post-run snapshot 才是首选 run 完成信号
ReconcileRemote client 从 REST/事件搜索补齐 WS 连接窗口或断线期间遗漏事件不是把客户端状态写回服务端
Fail-safe / fail-closed安全分析故障时提高风险或要求确认，避免静默执行与 Hook 的某些基础设施 fail-open 行为需分别审计
Optional isolation默认可本地执行，需要时改用 Remote/Docker 等隔离 adapter“可选”不表示本地安全，也不保证所有容器部署具有相同隔离强度
Multi-tenant audit验证租户身份、授权、Secret、共享服务、资源和审计链的系统性安全评估session auth、每会话状态或独立容器只是输入证据，不等于审计已经完成
Multi-agent coordination多个 Agent 的调度、通信、状态一致性、失败恢复与权限协作协议当前 blocking Task/subagent delegation 是局部能力，不等于完整协调平台
Owner对某一契约、状态或副作用拥有最终修改责任的包/模块调用方使用对象不意味着拥有其语义
