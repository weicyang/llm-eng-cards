1. 模块定位

执行主链是“控制循环”，不是全系统状态存储、Prompt 工程、LLM transport（传输层）或具体工具实现。 它拥有入口分流、一次运行的状态推进、一步执行顺序和终止判断；把事件树与持久化委托给 ConversationState/EventLog，把上下文构造与模型调用委托给 Agent/LLM，把副作用委托给工具执行器和 Workspace。 openhands-sdk/openhands/sdk/conversation/conversation.py:34-43 openhands-sdk/openhands/sdk/conversation/base.py:123-129

3. 核心概念

run（一次运行）
从显式 run()/arun() 开始，到完成、等待确认、暂停、卡住、预算/迭代上限或异常结束；并不等于 Conversation 永久关闭。
step（一步）
优先消费 unmatched Action；否则由活跃分支的 View 准备 LLM 消息，调用 LLM 并分派一个响应。openhands-sdk/openhands/sdk/agent/agent.py:636-687
unmatched Action（未匹配动作）
活跃事件分支中已有 ActionEvent、但尚无对应 Observation 的动作；它是确认延后、进程恢复和中断修补的连接点。openhands-sdk/openhands/sdk/conversation/state.py:662-701
implicit confirmation（隐式确认）
第一次运行写入待确认 Action 并停在 WAITING_FOR_CONFIRMATION；再次调用 run 把状态改回 RUNNING，Agent 先执行这些 pending actions。openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1931-1947
pause 与 interrupt
pause() 在步骤边界生效；interrupt() 会取消正在执行的异步任务，并用线程安全 token 通知工具线程。openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2559-2617

4.3 Agent 一步与响应分派

没有 pending action 时，Agent 从 state.view 准备消息；Condenser 若返回 Condensation，本步只写压缩事件，不调用新模型。否则才调用 LLM。 openhands-sdk/openhands/sdk/agent/agent.py:669-726

优先级LLMResponseType判定处理与状态

5. 完整运行流程

5.1 正常成功：消息 → 工具 → 最终文本

  1. 调用者创建 Conversation；工厂按 Workspace 类型返回 Local 或 Remote。
  2. send_message() 规范化 user message，经过 skill/Hook/callback，追加 MessageEvent。
  3. run() 准备 Agent 和取消 token，把 IDLE/PAUSED/ERROR/STUCK 转为 RUNNING。
  4. Agent 发现没有 unmatched Action，从 View 准备上下文并调用 LLM。
  5. TOOL_CALLS 先连续发出一批 ActionEvent；无需确认时由并行执行器产生配对 Observation。
  6. 下一步重新从活跃分支构造 View；若 LLM 返回 CONTENT，写 Agent MessageEvent 并置 FINISHED。
  7. 运行循环在下一轮先执行 Stop Hook；允许停止后退出。

工具批处理的同步和异步实现共享 prepare/emit/finalize 结构，异步版通过 aprepare 等待线程池工具执行；两者都把 cancel token 下传。 openhands-sdk/openhands/sdk/agent/agent.py:571-634

5.2 拒绝：确认等待 → 用户拒绝

  1. TOOL_CALLS 已规范化并持久化 ActionEvent。
  2. 风险分析结果交给 confirmation_policy.should_confirm()；任一 action 需要确认即置 WAITING_FOR_CONFIRMATION，本次不执行。单一 Finish/Think 不要求确认。
  3. 调用 reject_pending_actions(reason) 为每个 unmatched Action 写 UserRejectObservation，从而恢复 Action–Observation 配对，并把等待状态改为 IDLE。

这条路径是“已记录动作、拒绝副作用”，而不是删除 Action。 openhands-sdk/openhands/sdk/agent/agent.py:1025-1066 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2489-2527

5.3 恢复：中断异步 LLM/工具后再运行

  1. arun() 记录当前 asyncio Task，并为本次运行创建 CancellationToken。
  2. interrupt() 先置 token，再通过目标 event loop 的 call_soon_threadsafe(task.cancel) 取消任务。
  3. arun() 吞掉预期的 CancelledError；为所有 orphan Action 写合成 AgentErrorEvent，置 PAUSED，发出 InterruptEvent。
  4. 后续 run()/arun() 可从 PAUSED 转回 RUNNING；新的运行使用新的 token，历史仍满足工具调用配对。

中断后的已取消 token 会暂时保留，供晚退出的工具线程观察；下一次运行替换它。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2417-2481 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2529-2557 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2584-2617

6. 数据与状态模型

权威可变对象是 ConversationState。它持有 ID、Agent 配置、Workspace、 persistence_dir、执行上限、执行状态、确认策略和安全分析器；默认持久目录字段为 workspace/conversations，但 LocalConversation 未传 persistence_dir 时会显式创建不持久化状态。 openhands-sdk/openhands/sdk/conversation/state.py:82-127 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:349-361

事件经默认 callback 进入 append_event()；同一 chokepoint 负责 parent stamping 后推进 HEAD，并记录最近 user message ID。状态写入发生在 state lock 内。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:365-405

状态主链含义典型进入离开
IDLE可开始运行初始；拒绝；新消息重置终态run → RUNNING
RUNNING控制循环活跃run/arun 开始或 Stop Hook 拒停各类终止/等待状态
WAITING_FOR_CONFIRMATIONAction 已写、尚未执行确认策略命中再次 run 隐式接受；reject → IDLE
PAUSED可恢复的暂停pause 或 interrupt再次 run/arun → RUNNING
FINISHED当前任务完成文本回复、Finish、ACP 无待处理消息新消息 → IDLE；Stop Hook 可改回 RUNNING
ERROR本次运行失败异常、预算/迭代上限再次 run 可重试
STUCK检测到循环StuckDetector新消息 → IDLE；run 可重试

DELETING 属于删除生命周期，不是本地 run 循环的成功/失败出口；终态判定仅含 FINISHED、ERROR、STUCK，IDLE 不是终态。 openhands-sdk/openhands/sdk/conversation/state.py:48-79

9. 并发、性能与资源

Local 主循环以 ConversationState 的 FIFO lock 保护状态判断、Agent step 和事件写入。 同步 pause() 从其他线程获取同一锁，因此只在当前 step 完成后生效。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1885-1950

普通 Agent 的 arun() 仍让 step 处于状态临界区，但在真正等待 LLM 网络 I/O 时通过 _released_state_lock_during_io() 临时完整释放并按原深度重入，使并发 send_message() 和状态快照保持响应。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1831-1854 openhands-sdk/openhands/sdk/agent/agent.py:912-923

FIFOLock 是线程重入而非 asyncio task 重入；因此不相关的异步状态 mutator 不得在持锁的 event-loop 线程中直接 await，必须放到 worker thread。ACP 的长 prompt 则专门在锁外 await， callback 每次写事件时短暂取锁。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2177-2203 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2246-2308

工具批处理在 sync/async 路径都使用 ParallelToolExecutor；异步路径把阻塞工具放入线程执行， CancellationToken 使用 threading.Event，可跨 event loop 和线程池读取。 openhands-sdk/openhands/sdk/conversation/cancellation.py:1-43 openhands-sdk/openhands/sdk/agent/agent.py:601-623

源码没有为本章给出通用吞吐、延迟或队列容量保证；除明确默认超时和阈值外，不应推导 SLA。

10. 安全与信任边界

安全决策位于 Action 已被解析并持久化之后、工具副作用之前。SecurityAnalyzer 产生风险， ConfirmationPolicy 决定是否停在 WAITING；两者不是同一个职责。 openhands-sdk/openhands/sdk/agent/response_dispatch.py:160-184 openhands-sdk/openhands/sdk/agent/agent.py:1047-1066

Hook 是另一条准入边界：被 UserPromptSubmit 阻止的最近 user message 会让 Agent 在 LLM 调用前直接置 FINISHED；Stop Hook 则能拒绝 FINISHED、注入 environment feedback 并把状态改回 RUNNING。 openhands-sdk/openhands/sdk/agent/agent.py:655-667 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1897-1925

显式旁路：execute_tool() 不经过 Agent loop、确认策略和安全分析器；调用方必须自行 加保护，不能把它当作“受确认保护的快捷 run”。 openhands-sdk/openhands/sdk/conversation/base.py:367-394

RemoteConversation 是控制客户端，不应获得本地状态锁或直接执行 Workspace 副作用；鉴权与服务端策略属于 Agent Server 边界，本章只确认其 POST/WS 控制语义。

12. 可观测性与排障

现象先检查常见原因修复
run 立即返回 FINISHED、没有 LLM 调用blocked_messages、HookExecutionEvent、last_user_message_idUserPromptSubmit Hook 阻止修正 Hook 或输入；不要强制重跑绕过

15. 设计权衡与已知限制

状态锁覆盖 step，但释放网络等待

收益是事件与状态转换原子、并发消息不会静默覆盖；成本是同步 step 的长工具调用会推迟 pause。 async LLM 网络等待专门释放锁降低阻塞，但增加“持锁线程重入 vs asyncio task”理解成本。若未来所有状态写入 都可经过单线程 actor queue，可重新评估锁模型。

Action 先持久化，再确认/执行

收益是拒绝和进程恢复都有可审计对象；成本是任何中断都必须补齐 Observation，否则 provider 历史不合法。 不应改为“确认后才记录 Action”，那会丢失模型提出过什么的审计事实。

CONTENT 直接结束当前任务

这是简洁的默认协议：用户可见文本意味着等待下一条用户输入。Stop Hook 可推翻该停止；若业务需要 “文本中间态”，应设计显式事件/工具协议，而不是按文本内容猜测。

Remote 完成采用 WS 权威、REST 延迟降级

这避免 FINISHED 在 Stop Hook 判定前被客户端误当作最终完成；成本是 WebSocket 丢失时最多需等待连续 30 秒的 REST 终态。该数值是当前实现常量，不是 SLA。 openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:1223-1230,1284-1315

当前限制

  • 同步 run() 不能取消正在阻塞的 LLM 调用；interrupt() 在无活跃 arun 时只请求 pause。
  • 线程中的已开始工具副作用不可由 asyncio task cancellation 自动回滚，只能协作停止。
  • Remote 客户端不暴露本地 StuckDetector；卡住检测由服务端处理。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:1106-1113

17. 术语表

ACP（Agent Client Protocol）
外部 Agent 子进程协议；本仓库的 ACPAgent 有独立 prompt 队列和较重的会话初始化。
Action / Observation
Agent 提出的工具动作 / 环境返回的工具结果。持久历史必须保持可配对。
active branch（活跃分支）
事件树从当前 HEAD 回到根的路径；pending Action 和 LLM View 都应基于它，而不是全事件文件。
callback（回调）
事件或 token 产生时调用的函数；LocalConversation 的默认事件回调负责写入 State。
CancellationToken（取消令牌）
基于 threading.Event 的线程安全协作取消标志，不等同于 asyncio Task cancellation。
Condenser（上下文压缩器）
把过长或结构异常的事件 View 转为可继续调用 LLM 的压缩表示；不拥有 run 循环。
fail-open / fail-closed
安全组件故障时允许继续 / 拒绝继续。本章不把所有 Hook 或分析器错误统一归类，须以具体实现为准。
FIFO lock
按等待顺序授予的状态锁；此处是线程重入，不是按 asyncio task 隔离。
Hook
生命周期扩展点，可在用户消息、工具执行或停止阶段允许、阻止或返回反馈。
implicit confirmation（隐式确认）
WAITING 状态下再次调用 run，被解释为接受已持久化的 pending actions。
LLMResponseType
模型响应的互斥分类：TOOL_CALLS、CONTENT、REASONING_ONLY、EMPTY。
orphan / unmatched Action
尚无匹配 Observation 的 Action；“orphan”常强调中断造成的历史缺口，“unmatched”也涵盖正常等待确认。
pause / interrupt
步骤边界暂停 / 取消活跃异步任务并传播协作取消。同步阻塞调用不能被 interrupt 立即打断。
REST / WebSocket（WS）
远端控制请求 / 双向事件通道。RemoteConversation 以 post-run full-state WS snapshot 判定权威完成。
step / run
Agent 的一次决策与分派 / Conversation 包含多步的完整控制循环。
transport（传输层）
LLM 或远端服务实际发起网络请求的边界；主链调用它，但不拥有 provider 协议细节。
View
从事件树活跃分支派生、供 LLM 使用的上下文视图，不等同于 EventLog 或 base_state.json。
