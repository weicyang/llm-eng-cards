Workspace 与 Git

Workspace 是环境、远端控制与 Git/文件操作的执行端口：SDK 定义统一契约， 本地实现直接触达当前主机，远端实现经 Agent Server 协议执行，而 Workspace 包负责获得和管理具体容器或云运行时。当前具体 ToolExecutor 通常仍由 Agent 在同一进程直接调用；并非所有工具 I/O 都必须转发为 Workspace 方法。

3. 核心概念

Host path 与 source/wire path

host-native path（主机原生路径）用于当前进程真正读写文件， 应由 Path/os.path 按当前 OS 判断。 source/wire path（来源/传输路径）则是配置或 HTTP 中表达的路径， 可能来自另一操作系统。is_absolute_path_source()同时识别 POSIX 与 Windows 绝对路径；is_host_absolute_path()只承认当前主机语义； to_posix_path()只替换分隔符，不解析或校验。 openhands-sdk/openhands/sdk/utils/path.py:13-49

Workspace、runtime 与 worktree

  • Workspace：执行接口及其 working directory。
  • Runtime/sandbox：承载 Agent Server 的容器或云资源；由具体后端管理。
  • Git worktree：共享对象库、拥有独立工作目录和分支的 Git checkout；这里只对本地 Git workspace 可选启用。
  • saved workspaces：GUI 的路径列表，是独立的文件后端元数据，不等于运行中 Workspace。openhands-agent-server/openhands/agent_server/workspaces_router.py:1-7,58-83

Opt-in sandbox 与 LocalWorkspace 默认值

“opt-in”描述的是部署选择，不是 LocalWorkspace 内部的开关。未传 host 时，Workspace 工厂返回 LocalWorkspace； 它的命令、文件和 Git 实现直接使用当前主机能力。要获得容器或云隔离，调用方必须 显式构造 Docker、Apptainer、Cloud 或其他 Remote 后端，并单独审计挂载、网络、 凭据和资源限制。 openhands-sdk/openhands/sdk/workspace/workspace.py:20-49 openhands-sdk/openhands/sdk/workspace/local.py:47-80 openhands-workspace/openhands/workspace/__init__.py:1-43

5. 完整运行流程

5.1 正常成功：远端命令

  1. 调用 RemoteWorkspace.execute_command(command, cwd, timeout)，同步类驱动共享 generator；异步类使用 AsyncClient 驱动同一 generator。openhands-sdk/openhands/sdk/workspace/remote/base.py:109-154 openhands-sdk/openhands/sdk/workspace/remote/async_remote_workspace.py:48-78
  2. cwd 经 slash normalization 后，客户端 POST /api/bash/start_bash_command；服务端启动后台任务并立即返回 command ID。openhands-sdk/openhands/sdk/workspace/remote/remote_workspace_mixin.py:88-109 openhands-agent-server/openhands/agent_server/bash_router.py:100-108

15. 设计权衡与已知限制

问题当前选择收益成本/失败模式重评条件
Local/Remote 一致性抽象同步接口，另有 AsyncRemote调用面简单，后端复用异步类不是 BaseWorkspace；共享 generator 中有同步 sleep，timeout/limits 默认也不完全对称异步高并发出现 event-loop 延迟或 API 需要统一类型时
命令结果传输后台启动 + 事件轮询可增量抓取且服务端任务独立100 条 page 与轮询间隔带来延迟；超时不证明远端命令已取消需要强取消、流式背压或大输出保证时
非 Git workspacechanges/diff 返回空，worktree 请求降级GUI 和会话可继续空结果不能区分“干净 repo”与“非 repo”客户端需要精确诊断时可增加兼容的状态字段/端点
会话隔离Git worktree 而非复制 repo共享对象库、快速、保留子目录branch/worktree 清理与同 ID 并发需要治理；fetch 引入网络依赖磁盘泄漏、跨租户共享或并发冲突成为实际问题时
多部署后端后端只负责 provisioning，再复用 Remote协议行为集中各后端 pause、认证、cleanup 能力并不完全一致需要可查询 capability model 而不是靠异常判断时
上下文退出各后端自行串联 callback 与 cleanup可按资源类型定制Docker/Apptainer 跳过父类退出逻辑，completion callback 与 Cloud/Runtime 不对称automation 需要所有后端一致报告完成状态时
路径跨平台source/wire 与 host-native helper 分离避免 Windows 路径污染 URL 或 POSIX 本地写盘调用者必须选择正确 helper；规范化本身不验证安全发现新的 UNC/URL/挂载语义时扩充聚焦测试
默认隔离论文 §3.1 的 opt-in sandbox；LocalWorkspace 默认直接运行本地开发、MCP 和 IDE 集成路径简单，避免 V0 双进程状态分叉默认没有 OS 隔离；调用方必须按威胁模型选择远端/容器后端不可信代码、多租户或资源配额成为要求时

真实 Docker、Cloud、Apptainer 的容量、延迟、SLA、网络隔离强度与并发上限均没有 当前审计证据，本文不提供推测数值。worktree 结束清理机制也未在决定性创建路径中发现； 这是明确的证据缺口，不应写成“自动删除”。

17. 术语表

术语本文含义
Workspace向 Agent/Tool 提供 working directory、命令、文件和 Git 操作的统一执行端口，不天然等于沙箱。
LocalWorkspace在 SDK 当前进程所在主机直接产生副作用的 Workspace。
Opt-in sandbox默认采用本地直接执行，只在调用方显式选择容器、云或其他远端后端时增加隔离；不是 LocalWorkspace 的布尔开关。
ToolExecutor执行已验证 Action 并返回 Observation 的具体工具实现；当前本地运行时通常与 Agent 同进程，不要求所有 I/O 经 Workspace 方法。
RemoteWorkspace通过 HTTP 调用 Agent Server 执行副作用的同步 Workspace。
Runtime / Sandbox承载 Agent Server 和文件系统的容器或云执行环境，由部署后端创建或连接。
Host-native path按当前操作系统文件系统规则解析、可实际用于本地读写的路径。
Source/Wire path来自配置、序列化或网络协议的路径表达，可能采用另一 OS 的语法。
Slash normalization将反斜杠替换为正斜杠用于 wire/storage/display；不等于 resolve、校验或授权。
Git worktree共享同一 Git 对象库、具有独立工作目录与 branch 的 checkout。
Conversation worktreeAgent Server 按 conversation ID 创建的可选 Git worktree，用于隔离会话文件和分支。
SIFSingularity Image Format，Apptainer 使用的容器镜像文件格式。
HPCHigh Performance Computing，高性能计算环境；常使用无需 Docker daemon/root 的 Apptainer。
Provisioning创建、连接、健康检查和销毁 runtime 的部署生命周期，不包含统一命令/文件协议本身。
Fail-soft可选能力不可用时保留核心流程，例如非 Git workspace 请求 worktree 时继续使用原目录。
Containment路径 resolve 后仍位于授权 workspace 根内的约束，用于阻止 traversal 和外部 symlink。
Backpressure消费者处理速度低于生产者时限制数据流的机制；当前命令轮询没有显式流式背压协议。
