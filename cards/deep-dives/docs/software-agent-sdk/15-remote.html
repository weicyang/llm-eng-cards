1. 模块定位

RemoteConversation 是同步 Python 客户端代理：它不在客户端执行 Agent、LLM、工具或 Hooks，而是把 Agent 配置与 LocalWorkspace 形状发送到 Agent Server，服务端再创建并运行真正的 LocalConversation。 openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:694-780,819-886

边界本模块负责委托/明确不负责
控制面创建/附着、消息、run、pause、interrupt 等 REST 调用路由校验与执行由 Agent Server 负责
数据面接收 WS 事件，维护 RemoteState 与 RemoteEventsList 镜像规范持久状态仍在服务端 ConversationState/EventLog
完成语义arming、FULL_STATE 屏障、REST hard fallback、结束 reconcileStop hook 与运行循环在服务端执行
工具执行接收事件及 client tool 回调所需信息execute_tool() 对 RemoteConversation 明确不支持 openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:1658-1677

3. 核心概念

控制面（control plane）
改变服务端状态的 REST 命令，如 POST /run、/pause、/interrupt。
事件镜像（event mirror）
客户端缓存，不是持久化真相；WS 增量与 REST reconcile 共同补齐它。
arming
客户端在 run POST 返回后设置的门闩，只允许本次 run 期间的 FULL_STATE 成为完成候选，防止连接初始快照误结束下一次 run。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:951-991,1156-1189
字段级更新与 FULL_STATE
前者用于低延迟状态镜像；后者是完整 ConversationState 快照。只有 armed 后、服务端 run 尾部发布的非 RUNNING FULL_STATE 才是正常完成屏障。openhands-sdk/openhands/sdk/event/conversation_state.py:15-25,81-101
reconcile（对账）
分页读取全部远端事件，按 event ID 去重合并，修补 REST 初始读取与 WS 订阅/断线之间的缺口。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:319-402

4. 架构组成

4.1 WebSocketCallbackClient

独立 daemon thread 运行 asyncio WS 循环；首个状态事件置 ready，重连后调用 reconcile，非致命断线以 1 秒起步、最多 30 秒的指数退避重连，4001/4004 视为致命关闭。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:128-169,203-286

4.2 RemoteEventsList

构造时做一次全量分页同步；随后接受 WS 增量，以 RLock 保护缓存， 按时间戳有序插入并按 event ID 去重。reconcile 失败返回已取得的部分结果， 不让临时 REST 错误破坏现有镜像。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:289-317,349-402,441-491

4.3 RemoteState

_cached_state 为空时 REST GET；FULL_STATE 用字典 update 合并，字段事件 只更新单 key。客户端 setter 禁止修改 execution_status，明确状态所有权 在服务端。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:494-597

4.4 EventService

它创建后台 run task，优先使用原生 arun()，兼容 sync-only 实现时转入 executor；finally 先等待异步事件回调排空，再清除 run task 并发布 FULL_STATE。 openhands-agent-server/openhands/agent_server/event_service.py:1129-1221

5. 完整运行流程

5.1 正常成功路径

  1. 构造时创建或附着会话；注册动态 client tool 事件类型，再做 REST 事件初始同步。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:791-916
  2. 启动 WS，等待首个状态快照表示订阅已建立，然后 reconcile 订阅窗口内遗漏。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:997-1040
  3. send_message() POST 事件且固定 run=false，保持“显式 run”语义。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:1115-1134
  4. run() 清除 armed、排空旧信号，POST /run；blocking 模式随后 armed 并等待。409 表示已运行，不重复触发。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:1136-1189
  5. 服务端 EventService 后台执行 LocalConversation.arun；run 退出后等待 pending events，最后发布 FULL_STATE。openhands-agent-server/openhands/agent_server/event_service.py:1171-1221
  6. 客户端收到 armed 后非 RUNNING FULL_STATE，处理状态、reconcile 尾部事件并返回。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:1232-1261

5.2 Stop hook 拒绝：字段级 FINISHED 竞态

  1. Agent step 把状态设为 FINISHED，字段更新可先通过 WS 被客户端看见。
  2. LocalConversation 下一轮持锁执行 Stop hook；若 hook deny，则写入反馈、恢复 RUNNING 并继续。openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2082-2119
  3. 因此客户端忽略字段级 FINISHED；REST FINISHED 也只启动连续终态计时，不立即返回。
  4. 只有最终 run task 退出后的 FULL_STATE 完成屏障才结束等待。测试覆盖字段 FINISHED 与 REST FINISHED→RUNNING 回退。tests/sdk/conversation/remote/test_remote_conversation.py:1078-1220

5.3 WS 丢失：30 秒 hard fallback

若 REST 连续报告 terminal，客户端记录首次见到时间；任一次 RUNNING 或轮询异常都会 重置计时。连续满 30 秒仍无 post-run FULL_STATE，才刷新 RemoteState、reconcile 事件并返回。该阈值按单调时间计算，不按 poll 次数计算。 openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:1217-1229,1265-1318

5.4 Pause 与 Interrupt

Pause 在 worker thread 调用同步 LocalConversation.pause()，它等状态锁并在 step 边界生效；Interrupt 直接调用 LocalConversation.interrupt()，先取消 CancellationToken，再线程安全地取消在途 asyncio task。arun() 捕获 CancelledError，修补 orphan actions，写 PAUSED 与 InterruptEvent，不再 向上传播取消异常。openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2417-2481,2559-2614

6. 数据与状态模型

对象权威性生命周期/同步锁
服务端 ConversationState + EventLog规范运行状态与持久事件由 LocalConversation 修改，EventService 暴露快照/检索同步 FIFOLock；异步服务必须经 executor
RemoteState._cached_state镜像；REST refresh 或 WS 更新会话客户端存活期间threading.RLock
RemoteEventsList 缓存镜像；event ID 去重初始全量、WS 增量、重连/完成 reconcilethreading.RLock
_terminal_status_queue单次等待信号，不持久每次 run 前排空线程安全 Queue
_run_armed本地完成门闩，不持久POST 后 set，等待 finally clearthreading.Event

状态枚举包含 IDLE、RUNNING、PAUSED、WAITING_FOR_CONFIRMATION、FINISHED、ERROR、 STUCK、DELETING；其通用 is_terminal() 仅把 FINISHED、ERROR、STUCK 视作 terminal，特意排除初始 IDLE。openhands-sdk/openhands/sdk/conversation/state.py:48-79

镜像不是持久化中心。 FULL_STATE 的“权威”仅指它是本次远程 run 的完成屏障；持久化与恢复仍由服务端 ConversationState/EventLog 负责。RemoteState 的字段 setter 不能改变服务端状态。

10. 安全与信任边界

HTTP 认证 headers 由 RemoteWorkspace client 统一提供；WS 若有 api_key，连接后发送 {"type":"auth","session_api_key":"..."}，不把 key 放入 URL。 服务端也保留 query 参数兼容面，但首消息认证会校验配置中的 session keys，失败以 4001 关闭。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:213-232; openhands-agent-server/openhands/agent_server/sockets.py:190-230

  • Hooks、confirmation policy、security analyzer 与工具副作用都在服务端信任域执行；RemoteConversation 只提交配置/命令。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:831-866,1056-1057
  • secrets 创建后通过专用 REST 更新；SecretSource 序列化时显式暴露给目标服务端，因此传输安全依赖部署的 HTTPS/WSS 与服务端认证。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:1458-1481
  • 拒绝 pending actions 走 confirmation response endpoint，服务端生成 UserRejectObservation；客户端不直接篡改状态。openhands-sdk/openhands/sdk/conversation/impl/remote_conversation.py:1424-1434; openhands-agent-server/openhands/agent_server/event_router.py:217-226
不要把客户端镜像当授权依据。 RemoteState 可滞后或来自未完成的字段更新；准入、确认和 Hook 判定必须继续由服务端完成。

命令与事件传输REST + WS 双通道命令清晰、事件低延迟需要 reconcile 与完成屏障统一双向协议能提供同等兼容/恢复能力
最终完成post-run FULL_STATE建立“事件已 flush、run task 已退出”边界依赖 WS 最终投递服务端提供可查询 run generation/receipt
WS 丢失降级REST 连续 terminal 30 秒避免永久挂起且不轻易误判 Stop hook故障时至少额外等待 30 秒；常量不可配置有服务端权威 run-completed token
事件缓存全量分页 reconcile实现简单、按 ID 幂等历史增长时网络/CPU 成本上升观测到大历史瓶颈并引入可靠 cursor
同步 SDK 表面WS 后台 thread + blocking Queue兼容同步 Conversation API额外线程和跨线程协调公共 async RemoteConversation 成为一等接口

当前没有独立的远程 run ID/generation 随 FULL_STATE 传输；arming 只能按“POST 后” 这一时间边界过滤初始快照。并发调用同一 RemoteConversation 的多个 blocking run() 不是文档化支持场景，队列与单个 armed event 也未提供按 run 分区的信号。该限制来自当前结构，而不是已证明的并发安全保证。

17. 术语表

术语本章含义
RESTRepresentational State Transfer；本模块用于创建、命令与补偿查询的 HTTP API。
WS / WebSocket服务端向客户端持续推送事件与状态更新的双向连接。
FULL_STATEConversationStateUpdateEvent.key == "full_state" 的完整状态快照；post-run 版本承担完成屏障。
字段级更新key 为 execution_status、stats 等单字段的状态事件；用于镜像，不等同于 run 已退出。
armingPOST /run 后开启的本地门闩，用于排除订阅时或上一次 run 留下的快照。
reconcile通过 REST 重新读取并按 event ID 合并远端事件的对账操作。
hard fallback缺少 WS 完成快照时，以 REST 连续 30 秒 terminal 状态接受完成的最后降级路径。
terminal通用状态枚举中的 FINISHED、ERROR、STUCK；但远程正常完成仍需额外满足完成屏障。
Stop hookAgent 已报告 FINISHED 后、运行循环真正退出前执行的停止钩子；可拒绝停止并恢复 RUNNING。
Pause请求在 step 边界暂停；不会主动打断当前 async LLM 调用。
Interrupt取消在途 async task 与 CancellationToken，清理历史后进入 PAUSED 的即时中断。
CancelledErrorasyncio task 取消异常；在 LocalConversation.arun 内被消费并转换为 PAUSED + InterruptEvent。
orphan action已有 ActionEvent 但尚无 ObservationEvent 的工具调用；中断时以合成 AgentErrorEvent 配对修补。
RemoteState远端 ConversationState 的客户端缓存视图，不是可独立写入的状态所有者。
RemoteEventsList结合 REST 全量/对账与 WS 增量的只读事件镜像。
