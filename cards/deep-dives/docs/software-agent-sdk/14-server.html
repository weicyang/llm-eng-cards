1. 模块定位

Agent Server 是 SDK 之上的部署适配层：它拥有 HTTP/WS 协议、服务生命周期、会话驻留策略、 元数据目录和共享存储协调；真正的 Agent 推理、工具编排、状态机与事件树仍由 SDK 的 LocalConversation 完成。ConversationService 管理“会话集合”， EventService 管理“一个活跃会话”，两者都不是新的 Conversation 实现。 openhands-agent-server/openhands/agent_server/conversation_service.py:620-650 openhands-agent-server/openhands/agent_server/event_service.py:109-155

3. 核心概念

Catalog（目录）
启动时仅扫描每个会话的 meta.json 与 base_state.json 状态摘要， 不加载完整 EventLog；这是轻量查询层，不是另一个权威数据库。 openhands-agent-server/openhands/agent_server/conversation_service.py:655-716
Hydrate（实例化恢复）

Lease（所有权租约）
共享目录中的 owner_lease.json 记录 owner、generation、到期时间及可选 host/pid； generation 是 takeover 后阻止旧 owner 写入的 fencing token（隔离令牌）。 openhands-agent-server/openhands/agent_server/conversation_lease.py:18-37 openhands-agent-server/openhands/agent_server/conversation_lease.py:101-164
PubSub（发布/订阅）

FIFOLock
SDK ConversationState 使用的同步、公平、按 OS thread id 重入的锁；它不是 asyncio 锁， 同一 event-loop 线程上的不同 coroutine 会被视为“重入”，等待它也可能阻塞整个事件循环。 openhands-sdk/openhands/sdk/conversation/fifo_lock.py:14-43

9. 并发、性能与资源

9.1 三类锁不可互换

  • asyncio.Lock：_lifecycle_lock 串行 runtime map 变更；_run_lock 原子检查并创建 run task；InitService lock 串行初始化。
  • FIFOLock：同步保护 ConversationState 与 autosave，不得在 event loop 上阻塞等待。
  • 文件锁：EventLog、settings/secrets 和 lease 提供进程间写入互斥；其可靠性仍受文件系统影响。

读取执行状态、构造 full-state、更新 tags、发送消息及其他同步 Conversation 操作都跨 run_in_executor/to_thread；尤其 WS reconnect 的初始快照不能在 event loop 上等待 FIFOLock。openhands-agent-server/openhands/agent_server/event_service.py:631-667 openhands-agent-server/openhands/agent_server/conversation_service.py:1683-1724

FIFOLock 的 async 陷阱 锁按线程而非 task 标识 owner；同一 loop 上的另一个 coroutine 可能被当作重入，且直接同步等待会冻结 /ready 等无关请求。正确模式是在线程中完成“获取锁—快照/修改—释放锁”，锁释放后才 await 网络 I/O。 openhands-sdk/openhands/sdk/conversation/fifo_lock.py:28-31

9.2 任务、线程池与背压

  • 每个 Service 一个 ThreadPoolExecutor(max_workers=max_concurrent_runs)，只用于 sync run fallback；原生 async Agent 不占该 worker。
  • 所有活跃会话共用一个 15 秒 lease 续期 task，每次同步文件 I/O 通过 to_thread。
  • eviction 每 max(60, ttl/2) 秒扫描一次；只有无 run、goal、rerun 和外部 subscriber 的会话可卸载。
  • PubSub 并发通知 subscriber、逐订阅者隔离异常，但没有每订阅者持久队列；慢 subscriber 会延长该次 publish 完成时间。
  • 首次状态推送硬限 0.5 秒，超时只丢本次初始推送且保留订阅；后续 publish 没有同样的 per-subscriber timeout。

15. 设计权衡与已知限制

问题当前选择收益成本/失败模式重评条件
大量历史会话启动成本轻 catalog + 按需 hydrate启动不加载全部 EventLog首次实时访问有冷启动；损坏可能延迟暴露catalog 扫描成为启动瓶颈
多实例共享存储文件 lease + generation fencing无需中心数据库依赖锁/rename/时钟与 FS 契约跨区域、多主或 NFS 语义不足
async 与同步 SDK 状态worker thread 包裹同步临界区保持 SDK sync API 与自定义实现兼容线程切换与误用风险SDK 提供 task-aware async state API
事件实时传播内存 PubSub，无 durable per-client queue简单、低延迟、subscriber 故障隔离断线需重放/reconcile；慢 subscriber 延长 publish需要跨进程 fan-out 或严格投递 QoS
warm pool 安全启动健康端点可用，业务 API 503，独立 init key镜像可预热后注入用户配置无 secret 时 init endpoint 开放；ready 语义易误读编排器需要更细 readiness contract
Git 会话隔离可选独立 worktree，非 Git 静默降级同 repo 并行分支且保持子目录创建会 fetch/prune/删同名 branch；无完整 worktree 回收策略证据长生命周期部署出现磁盘累积

当前限制与证据缺口

  • lease 注释与测试只证明本地文件系统行为；EventLog 明示 NFS flock 不可靠，不能宣称任意共享存储安全。
  • PubSub 没有单订阅者 timeout（初始快照除外）或持久队列；当前仅有 subscriber 上限 50。
  • EventService._publish_state_update 附近注释仍称 PubSub 顺序迭代，与当前 gather 实现漂移；以实现为准。
  • 删除 conversation 只删除持久化目录并保留 workspace；独立 worktree 是否另行回收在所审计路径没有直接证据。
  • 本工作区没有可读取的 .git 元数据且 shell 找不到 Git，文档只能标记为“当前快照”。

17. 术语表

ASGI
Asynchronous Server Gateway Interface，Python 异步 Web 应用与服务器之间的接口规范；FastAPI 应用由 ASGI server 托管。
Catalog
本文指 ConversationService 在内存中的轻量会话目录，只含元数据和状态摘要，不含完整 EventLog。
Deferred init
延迟初始化；进程和无状态服务先启动，业务 Service 等编排器注入用户运行配置后再创建。
Dormant
休眠态；deferred server 已能响应健康与 init 路由，但受 gate 保护的业务 API 返回 503。
EventLog
SDK 的追加式事件文件序列；每个事件单独持久化，并保留事件树 parent 关系。
Eviction
驱逐；卸载空闲会话的内存 runtime，但不删除磁盘记录，后续可 hydrate。
Fencing token
隔离令牌；lease generation 在 takeover 时递增，使旧 owner 的后续写入校验失败。
FIFOLock
按请求顺序公平获取、按 OS 线程重入的同步锁；不是 asyncio task-aware lock。
Full-state snapshot
由 ConversationStateUpdateEvent.from_conversation_state 产生的完整状态更新；与单字段 update 不同。
Hydrate
根据 catalog 与持久化文件重新构造 EventService 和 LocalConversation 的过程。
Lease
有期限的会话 owner 声明；用于共享存储环境避免两个 Agent Server 同时拥有同一会话。
Lifespan
FastAPI/ASGI 的应用启动与关闭上下文，负责 Service 初始化、后台任务和资源回收。
LocalConversation
SDK 中真正拥有可变状态并执行 Agent 的本地 Conversation 实现；Agent Server 在进程内托管它。
OpenAPI
REST API 的机器可读契约；本仓库的公开兼容 gate 只过滤 /api 路径。
PubSub
Publish/Subscribe，发布/订阅；EventService 用它把事件和状态更新分发给 WS、webhook、telemetry 等 subscriber。
Reconcile
对账；远程客户端用 REST/EventLog 补齐可能因断线或实时流丢失的事件。
Split-brain
脑裂；两个 Service 同时认为自己拥有同一会话并写共享状态，lease 与 fencing 用于阻止它。
Worktree
Git worktree；同一仓库的独立工作目录与分支，Server 可按会话创建并保持原 workspace 的仓库内相对路径。
WS
WebSocket，双向长连接协议；本模块用于事件推送、历史重放和消息输入。
