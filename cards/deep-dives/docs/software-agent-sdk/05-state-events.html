1. 模块定位

本模块是 Conversation 的“可恢复记忆层”：ConversationState 保存当前可变状态， EventLog 追加完整事件，leaf_event_id 选中树的一条活跃分支， View 再把该分支投影为满足 LLM 历史约束的输入。事件不嵌入状态快照，而是独立持久化。 openhands-sdk/openhands/sdk/conversation/state.py:82-106,175-189,232-255

表面本模块负责委托/明确不负责
执行状态 状态值、终态判断、状态字段持久化与更新事件 具体何时结束、确认或重试由 Agent 与 LocalConversation 运行循环决定
历史 不可变 Event、父子关系、HEAD、活跃分支、追加与读取 事件业务内容由 Agent、Tool、Hook、Condenser 等生产者定义
LLM 上下文 从活跃分支派生并缓存 View Prompt 组装、模型调用和 condensation 策略属于上下文/LLM/恢复模块
恢复 加载快照与 EventLog、重建 View、调用 Agent 兼容校验 Workspace 外部副作用不能由事件回放自动撤销
远程同步 提供状态更新事件模型 REST/WS reconcile 与权威完成屏障属于 RemoteConversation/Agent Server
不要把枚举误读为集中式有限状态机。 当前实现没有统一的合法迁移表；运行循环、Agent、pause/interrupt 和删除流程直接赋值。 因而本文的箭头描述“当前代码路径会发生的迁移”，不表示模型层拒绝其他赋值。 openhands-sdk/openhands/sdk/conversation/state.py:48-79,580-607

3. 核心概念

State 与 EventLog

State 是“现在是什么”；EventLog 是“发生过什么”。状态快照不包含事件字段，二者共同恢复。

HEAD 与存储尾部

leaf_event_id 是下一事件的父节点，不一定是 EventLog 最后一个文件；navigate 后两者通常不同。

活跃分支与旁支

path_to_root(HEAD) 返回 root-first 活跃路径。旁支仍在磁盘，但不进入当前推理、pending action 检查与 stuck detection。

View 与 EventLog

View 只保留 LLM 可转换事件并应用 condensation 和结构属性；它不是事件审计日志，也不是第二份持久化。

每个 Event 默认生成 UUID 形式的 id，并带时间、来源与可空 parent_id； 模型为 frozen 且禁止未知字段。同一 EventLog 在追加时拒绝重复 ID。 __root__ 是显式新根的保留父 ID，不能作为事件自身 ID。 openhands-sdk/openhands/sdk/event/base.py:20-49 openhands-sdk/openhands/sdk/conversation/event_store.py:184-215 openhands-sdk/openhands/sdk/event/types.py:7-18

Action–Observation 的两层含义

  • 运行时 pending 判断：get_unmatched_actions() 找可执行且尚无 ObservationEvent/UserRejectObservation/AgentErrorEvent 的 Action。 openhands-sdk/openhands/sdk/conversation/state.py:661-701
  • LLM 历史合法性：View 要求每个 tool_call_id 恰有一个 observation-like 结果， 会在重建时丢弃不匹配项与重复结果。 openhands-sdk/openhands/sdk/context/view/properties/tool_call_matching.py:15-59 openhands-sdk/openhands/sdk/context/view/properties/observation_uniqueness.py:18-52

4. 架构组成

4.1 ConversationExecutionStatus

八个状态为 IDLE、RUNNING、PAUSED、 WAITING_FOR_CONFIRMATION、FINISHED、ERROR、 STUCK、DELETING。只有 FINISHED、ERROR、STUCK 的 is_terminal() 为真；IDLE 与 DELETING 都不在该集合。 openhands-sdk/openhands/sdk/conversation/state.py:48-79

4.2 ConversationState

State 的 Pydantic public fields 是快照内容；_events、_view、锁、FileStore、Cipher 和 callback 是 PrivateAttr，不进入快照。公共字段改变会自动保存；在 with state 内多次改变合并成一次落盘。 openhands-sdk/openhands/sdk/conversation/state.py:232-257,580-629,728-749

4.3 EventLog

EventLog 同时维护 index↔ID 映射与按 index 的反序列化缓存。append 在 FileStore 锁下同步磁盘长度、拒绝重复 ID 和不存在的显式 parent， 然后写单个 JSON 文件并更新内存索引。 openhands-sdk/openhands/sdk/conversation/event_store.py:30-57,184-233

4.4 View 与属性系统

View.append_event() 处理 Condensation、CondensationRequest 与 LLMConvertibleEvent； 其他控制/状态事件跳过。全量 from_events() 最后递归执行四类属性： observation 唯一、batch 原子、tool-call 匹配、tool-loop 原子。 openhands-sdk/openhands/sdk/context/view/view.py:111-160 openhands-sdk/openhands/sdk/context/view/properties/__init__.py:14-28

4.5 缓存策略

View 用 _view_branch_leaf 作水位：相同 HEAD 直接复用；缓存 HEAD 是新 HEAD 祖先时只追加尾部； 分支切换、增量失败或显式恢复时全量重建。重建成功才替换旧缓存，失败会向上传播并保留旧对象。 openhands-sdk/openhands/sdk/conversation/state.py:336-395

5. 完整运行流程

5.1 正常成功：消息 → Action → Observation → FINISHED

  1. send_message() 只接受 user role；若原状态是 FINISHED/STUCK，先重置为 IDLE，再发出 MessageEvent。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1761-1792,1818-1824
  2. run() 将 IDLE/PAUSED/ERROR/STUCK 置 RUNNING。Agent 每步先从活跃分支找 unmatched actions； 有 pending action 就先执行，不采样新 LLM 响应。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1856-1883 openhands-sdk/openhands/sdk/agent/agent.py:636-653
  3. 新事件在权威追加点补 parent，写 EventLog，再将 HEAD 推到该事件；状态同步事件不推进 HEAD。 openhands-sdk/openhands/sdk/conversation/state.py:304-334
  4. 下一步读取 state.view，增量投影活跃分支；Agent 完成时置 FINISHED。运行循环下一轮仍先执行 Stop hook， hook 允许后才真正退出。 openhands-sdk/openhands/sdk/agent/agent.py:678-687 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1897-1925

5.2 拒绝/提前结束：确认与 Hook

  1. ActionEvent 已经产生并进入事件历史后，风险分析与 confirmation policy 可把状态置 WAITING_FOR_CONFIRMATION。
  2. 下一次 run 将该状态清回 RUNNING，Agent 发现 unmatched actions 并执行；若用户调用 reject_pending_actions()，则状态回 IDLE，并为每个 pending Action 追加 UserRejectObservation，使 tool history 闭合。 openhands-sdk/openhands/sdk/agent/agent.py:1052-1064 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1931-1938,2489-2527
  3. PreToolUse hook 阻止也用 UserRejectObservation，但 rejection_source="hook" 可与用户拒绝区分。 openhands-sdk/openhands/sdk/event/llm_convertible/observation.py:86-107
  4. Stop hook 可拒绝 FINISHED：可选反馈作为 environment MessageEvent 进入历史，状态回 RUNNING，循环继续。 这说明“看到 FINISHED 字段”不等于服务端运行已完成。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1897-1924

5.3 中断与恢复：修补 orphan Action

  1. interrupt() 取消正在执行的 async task；CancelledError 在 arun() 捕获。
  2. 在 State 锁内，运行时扫描活跃分支上未匹配的 Action，为每个 Action 追加合成 AgentErrorEvent，再置 PAUSED 并发出 InterruptEvent。 openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2417-2452,2529-2557
  3. 下次 run 可从 PAUSED 进入 RUNNING；闭合后的 Action–result 历史避免严格 provider 因孤立 tool call 拒绝请求。

5.4 冷恢复：resume + verify

  1. 读取 base_state.json；存在时用可选 Cipher context 反序列化 State。
  2. 校验 conversation ID，连接同一 FileStore 上的 EventLog，随后从活跃分支全量重建 View。
  3. agent.verify() 要求 Agent 具体类一致，运行时工具集合不能移除历史工具；允许增加工具，也允许更换 LLM、context、condenser 等配置。 openhands-sdk/openhands/sdk/conversation/state.py:512-553 openhands-sdk/openhands/sdk/agent/base.py:670-736
  4. 验证通过后采用运行时 Agent、Workspace 与 max_iterations；历史 stats 和其他持久字段保留。

6.2 树身份与遗留线性规则

  • 新事件显式 parent 指向当前 HEAD；显式 parent 不存在时 append 拒绝。
  • 老事件没有 parent：index 0 是根，其余隐式指向 index−1，无需重写历史文件。
  • navigate_to(None) 用持久化的 head_is_empty 区分“主动空 HEAD”和“旧快照未设置 leaf”。
  • 在非空日志上创建新根时用 ROOT_PARENT_ID，避免被遗留规则误链到存储尾部。

openhands-sdk/openhands/sdk/conversation/event_store.py:91-126,184-215 openhands-sdk/openhands/sdk/conversation/state.py:263-313

6.3 生命周期、事务与清理

State 字段与 Event 文件不是一个跨文件原子事务：EventLog 单文件 append 受锁保护，State 快照另行 autosave。 with state 只把多个字段改变合并成一次快照写入，并不把事件文件与快照组成数据库事务。 EventLog 当前也没有 clear API；fork 复制事件，navigate 保留旁支。 openhands-sdk/openhands/sdk/conversation/state.py:580-607,728-749 tests/sdk/conversation/test_event_store.py:192-213

6.4 Secret 与隐私

有 Cipher 时快照中的 secrets 加密；没有 Cipher 时会警告并以 ********** 保存，恢复后原值丢失。 Event payload 本身没有由本模块提供的通用加密层，因此生产者不应把 secret 明文放进事件。 openhands-sdk/openhands/sdk/conversation/state.py:420-442 tests/sdk/conversation/local/test_state_serialization.py:844-922,925-1007

9. 并发、性能与资源

  • State 用可重入 FIFO 线程锁保证等待顺序并避免线程饥饿；同一 OS 线程上的 asyncio tasks 会被视为重入， 因而不能把它当 coroutine mutex。 openhands-sdk/openhands/sdk/conversation/fifo_lock.py:14-31,45-96

  • EventLog append 使用 FileStore 进程锁，并在获得锁后同步其他进程新增文件；LocalFileStore 的 flock 在 NFS/网络文件系统上不可靠。 openhands-sdk/openhands/sdk/conversation/event_store.py:30-41,194-227
  • View 另用 threading.RLock 保护缓存；线性追加成本为新增尾部 O(k)，分支切换/恢复全量重建 O(n)。 openhands-sdk/openhands/sdk/conversation/state.py:235-242,336-395
  • EventLog 的 limit 从 leaf 回溯，最近窗口为 O(limit)；反序列化结果按 index 缓存，但源码没有独立缓存淘汰策略。 openhands-sdk/openhands/sdk/conversation/event_store.py:106-126,140-181

9.1 论文事件溯源实验与仓库复现口径

“deterministic replay”的边界： 论文 §4.2 的设计表述指从已持久化 事件重建 SDK 内存历史、View 与未匹配 Action 检测可重复；当前恢复同时还读取 base_state.json，并不会重新执行、验证或回滚终端命令、文件写入、 HTTP 请求等外部副作用。因而它不是环境的完整执行重演，也不保证外部世界与事件日志 处于事务一致状态。 openhands-sdk/openhands/sdk/conversation/state.py:512-553 scripts/event_sourcing_benchmarks/README.md:7-13,117-132
没有事件级背压队列。大量事件对应大量独立文件与内存索引；本文不推断容量上限或延迟 SLA。 测试证明六位 index 可冷加载，不等于给出生产容量保证。

10. 安全与信任边界

本模块不做用户鉴权或 Tool 授权。它保存 confirmation policy、security analyzer、blocked action/message 等决策状态， 但确认与 Hook 的准入发生在 Agent/LocalConversation。Action 必须先作为事件存在，随后才可能等待确认、执行或被拒绝。

  • Event 的 Pydantic 模型通常通过 frozen/extra 约束校验形状；EventLog 还校验重复 ID 与 parent 存在性。
  • 事件来源 source 是数据字段，不是密码学身份；不要据此单独做授权。
  • FileStore 目录、事件文件和 base_state.json 的访问控制由部署环境负责。
  • State secrets 可加密或脱敏；事件没有自动 secret 扫描/加密，回调与日志也可能暴露事件内容。
  • execute_tool() 可绕过正常 Agent 确认链；这是相邻接口的显式能力，不由 EventLog 防护。

禁止捷径

  • 不要让业务调用方绕过 ConversationState.append_event() 写新运行时事件，否则 HEAD 可能不推进；fork 的预盖章复制是有意例外。
  • 不要用 EventLog 存储尾部代替 HEAD；navigate 后它们语义不同。
  • 不要直接持久化 View；它必须可由事件活跃分支重新推导。
  • 不要删除 deprecated event/message field handler，即使当前 writer 已不再输出旧字段。
  • 不要把旁支 orphan Action 当当前 pending work；扫描必须传 active_branch()。

15. 设计权衡与已知限制

问题当前选择与收益成本/失败模式重评条件
事件存储每事件一文件，易增量写、检查与局部读取大量小文件、跨文件无事务、index 缺口截断文件系统成为主瓶颈或需要原子多事件提交
分支模型parent + movable HEAD，不删除旁支，fork/navigate 简单可追溯磁盘只增不减；旁支与活跃分支容易被调用方混淆需要 GC、合并分支或跨会话共享节点
View cache线性追加 O(k)，分叉时按需 O(n) 重建旧 View 引用在 rebuild 后失效；全量属性只在重建执行热路径需要持续增量验证或超长分支重建成本不可接受
遗留 parent 兼容无迁移按 index−1 解释，旧磁盘数据原样加载None 同时承载旧形状与真实根，需要 sentinel/head_is_empty 消歧未来引入明确事件 schema version 与离线迁移
恢复验证禁止移除工具，允许配置演进，兼顾历史安全与运行时升级工具重命名等同移除；Workspace 外部状态仍可能漂移有可靠工具别名/迁移协议或可验证副作用快照
永久兼容旧生产会话始终可加载handler 永久累积，模型维护成本增加只有明确切断持久化兼容面且有独立归档转换器时才可讨论
EventLog + base snapshot 是 “Event Sourcing Lite”，不是完整事件溯源数据库：State 不是纯事件 reducer 的产物， 外部 Tool 副作用也不由事件回放重建或回滚。恢复保证的是 SDK 会话结构与 LLM 历史可继续处理，不是环境事务一致性。

17. 术语表

术语本章含义
ActionAgent/LLM 提出的工具调用事件；只有 action 非空时才被视为可执行 pending action。
Observation工具执行、用户/Hook 拒绝或 Agent 错误形成的 tool result；用 action ID 或 tool-call ID 与 Action 配对。
orphan Action活跃分支中已有可执行 Action、但尚无任何匹配 Observation-like 结果的事件。
EventLog保存全部分支事件的文件型追加日志；不是当前 LLM 上下文。
Event tree由 Event 的 parent_id 建立的树；同 parent 的事件是 sibling branches（兄弟分支）。
HEAD / leafleaf_event_id 指向当前活跃分支末端，也是下一新事件的默认 parent。
active branch从 HEAD 沿 parent 回到根、再按 root-first 返回的当前事件路径。
View活跃分支经 condensation 与结构属性处理后的 LLMConvertibleEvent 线性投影。
watermarkView cache 的 _view_branch_leaf，记录缓存已投影到哪个 HEAD。
fork创建新 Conversation，并复制全日志或指定事件的 root path；源会话保持不变。
navigate在原 Conversation 内移动 HEAD；不复制、不删除事件，后续 append 可形成旁支。
resume从 base snapshot 与 EventLog 恢复 State、重建 View，并使用 runtime Agent 继续。
deterministic replay本文限定为从已持久化 SDK 状态与事件可重复重建内存历史及恢复扫描；不表示重新执行或回滚 Workspace、网络等外部副作用。
verifyresume 时检查 Agent 具体类型与工具向后兼容；不是事件内容的完整业务校验。
terminal stateis_terminal() 判定的 FINISHED、ERROR、STUCK；IDLE 和 DELETING 不属于该集合。
Condensation记录“忘记哪些事件、可插入何种摘要”的事件；应用于 View，不删除 EventLog 文件。
LLMConvertibleEvent可转换成 LLM Message 的 Event；状态同步、Pause 等控制事件通常不进入 View。
ROOT_PARENT_ID__root__ 保留 sentinel，用于在非空 EventLog 中显式创建独立根。
artifact本章特指状态同步/会话错误等运行时记录；它们可在 EventLog 中，但不应被误当作 legacy tree 的有效 HEAD。
FileStoreState/EventLog 使用的存储抽象；可落本地文件，也可仅在内存中存在。
FIFOFirst In, First Out（先进先出）；State 线程锁按请求顺序授予访问。
LLMLarge Language Model（大语言模型）；本章关注发送给它的历史结构，不展开 transport。
NFSNetwork File System（网络文件系统）；当前 LocalFileStore flock 在此类共享存储上不保证可靠。
