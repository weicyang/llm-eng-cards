1. 模块定位

Condenser（上下文压缩器）不是事件存储，也不是 Conversation 状态机；它接收只读 View，返回可直接转成 LLM messages 的新 View，或返回一条待追加的 Condensation 事件。基类还明确要求实现不得原地修改 Conversation 缓存的 View。openhands-sdk/openhands/sdk/context/condenser/base.py:16-62

3. 核心概念

View 与 EventLog

View 是活跃分支中“当前可给 LLM 的事件”投影，不是规范历史；加载时按事件顺序应用 request 与 condensation，并执行历史合法性约束。openhands-sdk/openhands/sdk/context/view/view.py:142-160

Soft 与 Hard

Soft 表示希望压缩但失败后仍可用原 View 继续；Hard 表示本轮不能跳过，普通压缩不可用时尝试 hard context reset。openhands-sdk/openhands/sdk/context/condenser/base.py:95-105

Retry 与 Fallback

Retry 对同一 LLM 的白名单瞬时异常重试；Fallback 在主模型重试耗尽后按配置尝试其他 profile。两者都不改变 Conversation 历史。openhands-sdk/openhands/sdk/llm/utils/retry_mixin.py:76-102 openhands-sdk/openhands/sdk/llm/fallback_strategy.py:39-45

Nudge 与 Condensation

Nudge 是新增一条纠正性 user-role 事件让模型改答；Condensation 改变后续 View 的历史投影。空/纯 reasoning 响应走前者。openhands-sdk/openhands/sdk/agent/response_dispatch.py:252-272

Malformed history 不等于 context overflow。 前者表示 tool_use/tool_result 等消息结构不合法，通常提示事件流、恢复或顺序问题； 后者表示输入超过模型上下文容量。两者使用不同 SDK 异常，仅在 Agent 恢复动作上都可能 汇合到 CondensationRequest。openhands-sdk/openhands/sdk/llm/exceptions/types.py:57-77

15. 设计权衡与已知限制

问题当前选择收益成本/失败模式重评条件
追加式历史如何“遗忘”追加 tombstone-like Condensation，在 View 投影应用保留审计与恢复原始历史View 重建与事件兼容更复杂事件量或重建成本成为实测瓶颈
压缩粒度保留开头、摘要中段、保留最近尾部兼顾早期目标与近期连续性摘要可能丢细节；prompt cache 被破坏质量评测证明其他 memory 策略更优
Soft failure保留原 View 继续event 阈值启发式不会中断任务历史可暂时超过期望 event 上限模型输入已接近硬容量时应依赖 token hard trigger
Hard reset总结整个 View并逐次截短事件字符串在普通边界不可用时仍有恢复机会上下文损失最大；每次外层 attempt 还可能触发摘要 LLM 自身 retry出现高成本或低恢复率的实测证据
Async fallback在线程池运行同步备用调用复用成熟同步 fallback 逻辑不是真正 async transport，线程资源受外部 executor 管理高并发 fallback 显示线程池压力
Malformed 恢复先 enforce 重建 View，再压缩能修复部分结构性历史并保留独立诊断可能掩盖上游事件流 bug，且不是所有 malformed 都可由遗忘修复同一错误重复出现时应调查 persistence/resume
成本优化通过摘要约束后续每步输入 token论文 §4.6 引用的特定实验最高约 2× 成本降低且解决率未降摘要本身收费且可能丢失细节；收益依模型、任务、价格和阈值而变目标 workload 的成本/质量评测不再复现实验趋势

当前明确的证据缺口：没有发现 PipelineCondenser 专门单元测试；本次文档工作未 执行需要真实模型与凭据的 a/c integration；工作区没有可读取的 Git 元数据，无法把页面绑定 到具体 SHA。这些缺口不应以推测的 provider SLA、成功率或容量数字填补。

17. 术语表

术语本章含义
Condenser把 Conversation 的 LLM 可见 View 缩小，或产生压缩事件的策略对象。
Condensation记录遗忘 event IDs、摘要和插入位置的持久事件；不是已删除历史的副本。
CondensationRequest请求下一次 compatible condenser 必须尝试压缩的内部事件。
View活跃事件分支经 condensation 与历史合法性规则投影后的 LLM 可见事件序列。
Soft requirement希望压缩，但暂时失败时仍允许使用原 View 继续的要求。
Hard requirement必须在继续调用 Agent LLM 前完成压缩，否则只能降级或报错的要求。
Hard context reset普通遗忘范围不可用时，对整个 View 生成摘要的高损失恢复方式。
Retry对同一个 LLM 和同一次逻辑请求，按白名单异常与退避预算重新尝试。
Fallback主 LLM 重试耗尽后，改用按顺序配置的备用 LLM profile 完成本次调用。
Nudge框架注入的纠正性 user-role 消息，用于让模型改变下一次输出。
Malformed history消息结构不符合 provider 协议，如 tool_use/tool_result 缺失、重复、错序或 ID 不匹配。
Context overflow模型输入超过当前 route/model 可接受的上下文窗口，不表示消息结构一定非法。
Manipulation index同时满足所有 View properties、可安全插入摘要或切割事件的边界。
LLM profile可由 profile store 加载、包含模型与连接配置的备用 LLM 定义。
AttemptTenacity 预算中的一次实际 transport 调用；当前 num_retries 表现为总 attempts，而非“首次外加 N 次”。
2× cost reduction论文 §4.6 引用的特定外部实验中，压缩后每轮成本最终低于 baseline 一半的经验总结；不是 SDK 成本 SLA。
API compliance test直接向真实 provider 发送特定非法消息排列，记录接受或拒绝行为的 a-suite 测试。
