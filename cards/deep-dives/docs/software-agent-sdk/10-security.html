1. 模块定位

本模块不是一个统一“安全沙箱”。它由四个相互独立的控制面组成：SecurityAnalyzerBase给 Action 分级，ConfirmationPolicyBase把风险映射为是否等待用户，Hook 在生命周期节点允许、拒绝或补充上下文，Tool/Workspace 最终执行副作用。分析器接口只接收已验证的 ActionEvent 并返回 SecurityRisk。openhands-sdk/openhands/sdk/security/analyzer.py:15-39

论文基线：官方论文 arXiv:2511.03690 §4.9 已把两项职责分开：SecurityAnalyzer只评估 LOW / MEDIUM / HIGH / UNKNOWN，ConfirmationPolicy才决定是否要求用户批准。论文 §7 同时明确，LLM 安全分析会受对抗提示和分类不一致影响，因而不能提供完整安全保证。本文以下“当前事实”以源码为准；论文结论只用于说明 V1 设计基线。

职责本模块负责委托或明确不负责
风险分类对待执行 Action 给出 LOW / MEDIUM / HIGH / UNKNOWN不直接决定 UI、身份或工具授权
用户确认根据 policy 决定是否进入 WAITING_FOR_CONFIRMATION调用 run() 表示批准；拒绝由 Conversation API 写入 Observation
生命周期策略六种 Hook 事件、命令/Prompt/Agent 三类执行器、阻断与审计事件不提供操作系统级隔离；命令 Hook 本身运行在宿主工作目录
副作用在 PreToolUse 阻断后阻止对应 Action 进入 Tool executorTool 与 Workspace 模块拥有实际命令、文件、网络等能力
鉴权无通用用户鉴权模型Agent Server/部署层负责 REST、会话和租户鉴权
边界结论：NeverConfirm 是状态和启动请求的默认 policy；因此“配置了风险描述”不等于“启用了确认”。openhands-sdk/openhands/sdk/conversation/state.py:119-127 openhands-sdk/openhands/sdk/conversation/request.py:129-137

3. 核心概念

  1. LLM tool call 经名称规范化、参数修复和 Pydantic Action 校验；失败会发 ActionEvent（action=None）与 AgentErrorEvent，不进入确认或执行。openhands-sdk/openhands/sdk/agent/agent.py:1199-1315

  4. Analyzer 为每个 Action 计算风险；policy 对每个风险决策。任一返回 true，则整批等待；全部 false 才继续。openhands-sdk/openhands/sdk/agent/agent.py:1025-1066

17. 术语表

Action
模型工具调用经规范化与 Schema 校验后形成的可执行意图，以 ActionEvent 持久化。
Observation
工具执行、用户拒绝或 Agent 错误对 Action 的结果；用于维持工具调用与结果配对。
SecurityAnalyzer
安全分析器；只负责给 Action 分类风险，不决定是否询问用户。
ConfirmationPolicy
确认策略；把 SecurityRisk 映射为“执行前是否必须等待用户”。
Defense in depth
纵深防御；组合彼此独立的检测、确认、Hook 与隔离层，以降低单点失效影响，但不承诺绝对安全。
SecurityRisk
LOW、MEDIUM、HIGH、UNKNOWN 四级风险；UNKNOWN 不参与数值式排序。
WAITING_FOR_CONFIRMATION
等待确认状态；非终态，表示 EventLog 中存在尚无结果的待批 Action。
Pending / unmatched Action
活跃事件分支上尚未被 Observation、UserRejectObservation 或 AgentErrorEvent 配对的可执行 Action。
Hook
生命周期钩子；在用户消息、工具前后、会话起止或 Agent 停止时运行的策略/自动化。
PreToolUse / PostToolUse
分别在工具执行前和结果事件转发前触发；只有同步 PreToolUse 能阻止副作用。
UserPromptSubmit
用户 MessageEvent 进入 Agent 前触发，可阻断消息或向 extended_content 注入上下文。
Stop deny
Stop Hook 拒绝 Agent 结束，使 FINISHED 回到 RUNNING，并可注入返工反馈。
fail-safe
故障时选择更保守结果；本模块特指 Analyzer 异常转 HIGH，但最终是否阻断仍取决于 policy。
fail-open
控制组件故障时允许主操作继续；Hook 超时、普通非零退出和无效 LLM verdict 多数采用此行为。
fail-closed
控制组件故障时拒绝主操作；当前 Hook 执行器没有通用 fail-closed 配置。
HookExecutionEvent
持久化的 Hook 审计事件，记录触发类型、命令/标签、结果、输出和关联 Action/Message id。
EventLog
按事件独立存储的追加日志；与 base_state.json 一起支撑确认、拒绝和恢复。
Active branch
由 leaf_event_id 指向的当前事件树分支；pending Action 只从该分支计算。
execute_tool 旁路
受信程序化 API 直接调用工具；不进入 Agent loop，也不经过确认、安全分析和 Hooks。
LLM
Large Language Model，大语言模型；可用于主 Agent、风险标注以及 Prompt/Agent Hook，但其输出仍是不可信输入。
