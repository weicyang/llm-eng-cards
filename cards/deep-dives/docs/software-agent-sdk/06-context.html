上下文工程：从事件分支到可调用 Skills

本章解释 SDK 如何把活跃事件分支约束成合法的 LLM 历史，把系统提示拆成 STATIC/DYNAMIC 两个缓存层，并通过触发注入与 invoke_skill 实现渐进式披露。

1. 模块定位

上下文工程不是一份字符串，而是三条相互衔接、所有权不同的管道： 历史投影（View）、系统提示组装 （PromptSection/PromptRegistry）和 按需知识披露（AgentContext/Skill）。 View只接收可转换为 LLM 消息的事件，并在构造完成后执行属性修复。 openhands-sdk/openhands/sdk/context/view/view.py:22-33,142-160

表面负责委托明确不负责
View 活跃分支的 LLM 可见历史、压缩语义、结构合法性 分支选择给 ConversationState；裁剪策略给 Condenser 不是 EventLog，也不持久化自身
Prompt Registry 按顺序 guard/render，并分入 STATIC/DYNAMIC 动态数据解析给 AgentContext；provider 缓存标记给 LLM 不执行 I/O，不保存会话状态
AgentContext / Skills 技能目录、suffix、memory 文本、secret 元信息和时间的规范化 项目技能与 memory 的磁盘解析给 LocalConversation 不拥有完整事件历史或 Condenser

AgentContext明确将项目 skills 和 memory 延迟到会话知道 workspace 后再加载；memory_context仅携带解析结果并排除序列化。 openhands-sdk/openhands/sdk/context/agent_context.py:127-170

2. 系统位置与依赖

EventLog 的活跃分支 └─ ConversationState.view（派生缓存） ├─ View.append_event：应用 Condensation / 过滤非 LLM 事件 ├─ View properties：约束可裁剪边界与修复非法历史 └─ Condenser（只读输入）→ View 或 Condensation Agent + ConversationState.secret_registry └─ Agent._build_prompt_context └─ AgentContext._resolve_dynamic_data └─ PromptRegistry.build ├─ STATIC → SystemPromptEvent.system_prompt └─ DYNAMIC → SystemPromptEvent.dynamic_context Skill catalog ├─ catalog 元数据 → <available_skills> ├─ keyword/task 命中 → MessageEvent.extended_content ├─ path 命中 → ObservationEvent.extended_content └─ invoke_skill Action → 完整正文 → InvokeSkillObservation

SystemPromptEvent把静态和动态文本放进同一 system message 的两个 content block；事件本身不加缓存标记，真正的 provider 特定标记由 LLM._apply_prompt_caching()处理。 openhands-sdk/openhands/sdk/event/llm_convertible/system.py:12-40,72-85

组件所有者路径依赖方向进程边界

3. 核心概念

View 与 EventLog

EventLog 是权威事件记录；View 是当前活跃分支上、已应用压缩语义的派生投影。 缓存字段是 PrivateAttr，明确“never persisted”。 openhands-sdk/openhands/sdk/conversation/state.py:232-243

Memory 与 Context

Memory 是磁盘上的持久索引；Context 是本次模型调用可见的信息集合。 只自动读取两级 MEMORY.md，daily log 不自动注入。 openhands-sdk/openhands/sdk/context/memory.py:1-24,55-80

STATIC 与 DYNAMIC

这是 section 的组装层级，不等于“永不变化/总是缓存”。STATIC 对同一 agent 配置跨会话稳定；是否加 provider cache marker 仍由 LLM 能力决定。 openhands-sdk/openhands/sdk/context/prompts/section.py:24-31,133-143

Progressive Disclosure

渐进式披露先展示 name/description，再通过触发器或 Tool 注入正文； AgentSkills 格式与 legacy 无触发 skill 的行为不同。 openhands-sdk/openhands/sdk/skills/skill.py:178-194

易混点：invoked_skills记录显式 Tool 调用； activated_knowledge_skills记录消息触发； activated_path_rules记录文件路径触发。三者都是会话状态中的独立去重集合。 openhands-sdk/openhands/sdk/conversation/state.py:129-150

4. 架构组成

4.1 View 属性系统

属性有两种机制：manipulation_indices()给 Condenser 合法切点， enforce()在坏数据或恢复场景返回应删除的事件 ID。正常设计依靠合法 切点归纳保持不变量，enforcement 是后备修复。 openhands-sdk/openhands/sdk/context/view/properties/base.py:8-25,28-59

属性（执行顺序）不变量修复/限制故障隔离
ObservationUniqueness 每个 tool_call_id 最多一个 observation-like event 保留首次、删除后续重复；不限制切点 必须先于 matching，避免后者 remove 时异常
BatchAtomicity 同一 llm_response_id 的 Action batch 全有或全无 部分缺失则删掉 view 中整批；批内不可切 对照 all_events 识别完整 batch
ToolCallMatching Action 与 observation 按 tool_call_id 一一对应 删除孤立双方；pending 区间不可切 重复 observation 不被静默容忍
ToolLoopAtomicity 带 thinking block 开始的连续工具循环全有或全无 部分存在则删除剩余片段；循环内部不可切 保护 Anthropic thinking/checksum 结构

注册顺序固定为 uniqueness → batch → matching → tool loop。 openhands-sdk/openhands/sdk/context/view/properties/__init__.py:14-20 各属性实现分别见 openhands-sdk/openhands/sdk/context/view/properties/observation_uniqueness.py:18-74、 openhands-sdk/openhands/sdk/context/view/properties/batch_atomicity.py:10-88、 openhands-sdk/openhands/sdk/context/view/properties/tool_call_matching.py:15-100、 openhands-sdk/openhands/sdk/context/view/properties/tool_loop_atomicity.py:14-126。

4.2 PromptSection 与 Registry

PromptContext是冻结快照，连嵌套的 template_kwargs 也复制为只读 MappingProxy；section 的 guard与render 必须纯函数、无 I/O。 openhands-sdk/openhands/sdk/context/prompts/section.py:52-87,103-130

Registry 按注册顺序执行；guard false、render None 或空白均不产出，非空文本 strip 后按 tier 用两个换行连接。重名 register 报错，replace 原位覆盖。 openhands-sdk/openhands/sdk/context/prompts/registry.py:26-64

4.3 AgentContext 与 Skills

动态解析先分区 skills，再按模型 family 过滤名为 claude/gemini 的 legacy repo 指令，生成 catalog，合并 secret 元信息（conversation registry 同名项覆盖），最后格式化时间。 openhands-sdk/openhands/sdk/context/agent_context.py:327-350,396-449

to_prompt()只输出 name/description，并故意省略 location； description 最多取 1024 字符，发生截断时附加调用 invoke_skill 的提示。 openhands-sdk/openhands/sdk/skills/skill.py:1431-1511

5. 完整运行流程

5.1 正常成功：事件到模型上下文

  1. ConversationState.append_event()给事件补 parent_id、写 EventLog、推进 HEAD。 openhands-sdk/openhands/sdk/conversation/state.py:304-334
  2. 读取 state.view时，如缓存 leaf 是新 leaf 的祖先，只回放 tail； 分支切换则从 active branch 全量重建。 openhands-sdk/openhands/sdk/conversation/state.py:336-381
  3. Agent 解析 template kwargs 与动态数据，Registry 生成两块文本，并发出一个 SystemPromptEvent。 openhands-sdk/openhands/sdk/agent/base.py:419-496 openhands-sdk/openhands/sdk/agent/agent.py:524-544
  4. system event 转为两个 content block；启用且 provider 支持时，LLM 只标记静态块， 动态块保持未标记。 tests/sdk/llm/test_prompt_caching_cross_conversation.py:72-144

5.2 正常成功：渐进披露与显式调用

  1. AgentSkills 或有触发器的 legacy skill 进入 catalog；正文不常驻 system prompt。
  2. 模型发出 InvokeSkillAction(name)，executor trim 名称、精确查找、 在 workspace cwd 渲染正文，记录去重后的 invocation，并返回 Observation。 openhands-sdk/openhands/sdk/tool/builtins/invoke_skill.py:90-123
  3. 若 skill 来源是实际文件，结果附资源目录；在 workspace 内时使用相对路径避免泄露 home 绝对路径。 openhands-sdk/openhands/sdk/tool/builtins/invoke_skill.py:125-160

5.3 拒绝/提前结束

未知名称返回 error Observation，并列出可直接调用的名称；被 disable_model_invocation禁用的 skill 返回“只能由 trigger 激活”。 两条路径都不会写 invoked_skills。 openhands-sdk/openhands/sdk/tool/builtins/invoke_skill.py:95-116 tests/sdk/tool/test_invoke_skill.py:270-321

5.4 恢复/降级

冷加载、fork、导航或错误恢复调用 rebuild_view()，从 active branch 重建并执行全部属性；属性删除事件后从第一项重新检查，直到稳定。若重建抛错， 旧缓存保持不变并继续抛出异常。 openhands-sdk/openhands/sdk/context/view/view.py:74-109 openhands-sdk/openhands/sdk/conversation/state.py:383-395 tests/sdk/conversation/test_state_view_cache.py:219-231

9. 并发、性能与资源

  • View 读取由 RLock保护；线性 append 只回放新增 tail，复杂度为 O(k)， 分支切换全量 O(n)。热路径不执行属性 enforcement。 openhands-sdk/openhands/sdk/conversation/state.py:336-395
  • public skills 使用进程级 dict + threading.Lock；可变 ref TTL 为 60 秒， pinned tag/SHA 用 infinity 时间戳缓存到进程结束，且空结果不缓存。 openhands-sdk/openhands/sdk/skills/skill.py:1127-1151,1345-1353
  • Jinja 兼容路径缓存 64 个 Environment、256 个 Template，并使用用户目录下的 FileSystemBytecodeCache；模板 mtime 变化可使 loader 判定失效。 openhands-sdk/openhands/sdk/context/prompts/prompt.py:16-45,57-85
  • 同名 skill invocation 声明资源 key skill:<name>，允许不同 skill 并行、同一 skill 串行。 openhands-sdk/openhands/sdk/tool/builtins/invoke_skill.py:163-172
  • inline command 每条默认超时 10 秒，stdout 上限 50 KiB；这里没有全局队列或重试预算。 openhands-sdk/openhands/sdk/skills/execute.py:28-32,52-95

10. 安全与信任边界

关键边界：repo skill 与 memory 内容会被明确标为 UNTRUSTED_CONTENT，但 invoke_skill渲染中的 !`command`会以当前进程权限、shell=True执行。 因而 Tool 的 readOnlyHint=True描述的是工具注解，不构成无副作用保证。 openhands-sdk/openhands/sdk/context/prompts/sections/dynamic.py:45-96 openhands-sdk/openhands/sdk/skills/execute.py:1-14,52-73 openhands-sdk/openhands/sdk/tool/builtins/invoke_skill.py:188-194
  • catalog 不暴露 location，避免模型绕过统一 Tool；Tool 成功后才给可信的实际目录提示。 openhands-sdk/openhands/sdk/skills/skill.py:1431-1445,1498-1511
  • path rule 强制 disable_model_invocation=True，只能由文件触达触发。 openhands-sdk/openhands/sdk/skills/skill.py:723-730
  • secret 动态块只广告名称/描述；AgentContext 序列化默认遮罩原始字符串， 可在显式 expose context 下导出。 openhands-sdk/openhands/sdk/context/agent_context.py:208-245,291-307
  • inline command 的 fenced code、普通 inline code 和转义 \!`...` 不执行；未闭合 fence 保护直到 EOF。但可信来源判断仍由调用方负责。 openhands-sdk/openhands/sdk/skills/execute.py:34-49,98-119

17. 术语表

术语本章含义
View从 EventLog 活跃分支派生、应用压缩语义并满足 LLM 历史约束的事件序列。
EventLog会话事件的权威追加记录；不是 View 缓存。
Active branch从当前 leaf_event_id 回溯到根的事件路径；放弃的分支不进入当前 View。
Manipulation index在不破坏 View 属性的前提下允许 Condenser 切割或操作的位置。
Enforcement重建时通过删除违规事件修复 View 的后备机制。
PromptSection具有 name、cache_tier、guard、render 的纯提示片段协议。
PromptRegistry按注册顺序组装 PromptSection 并输出两个 tier 的容器。
STATIC tier面向同配置跨会话稳定前缀的 section 层；并不自行设置 provider cache marker。
DYNAMIC tier承载仓库、skills、memory、secret 名称、suffix 和时间等会话相关内容的层。
Progressive disclosure先展示轻量 catalog，命中触发器或显式调用后再把完整 skill 正文加入历史。
AgentSkills以 SKILL.md 和标准字段描述 skill 的格式；在 SDK 中默认采用渐进式披露。
Legacy skill旧 OpenHands 格式；无触发器时全文常驻 REPO_CONTEXT，有触发器时按需注入。
invoke_skill按名称显式取得并渲染 skill 全文的内置 Tool；成功结果是 Observation。
Trigger按 keyword/task 或 path 自动激活 skill/rule 的条件。
Memory用户/项目目录中的持久 MEMORY.md 索引；加载后只是动态 Context 的一部分。
Cache marker交给 provider 的显式提示缓存控制标记；由 LLM 层而非 PromptRegistry 设置。
ACPAgent Client Protocol；AgentContext 提供仅提示文本的兼容适配，不接管 ACP server 的工具和执行模型。
本页依据当前工作区源码与测试审计生成；源码变化后应重新核对行号、默认值、失败语义与测试映射。
