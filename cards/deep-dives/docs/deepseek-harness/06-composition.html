1. 模块定位

启动层把分发时的 bundle、部署时的 profile/home patch、命令行 overlay 和会话级 preset 组合为两级插件树：Host Context 运行产品基础设施，Agent Context 运行每会话能力。

边界说明
负责启动层把分发时的 bundle、部署时的 profile/home patch、命令行 overlay 和会话级 preset 组合为两级插件树：Host Context 运行产品基础设施，Agent Context 运行每会话能力。
委托Loader 负责插件导入和 Fiber 生命周期；各 entry 的 Config 仍由插件自己的 schema 验证。
不负责组合层不定义 Agent Turn 行为，也不替 Provider 猜测缺失配置。

2. 系统位置与依赖

dsh CLI、环境变量、profile metadata、cordis.patch.yml ↓ 启动与 Profile / Bundle / Preset 组合 ↓ 根 Context、Loader fibers、Web roster 或 Headless runner

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • Profile：列出有序 bundle 并承载部署 patch。
  • Bundle：可安装的 Cordis row 分发层。
  • Preset：单 Session/Agent 的插件 roster。
  • Overlay：home、--patch 和启动器派生行。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

5. 完整运行流程

成功路径

  • 读取环境和 profile 的 bundle 列表。
  • 依次应用 bundles、profile patch、home patch、--patch 和派生 overlay。
  • boot 挂载最终 root include 并等待 Loader。
  • 激活断言通过后产品入口开始服务。

拒绝或提前结束

  • 未知 bundle、无效 row 或自包含 Config 在启动时直接失败。
  • 依赖缺失导致 PENDING，激活断言拒绝继续。

恢复、中断或降级

  • 启动失败按 Context 生命周期卸载已激活 Fiber。
  • 修正 patch 后重新启动；预发布配置不提供隐式兼容 shim。

6. 数据与状态模型

最终 entry table 是启动快照；Host Context 拥有全局基础设施，Web preset mount 创建 Agent Context。SessionHeader 记录 agentPreset，使 resume 不换能力集合。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

Patch 以 entry id 定位并替换整行 config；后层覆盖前层。Web 的 preset provider 是会话装配入口，Headless 直接在 host 组合中创建一次性 Agent。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

顺序固定为 bundle 列表 → profile patch → home patch → --patch，再叠加 preset roots/telemetry 等派生 overlay。config 不做 deep merge。

原则默认/优先级失败行为
显式 resolve由 owning implementation 在执行前解析缺失 referent 或歧义 fail loud
Composition后层 row 覆盖前层，agent scope 可 shadow global不静默 deep merge 或选择第一个 Provider

9. 并发、性能与资源

Loader 按依赖条件推进 Fiber；启动等待收敛。Agent preset mount 是创建事务的一部分，失败会回滚会话与作用域。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

Patch 可以装载任意同进程插件，是高信任部署输入。环境和 credential 引用需在边界验证，不能把配置覆盖当权限控制。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

整行替换消除隐式深合并歧义，但局部覆盖需要重述整行。两级 Context 提供会话隔离，但要求明确区分 Host 与 Agent 所有权。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
