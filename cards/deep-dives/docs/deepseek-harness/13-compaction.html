  • generation：判断 overflow recovery 是否真正推进 Surface。

5. 完整运行流程

成功路径

  • 写 compaction/start 获取日志锁。
  • 可选 pruning 后重算 pressure。
  • 选择 tool-balanced range 并生成 summary。
  • 写 summary + user/message replace，最后写 end 并 flush。

拒绝或提前结束

  • busy、changed、summary failure 在不改变 Surface 时闭合失败 bracket。
  • 找不到 useful balanced range 返回 null。

恢复、中断或降级

  • 请求被确认为 context-overflow 后调用 compactIfNeeded。
  • 只有 Surface generation 推进才返回 retry；取消优先并完成清理。

6. 数据与状态模型

start/summary/end 和 replacement 都 durable；进程内 mutex/selection snapshot 是 runtime-only。原始被 shadow 的事件仍保留。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

compactIfNeeded 支持 pressure/context-overflow；compactNow 是 idle maintenance；compactRegion 操作显式 Surface 范围。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

9. 并发、性能与资源

日志 bracket 防止同 Session 并行 compact；手动路径提交前重验证选中位置，允许无关 idle injection 生存。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

摘要是新的模型可见内容，必须记录 provider/model/request 与 usage。工具输出 spill 的引用仍受 FS/sandbox 权限约束。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

保留原日志保障审计和恢复，但存储不会因摘要缩小。Provider policy 可替换，却要求明确记录摘要请求才能重建。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
