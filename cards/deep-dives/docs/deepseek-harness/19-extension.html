1. 模块定位

扩展设计从“谁拥有状态和决策”开始，而不是从“在哪个文件加 if”。新行为挂在公开事件或完整 capability seam 上。

边界说明
负责扩展设计从“谁拥有状态和决策”开始，而不是从“在哪个文件加 if”。新行为挂在公开事件或完整 capability seam 上。
委托具体实现落入 owning package；总览和本页只提供路由规则。
不负责不提供无 Consumer 的抽象、不鼓励直接修改 agent-loop 或跨包私有导入。

2. 系统位置与依赖

产品需求、Provider 集成、工具和 UI 扩展 ↓ 二次开发与推荐扩展点 ↓ packages、Config、events、tests、snapshots、docs 与 Agent Note

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • extension point：已文档化的 Service/Event/Registry 接入位置。
  • complete seam：Definition + Provider + Consumer。
  • model experience：模型实际看到的 prompt/schema/result。
  • real composition：通过 Loader 和真实 bundle/preset 组装的测试。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

5. 完整运行流程

成功路径

  • 确认 owner、状态和调用边界。
  • 选择已有 extension point 或设计完整 seam。
  • 实现 Config、lifecycle、failure 和 presentation。
  • 更新 unit/e2e/snapshot/docs/Agent Note 并验证真实组合。

拒绝或提前结束

  • 缺 Provider/Consumer 的半套 seam 不合入。
  • 缺 referent、歧义 Provider 或自包含误配置尽早 fail loud。

恢复、中断或降级

  • 注册通过 effect 可卸载；Provider failure 通过 typed error/result 收敛。
  • 持久格式变化按 pre-release 立场同步更新所有 reader/writer。

6. 数据与状态模型

扩展自己的 durable 状态进入 SessionEvent 或 owning store；缓存、controller 和连接归 effect/lifecycle owner。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

模型→LlmAdapter；行动→ToolRegistry；执行→FS/Subprocess/Shell；背景→Jobs/Subagents；UI→ConversationNode；持久事实→SessionEvent。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

所有部署可变选择进入可验证 Config，显式 resolve(request): spec；禁止在 run() 内用隐藏 ?? default。

原则默认/优先级失败行为
显式 resolve由 owning implementation 在执行前解析缺失 referent 或歧义 fail loud
Composition后层 row 覆盖前层，agent scope 可 shadow global不静默 deep merge 或选择第一个 Provider

9. 并发、性能与资源

每个异步 operation 一个 lifecycle controller/transaction；声明并测试取消、rollback、callback containment 与 quiescence。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

在真正做决策/副作用的 executor 或 Provider 强制 policy；UI 隐藏、schema omission 和 prompt instruction 都不能替代。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

严格所有权和完整 seam 增加前期设计工作，却避免 Provider-specific 分叉、隐藏状态和无法卸载的全局注册。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
