1. 模块定位

SystemPrompt Registry 组装 request prefix；LlmRuntime 维护 adapter registry 并通过 llm/stream waterfall 调用具体 Provider。Loop 只负责把两者写入 request/header。

边界说明
负责SystemPrompt Registry 组装 request prefix；LlmRuntime 维护 adapter registry 并通过 llm/stream waterfall 调用具体 Provider。Loop 只负责把两者写入 request/header。
委托Credential Service 解析 secret 引用；Adapter 转换供应商 wire；Session 保存 request 与输出事件。
不负责Prompt 不拥有会话历史，Adapter 不决定工具权限。

2. 系统位置与依赖

ReactLoopAgent request builder 与 agent/request listeners ↓ System Prompt 与 LLM 流式管道 ↓ LlmAdapter、SSE/stream transport、BlockAssembler、Session events

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • Prompt section：带稳定 key/顺序的 system prompt 贡献。
  • Adapter：Provider-neutral request 到供应商协议的转换。
  • StreamChunk：增量文本、推理、工具调用和 usage。
  • Provenance：assistant message 的 provider/model/replay identity。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

4. 架构组成

4BlockAssembler：收敛 chunks 为 assistant message。由 owning plugin 的 effect 管理，失败不发布半状态。

5. 完整运行流程

成功路径

  • pre-step 读取 agent scope 的 prompt sections。
  • request 解析 provider/model 和 adapter defaults。
  • 写 request/header/context 后调用 llm/stream。
  • 逐 chunk 记录并组装 message/usage。

拒绝或提前结束

  • 缺少 provider/model、未知 adapter 或 credential 解析失败在调用前报错。
  • 非法 tool-call JSON 在模型/工具边界形成类型化错误。

恢复、中断或降级

  • transport/provider error 交给 agent/request-error。
  • 插件可退避、修复 route 或触发 compaction；最终失败闭合 Step。

6. 数据与状态模型

Adapter registry 和 active stream 是 runtime-only；request/header、assistant chunks/message 和 usage 是 Session 事实。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

LlmAdapter 声明 prepare/stream 能力；llm/stream 是 waterfall。Message/ContentBlock/ToolSchema 是 Provider-neutral vocabulary。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

SystemPrompt 默认包含 Harness identity 和 runtime context，persona 默认为空；LLM retry policy 默认最多重试 2 次，初始延迟 500ms、最大 10000ms、jitter 0.1，默认代码不含 STREAM_CLOSED。AgentOptions 选择 provider/model/maxTokens，精确 Adapter 可物化 defaults。 packages/core/system-prompt/src/index.ts:337-369 packages/llm/llm/src/retry-policy.ts:14-57

9. 并发、性能与资源

一个 Step 一个 conversation stream；取消 signal 穿透 adapter。不同 Agent 可并发流式调用，registry 注册/卸载仍归 Cordis effect。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

模型响应和 tool arguments 是非可信 wire 输入；在边界解析/验证。Prompt 和 tool schema 可能泄露能力信息，应按 agent scope 解析。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

统一 vocabulary 降低 Provider 耦合，但供应商特性必须显式进入 Adapter 能力和 provenance，不能靠宽松 any 透传。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
