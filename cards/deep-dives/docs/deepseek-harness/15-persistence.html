1. 模块定位

SessionPersistence 是 append-only Session log 的 durability seam。Coordinator 异步复制事件并提供 flush；JSONL 和 SQLite 实现同一协议。

边界说明
负责SessionPersistence 是 append-only Session log 的 durability seam。Coordinator 异步复制事件并提供 flush；JSONL 和 SQLite 实现同一协议。
委托Session Core 验证事件；Projection/Query/Title/Stats/Telemetry 只消费日志或快照。
不负责Persistence 不定义模型 Surface，也不把 telemetry 变成权威账本。

2. 系统位置与依赖

session/event、session/flush、Agent create/resume/fork ↓ Session Persistence、恢复与读模型 ↓ JSONL/zstd 或 SQLite、projection cache、query/title/telemetry

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • flush：取消批量等待并排空到 durable quiescence。
  • cold repair：只对未 live 的 Session 合成 interrupted closure。
  • SessionHeader：事件外的 version/cwd/lineage metadata。
  • inspection/preparation：未发布 Session 的只读与事务所有权。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

5. 完整运行流程

成功路径

  • session/event 同步复制到 per-session controller。
  • 固定 batching window 到期写 durable batch。
  • flush 等待当前及跟随 batch 收敛。
  • resume prepare 发布验证后的 Session。

拒绝或提前结束

  • 未知 format/version/event 拒绝为 unsupported，不伪装 corruption。
  • backend write failure 保留 pending events，显式 flush 报错。

恢复、中断或降级

  • JSONL 仅丢弃 torn physical tail。
  • cold log 的 open turn 追加 interrupted end；live open turn load 拒绝修补。

6. 数据与状态模型

SessionHeader + events 是 durable；write queue、LRU inspection cache 和 controller 是 runtime。Projection 是可重算读模型。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

locate/create/append/load/inspect/prepare/flush/readRaw 构成 seam；supportsRawArtifacts 区分后端能力。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

9. 并发、性能与资源

append producer 不等待 IO；controller 有界批量并在 dispose final drain。prepare 预留身份，防止重复发布。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

locate 返回路径 hint，不是授权。raw artifact 可能含完整会话；credentials 不应进入事件，存储权限由部署负责。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

异步复制保持 Agent 延迟低，但完成屏障需要显式 flush。拒绝旧格式有利于预发布基础修正，却牺牲无缝升级。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
