1. 模块定位

Session 是每个 Agent 的权威交互历史。Surface 是日志中当前模型可见节点的投影；deriveMessages() 从 Surface 生成下一次模型历史。

边界说明
负责Session 是每个 Agent 的权威交互历史。Surface 是日志中当前模型可见节点的投影；deriveMessages() 从 Surface 生成下一次模型历史。
委托Persistence 负责 durable storage；context plugins 负责生产可见输入；UI、telemetry 和 query 负责消费投影。
不负责Session 不调用模型、不选择 Provider，也不把 request cache 当事实源。

2. 系统位置与依赖

Agent Loop、Inbox、Tools、Compaction 与插件事件 ↓ Session Event、Surface 与 Context ↓ deriveMessages、persistence、projection、Web/ACP/SDK

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • SessionEvent：带连续 seq 的 lossless JSON 事实。
  • Surface：由 append/replace 操作得到的模型可见序列。
  • request/header：重建 system、tools 与 call config 的完整快照。
  • seed boundary：区分继承历史与当前生命周期事件。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

5. 完整运行流程

成功路径

  • Loop 先追加 lifecycle 与用户输入。
  • assistant/chunk 保留回放，assistant/message/tool result 进入 surface。
  • deriveMessages 从当前 surface 生成合法模型历史。
  • request/header/context 让下一请求可解释和重建。

拒绝或提前结束

  • 非 JSON meta、未知 required event 或非法 version 在边界拒绝。
  • surface replacement 边界无效或 tool 配对失衡时不提交。

恢复、中断或降级

  • resume 从持久日志重建相同 Session 与 surface。
  • fork 复制 seed 并记录 parent/seedLength，不回滚源 Session。

6. 数据与状态模型

Event log 与 SessionHeader 是权威；surface、requestContext 和 UI nodes 是可重算投影；active writer 与 firstLiveSeq 仅服务当前生命周期。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

session/event 是同步通知；Session.append 是唯一写入口。SurfaceEventType 决定模型投影，log-only event 不进入 deriveMessages。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

Session 本身无部署调优项；cwd、lineage、origin、delegationDepth、agentPreset 来自创建 meta，版本由构建常量写入。

原则默认/优先级失败行为
显式 resolve由 owning implementation 在执行前解析缺失 referent 或歧义 fail loud
Composition后层 row 覆盖前层，agent scope 可 shadow global不静默 deep merge 或选择第一个 Provider

9. 并发、性能与资源

同一 Session 保持连续 seq；持久化监听不能阻塞 append。需要跨事件原子语义的功能用开始/结束 bracket 和重验证实现。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

Session 内容可能含用户、模型与工具数据；meta 必须 lossless JSON。Secret 引用应在进入日志前 redaction，SessionId 不是授权令牌。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

保留完整日志简化恢复与审计，但增加存储和格式演进成本。Surface replacement 允许压缩而不篡改历史。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
