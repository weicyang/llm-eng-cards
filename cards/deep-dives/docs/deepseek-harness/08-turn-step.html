1. 模块定位

ReactLoopAgent 是 Agent 接口的默认 Provider。它只拥有 driver、Turn/Step 编排、错误边界和工具调度，不拥有 prompt、LLM、工具 policy 或持久化实现。

不负责Compaction、retry、jobs、goals 等能力通过扩展点加入，不是 loop 内建状态分支。

2. 系统位置与依赖

Agent.send/wakeup 与 config-created Agent ↓ ReactLoopAgent Turn / Step 状态机 ↓ Session append、agent waterfalls、llm/stream、ToolRegistry

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • Turn：零或多个 Step，一次被处理的用户意图窗口。
  • Step：一次模型请求和其工具调用。
  • pre-step：接纳、改写或拒绝已 claim 输入的 waterfall。
  • turn-stopping：最终检查新工作和 continuation 的 serial checkpoint。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

4. 架构组成

#组件与职责生命周期与故障隔离
1driver：从 idle 到 running 并排空可运行工作。由 owning plugin 的 effect 管理，失败不发布半状态。
2preStep：先组装 prompt/runtime context，再触发 admission。由 owning plugin 的 effect 管理，失败不发布半状态。
3request path：derive history、header/context、stream。由 owning plugin 的 effect 管理，失败不发布半状态。
4tool-call scheduler：并发执行、顺序提交结果。由 owning plugin 的 effect 管理，失败不发布半状态。

5. 完整运行流程

成功路径

  • 写 turn/start 后 claim all next-step + 至多一个 next-turn。
  • 组装 prompt，再执行 agent/pre-step。
  • 接纳后写 step/start 和 user/message，构建并发送 request。
  • 写 assistant/tool 事件与 step/end；无欠债后通过 turn-stopping 写 turn/end。

拒绝或提前结束

  • pre-step reject 或首批改写为空会关闭零 Step Turn。
  • 工具 guard/approval 拒绝形成 tool result，不跳过 call/result 配对。

恢复、中断或降级

  • request 失败先闭合当前 step，再由 agent/request-error 决定 retry、compaction 或终止。
  • 取消中断 activity 并以稳定 reason 闭合；dispose 等待 driver 收敛。

6. 数据与状态模型

turn/step 序号和生命周期事件是 durable；active Promise、AbortSignal、wakeup latch 和 scheduler group 是 runtime-only。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

agent/pre-step、agent/request、llm/stream 与 tools/* 是 waterfall；agent/turn-stopping 是 serial。request-error 位于 step 内，重试不创建新的用户 Turn。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

9. 并发、性能与资源

同一 Step 的 concurrency-safe tool 可重叠，exclusive call 形成 barrier；结果按模型 call 顺序追加。stopping 后再次检查 steering，关闭竞态窗口。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

Loop 不判定工具权限；它必须经过 ToolRegistry executor，确保 direct/alternate caller 不能绕过 policy。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

11. 失败、恢复与兼容

故障/现象检测与即时行为恢复/运维

重复请求重复请求：检查 request-error action 与 surface generation。检查对应事件、Fiber/Agent 状态和 owner 日志；修复配置或使 lifecycle 收敛。
Turn 不结束Turn 不结束：检查 next-step debt 和 turn-stopping listener。检查对应事件、Fiber/Agent 状态和 owner 日志；修复配置或使 lifecycle 收敛。

当前为预发布版本；涉及 Session/SQLite 等格式时按 owner 的版本拒绝策略处理，不假设存在迁移。

15. 设计权衡与已知限制

薄 loop 降低核心爆炸半径，但完整行为分布在多个事件监听器。扩展点时间语义必须文档化并由真实组合测试固定。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。

17. 术语表

Turn
一次输入处理周期，可无模型请求。
Step
一次模型请求及其工具调用。
debt
要求 loop 再进入 Step 的待处理工作。
barrier
阻止工具调用与兄弟调用重叠的独占边界。
