依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • blast radius：一个改动影响的组合和持久格式范围。
  • single source of truth：只有一个权威写路径。
  • pre-release refusal：拒绝未知旧格式而不维护迁移。
  • thin loop：核心只编排，能力由插件贡献。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

5. 完整运行流程

成功路径

  • 先确认事实所有者。
  • 比较选择对恢复、安全、扩展和测试的影响。
  • 记录接受的成本和重评信号。
  • 把具体变更放回拥有模块。

拒绝或提前结束

  • 无来源性能数字、SLA 或完成度不进入结论。
  • 只根据包名或总览推断的限制标记为证据缺口。

恢复、中断或降级

  • 发现事实变化时更新 owner docs 和本页限定。
  • 决策逆转用新 Agent Note，不把旧 rationale 改写成相反结论。

6. 数据与状态模型

权衡本身不是 runtime 状态；Session format、schema version、作用域和 Provider 选择是其可观察实现。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

跨模块交互只通过公开 Service、Event、Tool 或 wire；私有导入会破坏可替换边界。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

部署 tunable 必须由拥有插件 Config 暴露；硬编码外部选择会把权衡藏入实现。

原则默认/优先级失败行为
显式 resolve由 owning implementation 在执行前解析缺失 referent 或歧义 fail loud
Composition后层 row 覆盖前层，agent scope 可 shadow global不静默 deep merge 或选择第一个 Provider

9. 并发、性能与资源

薄 Loop 和独立 lifecycle controller 降低竞态共享面；代价是需要跨插件 checkpoint 和清晰的 quiescence。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

插件内替换不等于安全隔离。Sandbox/process/trust fence 是真实边界；prompt、schema 和 redaction 只能辅助。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

11. 失败、恢复与兼容

故障/现象检测与即时行为恢复/运维
组合复杂组合复杂：用 dump-config + Fiber 状态诊断。检查对应事件、Fiber/Agent 状态和 owner 日志；修复配置或使 lifecycle 收敛。
日志增长日志增长：用 compaction surface，不删除事实。检查对应事件、Fiber/Agent 状态和 owner 日志；修复配置或使 lifecycle 收敛。
升级拒绝升级拒绝：按预发布策略导出或使用匹配构建。检查对应事件、Fiber/Agent 状态和 owner 日志；修复配置或使 lifecycle 收敛。

当前为预发布版本；涉及 Session/SQLite 等格式时按 owner 的版本拒绝策略处理，不假设存在迁移。

15. 设计权衡与已知限制

系统选择 foundation over compatibility：用更多显式协议和门禁换取可替换、可恢复与可审计；短期代价是配置、文档和测试表面更广。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。

17. 术语表

一个变化影响的运行和发布范围。

只负责编排、不拥有能力策略的循环。
