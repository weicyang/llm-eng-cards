1. 模块定位

产品面是核心的 Consumer。Web 通过 BFF/Typert/Connection 把 API 与 SessionEvent 送到浏览器；其他面直接通过 CLI/stdio 协议驱动 ctx.agents。

边界说明
负责产品面是核心的 Consumer。Web 通过 BFF/Typert/Connection 把 API 与 SessionEvent 送到浏览器；其他面直接通过 CLI/stdio 协议驱动 ctx.agents。
委托AgentRegistry 执行生命周期，SessionPersistence 提供恢复，interaction Service 处理 permission/ask。
不负责浏览器节点不是权威状态；Headless 不经 Web roster；ACP 与 SDK 不是同一 wire envelope。

2. 系统位置与依赖

HTTP/WebSocket、CLI、ACP stdio、JSON-RPC client ↓ Web、Headless、ACP 与 JSON-RPC SDK ↓ ctx.agents/ctx.sessions、Typert gateway、Connection、ConversationNodeAssembler

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

  • Typert：从类型图注册 RPC。

  • ConversationNode：SessionEvent 的 keyed UI 投影。

5. 完整运行流程

成功路径

  • 产品入口 boot 对应 bundle。
  • 请求创建/恢复 Agent 并发送 identified message。
  • SessionEvent 经本地输出或 wire 通知传播。
  • 消费者以 idle + flush 或协议 completion 结束。

拒绝或提前结束

  • trusted-host、RPC schema 或 permission 失败在边界拒绝。
  • 未知 Session/Agent 返回 typed protocol error。

恢复、中断或降级

  • Web 重连按 event cursor/host stream 对账。
  • SDK/ACP 客户端根据协议重新连接或恢复 Session；核心 crash repair 不由 UI 实现。

6. 数据与状态模型

Agent/Session 在 Host 权威；Web nodes、Remote client lists 和 pending UI 是投影。Headless 只输出最后非空 assistant 文本。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

Typert RPC、events.mux/host、ACP updates 与 JSON-RPC notifications 是不同 wire。SDK send 返回 MessageId，不把它当 assistant result。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

Web/headless profile 选择 bundle；listen 地址与 trust policy 归 Host Config。Web /api 的非 loopback/untrusted 请求返回 403，160 MiB 请求体上限只限制载荷，不构成认证。SDK 使用 NDJSON JSON-RPC，当前没有 cancel/session-close RPC。 packages/client/connection/src/api-request-trust.ts:1-120 packages/sdk/protocol/README.zh.md:5-38

9. 并发、性能与资源

WebSocket 事件与 RPC 并发，客户端按 seq 重建；完成需要避免 idle 与最后持久化/通知之间的竞态。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

Web Host 有 trusted-host fence 和 API policy；stdio 假定本地进程信任。wire redaction 不替代宿主文件权限。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

11. 失败、恢复与兼容

故障/现象检测与即时行为恢复/运维
UI 少节点UI 少节点：检查 SessionEvent cursor 和 renderer key。检查对应事件、Fiber/Agent 状态和 owner 日志；修复配置或使 lifecycle 收敛。
Headless 能跑但 Web 会话失败Headless 能跑但 Web 会话失败：检查 preset roster。检查对应事件、Fiber/Agent 状态和 owner 日志；修复配置或使 lifecycle 收敛。
MessageId 已返回但无答案MessageId 已返回但无答案：投递 receipt 不是 completion。检查对应事件、Fiber/Agent 状态和 owner 日志；修复配置或使 lifecycle 收敛。

当前为预发布版本；涉及 Session/SQLite 等格式时按 owner 的版本拒绝策略处理，不假设存在迁移。

15. 设计权衡与已知限制

同核多壳减少行为漂移，但每个协议必须明确定义投递、事件和完成语义；强行统一会泄露 UI 或 transport 概念。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
