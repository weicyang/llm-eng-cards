1. 模块定位

ToolRegistry 是模型能力的窄腰：注册定义同时提供 model schema、执行函数、规范输出和可选 presentation；所有调用必须通过统一 pipeline。

边界说明
负责ToolRegistry 是模型能力的窄腰：注册定义同时提供 model schema、执行函数、规范输出和可选 presentation；所有调用必须通过统一 pipeline。
委托approval/sandbox/timeout/hooks 通过 tools/* listeners 加入；具体副作用由 FS、shell、web 或其他 capability Consumer 执行。
不负责Registry 不拥有某个工具的业务状态，也不把 UI meta 发送给模型。

2. 系统位置与依赖

SystemPrompt schema assembly 与 ReactLoopAgent tool calls ↓ 工具注册、调度与执行管线 ↓ pre/execute/post listeners、tool body、Session tool/result

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • ToolDefinition：schema + canonical output + execute + scheduler/UI metadata。
  • canonical value：tool body 返回并按 output schema 验证的 JSON。
  • monotonic guard：只能 deny 或 abstain。
  • presentation：由 args/result 纯投影的 UI render intent。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

5. 完整运行流程

成功路径

  • 从模型 raw arguments 解析并验证 args。
  • pre/guards 放行，execute wrapper 调用 tool body。
  • 验证 canonical output，post 可接受/阻止/替换。
  • finalizeContent 只改模型 content，追加 durable result/meta。

拒绝或提前结束

  • INVALID_ARGS 在副作用前失败。
  • approval/guard 拒绝转为结构化 error result。
  • INVALID_TOOL_OUTPUT 防止错误值进入模型或 replay。

恢复、中断或降级

  • timeout abort cooperative signal 并等待 tool quiescence。
  • pipeline error 标准化为 result；同批兄弟调用仍按顺序提交。

6. 数据与状态模型

注册与 active execution 是 runtime-only；tool/call、tool/result 及 presentation meta 是 durable。deferred context 经 next-step 事件进入模型。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

tools/pre-execute、tools/execute、tools/post-execute 是 waterfall。finalizeContent 是工具自身最后一次 total transform，不能改 error identity。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

9. 并发、性能与资源

仅 classifier 明确返回 true 的调用可同组；异常/省略一律 exclusive。并发产生、顺序提交，避免 nondeterministic history。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

schema omission 不是 enforcement；ToolRegistry 在执行点应用 restriction、guard 和 approval。args/value 在 model JSON 边界验证并冻结。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

丰富 ToolDefinition 增加作者责任，但把 wire、执行、安全、模型结果和 UI 生命周期绑定在一个可验证定义上。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
