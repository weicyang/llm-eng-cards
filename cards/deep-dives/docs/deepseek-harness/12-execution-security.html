1. 模块定位

执行世界由 ctx.fs 与 ctx.subprocess 共同定义；shell、terminal 和 LSP 只消费它们。Sandbox 决定技术可达范围，Approval 决定用户是否授权一次意图。

边界说明
负责执行世界由 ctx.fs 与 ctx.subprocess 共同定义；shell、terminal 和 LSP 只消费它们。Sandbox 决定技术可达范围，Approval 决定用户是否授权一次意图。
委托Tool pipeline 负责调用身份和 policy 时点；Provider 负责本地 OS 或 E2B 传输细节。
不负责远端执行不把 Agent/Session/LLM 搬入 E2B；Approval 也不替代 OS confinement。

2. 系统位置与依赖

tool-fs、tool-bash、tool-terminal、tool-lsp、hooks ↓ 执行世界、Sandbox 与 Approval ↓ local filesystem/process tree 或 E2B sandbox

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • 执行世界：路径和进程必须落在同一 Provider 环境。
  • request/spec：shell 先显式 resolve，再运行不可变 spec。
  • sandbox mode：read-only、workspace-write、danger-full-access。
  • approval decision：一次调用的 allow/deny/unavailable。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

5. 完整运行流程

成功路径

  • 工具解析 workspaceRoot 和 sandbox mode。
  • 必要时请求 approval。
  • sandbox 包装 argv/路径，subprocess 或 E2B 执行。
  • 收集输出并等待资源收敛后返回 tool result。

拒绝或提前结束

  • 无 answerer 的 ask 返回 unavailable，不默认允许。
  • Provider 无法满足 sandbox mode 时 fail closed。
  • 路径或命令输入校验失败不产生副作用。

恢复、中断或降级

  • 超时先发 cooperative cancel，再 hard kill 进程树。
  • dispose 关闭 PTY/LSP/readers 并等待 quiescence。

6. 数据与状态模型

进程、PTY、LSP connection 是 runtime resources；命令结果通过 tool/result 持久化。E2B workspace 自身生命周期由 Provider/owner 管理。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

FS 和 Subprocess 是完整 capability seams；Shell 采用 request/spec；Sandbox resolver 返回执行约束；Approval request/decision 是 interaction seam。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

Sandbox policy 默认 read-only，未配置 workspaceRoot 时取 process.cwd()；Approval policy 默认 ask。部署通过 composition 成对选择 local/E2B FS 与 subprocess Provider。 packages/sandbox/sandbox-policy/src/index.ts:61-154 packages/interaction/user-approval/src/index.ts:176-347

9. 并发、性能与资源

Provider 必须正确处理并行工具、输出 reader 与取消。进程树 teardown 是一个生命周期事务，不能在父进程退出时提前 resolve。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

环境默认清洗 KEY/SECRET/TOKEN/PASSWORD/DSH_* 类变量。redaction 降低误泄露但不隔离同 UID 代码；dynamic Cordis 与 shell 都是高信任能力。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

共同执行世界让工具无需分叉，但要求 Provider 对路径、环境、取消和进程树提供一致语义；本地平台隔离强度也受 OS 能力限制。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
