14 Subagent、Workflow、Jobs 与协作能力

1. 模块定位

高级能力位于 Agent 核心之上：通过工具启动、通过 Inbox 继续、通过 SessionEvent 持久化事实，并通过 effect 拥有生命周期。

边界说明
负责高级能力位于 Agent 核心之上：通过工具启动、通过 Inbox 继续、通过 SessionEvent 持久化事实，并通过 effect 拥有生命周期。
委托子 Agent 仍由 AgentRegistry/Loop 执行；workspace 保存外部成果；UI 只消费事件投影。
不负责one-shot Run 不是 continuable Activation；Plan/Todo 不是循环控制器；Skill 不是任意代码权限。

2. 系统位置与依赖

模型工具、用户命令、turn-stopping/idle events ↓ Subagent、Workflow、Jobs 与协作能力 ↓ Subagent providers、worker thread、Agent Inbox、workspace 与 Session

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • one-shot：start 后等待单次结果并清理。
  • Activation：一个 durable child Session 的进程内驻留期。
  • Job：后台 producer 及其输出/终止控制。
  • Goal round：同 Session 目标在 idle checkpoint 的继续轮次。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

5. 完整运行流程

成功路径

  • 工具根据 named Provider 做 capability check。
  • one-shot 返回 tool result，或 continuable 创建 child Session/Activation。
  • 后台完成通知按 busy→inject、idle→followup 路由。
  • 所有可见结果通过 child/parent Session 记录。

拒绝或提前结束

  • Provider 不支持 requested feature 时 UNSUPPORTED_CAPABILITY。
  • continuation/interrupt authority 不匹配时 UNAUTHORIZED。
  • 未知 skill/goal/job id 在边界失败。

恢复、中断或降级

  • continuable child 无 Activation 时 cold resume。
  • dispose child-first 收敛 descendants；workflow/worker cancellation 传播。

6. 数据与状态模型

child descriptor、lineage、goal/todo/plan events durable；Activation、worker、Job reader 和 dynamic fiber runtime-only。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

ctx.subagents 是多 Provider registry；continuation 使用 Agent.followup FIFO；jobs/goals/skills 通过各自 Service 与 tool Consumer 暴露。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

Subagent Provider 名、depth、tool filter 与 persona 由调用/Consumer 显式给出并做 capability check；Goal 的 defaultMaxGoalRounds 默认 256。Todo 的 allowParallelInProgress 是必填策略，Skill 同 scope layer 内由较低 rank 获胜。 packages/goal/goal/src/index.ts:115-196 packages/todo/tool-todo/src/index.ts:91-107

9. 并发、性能与资源

Activation 每个 child 最多一个，Inbox 是唯一 FIFO；worker thread 与后台 Job 必须拥有取消和 settlement；descendants child-first dispose。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

followup/interrupt 依据 live Agent 与 durable direct-parent 授权。dynamic Cordis 等同任意宿主代码执行，不是 sandbox。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

高级能力独立演进且不污染 loop，但生命周期和授权分散在各 Service；跨模块编排必须坚持 Agent/Session 所有权。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
