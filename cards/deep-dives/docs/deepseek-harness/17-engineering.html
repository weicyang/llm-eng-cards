2. 系统位置与依赖

源码、Config、docs、examples、fixtures 与 package manifests ↓ 测试、构建、发布与工程治理 ↓ Vitest、TypeScript、ESLint、tsdown、knip/publint、doc-sync 与 CI

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

3. 核心概念

  • source plane：clean tree 通过 tsconfig paths 解析 src。
  • artifact plane：显式依赖 build 输出的发布验证。
  • keyless snapshot：无需 API key 的真实应用 transcript replay。
  • package invariant：运行时检查包拥有的关系。
当前事实当前事实：由当前工作区实现或公共类型直接证明。
运行态运行态：只存在于进程内，不是恢复后的事实来源。
持久事实持久事实：追加到 SessionEvent log，恢复和投影都从这里派生。

5. 完整运行流程

成功路径

  • 根据 diff 识别变更表面。
  • 运行聚焦 unit 或真实 composition。
  • 用户可见行为更新 snapshot。
  • 发布路径运行 build/hygiene/consumer smoke。

拒绝或提前结束

  • coverage per-file 未达门槛、generated catalog stale 或 package constraint 失败直接阻止。
  • 文档死链、类型摘录漂移和预算越界由 doc-sync 拒绝。

恢复、中断或降级

  • 修正 owner source 后重新生成派生产物。
  • 平台特有失败由 CI 信号诊断；仅在已知 Windows 故障时本地 Wine 检查。

6. 数据与状态模型

测试 fixture、snapshot 和生成 catalog 是派生产物；源类型、runtime contracts 与 owning docs 是输入。CI 状态不是产品持久状态。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

根 package scripts 是顶层门禁入口；每包 tests 与 invariant companion 提供局部证明；pre-push skill 选择最小充分集合。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

Node 引擎固定为 ^22.19 || >=24；Host 与 Client 使用分离的 TypeScript programs。Telemetry sharing 为 full | feedback-only | disabled，capture 为 live | on-demand，发送是 best-effort，没有 durable outbox。 docs/development.zh.md:46-76 docs/subsystems/session-telemetry.zh.md:1-57

检查面本地证据职责
行为focused tests / snapshot / e2e按改动面选择最小充分检查
发布build / hygiene / built smokeCI 拥有完整平台矩阵

9. 并发、性能与资源

可独立 gates 可并行，但高资源测试和 build 需避免互相污染。测试 teardown 与产品 teardown 使用同样的 quiescence 要求。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

真实 API e2e 从环境/.env 读取 key 且无 key 自跳过；fixtures 和 logs 不能提交 credential。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

强门禁增加变更成本，但把插件生命周期、模型可见日志和发布面等跨文件关系变成可执行约束。CI 保留全平台责任以控制本地成本。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
