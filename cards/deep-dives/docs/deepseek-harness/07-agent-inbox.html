2. 系统位置与依赖

Web/Headless/ACP/SDK、jobs、goals、subagent orchestrator ↓ Agent Registry、Handle 与 Inbox ↓ AgentFactory、SessionStore、Agent Context 与 ReactLoopAgent

依赖方向遵循显式 Service、Event、Tool 或 wire 接口；实现包不得从相邻模块私有状态反推所有权。兄弟 Provider 共享同一公共协议，产品组合负责选择实现。

  • followup：next-turn + wake。
  • steer：next-step + wake。
  • inject：next-step 且不 wake。

5. 完整运行流程

成功路径

  • Registry 预留 SessionId 并准备 Session。
  • setup 在未发布的 Agent Context 中挂载能力。
  • commit 成功后发布 Agent 与 Session 并返回 Handle。
  • send 记录 inbox splice，driver 在正确边界 claim。

拒绝或提前结束

  • 重复 id、setup rejection 或 commit throw 在发布前回滚。
  • 重复 pending MessageId 被 Inbox 拒绝。

恢复、中断或降级

  • cancel 中断当前 activity，可按选项保留 Inbox。
  • dispose 停止 loop、等待 idle、注销 Agent、移除 Session 并卸载 scoped world。

6. 数据与状态模型

Agent status 只有 idle/running；disposed 是从 registry 消失。Inbox splice 是 durable projection，活跃 driver、AbortController 和 maintenance ownership 是 runtime-only。

状态发布只能发生在提交点之后；缓存、UI 和查询视图从权威事件或 Service 状态派生，不能建立第二条写路径。

7. 接口、协议与事件

send(message,target,wakeup) 是统一原语；followup/steer/inject 是固定参数别名。whenIdle 观察整个 Agent 的 quiescence，不确认某条消息生成了结果。

调用者必须保留身份、取消、错误和时序语义；跨进程或模型 JSON 输入在边界验证，同进程 typed interface 信任 TypeScript。

8. 配置与默认行为

AgentOptions 的 provider/model 在 request 后必须可解析；maxTokens 若存在必须是正安全整数。创建 meta 可携带 cwd、lineage、delegationDepth 与 agentPreset。

原则默认/优先级失败行为
显式 resolve由 owning implementation 在执行前解析缺失 referent 或歧义 fail loud
Composition后层 row 覆盖前层，agent scope 可 shadow global不静默 deep merge 或选择第一个 Provider

9. 并发、性能与资源

一个 Agent 同时只有一个 turn-driving activity 或 maintenance owner。取消原因 first-wins；wakeup latch 保证收敛期间到达的新工作不会丢失。

只记录源码定义的队列、锁、预算和超时；没有实测证据时不承诺吞吐、延迟或 SLA。

10. 安全与信任边界

AgentHandle.dispose 是 capability，只暴露给创建者；SessionId/MessageId 是身份，不自动授予跨 Agent 控制权。

Prompt、UI 隐藏和 schema omission 不是权限强制；安全决策必须在执行副作用的 operation 中实施。

15. 设计权衡与已知限制

统一 Agent 接口让产品面共享核心，但 MessageId 只标识投递事实；需要 request/response 语义的上层必须建立自己的 operation lifecycle。

重评条件：当前 Consumer、恢复不变量、安全边界或部署拓扑发生变化，并有源码与测试证明原选择不再满足。
