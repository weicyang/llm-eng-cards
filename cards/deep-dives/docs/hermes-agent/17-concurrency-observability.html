1. 模块定位

定义跨子系统的锁、队列、背压、恢复和观测契约；不把业务内容默认发送第三方遥测。 证据：tools/async_delegation.py:81-90、tools/async_delegation.py:392-407

边界本模块负责委托/不负责
输入接收相邻模块已经规范化的请求、配置或状态。不复制入口鉴权和上游 Session 路由。
核心定义跨子系统的锁、队列、背压、恢复和观测契约；不把业务内容默认发送第三方遥测。具体业务副作用归真正 Owner。
输出产生结构化结果、状态变化、事件或下一阶段输入。Surface 呈现和跨平台传输由适配层处理。
边界原则：以代码所有权而不是文件名直觉划分模块；公共门面可能只做 Forward，状态真相源可能位于独立 Store。

3. 核心概念

At-least-once Delivery后台完成在 Crash 后可能重放，消费者必须幂等或可识别。
DrainGateway 重启/关闭前停止准入并等待或中断活工作。
Background Work Gauge不能只看 active_agents；还需 Delegation、Terminal、Kanban、Cron。
Content-free Monitoring指标和 Trace 只含 bounded metadata，不含 Prompt、Tool Args/Result。
阅读要点：术语表示不同所有权或生命周期时必须保留区分，不能为了简化图示合并成单一“Agent 状态”。

4. 架构组成

组成职责状态/隔离扩展规则
入口/Facade校验、规范化并把调用送到 Owner。不复制权威状态。公共签名保持兼容。
Core Owner定义跨子系统的锁、队列、背压、恢复和观测契约；不把业务内容默认发送第三方遥测。会话、进程或持久化边界明确。扩展现有 Strategy/Registry/ABC。
State/Store保存恢复与可观测所需最小事实。短事务、可重建缓存、Profile 隔离。变更提供 Migration 和恢复测试。
Adapter连接 Provider、Surface、Environment 或外部服务。依赖失败局部隔离。不得把厂商分支写回核心 Loop。

组件证据：tools/async_delegation.py:392-407、tools/process_registry.py:450-478、gateway/run.py:3574-3603、gateway/run.py:12383-12387

5. 完整运行流程

5.1 正常成功路径

运行产生 Lifecycle/Usage/Queue/Lock 事件 → 本地日志与 Session 统计 → Monitoring Emitter → 可选 /metrics /traces；关闭时 Drain → 标记 Interrupted → Startup Restore/Reclaim

成功不仅是返回文本，还必须完成规定的状态提交、资源清理与事件发布。证据：tools/process_registry.py:450-478、gateway/run.py:3574-3603、gateway/run.py:12383-12387

5.2 拒绝或提前结束

队列满、锁竞争、Readiness 未满足、Restart Drain 超时或 Scale-to-zero 发现后台工作 → 背压/拒绝挂起/安全中断

拒绝应发生在目标副作用之前，并保留可诊断原因；已发生副作用时不得用无条件重试伪装原子性。

5.3 恢复与降级

Completion WAL 重放、Cron Interrupted、Kanban Reclaim、FTS Rebuild、Environment Reconnect 和 Primary Provider Recovery 分层恢复

恢复策略必须有预算、所有权和终止条件。证据：gateway/readiness.py:94-114、agent/monitoring/gateway_health.py:210-238、agent/monitoring/gateway_health_export.py:304-377

6. 数据与状态模型

状态类别权威位置生命周期恢复语义
会话状态SessionDB 或 AIAgent 会话对象跨 Turn按 Session ID/Profile 恢复。
运行状态Owner 内存、ContextVar、Queue/Lease一次 Turn/Run中断后形成明确终态；非耐久状态不假装可续跑。
缓存进程级有界 Map/TTL可重建Generation、配置或显式 Invalidate 失效。
持久化状态Profile-aware SQLite/JSON/Sidecar跨进程Migration、Probe、Rebuild 或 Reclaim。
身份规则：Durable Session、Runtime Key、Compression Lineage、Gateway Routing 和 Background Delivery ID 不可互换。

7. 接口、协议与事件

接口面契约错误/顺序语义
Python / Registry稳定公共门面把实现委托给 Owner。异常被归一化；不可恢复错误保留类型。
Tool / Hook结构化参数与 JSON/事件结果。Pre Hook 可拒绝；Post Hook 不应覆盖核心终态。

Persistence短事务写入；Sidecar 仅保存其自身权威数据。至少一次投递需要幂等消费。

9. 并发、性能与资源

  • 锁的粒度跟随权威状态：Session、SQLite、Compression、Cron、Board 和 Registry 不共享一个全局锁。
  • 后台完成经 Queue/Watcher 排空，通知关闭不等于停止 Drain。
  • Provider Client、Tool Definition 和 Probe 结果有界复用；Generation 或配置变化使缓存失效。
  • Timeout 必须覆盖清理，迟到 Worker 不得提交过期结果。
  • 性能数字只采用源码默认或实测值；本文不推断吞吐与 SLA。

并发证据：gateway/run.py:3574-3603、gateway/run.py:12383-12387、gateway/readiness.py:94-114、agent/monitoring/gateway_health.py:210-238

10. 安全与信任边界

  1. Surface 鉴权、Session Source 和 Toolset 先决定可见能力；Prompt/Skill 不能授予权限。
  2. 副作用前经过参数校验、Hook、Approval、Policy 与 Environment 边界。
  3. Secret 不写入普通配置、日志、Trace、Skill Usage 或架构报告。
  4. Profile、Board、Workspace 和 Remote Backend 各自是不同隔离维度。
  5. Fallback 不能跨越凭据信任边界，也不能在已提交副作用后无条件重放。

11. 失败、恢复与兼容

故障/现象即时行为恢复
只看 active_agents后台任务被误判空闲并挂起合并所有 work gauges
把 at-least-once 当 exactly-once重复投递副作用使用 Delivery ID/Consumed 状态
遥测携带内容隐私和凭据泄漏仅 bounded metadata 且外发 opt-in

瞬时故障、权限拒绝、配置错误、取消、中断和数据损坏必须分型；只有瞬时且副作用安全的路径适合自动重试。

12. 可观测性与排障

现象先检查修复方向
入口成功但没有终态Session Key、Queue/Lease、Lifecycle、Background Work。区分仍在运行、等待超时和执行超时。
能力不可见Toolset、Session Source、check_fn、Plugin/MCP Registration。不要只检查 Registry 中是否存在名字。
恢复后重复结果Delivery ID、Consumed、Claim Owner、已提交副作用。按至少一次投递做幂等处理。
成本或延迟突增Prompt Cache、Tool Schema、Compression、Fallback、Usage。先验证稳定前缀和有效 Provider，再调参数。

14. 开发与扩展指南

新增后台系统必须接入 Readiness、Drain、Scale-to-zero、Interrupted/Restore 和 Content-free Monitoring，不允许只加一个线程。

变更目标正确动作必要证明
扩展现有能力修改真实 Owner，通过 Facade/Registry 接入。成功、拒绝、恢复和兄弟路径。
新增边缘能力按 Footprint Ladder 选择 Skill、Plugin 或 MCP。禁用时零 Schema/依赖成本。
改变状态或协议提供 Migration、兼容默认和文档。旧数据/客户端重放与并发。

15. 设计权衡与已知限制

本地优先系统用多种细粒度锁避免全局串行；代价是恢复状态分散。统一的是 Lifecycle 与观察契约，不是强制所有子系统使用同一存储。

重评条件：当当前边界导致三个以上平行实现、无法维持缓存/角色不变量，或恢复协议已经跨越多个独立 Owner 时，应先设计共享 ABC/Orchestrator，而不是继续复制分支。
