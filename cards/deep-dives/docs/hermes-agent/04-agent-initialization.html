1. 模块定位

装配一次可运行、会话期稳定的 AIAgent。它负责解析模型运行时、建立客户端、冻结工具面并连接状态服务；不负责单轮循环、Transport 消息转换或压缩算法。 证据：run_agent.py:412-600、agent/agent_init.py:493-626

边界本模块负责委托/不负责
输入接收相邻模块已经规范化的请求、配置或状态。不复制入口鉴权和上游 Session 路由。
核心装配一次可运行、会话期稳定的 AIAgent。它负责解析模型运行时、建立客户端、冻结工具面并连接状态服务；不负责单轮循环、Transport 消息转换或压缩算法。具体业务副作用归真正 Owner。
输出产生结构化结果、状态变化、事件或下一阶段输入。Surface 呈现和跨平台传输由适配层处理。

3. 核心概念

AIAgent 门面稳定公共 API，主要实现已经下沉到 agent/ 子模块。
Runtime Snapshot会话构造时确定并在 Turn 间复用的 Provider、Toolset、Prompt 与回调集合。
IterationBudget限制工具调用迭代的显式状态；父子代理不应被误写成一个全局共享计数器。
Lazy StateSessionDB 等依赖可在首次需要时创建，避免初始化失败永久破坏 Agent。

4. 架构组成

组成职责状态/隔离扩展规则
入口/Facade校验、规范化并把调用送到 Owner。不复制权威状态。公共签名保持兼容。
Core Owner装配一次可运行、会话期稳定的 AIAgent。它负责解析模型运行时、建立客户端、冻结工具面并连接状态服务；不负责单轮循环、Transport 消息转换或压缩算法。会话、进程或持久化边界明确。扩展现有 Strategy/Registry/ABC。

5. 完整运行流程

5.1 正常成功路径

AIAgent.__init__ → init_agent → 规范化 provider/api_mode → 创建 Client → 解析 Toolset → 装配 Prompt Cache、Compression、Memory 与 Context Engine → 发布可运行实例

成功不仅是返回文本，还必须完成规定的状态提交、资源清理与事件发布。证据：agent/agent_init.py:672-710、agent/agent_init.py:900-939、agent/agent_init.py:1080-1147

5.2 拒绝或提前结束

非法或不可用配置 → 跳过可选能力；Context Engine 加载失败 → 回退内置 Compressor；持久化禁用时不创建 SessionDB

拒绝应发生在目标副作用之前，并保留可诊断原因；已发生副作用时不得用无条件重试伪装原子性。

5.3 恢复与降级

SessionDB 首次使用失败 → 后续重试；Primary Runtime 恢复时重建 Client 与 Cache Policy；不可用插件能力隔离而非破坏核心

恢复策略必须有预算、所有权和终止条件。证据：agent/agent_init.py:2497-2595、run_agent.py:602-675、providers/base.py:38-80

6. 数据与状态模型

状态类别权威位置生命周期恢复语义
会话状态SessionDB 或 AIAgent 会话对象跨 Turn按 Session ID/Profile 恢复。
运行状态Owner 内存、ContextVar、Queue/Lease一次 Turn/Run中断后形成明确终态；非耐久状态不假装可续跑。
缓存进程级有界 Map/TTL可重建Generation、配置或显式 Invalidate 失效。
持久化状态Profile-aware SQLite/JSON/Sidecar跨进程Migration、Probe、Rebuild 或 Reclaim。
身份规则：Durable Session、Runtime Key、Compression Lineage、Gateway Routing 和 Background Delivery ID 不可互换。

接口面契约错误/顺序语义

Tool / Hook结构化参数与 JSON/事件结果。Pre Hook 可拒绝；Post Hook 不应覆盖核心终态。

9. 并发、性能与资源

  • 锁的粒度跟随权威状态：Session、SQLite、Compression、Cron、Board 和 Registry 不共享一个全局锁。
  • 后台完成经 Queue/Watcher 排空，通知关闭不等于停止 Drain。
  • Provider Client、Tool Definition 和 Probe 结果有界复用；Generation 或配置变化使缓存失效。
  • Timeout 必须覆盖清理，迟到 Worker 不得提交过期结果。
  • 性能数字只采用源码默认或实测值；本文不推断吞吐与 SLA。

并发证据：agent/agent_init.py:900-939、agent/agent_init.py:1080-1147、agent/agent_init.py:2497-2595、run_agent.py:602-675

10. 安全与信任边界

  1. Surface 鉴权、Session Source 和 Toolset 先决定可见能力；Prompt/Skill 不能授予权限。
  2. 副作用前经过参数校验、Hook、Approval、Policy 与 Environment 边界。
  3. Secret 不写入普通配置、日志、Trace、Skill Usage 或架构报告。
  4. Profile、Board、Workspace 和 Remote Backend 各自是不同隔离维度。
  5. Fallback 不能跨越凭据信任边界，也不能在已提交副作用后无条件重放。

11. 失败、恢复与兼容

故障/现象即时行为恢复
把门面当 God Object扩展继续堆入 run_agent.py，破坏所有权和可测试性把装配、Loop、Prompt、Compression 放回各自 owner
构造默认与产品默认混写文档和测试得出错误迭代上限同时引用构造签名与 config_defaults
会话中重装工具Prompt Cache 失效且 Tool Schema 漂移新 Session 生效；只允许明确的缓存失效流程

瞬时故障、权限拒绝、配置错误、取消、中断和数据损坏必须分型；只有瞬时且副作用安全的路径适合自动重试。

现象先检查修复方向

14. 开发与扩展指南

新增运行时能力先判断它是否属于装配；如果是 Tool、Transport、Memory Provider 或 Context Engine，应扩展对应接口，再由 init_agent 组合，避免在构造器加入产品专属分支。

变更目标正确动作必要证明
扩展现有能力修改真实 Owner，通过 Facade/Registry 接入。成功、拒绝、恢复和兄弟路径。
新增边缘能力按 Footprint Ladder 选择 Skill、Plugin 或 MCP。禁用时零 Schema/依赖成本。
改变状态或协议提供 Migration、兼容默认和文档。旧数据/客户端重放与并发。

15. 设计权衡与已知限制

集中装配让一次会话拥有一致快照，代价是构造参数多。当前方向是把实现拆为窄职责模块，而不是让会话中途热替换整个对象图。

重评条件：当当前边界导致三个以上平行实现、无法维持缓存/角色不变量，或恢复协议已经跨越多个独立 Owner 时，应先设计共享 ABC/Orchestrator，而不是继续复制分支。
