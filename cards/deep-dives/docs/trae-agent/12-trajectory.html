1. 模块定位

准确定义：Trajectory 是当前任务的观测记录（observability record）。它保存输入、响应、工具调用/结果和结束元数据，供事后阅读；它不是运行控制面。
边界负责明确不负责
TrajectoryRecorder内存字典、字段序列化、路径创建、JSON 写盘。不执行 Agent Loop，不决定成功，不做脱敏、加密、轮转或上传。
Provider Adapter成功构造统一 LLMResponse 后记录一次 LLM interaction。失败请求尚未形成响应时，不保证留下请求/异常事件。
BaseAgent单步 finalize 时记录 Agent Step。不把 Trajectory 读回上下文，也不从文件恢复步骤。
TraeAgent任务开始初始化，父循环返回后写最终状态。不提供 Replay、Resume、Checkpoint 或长期 Memory。

公共边界是 set_trajectory_recorder()、start_recording()、record_llm_interaction()、record_agent_step() 与 finalize_recording()。trae_agent/agent/base_agent.py:87-96；trae_agent/utils/trajectory_recorder.py:20-230

3. 核心概念与术语

术语当前含义不能据此声称
Trajectory任务执行期间反复覆盖写出的 JSON 观测快照。不是不可篡改审计日志，也不保证完整。
llm_interactions[]Provider 视角的一次成功请求/响应归一化记录。不是 Agent Step 的子数组，也没有显式 step id。
agent_steps[]Loop 视角的一轮响应、工具执行与错误记录。不能依靠数组位置无条件关联 Interaction。
增量保存内存数组追加一项后，把完整根对象重新序列化到同一路径。不是 append-only、JSON Lines 或事件流。
用量（Usage）Provider 返回并归一化的 Token 计数。不是货币 Cost；源码没有价格表或费用字段。
Memory影响后续推理、可被模型再次读取的状态。Trajectory 当前没有读路径，因此不是 Memory。
Replay / Checkpoint可重放输入或从一致状态继续执行的控制数据。Trajectory 没有版本、游标、随机状态、副作用幂等信息或加载 API。

4. 架构组成

4.1 Recorder 与内存状态

构造器立即解析绝对路径、尝试创建父目录，并建立固定顶层字典；此时尚不写文件。第一次 start_recording() 才写盘。目录创建失败只打印错误，构造仍继续。trae_agent/utils/trajectory_recorder.py:23-52

4.2 生命周期所有者

Agent 门面始终创建 Recorder；Trajectory 不是可关闭的 feature flag。TraeAgent.new_task() 在初始消息构造完成后 start；TraeAgent.execute_task() 只在 super().execute_task() 返回后 finalize。trae_agent/agent/agent.py:28-35；trae_agent/agent/trae_agent.py:122-164

4.3 Provider 记录点

Anthropic、Google、Ollama、OpenAI Responses API 以及 OpenAI-compatible 基类都在统一响应对象已创建后记录。Azure、Doubao、OpenRouter 通过 compatible 基类共享不变量。Provider 调用抛错时，该调用点不会到达，因此通常没有失败 interaction。trae_agent/utils/llm_clients/llm_client.py:27-80

4.4 Agent Step 记录点

_finalize_step() 先无条件把 state 置为 completed，再记录。因此即使步骤捕获过异常，JSON 也可能同时出现 state:"completed" 和非空 error。trae_agent/agent/base_agent.py:173-178,238-244

4.5 JSON 序列化器

Message 只输出 role/content 及可选 Tool Call/Result；Tool Result 的 name 不写入，Tool Call/Result 都会额外写可空 id。trae_agent/utils/trajectory_recorder.py:232-261；类型来源 trae_agent/tools/base.py:34-55。

5. 完整运行流程

5.1 正常成功路径

1选择路径
Agent 接收 CLI 自定义路径，或按秒生成 trajectories/trajectory_YYYYMMDD_HHMMSS.json。
2注入实例
同一 Recorder 注入具体 Agent 与底层 Provider Client。
3开始任务
new_task 写 task/provider/model/max_steps/start_time，清空两个数组并第一次保存。
4LLM 返回
Adapter 追加一个 llm_interactions[] 项，随后全量重写文件。
5工具与单步
Loop 执行工具；finalize step 时追加一个 agent_steps[] 项，再次全量重写。
6循环重复
正常情况下每轮先出现 Interaction 快照，再出现对应 Step 快照；两数组仍无外键。
7最终写盘
父循环返回后写 end_time/success/final_result/execution_time，并覆盖保存。
8CLI 提示
run 打印 “Trajectory saved to”；提示本身不重新校验文件存在或 JSON 完整性。

5.2 提前拒绝路径

CLI 的任务互斥、配置或工作目录校验发生在 Agent 构造前时，没有 Recorder、没有文件。若 Agent 已构造但 new_task 在 start_recording 前失败（例如缺 project_path），也可能尚无文件。trae_agent/cli.py:277-350；trae_agent/agent/trae_agent.py:125-153

5.3 异常、取消与部分文件

  • Provider 失败：前一次快照通常仍是合法 JSON，但失败请求本身通常没有 interaction。
  • 单步异常：Loop 尝试记录带 error 的 Step；若完成该写入，后续父循环仍可返回并 finalize。
  • KeyboardInterrupt/取消：CLI 宣称 “Partial trajectory saved”，但中断若发生在文件被 "w" 截断之后、json.dump 完成之前，文件可能是空或截断的无效 JSON。
  • 进程崩溃/断电：没有 fsync、临时文件与原子 rename，不能保证最后一次完整快照存活。

差异/陷阱真实契约影响
两个 Usage 形状不同Interaction Usage 始终是对象；无 usage 时前两项为 0、扩展项为 null。Step 的 llm_response.usage 可整体为 null，且只含 input/output。消费者不能共用一个严格 Schema 而不做 union/normalize。
总 Token 不在根对象AgentExecution.total_tokens 会累加五种计数，但 Recorder finalize 不写它。需从 interactions 汇总，且 Provider 缺失值与 0 的语义要保留。
Tool Result保存 call_id/success/result/error/id，不保存类型中的 name。应通过 call_id 与 Tool Call 关联；信息可能不足时标记未知。
Lakeview 字段不在初始 Step Schema；仅 update_lakeview 命中 step_number 时动态加入。消费者必须容忍可选字段；当前主调用点未检出。
Schema 版本根对象没有 schema_version。格式演化无法可靠协商，只能外部按版本/字段探测。

9. 并发、性能与资源

  • 单任务顺序：同一 Loop 中 Provider 记录发生在 Adapter 返回前，Step 记录发生在工具处理和 step finalize 后；没有后台写队列。
  • 全量写放大：每次事件都对随历史增长的根对象执行完整 json.dump，时间与写入字节随轨迹变大；没有 Buffer 上限、轮转或压缩。
  • 事件循环阻塞：save_trajectory 是同步文件 I/O，由 async Agent Loop 直接调用。
  • 同实例并发：内存列表和文件均无锁；若多个协程/线程共享 Recorder，append 与保存快照可交错。
  • 同路径多实例：没有跨进程锁、owner id 或 compare-and-swap；最后完成写入者覆盖另一实例的文件。
  • 默认名碰撞：名称只有秒级时间。同一目录一秒内创建多个 Agent 时可得到同一路径，即使每个实例的内存字典不同。
  • Interactive：一个 Agent/Recorder 在多个任务间复用；每次 start 清空两个数组并覆盖同一文件，所以默认保留的是最近任务，而不是会话合并日志。trae_agent/cli.py:494-505,516-586
当前实现不适合作为多租户并发写入协议。并发调用方至少应在外层为每个 task 分配全局唯一、权限隔离的路径；仅增加线程锁仍不能解决跨进程碰撞。

10. 安全与信任边界

数据面可能记录的敏感内容当前保护真实风险
task / input_messages问题描述、System Prompt、绝对工作区路径、用户粘贴的 Secret 或源码无字段级脱敏完整明文写入 Host 文件
LLM response模型复述的凭据、私有代码、推理文本无内容过滤Provider 返回什么就记录什么
Tool Call arguments命令、文件路径、待写代码、URL、Token 参数无参数策略编辑/命令参数可直接泄露代码和 Secret
Tool Result文件内容、Shell stdout/stderr、环境变量、错误堆栈仅按 Tool 本身返回内容记录结果是最容易发生批量代码/凭据泄露的表面
路径与文件权限自定义任意 Host 路径父目录自动创建；遵循 OS 默认权限无专用权限模式、租户隔离、加密或安全删除
不要沿用过强的旧结论：docs/TRAJECTORY_RECORDING.md:326-330 写“API keys are not logged”。源码只能证明 Recorder 不把 BaseLLMClient.api_key 作为独立配置字段写入；它不能阻止 Key 经 task、消息、Tool 参数/结果或模型响应进入文件。正确表述是“没有专门记录 API Key 字段，也没有通用 Secret 脱敏保证”。

Trajectory 不是安全审计边界：文件可被运行用户修改，记录失败采用 fail-open（打印 warning、主任务继续），也没有签名、哈希链或远端不可变存储。对私有仓库使用时，应在调用侧实施唯一目录、最小权限、保留期、脱敏与安全传输。

11. 失败、恢复与兼容

故障/现象检测方式即时行为状态影响重试/恢复运维操作
父目录不可创建stdout 错误构造继续；保存时再尝试 mkdir可能全程无文件修复权限后新事件可再次尝试检查目标父目录与运行身份
写盘异常/磁盘满Warning 文本异常被吞，Agent 继续内存已 append，磁盘停在旧快照后续保存可能把内存全量补写释放空间并核验 JSON，而非只看 CLI 成功
序列化异常Agent Step error/异常输出json.dump 内异常被吞；若构建字典阶段异常则可向上传播文件可能已被截断修正非 JSON 参数类型后重跑验证 Tool arguments/result 类型
Provider 请求失败Agent error/ConsoleAdapter 记录点未到达无该次 interaction；可能有错误 Step由 Provider/上层策略决定结合日志，不只依赖 Trajectory
用户中断/进程杀死CLI partial 提示或文件 mtime不保证 finalizeend_time 可能空；也可能无效 JSON不能从文件 resume先用 JSON parser 验证，再作取证副本
同路径并发task 突变、数组倒退、内容互相覆盖无冲突检测最后写入者获胜或形成截断文件不能可靠合并改用每任务唯一文件并隔离目录
旧/新字段变化消费者解析失败无版本协商离线工具中断按可选字段与宽松读取兼容引入 schema_version 前保留原始文件

恢复边界：合法的部分文件可以用于事后观察，但不能恢复 Agent：文件没有 Provider 原生完整历史、当前副作用一致性、待执行 Tool 游标或加载入口。重新运行是新任务，可能重复非幂等工具副作用。

15. 设计权衡与已知限制

当前选择收益成本/失败模式何时重新评估
单个易读 JSON无需额外服务，人工和脚本都容易读取长任务全量写放大；崩溃窗口可能损坏整个文件轨迹显著增长、并发或实时消费出现时
LLM 与 Step 双视图同时保留 Provider 与 Loop 语义字段重复且无外键，异常时计数可错位需要可靠跨视图查询时引入 event/step id
写失败 fail-open磁盘问题不阻断主要编码任务CLI 仍可能显示保存成功，审计完整性不可保证合规任务要求记录必达时提供可配置 fail-closed
原始内容优先调试信息丰富Secret、源码和路径泄露面大多用户、生产数据或外部上传前
无 schema_version实现最小消费者无法协商演化任何字段变更或第三方消费前
自动记录始终开启默认可排障没有明确 opt-out/保留策略隐私法规、低磁盘或嵌入式运行场景

当前限制与路线图必须分开

  • 当前：本地、同步、全量覆盖 JSON；无锁、无原子替换、无脱敏、无版本、无上传、无读取/恢复 API。
  • Roadmap：docs/roadmap.md:5-18,36-50 提到 streamed trajectory、MLOps 集成和高级分析；这些是规划，不是当前运行时能力。
  • 概念边界：Trajectory 不是 Memory、Replay 或 Checkpoint。即使未来增加分析后端，也只有新增明确的状态恢复协议后才能称为 Checkpoint。
