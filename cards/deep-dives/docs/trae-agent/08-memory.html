1. 模块定位

核心结论：当前没有独立 Memory 模块。主 Agent 的多轮连续性由具体 Provider Client 在 Python 对象内维护的 message_history 提供；BaseAgent 只发送本轮增量消息。它是 Context 状态，不是跨会话长期记忆。
边界当前负责明确不负责
Provider Client保存 Provider 原生消息历史，按 reuse_history 追加或替换。无数据库、检索、TTL、版本、跨进程恢复。
TraeAgent / BaseAgent每任务重建初始消息，并把 Tool Result 等增量交给 Provider。不拥有统一完整历史，也不做 Compaction。trae_agent/agent/trae_agent.py:102-153；trae_agent/agent/base_agent.py:147-236
Trajectory把交互与步骤写入 JSON，供审计和调试。Runtime 不读取它恢复历史，也没有 Replay 执行器。
Lakeview用独立 Client 生成供人阅读的步骤摘要与标签。不回灌主 History，不是 Memory 或 Compaction。
CKG / Sequential Thinking前者是可选代码图工具；后者保存工具对象内的 thought 计数/分支。都不是通用会话 Memory Store；不能替代 Provider History。

5. 完整运行流程

5.1 单个 run 成功路径

1创建对象
CLI 创建一次 Agent，其 BaseAgent 构造一个 LLMClient；历史初始为空。
2初始化任务
new_task 构造 System/User 增量，Trajectory 开始新记录；不执行历史 reset。
3首轮请求
BaseAgent 调用 chat(..., reuse_history=True)；Adapter 将初始消息加入自身 History。
4持续累积
Adapter 保存模型响应；Tool Result 作为下一轮增量进入同一 History，直到完成或失败。
5结束进程
资源清理后 CLI 进程退出，内存 History 随对象销毁；Trajectory JSON 留在磁盘，但不会成为下次输入。

5.2 Interactive 后续任务串接路径

1复用 Agent
Simple/Rich Interactive 都在会话外创建一次 Agent，后续任务反复调用同一 agent.run。trae_agent/cli.py:494-512,516-584
2覆盖初始消息
第二次 new_task 重建新的 System/User 增量，却不清空 Provider History。
3追加旧历史
默认 reuse_history=True，新 Task 消息拼到旧 Task 之后；模型可能看到前序任务内容。
4覆盖轨迹文件
start_recording 清空同一 JSON 的 interaction/step 数组；这与 Provider History 的继续累积相反。

5.3 拒绝、失败与恢复

  • 缺 project_path 时在 Provider 调用前抛 AgentError；没有新历史写入。trae_agent/agent/trae_agent.py:125-129
  • Provider 请求失败时通用重试复用同一状态和参数；没有从持久 Memory 恢复、裁剪或跨 Provider Failover。
  • 进程重启会丢失 Provider History；现有 Trajectory 不能自动 Resume。恢复只能重新运行任务并重新产生副作用。

6. 数据与状态模型

状态权威所有者生命周期清理/持久化

9. 并发、性能与资源

  • 当前单 Agent Loop 串行调用同步 Provider chat；History 是无锁可变列表，不适合共享给并发 Task。
  • Rich Console 通过 is_running_task 管理 UI 状态，但 Provider Client 本身没有锁、Copy-on-write 或并发隔离契约。trae_agent/utils/cli/rich_console.py:147-191
  • History、Tool Result 和 Tool Schema 没有 Token 预算、背压、有界 Buffer、TTL 或淘汰策略；长任务的内存和请求负载持续增长。
  • set_chat_history 是整体替换，不是原子事务；源码没有并发调用保护。
  • Trajectory 每次事件都全量重写 JSON；这是额外 I/O，与 Provider History 的内存增长彼此独立。

累计 Usage 是计费/观测值，不等于当前 History Token 数；同一旧历史会在后续请求中重复计入 input tokens。

10. 安全与信任边界

边界当前行为风险/缺口
Provider HistoryIssue、路径、文件内容、Tool Output 可进入外部模型请求。无字段级脱敏、租户隔离、显式销毁或最小保留策略。
Interactive 任务隔离同一 Agent/Client 可跨任务复用历史。旧项目内容可能泄露到后续 Task；切换工作目录尤其危险。
Trajectory 文件保存任务、增量消息、响应、Tool 参数与结果。明文 JSON 可能含源码、命令输出和 Secret；源码没有加密、权限收紧或脱敏。文档所称“API key 不记录”不能证明 Tool 输出不会包含 Key。
Lakeview把步骤文本发送给第二个 Provider Client。额外数据外发面；不是本地 Memory 隔离层。
外部 Memory 扩展当前不存在。未来必须定义用户/项目身份、ACL、删除、保留、加密、Prompt Injection 与数据来源可信度。
Fail-open 风险：当前没有任务边界 reset；Interactive 继续执行而不是因无法证明隔离而拒绝。需要强隔离时，应每任务创建新 Agent/Client，而不是依赖 UI 的 clear 命令——它只清屏。trae_agent/cli.py:531-564

11. 失败、恢复与兼容

故障/现象检测方式即时行为状态影响恢复/运维
第二个 Interactive Task 引用旧内容复用同一 CLI；首轮 input token 异常高新消息追加旧 History语义污染/跨项目泄露退出并重启；开发上新增统一 task-boundary reset。
进程崩溃或重启任务中断内存 History 丢失无自动 Resume人工读 Trajectory 后重新运行；注意 Tool 副作用可能已发生。
Context 超限Provider 错误、重试日志、Step.error同一过大请求通用重试不裁剪，最终任务失败拆任务、限制输出、重启会话；实现真正 Compaction。
Ollama 多轮缺模型回复检查下一轮请求/源码 History只保存输入增量Tool 配对与语义可能不完整补响应写回和多轮契约测试。
Trajectory 写失败stdout Warning主任务继续审计证据缺失，不影响内存 History检查目录权限/空间；不能据此假定 Memory 失败。
误把 JSON 当 Replay 输入没有 load/replay APIRuntime 不消费文件无法恢复状态或副作用边界先设计版本化 Replay/Resume 协议，不要直接重放 Tool Calls。

没有历史 Schema 版本、迁移器或遗留会话导入。set_chat_history 接收统一消息列表，但它只做当前进程内 Provider 转换，不能证明跨版本兼容或可恢复性。

12. 可观测性与排障

12.1 当前能看到什么

  • Console 展示累计 Token 与 Agent 状态，但不展示 History 条数、当前 Context Token、Session ID 或剩余窗口。
  • Trajectory 记录本轮增量输入、响应和 Tool 结果；不能直接还原 Adapter 实际发送的完整原生请求。
  • 源码调试可查看具体 Client 的 message_history；这是内部可变实现，不是稳定诊断 API。

15. 设计权衡与已知限制

当前选择收益成本/失败模式重新评估条件
Provider 保存原生 History适配各 SDK 的 System/Tool 结构直接。统一 reset、迁移、审计、压缩和 Failover 困难。需要 Session、长任务或跨 Provider 切换时。
BaseAgent 只传增量Loop 简洁，避免复制协议。上层看不到实际完整请求，Trajectory 也不是请求快照。需要窗口治理与可重现请求时。
Interactive 复用 Agent减少重复构造，保留交互连续感。当前没有显式“延续/隔离”选择，可能跨任务污染。支持多项目、多用户或安全隔离时。
Trajectory 写文件但不回读审计旁路不改变主推理。不能 Resume/Replay；敏感数据长期留存。需要恢复、实验重放或合规治理时。
无自动 Compaction不引入摘要信息损失和额外策略复杂度。History 无界增长，超窗后没有有效恢复。长任务频繁超窗或成本不可控时。

当前限制（源码事实）

  • 没有独立 Memory Store、Memory DB、向量库、Embedding、RAG、相关性检索或跨会话持久记忆。
  • 没有通用 Compaction、Pruning、窗口预检、Checkpoint、Resume 或 Replay 执行器。
  • Interactive 和程序化复用同一 Agent 时可能串接 Provider History；没有统一 clear/reset API 或任务隔离测试。
  • Ollama History 当前不保存 assistant 响应；不同 Provider 的 System reset 语义不完全一致。
  • Sequential Thinking 有局部进程状态，但不是通用 Memory，且任务边界同样没有 reset。
  • Trajectory 不是 Memory 或 Replay；Lakeview 不是 Memory；CKG 不是 Conversation/Long-term Memory。

Roadmap 与证据缺口

docs/roadmap.md 规划 SDK、Sandbox、Trajectory Analysis、MCP 和 Multi-Agent，但没有定义持久 Memory、RAG、Compaction 或 Replay 的已承诺契约。外部 Project Memory、统一 Session、向量检索和可恢复执行只能列为二次开发路线，不能写成官方已实现或已排期能力。
