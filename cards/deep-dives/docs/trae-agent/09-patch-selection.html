评估侧 Patch Selection 开发文档

审计“外部候选 → 标签/回归过滤 → 去重 → Docker 内 Selector → 分组产物与统计”的真实契约，并把它与单 Agent CLI Runtime 严格隔离。

一句话目标帮助研究与评测开发者安全运行、恢复和扩展候选 Patch 选择实验，而不把它误接成在线多 Agent Runtime。
源码快照工作区源码快照；pyproject.toml 版本 0.1.0；工作区无可用 Git 元数据/CLI，未取得 SHA。
证据状态静态审计已验证端到端受外部镜像、py312 与 LLM 凭证阻塞
所有者路径evaluation/patch_selection/；只复用 trae_agent/utils/llm_clients/、配置、Tool Schema 与 Trajectory。
目标读者SWE-bench 评测、候选生成、Selector、Docker 基础设施、实验复现与安全审计开发者。

1. 模块定位

硬边界：这是一条从独立 Python 脚本启动的评估流水线，不是 trae-cli 子命令，不由 Agent/TraeAgent/BaseAgent 调度，也不是线上多 Agent 协作或 BaseAgent 内置 GPS。
边界当前负责委托/输入明确不负责
Generator仓库内没有生成器实现。外部系统产生多次轨迹/候选 Patch，并写 JSONL。不由主 CLI 并行启动多个 Agent；不保证候选来源、独立性或多样性。
“Pruner”run_instance_by_group() 内联执行空 Patch 跳过、回归字段过滤与 cleaned Patch 去重。regressions 来自外部 Agentless 等流程；success_id 来自评测标签。没有独立 Pruner 类或 Agent；不会在此处运行回归测试。evaluation/patch_selection/trae_selector/selector_evaluation.py:168-203
Selector在 SWE-bench Docker 镜像内查看仓库、运行命令/编辑临时文件，并由 LLM 选择一个已有 Patch。复用主项目 LLMClient、Tool Schema、TrajectoryRecorder。Prompt 禁止创建新 Patch；不把选择结果提交回主 Runtime。
Reporter写 Patch、统计 JSON、原始输出、轨迹与汇总 CSV。analysis.py 离线扫描 statistics。不计算通用 Pass@1，不验证最终 Patch 实际应用成功，也不提供服务 API。

目录 README 把研究范式称为生成/剪枝/选择，但决定性源码只覆盖候选消费、内联过滤和选择。evaluation/patch_selection/README.md:1-18,20-72

3. 核心概念与术语

术语本模块准确含义容易误写成
候选补丁（Candidate Patch）外部 JSONL 中的 unified diff 字符串；运行时包装为 CandidatePatch，保留原始 Patch、清洗键、回归状态与正确性标签。Selector 在容器内生成的新修复。
生成器（Generator）仓库外部/上游过程；当前目录只定义其结果文件契约。Trae CLI 内置的多个并行 Agent。
Regression每个 Patch 对应的测试名列表；空列表表示上游宣称通过。Selector 只消费，不执行该筛选过程。Selector 在调用前自动跑完整测试。
Pruning有通过回归的候选时丢弃非空 regression 候选，再按去注释/空白后的 diff 内容去重。独立 Pruner Agent 或学习排序器。
success_id0/1 ground-truth 正确性标签，用于全对/全错组短路和选择后计分。可供无标签生产流量使用的预测。
多数投票（Majority Voting）对同一候选组重复运行 Selector，按原 candidate id 计票；达到严格过半可提前停。多个不同专业 Agent 协商或模型集成。
分组（Group）候选数组按 group_size 顺序切片；每组独立输出一个 Patch。已有自动的“组冠军再决赛”实现。

5. 完整运行流程

5.1 正常成功路径

1外部生成
同一 instance_id 的多个轨迹/patch 由仓库外部产生；回归测试也由外部流程执行并编码为 regressions。
2加载与关联
入口把 candidates 按 instance_id 覆盖写入字典，再按 instances 列表逐项索引；候选内 issue 不用于最终 Prompt，Prompt 使用 instance 的 problem_statement。
3分组
只遍历前 num_candidate 范围形成顺序切片；每组串行处理。evaluation/patch_selection/trae_selector/selector_evaluation.py:34-63
4标签短路
组内 success_id 全 0 或全 1 时不调用 Selector，直接保存第一项和统计；这是有标签评测优化，也是泄漏边界。
5过滤与去重
丢弃空 Patch；若存在回归列表为空的候选，则只保留这些候选；随后用清洗后的修改行内容去重。
6沙箱准备
按 instance 构造硬编码 SWE-bench 镜像名，启动容器、复制工具并 checkout base_commit。
7选择
Selector 获得 issue 与所有候选原文，可用 bash/edit 在原始仓库上调查或写测试；它并不会先把每个候选逐一 apply 到仓库。
8投票与落盘
可选重复选择，按 candidate id 多数票取结果；写 Patch 和标签统计，停止容器。每个 group 得到独立结果。

5.2 拒绝/提前结束路径

  • 缺模型、模型名不存在或 YAML 无效，在并发启动前抛错。evaluation/patch_selection/selector.py:52-60
  • 统计文件已存在且非空，整组视为完成并跳过；不会核对 Patch/trajectory/output 是否齐全或配置是否一致。
  • 全成功/全失败标签组直接短路。全失败仍保存第一 Patch，但统计标记失败。
  • 正则未得到合法结果并耗尽 max_turn 时，SelectorAgent 返回第一候选，Trajectory 却以 success=true finalize；“Agent 完成”与“Patch 正确”是两套状态。

5.3 重试与恢复路径

组执行异常后停止当前容器并重建，最多 max_retry 次；重试没有指数退避、错误分类或跨 Provider failover。进程重启时，仅以非空 statistics JSON 作为 checkpoint。Patch 已写而 statistics 未写会在重试时产生带递增后缀的额外 Patch；耗尽重试则没有终态统计，下一次全量运行会再次尝试。evaluation/patch_selection/trae_selector/selector_evaluation.py:87-97,146-297

未实现的阶段：README 建议候选很多时先分组、再从各组赢家中继续选择，但源码没有自动收集组赢家并执行最终决赛。当前产物是每组一个 Patch，不是 instance 唯一 Best Patch。evaluation/patch_selection/README.md:70-72

6. 数据与状态模型

6.1 输入文件契约

文件/字段类型与用途约束与缺口
instances JSONJSON array；至少消费 instance_id、base_commit、problem_statement。无本地 Schema；镜像必须已存在并与 instance 匹配。
candidate JSONL每行一个 object，以 instance_id 建字典。重复 id 后者静默覆盖；空行/坏 JSON 直接失败；编码未显式指定。
patcheslist[str]，原始 unified diff。与 labels/regressions 长度必须一致但不预检；空串在过滤阶段跳过。
regressionslist[list]；缺失时补成与 patches 等长的空列表。“缺失”因此被解释为“全部通过”，不是“未知”。
success_idlist[0|1]，评测 ground truth。实际上是必需字段；参与控制流和计分，不适用于盲测/生产选择。
issue候选文件中的 issue 文本。分组时复制但 Selector Prompt 使用 instances 的 problem_statement，两者漂移不会被检测。

6.2 中间状态与输出契约

路径内容写入/恢复语义
output/group_N/{instance}.log该组 retry、容器、Selector stdout/stderr。每次整组运行以 w 覆盖；异常详情写这里。
log/group_N/*_voting_V_trail_T.jsonSelector LLM 交互轨迹。唯一文件名递增；未调用 start_recording，task/provider/model/max_steps 保持 Recorder 初值，仅 interaction 与 finalize 字段可信。
patch/group_N/{instance}_T.patch选中的原始 Patch 文本。永不覆盖，trial 后缀递增；不记录配置哈希或候选集哈希。
statistics/group_N/{instance}.jsonpatch_id、is_success、全成/全败标志。固定路径覆盖写；非空即成为恢复 checkpoint。
analysis.csv按 group 汇总完成率、选择准确率等。每次 analysis 覆盖；无文件锁，运行中读取可能见到部分结果。

没有数据库、事务、manifest、实验 ID、配置快照、候选哈希、随机种子、租户或保留策略。所有状态都是共享目录中的普通文件。evaluation/patch_selection/trae_selector/utils.py:77-143

7. 接口、协议与事件

接口/协议请求响应/确认错误语义
脚本 CLIinstances、candidate、result、模型配置及预算参数。无结构化 stdout 响应；以目录产物表达结果。部分预检抛异常；日志目录创建失败打印后 exit()。
Selector PromptSystem 声明候选数、Issue、每个 Patch 全文。### Status: succeed、### Result: Patch-x、### Analysis:。正则不匹配则继续工具循环；合法状态但非法编号回退第一项并结束。
Tool Call 桥bash 或 str_replace_based_edit_tool 及 arguments。读取容器内 log.out，解析 Tool Call Status，构造 LLMMessage.tool_result。未知工具、dict 参数、脚本状态 -1 转失败 ToolResult。
Docker Session任意 shell command。pexpect 等待 shell prompt，返回去首尾后的文本。固定约 60 秒 TIMEOUT 返回字符串 Observation，不抛异常。
统计 checkpoint成功选择或标签短路。单个 JSON 文件非空即确认完成。没有原子 rename、checksum 或产物一致性确认。

幂等性是局部且不完整的：statistics 防止重复 LLM/Docker 工作，但 Patch 与 trajectory 使用唯一后缀，失败重跑会累积；配置变化也不会使旧 checkpoint 失效。

9. 并发、性能与资源

  • 并发层级：instances 由 ProcessPoolExecutor(max_workers) 并行；同一 instance 的 groups 串行；同一 group 的投票串行，不是模型请求并发。源码 docstring 错称 ThreadPool。evaluation/patch_selection/trae_selector/selector_evaluation.py:331-370
  • 调用上界：在没有提前多数、没有标签短路且每轮只产生一个最终响应的理想化上界下，每组最多 num_candidate × max_turn 次 LLM 调用；发生整组异常重试时再乘 max_retry。这只是源码预算上界，不是实测成本。
  • 容器资源：每个并发 instance 同时最多持有一个容器；源码没有 CPU、内存、PID、磁盘、网络配额，也没有全局 Docker/Provider 背压。
  • Prompt 成本：每次投票把该组所有原始 Patch 全文重新发送；LLM Client 默认复用单次 Selector 内历史。多数投票新建 Client，因此不会共享 KV/对话状态。
  • I/O：stdout/stderr 被进程级重定向到每组日志；Trajectory 每轮全量重写 JSON；analysis.py 可与写入并发但无锁。
  • 超时：Session.execute(timeout=60) 参数未传给 expect，内部固定 60 秒；外层工具命令还使用各自 120 秒逻辑，但桥接 shell 可先超时。evaluation/patch_selection/trae_selector/sandbox.py:61-104

仓库只记录 token usage，不把模型单价换算成货币成本；本文不提供吞吐、延迟或费用数字。

10. 安全与信任边界

边界/资产当前机制风险与结论建议控制
Docker Host容器以 privileged=True 启动，并把宿主 /tmp 读写挂载到容器。非强沙箱特权容器可显著扩大逃逸和宿主访问面。仅在隔离评测节点运行；移除 privileged，改为最小 capabilities/只读根文件系统/独立临时卷。
宿主工具目录宿主执行 chmod -R 777，再以 shell=True 调用 docker cp。修改工作区权限；路径/容器名未经 shell quote；工具供应链来自外部下载。固定 artifact hash，避免 shell=True，复制到隔离 staging，不修改源码树权限。
网络Docker run 未配置 network mode。默认网络行为由 Docker 环境决定，源码不能证明断网；恶意测试/仓库可外联。默认 network=none，按测试需求显式 allowlist。
候选与 Issue完整文本发给配置的 LLM Provider，并写入 Prompt/Trajectory/日志。可能包含私有代码、路径、Prompt Injection、许可证或个人数据；无脱敏。只处理获准数据；Provider 数据协议审查；预扫描 Secret；设置保留与删除策略。
API KeyKey 在宿主 ModelConfig 中解析并用于 Provider SDK；未显式传入容器。容器默认拿不到模型 Key是有限隔离，但宿主日志/进程仍是信任面。短期凭证、最小权限、避免写配置文件、隔离 worker 身份。
命令/文件工具Selector 可执行任意 bash、读取/编辑容器绝对路径。Prompt 约束不是访问控制；容器内任意代码和测试都不可信。命令策略、路径根限制、资源配额、seccomp/AppArmor、只读输入快照。
评测标签success_id 参与短路和结果计分。评测泄漏若用于算法选择、调参或报告全量表现，ground truth 已进入控制流。盲测路径完全移除标签；评分在选择结果冻结后由独立进程关联。
Fail-open 行为：如果所有候选都有非空 regression，过滤器不会淘汰任何一个，而是保留全部；缺失 regressions 则被补为空列表，相当于全部通过。安全或质量门禁不能依赖这一字段过滤。evaluation/patch_selection/selector.py:66-69；evaluation/patch_selection/trae_selector/selector_evaluation.py:184-190

11. 失败、恢复与兼容

故障/现象检测与即时行为状态影响恢复/运维操作
instance 无候选candidate_dic[id] KeyError，可能在 futures 构造阶段终止整个 run。未启动或部分已启动任务；无该实例统计。启动前做集合差和重复 id 检查。
字段长度不一致/空候选集索引错误或 candidate_list[0] 错误，进入整组 retry。重复建容器，耗尽后无 checkpoint。Schema 预检 patches/success_id/regressions 等长且过滤后非空。
malformed diffPatchSet 抛错，整组 retry。确定性坏输入被无退避重复。并发前单次解析并隔离坏 candidate，不应重试确定性错误。
镜像不存在/checkout 失败Docker 抛异常会重试；checkout 返回值只打印、不检查 exit code。可能在错误 commit 上继续选择。预拉镜像；校验 exec exit_code 和 HEAD。
LLM/Provider 失败底层 Client 自身 max_retries 后异常，再触发整组 retry。形成嵌套重试，成本放大。区分限流、认证、格式、确定性错误；认证失败应停止而非重建容器。
Tool TIMEOUT返回含 seconds. Partial output 的文本；Selector 替换 shell session。容器保留，未自动回滚已发生的副作用；下一 Selector 构造/结束会 hard reset tracked files。检查 untracked/process 状态；需要全新容器才能获得强恢复。
非法 Patch 编号状态正则匹配但编号越界，静默选第一项并 break。Trajectory 标成功，统计可能失败。将格式错误视为可重试响应，不要静默默认。
统计已存在但其它产物缺失非空统计文件触发 skip。不一致状态被当作完成。使用 manifest/原子提交，并校验 config/candidate hash 和全部产物。
耗尽 retryfinally 只打印 finished。无显式 failed statistics，run_all future 可正常返回 None。写失败终态与最后异常；批处理退出码应反映未完成数。

兼容面有限：输入/输出都没有 schema_version；镜像命名硬编码 x86_64 与字符串替换规则；README 要求 Python 3.12 工具包。Windows 宿主还依赖可用的 Docker CLI 与 pexpect 对交互 TTY 的兼容，当前没有平台测试证据。

15. 设计权衡与已知限制

选择收益成本/失败模式何时重评
文件式 JSON/JSONL 流水线简单、可离线检查、易接不同生成器。无 Schema/version/事务；共享目录并发和恢复脆弱。多实验并发、长期运行或需要严格复现时。
先分组再选择控制单次 Prompt 候选规模。组间没有自动决赛；分组顺序影响问题；每组都重复 Issue/代码调查。候选数大、需唯一全局结果或比较分组策略时。
LLM Agent 而非静态 scorer能阅读仓库和主动运行测试。高 token/时间成本、非确定性、工具副作用、格式解析脆弱。可用更可靠的可执行测试/形式化规则或预算受限时。
Majority Voting可能降低单次随机选择波动。最多按 num_candidate 重复整个 Selector；同模型同 Prompt 的相关误差不等于独立投票。应先量化增益、方差和边际 token 成本。
回归字段优先可利用上游测试信号缩小空间。缺失即通过、全失败则保留全部；测试选择偏差可误删正确候选。引入可验证三态结果和可信测试 provenance 时。
cleaned diff 去重忽略注释与空白差异，减少近重复候选。可能合并语义上不同的注释、字符串边缘或格式敏感修改；不考虑文件路径/上下文行。观察到碰撞或多语言 Patch 时。
Ground truth 短路有标签评测中避免无信息的全对/全错选择。标签进入算法控制流，不能作为盲测或部署路径；也改变成本统计。报告可泛化效果、做 leaderboard 盲测或生产使用时必须移除。

当前限制与证据缺口

  • 没有仓库内 Generator、生成轨迹到 candidate JSONL 的转换脚本或生成成本统计。
  • 没有自动回归执行；README 指向外部 Agentless，版本、命令和结果 provenance 未锁定。
  • 没有 evaluation 自动测试、CI job、E2E fixture 或支持平台矩阵。
  • 没有论文结果对应的配置、模型快照、候选集、随机种子、完整统计和成本，因此不能从当前源码独立复现报告数字。
  • 没有验证 success_id 的来源/时间点，也没有盲评隔离；评测泄漏风险必须在实验设计中单独审计。
  • 没有容器镜像 digest、外部 py312 artifact checksum、SBOM、网络策略或资源配额证据。
  • Roadmap 把高级多 Agent 协调列为未来能力；不能用 Patch Selection 反证主 Runtime 已实现在线多 Agent。docs/roadmap.md:68-83
