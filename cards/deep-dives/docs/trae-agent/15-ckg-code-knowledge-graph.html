1. 模块定位

准确定位：CKG 是一个可选的本地 Tool。首次查询某目录时，它用 tree-sitter 扫描受支持源码，把函数、类和方法定义写入 SQLite，再按标识符精确匹配返回位置、结构摘要及可选源码体。
边界负责委托明确不负责
CKGTool参数准入、按 Path 缓存数据库对象、三种查询和输出截断。索引与 SQL 查询委托给 CKGDatabase；异常归一化委托给 ToolExecutor。不做自然语言理解、模糊搜索、排序或访问授权。trae_agent/tools/ckg_tool.py:14-224
CKGDatabase快照 Key、SQLite 表、AST 遍历、插入与精确查询。语法树与 grammar 委托给第三方 tree-sitter 包。不建立继承边、调用边、import 边、影响传播或向量索引。trae_agent/tools/ckg/ckg_database.py:31-722
Tool FrameworkRegistry 发现、按配置实例化、并/串行调用和 ToolResult。具体查询语义归 CKG。“已注册”不等于“默认启用”。trae_agent/tools/__init__.py:27-34；trae_agent/agent/base_agent.py:37-45

它补充普通文件搜索：适合“已知定义名，找结构与源码”；普通文本搜索更适合任意字符串、引用点、配置与不受支持语言。CKG 查询结果进入 Provider 历史，但 CKG 本身不是 Context 管理器或跨任务 Memory。

4. 架构组成

4.1 Tool 契约与进程内缓存

CKGTool 暴露固定命令 search_function、search_class、search_class_method；path、identifier 必填，print_body 缺省为 true。一个 Tool 实例用 dict[Path, CKGDatabase] 缓存已经打开的目录。trae_agent/tools/ckg_tool.py:11-27,50-100

4.3 SQLite 与输出层

数据库只有 functions 和 classes 两张表；除自增主键外没有索引、唯一约束、外键或 graph edge 表。每插入一条记录就 commit。输出按查询返回顺序拼接，超过 16,000 字符时裁切。trae_agent/tools/ckg/ckg_database.py:122-145,576-646；trae_agent/tools/run.py:17-18

5. 完整运行流程

5.1 正常成功路径

1显式启用
YAML 的 agents.trae_agent.tools 加入 ckg；BaseAgent 从 Registry 构造 CKGTool。
2调用准入
Tool 检查 command/path/identifier 是否提供，且 path 存在并为目录。
3选择数据库
先查进程内 Path Map；首次访问才构造 CKGDatabase。
4计算快照
Git 可用且目录在 worktree 内则走 Git Key，否则遍历全部非隐藏文件的元数据。
5复用或重建
storage_info.json 的绝对路径映射命中同一 Key 且 DB 存在则复用；Key 改变时删除该路径旧 DB，写映射并新建表。
6AST 扫描
递归文件；跳过隐藏路径与未知扩展；按语言延迟取得 Parser，解析 bytes 并遍历受支持节点。
7精确查询
以 identifier 执行参数化 SQL；function/class_method 再按 parent_class 是否为空分流。
8返回观察
返回数量、绝对文件路径、行号、可选 body；ToolExecutor 包为 ToolResult，进入下一轮模型历史。

5.2 拒绝与提前结束

缺 command/path/identifier、路径不存在、路径不是目录、命令不在三项列表时，CKGTool 返回 error_code=-1，不会查询；查无精确名称不是错误，而是成功文本 No ... found.。trae_agent/tools/ckg_tool.py:81-133,140-143,169-172,202-205

5.3 恢复与降级

没有 CKG 内部重试。Parser、文件读取、JSON、SQLite 或删除失败会抛给 ToolExecutor，被转换成失败 ToolResult，Agent 可在后续轮次改用 bash/文本搜索。若重启 Tool，新构造会再次做快照判定；但已生成的部分数据库可能因文件存在而被复用，不能把“重启”视为可靠修复。trae_agent/tools/base.py:205-236

7. 接口、协议与事件

接口输入契约输出错误/幂等语义
ckg.executecommand enum；path/identifier string；print_body boolean 可选ToolExecResult参数缺失/路径/未知命令用 -1；内部异常向外抛。Schema 约束由模型侧生成，execute 仍自行检查关键字段。
search_function名称完全相等所有 parent_class IS NULL 的同名记录；其中可能包含嵌套函数只读查询；顺序没有 ORDER BY 保证。
search_class类名完全相等同名类，始终可带 fields/methods 摘要，print_body 只控制完整 body查无结果返回成功文本。
search_class_method方法名完全相等parent_class IS NOT NULL 的同名函数记录不支持用 Class.method 限定，也不能过滤文件/类。
CKGDatabase.update无参数None非幂等：直接再次插入，产生重复；主 Tool 未暴露此命令。

print_body 使用 Python bool(value) 转换；直接内部调用若传字符串 "false" 仍为 true。正常 Provider Schema 应传 JSON boolean，但这不是严格运行时类型校验。输出裁切按 Python 字符数在拼接后切片，可能截断源码或某条记录，尾部标记剩余条目数。trae_agent/tools/ckg_tool.py:94-100,135-224

模块不发事件、不写 Trajectory 自有记录。通用 Agent Step/ToolResult 可观察到调用参数与返回值；没有构建进度、扫描统计、缓存命中或 Parser 错误的结构化事件。

9. 并发、性能与资源

  • 同步阻塞：execute 是 async 声明，但构造、Git subprocess、全目录扫描、文件读取、parse 与 SQLite 都同步执行，会阻塞 Agent 事件循环。
  • 全量扫描：首次构建使用 glob("**/*")；没有 ignore 文件、大小上限、目录白名单、文件数/字节预算、取消点或构建超时。隐藏文件/目录除外。trae_agent/tools/ckg/ckg_database.py:534-574
  • 内存与磁盘：每个语法节点 body 同时存在于 tree-sitter Node/bytes 处理和 SQLite TEXT 中；class body 与其 method body会重复保存。大仓库可能带来高 CPU、内存、数据库体积和上下文输出。
  • 查询热路径：name 没有数据库索引，精确查询仍需表扫描；同名项多时先 fetchall 到内存再拼接，16,000 字符限制只约束最终文本，不约束查询或读取成本。
  • 并发无保护：全局 storage_info.json 无锁且整文件覆盖；多个 Agent/并行 ToolCall 可丢映射更新。相同 DB 也可能并发建表/写入，引发 SQLite 锁、重复或部分索引。
  • 清理竞态：每个 BaseAgent 构造都会扫并删除过期 DB，不检查是否正被另一进程打开。Windows 可能删除失败并打印错误；Unix 可 unlink 后让旧连接继续持有文件。
  • 连接清理：通用 close_tools() 会调用继承的空 close；CKG SQLite 连接依赖析构，不具备确定性释放。

源码没有容量、延迟或吞吐基准，也没有背压/并发上限。不能用“SQLite 很快”替代仓库规模测试。

10. 安全与信任边界

边界当前行为风险部署/开发要求
路径授权只验证存在且为目录，不要求位于任务 project root。模型可请求读取 Agent 进程账户可访问的任意目录；Docker 模式下 CKG 仍在 Host。把 path.resolve() 后的允许根校验放在 Tool 侧；不要依赖 Prompt。
本地持久化保存完整函数/类源码和绝对路径到用户 Home。Secret、专有源码、用户名/目录结构在任务后继续驻留；权限、备份和恶意本机用户可见性未控制。设置目录最小权限、明确保留/擦除策略；高敏仓库禁用或使用隔离账户。
模型输出面默认 print_body=true，结果进入外部 Provider 消息历史及可能的 Trajectory。源码和硬编码凭证可能离开主机；16k 裁切不是脱敏。默认调用时优先 false，读取具体文件前再授权；结合 Provider 数据策略。
Parser/grammar加载固定版本第三方二进制 wheel 与多语言 grammar，解析不可信源码 bytes。供应链、原生扩展崩溃、恶意超深/超大输入造成资源耗尽。锁定并验证制品；限制仓库/文件规模，在低权限进程或独立 worker 中解析。
SQLite/JSON用户可写 Home 中的文件直接打开/解析，没有签名。损坏或替换可造成拒绝服务、伪造检索结果；参数化 name SQL 可防止 identifier 注入，但不能保证缓存可信。保护目录所有权；损坏时隔离并重建，不把 DB 当可信制品分发。
CKG 没有认证、沙箱、Secret 检测、脱敏、加密或工作区 Allowlist。它是高读取权限工具；显式配置即授予模型结构化复制本地源码的能力。

12. 可观测性与排障

现象优先检查可能原因修复方向

15. 设计权衡与已知限制

当前选择收益成本/失败模式何时重评
手写每语言 AST visitor实现直观，可精确控制输出字段语言覆盖不一致，grammar 升级易漂移；JS/TS 普通函数缺失语言或节点种类增长、需要统一符号模型时
完整 body 存 SQLite一次查询可直接给模型源码磁盘重复、隐私暴露、索引/输出成本高大仓库、多用户、敏感代码或只需定位时
Snapshot DB 整体复用干净提交上重复启动快有未提交修改/元数据 Key 不够内容敏感；失败可留下部分 DB交互式编辑后查询或 CI 并发成为常态时
SQLite 两表、精确 name依赖少、查询契约简单、参数化安全无索引/边/限定条件/排名，名称冲突结果大需要文件/类限定、稳定性能或关系查询时
CKGTool 内 Path 对象缓存同任务避免反复打开 DB编辑后不刷新；Path 未规范化；连接不确定关闭工具用于“读取—编辑—再查询”循环时
错误交给 ToolExecutorAgent Loop 保持运行，可改用其它工具缺构建阶段/文件级诊断；部分 DB 可能被缓存需要可运营的大仓库索引服务时

当前已证实的能力边界

  • 只有 Python、Java、C++、C、TypeScript、JavaScript 的列出扩展名进入解析；实际符号覆盖以第 4 节 visitor 矩阵为准。
  • 只有函数、类、方法、部分字段/方法摘要及父函数/父类名称标签；没有模块、import、引用、调用、继承、类型、控制流或数据流边。
  • 只有精确标识符查询；没有前缀/模糊/正则/全文/语义搜索，也没有影响分析。
  • 语法错误不 fail-closed；无错误节点检测意味着“成功建库”不证明完整索引。
  • 缓存不是强一致；更新方法非幂等；并发、原子发布和确定性连接清理缺失。

这些限制是当前工作区源码事实，不代表 tree-sitter 或 SQLite 本身不支持更强能力，也不构成 Roadmap 承诺。
