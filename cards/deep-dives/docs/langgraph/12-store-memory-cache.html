十二、Store、Memory 与 Cache

把跨 thread 长期记忆、执行恢复与节点结果复用拆成三个可审计契约，并沿 Runtime/ToolRuntime 跟踪真实注入链。

1. 模块定位：三种“记忆”不可互换

Store 是跨 thread、跨会话的业务数据平面；Cache 是按节点输入复用节点 writes 的执行优化；Checkpointer 是 Pregel 超级步与 task 写的恢复协议。三者都可能“保存东西”，但身份、生命周期和失败语义完全不同。

机制身份键保存内容生命周期明确不负责
Checkpointerthread_id + checkpoint_ns + checkpoint_idChannel 值/版本、versions_seen、pending writes执行线程与历史分支用户语义检索、通用 KV
BaseStorenamespace + key业务 dict、时间戳，可选向量与 TTL由应用、租户和适配器管理恢复节点调度位置
BaseCache内部 namespace + 输入摘要成功节点的 writes 与秒级 TTL可随时清除、命中失败可重算业务真相、授权、跨版本兼容

Checkpointer 的公共说明明确把 checkpoint 定义为图状态快照并区分 put_writes 与 put；Store 则声明为可跨 thread 共享的 namespace KV。libs/checkpoint/README.md:17-33；libs/checkpoint/langgraph/store/base/__init__.py:708-724

设计评审时先问“这是恢复执行、保存业务事实，还是省一次计算？”答案分别落到 Checkpointer、Store、Cache。不要用一个模糊的 memory 变量掩盖所有权。

3. 核心概念：Batch、Namespace、TTL、Vector 与 Writes

3.1 batch/abatch 是 Store 的最小实现面

BaseStore 只要求适配器实现有序的 batch(Iterable[Op]) 与 abatch；get/search/put/delete/list_namespaces 及其异步版本都把单次调用规范化为 GetOp、SearchOp、PutOp、ListNamespacesOp。结果必须与输入操作按位置对应。libs/checkpoint/langgraph/store/base/__init__.py:708-754；libs/checkpoint/langgraph/store/base/__init__.py:756-777

3.2 Namespace 是层级作用域，不是授权系统

namespace 为 tuple[str, ...]，搜索使用前缀，枚举可组合 prefix/suffix、通配符、深度和分页。公共 put/aput 拒绝空 namespace、空标签、含句点标签及保留根 "langgraph"；但直接调用适配器 batch/abatch 可绕过公共入口校验，因此自定义适配器不能把它当安全边界。libs/checkpoint/langgraph/store/base/__init__.py:1263-1283；绕过行为由 libs/checkpoint/tests/test_store.py:429-480 固化。

3.3 两套 TTL 单位不同

  • Store 的 PutOp.ttl 与 TTLConfig 使用分钟，读取可刷新过期时间，物理删除是 best effort。libs/checkpoint/langgraph/store/base/__init__.py:526-575
  • Cache 的 CachePolicy.ttl 使用秒，传入 BaseCache.set/aset。libs/langgraph/langgraph/types.py:520-529；libs/checkpoint/langgraph/cache/base/__init__.py:24-38

3.4 Vector search 是可选索引，不改变 KV 身份

IndexConfig 提供 dims、embedding 函数/对象/provider 字符串和字段路径；未配置时语义搜索禁用，index 参数被忽略。index=False 仅不建向量，条目仍可 get 和结构化 search。字段路径支持嵌套、数组索引和 [*]。libs/checkpoint/langgraph/store/base/__init__.py:490-534；libs/checkpoint/langgraph/store/base/__init__.py:578-705

5. 完整运行流程：成功、拒绝与恢复/降级

5.1 成功路径：Store 写入并由 ToolRuntime 读取

  1. 应用以租户与用户组成 namespace，例如 ("tenant", tenant_id, "user", user_id, "memory")；调用 put 时公共入口校验 namespace，并生成 PutOp。
  2. 适配器 batch 按类型分组；若启用索引，提取字段并批量调用 embedding；数据库实现将业务值、TTL 与向量写入事务。
  3. compile(store=store) 将 Store 放入 Pregel；每个 task 准备时，Runtime 被 override 为当前 store 和 ExecutionInfo。libs/langgraph/langgraph/pregel/_algo.py:688-701
  4. ToolNode 为每个 tool call 构造独立 ToolRuntime，转发 context/store/writer/执行身份；同步工具走 executor，异步工具由 asyncio.gather 并发。libs/prebuilt/langgraph/prebuilt/tool_node.py:793-858
  5. 注入阶段移除模型伪造的隐藏参数，再注入可信 store/runtime；工具按 namespace get/search，返回 ToolMessage/Command，最终成为普通节点 writes。libs/prebuilt/langgraph/prebuilt/tool_node.py:1407-1429

5.2 拒绝路径：配置、namespace 与注入 fail-closed

  1. 空 namespace、非法标签或保留根在公共 put/aput 前抛 InvalidNamespaceError，没有 Store 写。libs/checkpoint/langgraph/store/base/__init__.py:919-935
  2. 适配器未声明 supports_ttl 且调用者给非空 TTL 时抛 NotImplementedError；不会悄悄接受一个无法执行的过期承诺。libs/checkpoint/langgraph/store/base/__init__.py:919-924
  3. 工具声明 InjectedStore 但图未提供 Store 时，在工具执行前抛 ValueError；不会把 None 交给工具继续副作用。libs/prebuilt/langgraph/prebuilt/tool_node.py:1407-1415

5.3 缓存成功、miss 与降级路径

  1. task 准备阶段选择节点级 policy，否则使用图级 policy；key_func(input) 的结果经 xxh3-128 摘要，namespace 包含内部 writes 标识、节点 runnable identity 与节点名。libs/langgraph/langgraph/pregel/_algo.py:663-687
  2. Loop 只为“有 cache key 且当前没有 writes”的 task 批量查询缓存；命中后把缓存的 writes 扩展进 task，节点不执行，updates stream 带 {"cached": true}。libs/langgraph/langgraph/pregel/_loop.py:1549-1562；libs/langgraph/langgraph/pregel/_loop.py:1416-1466
  3. miss 时正常执行节点；成功提交后缓存的是 task.writes，不是节点返回对象、整图 state 或 checkpoint。同步与异步写回见 libs/langgraph/langgraph/pregel/_loop.py:1609-1625、libs/langgraph/langgraph/pregel/_loop.py:1864-1883。
  4. Redis 不可用或值损坏时读返回空映射、写静默丢弃，图降级为重算；这是 cache 的 fail-open，不适用于 Store 或 Checkpointer。libs/checkpoint/langgraph/cache/redis/__init__.py:52-78；libs/checkpoint/langgraph/cache/redis/__init__.py:84-108

7. 接口、协议与事件：注入面与可见性

7.1 Runtime 与 ToolRuntime

Runtime[ContextT] 注入图节点和 middleware，包含 context、store、stream_writer、previous、execution_info 等，但不含 RunnableConfig；节点需要 config 时应显式声明。libs/langgraph/langgraph/runtime.py:124-141；字段定义见 libs/langgraph/langgraph/runtime.py:198-238。

ToolRuntime 是工具专用注入对象，增加 state、config、tool_call_id、tools，并共享 context/store/writer。参数只需类型标注为 ToolRuntime；InjectedStore 则用于只注入 Store 的 Annotated 参数。libs/prebuilt/langgraph/prebuilt/tool_node.py:1662-1685；libs/prebuilt/langgraph/prebuilt/tool_node.py:1829-1900

7.2 模型 schema 与信任边界

InjectedState、InjectedStore 和 ToolRuntime 参数由系统识别，不属于模型应控制的普通参数；执行前还会剥离 tool call 中同名伪造值，再覆盖可信值。缺 Store 或缺必需 state 字段时在工具调用前拒绝。libs/prebuilt/langgraph/prebuilt/tool_node.py:1315-1348；libs/prebuilt/langgraph/prebuilt/tool_node.py:1363-1429

7.3 缓存事件

缓存命中不会产生真实 task 完成事件；updates 会带 cached metadata，而普通 cache API 没有命中率、错误或 eviction 事件协议。需要指标时应在自定义 BaseCache 包装器记录 get/set/miss/error/latency，不应从节点调用次数反推全部原因。

9. 并发、性能与资源：锁、队列、批次和背压

9.1 Store 并发模型

  • AsyncBatchedBaseStore 在构造时绑定 running loop，以无界 asyncio.Queue 收集同一 tick 操作；重复 get/search 去重，同键 put 后者覆盖，结果再映射回每个 Future。取消 Future 会在入批前或回填时跳过。libs/checkpoint/langgraph/store/base/batch.py:58-101；libs/checkpoint/langgraph/store/base/batch.py:283-366
  • 在该 Store 所属主 event loop 内调用同步方法会抛 asyncio.InvalidStateError，防止 run_coroutine_threadsafe(...).result() 自锁；异步代码必须使用 await store.a*。libs/checkpoint/langgraph/store/base/batch.py:33-53
  • SQLite 同步 Store 用单把 lock 串行化共享连接并把整个 batch 放进事务；高并发不会变成并行 DB 操作。libs/checkpoint-sqlite/langgraph/store/sqlite/base.py:1039-1058
  • Postgres 可使用 pool 并发借连接；单连接 pipeline/transaction 路径在需要时加 lock，异步实现使用 asyncio.Lock。libs/checkpoint-postgres/langgraph/store/postgres/base.py:960-980；libs/checkpoint-postgres/langgraph/store/postgres/aio.py:142-160

9.2 Cache 并发模型

InMemoryCache 用 RLock 将 get/set/clear 原子化到单进程临界区；SqliteCache 用共享连接、RLock 和 WAL，并用 asyncio.to_thread 提供异步包装。libs/checkpoint/langgraph/cache/memory/__init__.py:11-31；libs/checkpoint-sqlite/langgraph/cache/sqlite/__init__.py:13-44；libs/checkpoint-sqlite/langgraph/cache/sqlite/__init__.py:74-114

RedisCache 的 aget/aset/aclear 直接调用同步方法，并非真正异步 Redis I/O；若传入慢同步客户端，会阻塞 event loop。其 clear 使用 KEYS 扫 prefix，keyspace 较大时可能造成服务端停顿；生产扩展应评估 SCAN 或版本化 prefix。libs/checkpoint/langgraph/cache/redis/__init__.py:80-112；libs/checkpoint/langgraph/cache/redis/__init__.py:114-144

9.3 Embedding 与背压

InMemoryStore 同步查询会为不同 query 启动 ThreadPoolExecutor，异步查询用 gather；数据库适配器也会在批次内调用 embedding provider。代码未定义并发上限、重试或速率限制，调用者必须在 embeddings 包装层实现预算与背压。libs/checkpoint/langgraph/store/memory/__init__.py:268-300

10. 安全与信任边界：多租户、注入与副作用

10.1 多租户 namespace 设计

推荐把不可伪造的服务端 tenant/user identity 放在 namespace 最前部，并由可信 Runtime context 构造，而不是接受模型或请求正文给出的完整 namespace。例如 ("tenant", tenant_id, "user", user_id, "memories", schema_version)。Store 自身只匹配 tuple，不验证“当前用户是否拥有该前缀”；本地 Runtime 也不自动提供 Auth。

禁止把所有用户写进 ("memories",) 后仅靠 value filter 隔离。filter 是检索条件，不是行级安全；漏传 filter 或向量搜索实现差异都可能跨租户泄露。

10.2 Tool 注入防伪

ToolNode 先去除调用方提供的 injected 参数，再加入可信 Runtime 值，避免 LLM 在 tool args 中伪造 Store、state 或 runtime。该保护只覆盖注入参数；普通参数仍由模型控制，工具必须校验资源 ID、操作类型和权限。libs/prebuilt/langgraph/prebuilt/tool_node.py:1421-1429

10.3 序列化与 Secret

BaseCache 默认 JsonPlusSerializer(pickle_fallback=False)，减少缓存反序列化退回任意 pickle 的风险；但缓存和 Store 内容仍可能落到 SQLite/Postgres/Redis，不能写入明文 API key、访问令牌或无保留期限的敏感 prompt。libs/checkpoint/langgraph/cache/base/__init__.py:15-22

10.4 副作用节点误缓存

缓存命中直接恢复 writes，节点函数不再执行。因此“发送邮件、扣款、写外部 DB、审计记录、权限检查、读取当前时间/随机数”的节点若被缓存，会跳过副作用或返回过期授权结果。安全默认是：副作用节点不配置 CachePolicy；纯计算与只读检索节点才缓存，并让 key 包含影响结果的租户、权限版本、模型/提示版本与数据版本。

最小自定义 Store 原则

  • 把 batch/abatch 当公共一致性核心：结果长度和顺序必须严格对应输入；未知 Op 显式失败。
  • 明确支持能力：未支持 TTL 时保留 supports_ttl=False；未配置向量时不要伪造 score。
  • 批次原子性、同批读写可见顺序、重复 Put 规则必须写测试，不能从“batch”一词推断事务。
  • 同步与异步不是简单函数名复制：检查 event-loop 阻塞、连接池、锁、取消和清理。

15. 设计权衡与已知限制

Batch-first API收益是后端可分组查询与批量 embedding；成本是同批读写顺序不一定等价逐条调用，适配器必须明确快照与覆盖语义。
Writes cache收益是 Graph/Functional API 共享同一恢复形态；成本是缓存与 Channel 写格式耦合，代码/节点 identity 漂移需要失效策略。
Fail-open Redis收益是缓存故障不阻断图；成本是异常被吞，若无指标会长期退化且难发现。
显式 TTL sweeper收益是生命周期由应用控制；成本是遗漏启动造成过期数据滞留，遗漏停止造成资源泄漏。
Namespace 灵活收益是可表达任意租户/用户/版本层级；成本是协议不含授权，错误前缀会直接变成隔离漏洞。
同步/异步兄弟类收益是匹配不同驱动；成本是能力与错误语义可能漂移，必须用 parity 测试约束。

当前限制与证据缺口

  • 本仓库没有为 Store namespace 提供本地统一 Auth/RBAC；远程 Server 的租户与授权不能推导为本地默认能力。
  • BaseStore 不声明批次全局原子性、分页快照隔离或跨后端一致 score；这些由适配器和数据库决定。
  • RedisCache 的异常降级无日志/指标，async 接口也不提供非阻塞 I/O 保证。
  • 同步/异步缓存失败写守卫存在实现不对称，需回归测试和维护者决策。
  • Cache 不参与 checkpoint 事务；命中结果与外部数据新鲜度只由 key、TTL 和主动清除控制。

17. 术语表

术语本文含义
Batch / AbatchStore 的同步/异步最小批处理契约；结果按输入位置对应，不天然等于跨所有后端的原子事务。
CachePolicy节点/task 的缓存策略，定义输入 key 函数和秒级 TTL；没有 BaseCache 时不产生实际复用。
Cached writes节点成功产生的 Pregel writes；命中时注入 task，跳过节点函数，不是整图快照。
Checkpointer保存 Channel 状态、版本和 pending writes 的执行恢复组件，与业务 Store 分离。
Embedding把文本转成固定维度向量的函数/模型；可能是外部网络副作用并受维度、模型与费用约束。
Fail-open依赖失败时继续主流程。本文 RedisCache 把连接/损坏值降级为 miss；Store 不采用该默认语义。
InjectedStoreToolNode 识别的隐藏工具参数标记，从可信 Runtime 注入 BaseStore，不暴露给模型控制。
Item / SearchItemStore 条目及带可选相似度 score 的搜索结果；身份由 namespace + key 决定。
Namespace层级字符串 tuple，用于数据组织和查询作用域；它本身不是 Auth/RBAC。
Runtime图节点的 run-scoped 依赖容器，携带 context、store、stream writer 和执行身份等。
Semantic search基于 embedding 相似度的语义检索；只有适配器配置 index 后才启用。
Store跨 thread/会话的业务 KV 与可选搜索能力；不保存 Pregel 调度位置。
Sweeper周期性物理删除过期 Store 条目的后台线程或 task；SQLite/Postgres 需要显式启动。
TTLTime-to-live，存活时间。Store 使用分钟，CachePolicy/BaseCache 使用秒，必须显式区分。
ToolRuntime工具专用 Runtime，增加 state、config、tool_call_id 和 tools，同时共享 context/store/writer。
Vector indexnamespace/key 条目的一个或多个字段向量；index=False 不影响普通 KV 可达性。
