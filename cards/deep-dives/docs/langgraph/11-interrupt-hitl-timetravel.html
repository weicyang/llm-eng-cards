第 11 章：Interrupt、HITL 与 Time-travel

1. 模块定位

本模块负责在 Pregel 可恢复边界上表达“现在暂停、向调用者暴露什么、以后用哪个值继续”，以及从历史 checkpoint 重放或分叉。它依赖 Checkpointer 保存 Channel 状态和 pending writes；不保存函数调用栈，也不替业务系统提供审批权限、审计签名或外部事务的 exactly-once。

范围负责委托 / 明确不负责
静态中断interrupt_before/interrupt_after 在节点边界暂停不携带动态问题值，不使用节点内 scratchpad index
动态中断interrupt(value)、Interrupt.id、Command(resume=...)审批身份、授权、输入净化由应用或远程服务负责
恢复pending INTERRUPT/RESUME、任务重建、旧 resume 清理外部副作用幂等由节点/基础设施负责
时间旅行get_state_history、指定 checkpoint_id、update_state 与 fork历史保留能力由具体 Saver 决定；Store 不是执行历史

公共 Interrupt 只保留 value 与 id；StateSnapshot 同时暴露待执行任务和聚合后的 pending interrupts。libs/langgraph/langgraph/types.py:575-618、libs/langgraph/langgraph/types.py:683-701

相邻第 9 章负责 Checkpoint/Durable Execution，第 7 章负责 Pregel 超级步，第 13 章负责 stream 传输。本章只解释这些机制怎样承载暂停、恢复与分叉，不把远程 Server 的队列、Auth 或 UI 当成本地 Runtime 内建能力。

3. 核心概念

静态 interrupt图编译或本次 stream 配置的节点边界断点。Loop 在任务执行前或本步 apply/checkpoint 后检查，不生成带业务 value 的动态 Interrupt。
动态 interrupt(value)节点代码主动请求输入。无 resume 时抛 GraphInterrupt；恢复后节点从头调用，按 scratchpad index 取回值。
HITLHuman-in-the-loop（人在回路）：应用读取 Interrupt(value,id)，执行授权/审批，再提交 Command(resume=...)。
Time-travel读取历史 checkpoint，并从该历史点 replay；如继续产生执行记录，则创建保留旧分支的新 fork。
易混点正确区分
暂停位置静态 before/after 是超级步任务边界；动态 interrupt 是节点内部表达，但恢复仍从节点入口开始。
index 与 idindex 是单 task 内按调用顺序递增的位置；id 是 checkpoint namespace 的 xxh3-128 hash，用于跨 pending task 定向 resume。
resume list 与 resume maplist 是 scratchpad 内某 task 已消费值的顺序记录；map 是客户端的 {Interrupt.id: value} 定向输入。
replay 与 retryreplay 主动选择历史 checkpoint 创建新执行分支；retry 是同一 task 失败策略，不等于时间旅行。
update 与原地修改update_state 模拟某节点写入并创建新 checkpoint；旧 checkpoint 保留。

3.1 从离散步骤到长期等待

LangChain 官方设计长文把“结构化为离散步骤”视为 checkpoint 与 HITL 的前提：单个大循环或活着的 generator continuation 难以保存为可移植状态；Pregel/BSP 则把执行组织为带屏障的超级步，使 Channel 值、版本和已见版本可以序列化。Google Pregel 提供的是超级步、消息传递与屏障这一基础计算模型；LangGraph 在其上增加 checkpoint、动态 interrupt 和 resume 协议。当前 Loop 确实在任务规划后执行节点，并在超级步 writes 合并后保存 checkpoint。libs/langgraph/langgraph/pregel/_loop.py:599-724

因此“等待数天或数月”不是让 Python 调用栈、worker 或某台机器一直挂起：持久化边界完成后本次运行可以退出，之后任意合适进程用同一持久线程重新载入状态。映射到当前 API，就是图必须配置可持久化 checkpointer，调用必须带稳定 thread_id；恢复端再次调用图并提交 Command(resume=...)，Loop 才会把回答写入恢复协议。无 checkpointer 的 resume 会被明确拒绝。libs/langgraph/langgraph/types.py:862-871、libs/langgraph/langgraph/pregel/_loop.py:851-920

types.py 的当前公共契约是：恢复从节点开头重新执行全部逻辑，不是从 interrupt() 所在行继续，也没有恢复 Python 栈帧。重建 task 时，scratchpad 从 index 0 重新匹配已持久化的 task-scoped resume list；所以 interrupt 调用顺序必须稳定，中断前副作用必须幂等、可去重，或拆到审批后的独立节点。libs/langgraph/langgraph/types.py:858-871、libs/langgraph/langgraph/types.py:950-974
结构化执行让 tracing、UI 和审批工作流更容易集成，但本地 interrupt() 自动提供的只是暂停值、checkpoint 恢复与 resume 路由。Tracing/可视化属于 LangSmith、Studio 或其他观测集成；审批策略、身份认证、授权、租户隔离和通知属于应用或平台，不能从本地 interrupt 推导为已自动具备。

4. 架构组成

4.1 静态边界判定器

should_interrupt 先比较 checkpoint.channel_versions 与 versions_seen[INTERRUPT]，确认自上次暂停后存在版本推进，再筛选命中的可见 task；"*" 会排除带 hidden tag 的 task。这避免仅用 invoke(None) 继续时原地再次暂停。libs/langgraph/langgraph/pregel/_algo.py:155-185

Loop 在执行前检查 interrupt_before，在 apply writes、清 pending writes、保存 checkpoint 后检查 interrupt_after。libs/langgraph/langgraph/pregel/_loop.py:667-724

4.2 动态 interrupt 与 scratchpad

PregelScratchpad 持有原子式 interrupt_counter、task-scoped resume list 与一次性 get_null_resume。每次 task 重建都会重新从 index 0 计数，而已保存的 resume list 让前序调用直接返回。libs/langgraph/langgraph/_internal/_scratchpad.py:8-19、libs/langgraph/langgraph/pregel/_algo.py:1333-1345

interrupt() 依次尝试：按 index 读取 task resume list；消费单值 null-task resume 并追加到 list；都不存在时基于 checkpoint namespace 生成 Interrupt.id 并抛出。libs/langgraph/langgraph/types.py:950-974

4.3 Runner 与持久写

Runner 捕获 GraphInterrupt 后，将 INTERRUPT 以及 task 已产生的 RESUME 一并交给 put_writes；根图抑制该控制异常并向调用者暴露 interrupt，子图则可沿 GraphBubbleUp 上抛。libs/langgraph/langgraph/errors.py:102-107、libs/langgraph/langgraph/pregel/_runner.py:584-603

4.4 历史视图与状态更新

get_state 读取一个 checkpoint 并组装 StateSnapshot；未显式给 checkpoint_id 时可应用当前 pending writes。get_state_history 委托 Saver 的 list 并把每项还原为 snapshot。libs/langgraph/langgraph/pregel/main.py:1392-1434、libs/langgraph/langgraph/pregel/main.py:1480-1531

update_state 是单超级步的 bulk_update_state 包装；必须有 checkpointer，拒绝空 supersteps，并可以把请求委托给 namespace 对应的子图。libs/langgraph/langgraph/pregel/main.py:1590-1638、libs/langgraph/langgraph/pregel/main.py:2515-2541

5. 完整运行流程

路径 A：静态 interrupt_before/after 成功暂停与继续

  1. 输入与校验：StateGraph.compile 把空值规范化为列表，并验证列出的节点存在；"*" 是特殊全选值。未知节点在编译时拒绝。libs/langgraph/langgraph/graph/state.py:1129-1174、libs/langgraph/langgraph/graph/state.py:1256-1267
  2. 调度：Loop 准备当前超级步 tasks；before 在节点运行前检查，after 在本步 writes 应用并 checkpoint 后检查。
  3. 状态变化：暂停标记由 versions_seen[INTERRUPT] 与 Channel 版本共同控制；恢复时将当前版本记为已见，避免同一边界立即再次命中。libs/langgraph/langgraph/pregel/_loop.py:945-951
  4. 输出与最终状态：执行返回暂停状态；持久线程用同一 thread_id 再次 invoke(None, config)，进入下一个可运行边界。无 state key 更新的 noop 节点也可按边界逐步暂停。libs/langgraph/tests/test_interruption.py:11-50

路径 B：动态 interrupt 的提前结束、拒绝与恢复

  1. 触发：节点调用 interrupt(question)；首次无 resume，抛 GraphInterrupt((Interrupt(...),))。
  2. 持久化：Runner 写 task 级 INTERRUPT；snapshot 汇总 task interrupts，stream/invoke 向客户端暴露 __interrupt__。
  3. 准入：客户端提交 Command(resume=value)。若无 checkpointer，Loop 直接报错；若当前有多个未恢复 interrupt，单值 resume 被拒绝，必须用 id map。libs/langgraph/langgraph/pregel/_loop.py:902-928
  4. 恢复：节点从头运行。第一个 interrupt 的 index 0 返回已保存值；若函数随后到达第二个 interrupt 且尚无值，再次暂停。两个顺序 interrupt 的测试展示了“两次 resume、三次节点进入”的语义。libs/langgraph/tests/test_pregel.py:4838-4906
  5. 最终状态：最后一个 resume 被消费后，节点返回 partial update，进入普通 Channel 合并和后续节点。
恢复绝不是从 interrupt() 下一行继续。中断前的计费、发信、数据库 insert、HTTP POST、文件写入都会再次执行。把不可逆副作用拆成审批后的独立节点，或使用由 thread/task/业务对象组成的稳定幂等键，并让外部系统支持 upsert/dedup。

路径 C：历史 replay、update_state 与 fork

  1. 选择历史：get_state_history(config) 返回带 configurable.checkpoint_id、next、values、tasks、interrupts 和 parent 的 snapshots。
  2. 只重放：把历史 snapshot 的 config 传给 invoke(None, historical_config)。历史点之前的节点不重跑，next 指向的节点重新执行。若该节点调用 interrupt，旧 RESUME 不应被复用，问题重新触发。libs/langgraph/tests/test_time_travel.py:226-282
  3. 修改并分叉：update_state(historical_config, values, as_node=...) 按图 writer/Channel 语义生成新 checkpoint config；随后从新 config invoke，后继节点读取修改后的分支状态。libs/langgraph/tests/test_time_travel.py:143-179
  4. 清理旧控制写：Loop 识别真正 time-travel 时删除旧 RESUME；创建 replay fork 前还删除旧 INTERRUPT，避免新 task id 与旧 pending 控制写混杂。libs/langgraph/langgraph/pregel/_loop.py:874-900、libs/langgraph/langgraph/pregel/_loop.py:952-971
  5. 最终状态：新 checkpoint 的 parent 指向分支点，旧分支仍可列出；新 resume 只推进新分支。完整测试验证 source=fork 与新旧回答并存。libs/langgraph/tests/test_time_travel.py:285-392

9. 并发、性能与资源

  • 超级步：多个兄弟 task 可同时动态 interrupt；它们读取同一稳定 Channel 快照，各自拥有 task id、namespace、scratchpad 和 resume list。
  • 多 pending：Loop 扫描 pending writes，建立 task id → interrupt id，并排除已有 task-specific RESUME 的项；剩余集合决定是否要求 id map。libs/langgraph/langgraph/pregel/_loop.py:818-846
  • 原子计数：scratchpad 使用 LazyAtomicCounter 生成 interrupt index，避免普通 +=1 的线程安全问题；但业务函数必须保持 interrupt 调用顺序稳定。libs/langgraph/langgraph/pregel/_algo.py:1333-1341
  • 部分恢复：id map 可以一次回答全部 pending，也可只回答部分；未命中的 task 继续保持 interrupt，已命中 task 可完成并产生 writes。并发子图测试验证逐个恢复与缓存成功结果。libs/langgraph/tests/test_pregel.py:7577-7732
  • 资源成本：历史查询的时间/空间取决于 Saver 保留的 checkpoint 数、values 大小和 pending writes；本模块没有固定容量、TTL 或 SLA。
不要在条件分支中改变同一节点内 interrupt 的数量或顺序后，仍期望旧 resume list 正确配对。index 是“调用序号”，不是语义字段名；代码升级应通过迁移测试保护既有暂停线程。

10. 安全与信任边界

边界风险必须由谁控制
Interrupt.value 出站提示中泄露 PII、Secret、内部 tool 参数节点在调用 interrupt 前最小化/脱敏；stream 与 Saver 按敏感数据保护
Command.resume 入站未授权审批、类型混淆、prompt/tool 注入应用/API Server 做身份、租户、thread 所有权、schema 与业务策略校验
id map跨 thread 猜测/重放 id不能只凭 hash id 授权；必须同时绑定用户、thread、namespace 和当前 pending 集
time-travel绕过已发生审批、读取旧敏感状态、重复外部动作运维权限、审计日志、分支政策和副作用幂等由应用平台负责
checkpoint serde不可信对象反序列化Checkpointer/Serde allowlist 与存储访问控制；本模块不提供 Auth

Interrupt.id 是 namespace hash，用于路由而非安全令牌；公共类型没有签名、过期时间或 principal 字段。libs/langgraph/langgraph/types.py:593-618

本地 OSS Runtime 的 fail-closed 只体现在结构性拒绝（例如多 pending 禁止单值 resume、无 checkpointer 禁止动态 resume）。谁有权回答、回答内容是否合法、是否需要四眼审批，不在该代码路径内。

15. 设计权衡与已知限制

问题当前选择收益成本 / 失败模式重评条件
跨进程暂停保存状态与 writes，节点从头重跑不依赖 Python 栈，可跨时间/进程中断前逻辑重复，要求幂等若引入可序列化 continuation，需重新评估复杂度与安全
长期 HITL 等待离散步骤边界 + 持久 checkpoint；等待时释放本次进程/机器大量暂停线程不必各自占住活 worker，可在以后由其他进程恢复必须有耐久 Saver、稳定 thread_id 与恢复调度；本地库不自动提供队列、通知或审批 SLA若运行环境不能长期保存 checkpoint，或恢复必须保留进程内资源时
多个调用匹配task 内按调用 indexAPI 简单，普通顺序代码自然条件分支/代码升级改变顺序会错配需要长期版本迁移时可考虑显式业务 key 协议
并发定向恢复namespace hash id map一次或部分恢复多个 taskid 不是认证信息，fork 后身份可变远程协议需额外签名/租户绑定时由 Server 扩展
历史修改append-only fork，而非原地覆盖保留审计与旧分支存储增长、查询/保留策略更复杂受限 Saver 可只保 head，但会失去完整 time-travel
静态断点重复抑制Channel 版本与 versions_seen无须额外 UI token新输入会合法地再次命中若业务需要一次性全局断点，应在应用层建策略状态

当前限制：本地 Runtime 没有内建 tracing 后端或可视化 UI，也没有审批 TTL、撤销、角色模型、身份认证/授权、双人复核、外部事务协调或 exactly-once；这些属于观测集成、应用协议或 LangGraph Platform / LangSmith 等平台表面，不能写成 Interrupt/Command 自动能力。完整历史也不是所有 Saver 的必然能力。

17. 术语表

术语本章含义
HITLHuman-in-the-loop，人在回路；执行暂停并由人类或治理系统提供决策。
Static interrupt通过 interrupt_before/after 配置的节点边界暂停，不等同于节点内 interrupt(value)。
Dynamic interrupt节点调用 interrupt(value) 产生的可恢复控制异常与业务提示。
Interrupt id由 checkpoint namespace 派生的稳定 hash，用于把 resume 定向到 pending interrupt；不是授权令牌。
Scratchpad单个 Pregel task 执行期的运行辅助对象，保存调用计数器、resume list 与父级 resume 访问器。
Interrupt index同一 task 内 interrupt() 的调用序号，用来匹配顺序 resume 值。
Resume map{Interrupt.id: value}，用于一次定向恢复一个或多个并发 pending interrupts。
Pending write绑定 checkpoint 与 task id 的中间写；本章关键类型是 INTERRUPT 与 RESUME。
Replay从显式历史 checkpoint 重新执行该点之后的任务。
Fork从历史点创建新 checkpoint 分支并保留旧分支；metadata source 可标记为 fork。
Time-travel历史查询、选择 checkpoint、replay/update/fork 的统称，不表示回滚外部世界。
Idempotency幂等性；同一操作重复执行仍得到等价外部结果，是 interrupt 重跑前置副作用的业务责任。
Checkpoint namespace区分父图、子图与具体 task 路径的持久化命名空间，也是动态 interrupt id 的输入。
Sourcecheckpoint metadata 的来源标签，如 input、loop、update、fork。
