1. 模块定位

本模块位于 Pregel durable execution（耐久执行）与数据库之间：它接收 Checkpoint、metadata 和 task 级 pending writes，将其编码并持久化，再按 thread_id + checkpoint_ns + checkpoint_id 恢复为 CheckpointTuple。基础接口明确要求 put、put_writes、get_tuple、list、delete_thread；异步执行还要求对应的 async 方法。libs/checkpoint/README.md:52-67

范围负责明确不负责
checkpoint 基础包协议、公共类型、JsonPlus/Encrypted serde、默认兼容行为选择何时 checkpoint、节点重试、业务副作用幂等
SQLite saver单 SQLite 连接上的 sync/async checkpoint 与 writes 落盘、WAL、Delta history多写者横向扩展、远程数据库服务能力
Postgres saver表迁移、历史 checkpoint、blob 复用、pending writes、sync/async/pool/pipeline数据库运维、备份、租户授权和连接 Secret 管理
Conformance按方法覆盖检测并运行公共行为规范替代真实数据库集成测试、性能测试或故障注入

Checkpoint 保存 Channel 值、版本、versions_seen 与 pending writes；它不是 Python 栈帧或事务日志。成功 task 的中间 writes 与超级步 checkpoint 是两个持久化动作，不能把 put_writes 当成 put。数据库 saver 只实现存取契约，何时调用由上游 Runtime 所有。

3. 核心概念

Checkpoint
超级步边界状态快照，包含 channel values、channel versions、versions_seen 等；数据库行还关联 metadata 与父 checkpoint。
Pending write
某 task 已产生但尚未并入下一超级步 checkpoint 的写，主键包含 task 与 idx，支持失败后跳过已成功 task。
Serde
serialization/deserialization（序列化/反序列化）。协议输出 (type, bytes)，type tag 决定恢复分支。libs/checkpoint/langgraph/checkpoint/serde/base.py:14-26
Blob 复用
Postgres 以 (thread, namespace, channel, version) 为 blob 主键；checkpoint JSONB 记录版本，通过版本关联复杂 Channel 值。libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py:47-76
Delta history
为 DeltaChannel 返回最近祖先 seed 与从 seed 到目标父节点之间、按时间正序排列的 writes；目标 checkpoint 自己的 pending writes 不属于历史。libs/checkpoint-conformance/langgraph/checkpoint/conformance/spec/test_delta_channel_history.py:17-75
Shallow saver
每个 thread/namespace 只保留最新 checkpoint 的历史压缩实现；当前已 deprecated，推荐常规 PostgresSaver 配合 durability='exit'。libs/checkpoint-postgres/langgraph/checkpoint/postgres/shallow.py:169-197
Conformance
公共能力规范，不是声明字段；框架通过 async 方法是否覆盖基础实现来检测能力。libs/checkpoint-conformance/langgraph/checkpoint/conformance/capabilities.py:52-96

4. 架构组成

4.1 SQLite：整包 BLOB 与自动 setup

SqliteSaver 保存 checkpoints 与 writes 两张表；checkpoint、pending write 均经 typed serde 成为 type+BLOB，metadata 单独 JSON 编码。首次 cursor 自动调用 setup，执行 PRAGMA journal_mode=WAL 与幂等建表，再由同一实例锁串行 cursor。libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/__init__.py:129-189

同步类面向轻量、同步场景，源码明确说明不扩展到多线程吞吐；check_same_thread=False 只是允许连接跨线程使用，真正互斥仍由实例的 threading.Lock 提供。libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/__init__.py:45-53；libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/__init__.py:85-125

4.2 Async SQLite：同一模型，不同调度约束

AsyncSqliteSaver 通过 aiosqlite 和 asyncio.Lock 实现相同 schema；setup 自动连接、建表并 commit。同步桥只允许从不同线程调用，在创建 saver 的事件循环线程上同步调用会抛 asyncio.InvalidStateError，避免把该 loop 等死。libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/aio.py:115-145；libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/aio.py:161-175；libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/aio.py:305-344

4.3 Postgres：JSONB 元数据、版本化 blob 与 writes

常规 Postgres saver 建立 checkpoint_migrations、checkpoints、checkpoint_blobs、checkpoint_writes。primitive（None/str/int/float/bool）留在 checkpoint JSONB；复杂值按 Channel version 外置到 blob，读时按 channel_versions join 回来，因此相同版本不会重复插入 blob。libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py:43-91；libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:295-345

setup() 不会由普通读写自动触发：它读取最大 migration 版本、按列表顺序执行未应用 SQL，并写入 migration 表。应用首次部署必须显式执行。libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:85-110；libs/checkpoint-postgres/langgraph/checkpoint/postgres/aio.py:90-117

4.4 JsonPlus 与 EncryptedSerializer

JsonPlus 对 null、bytes、bytearray 使用专用 tag，其余优先 msgpack；编码失败只有在显式 pickle_fallback=True 时才退到 pickle，否则抛原编码错误。未知 type tag 直接 NotImplementedError。libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py:258-290

EncryptedSerializer 先由内层 serde 编码，再用 CipherProtocol 加密，并把 tag 写成 原类型+密码名；读取无 “+” 的旧数据会回退到未加密内层 serde，从而支持渐进迁移。AES helper 默认 EAX，要求显式 key 或 LANGGRAPH_AES_KEY，长度必须为 16/24/32 bytes。libs/checkpoint/langgraph/checkpoint/serde/encrypted.py:8-36；libs/checkpoint/langgraph/checkpoint/serde/encrypted.py:38-80

5. 完整运行流程

5.1 正常成功：Postgres 写入后恢复

  1. 输入：Runtime 传入含 thread/ns/父 checkpoint id 的 config、checkpoint、metadata 与 new_versions。
  2. 规范化：saver 复制 checkpoint；primitive 留在 JSONB，复杂值从 channel_values 移出，按新版本生成 typed blob。libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:295-323
  3. 状态写入：先对 blob 执行冲突忽略，再 upsert checkpoint；返回的新 config 把 checkpoint id 指向本次 id。libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py:131-159；libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:321-345
  4. task writes：put_writes 以 task_id+idx 持久化；特殊 Channel 可覆盖，普通 write 冲突时保持首次结果。libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:347-379
  5. 恢复：get_tuple 精确取 id，或按 id 倒序取最新；SQL join blob 并聚合 writes，最后恢复 checkpoint、metadata、parent config 与 pending writes。libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py:93-118；libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:227-261；libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:559-599

5.2 拒绝/提前结束

  1. 把 pipeline 与 ConnectionPool 同时传入 saver 会立即 ValueError；pipeline 只允许单 connection。async 版本执行相同拒绝。libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:45-60；libs/checkpoint-postgres/langgraph/checkpoint/postgres/aio.py:45-61
  2. 在 Async saver 的所属事件循环线程调用同步 get/list/delete 会抛 InvalidStateError，而不是阻塞等待自身 loop。libs/checkpoint-postgres/langgraph/checkpoint/postgres/aio.py:567-617
  3. 严格 msgpack 遇到未登记类型时不 import/构造该类型；扩展 hook 返回原始参数或 dict，并发出 warning/event。方法调用只允许固定安全集合，未允许方法同样被拒绝。libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py:559-631；libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py:633-690
  4. 查询不存在的 checkpoint 返回 None；Delta history 若无目标则为每个请求 Channel 返回空 writes，而不是伪造 seed。libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:237-244；libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:464-474

5.3 恢复/迁移：Delta 祖先链

  1. 从目标 checkpoint 的父节点开始回溯，目标自己的 writes 明确排除。
  2. 每个 Channel 独立寻找最近 seed；找到 _DeltaSnapshot 或 pre-delta 普通值后停止该 Channel 的祖先 walk。
  3. Postgres 第一阶段分页只读取 checkpoint 的版本、blob 存在性与 inline primitive；第二阶段按 Channel 独立 UNION ALL 读取路径 writes 和 seed blob。libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:444-557
  4. SQLite 没有独立 blob 表，第一阶段逐行反序列化祖先 checkpoint，跳过 sibling branch；第二阶段只取相应 Channel/链的 writes。libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/_delta.py:68-124；libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/__init__.py:503-583
  5. 结果以 seed（可缺省）加 oldest→newest writes 表达。seed 祖先自己的 write 必须重放，因为 checkpoint value 是“进入该 checkpoint 的状态”；比 seed 更老的 write 才已被 seed 吸收。libs/checkpoint-conformance/langgraph/checkpoint/conformance/spec/test_delta_channel_history.py:202-267
祖先链断裂、parent id 不存在或排序/id 假设被第三方 saver 破坏时，恢复可能提前到“无 seed，从空状态重放”，甚至漏写。Conformance 能证明规范样例，不能替代对损坏链和并发删除的故障注入。

9. 并发、性能与资源

9.1 SQLite 锁与 WAL

sync saver 用单 threading.Lock 包住 setup、cursor 使用与 commit；async saver用单 asyncio.Lock 包住连接操作。WAL 改善读写重叠，不会消除 SQLite 单文件写竞争，也不会让一个 saver 连接并行执行多条 SQL。libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/__init__.py:181-189；libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/aio.py:360-428

Async SQLite 连接必须关闭；源码警告未关闭的 aiosqlite worker 会让进程看似挂住，优先使用 async with。该实现也明确不推荐用于高写入生产负载。libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/aio.py:53-72

9.2 Postgres connection、pool 与 pipeline

常规 sync/async saver 都先获取实例锁，再从单 connection 或 pool 取得连接；即使 psycopg pipeline 可跨线程/协程共享 connection，同一时刻仍只使用一个 cursor。pipeline 请求在客户端不支持时回退事务 context，而不是失去原子边界。libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:404-442；libs/checkpoint-postgres/langgraph/checkpoint/postgres/aio.py:363-403

9.3 Delta history 读取成本

Postgres ancestor scan 以 1024 行内部页读取，找到所有 Channel seed 或链耗尽即停止；页大小当前不是公共配置。SQLite 流式处理每个祖先 BLOB，目标是只保留一个反序列化 checkpoint 的峰值内存。libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py:21-23；libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:490-528；libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/_delta.py:1-19

不要从源码注释中的局部 benchmark 推导生产 SLA；数据库大小、网络、索引、Channel 数、seed 间距和 serde 类型都会改变成本。

10. 安全与信任边界

10.1 数据库内容必须视为可执行输入面

宽松 JsonPlus 可以依据 checkpoint 内的 module/name import 并构造 Python 类型；源码明确警告：攻击者若能直接写 checkpoint 数据库，反序列化可能触发代码执行。libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py:82-95

  • 生产新应用启用 strict msgpack，并为业务类型使用精确 symbol allowlist；不支持 prefix allowlist。
  • 保持 pickle_fallback=False；pickle 只能用于完全可信、受访问控制的数据。
  • 数据库账号按最小权限配置；saver 本身不提供租户授权，thread_id 也不是访问控制。
  • SQL 中 Channel 名和 filter 值使用参数绑定；动态 Delta SQL只插入受长度约束的数字 alias，而不插入 Channel 文本。libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py:255-263

10.2 加密边界

EncryptedSerializer 只加密 typed bytes：SQLite 的 checkpoint/write BLOB 与 Postgres 的 blob/write BYTEA 会加密；Postgres checkpoint JSONB 中保留的 primitive、metadata、thread/ns/id、版本和表结构仍可见。因此它不是“整个数据库透明加密”。libs/checkpoint/langgraph/checkpoint/serde/encrypted.py:17-36；libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py:309-343

AES EAX 对 ciphertext 做认证，错误 key/tag 会在 decrypt_and_verify 失败并拒绝恢复；没有 key rotation、key id 路由或 Secret 存储实现，这些必须由应用/平台设计。libs/checkpoint/langgraph/checkpoint/serde/encrypted.py:61-80

EncryptedSerializer 的“可读取无加密旧数据”是迁移能力，也是策略边界：它不会强制数据库中所有行都加密。若要求 fail-closed，需在包装层拒绝没有 “+cipher” 的 type tag，并提供迁移审计。

11. 失败、恢复与兼容

15. 设计权衡与已知限制

选择收益成本/失败模式重评条件
SQLite 整包 BLOB + WALschema 小、部署简单、serde 行为统一每个 checkpoint 重写整包；单文件写锁、缺少 JSONB 查询多进程写竞争、历史/文件持续增长或需要服务级 HA。
Postgres JSONB + 版本 blobprimitive 可查询；复杂大值按 Channel version 复用schema/migration/join 更复杂；元数据与 primitive 不被 EncryptedSerializer 覆盖敏感 primitive 需全字段加密，或 blob join 成为瓶颈。
显式 Postgres setup迁移时机和 DDL 权限可控遗漏会在运行时失败；并发部署需要编排平台拥有独立 migration job，可进一步禁止应用账号 DDL。
Shallow 只保留最新历史空间最小、读模型简单丢失时间旅行/旧恢复点，且当前已 deprecated新项目不应采用；现有项目迁移常规 saver + exit durability。
JsonPlus 当前默认宽松旧 checkpoint 与任意业务类型兼容数据库被篡改时 import/构造攻击面更大新部署应立即显式 strict；全局默认改变前验证历史类型矩阵。
EncryptedSerializer 可读明文支持无停机渐进迁移不提供全密文保证，缺少 key id/rotation合规要求 fail-closed 时增加策略 wrapper 与离线重写。
Delta 祖先回放减少每步完整 Channel snapshot 写放大读成本依赖 seed 距离；prune/断链/迁移更复杂长链读延迟或恢复风险超过写入收益时增加 snapshot。

17. 术语表

WAL
Write-Ahead Logging，预写日志。SQLite journal 模式，可改善读写并发，但不消除单文件写者约束。
Serde
Serializer/Deserializer，序列化与反序列化。本模块以 (type, bytes) 为持久化边界。
Checkpoint
超级步边界的 Channel 状态、版本和消费进度快照，不包含 Python 调用栈。
Pending write
task 级中间写；用于部分成功后的恢复，与超级步 checkpoint 分开持久化。
Namespace
checkpoint_ns，同一 thread 下隔离子图或持久化空间的键。
Blob
Binary Large Object。Postgres saver 中按 Channel/version 外置的 typed bytes。
JSONB
Postgres 二进制 JSON 类型；保存 checkpoint 结构、primitive Channel 值与 metadata。
Pipeline
Psycopg 将多条命令减少往返的模式；不等于同一 cursor 并发执行，也不与 connection pool 同时作为 saver 参数使用。
Shallow saver
只保留 thread/namespace 最新 checkpoint 的已弃用 Postgres 实现，不支持完整时间旅行。
Strict msgpack
仅允许内建安全类型和显式 allowlist 类型被构造的反序列化模式。
Allowlist
允许清单；这里使用精确 module/name 或 type，不接受模糊 prefix。
CipherProtocol
加密/解密协议，返回 cipher name 与 ciphertext；由 EncryptedSerializer 包装 typed serde。
AES-EAX
带认证的 AES 模式；本仓库 pycryptodome helper 的默认模式。
Delta history
某 Delta Channel 最近祖先 seed 与后续 writes 的恢复材料。
Seed
祖先链上最近的完整 Channel 值，可能是 _DeltaSnapshot 或迁移前 plain value。
Ancestor chain
由 parent_checkpoint_id 连接的 checkpoint 祖先链；Delta 恢复依赖其完整性。
Conformance
一致性规范套件，用相同测试验证不同 saver 的公共与扩展能力。
Time-travel
选择旧 checkpoint 查看或从历史点分叉执行；Shallow saver 因覆盖历史而不支持完整能力。
