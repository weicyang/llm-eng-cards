1. 模块定位

langgraph-prebuilt 是高层构图和工具执行库，不是新的调度内核。create_react_agent 把 model、tools、hook 和路由装配进 StateGraph，最后调用 compile() 返回 CompiledStateGraph；执行、checkpoint、interrupt 和 stream 仍由普通 LangGraph Runtime 提供。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:787-828、libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:861-1002

职责本模块负责委托/明确不负责
ReAct 构图model/tool 节点、条件边、hook、structured response、return_direct超级步调度、Channel 合并、checkpoint 由 core LangGraph 负责
工具执行输入解析、并行调用、注入、结果规范化、工具错误消息外部 API 权限、事务、幂等和速率限制由工具或 wrapper 负责
兼容入口保留 create_react_agent 与旧别名新 Agent middleware 设计位于 langchain.agents.create_agent
持久化把 checkpointer/store 传给编译器不自行实现 saver、Store 或远程服务队列

包声明依赖 langgraph-checkpoint >=2.1.0,<5.0.0 与 langchain-core >=1.3.1，测试才额外依赖 core langgraph 和具体 saver。libs/prebuilt/pyproject.toml:5-29、libs/prebuilt/pyproject.toml:37-50

2. 系统位置与依赖

调用方 invoke / stream / ainvoke / astream │ ▼ CompiledStateGraph（普通 Pregel 可执行图） agent ──tool_calls──► tools: ToolNode ──ToolMessage/Command──┐ ▲ │ │ │ └─无调用─► post hook / structured response / END│ └──────────────── pre_model_hook（可选）◄──────────────────┘ │ ┌───────────────────┼────────────────────┐ ▼ ▼ ▼ ChatModel provider 外部工具副作用 Checkpointer / Store

公共入口由 langgraph.prebuilt.__init__ 导出；真正 Owner 分别是 chat_agent_executor.py 与 tool_node.py。libs/prebuilt/langgraph/prebuilt/__init__.py:1-23

进程边界必须分清：ToolNode 本身在 Python 运行时中调用 BaseTool.invoke/ainvoke。某个工具可以访问网络或数据库，但那是工具的副作用边界；Auth、队列、远程 checkpoint 与部署能力不能反推为 prebuilt 默认能力。

3. 核心概念

ReAct loop

模型产出 tool calls，工具结果以消息回灌模型，直到模型不再请求工具。

Message reducer

add_messages 按消息 ID 追加、替换或删除，不是简单 list 拼接。

ToolRuntime

每个 tool call 独立构造的受信运行上下文，包含 state、context、config、store、writer、call id 等。

Control-flow value

Command 改变 State 或路由；GraphBubbleUp 是异常型控制流，不等同普通工具失败。

AgentState.messages 标注为 Annotated[Sequence[BaseMessage], add_messages]，remaining_steps 是 ManagedValue。旧 State 类型本身也已标记迁往 LangChain agents。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:53-74

Runtime 面向图节点；ToolRuntime 面向单个工具调用，额外携带 state、config 与 tool_call_id。两者不可互换。libs/prebuilt/langgraph/prebuilt/tool_node.py:1662-1730

4. 架构组成

4.1 Agent model 节点与路由

model 节点先取得 messages（有 pre-hook 时可取 llm_input_messages），校验历史，再同步或异步调用静态/动态模型并返回 {"messages":[response]} partial update。步数不足时，它用相同 message ID 返回解释性 AIMessage，从而由 reducer 替换原响应。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:620-721

4.2 ToolNode

构造阶段把 callable 转为 BaseTool，按名称建索引，并一次扫描 schema 与函数签名缓存注入信息；执行阶段才解析 tool calls、构造逐调用 runtime、注入受信参数、调用工具并组合输出。libs/prebuilt/langgraph/prebuilt/tool_node.py:743-786、libs/prebuilt/langgraph/prebuilt/tool_node.py:1967-2030

4.3 v1 与 v2 图形差异

兼容参数 version 默认 v2。v1 把某轮全部 tool calls 交给一次 tools 节点运行；v2 为每个 call 产生一个 Send("tools", ToolCallWithContext(...))。二者都仍是 StateGraph/Pregel task，只是 fan-out 和恢复粒度不同。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:305-308、libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:830-859

4.4 hooks 与 structured response

pre_model_hook 每轮位于 model 前；post_model_hook 位于 model 后并重新判断尚未完成的 calls；最终 structured response 由独立节点再次使用 model 的 with_structured_output 生成。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:723-785、libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:874-968

5. 完整运行流程

5.1 成功路径：模型 → 并行工具 → 模型 → END

  1. 调用方提交含 HumanMessage 的 State；add_messages 规范化消息并分配缺失 ID。
  2. agent 校验完整历史，模型返回带多个 tool calls 的 AIMessage。
  3. v1 路由到一个 ToolNode task；v2 为每个 call 建独立 Send task。ToolNode 创建对应 ToolRuntime。
  4. sync 使用 executor，async 使用协程并发；普通返回被 BaseTool 规范成 ToolMessage，Command 经过结构校验。
  5. 消息 reducer 在超级步屏障后合并 writes；非 return_direct 路回 model。模型不再发 tool call 时结束，或进入 structured response 节点。

真实双工具测试得到两条 ToolMessage，随后模型生成最终 AIMessage。libs/prebuilt/tests/test_react_agent.py:1093-1179

5.2 拒绝/提前结束路径

  • 历史中 AI tool call 没有对应 ToolMessage：model 调用前抛 ValueError(INVALID_CHAT_HISTORY)，不向 provider 发送非法历史。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:243-271
  • 未知工具名：不是异常终止，而是返回绑定相同 call id 的 ToolMessage(status="error")，让模型有机会纠正。libs/prebuilt/langgraph/prebuilt/tool_node.py:1268-1279、libs/prebuilt/tests/test_tool_node.py:568-594
  • return_direct=True 的工具完成后路由 END；并行轮中任一 call 属于 return-direct 工具也会提前结束。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:970-990、libs/prebuilt/tests/test_react_agent.py:982-1084
  • 剩余步数不足且模型仍请求工具时，model 返回 “need more steps” AIMessage，不执行该批工具。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:620-634、libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:681-694

5.3 中断与恢复路径

工具内 interrupt() 产生 GraphInterrupt/GraphBubbleUp，直接工具执行路径显式上抛；根图记录 pending interrupt，调用方以同一 thread 配置和 Command(resume=...) 恢复。libs/prebuilt/langgraph/prebuilt/tool_node.py:973-1003、libs/prebuilt/tests/test_react_agent.py:580-595

恢复副作用差异：真实并行中断测试中，v1 恢复后非中断天气工具执行两次；v2 因独立 Send task 只执行一次。动态 interrupt 恢复仍会从中断工具函数开头重跑，所以中断前副作用必须幂等或拆到独立节点。libs/prebuilt/tests/test_react_agent.py:598-676

6. 数据与状态模型

数据所有者/生命周期关键语义
messagesStateGraph Channel；跨超级步按 ID 替换、追加、RemoveMessage 删除；不是线程共享 list
remaining_stepsManagedValue；当前执行保护循环预算，不要求调用者手工维护普通字段
structured_response可选 State key启用 response_format 时 schema 必须声明该 key
ToolRuntime.state单个 tool call 的快照v2 Send 可从携带快照或 Pregel local read 水合
ToolRuntime.store编译图注入的 BaseStore 引用跨 thread 长期数据；不是 checkpoint
pending writes/checkpointcore Runtime/checkpointerprebuilt 只透传配置，不另建持久化格式

add_messages 会把输入转成消息、补 ID；同 ID 的新消息替换旧消息，RemoveMessage 删除已有 ID，删除未知 ID 则报错，REMOVE_ALL_MESSAGES 清空此前历史。libs/langgraph/langgraph/graph/message.py:187-240

v2 的新 Send payload 可以仅含 tool call，再经 Pregel 提供的 CONFIG_KEY_READ 从 channels 做 fresh local read；ManagedValue 仍走自己的 runtime 注入路径。libs/prebuilt/langgraph/prebuilt/tool_node.py:1281-1313

Secret 不应放进模型可见 messages 或普通 tool args。Store 的 namespace、TTL、租户授权和数据清理由应用所有；ToolNode 仅传递 Store 对象。

7. 接口、协议与事件

7.1 公共 API

create_react_agent(...)->CompiledStateGraph 支持 Runnable 的 invoke/stream/async/state API；ToolNode 自身也是 Runnable node，可接收消息 list、含消息字段的 dict/BaseModel、直接 tool-call list，或内部 ToolCallWithContext。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:278-308、libs/prebuilt/langgraph/prebuilt/tool_node.py:1224-1266

7.2 Tool 输出协议

工具的规范结果是 ToolMessage、Command 或由二者组成的 list；普通 BaseTool 返回通常先由 LangChain 转成 ToolMessage。Command 当前图更新必须包含且仅终结一次对应 call id 的 ToolMessage；输入形状与 Command.update 的 dict/list 形状必须一致。libs/prebuilt/langgraph/prebuilt/tool_node.py:1432-1501、libs/prebuilt/langgraph/prebuilt/tool_node.py:1503-1579

多个 Command.PARENT 且 goto 为 Send list 时，ToolNode 合并为一个 parent Command；其他 Command 和消息更新保持独立输出供 LangGraph 处理。libs/prebuilt/langgraph/prebuilt/tool_node.py:862-920、libs/prebuilt/tests/test_tool_node.py:1197-1281

7.3 Wrapper 协议

wrap_tool_call(request, execute) 与异步版本允许修改不可变请求副本、多次调用 execute 做重试、零次调用做缓存/拒绝，或直接返回 ToolMessage/Command。异步未给 awrap_tool_call 时会退回 sync wrapper 和 sync tool 执行。libs/prebuilt/langgraph/prebuilt/tool_node.py:202-283、libs/prebuilt/langgraph/prebuilt/tool_node.py:1161-1222

9. 并发、性能与资源

ToolNode sync 路径使用 get_executor_for_config(config) 和 executor.map；async 路径为每个 call 建 coroutine 并 asyncio.gather。返回列表保持输入顺序，但完成时间和外部副作用顺序不受该列表顺序保证。libs/prebuilt/langgraph/prebuilt/tool_node.py:793-860

v1 的“一个 ToolNode task 内并行”和 v2 的“多个 Send/PUSH task”不能混为一谈。两者的工具都可能并发；v2 额外获得 task 级 pending-write/恢复隔离，真实中断测试证明它能避免已完成兄弟工具重跑。libs/prebuilt/tests/test_react_agent.py:645-676

Channel reducer 只合并图 State writes，不会为两个工具同时修改同一数据库行、文件、支付请求或邮件发送提供锁。使用数据库事务、幂等键、租户级锁，或把有依赖的操作拆成顺序图节点。

源码未为 ToolNode 定义独立队列容量、背压、工具超时或重试预算；这些来自 RunnableConfig/executor、工具客户端、wrapper 或上层 Runtime。不要虚构固定并发数或 SLA。

10. 安全与信任边界

InjectedState、InjectedStore 与 ToolRuntime 属系统注入参数。执行前，ToolNode 会移除模型伪造的所有 injected keys，再写入受信值；缺失必要 state 字段或 Store 时拒绝。libs/prebuilt/langgraph/prebuilt/tool_node.py:1315-1430

完整 schema 与函数签名都用于发现注入参数，schema 注解优先；任何 InjectedToolArg 子类也会被列入剥离集合。libs/prebuilt/langgraph/prebuilt/tool_node.py:1967-2029

风险内建防线应用仍需负责
模型伪造 user/store/runtime隐藏 schema 参数并剥离 caller 值context 和 Store 本身必须由可信入口建立
未知工具error ToolMessage，默认 fail-closed 不执行wrapper 动态注册工具时重新做授权
危险副作用无默认审批在 post-model hook/wrapper 实现 policy、HITL、审计与幂等
错误信息泄露错误模板可配置不要把 Secret、SQL、内部路径回显给模型
多租户 Store只注入 Store 引用namespace 必须绑定可信 tenant/user，工具不能相信模型给出的租户 ID

11.1 GraphBubbleUp 与 wrapper 的准确边界

没有 wrapper 时，sync/async 的直接工具执行都先捕获 GraphBubbleUp 并立即重抛，普通错误处理器即使声明捕获它也不能吞掉；测试覆盖这一点。libs/prebuilt/langgraph/prebuilt/tool_node.py:973-1003、libs/prebuilt/langgraph/prebuilt/tool_node.py:1120-1159、libs/prebuilt/tests/test_tool_node.py:597-626

当前 wrapper 锐边：_run_one/_arun_one 的 wrapper 外层捕获普通 Exception，在 handle_tool_errors 启用时会转为 error ToolMessage；由于 GraphBubbleUp 继承 Exception，一个 passthrough wrapper 经 execute() 收到的控制流异常存在被该外层转换的实现风险。现有测试只覆盖无 wrapper 的传播，未覆盖 wrapper + interrupt。wrapper 应显式 except GraphBubbleUp: raise，且扩展时应补回归测试。libs/langgraph/langgraph/errors.py:50-54、libs/prebuilt/langgraph/prebuilt/tool_node.py:1053-1067、libs/prebuilt/langgraph/prebuilt/tool_node.py:1204-1222

11.2 迁移兼容边界

create_react_agent 已用 LangGraph v1 deprecation 类别标记迁往 langchain.agents.create_agent；旧别名 create_tool_calling_executor 仍直接指向它。它是兼容入口，不应成为新项目唯一架构基线。libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:274-317、libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:1004-1015

迁移不是机械改 import：当前 prebuilt 参数包含 v1/v2、pre/post hook、State schema、structured response 与 ToolNode wrapper；LangChain create_agent 使用 middleware，尤其工具 wrapper 应迁到 AgentMiddleware.wrap_tool_call 并重新证明 interrupt、State 类型、stream 与 checkpoint 兼容。libs/prebuilt/langgraph/prebuilt/tool_node.py:202-222

14.1 推荐的工具治理 wrapper

  1. 从 request.runtime.context 读取可信主体，不从模型 args 读取 tenant/user。
  2. 先做工具名、参数与资源范围授权；拒绝时返回绑定原 call id 的安全 ToolMessage。
  3. 调用 execute(request.override(...))；只对确认可重试的瞬时异常重试。
  4. 把 GraphBubbleUp 单独重抛；不要把 interrupt 变成模型可见普通错误。
  5. 记录 tool name、call id、decision、attempt 和耗时，但清理 Secret。

禁止直接修改 ToolCallRequest 属性；该方式已发 deprecation warning，应使用返回新实例的 override()。libs/prebuilt/langgraph/prebuilt/tool_node.py:151-199

15. 设计权衡与已知限制

选择收益成本/失败模式重评条件
ReAct 编译为普通 StateGraph复用 checkpoint、stream、interrupt、可视化需要理解 Pregel 超级步而非 while-loop 直觉若新 middleware API 已覆盖全部契约
v2 每 call 一个 Send更细恢复与 HITL 隔离更多 task/路由开销；仍需 reducer 合并大量微工具调用或状态体积压测
错误转 ToolMessage模型可自修复，历史保持完整可能泄露内部错误或造成无界重试安全敏感/不可重试副作用应 fail-closed
强制 Command 终结消息避免 provider 非法历史复杂 handoff 需显式构造 ToolMessage消息协议改变时
兼容入口继续保留降低现有应用升级成本两套 Agent API 长期漂移迁移验证完成并进入移除窗口

已知限制包括：无 ToolNode 内建事务/锁/速率限制；无固定并发或背压保证；工具外部副作用不能由 Channel reducer 回滚；wrapper 控制流异常传播存在上述缺口；本仓库测试不能证明具体 LLM provider、API Server 或托管平台行为。

17. 术语表

术语本章含义
ReActReason + Act；模型推理后请求工具，再根据工具结果继续的循环模式。
Prebuilt构建于 LangGraph core 之上的高层现成组件，不是独立运行时。
ToolNode解析并执行一批 tool calls、完成注入和输出规范化的 Runnable 图节点。
Tool callAIMessage 中由模型提出的结构化工具请求，至少关联 name、args 与 id。
ToolMessage与 tool call id 配对的工具结果消息；status="error" 表示可回灌模型的失败结果。
Command携带 State update、goto 与 graph 作用域的控制值；不同于抛异常。
GraphBubbleUp向上层图传播 interrupt 等控制流的异常基类；不应按普通工具错误处理。
InjectedState声明工具需要完整图 State 或某字段的隐藏参数注解。
InjectedStore声明工具需要编译图所持 BaseStore 的隐藏参数注解。
ToolRuntime按单个 call 注入的工具运行上下文，包含 State、context、config、Store、writer 和 call id。
Wrapper包围单次工具执行的拦截器，可授权、改写、短路或重试。
Send / PUSH task携带自定义参数动态调度节点的机制；ReAct v2 用它拆分每个 tool call。
ManagedValue由 Runtime 管理、不是普通用户 Channel 字段的运行值；本章典型值为 RemainingSteps。
Checkpointer保存图执行 State、版本与 pending writes 以支持恢复的组件；不同于长期 Store。
return_direct工具属性；该工具完成后兼容 ReAct 图直接结束，不再调用 model。
HITLHuman in the Loop，人类参与审批或补充输入；常通过动态 interrupt 实现。

本页只描述本仓库基线中的本地 Python prebuilt 实现；远程 API Server 与托管平台能力需按各自版本和协议另行验证。
