1. 模块定位

LangGraph 的运行时 State 不是多个节点共同原地修改的 Python dict，而是一张以名称索引的 Channel map。StateGraph 节点返回 partial update；Runtime 把它规范化为 task writes，等本超级步任务结束后，再由 apply_writes 在屏障处合并。Channel 决定值如何读取、多个 update 如何折叠、何时清空、何时可触发订阅者以及如何进入 checkpoint。libs/langgraph/langgraph/channels/base.py:19-99

职责分界：本模块拥有 Channel 值语义和屏障合并；StateGraph schema 到 Channel 的编译属于第 04/05 章，任务并发执行属于第 07/08 章，checkpoint 存储事务与数据库裁剪属于第 09/10 章。
负责委托明确不负责
BaseChannel 生命周期；各 Channel 的 merge/availability；apply_writes 排序、分组、版本推进节点输出规范化给 Graph/Pregel 写入层；版本 ID 生成给 saver；持久化给 checkpointer节点何时并发启动、事务提交、网络鉴权、跨 thread Store、模型或工具副作用
DeltaChannel 内存 reducer、快照表示和 replay祖先 writes 查询给 BaseCheckpointSaver.get_delta_channel_history自动修复被删除或错误裁剪的祖先链；保证任意 reducer 可重放

3. 核心概念

3.1 稳定快照与屏障合并

“稳定快照”是逻辑隔离语义：超级步 n 的所有兄弟任务从进入该步时的 Channel map 读取。某任务先完成并不会让其 writes 对仍在运行的兄弟任务可见。只有整步完成，writes 才在屏障后成为超级步 n+1 可见状态。这里不是数据库 MVCC，也不承诺节点副作用隔离；它只约束 LangGraph State 的可见性。libs/langgraph/langgraph/pregel/_loop.py:611-629 libs/langgraph/langgraph/pregel/_loop.py:683-718

经典 Pregel superstepLangGraph 当前映射不能推出的等价关系
Read：Vertex 在超级步 S 读取自身状态，并接收 S-1 发送给它的消息prepare_next_tasks 从当前 checkpoint、Channel map 和版本前沿准备整步任务；兄弟任务读稳定逻辑快照Channel 不是某个 Vertex 的私有值或消息邮箱；一个节点可订阅多个命名 Channel，Channel 也可被多个节点订阅
Compute：每个活跃 Vertex 执行用户函数、修改本地状态并发送消息活跃 node/task 并发执行，只累计 task-local (channel, value) writes，不直接改共享 ChannelLangGraph node 不是拥有持久私有状态与出边的经典 Vertex；State key、控制边和任务写入共同构成运行时数据流
Barrier：所有 Vertex 完成本步后进入全局同步点after_tick() 等整步 tasks 完成，再把它们交给 apply_writes；后者稳定排序、标记 trigger consumption、分 Channel 聚合 writesNamedBarrierValue 是图内固定 join Channel，不等于 PregelLoop 的全局超级步屏障
Message visibility：S 中发送的消息到 S+1 才可见BaseChannel.update(vals) 在屏障执行；reducer 把本步 updates 合成新 Channel value，变更后推进 channel_versions，下一轮再以其和 versions_seen 的差判断订阅者是否有未消费变化reducer 是 State 合并代数，不等同于 Pregel 可选 message combiner；版本向量记录变化/消费，不是论文消息本身

这个对照只说明 BSP 的阶段与可见性边界：论文以 Vertex-centric message passing 描述大图计算，LangGraph 则以 node/task 对命名 Channel map 的订阅和写入组织有状态 agent。二者不是数据模型或分布式实现的同构。当前合并顺序、Channel 生命周期与版本推进由 apply_writes 明确定义。libs/langgraph/langgraph/pregel/_algo.py:253-342 libs/langgraph/langgraph/channels/base.py:87-120

3.2 update、value 与 checkpoint

ValueType 是读取值类型，UpdateType 是写入单元类型，二者可以不同；例如 Topic 读取 Sequence[T]，但接收 T | list[T]。checkpoint()/from_checkpoint() 是 Channel 自身快照协议，不等于整个 Pregel checkpoint。libs/langgraph/langgraph/channels/topic.py:23-85

3.3 版本向量

channel_versions[channel] 表示该 Channel 的当前单调版本；versions_seen[node][channel] 表示某节点执行时已消费到的触发版本。调度器比较二者，决定订阅节点是否有未消费更新。它们描述“变化与消费”，不保存值本身。libs/checkpoint/langgraph/checkpoint/base/__init__.py:89-123

3.4 稳定排序不是 reducer 无序免责条款

apply_writes 按 task path 前三段的字符串表示稳定排序，再按 Channel 收集 writes。它消除线程完成先后的影响，但 BaseChannel.update 的抽象契约仍声明 update 序列顺序可视为任意；自定义 reducer 应满足结合性，并在业务要求跨拓扑稳定时尽量满足交换性。不要依赖 task ID 或 path 第四段以后的偶然顺序。libs/langgraph/langgraph/pregel/_algo.py:253-309 libs/langgraph/langgraph/channels/base.py:87-99

5. 完整运行流程

5.1 成功路径：兄弟 reducer writes 在屏障合并

  1. 触发与读取：tick() 从当前 channel_versions/versions_seen 选择 PULL 任务；所有任务读取本步进入时的 Channel map。
  2. 执行：兄弟节点可以并发运行，各自只向 task-local writes 容器追加 (channel, value)；完成速度不改变 State 可见性。
  3. 屏障：after_tick() 在所有任务完成后汇总 writes，调用 apply_writes。libs/langgraph/langgraph/pregel/_loop.py:683-698
  4. 规范化与合并：任务按 path 排序；触发版本记入 versions_seen；被读取 Channel 先 consume()；writes 按 Channel 分组后调用一次 update(vals)。libs/langgraph/langgraph/pregel/_algo.py:253-320
  5. 版本与输出：真正改变且可用的 Channel 获得本步统一的 next_version，加入 updated_channels，供 values stream、checkpoint 与下一步快速调度使用。
  6. 最终状态：下一超级步才看到合并结果；若没有可触发节点，finish() 可让 AfterFinish Channel 完成最后一次状态转换。libs/langgraph/langgraph/pregel/_algo.py:325-345

5.2 拒绝路径：LastValue 并发写冲突

  1. 两个兄弟任务在同一步写同一个普通 State key，写入被稳定收集为两个 values。
  2. LastValue.update([v1, v2]) 检测长度不为 1，抛出错误码为 INVALID_CONCURRENT_GRAPH_UPDATE 的 InvalidUpdateError。libs/langgraph/langgraph/channels/last_value.py:56-64
  3. 该步不应被描述为部分成功状态；开发者必须重构为唯一写者、拆开超级步，或为字段声明明确 reducer。测试直接验证多值拒绝。libs/langgraph/tests/test_channels.py:33-49

5.3 恢复路径：DeltaChannel 冷读重建

  1. 加载 checkpoint 时，如果 DeltaChannel 在目标 channel_values 中缺失，hydration 将其加入一次批量 history 查询。libs/langgraph/langgraph/pregel/_checkpoint.py:229-263
  2. saver 从目标的父 checkpoint 开始沿 parent chain 向祖先遍历，收集目标 Channel 的 pending writes，直到遇到最近的 _DeltaSnapshot 或迁移前普通值 seed；目标 checkpoint 自己的 pending writes 属于下一超级步，不纳入当前值。libs/checkpoint/langgraph/checkpoint/base/__init__.py:149-170 libs/checkpoint/langgraph/checkpoint/base/__init__.py:620-649
  3. from_checkpoint(seed) 建立 base，replay_writes 按 oldest-to-newest 重放；若遇到 Overwrite，以最后一个 Overwrite 作为 reset point。libs/langgraph/langgraph/channels/delta.py:118-157
  4. 恢复后得到普通内存 Channel；后续节点读取与普通 reducer 无异。迁移测试证明 BinaryOperatorAggregate 的旧 plain-value blob 可作为 seed，冷读后继续折叠新 deltas。libs/langgraph/tests/test_delta_channel_migration.py:137-167 libs/langgraph/tests/test_delta_channel_migration.py:638-660

DeltaChannel 的 history 是状态的一部分，而不是可随意丢弃的审计日志。删除 ancestor、只复制 tip checkpoint、重排 pending writes 或让 shallow/prune 实现忽略 delta 能力，都会破坏重建。任何 saver 的 copy/prune/delete 必须以 DELTA_HISTORY conformance 为准，不能仅验证普通 get/put。

本模块不保存 Secret，也不建立 namespace 授权；这些由上层 config、checkpointer 存储和服务端边界负责。Channel 值一旦进入 checkpoint writes 或 snapshot，就受 saver serde 与存储保留策略约束。

9. 并发、性能与资源

9.1 BSP 隔离的实际保证

Runner 可以使用线程或协程并发执行节点，但 State 合并是单个屏障阶段。这样避免共享 dict 的写竞态，同时把冲突显式收敛到 Channel 契约。该保证不覆盖节点访问的数据库、文件、网络和进程全局对象；这些副作用仍需要业务锁、事务或幂等键。

9.2 排序与确定性

任务按 task_path_str(path[:3]) 排序；PULL 节点候选集合也会排序，triggers 元组同样排序，减少 hash/set 枚举差异。稳定排序保证同一拓扑和输入下不受完成时序影响，但若 reducer 非结合或非交换，改变图 path、fan-out 索引或批次边界仍可能改变结果。libs/langgraph/langgraph/pregel/_algo.py:468-495 libs/langgraph/langgraph/pregel/_algo.py:601-623

9.3 版本推进

每次 apply_writes 先从所有 Channel 的最高现有版本生成一个 next_version；本步所有真正改变的 Channel 使用这个版本。这形成超级步级可比较前沿，而不是每个 update 各发一个版本。consume、空更新导致的生命周期变化和 finish 也会推进版本。libs/langgraph/langgraph/pregel/_algo.py:271-292 libs/langgraph/langgraph/pregel/_algo.py:315-342

9.4 DeltaChannel 的成本模型

普通 reducer 以完整值换取常数级 checkpoint hydration；DeltaChannel 以较少完整快照换取祖先查询、pending writes 读取和 reducer 重放。系统通过“update 次数或超级步跨度任一达到阈值”触发快照。libs/langgraph/langgraph/pregel/_checkpoint.py:50-71 该上界限制的是逻辑祖先步跨度，不是固定数据库查询次数或字节数；实际 I/O 仍取决于 saver 实现、每步 writes 数和索引。

Delta hydration 将所有待重放 Channel 合并为一次 saver 调用，避免逐 Channel 独立走祖先链；sync 与 async 都保持该批量形状。libs/langgraph/langgraph/pregel/_checkpoint.py:254-277 libs/langgraph/langgraph/pregel/_checkpoint.py:296-319

10. 安全与信任边界

  • Schema 不是授权：Channel 约束可写 key 与合并形状，但不验证调用者是否有权更改业务字段。
  • Reducer 是受信代码：它处理节点或恢复历史中的数据，可能分配大量内存、抛异常或产生不确定结果。不要对不可信输入执行任意动态导入或代码求值。
  • 历史值是持久化输入：Delta replay 会再次把旧 writes 送入 reducer。反序列化 allowlist、加密和租户隔离属于 serde/saver/服务端，Channel 本身不提供。
  • 未知 Channel fail-soft：apply_writes 对未知 key 记录 warning 并忽略；如果业务要求非法字段必须拒绝，应在 State 输出规范化或节点边界校验，而不能只依赖该 warning。
  • 资源攻击面：不受限的 Topic accumulation、列表 reducer 或过大的 delta history 可放大内存和 I/O；本模块没有内建配额、背压或租户级容量限制。

17. 术语表

Channel map运行时以名称到 BaseChannel 实例的映射表达 State；不是共享 dict 的即时并发修改。
BSPBulk Synchronous Parallel，批量同步并行：稳定读取、并行计算、屏障合并三个阶段。
Stable snapshot稳定快照；同一超级步所有兄弟任务读取同一个逻辑 State 边界。
Barrier屏障；等待整步任务完成后统一应用 writes。NamedBarrierValue 则是图中固定多前驱 join 的 Channel。
Partial update节点只返回需要改变的 State 字段；Runtime 将其变成 Channel writes。
Reducer归约函数；把当前值与一个或多个 updates 合成为新值，必须明确代数性质。
Associative / batching-invariant结合性 / 批次不变性；分批 fold 与合批 fold 得到相同结果，是 Delta replay 的硬要求。
Commutative交换性；交换 writes 顺序仍得到相同结果。不是所有 reducer 的强制接口要求，但可降低拓扑排序耦合。
LastValue每超级步最多接受一个 update 的 Channel；“last”不表示并发时任选最后完成者。
Overwrite显式重置聚合值的更新形式；同一步多个 Overwrite 会被拒绝。
channel_versions每个 Channel 的单调变化版本，用于调度与 checkpoint blob 身份。
versions_seen每个节点已经消费到的触发 Channel 版本，用于判断是否应再次执行。
DeltaChannel通过周期完整快照与祖先 writes 重放恢复聚合值的 beta Channel。
SeedDelta history 向祖先回溯遇到的最近完整基础值，可为 _DeltaSnapshot 或迁移前普通值。
Pending write附着于 task/checkpoint 的中间写；Delta history 选择其中属于目标 Channel 且位于目标路径上的 writes。
Cold read丢弃当前内存 Channel 后，从 saver checkpoint 与历史重新 hydration；是验证 Delta 持久正确性的必要测试。
MISSING内部“值缺席”哨兵，不等于业务值 None；对 DeltaChannel 可表示需要历史重放。
Hydration从 checkpoint snapshot 或 seed + writes 重建内存 Channel map 的过程。
