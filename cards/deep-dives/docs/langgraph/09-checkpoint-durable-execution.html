1. 模块定位

Checkpoint 子系统是本地 Pregel Runtime 的执行恢复协议。当前 Checkpoint 本体保存 channel_values、channel_versions、versions_seen 等超级步快照字段；读取时由 CheckpointTuple 把该快照与 config、metadata、parent config 以及可空的 pending_writes 关联起来。它恢复的是“下一步应调度什么、哪些 task 结果已经完成”，不是保存 Python 栈帧、continuation（续延）、线程、协程或打开的网络连接。两种类型的字段边界见 libs/checkpoint/langgraph/checkpoint/base/__init__.py:89-146；运行时装载 tuple 见 libs/langgraph/langgraph/pregel/_loop.py:1629-1708。

职责本模块负责委托/明确不负责
执行状态超级步边界快照、task writes、父 checkpoint 链State schema/reducer 由 Graph/Channel；不保存 Python 栈帧
恢复调度用 versions_seen 与 pending writes 恢复任务节点业务副作用的幂等与补偿由应用负责
存储协议BaseCheckpointSaver sync/async 接口SQLite/Postgres 表结构、事务和迁移由第 10 章的实现负责
记忆/缓存同一执行 thread 的可恢复历史跨 thread 语义记忆属于 Store；结果缓存属于 Cache
服务能力本地 Runtime 调用 saver远程 API Server 的鉴权、多租户、队列、备份与 SLA 不在本仓库本模块内
开发心智模型：put_writes 是“某个 task 已经产生了什么”，put 是“屏障合并后整张图处于什么 checkpoint”。二者时间粒度和恢复用途不同，不能当作两个等价保存入口。libs/checkpoint/langgraph/checkpoint/base/__init__.py:277-318
为什么结构化离散步骤使 checkpoint 可移植：LangChain 官方设计长文指出，单个大 while 循环或可中断生成器依赖仍存活的执行状态，难以保存成可在另一台机器、任意时间后恢复的格式。LangGraph 先把执行拆成 node/superstep，再在屏障处只序列化 Channel 值、版本和每个 node 已见版本；恢复端据此重新规划下一批 task，而不搬运语言运行时的指令指针。这里的“可移植”是checkpoint 数据不依赖原 Python 进程继续存活，不是承诺任意代码版本、序列化类型、外部资源或部署环境都自动兼容。设计依据：LangChain《Building LangGraph》；当前字段契约：libs/checkpoint/langgraph/checkpoint/base/__init__.py:92-123；恢复规划：libs/langgraph/langgraph/pregel/_loop.py:599-681。

3. 核心概念

Checkpoint某一时刻的图状态快照：v、id、ts、channel_values、channel_versions、versions_seen、updated_channels。libs/checkpoint/langgraph/checkpoint/base/__init__.py:92-123
CheckpointMetadata描述快照来源和历史语境；source 可为 input/loop/update/fork，另有 step、parents、run_id 与 Delta 计数。libs/checkpoint/langgraph/checkpoint/base/__init__.py:37-85
CheckpointTuple读取 API 的聚合返回：config + checkpoint + metadata + 可空 parent_config + 可空 pending_writes。pending writes 不属于 Checkpoint TypedDict 本体。libs/checkpoint/langgraph/checkpoint/base/__init__.py:139-146
PendingWrite(task_id, channel, value) 三元组；它把 task 结果、ERROR、INTERRUPT、RESUME 等特殊写挂到产生该 task 的 checkpoint。libs/checkpoint/langgraph/checkpoint/base/__init__.py:22-31,788-795

三维坐标不是一个复合字符串

Checkpoint identity = thread_id × checkpoint_ns × checkpoint_id
  • thread_id：执行线/会话线的身份；复用它会延续该 thread 的状态。
  • checkpoint_ns：同一 thread 内的图/子图命名空间；根图通常是空字符串，子图按嵌套路径隔离。
  • checkpoint_id：命名空间内的具体历史点；省略时 saver 通常取最新点，显式给出时用于精确读取、回放或分叉。

InMemorySaver 的存储形状直接体现这三维坐标：checkpoint 为 thread → namespace → checkpoint id；writes 以三元组为外键。libs/checkpoint/langgraph/checkpoint/memory/__init__.py:68-83

不要误读：thread_id 不是数据库租户授权；checkpoint_ns 不是安全沙箱；checkpoint_id 也不是全局唯一访问令牌。它们是持久化寻址字段，调用方仍需在外层完成身份验证和授权。

数据快照、task 结果与执行栈是三件事

  • Checkpoint：只表达可序列化的图状态和调度版本；其 TypedDict 没有 pending_writes、Python frame 或 continuation 字段。libs/checkpoint/langgraph/checkpoint/base/__init__.py:92-123
  • CheckpointTuple.pending_writes：saver 读取时关联到该 checkpoint 的 task 级结果；Loop 将普通 writes 注回稳定 task id，使已成功 task 可跳过，控制写则不伪装成成功结果。libs/checkpoint/langgraph/checkpoint/base/__init__.py:139-146；libs/langgraph/langgraph/pregel/_loop.py:736-749,1675-1684。
  • 重放：恢复会重新进入节点或 Functional API entrypoint；已完成 task 的结果可复用，但未完成 task 可能重跑。外部 API、文件和数据库副作用不在 checkpoint 的原子边界内，必须以幂等键、查重、outbox/事务或补偿保护。历史设计动机见 LangChain 设计长文；当前跳过规则见 libs/langgraph/langgraph/pregel/_loop.py:661-664,736-749。

5. 完整运行流程

路径 A：正常成功，task writes 进入超级步 checkpoint

  1. 触发/读取：invoke/stream 解析 saver 与默认 durability；Loop 用 config 读取最新或指定的 CheckpointTuple。默认 durability 是 async。libs/langgraph/langgraph/pregel/main.py:2589-2612；libs/langgraph/langgraph/pregel/_loop.py:1629-1654
  2. 执行：同一超级步的 tasks 基于稳定 Channel 快照运行；每个 task 完成后将 (channel,value) 交给 Loop。
  3. task 持久化：非 exit 模式下，Loop 用当前 checkpoint id 调 put_writes；InMemorySaver 以 (thread,ns,checkpoint) + (task,index) 保存。libs/langgraph/langgraph/pregel/_loop.py:415-505；libs/checkpoint/langgraph/checkpoint/memory/__init__.py:467-503
  4. 屏障合并：after_tick 收集 task writes，经 apply_writes 更新 Channel/版本，再清空本步 pending list。libs/langgraph/langgraph/pregel/_loop.py:683-718
  5. 超级步持久化：_put_checkpoint 计算新版本、构造快照并提交 put；提交按前序 future 串行，避免 checkpoint 乱序。libs/langgraph/langgraph/pregel/_loop.py:1132-1219

路径 B：配置拒绝或无效能力

  1. 存在 checkpointer 但 config 没有可配置坐标时，Pregel 默认解析直接抛 ValueError，不会进入节点执行。libs/langgraph/langgraph/pregel/main.py:2589-2593
  2. 调用 Command(resume=...) 却没有 checkpointer 时，Loop 抛 RuntimeError；空 Command 则抛 EmptyInputError。libs/langgraph/langgraph/pregel/_loop.py:902-931
  3. 显式传 durability 但没有 checkpointer 时，仅发出“durability 无效果”的 warning；它不会凭空创建持久化。sync/async 入口行为一致。libs/langgraph/langgraph/pregel/main.py:2798-2805,3229-3232

路径 C：同一步部分失败，恢复跳过成功 task

  1. task one 成功并落下普通 pending write；task two 失败并落下 ERROR。整体超级步没有形成新的已合并 checkpoint。
  2. 下次以同一 thread 恢复时，Loop 从 tuple 装载 pending writes，重新生成相同稳定 task ids。libs/langgraph/langgraph/pregel/_loop.py:1675-1684,611-629
  3. _reapply_writes_to_succeeded_nodes 把普通 writes 注回对应 task；ERROR/INTERRUPT/RESUME 等控制信号被跳过，所以成功 task 因已有 writes 不再执行，失败/中断 task 保持空 writes 并重跑或路由。libs/langgraph/langgraph/pregel/_loop.py:661-664,736-749
  4. sync 与 async 测试都断言成功节点调用次数仍为 1。libs/langgraph/tests/test_pregel.py:891-976；libs/langgraph/tests/test_pregel_async.py:1807-1897
边界：“跳过成功 task”只避免重复执行已由 pending writes 证明完成的 LangGraph task；若失败 task 在抛错前已调用外部 API、写文件或提交数据库，但尚未产生可识别的成功 write，该副作用仍可能在重跑时发生。应用必须使用幂等键、事务/outbox 或补偿。

Durability 的精确定义

sync下一超级步开始前等待 checkpoint future。task writes 也按任务产生，恢复窗口最窄，但存储延迟进入步间关键路径。libs/langgraph/langgraph/pregel/main.py:2983-2988
async（默认）checkpoint 与下一步执行重叠；提交仍按前序 future 排序。进程在后台保存完成前崩溃，最新边界可能尚未持久。libs/langgraph/langgraph/pregel/main.py:2602-2604；libs/langgraph/langgraph/pregel/_loop.py:1199-1209
exit中间 _put_checkpoint 只推进内存状态，不调用 saver；图退出/中断/错误的上下文清理时保存最终 checkpoint 和 pending writes。运行中宕机不具备逐步恢复承诺。libs/langgraph/langgraph/pregel/_loop.py:1132-1147,1317-1335

9. 并发、性能与资源

  • 超级步屏障：task writes 在 task 完成时可先持久化，但 Channel 合并发生在 after_tick；兄弟 task 不会因为 saver 已收到 write 就即时看到它。libs/langgraph/langgraph/pregel/_loop.py:683-718
  • 提交顺序：sync/async 的 checkpoint put 都等待前一个 put；Delta write futures 也在 checkpoint 可见前 drain，避免读到“有 checkpoint、缺 backing writes”的状态。libs/langgraph/langgraph/pregel/_loop.py:1530-1547,1783-1802
  • sync 等待点：仅 sync 在每个 tick 后显式等待 checkpoint future；async 允许重叠，但 executor/上下文退出仍负责收尾。libs/langgraph/langgraph/pregel/main.py:2983-2988,3457-3465
  • 取消：async Loop 在退出时创建并等待 stack exit task；若取消，会把该 task 附到异常参数中供上层等待后再复用数据库连接。libs/langgraph/langgraph/pregel/_loop.py:1972-1988
  • 内存占用：InMemorySaver 的 checkpoints、writes、blobs 都随 thread 历史增长，除非显式 delete/prune 或销毁对象；实现没有容量上限、TTL 或跨进程协调。libs/checkpoint/langgraph/checkpoint/memory/__init__.py:68-99,505-521
源码没有为本模块给出固定吞吐、容量、超时或 SLA。性能取决于 Channel 数据大小、序列化成本、超级步频率、saver I/O 和 durability；不要把 async 写成“绝不阻塞”或把 sync 写成“事务性 exactly-once”。

17. 术语表

Checkpoint
超级步边界上的可序列化图状态快照；不包含 Python 栈帧。
CheckpointMetadata
描述 checkpoint 来源、step、父图坐标、run 等上下文的可扩展元数据。
CheckpointTuple
saver 读取返回的聚合对象，包含 config、checkpoint、metadata、parent_config 和 pending_writes。
PendingWrite
(task_id, channel, value) 中间写；用于保存 task 结果及 ERROR、INTERRUPT、RESUME 等控制状态。
Durable Execution
耐久执行：利用已保存状态和 task 结果，在故障或中断后从可证明的边界继续，而非保证外部副作用 exactly-once。
thread_id
一条持久执行/会话线的标识；是寻址字段，不是租户授权机制。
checkpoint_ns
同一 thread 内区分根图、子图和嵌套执行的命名空间。
checkpoint_id
namespace 内某个具体历史 checkpoint 的标识；显式指定用于精确读取或回放。
put_writes
task 粒度保存中间 writes 的 saver 操作。
put
超级步边界保存整体 checkpoint、metadata 与新 Channel 版本的 saver 操作。
sync durability
下一超级步前等待 checkpoint 持久化完成。
async durability
checkpoint 持久化与下一超级步重叠；当前默认模式。
exit durability
图退出上下文收尾时才持久化本次最终状态；运行中崩溃窗口最大。
Channel
State 的运行时存储单元，定义值、更新合并、版本和 checkpoint 形状。
versions_seen
每个节点已经消费到的 Channel 版本映射，参与下一步调度。
Superstep
超级步：一批任务读取稳定快照并行执行，随后在屏障处合并 writes 的 BSP 阶段。
Replay / Resume
Replay 从指定历史点重放并可形成分支；Resume 从当前 pending interrupt/失败状态继续。两者都不是恢复 Python 指令指针。
InMemorySaver
基于进程内映射的 saver，适合测试与调试，不提供生产数据库的耐久、容量、ACL 与高可用保证。
Store / Cache
Store 保存跨 thread 业务记忆；Cache 复用节点结果。两者都不替代 Checkpointer 的执行恢复职责。
Serde
serializer/deserializer，负责 checkpoint 与 writes 编解码，也是反序列化安全边界。
