1. 模块定位

Streaming 是执行结果的增量投影与交付层，不是独立调度器，也不是把日志开关改成实时输出。Pregel Loop 仍拥有任务、Channel、checkpoint 与超级步；stream 层把 Loop、callback 和节点 writer 产生的事件按 mode、namespace 和版本整形后交给本地迭代器或远程 transport。七个稳定 mode 的公共枚举是 values、updates、messages、custom、checkpoints、tasks、debug。libs/langgraph/langgraph/types.py:122-141

职责本模块负责委托/明确不负责
事件生产mode 选择、消息 callback、custom writer、输出形状节点执行、BSP 屏障与 writes 合并由 Pregel Runtime 负责
本地交付v1/v2 queue drain；v3 caller-driven pump、projection、transformer不提供跨进程 durability 或消息代理
嵌套来源用 checkpoint namespace 标识子图来源namespace 的生成与 checkpoint 身份属于调度/持久化模块
远程交付SDK 解码、订阅、游标、重连和客户端队列API Server 的执行、鉴权、保留窗口与取消语义不在本地 Pregel 内
关键不变量：stream 观察到的是事件或屏障后的可见状态；它不能让同一超级步中的兄弟任务提前看到彼此 writes。libs/langgraph/langgraph/pregel/main.py:2959-2963

3. 核心概念

概念准确语义常见误解
values每个相关步骤后完整可见 state；Functional API 通常只在结束时发一次不是每个 task 的即时共享 dict
updates节点/任务名到局部输出；同一步多个更新可分开发出不是已经 reducer 合并后的完整 state
messagesv1/v2 为 message/token 与 metadata；v3 投影为每次模型调用的 ChatModelStream不等同普通日志文本
custom节点或 task 通过 StreamWriter 主动发出的任意数据未选该 mode 时 writer 是 no-op
checkpoints创建 checkpoint 时的 StateSnapshot 类视图；无 checkpointer 时不产生不是持久化成功 SLA，也不保存 Python 栈帧
taskstask start/result，含 id、input、triggers、result/error/interrupts不是节点日志；可暴露输入与错误
debugcheckpoint、task、task_result 的带 step/timestamp 包装不是生产环境免费全量追踪

v2 的 StreamPart 是以 type 为判别字段的 TypedDict union，每个 part 都有 ns 与 data；values 额外承载 typed interrupts。libs/langgraph/langgraph/types.py:264-354

namespace（命名空间）是子图调用路径，元素通常形如 node_name:task_id；根为 ()。它表达来源，不是租户授权边界。v1 在 subgraphs=True 时把 namespace 放进 tuple；v2 始终放进 part["ns"]。libs/langgraph/langgraph/pregel/main.py:2713-2718

4. 架构组成

4.1 Pregel 生产与队列

stream() 规范化 mode 后建立无界 SyncQueue；消息 callback 和 custom writer 都向它写入三元组 (namespace, mode, payload)，Loop 则通过 StreamProtocol 写入。libs/langgraph/langgraph/pregel/main.py:2737-2749 libs/langgraph/langgraph/pregel/main.py:2811-2854 同步实现用 semaphore 唤醒 eager 消费，但 queue 的 put 从不阻塞。libs/langgraph/langgraph/_internal/_queue.py:70-122

Loop 在 task 准备/完成处产生 tasks，checkpoint 处产生 checkpoints，屏障合并后产生 values。这解释了 mode 的事件时机，而不是保证不同 callback/transport 的全局事务顺序。libs/langgraph/langgraph/pregel/_loop.py:631-674 libs/langgraph/langgraph/pregel/_loop.py:683-724

4.2 Message handler

StreamMessagesHandler 以内联 callback 避免额外线程顺序问题，按 run id 保存 metadata，捕获 chat model token 与节点最终 message，并按 message id 去重。它用 checkpoint namespace 过滤子图，TAG_NOSTREAM 与 hidden tag 可阻止相应事件。libs/langgraph/langgraph/pregel/_messages.py:49-104 libs/langgraph/langgraph/pregel/_messages.py:130-179 libs/langgraph/langgraph/pregel/_messages.py:191-256

4.3 StreamMux、StreamChannel 与 transformers

StreamMux 按注册顺序运行 transformer，合并 projection，拒绝 key 冲突，把命名 StreamChannel 自动转发为 protocol event，并在根 mux 分配单调 seq。任何 transformer 返回 False 都可从主事件日志抑制事件，但此前 transformer 的副作用保留。libs/langgraph/langgraph/stream/_mux.py:227-296

StreamChannel 是 drain-on-consume、单订阅者、本地内存队列；未订阅时本地 projection 不积累，命名 channel 的 wire forwarding 仍执行。tee/atee 才是显式 fan-out。构造参数 maxlen 当前只校验、不实施容量限制。libs/langgraph/langgraph/stream/stream_channel.py:14-68 libs/langgraph/langgraph/stream/stream_channel.py:120-180 libs/langgraph/langgraph/stream/stream_channel.py:245-341

4.4 GraphRunStream

GraphRunStream/AsyncGraphRunStream 不开后台 pump；调用方迭代 projection、raw events 或读取 output 才推动底层图。sync 每次拉一个 part；async 用 condition 保证只有一个并发 __anext__。libs/langgraph/langgraph/stream/run_stream.py:36-55 libs/langgraph/langgraph/stream/run_stream.py:417-482

5. 完整运行流程

5.1 正常成功路径：本地 v2 多 mode

  1. 调用方传入 input、config、mode 列表与 version="v2"；默认 mode 来自 graph 的 self.stream_mode，通常是 values。
  2. _defaults 把 mode 转为 set，合并 print_mode，解析 output keys、checkpointer 与 durability。libs/langgraph/langgraph/pregel/main.py:2543-2613
  3. runtime 安装 message callback、custom writer 与 StreamProtocol；Loop/Runner 执行 task，事件写入 queue。
  4. _output drain queue。v2 统一输出 {"type", "ns", "data"}，对 values 抽出 interrupts，并用 state/output mapper 恢复声明的 Pydantic/dataclass 类型。libs/langgraph/langgraph/pregel/main.py:2884-2902 libs/langgraph/langgraph/pregel/main.py:4184-4230
  5. 超级步完成后 values 反映合并后的 Channel map；迭代器耗尽，run manager 得到正常终态。

5.2 拒绝/提前结束路径：v3 契约保护

  1. 调用方选择 stream_events(version="v3")，同时错误地传入 stream_mode 或 subgraphs。
  2. dispatcher 在运行图之前 fail-closed 抛出 TypeError，因为 v3 必须从 transformer 需求计算 mode，并强制所有子图 namespace 流入 mux。libs/langgraph/langgraph/pregel/main.py:379-414
  3. 同样，传预构造 transformer instance、非 callable、projection key 冲突或在 sync lane 注册 async-only transformer，都会在 pump 前拒绝。libs/langgraph/langgraph/pregel/main.py:428-440 libs/langgraph/langgraph/stream/_mux.py:227-267
  4. 无节点错误、无 checkpoint 写、无流事件；调用方修正配置后重新创建 run。

5.3 中断、恢复与取消路径

  1. 节点触发 interrupt 时，values v2 part 把 interrupts 放在独立字段；v3 run 只统计自身 scope 的 values 事件并设置 interrupted/interrupts。libs/langgraph/langgraph/stream/run_stream.py:110-121
  2. 本地恢复由调用方用同一 thread/checkpoint config 再次调用 graph 并传 Command(resume=...)；stream 只是展示新执行，不保存恢复位置。动态 interrupt 恢复会从节点开头重跑，因此先前外部副作用仍需幂等。
  3. v3 sync 提前退出应使用 context manager 或 abort()；它关闭 generator，使 GeneratorExit 传播。async abort 会取消正在等待的 __anext__，再 aclose generator 与 mux。libs/langgraph/langgraph/stream/run_stream.py:148-182 libs/langgraph/langgraph/stream/run_stream.py:484-535
  4. 远程 SDK 的 interrupt 由独立 lifecycle/input SSE 更新；run.respond 校验 outstanding interrupt，拒绝无 interrupt、歧义或错误 id，再向 Server 发送 input.respond。libs/sdk-py/langgraph_sdk/_async/stream.py:211-266

6. 数据与状态模型

数据Owner/生命周期持久化清理与隐私
Channel values/writesPregel Loop；跨超级步由 checkpointer 决定stream 只读投影，不改变 retention
SyncQueue/AsyncQueue一次 v1/v2 调用否迭代 drain；无界，慢消费可增长
StreamPartv2 单事件否携带 state、message、input/error 时应按敏感数据处理
ProtocolEventv3 mux/远程 wire本地否；Server buffer 策略不在仓内证明seq 排序，wall-clock timestamp 不保证单调
StreamChannel buffer一个 projection 订阅否消费即删除；未订阅不积累；close/fail 终结
SDK subscription queue一个 thread stream session否context close 后取消任务、关闭 transport、使 active handles 失败

ProtocolEvent.params 包含 namespace、毫秒 wall-clock timestamp、data 与可选 interrupts；跨根事件的总序应使用 mux 分配的 seq，不能使用可能因 NTP 回拨的 timestamp。libs/langgraph/langgraph/stream/_types.py:14-41

checkpoints mode 只有配置 checkpointer 才产生数据；它的 payload 包含 config、metadata、values、next、parent_config 与 tasks，但这只是 checkpoint 视图，不意味着客户端收到事件后持久化才完成。libs/langgraph/langgraph/types.py:182-220 libs/langgraph/langgraph/stream/transformers.py:927-963

Namespace 不是访问控制。远程事件中的 state、task input、metadata、error 与 custom payload 都可能含 Secret/PII；授权、脱敏与租户隔离必须在 Server/应用边界完成。

9. 并发、性能与资源

9.1 v1/v2：无界 queue，不承诺消费者背压

SyncQueue.put 永不阻塞，AsyncQueue 继承默认无界 asyncio.Queue；因此 v1/v2 中生产者快于消费者时，queue 可增长。eager 模式的 waiter 只用于尽快把已产生事件交给 generator，不是容量控制。libs/langgraph/langgraph/_internal/_queue.py:12-41 libs/langgraph/langgraph/pregel/main.py:2932-2957

9.2 v3 本地：拉模型形成自然节拍

v3 每次 projection cursor 缺数据才请求 pump；未订阅 projection 不缓存，单消费者通常把缓冲限制在调用方驱动的事件节奏内。async 多 projection 并发共享一个 condition/single-flight pull，避免并发推进同一 async generator。libs/langgraph/langgraph/stream/run_stream.py:319-345 libs/langgraph/langgraph/stream/stream_channel.py:38-46

但 tee/atee 为每个分支复制 buffer；落后的分支可以积压。StreamChannel(maxlen=...) 当前不实施截断或阻塞，因此不能据此声称有硬背压。libs/langgraph/langgraph/stream/stream_channel.py:245-341

9.3 transformer 调度

async aprocess 在 transformer 链中串行 await，适合必须在后续 observer 前完成的脱敏；独立异步工作可 schedule()。mux 正常关闭会 await scheduled tasks，失败则 cancel 并 await，再运行失败清理。libs/langgraph/langgraph/stream/_types.py:166-184 libs/langgraph/langgraph/stream/_mux.py:380-449

9.4 远程背压边界

SDK async fanout 从共享 SSE 读取后对每个 subscription 执行 put_nowait；队列容量是客户端保护阈值，不是传播到 Server/Pregel 的端到端流量控制。慢消费者可能触发客户端 QueueFull/断流，而 Server 是否暂停生产、保留多久、是否可重放属于仓库外 API Server 契约。libs/sdk-py/langgraph_sdk/_async/stream.py:1605-1665

10. 安全与信任边界

  • 输入与输出：tasks 可包含节点 input、result、error；values/checkpoints/debug 可包含完整业务 state；custom 完全由应用定义。选择 mode 即选择数据暴露面。
  • 消息过滤：TAG_NOSTREAM 可排除模型流，hidden tag 可排除节点链事件，但这属于事件选择，不是授权机制。libs/langgraph/langgraph/pregel/_messages.py:130-149 libs/langgraph/langgraph/pregel/_messages.py:191-212
  • transformer 信任：transformer 可观察、修改或抑制事件；before_builtins 可在内建 messages 投影前做 PII redaction，但修改 tasks 的 namespace/id/result 会破坏 lifecycle 与 subgraph bookkeeping。libs/langgraph/langgraph/stream/_types.py:94-109
  • 远程 Auth：SDK 只是客户端，Server URL、headers、token 与服务端授权必须由部署层配置；本地 Pregel 没有隐式多租户 ACL。SDK 会把 headers 转发到 command 与 stream 请求，但不能证明 Server 的策略。
  • fail-closed：若必须在输出前脱敏，应使用 awaited、before-builtins transformer，并让失败传播；默认 schedule(on_error="log") 会记录并吞掉异步任务错误，不适合强制安全门。libs/langgraph/langgraph/stream/_types.py:233-292

14.1 最小 transformer 规则

  1. 传 class 或 factory(scope)，不要传 instance；每个 scope 必须得到独立状态。
  2. init() 返回 projection dict；命名 StreamChannel 会进入 wire，未命名 channel 仅本地。
  3. 声明精确 required_stream_modes，否则底层不会为 projection 生产数据。
  4. 同步工作实现 process；必须有序的 async 工作实现 aprocess；解耦工作用 schedule 并明确 on_error。
  5. 让 mux 管理 channel close/fail；在测试中覆盖正常、异常、abort、未订阅、子图 scope 与 async task 清理。
禁止捷径：不要从 node name 重建 namespace，不要把 timestamp 当全序，不要用 maxlen 声称本地 v3 有硬容量，不要把 SDK 重连说成 exactly-once，也不要把 Server 的取消/Auth 写成本地 Pregel 默认能力。

17. 术语表

BSP（Bulk Synchronous Parallel）
批同步并行；同一超级步读取稳定快照，writes 在屏障后合并。
Stream mode
选择流中承载哪类数据的枚举；当前稳定集合为 values、updates、messages、custom、checkpoints、tasks、debug。
StreamPart
Pregel stream(version="v2") 的判别联合，统一含 type、ns、data。
StreamEvent
LangChain Runnable callback 事件；不要与 StreamPart 混淆。
ProtocolEvent
v3 内部与远程协议使用的 event envelope，含 method、params、可选 event_id/seq。
Namespace / ns
标识子图嵌套调用来源的路径；根为空 tuple/list，不是授权域。
SyncQueue / AsyncQueue
v1/v2 Pregel 把 producer 与 iterator 解耦的本地无界 FIFO。
StreamMux
v3 中按顺序分发 ProtocolEvent、运行 transformers、管理 projections 与生命周期的中央多路器。
StreamTransformer
把原始事件转换、过滤或投影为 typed channel/handle 的扩展点。
StreamChannel
v3 本地单消费者、消费即删除、可按需驱动 pump 的 projection 队列。
GraphRunStream
实验 v3 的同步 run handle；projection 迭代或 output 读取驱动图运行。
Caller-driven pump
没有后台生产线程，由调用方每次请求下一项推动底层 graph iterator。
Backpressure（背压）
下游变慢时限制上游生产的机制；本地 v3 的拉模型有自然节拍，但 v1/v2 无界队列与远程 SDK 不提供统一端到端背压保证。
Drain-on-consume
项目从 StreamChannel buffer 取出后即删除，不保留历史。
SSE
Server-Sent Events，SDK 远程流的 HTTP 单向事件 transport。
WS / WebSocket
双向长连接 transport；当前 Python SDK async thread stream 可选，sync 文档边界以 SSE 为主。
Cursor / since
远程重连时表示已经应用到哪个序号，并请求从其后重放；仍需 event_id 去重和业务幂等。
Interrupt
可恢复暂停，不是普通错误；恢复位置由 checkpoint/Pregel 持有，stream 仅传递事件与 payload。
