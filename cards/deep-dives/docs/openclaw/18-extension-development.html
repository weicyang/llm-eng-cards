1. 模块定位

“扩展 OpenClaw”不等于“都写 Plugin”。Skill 是知识，Tool 是模型可调用函数，MCP 是外部服务协议，Channel/Provider/Harness/Node/Memory/Context 是不同所有权契约；只有需要进程内代码注册、生命周期或多能力组合时，Plugin 才是承载它们的包边界。

本模块负责委托给相邻模块明确不负责
扩展面选型、manifest/package/runtime 结构、SDK import、注册和生命周期。Tool Policy/Sandbox/Approval 由安全层；Channel 传输语义由 Channel 模块；模型 failover 由 Agent/Provider 编排。不鼓励用 core patch 承载可选/owner-specific 行为。
配置 Schema、UI hints、help/setup descriptor、Doctor migration、docs/test 同步责任。Core config owner 负责 generic schema/doctor；plugin-owned migration 由 plugin contract 提供。不在 runtime 读取 legacy key 或添加 silent fallback。
安装、更新、restart、runtime inspection 与 package acceptance。ClawHub/npm/git 提供包来源；Gateway 拥有进程重启和 generation。runtime loader 不运行包管理器或在线修依赖。

根边界：AGENTS.md:55-69；Plugin SDK owner：src/plugin-sdk/AGENTS.md:1-43；loader owner：src/plugins/AGENTS.md:1-45；plugin 生产 import 规则：extensions/AGENTS.md:25-46。

3. 核心概念与扩展面选型

选型前置门：先检查已有 OpenClaw plugin、ClawHub 包、成熟 OSS 库或免费 MCP server 是否已满足需求。只有现有方案不合适、不安全、不维护、成本不可接受，或需求明确要求自研时才新增表面。

需求信号首选扩展面何时升级为 Plugin/组合不要误用
只需教 Agent 一套步骤、命令或使用规范Skill：SKILL.md需要新可执行能力时，Skill + 现有 Tool 或 Tool plugin。Skill 不授予 shell/tool 权限。
模型需要调用一个本地/网络函数Tool用 tool-only plugin 或 mixed plugin 注册；需要 side effects 时标 optional/policy。不要把普通函数做成 Gateway RPC 或 Harness。
已有外部服务提供标准 tools/resources/promptsMCP需要 requester-scoped credentials/ownership 时由 Plugin 注册 connection resolver。不要绕过最终 effective tool policy。
新增 Telegram/Slack 类消息平台Channel plugin组合 shared message tool、inbound kernel、outbound adapter。不要在 core 硬编码平台 id/policy；不要自造产品命令树。
新增 HTTP/WS LLM、媒体、speech、search/fetch vendorProvider plugin同 vendor 多能力可由一个 cohesive plugin 所有。不要在 generic agent loop 写 vendor branch。
模型由 native daemon/CLI 拥有 thread、resume、compaction/tool eventsAgent Harness plugin通常同时有 Provider/route compatibility contract。普通 LLM API 不需要 Harness。
能力必须在已配对设备执行Node host commandPlugin 注册 command；可选 agentTool descriptor + invoke policy。Node capability 声明不是授权。
替换主记忆搜索/flush/runtimeMemory exclusive slot plugin只增补 corpus/prompt 时用 additive supplement，不抢主 slot。不要平行 JSON sidecar/双写。
替换 assemble/ingest/compact/maintain 上下文生命周期Context-engine exclusive slot plugin声明 hostRequirements；与 Harness 能力相容。不要 patch 多个 prompt builder 分支。
跨上述多项、需 install/config/lifecyclePlugin 作为 ownership/package 边界一个 vendor/feature plugin 可注册多个 capability。Plugin 不是 capability；不要做无关能力“杂物包”。

4. 架构组成

4.1 最小目录结构

my-plugin/ ├─ package.json # npm identity、ESM、built entry、deps/peer/compat/install ├─ openclaw.plugin.json # id、configSchema、ownership/contracts、activation、skills ├─ src/ or index.ts # definePluginEntry / defineChannelPluginEntry ├─ api.ts # 有意公开的 plugin-local 轻量契约（可选） ├─ runtime-api.ts # plugin-local runtime barrel（可选） ├─ setup-entry.ts # 轻量 setup-only entry（可选） ├─ dist/ # 发布包的 JavaScript + declarations/assets ├─ *.test.ts # unit/contract/loader smoke └─ README / docs # 用户配置、权限、故障与升级说明

4.2 三份契约不能混写

资产拥有内容不能承载决定性证据
openclaw.plugin.jsonid、required configSchema、channels/providers/kind、contracts、activation、skills、uiHints、setup metadata。runtime behavior、代码 entry、npm install metadata。src/plugins/manifest.ts:327-430；docs/plugins/manifest.md:19-40
package.jsonname/version/type、openclaw.extensions built entry、runtime deps、peer、install/compat/build metadata。live registration 和 operator config。src/plugins/manifest.ts:2140-2211、src/plugins/manifest.ts:2222-2262
Runtime entrydefinePluginEntry/defineChannelPluginEntry + register(api)。磁盘 discovery 的唯一来源；control plane 不应为 metadata 执行 runtime。通用入口：src/plugin-sdk/plugin-entry.ts:303-365；Channel 入口：src/plugin-sdk/core.ts:556-572、src/plugin-sdk/channel-core.ts:20-33

4.3 Manifest-first load pipeline

discovery root → 安全打开 package root → 读取 package.json entry metadata → 读取/归一化 openclaw.plugin.json（≤256 KiB） → enable/deny/slot/config 校验 → 构造 metadata snapshot + activation plan → 仅 import 已计划的 runtime entry → 调用 register(api) → 校验 ownership/重复/contract → 发布 runtime registry → consumer 解析 capability

Manifest load 要求非空 id 与 object configSchema，拒绝 core reserved id 和不安全/过大路径；字段在进入 snapshot 前规范化。证据：src/plugins/manifest.ts:26-40、src/plugins/manifest.ts:1877-1950、src/plugins/manifest.ts:1994-2077。

5. 完整运行流程

5.1 成功路径：从开发到 live registration

选择窄表面 → 编写 package + manifest + entry → 聚焦 SDK import → unit + loader 支撑的 registration contract → 构建 JavaScript → npm pack → openclaw plugins install npm-pack:<tarball> --force → 受管 npm project 安装生产依赖 → Gateway restart → openclaw plugins inspect <id> --runtime --json → 演练真实 capability → 发布到 ClawHub/npm → 安装已发布 source + 重复 inspect/live 证明
  1. Manifest 先声明 tool/provider/channel/slot ownership 与 activation，避免为了发现能力加载所有 runtime。docs/plugins/building-plugins.md:86-120
  2. Entry 通过 register(api) 注册 live 实现；manifest 声明与 runtime registration 必须一致。docs/plugins/building-plugins.md:126-157、docs/plugins/building-plugins.md:278-325
  3. 发布 entry 指向 built JavaScript，npm pack 必须包含 dist。docs/plugins/building-plugins.md:182-202
  4. npm-pack: 使用受管 per-plugin npm project，能暴露 devDependency 假阳性；安装后 restart，再用 runtime inspect 证明实际注册。docs/plugins/building-plugins.md:189-211、docs/plugins/manage-plugins.md:141-156

5.2 拒绝路径：manifest/package/registration 不成立

发现候选 → manifest 缺失/不安全/非法？拒绝并诊断 → 缺 id/configSchema？拒绝 → package 缺失/空/非法 openclaw.extensions？安装拒绝 → minHostVersion/pluginApi range 不兼容？安装拒绝 → disabled/deny/未选中 slot？不激活 → import 缺依赖？plugin load error → 重复/非法/未声明 registration？跳过/error 诊断 → capability 不可用；隔离契约允许时 core 保持存活

安装会显式区分 openclaw.extensions 缺失、空数组、非法类型以及 host/plugin API 不兼容，不把错误拖到随机 import。证据：src/plugins/install-shared.ts:40-64、src/plugins/install-shared.ts:67-104、src/plugins/install-shared.ts:125-160。

Tool 注册若缺 name/execute/parameters、与 core 冲突，或 optional metadata 与 runtime 不一致，会跳过并产生 plugin diagnostics；Memory/Context 等 exclusive capability 还受 manifest kind/slot gate。证据：docs/plugins/building-plugins.md:302-325、docs/plugins/sdk-testing.md:174-187。

5.3 恢复路径：更新、依赖缺失与 Doctor

runtime 缺 import / 陈旧 registry / 损坏 host peer link → list/inspect/doctor 识别精确 owner 与 install record → tracked package：plugins update <id> → missing/replaced package：plugins install <source> → 历史遗留生成 state / 陈旧 index / peer link：doctor --fix → 受管 restart（或手动 gateway restart） → plugins inspect <id> --runtime --json → 聚焦 capability 证明

Gateway startup/reload 永不运行包管理器。Doctor 可以清理旧生成依赖状态、恢复配置仍引用但 install record 缺失的可下载插件、重建 registry、修 host peer link；它不为本地开发插件安装依赖。证据：docs/plugins/dependency-resolution.md:152-179；src/commands/doctor-plugin-registry.ts:494-595、src/commands/doctor-plugin-registry.ts:650-745。

7. SDK Import、注册接口与禁止边界

7.1 正确 import

import { definePluginEntry } from "openclaw/plugin-sdk/plugin-entry"; import { defineChannelPluginEntry } from "openclaw/plugin-sdk/channel-core"; import type { AgentHarness } from "openclaw/plugin-sdk/agent-harness"; import { createPluginRuntimeStore } from "openclaw/plugin-sdk/runtime-store"; // 仅在实现 outbound adapter 时使用： import { defineChannelMessageAdapter } from "openclaw/plugin-sdk/channel-outbound";

每个 subpath 应解决一个能力或 runtime 需求；宽根 barrel、provider/channel branded convenience seam、另一个 plugin 的 SDK facade 都不是新代码默认。内部共享通过本包 ./api.ts/./runtime-api.ts。窄 subpath：docs/plugins/sdk-overview.md:25-64；local barrel 与 self-SDK 禁止：docs/plugins/sdk-overview.md:693-709。

7.2 禁止 import

  • Plugin 生产代码不得导入仓库 src/**、src/channels/**、src/plugin-sdk-internal/**。
  • 不得导入另一个 plugin 的 src/**，不得用相对路径逃出 package root。
  • 不得从本 plugin 生产代码反向导入 openclaw/plugin-sdk/<自己的 id>；走 local barrel。
  • Host 需要 plugin helper 时，先通过 plugin api.ts/runtime-api.ts 或提升为中立、可复用 SDK capability。

硬边界：extensions/AGENTS.md:25-46；SDK 边界：src/plugin-sdk/AGENTS.md:23-67。

9. 并发、性能与资源生命周期

  • Manifest-first：metadata/config/setup 路径保持轻量，不因展示 catalog 或校验配置 import runtime。src/plugins/AGENTS.md:22-43
  • Activation plan：按 startup/provider/command/channel/route/capability 缩小 runtime load；activation 只是 planner hint，不是 hook。src/plugins/manifest.ts:163-189、src/plugins/manifest.ts:1396-1427
  • Generation：plugin metadata 对 Gateway process 稳定；install/update 后必须 restart 或走明确 owner reload，不能请求期 stat/hash 扫描。AGENTS.md:103-107
  • Lazy boundary：async-only send/probe/setup/login/runtime 保持专用 *.runtime subpath；避免同一 prod module static+dynamic import。src/plugin-sdk/AGENTS.md:33-41
  • Service cleanup：registerService、runtime lifecycle、Channel monitor、Node command 等必须有 stop/dispose，Gateway close/reload 回收。
  • State：使用 injected keyed/blob/lease/queue store；持久 state 落 shared/per-agent SQLite。Plugin 不持有 DB path/handle，不在 async SQLite transaction 内 await。docs/plugins/sdk-runtime.md:699-760
  • Runtime store：跨文件需要 runtime ref 时用 createPluginRuntimeStore；未初始化 fail 明确，测试后清理。docs/plugins/sdk-runtime.md:840-884

10. 安全与信任边界

  1. Native plugin 等价进程内代码执行。它能注册 route/tool/hook/service，也能使 Gateway 不稳定；安装来源审查比 runtime policy 更早。docs/plugins/architecture.md:420-430
  2. Allowlist 按 id，不等于来源证明。Workspace plugin 可同 id shadow bundled plugin；开发有用，生产需检查 source snapshot/install provenance。docs/plugins/architecture.md:432-436
  3. Tool 可见性与执行授权分离。Plugin 注册 Tool 后仍受 effective policy、hook、approval、sandbox；Skill 更不是授权。
  4. Channel 是 transport-only。入口 allowlist/pairing/mention/command gate 与平台限制在 typed adapter；产品 provider/policy 不塞入 Channel。docs/plugins/sdk-channel-plugins.md:21-35
  5. Node 仍走 pairing + allowlist + invoke policy。即使 command 发布为 agent tool，只有 node connected 且 command 在批准面才可见。docs/plugins/sdk-overview.md:181-192
  6. MCP requester credential 不持久化。resolver headers 不日志/不落盘；无 trusted requester 不物化，没有另一用户 credential fallback。docs/plugins/sdk-overview.md:267-310
  7. Install policy 与 runtime hook 分开。before_install 不是全局安装准入；覆盖 CLI/Gateway install/update 的决策属于 security.installPolicy。docs/plugins/sdk-overview.md:643-652
