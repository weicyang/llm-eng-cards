当前事实可选能力边界事实
一句话目标：OpenClaw 将日志、Health、诊断事件、Doctor、Audit 与 Usage 分成不同事实面；它们可以关联，但不能互相替代，更不能把“能返回 HTTP 200”误解成“渠道、会话和模型链均健康”。

1. 模块定位

可观测性不是单一监控服务，而是贯穿进程的投影层：日志描述离散事实，Health 描述当前服务状态，stability 记录有界运行事件，Doctor 检查磁盘/config/迁移，Audit 保存 metadata-only 责任链，Usage 从 transcript 与 provider 快照派生 token/成本。

边界本模块负责明确不负责
运行日志结构化 JSON、console/file 路由、subsystem、脱敏、按日/容量轮换。不保证日志是无损审计账本；写入或轮换失败不得阻塞业务。
服务健康浅 HTTP live、Channel-aware ready、WS health/status、可选 live account probe。不把一次 probe 成功等同于端到端消息、模型或投递 SLA。
稳定性诊断event-loop、内存、session attention、payload、tool/run 等脱敏 ring buffer 与 bundle。不是无限时序库；ring buffer 覆盖旧事件，support export 也不包含 raw payload。
Doctor--lint 非变更检查；普通 Doctor 报告；--fix 执行受控迁移和修复。不在 runtime 热路径长期兼容旧形状，也不替本地插件安装依赖。
Auditagent run、tool action、可选 message metadata 的 SQLite ledger。不复制 prompt、message body、tool args/result，不是法规级无损归档。
Usage/Costprovider quota snapshot、session transcript token/cost rollup、缓存状态。缺失或未知 pricing 不可伪装为可信零成本。

边界证据：日志故障隔离 src/logging/logger.ts:591-635；Audit 默认与 message opt-in src/audit/audit-config.ts:6-17；Usage 未知定价处理 src/infra/session-cost-usage.ts:830-865。

3. 核心概念与术语

Liveness仅证明进程的 HTTP/event loop 还能响应。它不加载配置，不询问 Channel，正常结果固定为 {ok:true,status:"live"}。
Readiness回答当前实例是否应接流量；综合 startup sidecars、draining、受管 Channel 状态，并附带 event-loop 指标，但 event-loop degraded 当前是观测字段而非直接 ready=false 条件。
WS health完整、可缓存的业务健康投影；probe:true 才要求 Channel plugin 执行实时 account probe。
Status配置和运行摘要；可包含 Channel summary，但不是强制 live probe。
Stability snapshot进程内 1000 条的脱敏 ring buffer，默认查询最近 50 条；按类型、序列过滤并汇总 memory/payload。
Session attentionlong_running 表示仍有 owner 的慢工作；stalled 表示有 owner 但无进展；stuck 表示 stale bookkeeping，可进入恢复。
Audit ledger责任链 metadata；identity 使用 HMAC pseudonym，固定保留期与行数上限，写入 best-effort。
Usage rollup可重建的 per-agent SQLite cache；以 transcript checkpoint 与 pricing fingerprint 判断 fresh/partial/stale/refreshing。

Stability 容量/默认 limit：src/logging/diagnostic-stability.ts:8-12、src/logging/diagnostic-stability.ts:707-765；session 分类：src/logging/diagnostic-session-attention.ts:5-26、src/logging/diagnostic-session-attention.ts:28-129。

5. 完整运行流程

5.1 成功路径：一次详细 Health 调查

operator: openclaw health --verbose → 已认证 WS method health {probe:true} → 绕过普通 60s health cache → 枚举只读 channel plugin 和所有相关 account → 解析 + 检查 account（不暴露 raw secret） → plugin.status.probeAccount(timeout) → 合并 live runtime snapshot + probe + queue/context/pricing/event-loop → 脱敏敏感字段，除非 operator.admin → 返回 HealthSummary
  1. --verbose 映射为 {probe:true}；普通请求可命中 cache 后后台刷新。src/commands/health.ts:831-835、src/gateway/server-methods/health.ts:138-180
  2. Health 先从 plugin config 解析 account，再走 inspection；失败只成为 diagnostics/fallback，不让整个 snapshot 崩溃。src/commands/health.ts:507-568
  3. 仅 enabled + configured + doProbe + plugin 实现 probeAccount 时才调用平台 live probe。src/commands/health.ts:659-708
  4. 无 admin scope 的结果删除敏感 probe 内容，仅保留允许的非敏感失败投影。src/commands/health.ts:733-754、src/gateway/server-methods/health.ts:140-143

5.2 拒绝/提前结束路径：浅探针与 Doctor lint

GET /healthz → 200 浅 live POST /healthz → 405 + Allow: GET, HEAD GET /readyz（remote 未认证）→ {ready:boolean}，无 subsystem 名 doctor --lint + 无效 config → finding/exit code，无 mutation doctor --lint --severity-min bad → 拒绝 CLI 输入

HTTP live 在加载 config 前处理，因此适合进程探活；ready 才读取 runtime readiness。远程未认证调用方只能看到布尔值，防止泄露 failing subsystem。Doctor lint 使用 readConfigFileSnapshot({observe:false})，先报告 parse 问题，之后才运行 core 与 plugin health checks。证据：src/gateway/server-http.ts:242-267、src/gateway/server-http.ts:285-321、src/gateway/server-http.ts:546-567；src/commands/doctor-lint.ts:45-94。

5.3 恢复路径：stuck session 与 support export

诊断 heartbeat → 检查进程内 session state + 活跃 run/tool/model owner → 分类 ├─ long_running：观察，永不恢复 ├─ stalled：警告；活跃 owner 通常不可恢复 └─ stuck 陈旧 bookkeeping：recoveryEligible → 恢复协调器校验当前 owner generation → 释放陈旧 queue/state → 发出 requested/completed event → 如需调查：diagnostics support export → 脱敏 config/status/health/log tail + 最新 stability bundle → 写私有 zip，绝不含 raw payload

关键安全规则是“慢不等于死”：active model call 在阈值内归类为 long_running；blocked tool/active run 是 stalled；只有没有活跃 owner 的 stale state 才直接 recoveryEligible:true。证据：src/logging/diagnostic-session-attention.ts:35-129。

导出路径不把 raw log 直接打包：日志只保留 operational summary/safe metadata，manifest 明确 payloadFree:true 与 rawLogsIncluded:false。manifest：src/logging/diagnostic-support-export.ts:773-791；summary prose：src/logging/diagnostic-support-export.ts:639-645。

9. 并发、性能与资源

  • 日志同步写但故障隔离：transport 构造结构化 line，经 regular-file append；任意异常吞掉。容量轮换发生在 append 前，失败后继续原文件。src/logging/logger.ts:591-635
  • Health 请求合并：普通与敏感 refresh 各持一个 Promise；cache 命中立即响应并后台刷新。src/gateway/server/health-state.ts:80-127、src/gateway/server-methods/health.ts:156-177
  • Live probe 有界：account probe 使用 capped timeout；仅详细 Health 执行昂贵平台调用。src/commands/health.ts:612-614、src/commands/health.ts:670-683
  • Audit 不阻塞主回调：worker queue 最多 4096；满或 worker 不可用时丢 metadata 并报告。stop 等待 SQLite busy window 后再超时终止。src/audit/audit-event-writer.ts:9-12、src/audit/audit-event-writer.ts:134-185
  • Usage cache：Gateway cache 30 秒、最多 256 key；per-agent refresh 有锁和指数 polling，agent fan-out 并发 12，避免 dashboard 放大扫描。src/gateway/server-methods/usage.ts:69-84、src/gateway/server-methods/usage.ts:106-134；src/infra/session-cost-usage.ts:1755-1869

10. 安全与信任边界

  1. Transport 边界重复脱敏。结构化 object 先按 key/value exact registry 处理，再对最终 JSON string 运行文本 redactor，避免嵌套 secret 和序列化形态遗漏。src/logging/logger.ts:475-486、src/logging/logger.ts:605-616
  2. 动态 SecretRef 进入 exact registry。raw、percent-encoded 与 JSON-escaped 形态均注册；上限 512 防止无界内存。src/logging/secret-redaction-registry.ts:17-50
  3. Readiness 最小披露。只有本地直连或通过 Gateway auth 的请求获得 failing subsystem；remote anonymous 只见布尔状态。src/gateway/server-http.ts:242-267、src/gateway/server-http.ts:299-315
  4. Audit identity pseudonymized。message account/conversation/message/target 使用 process store identity key 生成 HMAC ref，不保存原平台 id。src/audit/audit-event-store.ts:460-484
  5. Support export 是“脱敏后可分享”，不是“绝对无秘密”。实现拒绝 raw payload，限制路径逃逸并使用私有权限；操作者仍应在外发前检查 artifact。src/logging/diagnostic-support-bundle.ts:71-109、src/logging/diagnostic-support-export.ts:639-645
信任模型：Native plugin 与 core 同进程，可以生成日志和诊断事件；Plugin SDK 提供 scoped logger，但不会把恶意插件变成不可信沙箱。来源审查、allow/deny 与最小安装面仍是第一道防线。

配置/插件升级后异常openclaw doctor --lint，再普通 Doctorlegacy config/manifest、stale registry、broken peer link审查 finding 后 openclaw doctor --fix，再受管重启。

15. 设计权衡与已知限制

问题当前选择收益成本/限制重评条件
探活可靠性live 极浅、ready 与 deep health 分层探针不会自造故障或平台流量单一 200 无法证明业务健康部署平台需要独立 startup/readiness/liveness contract。
日志可靠性best-effort 同步 append，失败不阻塞业务可用性优先日志可能缺口需要强审计时应使用 owner ledger，不增强普通 log。
诊断历史1000 条 ring + 触发式 bundle内存和隐私有界无法做长期趋势需要长期 metric 时接 OpenTelemetry/Prometheus plugin。
Audit 内容默认 metadata-only，message metadata opt-in降低敏感复制和存储成本不能还原完整对话法规归档必须由专门、明确同意的外部系统承担。
Audit 写路径worker queue，满则丢不阻塞 Agent/tool 热路径不是 exactly-once若事件成为业务事实，应迁入对应 owner durable transaction。
成本估算优先 provider-billed；否则按已知 pricing 估算可解释来源catalog 漂移/未知模型会缺值Provider 提供权威账单/usage endpoint。
证据缺口：本次未进行真实 Channel API、生产磁盘故障、长时间 event-loop 压测、OOM 临界点或外部 telemetry exporter Live 验证。结论绑定当前 2026.7.2 工作副本、聚焦测试和文档契约；由于环境无 Git CLI，无法声明 SHA。
