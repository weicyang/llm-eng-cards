一句话目标：协议层先用严格 Frame/Connect Schema 和 challenge-bound Device Proof 建立身份，再用 pairing、Role、Scope、方法 descriptor 与动态 generation 限制每次操作；客户端声明的 capability 只描述“能做什么”，从不授予“允许做什么”。

1. 模块定位

Gateway 协议是 Operator、Control UI、Node 和轻量 probe 共用的控制面线协议。它拥有顶层帧、握手、版本范围、错误结构和跨语言生成契约；Gateway runtime 拥有认证、配对、连接状态及 RPC 授权。它不拥有具体 RPC 业务、Agent Tool Policy、Sandbox 或 Channel 平台认证。证据：packages/gateway-protocol/src/schema/frames.ts:148-179、src/gateway/server/ws-connection/message-handler.ts:283-394

边界负责委托/不负责
WireJSON text frame；req/res/event envelope；Connect/Hello/Error shape。方法 payload 由选中方法 Schema 再验证。
握手challenge、版本、origin、shared/device/bootstrap auth、Device Proof、pairing。TLS 证书和反向代理身份由 listener/auth owner 处理。
会话权限把批准后的 role/scopes 固定到连接；auth generation 改变时失效。每个 RPC 仍由 method registry 二次授权。
Node 声明携带 caps/commands/permissions 并与批准面调和。声明不是授权，也不绕过命令 deny、approval 或 OS permission。
可靠性payload 限制、slow-consumer policy、tick/ping、结构化 retry hints。广播不是持久事件日志；断线请求不自动 replay。
相邻边界：第 4 章解释 server/listener 与 RPC composition；第 7 章解释 Session；第 13 章解释 Tool Approval/Sandbox；第 15 章解释 Node invoke。协议通过 typed frame 和连接 principal 跨越这些边界，不接管它们的业务状态。

3. 核心概念与术语

Frame Schema顶层 envelope 是闭合对象；params/payload/details 在 envelope 层有意开放，由 method/event/error owner 再收窄。
Challenge服务端先发随机 nonce；Device Proof 必须签入同一个 nonce，防止旧签名重放。
Auth ≠ PairingShared secret/可信代理证明“可以进入 Gateway”；pairing 把设备公钥绑定到批准的 role/scopes。
Role ≠ ScopeRole 选择主体类别；Scope 是 Operator 方法与事件的细粒度授权。缺省 scope 为零权限。
Capability ≠ Authorizationcaps/commands/permissions 是客户端/Node 声明；服务端 allowlist、pairing generation 和 RPC policy 才能授权。
Protocol window普通客户端只接受当前 v4；已认证 node 与 probe 允许 v3–v4 的 N−1 窗口，且不放宽其他安全门。
Discovery ≠ callable sethello-ok.features.methods 是保守发现列表，不是全部可调用方法，也不是授权列表。
Generation fencingshared auth、pairing 或设备凭证变化后，旧连接被关闭或在请求前拒绝，避免 stale principal 继续使用。

5. 完整运行流程

5.1 成功：challenge → connect → hello-ok

  1. WS upgrade 成功后，服务端生成 connId 和 connectNonce，启动握手超时，并立即发 connect.challenge。src/gateway/server/ws-connection.ts:262-376、src/gateway/server/ws-connection.ts:424-431
  2. 参考客户端要求 challenge，读取非空 nonce 后才构造 connect；v3 Device Proof 签入 device/client/mode/role/scopes/time/token/nonce/platform/family。packages/gateway-client/src/protocol-client.ts:517-545、packages/gateway-client/src/client.ts:709-812
  3. 服务端先做 64 KiB pre-auth 限制，再要求第一帧是合法 RequestFrame(method="connect") 且 params 通过 Schema。src/gateway/server/ws-connection/message-handler.ts:184-203、src/gateway/server/ws-connection/message-handler.ts:283-324
  4. Admission 检查 startup、版本范围、Role、Scope 缺省拒绝与浏览器 Origin；认证解析 shared/password/trusted-proxy/bootstrap/device token。src/gateway/server/ws-connection/connect-admission.ts:82-150、src/gateway/server/ws-connection/connect-auth.ts:100-133
  5. Device Proof 验证公钥派生 ID、±2 分钟时间、challenge nonce 与签名；Pairing 再检查 role/scope 是否在批准集合内，必要时签发 device token。src/gateway/server/ws-connection/connect-device-proof.ts:64-100、src/gateway/server/ws-connection/connect-device-pairing.ts:521-594
  6. 连接成功注册为 GatewayWsClient 后发送成功 response，payload 为 hello-ok；包含当前 protocol、方法/事件、snapshot、实际 auth role/scopes 和 payload/tick policy。注册失败会先回滚并终止。src/gateway/server/ws-connection/connect-session.ts:412-421、src/gateway/server/ws-connection/connect-session.ts:555；payload：src/gateway/server/ws-connection/connect-hello.ts:84-121；发送与回滚：src/gateway/server/ws-connection/connect-hello.ts:155-171

5.2 拒绝：协议、认证、设备、配对

connect frame ├─ 无效 envelope/params → INVALID_REQUEST + close 1008 ├─ 无兼容协议 → PROTOCOL_MISMATCH + close 1002 ├─ 无效 origin/role → 结构化错误 + close 1008 ├─ 错误/缺失凭证 → auth 详情 + close 1008 ├─ 过期/错误 nonce/signature → DEVICE_AUTH_* + close 1008 └─ 未配对/scope 升级 → 持久化 pairing 请求 + NOT_PAIRED + close 1008

拒绝发生在 client 注册和业务 handler 前。Pairing-required 会广播 pending request；默认建议暂停自动重连，只有 bootstrap/SSH detached approval 明确给出 wait_then_retry、pauseReconnect:false 时持续重试。证据：src/gateway/server/ws-connection/connect-device-pairing.ts:430-516；packages/gateway-client/src/reconnect-policy.ts:20-47

5.3 恢复：启动中、token mismatch、断线与 gap

  • Gateway sidecars 未 ready：connect 返回 retryable UNAVAILABLE 和 retryAfterMs，客户端用 1013 + 指定延迟重连。src/gateway/server/ws-connection/connect-admission.ts:82-95、packages/gateway-client/src/client.ts:872-879
  • shared token mismatch：仅可信 endpoint 可进行一次 cached device-token 快速重试；失败后暂停循环。packages/gateway-client/src/client.ts:837-871、packages/gateway-client/src/client.ts:1066-1082
  • 一般断线：1 秒起步、乘 2、上限 30 秒；pending RPC 全部 reject，不在重连后 replay。packages/gateway-client/src/client.ts:449-456、packages/gateway-client/src/protocol-client.ts:594-626、packages/gateway-client/src/protocol-client.ts:636-643
  • 事件 seq 跳变：调用 onGap(expected,received)；协议没有 replay，客户端必须重新读取权威 snapshot/session/health。packages/gateway-client/src/protocol-client.ts:546-557

7. 接口、协议与事件

7.1 Frame Schema

Frame必填开放字段顺序/约束
reqtype、非空 id、非空 methodparams?: unknown握手前只允许 connect；握手后只接收 req。
restype、id、okpayload/error 详情id 对应 pending request；错误含 retry hints。
eventtype、eventpayload普通广播可有 per-client seq/stateVersion；targeted 可无 seq。
hello-okprotocol/server/features/snapshot/auth/policyplugin UI/surface 可选扩展只作为 connect 成功 response payload。

完整 TypeBox Schema 是严格契约；TypeBox-free guards 则只验证 dispatch-critical 字段并容忍 additive envelope 字段，供浏览器 bundle/CSP 敏感消费者使用。两者用途不同，不得用轻量 guard 替代方法 payload 校验。证据：packages/gateway-protocol/src/frame-guards.ts:37-55、packages/gateway-protocol/src/frame-guards.test.ts:4-50

7.2 版本协商

当前 PROTOCOL_VERSION=4；普通客户端最低 4，Node 与 probe 最低 3。Server 接受范围覆盖 v4；只有 role=node + mode=node 才能使用 N−1 node 路径。Legacy node 不因此获得 plugin-owned capability。证据：packages/gateway-protocol/src/version.ts:1-8、src/gateway/server/ws-connection/connect-admission.ts:98-134、docs/gateway/protocol.md:964-977

7.3 Error 与 codegen

客户端应按顶层 code 和 details.code 分支，message 仅供人读。JSON Schema 由 ProtocolSchemas 和 core method metadata 生成；Swift/Kotlin 从同一图生成，guard test 锁住 native 常量和 N−1 规则。证据：scripts/protocol-gen.ts:34-68、packages/gateway-protocol/src/native-protocol-levels.guard.test.ts:110-182

10. 安全与信任边界

  1. Transport：参考 client 拒绝公网明文 ws://；远程用 wss://，可选证书 fingerprint pin。packages/gateway-client/src/client.ts:181-207、packages/gateway-client/src/client.ts:490-553
  2. Origin：浏览器 UI/WebChat 在 auth 前检查 allowed origin；Host-header fallback 是显式危险配置并产生 security warning。src/gateway/server/ws-connection/connect-admission.ts:187-234
  3. Device Proof：公钥 fingerprint 必须等于 device id；签名绑定 challenge、role、scope、token 与设备元数据，且时间窗口有限。src/gateway/server/ws-connection/connect-device-proof.ts:64-100
  4. Pairing：新设备、role upgrade、scope upgrade 都进入批准决策；local/trusted-proxy/bootstrap 特例有精确条件和 scope cap。src/gateway/server/ws-connection/connect-device-pairing.ts:153-217、src/gateway/server/ws-connection/connect-device-pairing.ts:243-300
  5. RPC/事件：握手只建立 principal。RPC 方法在 dispatch 时由 authorizeGatewayMethod() 按 descriptor、Role 与 Scope 判定；事件 guard 独立过滤，未知广播 fail-closed。authenticated dispatch 只负责 post-auth frame、generation 与 flood 控制。src/gateway/server-methods.ts:313-357、src/gateway/server-methods.ts:928-931、src/gateway/server-broadcast.ts:101-150
  6. Capability 不授权：Node 的 caps、commands、permissions 只参与功能/批准面；调用还需要 paired generation、server command allowlist、方法角色和必要 Approval。
常见错误：不要因为 hello-ok.features.methods 含某方法或 Node 声明某 command 就启用 UI/执行；先看 negotiated role/scopes、pairing generation 和方法结果。Discovery 是可见性提示，capability 是支持声明，authorization 才是许可。

15. 设计权衡与已知限制

问题当前选择收益成本/限制
统一多客户端单一 JSON/WS protocol + role共享 auth、Schema、事件大契约面，需 codegen discipline。
兼容性additive first；仅 node/probe N−1rolling upgrade 不放宽 operator UI旧 node plugin capabilities 被 withholding。
Schema 严格性闭合 envelope + owner-local unknown payload边界清晰、可扩展每个 dispatcher 必须二次验证。
事件可靠性per-client seq、best-effort、不 replay低状态成本客户端必须能重建 projection。
背压buffer threshold 后 drop 或 close保护 Gateway 内存不可提供无损事件流。
设备信任共享 auth + 签名身份 + pairingcredential 与设备/权限分层时钟、密钥持久化和批准 UX 更复杂。
证据缺口：未验证真实 reverse proxy/Tailscale/TLS pin、移动端 Keychain、v3 Node 与 v4 Gateway 的现场互操作；worker closed protocol 是独立信任域，仅在本章标出边界，未展开其 credential/epoch/session CAS 内部。Git SHA 因工具不可用而未知。
