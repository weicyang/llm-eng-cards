1. 模块定位

边界本模块负责委托或明确不负责
选择解析 configured default、Channel、Session 与一次性 override，执行 allowlist 和 Harness 支持检查。Channel 只提供 route/context；不决定 Provider 策略。
Catalog合并 runtime registry、manifest、配置和 Provider plugin augmentation，形成 generation 内快照。Provider 专属 auth、onboarding、catalog 行由 Provider plugin 所有。
认证排序可用 Auth Profile，记录 cooldown/disabled/blocked 状态并轮换。Secret 解析与 SQLite 事务由 auth store/Secret owner 执行。
Failover构造有序候选、判定可继续错误、记录尝试与 turn-local winner。Context 溢出 留给第 10 章 compaction/retry，不跨模型掩盖。
Harness依据 model/provider runtime policy、显式 pin 与 supports 选择执行器。Harness 内部协议归其插件；显式插件 Harness 失败不改用 built-in。

3. 核心概念与术语

Provider拥有 transport、auth/catalog/onboarding 和 vendor policy 的逻辑路由 owner；不是模型本身。
Modelprovider/model 逻辑引用及能力元数据；Catalog 行可以对应不同 physical route variant。
Catalog用于可见性、能力、context window 和 route metadata 的 generation 快照；不是一次调用。
Auth Profile某 Provider 的一个可轮换凭证身份及其 usage/cooldown/disabled 状态；与 Harness 身份分离。
Harness执行 Agent 协议和 turn 生命周期的 runtime；built-in openclaw 或插件实现。
有效 Modeldefault、channel、stored session、primary recovery probe、explicit run override 和 可见性策略 共同得到的本次起点。
严格选择用户明确 Session/一次性选择不继承无关配置 fallback；失败必须可见。
Turn 局部 fallback本 turn 可由后续候选回答，但 winner 不永久改写下一 turn 的选中模型。

选择优先级实现：src/agents/command/model-selection.ts:224-349；严格策略：src/agents/agent-scope.ts:562-588；Catalog route 原子性：src/agents/model-catalog.ts:166-229。

5. 完整运行流程

5.1 成功路径：默认模型一次命中

agentCommand → 解析已配置的默认值 → 应用 channel 覆盖（若无 explicit run 覆盖） → 应用有效的已存储 session 覆盖 → 应用已授权的 explicit run 覆盖 → 可见性策略 + Harness 准备 → 解析有效 fallbacks → 构建 [requested, ...fallbacks] 候选链 → auth 顺序选择可用 profile → 选定的 Harness 运行 provider stream/tool 循环 → candidate_succeeded → reply + usage；下一 turn 仍从选定 model 开始

Stored session override 高于 Channel override；显式 run override 最后覆盖，但必须允许、未被 selection lock 锁定且通过 modelPolicy。Catalog/Harness 检查在模型调用前完成。src/agents/command/model-selection.ts:230-349、src/agents/command/model-selection.ts:357-437

5.2 拒绝/提前结束路径：严格用户选择

/model 或 picker 写入 modelOverrideSource="user" → 下一 turn 解析 stored provider/model → resolveEffectiveModelFallbacks() → user source => [] → 只构造 requested candidate → auth/provider 失败 → 无其他候选，表面化原错误或单候选错误 → 不让无关模型替用户“成功”

同样的 fail-fast 还包括：caller 未获 allowModelOverride、selection lock、modelPolicy 拒绝、显式 Harness 缺失或不支持。它们均发生在业务副作用前。src/agents/command/model-selection.ts:117-123、src/agents/command/model-selection.ts:330-365；src/agents/agent-scope.ts:562-588

5.3 恢复路径：Auth 轮换 → Model fallback → 安全过载重试

候选 A / profile 1 失败 → 分类原因 + 标记 profile 使用状态 → 下一个合格 profile（同 Provider） → profiles 耗尽 / 轮换上限 → 抛出归一化 FailoverError → 外层 runner 记录转换并尝试候选 B → 若胜出：turn 局部成功 → 若每个候选都只是过载： 仅当没有工具执行或 assistant 输出时 重试完整链 ≤ 10 次，指数 2.5s → 30s 上限 30s 后发出一条瞬态状态通知 → 否则 FallbackSummaryError / 可见终态错误

模型候选循环通过 canFallbackAfterError 询问调用方是否已有不可重放工作；CLI max-turn 也会在 candidate fallback 前停止，因为它可能跟在成功工具动作之后。Context 溢出 被立即抛回内层 compaction 路径。src/agents/model-fallback.ts:1812-1868；src/auto-reply/reply/agent-runner-error-handler.ts:64-70、src/auto-reply/reply/agent-runner-error-handler.ts:279-394

9. 并发、性能与资源

  • 预备 Catalog 是 generation 快照；manifest Catalog 按 config/snapshot WeakMap 缓存，避免 request-time discovery。src/agents/model-catalog.ts:77-101、src/agents/model-catalog.ts:327-397
  • 候选 cache 上限 256；auto-primary probe 上限 4096；cooldown probe 每 provider/agentDir 受 30 秒 throttle，状态上限 256。src/agents/model-fallback.ts:369-370；src/agents/agent-scope.ts:50-52；src/agents/model-fallback.ts:1116-1121
  • 同一 Provider 的 profile 轮换 发生在内层 attempt；外层 candidate loop 串行，避免并行候选产生重复工具副作用。
  • Cooldown profile 后移而非删除；最早到期者先排，允许无重启恢复。
  • 完整过载重试的计时器和 notice 都响应 AbortSignal；完成后取消 pending notice。

10. 安全与信任边界

  1. Secret 与路由分离：config 只保存 profile metadata/order；secret 与 usage state 在 per-agent auth store。
  2. 模型选择授权：一次性 override 需要 caller 显式授权，selection lock 和 modelPolicy 在调用前 fail-closed。src/agents/command/model-selection.ts:117-123、src/agents/command/model-selection.ts:330-346
  3. 显式 Harness 不降级：防止用户要求的运行时语义被另一个 backend 悄悄替换。src/agents/harness/selection.ts:298-399、src/agents/harness/selection.ts:553-576
  4. 副作用重放边界：模型 fallback 和完整过载 retry 都必须在 tool execution/assistant output 前；否则表面化错误供用户核验。
  5. 日志脱敏：结构化诊断保存 reason/status/code 与受限 raw preview，不应写出 API key/token。

11. 失败、恢复与兼容

故障/现象即时行为状态影响恢复
用户选择不在 allowlist调用前拒绝。Session 不被新值污染。选允许模型或修 modelPolicy。
Auth/限流/超时标记 profile，尝试下一 profile。cooldown/blocked usage state 更新。到期自动回归；必要时重新认证。
计费/永久 auth较长 disabled lane，向下一 profile/model。profile 跨模型不可用。修余额/凭证；探测或到期恢复。
Provider 过载同 Provider rotation 有界后尽快 model 回退。记录 overloaded bucket。纯失败链可做 turn-local 完整链重试。
Context 溢出不进入 model 回退。候选/selection 不变。交给 compaction/truncation（第 10 章）。
本地协调/Transcript 错误立即抛原错误。不消耗候选。修 session lock/owner 状态。
显式 Harness 缺失/失败fail-closed；运行中不回 built-in。无隐藏 backend 切换。安装/启用/修复 Harness 或改 policy。
全部候选耗尽FallbackSummaryError。可附 soonest cooldown；必要时 suspend lane。按 reason 修 auth、等待或改候选。

错误隔离：src/agents/model-fallback.ts:1840-1868、src/agents/model-fallback.ts:1932-2025；状态排序：src/agents/auth-profiles/order.ts:388-431。

禁止捷径：不要按 model prefix 偷选 Harness；不要在 Core 硬编码 plugin id；不要把未知错误一律当 timeout；不要让 fallback 永久覆盖用户 Session；不要在已有工具/消息副作用后重放整个 turn；涉及 Codex verdict 前必须直接检查 sibling ../codex。

15. 设计权衡与已知限制

选择收益成本/限制
Profile 轮换 先于 model 回退保持模型语义和 prompt cache，利用多账户。状态机复杂；需精确区分 cooldown 与 permanent failure。
用户选择 strict尊重能力、成本和隐私意图。短时故障不会自动“成功”。
Fallback turn 局部一次故障不永久改变 Session。每 turn 可能再次尝试 primary；需 notice/probe 去噪。
显式 Harness fail-closed不悄悄改变 runtime/tool/协议语义。插件故障直接影响该选择。
未知错误有剩余候选时继续提高可用性。必须保留原错误；最终未知不能伪装成已知 Provider failure。
纯过载完整链重试吸收短时容量波动。严格依赖无副作用证明，最多 10 次仍可能等待数分钟。
证据限制：未运行真实 Provider、OAuth、Codex app-server 或过载 Live 测试。已检查 Codex 上游协议与生命周期源码，但本文不承诺任何供应商 SLA、SDK 内部 retry-after 默认、服务容量，也不把 Codex 专属 thread/model 协议写成通用 Provider 行为。
