1. 模块定位

表面负责不负责规范状态
Cron时间/事件计划、durable reservation、执行、retry/backoff、delivery、历史。不保证 Gateway 离线时执行，不是外部集群 scheduler。shared SQLite cron_jobs + task_runs。
Task Ledger跨 cron/subagent/ACP/CLI 的 queued/running/terminal 统一视图。不替代各 runtime 的业务状态；ledger 创建失败不停止 Cron。shared SQLite task_runs / task_delivery_state。
Heartbeat按 agent cadence/active hours 运行周期 agent turn，消费 pending events，选择性通知。不是精确 scheduler；不创建 task ledger row。per-agent session + heartbeat_outcomes。
Internal HookOperator-installed command/session/message/Gateway 生命周期脚本。不是 typed policy middleware；多数 pushed messages 不回 chat。进程内 handler registry + hook files/config。
Inbound HTTP Hook认证外部 POST，规范化为 wake/agent/mapped action。不是 completion callback；不接受 query token。进程内 dedupe cache + dispatched session/cron work。
Typed Plugin Hook优先级有序的修改/阻断/claim 与并行 observation。不天然 durable；timeout 不取消 plugin side effect。active plugin registry。
Completion webhook将 Cron finished event POST 到 HTTP(S) URL。不是 inbound hooks token/path；失败不改写已完成 run。无 outbox，best-effort detached delivery。

3. 核心概念与术语

Job持久定义：schedule、sessionTarget、payload、delivery、failure policy 与 mutable state。
Run一次 reservation→execution→terminal 的尝试；run status 与 delivery status 分离。
Task跨 runtime 的运行镜像；Cron row 的 sourceId=jobId，不是另一个 schedule owner。
Main / isolated / current / customMain 注入 cron-owned wake lane；isolated 每次 fresh；current 在创建时绑定来源但执行用 detached cron run；custom 复用命名持久 session。
Time scheduleat/every/cron 产生 nextRunAtMs；on-exit/stream 永不 time-due，由 Gateway watcher fire。
Completion webhookfinished 后的 outbound observer；与 /hooks/* 入站触发器、typed plugin hook 均不同。

5. 完整运行流程

5.1 成功路径：一次到期 Cron run

timer 唤醒（≤60s） → Gateway root 准入 → 在 cron 锁下重新加载 shared SQLite store → 收集到期 jobs → 持久化 queuedAtMs reservation → shared cron 准入 → 重读 + 重新验证 reservation/spec/due → queuedAtMs → runningAtMs，持久化 → create task_runs(runtime=cron,status=running) → 执行 main / agentTurn / command / script → 应用 execution + delivery 状态和下次 schedule → 持久化 cron job 状态 → 完成 task ledger + 发出 finished → 分离的 completion/failure 通知 → 重新设置 timer
  1. Reservation 先写 SQLite，再释放 lock，防止 timer/manual/reload 同时启动同一 job。src/cron/service/ops.ts:1218-1347、src/cron/service/ops.ts:1350-1471
  2. Task row 创建是 best-effort；失败只 warning，Cron 主状态继续。src/cron/service/task-runs.ts:194-247
  3. Execution outcome 与 delivery outcome 分开保存，成功 agent turn 的普通发送失败不会自动改成 execution error；明确 target guard 或 required delivery 可失败。src/cron/types.ts:107-145、src/cron/isolated-agent/run.ts:1576-1624
  4. 完成事件先归档，webhook/失败目的地再以 independent root best-effort 发送。src/gateway/server-cron.ts:1036-1046、src/gateway/server-cron-notifications.ts:331-417

5.2 拒绝/提前结束路径

拒绝点条件最终状态
SpecMain + agentTurn、script + current/custom、stream + command、无效 webhook/session id。Add/update 拒绝；legacy malformed manual run 记 skipped/invalid-spec。
Dangerous automation gatecron.triggers.enabled!==true 且使用 trigger、stream、script payload。创建/启用拒绝，或执行 error；不启动 headless tools。
Admissionstopped/restart-recovery/already-running/not-due/reservation stale。不执行；queued manual run 发明确 skipped terminal。
Triggerfire:false。持久 trigger state/counter，推进 schedule；不创建普通 run history。
Heartbeatdisabled/quiet-hours/cron busy/requests in flight/empty file/no due tasks/all visibility off。skipped reason；busy 类由 wake layer retry，其他推进 cadence。
Inbound hook非 POST、query token、token mismatch、限流、body/agent/session policy 无效。400/401/405/413/429；不 dispatch。

Cron shape：src/cron/service/jobs.ts:318-450；Heartbeat busy：src/infra/heartbeat-runner.ts:1247-1388；HTTP hook：src/gateway/server/hooks-request-handler.ts:165-335。

5.3 恢复路径：重启、missed 与 retry

Gateway 启动 → 清除 queuedAtMs 且不记录 run → runningAtMs? ├─ 已终态的 task detail 存在 → 恢复精确 outcome/schedule └─ 无终态 → 标记 interrupted error；at job 禁用 → 收集过期任务 → 立即执行非 agent jobs 最多 5 个 → 溢出错开 5s；agentTurn 推迟 2m → 循环 error backoff 30s/60s/5m/15m/60m → 成功重置 error 链

启动不会盲目 replay 已产生副作用的 runningAtMs。若 task ledger 已终态，Cron 恢复它；否则记录 cron: job interrupted by gateway restart。过期 agentTurn 默认推迟，避免 Channel connect 窗口内做模型/tool bootstrap。证据：src/cron/service/ops.ts:169-295、src/cron/service/startup-run-repair.ts:36-140、src/cron/service/timer.ts:2081-2219。

6.2 Job 与 Task 状态机

Cron job: enabled + nextRunAtMs → queuedAtMs（durable 准入前） → runningAtMs（execution 拥有） → lastRunStatus ok|error|skipped → nextRunAtMs / disabled / deleted Task: queued|running → succeeded|failed|timed_out|cancelled|lost Delivery: pending|delivered|session_queued|failed|parent_missing|not_applicable

Task Ledger 是恢复证据而非强依赖：Cron 可在 ledger 写失败时继续；maintenance 在 runtime owner 消失并过 grace 后才用 durable history 判定 terminal/lost。证据：src/tasks/task-registry.types.ts:13-37、src/cron/service/task-runs.ts:83-406。

9. 并发、性能与资源

  • Cron mutation 通过 promise lock 串行；执行在 lock 外，前后各自重新读取和验证 authoritative row。src/cron/service/ops.ts:1218-1471
  • Timer tick 有 state.running 防重入，同时保留 60s watchdog recheck；所有 scheduled/manual/on-exit run 共享 Cron admission limit。src/cron/service/state.ts:244-274、src/cron/service/timer.ts:1387-1414
  • Stream 仅保留一个 active fire 与一个 bounded pending batch；owner identity 在 disable/remove/replace 时轮换，late callback 失效。
  • Trigger 同时最多 3 个 evaluation，30s/5 tool；prepared runtime cache 最多 128，按 config identity + agent + tools key single-flight。src/cron/trigger-script.ts:55-59、src/cron/trigger-script.ts:322-468
  • Heartbeat agent phase 由稳定 seed hash 分散；active-hours 最多向前搜索 7 天，schedule delay clamp 到 Node timer 安全范围。src/infra/heartbeat-schedule.ts:13-39、src/infra/heartbeat-schedule.ts:82-137
  • Typed modifying hooks 按 priority 顺序 await；void hooks 并行。Timeout 结束等待但不取消 plugin promise，因此长任务必须有 plugin-owned shutdown。src/plugins/hooks.ts:498-617

10. 安全与信任边界

  1. Command cron 是 admin automation：它直接在 Gateway host 执行 argv，不经过模型 tools.exec approvals。创建/修改/手动运行必须由 operator.admin 控制面授权。src/cron/command-runner.ts:77-166、docs/automation/cron-jobs.md:221-241
  2. Script/trigger gate：cron.triggers.enabled=true 开启 unattended code-mode，使用 owning agent 的有效工具；必须只授权可信 agent/operator。src/cron/service/jobs.ts:360-450、src/cron/trigger-script.ts:104-199
  3. External hook content：Webhook agent turn 标记 provenance，默认包装为 external-content fence；外部内容不能获得“job 指令优先/自删除” trusted suffix。src/cron/isolated-agent/run.ts:514-524、src/cron/isolated-agent/run.ts:967-1011
  4. Inbound hook auth：独立 token、constant-time compare、每 client 20/60s 失败限流、query token 拒绝、agent/session allowlist。src/gateway/server/hooks-request-handler.ts:40-42、src/gateway/server/hooks-request-handler.ts:178-214、src/gateway/server/hooks-request-handler.ts:270-335
  5. Webhook outbound：只允许 http(s)，经过 SSRF guard，URL 日志去 userinfo/query，token 由专属 secret owner提供。src/cron/webhook-url.ts:1-16、src/gateway/server-cron-notifications.ts:199-249
  6. Plugin hook：普通 plugin 不能凭 hook 增加 host 未提供的工具；conversation access/prompt injection 还需显式 operator config。docs/plugins/hooks.md:395-420、docs/plugins/hooks.md:601-620

11. 失败、恢复与兼容

故障/现象即时行为状态影响恢复
Gateway 离线时间计划不运行。nextRunAtMs 保留。启动 catch-up；非 agent 有界立即执行，agent 延迟。
重启时 queued marker清除，不记 run。释放 reservation。重新参与 due/catch-up。
重启时 running marker从 finalized ledger 恢复，否则 error/interrupted。不盲目 replay side effects。recurring backoff；at disable。
连续 execution error递增 counter，套 5 级 backoff。nextRunAtMs 取自然 schedule 与 backoff floor 较晚值。成功清零。
连续 schedule compute error第 3 次自动 disable 并 enqueue system event。无 next run。修表达式后显式 enable。
Trigger fire=falsequiet tick。state/counter 写入；无普通 run history。下个 schedule 再评估。
Task ledger 写失败warning。Cron job/run 仍完成。以 Cron state/history 为准；maintenance 可 reconcile。
Heartbeat cron/request busyskipped。busy attempt 不污染 cooldown。wake layer 约 1s 重试。
Hook handler timeoutInternal/Gateway shutdown按预算继续；typed plugin停止等待。plugin work可能后台继续。plugin 自管 cancellation；不要假设 timeout=cancel。
Completion webhook 失败10s abort/SSRF warning。已提交 run 不变，无 outbox。下次 run 再发；需要可靠交付时建设 owner-owned durable delivery。

15. 设计权衡与已知限制

选择收益成本/限制重新评估条件
Gateway 内 scheduler + SQLite部署简单、事务与 session/agent 紧密集成。Gateway 离线不执行；无 active-active。需要多节点 HA/全局时钟。
60s timer clamp处理 sleep/clock jump、修复 schedule drift。每分钟 maintenance wake。平台提供可靠 durable timer。
执行前 durable reservation避免 timer/manual/reload duplicate。重启需区分 queued/running 与 ledger terminal。引入外部 transactional queue。
Heartbeat 与 Cron 分离巡检可聚合，精确任务可独立 retry。用户易混淆 cadence 与 schedule。产品需要统一但不丢语义的编排层。
Hook 多模型Operator script、HTTP ingress、typed middleware 各适合其职责。术语与失败语义复杂。公共接口能统一且不牺牲 trust boundary。
Completion webhook best-effort不拖慢/回滚已完成 run。没有 outbox、重试或 exactly-once。Webhook 成为不可丢业务事实。
关键设计判断：“自动化”不是单一队列。计划的权威事实在 Cron，执行投影在 Task Ledger，周期判断在 Heartbeat，外部/内部扩展在不同 Hook，网络回调只是 delivery。把它们压成一个状态机会丢失 owner、retry 和信任边界。
