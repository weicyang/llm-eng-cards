1. 模块定位

Node 使用 Gateway WebSocket 协议中的 role: node 连接。连接帧可声明 caps、commands、permissions 与设备证明，但这些字段只描述候选表面；Gateway 先完成 device pairing，再单独持久化 node capability surface approval，并在每次 invoke 前重算命令策略。证据：packages/gateway-protocol/src/schema/frames.ts:31-72、src/infra/node-pairing.ts:1-7、src/gateway/node-connect-reconcile.ts:16-29。

边界本模块负责委托或明确不负责
连接身份Node role、签名设备身份、device token、pairing generation 与当前连接绑定。握手密码学与协议版本属于 Gateway Protocol；Node 声明不能自行授权。
能力批准把声明的 capability/command/permission 与已批准表面求交；扩大权限时生成新 pending request。OS 权限由设备平台决定；批准记录不能让未授权的 camera/location API 成功。
调用转发node.invoke 的 scope、generation、allowlist、plugin policy、路由、timeout、progress/result。真实 camera/screen/location/exec/MCP 副作用由目标 App 或 Node Host 执行。
离线恢复iOS APNs wake、有限重连等待、foreground pending queue、失效代际取消。不是任意平台通用的 durable job queue；普通断线 invoke 不保证跨重启 exactly-once。
Operator UICompanion App 可另建 operator session 用于聊天、配置、审批和状态。Operator session 不因此拥有 node capability；iOS 明确使用双 WS session。
Host 生命周期Headless Node Host 可作为独立用户服务运行。Gateway daemon 与 Node Host daemon 是两套 service identity、日志和重启生命周期。
章节边界：第 5 章应展开 connect challenge、device proof、Role/Scope；第 13 章应展开 exec approval 与 sandbox。本章只跟踪 Node capability approval、invoke transport、平台权限与宿主生命周期。

3. 核心概念与术语

Node role协议身份，允许 node-only RPC，例如 progress/result/event；它不是 Agent persona，也不是 operator scope。
Device pairing证明“这把设备公钥可连接此 Gateway”；Node capability approval 另行证明“这台已配对设备可暴露哪些能力”。
Declared surface当前连接声明的 caps/commands/permissions；用于可用性与升级检测，不是最终授权。
Approved surface持久化在 paired device 的 node surface；重连时与声明求交，扩大时需要重新批准。
Pairing generation由持久 identity + approved surface 推导的代际。批准、撤销或升级改变代际，使旧连接、wake 和 invoke lease 失效。
Capability / Command / PermissionCapability 是能力族；Command 是可调用 wire 名；Permission 是设备观察到的 OS 权限布尔值。三者不能互相替代。
Operator session面向 chat/config/approval 的控制连接。iOS 的 operator 与 node 是同一 App 的两条独立 WS session。
Headless Node Host无 GUI 的 TS runtime，重点提供 system.run/which、文件、browser proxy、plugin/MCP；不是第二个 Gateway。
Pi / Cell 纠错：当前主链没有“Gateway-Pi 云端大脑 + Cell 本地肢体”、通用 venv Cell Isolation、环境快照恢复或任意 Pi 故障转移。Built-in Agent Runtime 是 OpenClaw；Node 是受配对、批准、allowlist 和本地权限共同限制的设备能力宿主。证据应从 role: node、node.invoke 与当前 sandbox backend 出发，不能从历史命名反推实现。

5. 完整运行流程

5.1 成功路径：配对、批准、调用、进度和终态

Node connect(role=node, device proof, caps, commands, permissions) → device pairing 认证设备 → 将声明的 surface 与已存批准求交 → 首次/新 surface 创建 node.pair pending request → operator 以所需 scope 批准 → 持久化 nodeSurface 并旋转 pairing generation → 活动 session 缩窄为 approved ∩ declared Agent/Operator node.invoke(nodeId, command, params, idempotencyKey) → schema + operator scope → 捕获 pairing generation → 解析当前连接 → command allowlist + 已声明命令检查 → system.run sanitizer / plugin node policy → node.invoke.request event → node 执行本地 permission/feature 策略 → 零个或多个有序 node.invoke.progress → node.invoke.result → Gateway 解析原始请求
  1. 声明不授予权限。未配过 node surface 时 effective caps/commands 为空；pending request 保存候选表面。src/gateway/node-connect-reconcile.ts:149-173
  2. Pairing 批准与命令风险匹配。普通声明命令需要 pairing/write；pairing-admin surface 包含 direct-invoke admin-only 集合、system.run* 与 system.execApprovals.*，需要 pairing/admin。缺 scope 时不修改记录。该集合比直接 node.invoke 的 admin-only 集合更宽。src/infra/node-pairing.ts:531-556、src/infra/node-pairing-authz.ts:15-34
  3. 批准旋转代际。持久化 node surface 后清理旧 generation bins，并只在精确旧 lease 仍成立时原位更新 live session。src/infra/node-pairing.ts:558-595、src/gateway/server-methods/nodes.ts:1142-1195
  4. 调用前后都复核。Gateway 在 wake 前捕获 config/generation，wake 后与 dispatch 前再次检查当前 config、allowlist、connId 与 generation，避免 reload 反向授予或撤销后继续执行。src/gateway/server-methods/nodes.ts:1636-1655、src/gateway/server-methods/nodes.ts:1766-1794、src/gateway/server-methods/nodes.ts:1874-1919
  5. 进度有序有界。Node Host 把 UTF-8 输出切成最多 16 KiB chunk，seq 单调递增；空 chunk 可作为 idle heartbeat。Gateway 只接受匹配 node/connection 的活动 invoke。src/node-host/node-invoke-progress.ts:5-15、src/node-host/node-invoke-progress.ts:49-95、src/gateway/server-methods/nodes.handlers.invoke-progress.ts:10-46
  6. 终态只结算一次。Result 包含 ok、payload/payloadJSON 或 error；超时后晚到 result 返回 ignored，不重新打开已结算请求。src/gateway/server-methods/nodes.handlers.invoke-result.ts:30-77

5.3 恢复路径：iOS 离线唤醒与有界重连

node.invoke 未找到当前 generation 绑定的 session → APNs 后台唤醒（去重/节流） → 等待 3 秒，每 150ms 轮询 → 仍离线且 wake 路径可用 → 强制第二次 wake → 等待 12 秒 → 仍离线 ├─ 可能时发送节流的可见 reopen 提醒 └─ 返回 UNAVAILABLE / NOT_CONNECTED → 若 pairing generation 在任何处变化：中止 lifecycle

重连预算是源码常量，不是无限等待：第一段 3 秒，第二段 12 秒，轮询 150 ms。Wake state 按 nodeId + pairing generation single-flight，并在 pairing mutation 时 abort。证据：src/gateway/node-wake-state.ts:9-16、src/gateway/node-wake-state.ts:73-99、src/gateway/node-wake-state.ts:115-166；编排：src/gateway/server-methods/nodes.ts:1652-1758。

若 iOS 已连接但明确返回 NODE_BACKGROUND_UNAVAILABLE，camera/screen/talk 或 plugin 声明的 foreground-only command 可进入有 TTL、容量和 generation 绑定的 pending action；Node 回到前台后 pull/ack，并再次按当前声明与 allowlist 过滤。证据：src/gateway/server-methods/nodes.ts:335-365、src/gateway/server-methods/nodes.ts:616-656、src/gateway/server-methods/nodes.ts:1928-1993。

10. 安全与信任边界

  1. 身份与能力分离。Device pairing 保护连接身份；Node surface approval 保护 caps/commands/permissions。两个 requestId 可以不同。docs/cli/node.md:200-235
  2. 最小交集。重连只启用 approved ∩ declared；权限丢失会缩窄，新增 true permission 才触发升级。src/gateway/node-connect-reconcile.ts:55-91、src/gateway/node-connect-reconcile.ts:176-242
  3. 危险命令需要 arm。camera snap/clip、screen record、computer.act、mobile UI 与写操作不会仅因平台默认自动可用；config allow 与 deny 仍控制 invoke。src/gateway/node-command-policy.ts:102-114、src/gateway/node-command-policy.ts:424-467
  4. system.run 双重审批。Gateway 清洗 approval 字段并绑定真实 approval；Node Host 还用本地 exec policy/approval plan 决定执行，不接受 write-scoped caller 注入“approved”。src/gateway/node-invoke-system-run-approval.ts:240-243、src/node-host/invoke.ts:727-837
  5. 平台权限是最终门。iOS 声明当前 camera/location/screen 等权限；Android 在 foreground/availability 后才 dispatch；macOS TCC-sensitive 操作留在 app-owned native surface。
  6. MCP 不绕过 Node policy。mcp.tools.call.v1 必须被 Node 声明并批准/allowlist；Node Host 再按 server/tool schema、timeout 和 result size 处理。src/gateway/node-command-policy.ts:78-95、src/node-host/invoke.ts:688-690、src/node-host/invoke.ts:977-1014

变更目标正确所有者表面通常同步修改必要证明

新增 Headless commandPlugin Node Host registration 或 src/node-host/ 的通用核心能力manifest/availability、pairing surface、invoke handler、docs。Node-local policy、disconnect、payload bounds。
发布 Node plugin toolPlugin public SDK node-host descriptorcommand approval、tool schema、inventory update。Node 断连即从新 Agent run 消失；不能绕过 effective tool policy。
接 Node-hosted MCPnodeHost.mcp.servers + mcp.tools.call.v1server lifecycle、tool descriptors、result normalization。command 已批准、server unavailable、timeout、size truncation。
改变 pairing surfacenode-connect-reconcile.ts / node-pairing.tsgeneration、pending UI、required scopes、migration。缩窄不升级、扩大必升级、竞态 cleanup claim。
改变离线行为Gateway node wake owner + iOS push ownerthrottle、generation cancellation、pending action。有界等待、无 push、stale registration、重配中止。

禁止的捷径

  • 不要把 caps、platform label、已配对或 OS permission 单独当成授权。
  • 不要把 system.run 暴露在 generic nodes invoke 来绕过 exec tool 与 approval plan。
  • 不要让 App worker 建第二个 Gateway node identity；macOS worker 明确由 App bridge 代理。
  • 不要把 Node Host daemon 与 Gateway daemon 合并启停；它们可能在不同机器、不同 service owner 下运行。
  • 不要新增无界 progress/media/MCP payload；大媒体走专用 action 和 sanitizer。
  • 不要恢复 Pi/Cell legacy 名称作为新 public runtime contract。

15. 设计权衡与已知限制

问题当前选择收益成本/失败模式重新评估条件
跨设备执行单 Gateway 控制面 + 受配对 Node。Agent/Session 集中，设备权限本地化。Gateway 可用性是控制平面单点；Node 断线不可执行。需要多控制面一致性或离线自治。
授权表达device pairing、surface approval、allowlist、OS permission 分层。最小权限、可撤销、平台真实。Operator 需理解多个 pending/denied 状态。可在不混淆所有权的前提下提供统一 explain UI。
移动后台限制APNs wake + 有界等待 + foreground queue。符合 iOS 生命周期，不伪造后台能力。不能保证立即执行；APNs/用户 reopen 不确定。平台提供更可靠的受控后台执行契约。
Headless 与 App 共用共享 TS runtime，macOS 由 App-owned worker bridge。复用 system/MCP/plugin 行为并保留 TCC owner。bridge 与 native/worker inventory 协调复杂。原生平台能安全承载全部 headless 能力。
Invoke durability连接内 pending invoke；非通用 durable queue。协议简单，避免未知副作用重放。断线后调用失败，caller 必须判断能否重试。某命令族定义了 owner-owned idempotent durable ledger。
当前限制：Node 平台能力不对称。iOS 不实现 system.run；Android 设备能力丰富但受 foreground/OEM 权限限制；macOS 可借 App worker 与 TCC 提供最宽表面；Headless Host 重点是系统、文件、browser、plugin/MCP。不能把某个平台测试通过写成所有 Node 的统一能力保证。
