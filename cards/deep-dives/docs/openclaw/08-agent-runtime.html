1. 模块定位

“Agent Runtime”不是单一循环，而是三层所有权：Gateway/CLI 入口准备与接纳；OpenClaw Embedded 外层恢复循环；@openclaw/agent-core 内层模型/工具循环。Harness 决定具体执行 Runtime，Channel delivery 仍由 OpenClaw 所有。证据：src/gateway/server-methods/agent-run-handler.ts:29-101、src/agents/embedded-agent-runner/run-loop.ts:56-170、packages/agent-core/src/agent-loop.ts:267-450。

层负责明确不负责
Gateway / CLI参数校验、scope、session/route、idempotency、admission、异步执行、等待/取消。不实现 provider tool loop。
Agent 命令session work admission、model/harness/auth plan、delivery context、restart recovery claim。不直接实现 transport stream parser。
嵌入式外层循环prepared runtime、Harness、lanes、locks、Prompt assembly、fallback、Compaction、retry、terminal shaping。不拥有 Channel SDK 或外部平台发送。
agent-core 内层循环LLM request、assistant stream、Tool validation/execution、steer/follow-up、Agent 事件。provider-agnostic；runtime stream function由 host 注入。
Harness一次 prepared turn 的具体执行和 native runtime 契约。不自动获得 OpenClaw 所有 hook/tool/context 等价性。
排除：第 7 章解释 Session key/SQLite；第 9 章解释 provider/model/auth fallback 候选；第 10 章解释 Context Engineering；第 12/13 章解释 Tool 能力和审批/沙箱。本文只说明这些输入如何进入并结束一次运行。

3. 核心概念与术语

Run一个 runId 下从接纳到统一 terminal outcome 的执行；可含多个 recovery/fallback attempts。
Attempt一次具体 Harness/provider/model/auth 组合的执行；可能因重试或 Compaction 被下一次替代。
Harness实现 Agent Runtime 的插件/内建契约。内建 openclaw Harness 调用 runEmbeddedAttempt。
外层恢复循环跨 Attempt 保存 replay safety、Compaction 计数、usage、profile/failover 和终态状态。
内层工具循环一次 Agent.prompt/continue 内不断执行 model→tool batch→toolResult→model，直到无 tool/queue。
流桥把 agent-core/Harness 事件投影为 assistant/tool/thinking/lifecycle、block reply 和最终 payload。
回复整形去标签、去 reasoning、处理 directive/media、抑制 NO_REPLY 和 message-tool 重复。
终端结果completed/hard_timeout/timed_out/cancelled/aborted/blocked/abandoned/failed 的统一粘性结果。

5.2 Inner Tool Loop 与并行/串行语义

assistant 消息 stopReason=toolUse → 按来源顺序收集 toolCall 块 → 解析延迟 tools + 准备参数 + schema 校验 + beforeToolCall → 若 config 为 sequential 或任一解析出的 tool 的 executionMode=sequential： prepare → execute → afterToolCall → end → result，逐个执行 else: 准备阶段串行执行 被允许的调用并发执行 tool_execution_end 遵循完成顺序 toolResult 消息按 assistant 来源顺序发出 → 追加已排序的 toolResults → 下次模型调用

一个 batch 中只要存在一个强制 sequential tool，整个 batch 都串行。Parallel 不是“所有 preflight 也并行”：工具解析、参数准备、校验和 policy 顺序执行，只有通过准备的执行函数并发；abort 后尚未启动的 prepared tool 不会启动。证据：packages/agent-core/src/agent-loop.ts:563-611、packages/agent-core/src/agent-loop.ts:636-800、packages/agent-core/src/agent-loop.ts:1008-1067；契约：packages/agent-core/src/types.ts:27-35、packages/agent-core/src/types.ts:255-264、packages/agent-core/src/types.ts:458-488。

5.4 Compaction、Retry 与恢复

attempt 终态/异常 → 归一化 attempt + 重放安全 → 恢复决策 ├─ context 溢出 │ ├─ 压缩活跃 Transcript（最多 3 次外层 attempt） │ ├─ 可选 tool-result 截断 │ └─ 重建当前/已压缩 prompt → 重试 ├─ 可压缩压力下运行超时 │ └─ 有界超时压缩恢复 → 重试 ├─ auth/限流/idle 超时 │ └─ 有界 profile/同模型重试或模型回退 ├─ 重放安全的 Codex app-server 失败 │ └─ 至多一次恢复重试 └─ 不可恢复 / 副作用不安全 → 暴露 blocked/failed/timeout 终态 → 每次重试都重新进入完整的预备 Attempt 循环

外层循环 的 attempt 上限由 profile candidate 数计算；context recovery state 跨 attempt 保存 overflow/timeout Compaction 次数和 tool-result truncation 是否已尝试。Overflow 最多三轮；耗尽后返回 blocked 指引，不偷偷换 sessionId。证据：src/agents/embedded-agent-runner/run-loop.ts:170-187、src/agents/embedded-agent-runner/run-loop.ts:274-371；src/agents/embedded-agent-runner/run/context-recovery-state.ts:3-11；src/agents/embedded-agent-runner/run/overflow-context-recovery.ts:41-59、src/agents/embedded-agent-runner/run/overflow-context-recovery.ts:176-207、src/agents/embedded-agent-runner/run/overflow-context-recovery.ts:437-456。

Compaction retry 会清空 attempt presentation buffer/tool summary，保留已提交副作用 truth；否则重试可能重复投递或把 mutating failure 当成功。证据：src/agents/embedded-agent-subscribe.ts:1274-1325。

5.5 统一终态与 agent.wait

生命周期/去重观测 → 构建终端结果 hard timeout > blocked > aborted > cancelled > abandoned > wait timeout > failed > completed → 合并粘滞结果 cancelled 始终粘滞 hard_timeout 粘滞，除非更晚的 completion 证明 endedAt ≤ timeout endedAt → 按 runId/source 缓存 → agent.wait: 终态快照 → 返回 截止前无快照 → 仅等待超时（底层运行继续）

agent.wait 默认 30 秒，只等待终态，不取消 run。找不到 snapshot 时根据 Gateway 活动注册给出 gateway_draining 或 queue timeoutPhase；这与 provider hard timeout 不同。证据：src/gateway/server-methods/agent-wait.ts:10-62。

10. 安全与信任边界

  1. Ingress 权限在 Runtime 前。Gateway schema、Role/Scope、session owner、model override 权限和 idempotency 在模型调用前完成。src/gateway/server-methods/agent-run-handler.ts:29-101
  2. Harness 选择 fail-closed。显式 Runtime 不可用时不回落到能力不同的 OpenClaw；只有 auto 未 claim 才 compatibility fallback。docs/concepts/agent-runtimes.md:129-155

  5. 跨 Runtime fallback 看副作用。command-rpc 已提交媒体等副作用后禁止 fallback；replay state 缺证据时按潜在副作用处理。src/agents/embedded-agent-runner/run-entry.ts:189-276、src/agents/embedded-agent-runner/replay-state.ts:1-50
  6. Completion handoff 不继承 requester tools。冻结子 Agent 输出时禁用工具，防止把文本当作新特权指令。src/agents/command/attempt-execution.ts:517-525
  7. Stream/Reply 脱敏与分层。reasoning、final tags、directives、NO_REPLY、message-tool-only 在 bridge/delivery 层过滤；审计不复制 prompt/tool args/result。src/agents/embedded-agent-subscribe.ts:808-1021、docs/concepts/agent-loop.md:118-121

12. 可观测性与排障

现象先检查可能原因修复方向
RPC accepted 但没有 finalrunId 的 lifecycle、agent.wait、session lane仍排队、provider/tool 长运行、wait-only timeout再次 wait；不要把 wait timeout 当 run timeout
模型输出有 delta 但最终失败终态 stopReason/timeoutPhase/providerStartedpartial 后 hard timeout/abort/compaction failure以统一 terminal 为准，不以最后 delta 判成功
Tool 看似“乱序”start/end 与 toolResult 两种顺序parallel end 按完成序，result 按模型源序消费正确事件语义，不自行重排 Transcript

反复 Compaction/retryoverflow diag attempt、token budget、oversized tool result、replayInvalidContext 仍超限、summary 无效、Tool 输出过大检查 3 次 cap 和 blocked 指引；必要时 /reset/更大模型

最终回复重复message tool 回执、block 回复、assistant 文本bridge 未识别 committed send 或重试 presentation state保留 delivery evidence；勿只按文本 pending 推断

关键事件面：lifecycle 判断 run；assistant/thinking 看流；tool 看执行；lane wait/stage timing 看排队和启动；overflow/compaction diag 看恢复。官方 docs/concepts/agent-loop.md:112-146 给出面向运维的事件和 stuck 分类。

15. 设计权衡与已知限制

问题当前选择收益成本/限制重评条件
恢复能力外层恢复 + 内层工具循环Context/auth/provider 恢复不污染核心 Tool 状态机层次多、终态需统一所有 Runtime 原生提供同等恢复协议
Runtime 可插拔Harness 契约 + 预备计划OpenClaw/Codex/ACP/CLI 可共享入口和投递能力 parity 不是自动的可形成版本化统一 runtime protocol
Tool 性能默认并行，任何 sequential tool 强制整批串行安全默认明确，结果顺序稳定一个串行 tool 降低整批并发可证明依赖图级调度不会破坏 policy/order
错误恢复有界 retry/Compaction/fallback瞬时故障自动恢复，阻止成本失控计数和 replay safety 复杂provider 提供事务化 resume/side-effect receipt
事件终态多来源 snapshot + sticky merge + grace兼容 lifecycle、dedupe、chat 与 retry进程内 cache，推导较复杂Gateway protocol 拥有单一耐久 run ledger
流式体验实时 delta，但最终以 lifecycle 为准低延迟展示且终态正确partial 可能随后失败/被抑制客户端只消费事务化 committed chunks
当前限制：run-loop.ts、agent-loop.ts、embedded-agent-subscribe.ts 都是大型 owner 文件。拆分应围绕明确阶段/状态机，而不是复制控制流。Native Harness 的工具、Hook、Compaction 和 canonical thread owner 可能不同；不能把 OpenClaw embedded 行为写成所有 Harness 的保证。
