一句话目标：Tool 是模型可调用的执行契约，Skill 是按需读取的操作知识，Plugin 是 Host 进程加载并经公共 SDK 注册能力的代码包，MCP 是把外部 server 的 tools/resources/prompts 通过 transport 发现并物化为 plugin-scoped Tool 的协议；四者最终都不能绕过 OpenClaw 的 effective policy。

1. 模块定位

对象本模块负责明确不负责
Tool surface装配 core/shell/channel/plugin/MCP/LSP tools，应用策略，规范 Schema，挂 hook 与 abort。不替代 sandbox、exec approval 或 Node permission 的执行期判定。
Skill surface多层发现、同名覆盖、eligibility、agent filter、snapshot、prompt catalog 与 read-on-demand。Skill 文字不授予 Tool、文件或 shell 权限。
Plugin surfacemanifest-first discovery、验证、加载、registry registration、provenance、生命周期与故障隔离。Core 不知道具体 bundled id 的产品策略；plugin 不得深导入 core internals。
MCP surfacestdio/SSE/Streamable HTTP 连接、catalog、命名、物化、调用、资源/提示工具、最终 policy pass。外部 server 输出不可信；MCP 配置不等于已经连接或获权。

3. 四个概念与进入 Context 的方式

概念精确定义进入模型 Context执行/生命周期
Toolname + description + JSON Schema + execute，可带 executionMode 与 plugin metadata。最终可见 Tool 的名称、描述、Schema 作为隐藏 tool schema 发送给模型。模型发 tool call 后由 runtime dispatch；hook、approval、sandbox 在执行路径继续约束。
Skill目录中的 SKILL.md，frontmatter 描述用途/eligibility，正文教授如何使用已有能力。先注入紧凑 XML：name、description、location、version；匹配任务时模型用 read 加载正文。通常无代码执行；slash command 可确定性转发到 Tool。
Pluginmanifest 描述、Host 加载的代码模块，经 OpenClawPluginApi 注册能力。Plugin 注册的 Tool 进入 schema；prompt hook/skill/memory supplement 可进入文本 Context。metadata process-stable；代码/安装变化通常要求 Gateway restart。
MCPModel Context Protocol server 的 tools/resources/prompts，经 stdio/SSE/Streamable HTTP 连接。server catalog 物化为 provider-safe Tool；resources/prompts 变成显式 utility tools，不自动灌入 prompt。session-scoped runtime 连接并调用；输出标为 untrusted。

Skill prompt contract：src/skills/loading/skill-contract.ts:38-64；MCP 物化：src/agents/agent-bundle-mcp-materialize.ts:246-405。

关键区分：“出现在 catalog/manifest/Skill 中”不等于“模型可见”；“模型可见”不等于“执行被允许”；“调用被允许”也不等于“无审批或在 Host 上执行”。Policy、sandbox、approval 和 transport trust 是独立门。

5. 完整运行流程

5.1 成功：Tool 组装到执行

  1. Attempt 从可信 run facts 解析 capability profile：agent、provider、session、group、sender、sandbox、runtime allowlist。src/agents/agent-tools.ts:481-544
  2. 按 construction plan 创建 core、shell、channel 与 plugin tools；client caps 和 plugin policy 先限制可物化项。src/agents/agent-tools.ts:637-650、src/agents/agent-tools.ts:859-904
  3. message/provider 兼容过滤后进入完整 policy pipeline；owner-only、subagent、runtime 与 inherited 层继续收紧。src/agents/agent-tools.ts:1067-1137
  4. 授权后的 Schema 按 provider 规范化，随后挂 before_tool_call、approval、abort 与 outcome observers。src/agents/agent-tools.ts:1164-1227
  5. 最终 tool schemas 进入模型；模型调用时 execute 仍受 hook/approval/sandbox/transport 约束，结果回到下一模型 turn。

5.2 完整 Effective Policy 顺序

0. capability/materialization 门控（plugin enable/deny、client caps、MCP server filter） 1. profile 2. provider profile 3. global tools allow/deny 4. global provider allow/deny 5. agent tools allow/deny 6. agent provider allow/deny 7. group policy（server 派生的 group identity） 8. sender policy 9. sandbox tools.allow/deny 10. gateway sender owner-only deny 11. subagent policy 12. runtime tools.allow（并形成可继承权威） 13. inherited parent policy 14. delegation capability / 运行特定结构门控 15. MCP/LSP appended tools 再执行 final pass： profile → provider profile → global → global provider → agent → agent provider → group → sender → sandbox → subagent → inherited 16. provider schema 兼容性隔离

每一层都是进一步过滤，不是后层覆盖前层。Plugin tool grant 只能把已授权 runtime plugin tool 加入候选，不能推翻显式 deny。MCP/LSP 因为在 core pipeline 后追加，必须走第二次 final pass；它只过滤新增集合，避免重跑导致 wrapped plugin metadata 丢失。src/agents/agent-tools.ts:1086-1137；src/agents/embedded-agent-runner/effective-tool-policy.ts:25-119

5.3 成功：Skill 发现与渐进披露

extra/plugin（最低） → bundled → managed ~/.openclaw/skills → personal ~/.agents/skills → project /.agents/skills → workspace /skills（最高） → 同名 Map 覆盖 → metadata eligibility（os/bins/env/config/always） → 有效 agent allowlist → prompt 可见性 → snapshot + 紧凑 XML → 模型看到 identity → 匹配任务使用 read(SKILL.md) → tool 在独立 policy 下执行

优先级实现：src/skills/loading/workspace.ts:1181-1274；filter：src/skills/loading/workspace.ts:199-225；prompt：src/skills/loading/skill-contract.ts:38-64；snapshot refresh：src/skills/runtime/session-snapshot.ts:54-109。

5.4 成功：Plugin manifest 到 runtime

  1. Discovery 从 configured/workspace/global/bundled roots 找 candidate；manifest-first 读取 metadata、schema、compat 和 ownership，不执行 runtime。src/plugins/manifest-registry.ts:973-1077
  2. 校验 min host/plugin API、root containment、reserved/case-fold id 与重复 provenance；不合格 candidate 只产 diagnostic/skip。src/plugins/manifest-registry.ts:1078-1135、src/plugins/manifest-registry.ts:1173-1255
  3. Loader 创建 registration transaction，依 activation plan 逐个加载 module 并注册；失败可 rollback global side effects。src/plugins/loader-runtime-load.ts:80-165、src/plugins/loader-runtime-load.ts:220-225
  4. 成功 registry 被 pin/activate；tool、hook、service、Gateway method 等供 runtime 使用。代码或 install record 变化要求 restart/owner refresh 才成为 live generation。

5.5 恢复：MCP 单 server 失败

Session runtime 解析 stdio/SSE/Streamable HTTP，最多并发连接 6 个 server。单 server connect/list 失败会关闭其 client/transport、记录脱敏 diagnostic 并返回空 tool entries，其他 server 继续；连续 3 次 tool/protocol failure 后该 server 暂停 60 秒。Tool list changed 只使 session catalog 失效，下一次 discovery 重新列举。src/agents/agent-bundle-mcp-runtime.ts:80-85、src/agents/agent-bundle-mcp-runtime.ts:422-455、src/agents/agent-bundle-mcp-runtime.ts:592-815

5.6 拒绝：不可信扩权

Caller 提供的 groupId 必须与 session/spawnedBy 推导出的 group 候选匹配，否则丢弃；workspace/global 非 bundled plugin 若无 provenance 会警告；MCP stdio 环境过滤 loader/interpreter 注入变量；外部 server 的 metadata、resource、prompt 与 result 均视为不可信。src/agents/agent-tools.policy.ts:273-315；src/plugins/loader-provenance.ts:287-325；src/agents/mcp-config-shared.ts:13-43、src/agents/mcp-config-shared.ts:94-103

10. 安全、Provenance 与故障隔离

  1. Tool policy 是授权主线。Skill、Plugin manifest 或 MCP server 不能自授权限；deny 在所有层保持优先。
  2. 身份来自 server。group/sender/owner facts 必须来自已验证入站/session context；模型 input 不参与授权。src/agents/embedded-agent-runner/effective-tool-policy.ts:17-23
  3. Plugin 是进程内代码。不是 sandbox；安装即执行代码信任决策。非 bundled/untracked provenance 必须诊断并由 operator pin allow/install source。src/plugins/loader-provenance.ts:215-325
  4. SDK 隔离所有权。Plugin 只经公开 SDK 跨边界；Host 可替换/回滚 registration，不允许 private backdoor。
  5. MCP transport trust。stdio 继承 Gateway 进程 OS 权限，env 过滤 runtime injection；HTTP URL/header/OAuth 必须脱敏。src/agents/mcp-config-shared.ts:13-43
  6. MCP output 不可信。resource/prompt/tool result 不能作为 system authority；App-only tool 不进入 model list，App 可调工具还必须通过 final policy。src/agents/agent-bundle-mcp-materialize.ts:43-88、src/agents/agent-bundle-mcp-materialize.ts:141-158
  7. Schema quarantine。最终工具还经过 runtime/provider compatibility projection，不兼容 schema 被隔离而不是让整个 model call 失败。src/agents/embedded-agent-runner/run/attempt-bundle-tools.ts:159-205

15. 设计权衡与已知限制

选择收益成本/限制重新评估条件
Tool 与 Skill 分离执行与知识独立，知识可渐进披露。可见 Skill 可能引用不可用 Tool。需要声明式 capability dependency explain。
Manifest-first Pluginsetup/config/discovery 无需执行不可信 runtime。manifest 与 runtime 可能漂移。contract generation 能完全锁定一致性。
Process-stable metadata请求热路径稳定、低 I/O。代码/manifest 变化通常需 restart。出现有明确 owner 的安全 reload protocol。
多层 policy AND最小权限可组合、deny 稳定。肉眼难推断 effective surface。explain 工具不足以支持运维时。
MCP 物化为 Tool统一 model/runtime/policy 语义。外部命名/Schema/错误质量不受 Host 控制。协议增加更强 capability/authorization primitive。
Session-scoped MCP隔离 catalog、requester、failure 与 view lease。多 session 可能启动多个 transport。可证明安全的跨 session pooling contract。
当前限制：Plugin 仍是 Gateway 进程内代码，不提供 OS 级隔离；Skill 依赖 host eligibility，但 sandbox 内 binary 仍可能缺失；MCP server 的描述和结果不可信且质量参差；effective policy 分两次执行是因后追加 bundled tools 的现实边界，修改任一 pass 必须证明另一 pass 不漂移。
