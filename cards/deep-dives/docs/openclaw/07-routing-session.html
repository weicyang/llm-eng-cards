一句话目标：路由层把规范化 transport 身份确定性地映射到 Agent 与 session key；Session 层再把这个稳定会话桶映射到当前 sessionId、Transcript active path、外部 会话身份 和 Delivery 状态，并在 reset、并发、重启与迁移中保持所有权清晰。

1. 模块定位

路由回答“这条输入属于哪个 Agent、哪个会话桶”；Session 回答“该桶当前指向哪段模型历史、如何续接、何时换代、怎样投递和维护”。路由是纯决策面，Session 是 per-agent SQLite 持久状态面。证据：src/routing/resolve-route.ts:34-71、src/routing/resolve-route.ts:606-815、src/state/openclaw-agent-schema.generated.ts:35-184。

边界负责委托或明确不负责
Transport → Agent规范化 channel/account/peer/guild/team/roles，执行 binding tier。Channel plugin 负责生成可信 transport facts；路由不连接平台。
Agent → sessionKey按 DM scope、群组/频道、thread/topic 与 identity link 构造键。不选择模型、不执行 Agent。
sessionKey → sessionIdsession_entries 表示当前活跃映射；reset 换新 sessionId。历史 session 行和 Transcript 不因 reset 自动等同于删除。
TranscriptSQLite append-only event rows、active-path 投影、generation、索引和锁。Agent-core 解释消息和 tool loop；Session 只拥有历史事实。
外部地址会话身份 与 Delivery ledger 独立于模型 Session。Channel adapter 负责真正发送及平台 message id。
生命周期freshness、reset、archive、cleanup、migration。Gateway 只编排启动迁移和 RPC；不另建平行状态。
相邻边界：第 6 章提供规范化的 Channel ingress/delivery facts；第 8 章消费 session target 并写 Transcript；第 10 章从 active path 组装 Context；第 16 章解释 SQLite 基础设施。本文不展开平台协议、模型选择或 Tool Policy。

3. 核心概念与术语

Route binding配置中的 Agent/Channel 匹配规则。优先级由 tier 固定，不由配置顺序跨 tier 改写；同 tier 首个匹配项胜出。
sessionKey稳定会话桶标识，参与持久映射与 per-session lane；不是一次运行 id，也不是平台地址。
sessionId当前 Transcript 身份。一个 sessionKey reset 后指向新 sessionId，旧 session 可留作历史。
SessionEntrysession_entries.entry_json 的当前运行元数据；updatedAt 不等于 reset freshness。
活跃路径树状 Transcript 当前可见分支的有序投影；避免每次从全 DAG 追 parentId。
会话身份由 channel/account/kind/peer/parent/thread 哈希成 conv_... 的外部地址，与模型上下文解耦。
投递操作以 operationId 幂等记录 send/turn 的 created→queued/sent/rejected/... 状态。
归档 ≠ 重置 ≠ 删除archive 是用户搁置；reset 换活跃映射；delete 在移除行前生成并验证冷归档。

5. 完整运行流程

5.1 正常成功：Channel 输入到续接 Session

归一化 ingress 事实 → resolveAgentRoute(channel, account, peer, parent, guild/team/roles) → binding 层级选择 agent → 构建 sessionKey + mainSessionKey + lastRoutePolicy → 新鲜度读取当前 SessionEntry 生命周期时间戳 → 新鲜：保留 sessionId → 持久化 route/identity/session 元数据 → 入队 session:<sessionKey> → 获取 Transcript 写锁 → Agent 消费活跃 Transcript 路径 → 追加 user / assistant / tool 事件 → 更新当前 entry + 投递操作
  1. 输入先规范化；account 缺失成为 default，channel/Agent 结构 token 归一。src/routing/resolve-route.ts:606-627
  2. 绑定按固定 tier 决策，同 tier 使用数组 find()，因此源顺序第一个完整 scope match 胜出。src/routing/resolve-route.ts:727-812
  3. DM 根据 effective dmScope 折叠到 main 或加入 peer/channel/account；非 direct 始终隔离到 channel+kind+peer。src/routing/session-key.ts:191-243
  4. 当前 entry 通过 lifecycle 时间戳判定 fresh；无自动策略时继续原 sessionId。src/config/sessions/entry-freshness.ts:53-109
  5. Agent runner 先进入 per-session lane，再进入全局 lane；Transcript 写入再受跨进程 lock 保护。src/agents/embedded-agent-runner/run-orchestrator.ts:124-181、src/agents/session-write-lock.ts:889-1014

5.2 九级决策与同级冲突

级matchedBy必须满足冲突规则
1binding.peer当前 peer 精确匹配及全部附加 scope同 tier 按原始 bindings 源顺序，首个完整匹配胜出；更早配置不跨越更高 tier。
2binding.peer.parentthread 当前 peer 未命中后，父 peer 精确匹配
3binding.peer.wildcardpeer kind 匹配且 id=*
4binding.guild+rolesguild 匹配且成员拥有任一配置 role
5binding.guildguild 匹配且规则无 role 约束
6binding.teamteam 匹配
7binding.account具体 account（缺省只代表 default）
8binding.channelaccountId=* 的 channel fallback
9default无 binding 命中选择配置 default Agent；未知 binding Agent 也回退到现存 default。

术语校正：源码数组包含八个显式 binding tier；“九级”是把最终 default fallback 计为第九级。不要误写成九种 binding。

5.3 拒绝/提前结束

格式错误/未授权目标 ├─ 无效 Gateway 参数 → INVALID_REQUEST ├─ 显式 agent 与限定 sessionKey 不一致 → CLI 拒绝 ├─ 过期期望 sessionId / 并发重置 → 过期快照或会话已变更拒绝 ├─ 已归档会话 → work 准入拒绝 ├─ delivery operationId 以不同不可变输入复用 → 输入错误 └─ 写锁超时/过期活跃所有者 → 会话忙；无竞争写入

CLI target guard：src/commands/agent-via-gateway.ts:332-357；work admission：src/agents/agent-command.ts:170-220；delivery idempotency：src/config/sessions/conversation-delivery-store.ts:185-215；lock failure：src/agents/session-write-lock.ts:927-1064。

5.4 Reset、恢复与迁移

下一个 ingress → 解析重置策略 + 生命周期时间戳 → 过期/手动重置 → 准备新 sessionId + 干净的仅轮换元数据 → 在写入所有者下比较 revision → 事务更新活跃会话 entry → 旧会话/Transcript 保持为历史 → 可选已校验归档 / 近期重放 → 新运行使用新活跃目标 历史遗留 startup/doctor → 检查 sessions.json + JSONL → 导入行/事件到每 agent SQLite → 重建 active/index 投影 → 归档已导入的热 JSONL + 写入 manifest → 运行时仅读取 SQLite

Reply initialization使用 revision/CAS 语义；若 snapshot 已被并发 reset/rebind 改变，返回 stale-snapshot，而不是覆盖新状态。src/config/sessions/session-accessor.reset.ts:192-330

遗留迁移 Gateway 启动和 Doctor 负责导入；legacy reader 只用于已发现、尚无 SQLite 的只读兼容/离线维护，不是稳定热路径。src/config/sessions/legacy-store-readonly.ts:1-28、src/gateway/server-startup-session-migration.ts、src/commands/doctor-session-sqlite-migration-run.ts。

9. 并发、性能与资源

机制真实语义开发含义
Binding 索引/缓存先按 channel/account 建索引；resolved route cache 最多 4000 key，binding account cache 最多 2000，超限整体清空后保留当前项。不要在 hot path 重扫全部 bindings；identityLinks/debug 时跳过 route cache。
每会话 lanesession:<sessionKey> 默认 maxConcurrent=1，串行同会话 runs。防止同一上下文并行 tool/session race。
全局 lane主 Agent 全局并发由配置解析；Cron 内层映射到 cron-nested 防自锁。session lane 解决同会话一致性，global lane 提供系统总量背压。
SQLite 写入器per-agent 写入经 exclusive writer queue；transaction callback 同步提交。异步规划/归档在 transaction 外完成，提交时重读权威行。
Transcript 锁SQLite marker 映射为 session-locks/<agent>-<session>.sqlite-transcript.lock；带 PID/starttime/stale 检测。覆盖跨进程和绕过 lane 的写者；默认不可重入。
活跃路径预投影 active event/message 顺序。普通 history/context 不必遍历整棵 DAG。
物理磁盘预算统计 DB、WAL 和 sessions 资产；checkpoint/vacuum 后按冷归档、历史 session 顺序回收。不以 JSON 字符数估算物理空间。

10. 安全与信任边界

  1. DM 默认有连续性风险。main 让所有 DM 共用上下文；多用户入口应显式选择隔离 scope。docs/concepts/session.md:28-59
  2. Agent-qualified key 防跨 Agent 混写。CLI 对显式 Agent 与 qualified key 不一致直接拒绝。src/commands/agent-via-gateway.ts:332-357
  3. Transport identity 与 model state 分离。delivery target 必须来自权威 route facts；native metadata 不可重定向已有 conversationRef。src/config/sessions/conversation-identity.ts:88-154、src/config/sessions/conversation-identity.ts:157-196
  4. 并发 mutation 使用 CAS。reset/entry replacement 提交前重验 sessionId/revision，避免旧快照覆盖新 owner。src/config/sessions/session-accessor.reset.ts:217-308
  5. 跨进程写 fail-closed。活 owner 的旧锁只报告而不因年龄强删；dead/recycled owner 才可回收。src/agents/session-write-lock.ts:504-648
  6. 归档路径限制。归档文件必须留在解析后的 archive directory，内容写后 readback 验证。src/config/sessions/session-accessor.sqlite-archive.ts:25-39、src/config/sessions/session-accessor.sqlite-archive.ts:79-125

会话忙lock path、PID/starttime、age、owner argv真实长写、进程退出残锁、非 OpenClaw owner先诊断；只清可证明 stale 的锁
列表没有旧 reset 历史活跃 entry 与 sessions/history/search普通列表只显示当前映射用 history/search；不要把 reset 当删除
delivery 重复或未知operationId/status/platform id/message hash重试复用错误 id 或平台确认丢失同输入复用 operationId；unknown 先对账
升级后历史缺失Doctor SQLite 检查、迁移 manifest、导入归档import 未完成或降级后未 restore按 Doctor migration/restore sequence，不手改 sessions.json

可用操作面包括 openclaw sessions --json、openclaw sessions cleanup --dry-run、openclaw doctor --session-sqlite inspect --session-sqlite-all-agents。当前环境未执行命令，因此这里只把它们作为源码/官方文档证明的接口，不声称本次现场运行成功。docs/concepts/session.md:153-160、docs/concepts/session.md:208-216。

15. 设计权衡与已知限制

问题当前选择收益成本/限制重评条件
路由可预测性固定 specificity tiers + 同级源顺序决策稳定、可诊断错误的早期同级规则会遮蔽后项规则规模需要显式 priority/冲突 lint
DM 连续性与隔离默认 main，提供更强 scope个人 Agent 跨渠道连续多用户入口需主动隔离产品默认转向共享部署
当前映射与历史entry/route/session/transcript 分表reset 不丢历史；清理可精确判断引用投影和迁移复杂可证明单表能保留相同生命周期语义
外部地址会话身份 与 Session 解耦reset 后仍可投递；地址目录不创建模型上下文需要 association 与 delivery ledger平台提供统一稳定 conversation primitive
并发lane + SQLite 写入器 + file lock 三层覆盖进程内顺序、DB transaction、跨进程旁路锁诊断和 timeout 更复杂运行时变为单写者服务且无离线/多进程写
