当前事实可选能力边界事实
一句话目标：Tool Policy 决定能力是否出现，Sandbox 决定能力在哪里运行，Elevated 只改变 exec 的执行位置，Approval 决定一次 host/node 执行能否继续；四层按顺序叠加，没有一层能替另一层授予权限。

1. 模块定位

机制回答的问题所有者明确不负责
Tool visibility / policy模型能否看到、调用某个工具？Tool assembly 与多层 allow/deny；sandboxed turn 再套 sandbox tool policy。不隔离允许工具的内部副作用。
Sandbox location允许的文件/进程工具在哪里运行？resolveSandboxRuntimeStatus() 与 backend handle。Gateway 进程始终在 host；sandbox 不认证操作者。
Elevated escape已 sandbox 的 exec 是否显式转到 gateway/node？Sender allowlist、session directive、exec target resolver。不复活被 Tool Policy deny 的 exec，不授予其他工具。
Approval这一次 host/node 命令是否满足 policy、allowlist 和人类/自动审查？执行 host 本地 approvals policy + Gateway durable operator approval。不是多用户授权边界，也不把获批命令变为只读。

证据：src/agents/sandbox/runtime-status.ts:23-94、src/agents/sandbox/tool-policy.ts:186-267、src/agents/bash-tools.exec-runtime.ts:206-275、src/agents/exec-defaults.ts:128-220。

所有权边界：Sandbox backend 提供执行与文件桥接，不决定模型工具清单；Gateway 保存可审阅的 approval 生命周期，但真正执行权仍要求 process-local live binding 与执行 host 的 policy；Node 的设备配对/命令权限属于第 15 章。

3. 核心概念与术语

Visibility工具名是否进入模型 schema。Sandbox policy 仅在 sandboxed turn 追加过滤；deny 优先，非空 allow 是封闭集合。

5. 完整运行流程

5.1 成功路径：sandboxed exec

tool 组装 → global/agent/provider policy 保留 exec → 解析 session main alias + sandbox mode → 解析有效 agent config 和 scope key → 准备 workspace / skills → backend ensure → 验证 cwd 在 backend 拥有的根目录内 → 构建 backend exec spec → ProcessSupervisor 启动 → 流式有界输出 → finalize backend token → 诊断终态事件 + 处理 session result
  1. Mode off 或 non-main 的 main session 在 backend 加载前短路；不会因配置了 SSH/OpenShell 就启动它。src/agents/sandbox/runtime-status.ts:23-94、src/agents/sandbox/context.ts:139-168
  2. WorkspaceAccess 为 none/ro 时构造独立 workspace 并复制 bootstrap/skills；rw 直接使用 agent workspace，但受保护 skills 放在单独只读 materialization。src/agents/sandbox/context.ts:76-136
  3. Remote backend 在 approval/preflight/launch 前自己验证 canonical cwd；一次性验证状态若不用会被 discard。src/agents/sandbox/backend-handle.types.ts:67-78
  4. 执行后 finalizeExec 负责 SSH session 删除或 OpenShell mirror 回传；即使进程失败也调用。src/agents/bash-tools.exec-runtime.ts:725-783

5.2 拒绝路径：visibility / location / approval

tool 被拒绝 → tool 缺失/阻断（终止） 否则请求的 host 不允许 → 执行前拒绝 否则 elevated 对该 sender 不可用 → 保持门控 / 拒绝指令 否则 host policy deny 或 allowlist 未命中 → 先注册 durable approval → 发布安全 prompt → 无路由 / deny / 格式错误 / 超时 → 终态 deny → 命令永不启动

Approval presentation 不暴露 cwd、env hash 或完整 execution binding；未授权 lookup 与不存在记录返回同样错误。解析错误、kind mismatch、禁止的 decision 会原子转成 malformed-verdict deny。证据：src/gateway/server-methods/approval.ts:65-109、src/gateway/server-methods/approval.ts:436-556；src/gateway/server-methods/approval.test.ts:371-433、src/gateway/server-methods/approval.test.ts:1449-1550。

5.3 恢复路径：超时、重启与配置变化

pending approval 过期 → SQLite status=expired, decision=deny gateway 重启 → 旧 runtimeEpoch pending rows=cancelled/gateway-restart 迟到的 UI resolve → 返回已记录的终态事实，永不重新开启权限 allow-once → live grace window 内原子 consume policy/argv/cwd/session/env/file 变化 → prepared plan 不匹配 → 拒绝执行

默认审批存活 30 分钟；resolved live entry 仅保留 15 秒用于 handoff/消费。Gateway 重启保留审计行，但取消旧 epoch 的 pending row；仅凭 durable row 无法复原 raw execution capability。证据：src/infra/exec-approvals.ts:314-320、src/gateway/exec-approval-manager.ts:30-47、src/gateway/exec-approval-manager.ts:833-868、src/gateway/operator-approval-store.ts:1166-1229。

10. 安全与信任边界

  1. Docker defense in depth：--read-only、tmpfs、--network none、--cap-drop ALL、no-new-privileges 是实际 CLI flags；Docker 上游定义它们分别约束 rootfs、网络、Linux capabilities 与提权。src/agents/sandbox/docker.ts:338-384；Docker CLI upstream：container run reference
  2. Bind 是穿透能力：source 必须绝对、默认位于 workspace roots；规范化与 existing-ancestor canonicalization 各检查一次；系统、凭证、Docker socket、reserved target 仍禁止。src/agents/sandbox/validate-sandbox-security.ts:22-76、src/agents/sandbox/validate-sandbox-security.ts:318-373
  3. SSH 自动化仍校验 host：默认 BatchMode yes、StrictHostKeyChecking/UpdateHostKeys true。OpenSSH 上游说明 BatchMode 禁用交互，strict=yes 拒绝未知/变化 host key，UpdateHostKeys 用于受信主机轮换。src/agents/sandbox/ssh.ts:595-656；OpenSSH ssh_config(5)
  4. OpenShell 是外部安全域：OpenClaw 传递 source/policy/provider/GPU flags，并使用上游 get/create/delete/ssh-config/upload/download 契约；网络/资源隔离最终由 OpenShell policy/gateway 实现。extensions/openshell/src/backend.ts:706-743；OpenShell CLI reference
  5. 审批不是认证替代品：Gateway-authenticated operator/node 是既有 trust boundary；approval 降低误执行风险。已批准命令仍拥有选定 host 的文件权限。docs/tools/exec-approvals.md:30-45
威胁模型：防御模型误操作、配置注入、路径/符号链接逃逸、命令在批准后漂移、重复/竞态决议与无 UI 超时；不承诺抵御 Docker daemon compromise、恶意 kernel、被攻陷的 SSH/OpenShell host、operator 本人、显式 dangerous override 或已挂载 host secret。Sandbox 不是完美安全边界。

11. 失败、恢复与兼容

15. 设计权衡与已知限制

选择收益成本/限制重新评估条件
Sandbox 默认 off本地个人助手低摩擦。不可信输入默认仍可触达 host 能力。产品信任模型转向多租户。
Backend-neutral handleDocker/SSH/plugin 共享 exec/fs/tool wiring。backend 特有网络/browser 能力需显式 capability。出现 handle 无法表达的隔离原语。
SSH remote-canonical无持续双向冲突、适合 offload。本地编辑不会自动出现。需要可靠增量同步协议。
OpenShell mirror/remote 双模式开发便利与长任务效率可选。mirror 每次全 tree 成本与冲突风险；无 browser/bind。上游提供版本化增量 snapshot。
Durable truth + live capability审批历史可恢复，同时不让 SQLite row 变 bearer token。Gateway restart 后必须重新请求。能设计可验证、可撤销的持久 capability。
Prepared plan 精确绑定批准内容与执行内容一致。复杂 shell/interpreter 只能 best-effort 识别单文件 operand。执行协议能提供完整加载图。
