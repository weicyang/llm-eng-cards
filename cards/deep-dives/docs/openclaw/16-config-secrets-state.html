OpenClaw 配置、SecretRef 与 SQLite 详细设计

解释 authored JSON5 如何变成 canonical runtime snapshot，SecretRef 如何按 owner 原子激活，以及 shared/per-agent SQLite 如何承担唯一稳态所有权。

一句话目标：OpenClaw 把“可编辑来源”与“运行时权威”分开：JSON5/include/env 经严格 Core + Plugin 校验和默认值物化后才能发布；SecretRef 在 owner 边界一次性解析；持久运行状态进入 shared 或 per-agent SQLite，旧文件只由 Doctor 迁移后退役。

1. 模块定位

配置模块拥有从 authored 文件到 validated source config、materialized runtime config 和 active snapshot 的转换；Secret runtime 拥有 credential assignment、owner isolation、cold/stale degradation 与原子激活；State 层拥有 SQLite 文件、schema、事务、Kysely facade、完整性和迁移。三者相连但不能互相越权。证据：src/config/io.load.ts:33-207、src/secrets/runtime.ts:137-307、src/state/openclaw-state-db.ts:85-91。

边界负责不负责/委托
Authored configJSON5、$include、config-owned env、${VAR} substitution、strict validation。不在 runtime consumer 中读取 legacy alias 或重复扫描磁盘。
Canonical runtime默认值、路径和 provider/model normalization，发布 pinned in-memory snapshot。不把默认值写回 authored 文件，除非明确的配置 mutation/Doctor。
Secret activation识别有效 surface、分配 owner、批量解析 provider、验证值、原子发布。不在请求热路径逐次解析 SecretRef；不对 unknown owner 静默降级。
Shared state全局控制面、registries、approvals、pairing、cron/tasks、plugin/global KV 等。不保存 agent-private session/transcript/memory/auth state。
Per-agent state一个 agent 的 sessions、transcripts、memory index、auth、conversation/runtime state。数据库不可跨 agentId/role 复用。
迁移Schema forward migration、Doctor config/state repair、验证后退役 legacy files。steady-state runtime 不保留 JSON fallback、dual-write 或 read-through import。
硬边界：本章描述现有 schema 版本，但本次只创建外部 HTML 文档，没有修改任何 OpenClaw schema、DDL、version constant、generated schema 或迁移代码。

3. 核心概念与术语

Authored config用户文件中的原始形状，保留 JSON5 注释语义、include 和 SecretRef；用于安全写回与审计。
Source configinclude/env 解析并通过校验的规范来源形状；仍保留 SecretRef identity，不等于 resolved runtime bytes。
Runtime config应用默认值、路径/provider normalization 和 Secret materialization 后供运行时读取的对象。
Active snapshot进程内 pinned generation。只有成功启动/reload/managed write 才替换；请求热路径不 reread JSON5。
Secret owner实际使用 credential 的 account/capability/gateway/provider/route。Owner 包含是否 Gateway 必需及 isolate/fail-closed disposition。
Cold / StaleCold：当前 owner 没有可安全复用值，configured-unavailable；Stale：ref、provider definition、完整非 secret contract 均未变化，可用 LKG。
Shared DBstate/openclaw.sqlite；全局控制面和跨 agent registry 的权威库。
Per-agent DBagents/<agentId>/agent/openclaw-agent.sqlite；由规范化 agentId 和 role=agent 双重绑定。
Schema versionPRAGMA user_version + schema_meta.schema_version；新于二进制时 fail-closed。
Lazy additive table向旧二进制不可见但不破坏其读取的新表；在首次功能使用时 idempotent ensure，不为此单独 bump version。

5. 完整运行流程

5.1 成功路径：配置到原子运行时

openclaw.json → 加载 .env（仅真实进程） → JSON5 解析 → 在允许的 root 内解析 $include → 应用 config.env，不覆盖更高优先级的非空 env → 替换 ${UPPER_CASE_VAR} → 重复 agent-dir 检查 → 严格 OpenClaw Zod schema + 跨字段规则 → 加载 plugin metadata snapshot → 校验活跃 plugin/channel JSON Schema → 物化默认值 + 规范化 paths/provider/model id → 按 owner 准备 SecretRef assignment → 解析 provider + 校验值 → 原子激活 config/auth/web-tool/degraded-owner snapshot → runtime owner 读取 pinned 内存 config → store 读写规范化 SQLite
  1. 解析顺序有语义。env 字段先注入低于真实 process env、高于已标记 lower-precedence env 的值，再做全树 substitution；include 已先合并，因此 included env 也参与同一解析。src/config/io.read-helpers.ts:296-317、src/config/config-env-vars.ts:535-605
  2. Core 与 Plugin 都校验。Zod root 是 strict object；随后 runtime metadata 提供 plugin/channel schema。Plugin validation 只在明确的 updater/Doctor 场景可跳过，正常 Gateway 不跳过。src/config/zod-schema.ts:15-68、src/config/io.load.ts:103-139
  3. 默认值只进入 runtime 形状。Materializer 按固定顺序返回新对象，路径 normalization 和 safe-bin profile 最后执行；runtime 不依靠各 consumer 各自猜默认。src/config/materialize.ts:57-88
  4. Secret 预先物化。Resolver 先收集 assignments，再按 owner/provider 解析；值全部满足 target shape 才 apply。Resolved secret 注册精确值 redaction，runtime 请求不再触发 provider I/O。src/secrets/runtime.ts:205-297、src/secrets/runtime-shared.ts:215-257
  5. 发布是单一边界。Config snapshot、auth-store snapshots、web tools metadata 与 degraded owner list 在同一 activate 函数更新，并设置 refresh handler。src/secrets/runtime-state.ts:874-926

5.2 拒绝路径：无效配置或严格 Secret 失败

候选 read/write/reload → parse/include/env/schema/plugin 校验失败 → snapshot.valid = false + 类型化 issue → startup：InvalidConfigError(recovery=doctor)，Gateway 拒绝 → reload：警告 + 跳过候选，active snapshot 不变 → managed write：拒绝/保留候选以供检查 config 有效但 Secret 激活失败 → inactive surface：警告，跳过 → retryable + 已知可隔离 owner：cold/stale 降级 → Gateway 必需 / fail-closed / unknown / 值非法 / policy 违规： 拒绝 startup 或 reload；保留 active snapshot

Config load 的 catch 会回滚仅由本次读取产生且尚未被其他 owner 改写的 env 变化；因此无效候选不能把 process env 留在半更新状态。证据：src/config/io.load.ts:187-206、src/config/io.read-helpers.ts:351-367。

Secret owner 只有“provider failed”或“ref not found”等 retryable 原因可隔离；owner 为 unknown、Gateway 必需、disposition=fail-closed 或值形状不合法时抛出原错误。证据：src/secrets/runtime-degraded-state.ts:61-64、src/secrets/runtime-owner-assignments.ts:353-368。

5.3 恢复/迁移路径：Reload、LKG 与 Doctor

文件系统/写入通知 → debounce 300 ms → 缺失：重试 2 次 × 150 ms，然后跳过 → 无效：跳过，保留 active config → 有效：diff 规范化 compare config ├─ none：仅更新 source/metadata ├─ hot：preflight owner → commit → 刷新选定 owner └─ restart：校验 → managed restart reload 时 Secret provider 故障 → 相同 ref + 相同 provider definition + 相同完整 owner contract ├─ 是 + 存在 active 已解析字节：stale，应用 LKG └─ 否：cold，应用 unavailable 历史遗留 state → Doctor 检测 → 独占 lock/claim → 导入 SQLite transaction → 校验规范化行 → 移除/归档退役 source → runtime 仅读 SQLite

LKG 不是“只要 ref 字符串一样就继续”。分类同时比较 owner kind/id、排序后的 ref keys、provider definitions 和完整 owner contract digest；active bytes 缺失时即使分类候选为 stale 也降为 cold。证据：src/secrets/runtime-owner-assignments.ts:40-74、src/secrets/runtime-owner-assignments.ts:469-523。

普通 validation invalid 不自动恢复成旧配置；startup/reload 拒绝或跳过，显式 openclaw doctor --fix 才从 promoted LKG 修复。另有一个更窄的 clobber detector：在没有 include 且内容疑似被截断/覆写时，Config IO 可从 .bak 自动恢复并保留 clobbered snapshot。两者不能混写成同一个行为。证据：src/commands/doctor-config-preflight.ts:510-539、src/config/io.observe-recovery.ts:613-727。

6.3 Schema version 与 Lazy Additive Table

Schema bump 表达旧 reader 不能容忍的 shape change；新版本二进制会 forward migrate，旧版本看到更高 user_version 必须拒绝。纯新增表若旧版本仍能正常工作，只是看不到新功能，则不 bump：DDL 放在 canonical schema，同时由 feature 在首次使用前 idempotent ensure，下一次自然 bump 再折叠进主迁移。

实例首次使用规则为何不 bump证据
Agent Board第一次写 board 前，在独立 IMMEDIATE transaction 中 ensure；readonly 缺表视为“没有 board”。旧二进制可继续读 agent DB，只缺 board feature。src/boards/sqlite-board-store.ts:60-98、src/state/openclaw-agent-board-schema.ts:62-70
User Profiles第一次 profile 操作前 ensure 两张 STRICT table；成功 commit 后才记 WeakSet。普通 shared DB open 不创建 identity tables；旧 reader 不受影响。src/state/user-profiles-schema.ts:1-23、src/state/user-profiles.ts:87-109
版本纪律：不要为“方便”手改 OPENCLAW_STATE_SCHEMA_VERSION 或 OPENCLAW_AGENT_SCHEMA_VERSION。真正需要 bump 时必须先讨论兼容/降级影响；纯 additive table 使用 canonical DDL + one-time lazy ensure。

10. 安全与信任边界

  1. Include confinement。默认只能包含 config 目录；额外 root 必须显式配置。Lexical containment、realpath、open-time revalidation、regular-file/size/hardlink guard 共同防 path traversal 与 symlink race。src/config/includes.ts:248-312、src/config/includes.ts:426-468
  2. Strict config。Unknown/malformed fields 不进入 runtime。插件 config 也必须通过所属 manifest schema，Core 不为插件字段猜形状。
  3. Secret 最小 owner。Credential 失败只隔离已知且可隔离的最小 owner；Gateway ingress、unknown owner、policy violation、invalid resolved value 均 fail-closed。
  4. 无隐式 credential fallback。Cold owner 接收 canonical unavailable/SecretRef 形状并在使用时抛 typed unavailable，不能转向低优先级明文凭证掩盖故障。src/secrets/runtime-owner-assignments.ts:500-512、src/secrets/runtime-degraded-state.ts:124-239
  5. LKG 绑定完整 contract。Ref identity、provider definition 与 non-secret owner config 任一变化都使 owner cold，防旧 credential 与新 endpoint/account/plugin config 错配。
  6. SQLite owner 与版本 fail-closed。Agent DB 验证 role/agentId；新 schema 拒绝；quarantine/latch 防损坏文件被重复打开。
  7. 迁移需独占和验证。Doctor 对安全敏感退休文件使用 exclusive state lock、bounded safe read、claim rename、transaction import、canonical verify，再删除 claim。src/infra/state-migrations.node-host.ts:421-523、src/infra/state-migrations.node-host.ts:526-597
SecretRef 的真实边界：它减少持久明文和 SDK 链路暴露，但不是进程隔离；真实值仍存在同一进程内存并在最终 egress 注入点出现。日志 redaction 是纵深防御，不应替代 OS/container 权限。

14. 开发与扩展指南

变更目标正确所有者表面通常同步修改必要证明
新增配置项exported type + Zod schema + help/metadata + runtime consumerdefaults、reload rule、Doctor、官方 docs、baseline tests。现有行为/默认不能解决；真实 precedence、failure、hot/restart。
新增 Plugin configPlugin manifest JSON Schema + public SDK consumerPlugin help/docs/Doctor contract。Plugin 未安装/禁用/invalid 隔离；Core 不硬编码 id。
新增 SecretRef surfaceOwner collector + typed assignmentactive-surface rule、owner contract、degradation/status/doctor。inactive、healthy、retryable cold/stale、unknown/strict failure、无 fallback。
新增全局状态Shared DB 或 plugin KVcanonical schema/Kysely types/store tests。为何不是 per-agent；transaction 与 retention。
新增 agent 状态Per-agent DBowner schema/Kysely/store、deletion/backup/maintenance。agentId isolation、cache/transaction、migration。
新增纯 additive tableCanonical schema + feature-local lazy ensuregenerated types/schema，fold-at-next-bump comment/test。旧 reader 可容忍；first-use idempotent；不 bump。
需要不兼容 schema changeShared/agent schema ownerversion、forward migration、preflight/docs/backup/downgrade proof。先获明确讨论与接受；本次任务禁止修改版本。
退休 legacy fileDoctor/state migration ownerdetect、exclusive claim、import、verify、cleanup、restart guidance。runtime 无 dual-read/write/fallback；中断可恢复。

禁止的捷径

  • 不要在 runtime consumer 里读取 legacy key、旧 JSON 或“SQLite 失败则 fallback 文件”。
  • 不要在请求热路径 reread config、resolve SecretRef 或扫描 plugin metadata。
  • 不要新增 OpenClaw-owned JSON/JSONL/TXT sidecar 作为状态、cache、queue 或 cursor。
  • 不要在 SQLite transaction callback 中返回 Promise、await、调用网络、文件系统或 plugin hook。
  • 不要用 raw SQL 代替 Kysely 普通查询；仅 DDL、migration、bootstrap、PRAGMA/窄 SQLite primitive 例外。
  • 不要为纯 additive table bump schema；也不要未经明确讨论推进不兼容 schema version。
  • 不要把 stale Secret LKG 扩大成 ref/provider/owner contract 改变后的 fallback。

15. 设计权衡与已知限制

问题当前选择收益成本/失败模式重新评估条件
人类可编辑与运行一致性Authored source 与 materialized runtime snapshot 分离。保留注释/SecretRef，热路径稳定。需要 source/runtime 双 fingerprint 和 write ownership。配置改为完全生成且不再人工编辑。
扩展校验Core Zod + Plugin JSON Schema 两阶段。Core strict 且插件自治。Plugin metadata 不可用会形成复杂 warning/issue 分类。公共 schema contract 能统一而不让 Core 依赖插件。
Secret provider 故障按 owner isolate，严格表面 fail-closed，unchanged contract 可 stale。一个 provider/account 故障不必拖垮全部 Gateway。Owner assignment 和 contract digest 必须完整。存在跨 owner credential transaction 的明确产品需求。
单机状态SQLite-first，shared + per-agent 分库。事务、查询、备份、所有权平衡。schema/迁移/lease/WAL 纪律高。工作负载需要外部 DB 或多写者集群。
版本演进Forward-only schema；newer DB 拒绝旧 binary；additive table lazy ensure。防 silent corruption，并减少无意义 bump。降级需要备份/隔离 state dir；lazy DDL 增加 feature 首次使用路径。引入正式的双版本兼容读取协议。
Legacy retirementDoctor 单一 migration owner，验证后删除旧 source。稳态只有 canonical path。迁移流程复杂，需处理中断/锁/冲突。某 legacy store 成为仍受支持的外部公共 contract。
已知限制：配置、Secret 与 state migration 表面很大，部分文件仍是 grandfathered oversized composition modules。拆分应围绕真实 owner/phase，不应引入第二套 load、secret activation 或 migration path。官方 database schema history 当前也落后于源码版本，需要后续在官方 docs owner 下单独修正；本任务按要求不改 OpenClaw 仓库文档。
