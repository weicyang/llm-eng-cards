A27 · Agent Skill 从使用到原理

Agent Skill 概念 → 基础用法 → Reference 按需加载 → Script 代码执行 → 渐进式披露三层架构 → Skill vs MCP

Agent Skill 就是给模型准备的"随用随翻的说明书"——把规则、流程、资料和脚本写成文件夹，模型按需三层加载，从此不用每次对话粘贴长提示词。

一、Agent Skill 是什么

2025年10月 Anthropic 推出 Agent Skill，起初仅用于 Claude 特定任务，但行业迅速跟进（VS Code、Codex、Cursor 均跟进支持）。12月 Anthropic 将其发布为开放标准，支持跨平台复用。

通俗定义：Agent Skill 就是大模型可以随时翻阅的"说明文档"——在 skill.md 文件中写好规则、流程和示例，模型在执行任务时自动参考，无需每次对话重复粘贴长要求。

实际场景示例

场景Skill 中规定的内容
智能客服遇到投诉先安抚用户，不得随意承诺
会议总结按参会人员/议题/决定格式输出
爆款文案标题公式 + 结构 + 语气要求
Agent Skill 本质是一个以文件夹形式存在的、可动态加载的结构化系统提示词，包含指令、参考资料和代码脚本。

Skill 本质是结构化的系统提示词——把"每次对话都要粘贴的长要求"存成文件，模型需要时自动翻阅。

二、基础用法 — 创建与使用

Skill 文件夹结构

~/.claude/skills/
  └── 会议总结助手/           ← 文件夹名 = Skill 名称
      └── skill.md            ← 核心文件

skill.md 结构

---
name: 会议总结助手            ← metadata（元数据）
description: 用于总结会议录音内容
---

## 规则                           ← instruction（指令）
1. 必须总结参会人员、议题、决定
2. 按以下格式输出...

## 示例
输入：[会议录音文本]
输出：[格式化总结]

skill.md 两大组成部分

部分英文作用
元数据（metadata）metadataname + description，用于模型判断是否需要加载此 Skill
指令（instruction）instruction具体的规则、流程、示例，指导模型如何执行任务

一句话概括：metadata（元数据，即 name 和 description）回答"这个 Skill 是什么、何时该用"，instruction（指令，即规则与示例）回答"具体该怎么做"——前者用于匹配，后者用于执行。

metadata 负责"被找到"，instruction 负责"把事做对"——一个管匹配，一个管执行。

使用时机

在 Claude Code 中输入"你有哪些 agent skill"，Claude Code 会自动扫描 ~/.claude/skills/ 目录发现所有已安装的 Skill。

三、Agent Skill 运行机制 — 按需加载

完整调用流程

用户发送请求 ↓ Claude Code 将所有 Skill 的 metadata（name + description）发给模型 ↓ 模型判断：用户请求匹配"会议总结助手" ↓ Claude Code 读取匹配 Skill 的完整 skill.md ↓ Claude Code 将用户请求 + 完整 skill.md 发给模型 ↓ 模型根据 skill.md 指令生成结果 ↓ 结果返回用户
核心机制：按需加载。所有 Skill 的名称和描述始终对模型可见（轻量级目录），但具体的指令内容只在被选中后才加载，大幅节省 Token。

按需加载 = "目录常驻、正文用到才翻"——这正是 Skill 省 Token 的关键。

加载策略每次对话放入上下文的内容Token 消耗（以安装 10 个 Skill 为例）
全量加载所有 Skill 的完整 skill.md 正文约 10 × 2000 = 20000 的固定消耗
按需加载metadata 目录 + 命中 Skill 的正文通常只需 500–2000

四、Reference — 按需中的按需加载

当 Skill 需要引用大量外部资料（如财务规定、法律条文）时，全部写入 skill.md 会导致文件臃肿。Reference 解决了这个问题。

文件结构

会议总结助手/
  ├── skill.md                  ← 主指令
  └── 集团财务手册.md            ← Reference 文件

在 skill.md 中声明触发条件

## 财务提醒规则
仅在提到"钱/预算/采购/费用"时触发。
触发时读取"集团财务手册.md"，根据内容指出金额是否超标。

Reference 的核心特性

  • 条件触发 — 只有当模型判断内容涉及财务时，才会加载 Reference 文件
  • 零消耗 — 如果不涉及财务，Reference 文件不会被读取，不占一个 Token
  • 读取到上下文 — Reference 的内容会被加载到模型上下文中供参考

Reference 是"按需中的按需"：只有对话命中触发词，那本厚手册才会被翻开，否则不占一个 Token。

五、Script — 让 Skill 跑代码

Script 让 Agent Skill 从"只读文档"进化为"可执行动作"。

文件结构

会议总结助手/
  ├── skill.md
  ├── 集团财务手册.md
  └── upload.py                 ← Script 文件

在 skill.md 中声明触发条件

## 上传规则
如果用户提到"上传/同步/发送到服务器"，
必须运行 upload.py 脚本将总结上传到服务器。
Script 的关键特性：只执行不读取。Claude Code 不会去读代码内容，只关心执行结果。即使脚本写了 10000 行，消耗的模型上下文几乎为零。

Script 只跑不读——代码可以写一万行，进入模型上下文的只有执行结果那一行。

Script 执行流程

用户: "把会议总结上传到服务器" ↓ ┌─ Claude Code ───────────────────────────────────┐ │ 1. 匹配到 skill.md 中的"上传规则" → 条件触发 │ │ 2. 直接执行 upload.py（不读取代码内容） │ │ 3. 接收脚本执行结果（成功/失败） │ └─────────────────────────────────────────────────┘ ↓ upload.py → 服务器: 上传总结文件 ↓ 模型整理执行结果，回复用户

Reference vs Script 对比

维度ReferenceScript
本质被读取的参考资料被执行的代码
加载方式内容放入模型上下文不读取，只运行
Token 消耗有（文件越大越费）几乎为零
触发方式条件触发条件触发

六、渐进式披露三层架构

Agent Skill 的设计是一个精密的渐进式披露（Progressive Disclosure，逐层展开信息，只加载当前步骤所需的内容）结构，共三层：

┌─────────────────────────────────────────────────────┐ │ 第 1 层：元数据层 (Metadata) │ │ 内容：所有 Skill 的 name + description │ │ 加载：始终加载（轻量级目录） │ │ Token：极少 │ ├─────────────────────────────────────────────────────┤ │ 第 2 层：指令层 (Instruction) │ │ 内容：匹配 Skill 的 skill.md 正文 │ │ 加载：按需加载（仅被选中的 Skill） │ │ Token：中等 │ ├─────────────────────────────────────────────────────┤ │ 第 3 层：资源层 (Reference + Script) │ │ 内容：参考资料文件 + 代码脚本 │ │ 加载：按需中的按需（仅条件触发时加载） │ │ Token：Reference 有消耗，Script 几乎零 │ └─────────────────────────────────────────────────────┘

这种三层架构确保了：即使安装了十几个 Skill，每次对话只加载必要的信息，Token 消耗始终可控。

三层渐进式披露像剥洋葱：metadata 目录 → 命中的指令 → 触发的资源，一层一层剥，只加载当下需要的。

层级内容加载时机Token 消耗
① 元数据层所有 Skill 的 name + description始终加载极少（几百）
② 指令层命中 Skill 的 skill.md 正文按需（仅被选中时加载）中等
③ 资源层Reference 参考资料 + Script 脚本按需中的按需（仅条件触发时）Reference 有消耗，Script 几乎零

七、Agent Skill vs MCP

Anthropic 官方定义：MCP connects Claude to data; Skills teach Claude what to do with that data.
MCP 给大模型供给数据，Skill 教会大模型如何处理数据。
维度Agent SkillMCP
本质说明文档（Markdown 文件）独立运行的程序
核心功能教模型"怎么做"（规则/流程/经验）给模型"接数据"（查询/读取/操作）
代码能力轻量脚本（Script）完整的工具服务
安全性较低（脚本直接执行）较高（协议化通信）
适用场景规则流程、格式要求、操作指南数据查询、API 调用、外部系统集成

MCP 给模型递食材（数据），Skill 给模型递菜谱（规则）——两者互补，而非替代。

┌────────────────────┐ ┌────────────────────┐ │ Agent Skill │ │ MCP │ │ 教模型"怎么做" │ │ 给模型"用什么" │ │ 规则 / 流程 / 格式 │ │ 查询 / 读取 / 操作 │ └─────────┬──────────┘ └──────────┬─────────┘ └───────────┬──────────────────┘ ↓ ┌────────────────────┐ │ 模型综合处理 │ │ 按 MCP 取数据， │ │ 按 Skill 加工输出 │ └────────────────────┘
  • 用 Skill 定义输出格式、流程和规则
  • 用 MCP 连接外部数据源和 API
  • Skill + MCP 结合使用效果最佳
  • Skill 的 Script 适合轻量脚本
  • 用 Reference 拆分大文档，按需加载
  • 不要用 Skill 替代 MCP 做复杂数据操作
  • 不要在 skill.md 中塞入所有参考资料
  • 不要用 Skill 的 Script 运行危险命令
  • 不要忽略 metadata 的 description 质量
  • 不要把安全敏感逻辑放在 Script 里

高频问答

什么是 Agent Skill？它解决了什么核心问题？
Agent Skill 是一种以文件夹形式存在的结构化系统提示词，包含 skill.md（元数据+指令）、Reference（参考资料）和 Script（代码脚本）。核心解决的问题：①避免每次对话重复粘贴长提示词；②通过渐进式披露机制节省 Token（只加载必要的信息）；③将操作经验/规则/流程标准化，可跨平台复用。2025年 Anthropic 将其发布为开放标准，已被 VS Code、Cursor、Codex 等工具支持。
Agent Skill 的渐进式披露三层架构是什么？
三层架构：①元数据层（Metadata）— 所有 Skill 的 name + description，始终加载，相当于轻量级目录，Token 极少；②指令层（Instruction）— 匹配 Skill 的 skill.md 正文，按需加载，仅被选中的 Skill 才加载；③资源层（Reference + Script）— 按需中的按需，仅条件触发时加载。Reference 被读取到上下文（消耗 Token），Script 只执行不读取（几乎零 Token）。这种设计确保即使安装十几个 Skill，每次对话只加载必要信息。
Reference 和 Script 的加载方式有什么区别？
Reference 是"读"：当条件触发时，Claude Code 将文件内容加载到模型上下文中供参考，会消耗 Token。Script 是"跑"：Claude Code 不会读取代码内容，只执行脚本并获取运行结果，即使脚本写了上万行，消耗的模型上下文几乎为零。关键区别：Reference 增加模型的知识（提供信息），Script 扩展模型的能力（执行动作）。两者都是条件触发，但加载方式和对 Token 的影响截然不同。
Agent Skill 和 MCP 的区别是什么？什么时候用哪个？
Anthropic 官方总结：MCP connects Claude to data, Skills teach Claude what to do with that data。MCP 是独立运行的程序，负责给模型供给数据（查询数据库、调用 API）；Skill 是说明文档，教模型如何处理数据（格式要求、操作流程、规则约束）。Skill 本质是 Markdown 文件，MCP 本质是运行中的服务。选择原则：①定义输出格式/流程/规则 → Skill；②连接外部数据源/API → MCP；③大多数场景两者结合使用。Skill 的 Script 虽能连数据，但安全性和稳定性不及 MCP。
Agent Skill 的按需加载机制为什么能节省 Token？
按需加载分两步节省 Token：①初始阶段只将所有 Skill 的 metadata（name + description）发给模型，这是一个轻量级目录，即使有 20 个 Skill 也只占几百 Token；②模型判断用户请求匹配某个 Skill 后，Claude Code 才读取该 Skill 的完整 skill.md，而且只读取匹配的那一个；③Skill 内的 Reference 文件进一步条件触发，只在涉及特定内容时才加载。对比：如果将所有 Skill 的完整内容始终发给模型，10 个 Skill × 平均 2000 Token = 20000 Token 的固定消耗。按需加载后，通常只需 500-2000 Token。
如何设计一个高质量的 Agent Skill？
关键设计原则：①Metadata 的 description 要精准描述 Skill 的适用场景，这直接影响模型的匹配准确率；②Instruction 部分要有明确的规则和 few-shot 示例，确保模型理解输出格式；③用 Reference 拆分大文档（如财务手册、法律条文），设置精确的触发条件避免不必要加载；④Script 中的执行方法要在 skill.md 中写清楚，否则模型可能会去读取代码内容（浪费 Token）；⑤保持单一职责，一个 Skill 只做一类事情，避免"万能 Skill"。
