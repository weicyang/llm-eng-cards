DP13 · 模型量化

Quantization — 用更少的 bit 表示模型权重，在精度、速度与内存之间取得最优平衡

一、量化基础

量化就是把一条连续的数轴换成有限个刻度：省下的是存储和带宽，丢掉的是刻度之间的那些值。

什么是量化

量化 (Quantization) 是将模型权重和/或激活值从高精度浮点数（如 FP32）映射到低精度数据类型（如 INT8、INT4）的过程。其核心目标是在尽量保持模型精度的前提下，显著减少模型的内存占用和推理延迟。

FP32 权重 → 量化映射 → INT8 / INT4 权重 → 推理时反量化

对称量化 vs 非对称量化

对称量化 (Symmetric)

  • zero_point = 0，原点对齐
  • 公式：q = round(x / scale)
  • 适合权重分布近似关于 0 对称的情况
  • 计算更简单、推理更快

非对称量化 (Asymmetric)

  • 引入 zero_point 偏移量
  • 公式：q = round(x / scale) + zero_point
  • 适合分布不对称的激活值（如 ReLU 输出）
  • 表达范围更灵活，精度可能更高

量化核心公式

量化 (Quantize)：

q = clamp(round(x / scale + zero_point), q_min, q_max)

反量化 (Dequantize)：

x̂ = scale × (q − zero_point)

参数计算：

scale = (x_max − x_min) / (q_max − q_min)
zero_point = round(q_min − x_min / scale)

其中 x 是原始浮点值，q 是量化后的整数值，scale（缩放因子）和 zero_point（零点）决定了映射关系。

量化误差

量化本质上是一种有损压缩。量化误差来源于：

  • 舍入误差 — round() 操作引入的离散化误差
  • 截断误差 — clamp 操作将超出范围的值截断到边界
  • 量化粒度 — per-tensor（全局一个 scale）vs per-channel（每通道独立 scale）vs per-group（分组量化），粒度越细精度越高但开销越大
  • 量化 = 高精度浮点 → 低精度整数/浮点的映射，核心是 scale 和 zero_point
  • 对称量化用于权重、非对称量化用于激活值是常见搭配
  • 量化粒度：per-tensor < per-channel < per-group，粒度越细精度越好
  • 量化误差 ≠ 模型精度损失 — 误差需要在下游任务上实际评估

二、数据类型全览

低精度类型都在同一笔预算里分配位数：给指数多一点就换来范围，给尾数多一点就换来精度。

类型位宽范围精度典型用途
FP32 32 bit ±3.4×10³⁸ ~7 位有效数字 训练基准、参数存储
FP16 16 bit ±6.5×10⁴ ~3.3 位有效数字 混合精度训练、推理
BF16 16 bit ±3.4×10³⁸ ~3 位有效数字 大模型训练（Google TPU 原生）
FP8 (E4M3) 8 bit ±448 ~2 位有效数字 H100 推理加速、训练探索
INT8 8 bit -128 ~ 127 均匀量化 推理量化、边缘部署
INT4 4 bit -8 ~ 7 均匀量化 GPTQ/AWQ 权重量化
NF4 4 bit 非均匀分布 信息论最优 QLoRA / bitsandbytes

BF16 vs FP16 — 为什么大模型训练偏爱 BF16？

  • BF16：8 位指数 + 7 位尾数 → 范围与 FP32 相同，不易溢出
  • FP16：5 位指数 + 10 位尾数 → 精度更高但范围小，需要 loss scaling
  • 大模型训练中，数值范围比精度更重要 → BF16 无需 loss scaling 即可稳定训练

NF4 — 为正态分布量身定制

NF4 (4-bit NormalFloat) 假设权重服从正态分布，将量化桶不均匀地分布在正态分布的分位数上，使得每个桶覆盖大致相等的概率质量，从信息论角度达到4 bit 量化的最优精度。

  • BF16 vs FP16 的核心差异：范围 vs 精度的取舍；BF16 是大模型训练的事实标准
  • NF4 是信息论最优的 4-bit 数据类型（假设正态分布），是 QLoRA 的核心
  • FP8 是下一代推理加速方向（NVIDIA H100 原生支持 FP8 Tensor Core）
  • INT4 是当前 LLM 推理量化的主流位宽

三、PTQ vs QAT

QAT 是让模型在训练时就学会带着量化误差工作，PTQ 是训练完再压——对大模型来说，前者的账根本算不过来。

PTQ — 训练后量化 (Post-Training Quantization)

  • 在模型训练完成后直接量化
  • 不需要重新训练，只需少量校准数据
  • 计算成本极低（分钟级）
  • LLM 的主流方案（GPTQ、AWQ 等）
  • 4-bit PTQ 可能导致较大精度损失

QAT — 量化感知训练 (Quantization-Aware Training)

  • 在训练过程中模拟量化效果
  • 前向传播插入伪量化节点 (fake quantization)
  • 模型学会适应量化误差 → 精度更高
  • 需要完整训练流程，成本极高
  • 对 LLM 来说通常不现实（训练太贵）

为什么 LLM 主要用 PTQ？

  1. 训练成本 — 7B 模型全量训练需数千 GPU 小时，QAT 意味着重新训练
  2. PTQ 已够好 — GPTQ/AWQ 等方法在 4-bit 下精度损失可控
  3. 灵活性 — 同一个 FP16 基模型可按需求量化到不同精度
  4. 新方法不断涌现 — PTQ 算法持续改进，精度损失越来越小
  • PTQ 是 LLM 量化的事实标准，QAT 因训练成本过高在 LLM 场景较少使用
  • PTQ 只需校准数据（通常 128-512 条样本），无需标签
  • QAT 精度更高但成本不可接受 — 需要能解释为什么 LLM 偏好 PTQ

四、GPTQ

GPTQ 的巧思在于"错了就补"：一个权重被量化产生的误差，立刻摊到还没量化的权重上去抵消。

论文 GPTQ: Accurate Post-Training Quantization for Generative Pre-Trained Transformers (Frantar et al., 2023)

核心思想

GPTQ 是一种基于二阶信息（Hessian 矩阵）的逐层 PTQ 方法。它的目标是最小化量化前后每一层输出的差异：

min ‖WX − W_q X‖²

其中 W 是原始权重，W_q 是量化后的权重，X 是校准数据的激活值。

算法流程

  1. 收集校准数据 — 用少量数据（128 条）前向传播，记录每层输入激活 X
  2. 计算 Hessian — H = 2X Xᵀ，衡量每个权重对输出的影响程度
  3. 逐列量化 — 按列顺序，每量化一个权重后，用 Hessian 信息补偿其他未量化权重
  4. 分组处理 — 将列分成大小为 128 的组 (block)，组内顺序量化，组间懒更新 (lazy batch update)

从 OBQ 到 GPTQ

GPTQ 源于 Optimal Brain Quantization (OBQ) 的简化：

  • OBQ：每次选择量化误差最小的权重 → O(d³) 复杂度
  • GPTQ：固定量化顺序（按列），不再搜索最优顺序 → O(d·k²) 复杂度
  • 实验证明固定顺序的精度损失极小，但速度提升数个数量级

关键特点

特性说明
量化精度4-bit / 3-bit / 2-bit（4-bit 最常用）
量化速度7B 模型约 4-5 分钟（单 GPU）
校准数据128 条样本即可，无需标签
group_size默认 128，越小精度越高但体积越大
推理后端支持 ExLlama、AutoGPTQ、vLLM
# AutoGPTQ 使用示例
from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig

quantize_config = BaseQuantizeConfig(
    bits=4,
    group_size=128,
    desc_act=False,       # 是否按激活值降序排列列
)

model = AutoGPTQForCausalLM.from_pretrained(
    model_name, quantize_config=quantize_config
)
model.quantize(calibration_dataset)
model.save_quantized(output_dir)
  • GPTQ 核心 = Hessian 逐列量化 + 误差补偿（残差重分配到未量化列）
  • 相比 OBQ，GPTQ 固定列顺序，将复杂度从 O(d³) 降到 O(d·k²)
  • group_size=128 是精度与压缩率的平衡点
  • desc_act=True 精度更好但推理更慢（需重新排列权重）

五、AWQ (Activation-aware Weight Quantization)

AWQ 换了个角度看重要性：一个权重重不重要，不看它自己有多大，而看它乘的那个激活有多大。

论文 AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration (Lin et al., 2024)

核心洞察

不是所有权重都同等重要。AWQ 发现：仅 1% 的"显著权重" (salient weights) 就能显著影响模型精度，而这些权重可以通过对应的激活值大小来识别。

关键直觉

如果某个输入通道的激活值很大，那么该通道对应的权重即使量化误差很小，也会在输出端被放大。因此应该保护这些权重。

保护策略：对显著权重乘以缩放因子 s → 等效降低量化误差的影响

算法步骤

  1. 统计激活值 — 用校准数据计算每个输入通道的平均激活幅度
  2. 确定缩放因子 — 对显著通道的权重乘以缩放因子 s > 1（等效于缩小该通道量化步长）
  3. 搜索最优 s — 通过 grid search 找到每组权重的最优缩放因子，最小化量化误差
  4. 应用量化 — 在缩放后的权重上执行标准 INT4 量化

六、GGUF / llama.cpp 量化

k-quant 的思路很朴素：既然各层敏感度不同，那就别用统一位宽，敏感的多给几位，不敏感的少给几位。

GGUF 格式

GGUF (GPT-Generated Unified Format) 是 llama.cpp 生态系统使用的模型文件格式，由 Georgi Gerganov 设计。它是 GGML 格式的继任者，特点是：

  • 单文件 — 权重、tokenizer、元数据全部打包在一个文件中
  • 可扩展 — 支持自定义键值对元数据
  • 内存映射 — 可以直接 mmap 到内存，加载极快
  • 跨平台 — 纯 CPU 推理，支持 x86、ARM、Apple Silicon

量化级别详解

量化类型位宽 (avg)7B 大小精度推荐场景
Q2_K~2.6 bit~2.8 GB较差极端内存受限
Q3_K_S~3.4 bit~3.2 GB一般低内存设备
Q4_K_M~4.8 bit~4.4 GB推荐精度-大小最佳平衡
Q5_K_S~5.5 bit~5.0 GB较好更重视精度
Q5_K_M~5.7 bit~5.3 GB好精度优先
Q6_K~6.6 bit~5.9 GB优秀接近 FP16 精度
Q8_0~8.5 bit~7.2 GB极好几乎无损

K-quant 命名规则

Q{bits}_K_{size} 其中：

  • Q{bits} — 主要量化位宽
  • K — 使用 k-quant 方法（混合精度量化，关键层保留更高精度）
  • S / M / L — Small / Medium / Large，指非关键层使用的精度等级

k-quant 会自动将 attention 层和输出层保持在更高精度，非关键的 FFN 层使用更低精度。

示例场景：一个中文法律问答助手要压到 4-bit 上线，团队直接用了公开的通用英文语料做校准，量化耗时几分钟，PPL 只涨了一点点，看起来很顺利。

问题：上线后中文长条款的引用频繁出错，法条编号会被写错一两位，专业术语偶尔被替换成近义的日常词。用同一批业务样本对比量化前后，发现量化前的准确率约 八成八，量化后掉到约 七成一，而通用 PPL 指标几乎没动。原因是校准数据决定了各层激活值的统计分布，用英文通用文本校准出来的 scale，对中文法律文本里那些高频的专有名词和数字串并不合适。

方案：换成从线上真实请求里抽的 128 条样本做校准，覆盖条款检索、案情问答、文书生成三类，长度也按线上分布来；同时把 LM Head 和 Embedding 层排除在低比特之外，保持较高精度。

效果：准确率回到约 八成六，模型体积和推理速度基本不变。这里唯一变的是校准数据——校准集是量化方案的一部分，不是随便找一份文本就行。

使用流程

# 1. 从 HuggingFace 转换为 GGUF
python convert_hf_to_gguf.py ./model_dir --outtype f16

# 2. 量化
./llama-quantize model-f16.gguf model-Q4_K_M.gguf Q4_K_M

# 3. 推理
./llama-cli -m model-Q4_K_M.gguf -p "Hello" -n 128 \
    --threads 8 --ctx-size 4096
  • GGUF 是端侧/CPU 推理的事实标准格式（Ollama、LM Studio 等都基于此）
  • Q4_K_M 是最常推荐的量化级别 — 精度损失小且压缩率高
  • k-quant 使用混合精度：关键层高精度 + 非关键层低精度
  • GGUF 支持 mmap → 加载速度快，多进程可共享内存

七、bitsandbytes

bitsandbytes 优化的是"能不能跑起来"，不是"跑得多快"——它让单卡装下大模型，生产提速是另一批工具的事。

概述

bitsandbytes 是由 Tim Dettmers 开发的轻量级量化库，与 HuggingFace Transformers 深度集成。它以易用性著称 — 只需一行代码即可将模型以 4-bit 或 8-bit 加载。

核心功能

load_in_8bit

  • 使用 LLM.int8() 方法（Dettmers et al., 2022）
  • 混合精度分解：将权重矩阵按离群特征 (outlier features) 拆分
  • 离群特征以 FP16 计算，其余以 INT8 计算
  • 几乎零精度损失，内存减少约 50%

load_in_4bit + NF4

  • 使用 QLoRA 提出的 NF4 数据类型
  • 假设权重服从正态分布，分位数量化达到信息论最优
  • 支持双重量化 (double quantization) — 对量化常数再量化，进一步节省内存
  • 内存减少约 75%，是 QLoRA 微调的基础

使用方式

from transformers import AutoModelForCausalLM, BitsAndBytesConfig

# 8-bit 加载
model_8bit = AutoModelForCausalLM.from_pretrained(
    model_name,
    load_in_8bit=True,
    device_map="auto"
)

# 4-bit NF4 加载（QLoRA 配置）
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,   # 双重量化
)

model_4bit = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=bnb_config,
    device_map="auto"
)

bitsandbytes 与 QLoRA 的关系

预训练模型 (FP16) → bitsandbytes NF4 量化 → 冻结量化权重 → LoRA 适配器 (FP16/BF16)

QLoRA = NF4 量化底座 + LoRA 可训练适配器。bitsandbytes 提供量化层，PEFT/LoRA 提供参数高效微调。

  • bitsandbytes 是 HuggingFace 生态最易用的量化方案 — 一行代码即可使用
  • LLM.int8() 的关键创新：离群特征检测 + 混合精度分解
  • NF4 + 双重量化 → QLoRA 的核心，使得单卡微调大模型成为可能
  • bitsandbytes 主要用于微调和开发；生产推理通常用 GPTQ/AWQ/GGUF

八、精度-速度-内存权衡

位宽降一半不等于速度翻倍：省下的是显存和带宽，能不能变快取决于有没有对应的低精度 kernel。

九、量化最佳实践

量化最危险的地方在于它不会报错：模型照常输出，指标照常绿，质量已经悄悄掉了一截。

校准数据选择

  • 多样性优先 — 校准数据应覆盖模型预期处理的各种文本类型
  • 数量不需要太多 — GPTQ 通常 128 条即可，AWQ 更少
  • 常用数据集：C4、WikiText-2、Pile 子集、目标领域数据
  • 避免极端 — 不要用全空白或重复文本作为校准数据
  • 长度匹配 — 校准样本长度应接近推理时的典型输入长度

混合精度量化

不同层对量化的敏感度不同。混合精度策略：

  • Embedding 层 — 通常保持 FP16（或至少 8-bit），因为直接影响输入表示
  • Attention 层 — 可以使用 4-bit，但 Q/K 投影可能需要更高精度
  • FFN 层 — 对量化最不敏感，可以激进量化到 4-bit 甚至 3-bit
  • LM Head (输出层) — 保持高精度（影响 token 预测概率分布）
  • LayerNorm — 始终保持 FP32（参数极少，量化收益几乎为零）

示例场景：一个已经做过指令微调的对话模型压到 4-bit，量化前后在 WikiText 上的困惑度差异不到 1%，团队据此判断可以直接上线。

问题：灰度两天后客诉集中在"答非所问"和"不按格式输出"。人工抽了 200 条对比看，单轮短问答几乎没差别，问题全出在两类场景：需要严格 JSON 输出的接口调用，格式错误率从约 2% 涨到约 一成三；多轮对话超过五六轮后，模型开始忘记前面设定的角色和约束。困惑度衡量的是下一个 Token 的平均预测能力，而指令遵循和格式约束依赖的是分布尾部那些低概率 Token 的相对次序，量化恰好破坏的就是这部分。

方案：验收标准从"看困惑度"改成三件套：业务样本的下游任务准确率、结构化输出的格式合规率、以及一批固定的多轮对话脚本做人工对比；同时把 LM Head 保持在较高精度，这一层直接影响输出概率分布。

效果：调整后格式错误率回到约 3%，多轮遗忘问题明显缓解。结论是困惑度只能用来发现"崩得很明显"的量化，细粒度的能力退化必须靠贴近业务的评测才能看见。

  • 量化后必须评估 — 不能假设量化不影响精度
  • PPL 不是唯一指标 — 有时 PPL 差异很小但生成质量明显下降
  • 对话模型比基础模型更脆弱 — SFT/RLHF 微调可能放大量化敏感性
  • 校准数据：128 条多样化样本通常足够，领域数据比通用数据更好
  • 评估三件套：PPL + 下游任务 + 人工评估
  • 混合精度是高级优化方向：关键层高精度 + 非关键层低精度
  • GGUF k-quant 自动实现混合精度策略，GPTQ 的 desc_act 类似
  • 校准数据从线上真实请求抽样，覆盖各类任务，长度贴近真实分布
  • Embedding 与 LM Head 保持较高精度，LayerNorm 不参与量化
  • 验收用业务样本的下游任务指标，困惑度只作为崩溃探测
  • 结构化输出和多轮对话单独做一组回归，它们退化得最早
  • 量化版先与原版并行灰度，小流量对比输出稳定后再放量
  • 不要用通用公开语料校准垂直领域模型，scale 会拟合到错误的分布上
  • 不要因为困惑度没变就认为量化无损，尾部分布的破坏它看不见
  • 不要把位宽降低直接当成速度提升，没有对应 kernel 时反而更慢
  • 不要对微调过的对话模型套用基础模型的量化结论，它更脆弱
  • 不要为了压到极小位宽牺牲长回答质量，收益通常撑不住损失

十、Q&A

Q1：什么是模型量化？为什么 LLM 需要量化？

量化是将模型权重和/或激活值从高精度浮点数（FP32/FP16）映射到低精度数据类型（INT8/INT4）的过程。LLM 需要量化的原因：

  • 内存瓶颈 — 7B 参数模型以 FP16 存储需要约 14GB 显存，70B 则需要约 140GB
  • 推理加速 — 低精度运算可利用硬件加速（如 INT8 Tensor Core）
  • 部署需求 — 让大模型能在消费级 GPU 甚至 CPU 上运行
  • 带宽优化 — LLM 推理通常是内存带宽受限 (memory-bound)，减少数据量直接提升吞吐
Q2：对称量化和非对称量化有什么区别？各自适用场景？

对称量化：zero_point = 0，将 [-max(|x|), max(|x|)] 映射到 [-127, 127]。计算简单，适合权重（通常近似对称分布）。

非对称量化：引入 zero_point 偏移，将 [x_min, x_max] 映射到 [0, 255]。可更好表示不对称分布，适合激活值（尤其是 ReLU 后的非负激活）。

LLM 中常见的搭配：权重用对称量化、激活值用非对称量化。但很多 4-bit 方法只量化权重（weight-only quantization），此时激活值保持 FP16 计算。

Q3：PTQ 和 QAT 的区别？为什么 LLM 主要用 PTQ？

PTQ (训练后量化)：模型训练完成后直接量化，只需少量校准数据（无需标签），成本极低。

QAT (量化感知训练)：在训练中插入伪量化节点模拟量化效果，模型学习适应量化误差，精度更高但需完整训练流程。

LLM 主要用 PTQ 的原因：

  1. LLM 训练成本极高（数百万美元），QAT 意味着重新训练
  2. 现代 PTQ 方法（GPTQ/AWQ）在 4-bit 下精度损失已足够小
  3. PTQ 提供灵活性 — 同一模型可按需量化到不同精度
  4. QAT 需要修改训练管线，对开源社区不友好
Q4：请解释 GPTQ 的核心原理

GPTQ 是基于二阶信息的逐层 PTQ 方法：

  1. 目标：最小化量化前后每层输出的 L2 误差 ‖WX − W_qX‖²
  2. Hessian 矩阵：H = 2XXᵀ，衡量每个权重对输出的影响
  3. 逐列量化：固定顺序按列量化，每量化一个权重后利用 Hessian 逆将误差最优地补偿到剩余未量化权重
  4. 分组加速：按组 (block_size=128) 处理，组内精确更新，组间懒批量更新

核心创新：相比 OBQ（需要搜索最优量化顺序，O(d³)），GPTQ 固定列顺序但精度几乎不损失，复杂度降至 O(d·k²)，使得大模型量化变得实际可行。

Q5：AWQ 和 GPTQ 有什么区别？各自的优缺点？

GPTQ：通过 Hessian 信息做误差补偿，逐列量化后将误差重分配到未量化权重。

AWQ：通过激活值大小识别显著权重，对其乘以缩放因子保护，减少量化误差在输出端的放大效应。

Q6：GGUF 格式是什么？Q4_K_M 代表什么意思？

GGUF (GPT-Generated Unified Format) 是 llama.cpp 使用的模型格式，特点是单文件打包（权重+分词器+元数据）、支持内存映射 (mmap)、纯 CPU 推理。

Q4_K_M 的含义：

  • Q4 — 主要量化位宽为 4 bit
  • K — 使用 k-quant 方法（混合精度，关键层更高精度）
  • M — Medium 级别的非关键层精度

k-quant 的精髓是自动混合精度：attention 和 output 层保持更高精度（如 6-bit），FFN 等非关键层使用更低精度（如 4-bit）。Q4_K_M 是社区最推荐的量化级别，在精度和体积之间取得最佳平衡。

Q7：bitsandbytes 的 LLM.int8() 是如何处理离群特征的？

LLM.int8() 发现大模型中存在少量离群特征 (outlier features) — 某些隐藏维度的激活值远大于其他维度（可达正常值的 100 倍以上）。直接 INT8 量化会严重损害这些特征。

解决方案 — 混合精度分解：

  1. 检测离群特征维度（激活值 > 阈值，通常为 6.0）
  2. 将权重矩阵拆分为两部分：离群维度 + 正常维度
  3. 离群维度以 FP16 精度计算矩阵乘法
  4. 正常维度以 INT8 精度计算矩阵乘法
  5. 两部分结果相加，得到最终输出

这使得 INT8 量化几乎零精度损失，但因为分支计算有额外开销，推理加速有限。

Q8：NF4 为什么比普通 INT4 更适合量化神经网络权重？

神经网络权重通常近似正态分布。普通 INT4 使用均匀量化桶，导致：

  • 密集区域（均值附近）的权重被少数桶覆盖 → 精度浪费
  • 稀疏区域（尾部）占用过多桶 → 编码效率低

NF4 (4-bit NormalFloat) 的做法：

  1. 先将权重归一化到标准正态分布 N(0,1)
  2. 在正态分布的分位数上放置 16 个量化桶
  3. 每个桶覆盖相等的概率质量（约 1/16）

这从信息论角度是最优的 — 相同 4 bit 下，NF4 保留的信息量最大。实验表明 NF4 比 INT4 在量化精度上有明显优势。

Q9：如何估算一个 LLM 量化后的内存占用？

基本公式：内存 ≈ 参数量 × 每参数字节数

  • FP32：参数量 × 4 bytes
  • FP16/BF16：参数量 × 2 bytes
  • INT8：参数量 × 1 byte
  • INT4：参数量 × 0.5 byte

以 LLaMA-2 70B 为例：

精度计算约占内存
FP3270B × 4B~280 GB
FP1670B × 2B~140 GB
INT870B × 1B~70 GB
INT470B × 0.5B~35 GB

注意额外开销：量化元数据（scale/zero_point）、KV Cache、激活值内存、框架开销等。实际占用通常比理论值高 10-20%。分组量化 (group_size=128) 也会增加少量元数据开销。

Q10：在生产环境中，你会如何选择量化方案？

选择量化方案需要考虑多个维度：

  1. 部署硬件
    • 有 GPU → GPTQ / AWQ (4-bit) + vLLM/TensorRT-LLM
    • 纯 CPU → GGUF Q4_K_M + llama.cpp
    • 边缘设备 → GGUF 低比特 + llama.cpp（内存受限选 Q3/Q2）
  2. 精度要求
    • 精度敏感 → INT8 或 Q5_K_M / Q6_K
    • 精度可妥协 → 4-bit 量化
  3. 吞吐需求
    • 高并发服务 → AWQ + vLLM (Continuous Batching)
    • 单用户交互 → GGUF + Ollama 即可
  4. 评估流程
    • 量化后必须跑 PPL + 下游任务 + 人工评估
    • 与 FP16 基线对比，确认精度损失在可接受范围

黄金法则：AWQ 4-bit + vLLM 是当前 GPU 部署的最佳默认选择；GGUF Q4_K_M 是 CPU 部署的最佳默认选择。
