IA-02 · Agent Skill 与渐进式披露

提问：Agent架构中的Skill是什么？渐进式披露是如何实现的？

核心观点

关键认知：Skill 不只是 API 调用，而是一个"高内聚的可插拔能力包"，包含 API 接口 + 操作指南 + 成功案例。渐进式披露的核心是"按需披露，非需莫入"。

Skill 的正确定义

维度错误理解正确理解
本质一个函数/API调用高内聚的可插拔能力包
内容只有工具描述API接口 + 操作指南 + 少样本示例
加载全部常驻prompt按需加载，用后即卸

渐进式披露：三层递进架构

第一层：发现层（Metadata）

系统启动时只给模型喂一份极简"技能清单"（书的目录）：技能名 + 一句话描述。模型只需知道"我具备哪些能力"。

第二层：决策层（Reasoning）

用户提出需求后，模型翻"目录"找到对口技能，主动发出 read_skill 请求，让系统加载详细说明。

第三层：注入层（Injection）

系统从后台数据库读取该技能的完整约束条件、prompt模板、示例，实时拼接到当前对话上下文中。

渐进式披露的三大收益

收益说明
省钱常驻token从几万字降到几百个，TTFT（首字延迟）大幅提升
降噪一次只注入一个专业人设，减少幻觉和指令打架
扩展性不受上下文窗口限制，可挂载成千上万个技能

工程落地的两个硬骨头

1. 检索迷失

Metadata 写得不好 → 模型找不到对应技能或陷入死循环

解法：引入两级路由（先大类过滤 → 再定位具体skill），优化元数据的语义区分度

2. 上下文残留

加载 Skill A → 任务完成 → 加载 Skill B → Skill A 的残留变成垃圾信息

解法：自动卸载机制，任务切换时立刻清理过期指令

未来趋势：MCP 协议

Model Context Protocol 正在将技能管理标准化。只要符合该协议，不同平台开发的 Skill 都能在各种 Agent 架构中无缝切换。

高频问答

Q1: Skill 和普通 Function Calling 有什么区别？

Function Calling 只是调用一个 API 函数，而 Skill 是一个"能力包"，包含：(1) API 接口（干活工具）；(2) 操作指南（何时用、怎么用、注意事项）；(3) 少样本示例（成功案例）。Skill 的设计目标是让模型像一个专业人士一样使用工具箱，而不只是按按钮。

Q2: 渐进式披露的"按需披露"具体怎么实现？

三层递进：(1) 发现层：启动时只给极简清单（名字+描述），模型知道"我有什么能力"；(2) 决策层：用户需求触发后，模型翻目录找到对口技能，发出加载请求；(3) 注入层：系统从后台读取完整说明，实时拼接到上下文。这样模型每秒接触的信息都是精准的、纯净的。

Q3: 如果上百个Skill全塞进System Prompt会怎样？

三个核心问题：(1) 上下文溢出：几万字技能说明超出窗口限制；(2) 指令打架：多个技能的约束条件互相矛盾；(3) 注意力稀释：总注意力带宽有限，每条指令分配到的权重越来越稀疏，模型不按格式输出。这就是为什么需要渐进式披露。

Q4: MCP 协议和渐进式披露是什么关系？

MCP（Model Context Protocol）是将技能管理标准化的协议。渐进式披露是一种架构模式，MCP 是它的标准化实现方式。有了 MCP，不管在哪个平台开发的 Skill，只要符合协议就能在各种 Agent 架构中无缝切换，解决了跨平台的技能互操作性问题。
