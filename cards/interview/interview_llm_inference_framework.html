IE-08 · VLLM / SGLang / TensorRT-LLM 选型

核心问题

推理框架选型，考的不只是知道名字，而是工程权衡的理解。选错框架可能一台机器不够要加三台。

三大框架对比

vLLM - 行业基石

核心技术：PagedAttention

  • 显存像操作系统管理内存一样分页，不需要连续分配
  • 利用率从 60% 飙升到 90%+

特点：通用、生态好、支持 NVIDIA/AMD/国产芯片

适用：初创期、快速上线、硬件多样

SGLang - 进阶黑马

核心技术：Radix Attention（前缀缓存共享）

  • Prompt 像树根存储，共享 System Prompt 可直接复用
  • 多轮对话/长文本场景吞吐量达 vLLM 的 2~5 倍

杀手锏：压缩状态机实现结构化输出（JSON/SQL）极快

适用：复杂 Agent 工作流、多轮对话机器人

TensorRT-LLM - 性能王者

核心技术：Kernel Fusion（算子融合）

  • 算子层级优化，多个计算步骤合成一步
  • 减少显存反复读写

特点：NVIDIA 亲儿子，FP8 量化/极致低延迟的王者

缺点：安装复杂、编译慢、只支持 NVIDIA

适用：国民级应用、亿级请求、NVIDIA 顶配阵营

选型决策矩阵

场景选择原因
初创团队 / 快速验证vLLM稳定不挑食，上手极快
Agent 工作流 / 多轮对话SGLang缓存复用 + 结构化输出，并发翻倍
国民级应用 / 极致性能TensorRT-LLM压榨最后30%性能

高频考点

满分总结模板

三者不是谁取代谁，而是动态演进的过程：

  1. 初期 → vLLM 做性能基准，快速推向生产
  2. 深入 → KV Cache 成瓶颈时迁移到 SGLang
  3. 规模化 → 硬件锁定 NVIDIA 后投入 TensorRT-LLM
