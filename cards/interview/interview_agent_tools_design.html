IA-14 · Agent 结合 RAG 时的工具(Tools)设计

核心问题

当 Agent 与 RAG 结合时，工具设计面临特殊挑战：

  • 何时调用 RAG？ - 不是所有问题都需要检索
  • 检索什么？ - query 不等于用户原始问题
  • 结果怎么用？ - 检索结果需要筛选和验证
  • 多轮检索 - 复杂问题需要迭代式检索

工具设计决定了 Agent 能否"聪明地"使用 RAG 能力。

工具设计原则

好的 RAG 工具应该遵循三个核心原则：

原则1：职责单一

每个工具只做一件事，降低 Agent 的决策负担：

反面案例 正面案例
search_and_summarize(query) retrieve_documents(query)
"一个函数干所有事" "检索归检索，总结归 Agent 做"

原则2：语义清晰

工具的描述要让 Agent "一看就懂"：

// 差的描述
"search the database"

// 好的描述
"从公司知识库中检索与用户问题相关的文档片段。
适用场景：用户询问产品功能、技术问题、内部政策时调用。
不适用场景：闲聊、数学计算、实时信息查询。
返回：最多5个相关文档片段，每个包含内容和来源。"

原则3：容错友好

工具返回要帮助 Agent 处理异常情况：

  • 空结果 - 返回明确的提示和建议的替代查询
  • 超时 - 返回部分结果和重试建议
  • 低相关性 - 返回相关度分数，让 Agent 自行判断

工具类型设计

一个完整的 RAG 工具集通常包含以下类型：

类型1：检索工具

{
  "name": "knowledge_retrieve",
  "description": "从知识库检索相关文档",
  "parameters": {
    "query": {
      "type": "string",
      "description": "检索查询，应该是精炼的问题或关键词"
    },
    "top_k": {
      "type": "integer",
      "description": "返回结果数量，默认5",
      "default": 5
    },
    "filters": {
      "type": "object",
      "description": "可选过滤条件",
      "properties": {
        "category": "文档类别",
        "date_range": "时间范围"
      }
    }
  },
  "returns": {
    "chunks": [
      {
        "content": "文档内容",
        "source": "来源",
        "relevance_score": 0.85
      }
    ]
  }
}

类型2：查询优化工具

帮助 Agent 优化检索 query：

  • query_rewrite - 将用户问题改写为更适合检索的形式
  • query_decompose - 将复杂问题拆解为多个子查询
  • query_expand - 扩展同义词、相关术语

示例流程：

用户问："我们公司的 AI 产品今年营收如何？"

→ query_decompose 拆解为：

  • "公司 AI 产品列表"
  • "2024年 AI 产品营收数据"
  • "AI 产品销售报告"

类型3：结果处理工具

帮助 Agent 处理检索结果：

  • chunk_rerank - 对初步检索结果进行重排序
  • chunk_filter - 过滤低相关性或过时的内容
  • chunk_merge - 合并来自多个来源的相关信息

工具链编排

Agent 需要根据场景动态编排工具调用：

模式1：单次检索

适用于简单、明确的问题：

用户: "Python 的 list 有哪些内置方法？"
Agent: knowledge_retrieve(query="Python list 内置方法") → 直接回答

模式2：迭代检索

适用于复杂、需要多步推理的问题：

用户: "比较 A 产品和 B 产品的定价策略"
Agent:
  1. knowledge_retrieve(query="A 产品定价")
  2. knowledge_retrieve(query="B 产品定价")
  3. 整合对比 → 生成回答

模式3：自适应检索

Agent 判断是否需要检索：

用户: "1+1等于几？"
Agent: 不需要检索，直接回答 "2"

用户: "我们公司上个月的客户满意度是多少？"
Agent: 需要检索内部数据 → knowledge_retrieve(...)

工具实现示例

class RAGToolkit:
    def __init__(self, vector_db, reranker=None):
        self.vector_db = vector_db
        self.reranker = reranker
    
    def retrieve(self, query: str, top_k: int = 5) -> List[Chunk]:
        """基础检索"""
        results = self.vector_db.search(query, top_k=top_k * 2)
        
        # 可选：重排序
        if self.reranker:
            results = self.reranker.rerank(query, results, top_k)
        else:
            results = results[:top_k]
        
        # 添加来源追踪
        for chunk in results:
            chunk.metadata['retrieved_at'] = datetime.now()
            chunk.metadata['query'] = query
        
        return results
    
    def retrieve_with_fallback(self, query: str) -> Dict:
        """带降级策略的检索"""
        # 尝试精确检索
        results = self.retrieve(query, top_k=5)
        
        if not results or results[0].score < 0.5:
            # 降级：扩展查询重试
            expanded = self.expand_query(query)
            results = self.retrieve(expanded, top_k=5)
        
        if not results:
            return {
                "status": "no_results",
                "suggestion": f"尝试询问：{self.suggest_alternative(query)}",
                "chunks": []
            }
        
        return {
            "status": "success",
            "chunks": [c.to_dict() for c in results]
        }

高频考点

这道题考察什么？

  1. 工具设计能力 - 能否设计清晰、职责单一的工具
  2. Agent 思维 - 理解 Agent 如何决策工具调用
  3. RAG 实践 - 是否真正做过 Agent+RAG 的项目
  4. 工程化思维 - 考虑容错、优化、可维护性

标准回答思路

第一步：说明挑战 - Agent+RAG 的工具设计难点

第二步：设计原则 - 职责单一、语义清晰、容错友好

第三步：工具类型 - 检索、查询优化、结果处理

第四步：编排模式 - 单次、迭代、自适应检索

第五步：代码示例 - 展示具体实现

延伸思考

更高级的工具设计还可以考虑：

  • 工具学习 - Agent 根据历史调用记录优化工具选择
  • 动态工具注册 - 运行时添加/移除工具
  • 工具组合 - 自动生成工具链（Tool Chain）
  • 工具评估 - 监控工具调用成功率，持续优化
