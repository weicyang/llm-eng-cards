IA-01 · Agent Memory 设计

提问：Agent Memory 怎么设计？

核心观点

关键认知：Agent的记忆 ≠ 向量数据库。向量数据库只是记忆系统的"图书馆"，而非"大脑"。成熟的Agent记忆系统采用四层结构化设计，向量库只负责非结构化的历史经验检索。

向量数据库的两大陷阱

1. 模糊匹配问题

向量检索的本质是找"相似度"，而非"精确事实"：

  • 用户说"预算5万"，后改为"预算8万"
  • 向量库中两条记录语义距离都很近
  • 模型召回时新旧数据一起返回，产生冲突

2. 追加写入问题

向量数据库难以做原地更新：

  • 用户改职业、换城市、更新项目进度
  • 在向量库里都是新增记录，旧记录依然存在
  • 像"幽灵数据"干扰模型判断

向量数据库的正确使用场景

向量库不是"内存"，而是"图书馆"。只在以下三种情况使用：
  1. 非结构化超长内容：万字行业报告PDF、技术文档
  2. 数量开放增长的数据：几十万历史案例、知识库条目
  3. 模糊语义查询："帮我找找去年那个类似的营销方案"

四字心法

  • 准 — 长期事实靠结构化存储，求精准
  • 省 — 近期脉络靠轻量摘要，求省token
  • 强 — 当前语境靠滑动窗口，求即时
  • 多 — 历史经验靠向量检索，求海量

高频问答

Q1: 为什么不能把向量数据库当作Agent的唯一记忆？

向量数据库存在两个核心问题：

  1. 模糊匹配陷阱：向量检索找的是"相似度"而非"精确事实"。当用户更新信息（如预算从5万改为8万），两条记录都会被召回，导致模型困惑
  2. 追加写入问题：向量库难以原地更新，旧记录像"幽灵数据"持续干扰判断。用户画像的动态更新在向量库中逻辑上不可行

正确做法：长期事实用JSON/KV存储（可精确更新），向量库只用于历史经验和案例检索。

Q2: Agent记忆系统应该分几层？每层存什么？

成熟的Agent记忆系统分四层：

  1. 会话原数据：时区、设备、语言 → 决定回复风格
  2. 用户记忆档案卡：姓名、职业、偏好 → JSON存储，可原地更新
  3. 近期对话摘要：对话主题总结 → 省token，保持连贯
  4. 滑动窗口：最近N条原始对话 → 即时上下文

向量数据库作为"外挂图书馆"，存储历史案例和非结构化长文档。

Q3: 用户记忆档案卡为什么用JSON而不用向量库？

JSON/KV存储的优势：

  • 精确更新：用户说"我升职了"，直接修改字段值，而非新增记录
  • 唯一事实：模型读取时拿到的是最新的、无冲突的数据
  • 结构化查询：可以直接读取特定字段，无需语义匹配

这是防止Agent产生"记忆幻觉"的硬核保证。

Q4: 近期对话摘要如何生成？多久总结一次？

实现方式：

  • 触发条件：每隔N轮对话或达到一定token数时触发
  • 生成方式：让模型自己总结"我们刚才聊了什么"
  • 存储形式：轻量级清单（当前讨论主题、关键结论、待办事项）
  • 注入方式：下次对话时静态注入到prompt中

这样既省了token费用，又保持了逻辑连贯性。

Q5: 什么场景下必须使用向量数据库？

向量数据库适用于三种情况：

  1. 非结构化超长内容：万字PDF报告、技术文档、产品手册
  2. 数量开放增长的数据：几十万历史案例、FAQ库、知识库
  3. 模糊语义查询：用户记不清关键词，只能描述"大概感觉"（如"找去年类似的方案"）

在这些场景下，向量库的语义检索能力是不可替代的。
