IL-05 · Function Calling 实现原理

核心问题

大模型的Function Calling是怎么实现的？

实现原理

1. 工具描述注入

在Prompt中注入可用工具的描述：

你是一个智能助手，可以使用以下工具：
1. get_weather(city): 获取指定城市的天气
2. search_web(query): 搜索互联网
3. calculate(expression): 计算数学表达式

如果用户的问题需要使用工具，请按以下格式返回：
{"tool": "工具名", "args": {"参数": "值"}}

2. 意图识别与决策

大模型根据用户输入判断：

  • 是否需要调用工具？
  • 调用哪个工具？
  • 需要什么参数？

3. 结构化输出

大模型生成JSON格式的工具调用指令：

{"tool": "get_weather", "args": {"city": "北京"}}

关键：JSON Schema约束，确保输出可解析

4. 工具执行

系统解析JSON，调用对应的工具函数，获取返回结果。

5. 结果整合

将工具返回结果注入上下文，让大模型生成最终回答：

工具返回：北京今天晴，25°C
大模型生成：北京今天天气不错，晴朗，气温25摄氏度，适合户外活动。

训练阶段优化

  • 工具调用数据：在SFT阶段加入工具调用的训练数据
  • 格式约束：通过RLHF强化JSON格式输出
  • 参数理解：训练模型理解参数含义和约束

工程实现要点

要点做法
工具发现Tool RAG（按需检索工具描述）
输出约束JSON Schema + 预填充引导
错误处理重试机制、降级策略
安全防护工具权限控制、沙盒执行

高频考点

  1. 流程清晰：工具注入 → 意图识别 → 结构化输出 → 执行 → 整合
  2. 训练理解：SFT + RLHF如何教会模型调用工具
  3. 工程落地：Tool RAG、输出约束、错误处理、安全防护
