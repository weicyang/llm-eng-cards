一、Transformer 架构

为什么 Decoder-Only 架构赢了 Encoder-Only 和 Encoder-Decoder？

三个核心原因：①训练效率——Next Token Prediction 让 100% token 参与损失计算，而 BERT 的 MLM 只有约 15% token 参与，数据利用率低 6~7 倍；②简单性——单一 block 堆叠比两套结构更容易扩展，训练基础设施、分布式策略、推理引擎都只需针对一种 block 优化；③涌现能力——规模超过百亿量级后自发出现 in-context learning 和链式推理，这在其他架构中未被观察到。关键洞察：架构简单性是可扩展性的前提——能被极致优化的结构，最终会赢过理论上更精巧但难以规模化的结构。

描述一个 token 从输入到输出的完整旅程。

完整旅程 11 步：①分词——文本通过 BPE / SentencePiece 转为 token ids；②Embedding——整数查表得到 d_model 维向量，加上位置信息（RoPE / 绝对位置）；③Attention——token 间通过 Q/K/V 交流信息（因果掩码只看过去）；④残差连接——input + Attention 输出；⑤FFN——每个 token 独立做非线性变换与知识检索；⑥残差连接——再次 bypass；⑦重复③~⑥共 N 次（32~126 层），维度始终 [batch, seq_len, d_model]；⑧Final Norm；⑨LM Head——线性投影到 [vocab_size] 得到 logits；⑩Softmax——logits 转概率分布；⑪采样——按策略（greedy / top-k / top-p / temperature）选下一个 token。

残差连接为什么对深度 Transformer 至关重要？

残差连接解决深层网络的退化问题（更深的网络训练误差反而更高）。核心数学：反向传播时 ∂L/∂x = ∂L/∂y · (∂F/∂x + 1)，那个 +1 创建了「梯度高速公路」——即使 ∂F/∂x 很小（深层网络常见），梯度也不会消失。在 Transformer 中，每个子层（Attention 和 FFN）都包裹在残差连接中。没有残差连接，几十上百层的模型根本无法训练。附带的好处是残差让每层只需学习「增量」，训练早期网络近似恒等映射，收敛更稳。

FFN 在 Transformer 中的作用是什么？为什么说它是"知识存储"？

FFN 的作用：①引入非线性——Attention 本质是加权平均（对 value 是线性的），FFN 通过激活函数（GeLU / SwiGLU）提供非线性变换能力；②知识存储——研究发现 FFN 本质是关联记忆：第一层权重的每行相当于 Key（匹配输入模式），第二层权重的每列相当于 Value（存储对应知识）。Transformer 的事实性知识主要存在 FFN 权重里。FFN 通常占模型约 2/3 到 80% 的参数量，这也印证了它是知识的主要载体——这正是 MoE 选择对 FFN 做稀疏化、而不动 Attention 的原因。

Pre-Norm 和 Post-Norm 有什么区别？现代 LLM 用哪个？

Post-Norm 是 x = LN(x + Attn(x))，归一化在残差之后——梯度必须穿过 LayerNorm，深层训练不稳定，需要小心的 warmup。Pre-Norm 是 x = x + Attn(LN(x))，归一化在子层之前——残差通路保持「干净」，梯度可直接 bypass，训练近百层稳定。现代标准是 Pre-Norm + RMSNorm（去掉减均值，只做缩放，快约 20%）。代价是 Pre-Norm 的残差流会随层数不断累加导致数值增长，所以出口要有 Final Norm；最新趋势上 Post-Norm 配合 QK-Norm 有小幅回归，说明这不是一个已经终结的设计选择。

二、Self-Attention 机制

Self-Attention 中为什么要除以 √d_k？不缩放会怎样？

除以 √d_k 是为了控制注意力分数的方差。假设 Q 和 K 的每个分量都是均值 0、方差 1 的独立随机变量，那么 Q·K 点积的方差等于 d_k。当 d_k 较大（如 64 或 128）时，点积值的分布范围很大，导致 Softmax 输入差异极大，输出接近 one-hot 分布。这种「饱和」状态下 Softmax 的梯度接近零，训练停滞（梯度消失）。除以 √d_k 把方差归一到约 1，让 Softmax 工作在梯度健康的区域。这也解释了为什么不能简单地把 d_k 调大来增强表达力——缩放因子必须同步调整。

Self-Attention 和 Cross-Attention 有什么区别？

核心区别在于 Q、K、V 的来源。Self-Attention：Q、K、V 都来自同一个输入序列，每个 token 关注序列中的其他 token。Cross-Attention：Q 来自一个序列（如 Decoder 的当前状态），K 和 V 来自另一个序列（如 Encoder 的输出），用于两个不同序列之间的信息对齐，机器翻译和多模态融合是典型用法。在 Decoder-Only 架构中没有 Cross-Attention，只有带因果掩码的 Self-Attention——外部信息通过「拼进上下文」的方式进入模型，这也正是 RAG 能生效的结构性原因。

为什么 Self-Attention 需要 Multi-Head？单头不够吗？

单头 Attention 只能学习一种关注模式，而语言里同时存在语法依赖、指代关系、局部搭配等多种结构。Multi-Head 把 d_model 拆分为 n_heads 个子空间（如 512 拆成 8×64），每个头独立计算注意力，学习不同的关注模式，最后拼接并做一次线性投影融合。关键是参数量不变——总维度被切分而不是复制，所以多头几乎是「免费」获得的表达力提升。代价体现在推理侧：头数越多，KV Cache 越大，这正是后来 GQA / MQA 通过共享 K/V 头来优化的地方。

Self-Attention 的 O(n²) 复杂度是怎么来的？有哪些优化方法？

O(n²) 来自注意力分数矩阵——每个 token 的 Query 需要与所有 token 的 Key 做点积，产生 n×n 的分数矩阵。优化方法：①FlashAttention——IO 感知的分块计算，不实体化 n×n 矩阵，减少显存读写，实际加速 2~4 倍且显存占用从平方降到线性（注意它不改变数学结果，是精确算法）；②稀疏 Attention——只计算局部窗口加少量全局 token；③线性 Attention——用核函数近似 Softmax，复杂度降到 O(n)；④滑动窗口——每个 token 只看固定窗口内的 token。生产上首选 FlashAttention，因为它不牺牲质量。

Self-Attention 是置换不变的，这意味着什么？如何解决？

置换不变性意味着打乱输入序列的顺序，输出只是对应位置的打乱，不会改变任何值——模型无法区分「猫追狗」和「狗追猫」。解决方案是引入位置编码：①绝对位置编码——每个位置一个可学习向量，简单但难外推到训练长度之外；②RoPE（旋转位置编码）——把位置信息通过旋转矩阵注入 Q 和 K，使点积只依赖相对位置，可通过调整旋转基频外推更长上下文；③ALiBi——直接在注意力分数上加距离惩罚项。现代 LLM 普遍使用 RoPE，长上下文扩展也大多是在 RoPE 的频率上做插值或缩放。

三、KV Cache 与推理显存

什么是 KV Cache？为什么推理时需要它？

KV Cache 是推理时缓存已计算 token 的 Key 和 Value 的技术。自回归生成中，每生成一个新 token 都需要对所有已有 token 计算 Attention。如果不缓存，生成第 n 个 token 要重新计算前 n−1 个 token 的 K/V，总体是平方级的重复计算。KV Cache 把前面的 K/V 存下来，生成新 token 时只算新 token 的 Q/K/V 并与缓存拼接，把每步的计算量降为线性。代价是显存占用：2（K 和 V）× 层数 × KV 头数 × head_dim × 序列长度 × batch × 精度字节数——长上下文、大 batch 场景下它会超过模型权重本身，成为吞吐的第一瓶颈。

请当场估算一次 KV Cache 的显存占用。

套一个公式再代数字，这是应用开发者最该会算的一笔账。公式：KV 显存 = 2 × L（层数）× H_kv（KV 头数）× d_head × S（序列长度）× B（batch）× 精度字节数。示例场景：32 层、KV 头数 8（GQA）、head_dim 128、FP16（2 字节）、序列 8K、batch 16，算得 2×32×8×128×8192×16×2 ≈ 137 GB——单卡放不下，这就是为什么长上下文服务必须靠 PagedAttention 做分页管理、靠量化压缩、或者干脆降低并发。同样配置如果换成标准 MHA（32 个 KV 头），显存会变成约 550 GB，四倍差距——这一个数字就足以解释 GQA 为什么成了默认选择。

Prefill 和 Decode 两个阶段有什么本质区别？

这是理解 LLM 服务性能的关键分野。Prefill 处理输入 prompt，所有 token 可以并行计算，是计算密集型，GPU 算力被充分利用，耗时大致与输入长度成正比，它决定了首字延迟。Decode 逐个生成输出 token，每步只处理一个 token 但要读取全部模型权重和整个 KV Cache，是显存带宽密集型，算力大量闲置，耗时与输出长度成正比。两个阶段的瓶颈不同，因此优化手段也完全不同：Prefill 靠 Prompt Caching 和分块并行，Decode 靠增大 batch（连续批处理）、量化、投机解码。也正因为特性差异太大，生产系统会把两阶段拆到不同实例上分离部署。

四、MoE 架构

MoE (Mixture of Experts) 的核心思想是什么？

MoE 的核心是用多个「专家」FFN 替代单一 FFN，每次推理只激活少量专家。路由器（Router / Gating）为每个 token 决定分配给哪些专家。关键优势：①参数量大但计算量小——总参数可以做得很大，但每个 token 只经过其中一小部分；②专家自然分工——不同专家倾向学习不同领域或不同 token 类型的模式。主要挑战：①负载均衡——避免少数专家过载而其余闲置，通常靠辅助损失约束；②显存占用——所有专家的权重都必须驻留显存，省的是算力不是显存；③训练稳定性——路由决策不可导，需要特殊处理。

MoE 的"总参数量、激活参数量、显存占用"三个数为什么不能混为一谈？

这是 MoE 最容易答错的点。总参数量决定模型的知识容量与训练成本；激活参数量决定单 token 的计算量，也就是理论上的推理算力开销和成本；显存占用由总参数量决定，因为路由是逐 token 动态的，你无法预知下一个 token 会走哪个专家，所有专家都得常驻。所以一个「总参数很大、激活参数很小」的 MoE，推理算力便宜但显存门槛和稠密大模型一样高。这个区分直接决定选型结论：显卡显存受限的自部署场景，MoE 的优势会大幅缩水；而在算力受限、显存充裕的大规模服务场景，MoE 的性价比才真正体现出来。

MoE 的负载不均衡会带来什么后果？

两类后果，训练和推理各一类。训练侧的问题是专家坍缩：路由器一旦形成偏好，热门专家不断被训练变得更强、更容易被选中，冷门专家几乎不更新，最终等效于一个小得多的稠密模型，白付了大参数量的训练成本。缓解手段是加负载均衡辅助损失，惩罚分配不均，并给每个专家设容量上限，超出的 token 溢出（丢弃或走残差直通）。推理侧的问题是并行效率塌陷：专家分布在不同设备上时，热门专家所在的卡成为瓶颈，其他卡在等它，同时跨设备的 token 路由带来额外通信开销。所以 MoE 的工程复杂度主要不在算法，而在专家并行的通信与均衡。

五、Temperature 与解码策略

Temperature=0 时输出为什么还不唯一？

数学上 T=0 等价于 argmax，相同输入必然得到相同输出。但工程实现中：①GPU 并行归约时线程执行顺序不确定；②浮点数加法不满足结合律，不同累加顺序导致不同舍入误差；③FP16 / BF16 精度有限，极接近的 logit 可能被舍入为相同值；④当 top-1 与 top-2 的 logit 差距小于精度时，误差可能导致排名反转；⑤贪心解码只选第一名，一旦选错后续路径完全分叉，形成「数值蝴蝶效应」。另一个常被忽略的来源是批处理组成：同一请求在不同 batch 中被填充和归约的方式不同，也会带来微小差异。工业界方案：argmax 短路 + FP32 logits。

Top-K 和 Top-P (Nucleus Sampling) 有什么区别？

Top-K 固定保留概率最高的 K 个 token，缺点是 K 固定——分布集中时 K 太大（把低质量 token 也纳入候选），分布平坦时 K 太小（丢失好候选）。Top-P 动态保留累积概率达到 P 的最小 token 集合，因此是自适应的——分布集中时候选少，分布平坦时候选多。实际使用通常组合：先 Top-K 截断（设一个安全上限，防止长尾里出现离谱 token），再 Top-P 过滤（自适应收敛），最后按重新归一化的概率采样。顺序很重要：先截断再归一化，否则被裁掉的概率质量分配不正确。

如何在生产环境中保证 LLM 输出的确定性？

分层保障：①argmax 短路——T=0 时直接执行 argmax，跳过 softmax 和采样，避免采样环节引入随机性；②FP32 logits——LM Head 输出用 FP32 计算，有效精度从约 3 位提升到约 7 位，代价仅约 2%；③锁死随机种子——固定 Python / NumPy / 框架的显式随机源；④GPU 确定性模式——强制固定并行归约顺序，但性能下降 10%~30%；⑤固定批处理形态——避免同一请求因 batch 组成不同而走不同的归约路径。生产环境推荐组合是前两项，性价比最高；要求逐比特可复现时才付出第四、五项的性能代价。

Temperature 该怎么设？调高调低分别换来什么？

温度作用在 softmax 前的 logits 上：logits/T。T 小于 1 会放大差距使分布更尖锐（更确定、更保守），T 大于 1 会压平分布（更多样、更容易跑偏）。按任务分档：结构化抽取 / 分类 / 工具参数生成用 0~0.2，任何随机性在这里都是纯风险；知识问答 / 摘要用 0.2~0.5，需要一点措辞灵活但不能编；创意写作 / 头脑风暴用 0.7~1.0；需要多样候选再投票（Self-Consistency）时反而必须调高到 0.7 以上，否则采样出的多条路径完全相同，投票失去意义。要避免的做法是同时把温度和 Top-P 都调得很极端，两者叠加后的实际效果很难预测。

六、Scaling Laws 与涌现

什么是 Chinchilla Scaling Law？它和 Kaplan Law 有什么区别？

Kaplan Law（2020）认为模型性能主要取决于参数量，参数越多越好，数据可以相对少些。Chinchilla Law（2022）修正了这个结论：在固定训练算力下，参数量和数据量应该同步增长，最优配比约为 20 tokens / 参数。例如 7B 参数的模型应该用约 140B tokens 训练。Chinchilla 证明了此前很多大模型是「参数过多、数据不足」的。实践指导：训练预算固定时应同时增加模型大小和数据量，而不是只堆参数。补充一个现实修正——如果考虑推理成本，最优点会进一步偏向「更小的模型、更多的数据」，因为小模型要服务很久；Inference Scaling（推理时增加计算量换质量）是最新的独立维度。

什么是 Emergent Abilities（涌现能力）？

涌现能力指模型在规模超过某个阈值后突然出现的能力，在小模型中观察不到。典型例子：①in-context learning——给几个例子就能学会新任务，不需要微调；②链式推理——模型自发进行多步推理；③few-shot 学习——小模型 few-shot 效果差，大模型 few-shot 接近微调效果。争议在于：有研究认为部分「涌现」是评估指标选择造成的假象——使用连续指标（而非准确率这类阈值型指标）时，能力提升是平滑的。这个争议本身值得在面试里提一句，因为它体现你读的是原始论证而不是二手结论；但 in-context learning 的涌现性仍被广泛认可。

Scaling Laws 对应用开发者有什么实际意义？

三个可以直接用上的结论。第一，不要指望换更大的模型解决数据问题：损失随规模是幂律下降而不是线性，规模翻倍带来的提升往往只有几个百分点，而成本翻倍甚至更多，这也是「八成 Bad Case 不该靠换模型修」的理论依据。第二，小模型 + 好数据 / 好检索经常打赢大模型：因为对特定任务来说，上下文里有没有正确资料的影响远大于参数量差异。第三，推理时扩展是新的性价比洼地：让小模型多想几步、采样多条路径再投票，往往比换一个大模型更便宜，前提是任务的答案可以被验证或归一化比较。

为什么"长上下文"没有取代 RAG？

四个原因叠加。成本：把 200K 上下文填满，每次请求都按满额计费，而 RAG 只送进几千 token 的相关片段，成本差两个数量级。延迟：Prefill 耗时与输入长度成正比，长输入直接推高首字延迟。有效性：受 Lost in the Middle 影响，上下文中无关内容占比越高，模型抓错重点的概率越大，实测很多任务在上下文变长后准确率反而下降。可治理性：RAG 能做权限过滤、来源溯源、知识热更新，这些是企业场景的硬需求，长上下文一概不提供。正确的关系是互补而非替代：用检索决定「放什么进去」，用长上下文放宽「能放多少」的上限。

示例场景：某问答服务从 8K 上下文换到 128K，把整份手册全塞进去，期望「不用做检索了」。实测结果是准确率从 84% 降到 76%，单次请求成本涨约 14 倍，首字延迟从 0.9 秒涨到 6.3 秒。改回「检索 Top-5 片段 + 8K 上下文」并加 Rerank 后，准确率升到 91%，成本回落到原水平。这个对照说明：上下文容量是上限而不是策略，决定质量的仍然是「放进去的是不是对的东西」。

答题策略 Do / Don't

  • 把每道题挂回「token 旅程」这张骨架图，回答自带结构
  • 能当场算显存账：KV Cache 公式代入数字，比背概念更有说服力
  • 区分容易混的三元组：总参数 / 激活参数 / 显存，Prefill / Decode，精确 / 近似 Attention
  • 每个设计选择都答「换掉了什么、代价是什么」，而不只是「现在流行什么」
  • 把原理落到工程决策上：温度分档、长上下文 vs RAG、要不要上 MoE
  • 把 FlashAttention 说成近似算法，它是精确的，只是换了计算与访存方式
  • 用 MoE 的总参数量比能力，或以为显存按激活参数量算
  • 说「T=0 就完全确定」，忽略浮点归约顺序与批处理组成带来的差异
  • 笼统说「长上下文会取代 RAG」，答不出成本、延迟、有效性、可治理性四笔账
  • 只背结论不提争议，比如把涌现能力讲成已被完全证实的事实
