一、RAG 热更新怎么做

字幕里的核心判断是：RAG 热更新不是简单增删改查，而是企业级知识库的一致性问题。

视频把答案拆成了三块：第一是基础能力，包括增量索引、指纹校验、Embedding 重算和原子化 upsert；第二是工程痛点，包括新旧知识冲突、GraphRAG 重算成本和缓存残留；第三是落地方案，包括影子索引、蓝绿切换、冷热分层和逻辑删除。

这题的高分点在于能说出“不停机更新 + 版本治理 + 缓存失效 + 长期记忆一致性”是一套联动系统。

二、几百页 PDF 合同怎么喂给大模型

字幕里直接反驳了“上 RAG 就行”的初级答案，强调必须先识别业务难点，再按任务目标选择架构。

这期视频把问题拆成三大难点：复杂版面解析、长距离依赖、以及合同场景对零幻觉的强要求。对应地，它给了三条路线：条款级精准问答走增强型 RAG；整篇审计、汇总和一致性核查走 Map-Reduce；如果长上下文模型足够强，则可配合缓存直接处理长文档。

这题的关键不是背方案名，而是知道什么时候该用增强型 RAG，什么时候必须切到 Map-Reduce。

关联知识点：

  • Agent RAG 处理复杂 PDF
  • PDF 数据清洗（RAG 场景）
  • Chunking 策略

三、多模态 RAG 图片检索如何实现

字幕给出的核心观点是：传统“图转文再检索”会丢掉布局、空间关系和图像细节，多模态 RAG 更理想的路线是直接把页面当图像处理。

视频重点讲的是一类视觉 RAG / 类 ColPali 路线：把整页切成 patch，用视觉语言模型编码成多向量表示，再和文本查询做跨模态匹配。它的优势是保留像素级映射和空间结构，代价则是存储成本和检索延迟显著上升，因此生产上还要叠加量化压缩、元数据过滤和混合召回。

方案适用问题优点限制
纯视觉向量检索找相似图片直观、快解释性弱
OCR + 描述生成图表、截图、文档页利于问答和引用前处理成本更高
混合检索生产场景主流召回更稳、解释更强链路更复杂

关联知识点：

  • 多模态大模型
  • 数据预处理
  • PDF / 图像清洗与结构重建

四、什么场景必须用 GraphRAG

字幕里给出的边界非常清楚：GraphRAG 不是普通 RAG 的全面替代，而是专门解决“关系结构必须显式推理”的问题。

视频把必须用 GraphRAG 的场景总结为四类：全局总结、多跳推理、同名实体消歧、隐性关系挖掘。它反复强调，普通向量 RAG 最大的问题是只拿碎片、上下文断裂，而 GraphRAG 通过实体、关系和属性组成显式逻辑网，才有机会做可解释检索。

如果问题只是“找最相关的一段文本”，GraphRAG 往往太重；如果问题要找关系链、全景视图或跨实体逻辑，就该上 GraphRAG 或混合路由。

  • GraphRAG 指南
  • GraphRAG 多跳推理
  • 知识图谱基础
