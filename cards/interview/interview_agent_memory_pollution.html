IA-18 · Agent 记忆污染处置

提问：Agent 把错误信息写进记忆后要怎么办？

核心观点

核心结论：这不是“清缓存”问题，而是记忆污染问题。错误信息一旦进入长期记忆，就会持续影响后续决策，形成系统性的认知受损。

为什么它比脏缓存更严重

传统缓存脏数据通常只影响一次读取，但长期记忆会被模型反复使用，甚至被继续总结、扩写、传播。字幕里把这种情况描述成“错误前提驱动后续决策”，本质已经接近配置污染或知识污染。

  • 错误记忆会在后续推理中被当成事实前提
  • 污染内容可能经过摘要与抽取进一步固化
  • 如果长期记忆还能被其他 Agent 共享，影响范围会继续放大

治理框架

阶段目标手段
写入前防止错误进入长期记忆准入控制、来源校验、强反馈触发、风险分类
存储中降低污染扩散面索引与内容分离、容量约束、漂移防护、可回滚版本
事故后恢复系统认知Trace Log 溯源、原子回滚、补偿任务、认知重置

这题的高阶加分点

字幕特别提到两个工程化视角。第一，错误记忆可能来自间接提示注入，不一定只是模型自己总结错。第二，长期记忆本质上已经接近“动态配置层”，所以要像治理生产配置一样治理它。

高频问答

Q1: Agent 把错误写进记忆后，第一步应该做什么？

第一步不是直接删库，而是隔离污染面并做全链路溯源。要先查清错误记忆是怎么写进去的、影响了哪些推理链路、有没有被二次加工成其他摘要或索引。

Q2: 如何从架构上降低记忆污染风险？

核心做法是写入前准入控制、存储时保留版本、索引和原文分离、限制长期记忆容量并监控漂移。这样即使出现污染，也能追溯和回滚，而不是彻底失控。

Q3: 为什么要强调“认知重置”？

因为只删掉一条错误记忆还不够。如果模型已经基于这条错误记忆生成了任务计划、摘要或后续推理结果，系统整体认知状态已经受损，需要从健康快照恢复或者重建关键上下文。

Q4: 这题怎么体现安全意识？

可以主动补一句：错误记忆未必来自普通报错，也可能来自间接提示注入。只要外部恶意内容被 Agent 当作长期事实写入记忆，后果就会比一次 Prompt 注入更持久。
