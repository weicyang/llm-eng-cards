一、海量 Skill 为什么不能直接塞进 Prompt

字幕里的核心判断非常清楚：Skill 太多时，问题不只是 token 成本，而是模型的注意力预算被打散，最终工具选择准确率下降。

视频把解决方案抽成了三层渐进式披露架构：L1 元数据索引层 负责快速知道“有哪些 Skill”；L2 意图理解层 负责决定当前场景要不要深入；L3 深水执行层 才去加载完整 Skill 说明甚至接上 RAG。这样做的目标不是让模型知道所有工具，而是让它在正确的时刻知道足够的信息。

这题的高分回答不是“做工具 RAG”，而是“按需逐层暴露 Skill，控制上下文预算与决策复杂度”。

关联知识点：

  • 上百 Skill 塞爆 System Prompt 优化
  • Skill 架构设计
  • Agent Skills 基础

二、Agent 幂等性为什么是工作流级能力

字幕把幂等性的本质讲得很直白：允许重复执行，但只允许一次有效副作用。

视频强调，Agent 比普通接口更需要幂等，因为它天然运行在会重试、会恢复、会重复投递的环境里。答案不该只停留在“加唯一键”，而要拆成三层：请求层用 Idempotency Key 控入口，工具层防止重复副作用，流程层则依赖状态机、Checkpoint 和补偿机制保证长链路稳定。

这题的关键不是定义，而是能不能把 Request ID、状态机、补偿、Exactly Once / At Least Once 串成一套工程答案。

关联知识点：

  • AI 系统幂等设计
  • Agent 调用工具可靠性
  • Agent Checkpoint / 恢复点

三、错误信息写进记忆后，先隔离再修复

字幕里把这个问题直接升级成“记忆污染”，而不是普通缓存脏数据问题。

一旦错误信息被写进长期记忆，后续推理就会建立在错误前提上，形成“认知受损”。视频给出的高阶回答不是简单清缓存，而是三段式治理：写入前做准入控制，存储时做索引与内容分离、容量约束与漂移防护，出事故后再做全链路溯源、原子回滚和认知重置。

这题的加分点是提到 间接提示注入、Trace Log、健康快照 和认知重置，而不只是“删掉错误记忆”。

关联知识点：

  • 记忆污染防御
  • 记忆安全设计
  • Claude Code 记忆系统

四、哪些长期记忆值得写入数据库

字幕里给出的判断标准很明确：长期记忆绝不能存所有聊天记录，只该存未来高复用、低歧义、会持续影响决策的信息。

适合入库原因不适合直接入库
用户画像、偏好、权限、长期目标高复用、低歧义、适合结构化查询一次性情绪、临时报错、未确认猜测
稳定业务规则后续会持续影响决策未验证的模型推断
需要跨会话保持的事实下次仍然要精确命中当前会话内的短暂上下文

字幕还补了两层很工程化的细节：一是写入触发条件，通常来自强反馈、工作流闭环或异步自评高分；二是存储要分层，热记忆进上下文、近期记忆进向量库、长期冷记忆进关系库。

关联知识点：

  • 长期记忆架构
  • Agent Memory 设计
  • 记忆撑爆解决方案

五、“字节 Agent 二面”真正考什么

字幕显示，这期本质上是 10 道 Agent 平台工程高频问答速通，重点不是背概念，而是把模型、状态、协议、工具和租户隔离串成平台级答案。

视频覆盖了多模型统一协议与适配器、智能路由网关、双缓冲热切换、无状态多租户并发、Session 与 JWT 绑定、工具调用闭环，以及 SSE 流式返回协议。它想考的不是“你知道 tool_calls 吗”，而是“你能不能设计一个可以跑在线业务的 Agent 平台”。

这题最好的答法，是把模型接入层、运行时层、会话状态层和流式协议层连成一个完整系统。

关联知识点：

  • Agent 架构
  • Agent 架构有几部分
  • Agent vs Workflow
  • ReAct Agent 核心抓手
