IA-10 · Agent 调用工具可靠性

提问：如何保证 Agent 调用工具（Function Calling）的可靠性？

核心观点

核心公式：可靠性 = 高质量定义 + 严格代码约束 × 闭环反思重试机制。不能把赌注全压在模型智商上，要靠工程手段兜底。四层架构：结构化定义层 → 推理策略层 → 执行护栏层 → 自愈修复层。

四层防御架构

Layer 1: 结构化定义层

  • 强类型约束：用 JSON Schema 焊死字段（字符串/数字/枚举/是否可空）
  • 语义描述优化：函数描述是给模型看的说明书，像写 prompt 一样优化它

Layer 2: 推理策略层

  • 思维链（CoT）：强制要求调工具前先输出思考过程，挡掉 80% 低级错误
  • Few-shot 示例：给模型正确/错误调用模板，有样学样
  • 工具检索 RAG：100 个工具全塞给模型会干烧，用语义检索只给最相关的几个

Layer 3: 执行护栏层

  • Pydantic 自动校验：模型输出的数据先过代码逻辑、格式、参数完整性检查，不过关直接拦截
  • 人机交互：高风险操作（转账、改密码）必须弹窗让用户确认

Layer 4: 自愈修复层

  • 错误回传：工具执行报错后把报错信息原封不动喂回模型，让它根据报错重新生成。第二次大概率正确
  • 状态反思：工具跑完后让模型检查"拿到的数据真的解决用户问题了吗"，不符预期就重新规划

高频问答

Q1: 模型还没想清楚就直接调工具怎么办？

用思维链（CoT）：在提示词里强制要求"调工具之前必须先输出思考过程"，让模型自己先捋一遍逻辑。这种"慢思考"能挡掉 80% 的低级错误。再配合 few-shot 示例（正确/错误调用模板），模型模仿能力强，可靠性蹭就上来了。

Q2: Agent 有 100 个工具，模型选错工具怎么办？

用工具检索 RAG：先根据用户的话做语义检索，只把最相关的 3-5 个工具塞给模型。少即是多，干扰少了自然就准了。全塞进去模型会"干烧"，注意力分散导致选错。

Q3: 模型输出的 JSON 校验失败怎么办？

自愈修复层：(1) 错误回传：把报错信息（如"日期格式不对"）原封不动喂回模型，让它根据报错重新生成，第二次大概率正确；(2) 状态反思：工具跑完后让模型检查数据是否真的解决了用户问题，不符预期就重新规划。这是闭环修复，比简单重试有效得多。

Q4: 高风险工具操作怎么保护？

执行护栏层加人机交互：涉及转账、改密码、删除数据等高风险操作，必须弹窗让用户确认。不能让 Agent 成为脱缰的野马。同时在 Pydantic 校验不通过时直接拦截，不给执行机会。
