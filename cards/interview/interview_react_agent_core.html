IA-06 · ReAct Agent 核心抓手

提问：ReAct Agent 解决复杂问题的核心抓手是什么？

核心观点

一句话总结：ReAct 的核心抓手是"推理与行动的交替协同"以及由此产生的动态闭环。Thought → Action → Observation 循环，让模型有了观察世界的感官和操作工具的肢体。

ReAct 核心循环

环节作用类比
Thought（推理）在大脑里规划：第一步该干嘛想
Action（行动）调用工具（搜索、查数据库）做
Observation（观察）看工具返回结果，判断对不对看

形成"想一步做一步看一眼"的动态反馈闭环——哪怕第一步走歪了，通过观察也能在下一步纠正回来。

四大工程坑与解法

1. 无限死循环

模型搜出无用结果 → 一直搜 → token 哗哗掉

解法：max_iterations（如10轮强行掐断）+ 连续两次相同动作检测 → 喂强力指令换思路

2. 上下文爆炸

每步都把之前推理过程传给模型 + 搜索结果又臭又长

解法：信息提纯（小模型摘要/RAG只提取关键片段）+ 滑动窗口只留最新几轮

3. 工具调用格式错误

模型"手抖"生成错误 JSON 或缺参数

解法：优先用原生 Function Calling 接口（强约束）+ 报错信息作为 Observation 返回给模型做自愈

4. 错误级联

第一步推理错 → 后面全盘皆输

进阶方案：

  • Reflection（反思）：失败后先写反思报告，总结为什么失败
  • Plan-and-Solve：先规划大框架拆解子任务，再逐步执行

高频问答

Q1: ReAct 的核心抓手是什么？

推理与行动的交替协同，以及由此产生的动态闭环。三个环节 Thought → Action → Observation 形成反馈回路：模型先规划（想），再调用工具（做），再观察结果（看）。即使第一步走歪了，通过观察也能在下一步纠正。这就是 ReAct 能处理单次生成搞不定的复杂任务的原因。

Q2: ReAct Agent 会遇到哪些工程坑？

四大坑：(1) 死循环 → max_iterations + 重复动作检测；(2) 上下文爆炸 → 信息提纯 + 滑动窗口；(3) 工具格式错误 → 原生 Function Calling + 自愈机制（报错作为 Observation 返回）；(4) 错误级联 → Reflection（反思）或 Plan-and-Solve（先规划后执行）。

Q3: 工具调用报错时的"自愈机制"是什么？

不要把报错直接抛异常，而是把错误信息作为 Observation 返回给模型，告诉它"你刚才调工具报错了，你自己修一下"。模型会根据报错信息自动调整参数或换工具重试。这种自愈机制在长链路任务里是救命稻草。

Q4: Reflection 和 Plan-and-Solve 分别解决什么问题？

Reflection：解决"重复犯同样错误"的问题。模型失败后不急着重做，先写反思报告总结失败原因，下次避免同类错误。Plan-and-Solve：解决"走一步算一步导致方向跑偏"的问题。先在大框架上拆解子任务（行程表），再逐步执行每天的行程。两者都提升了容错率。

Q5: 回答的三个维度是什么？

(1) 理论高度：推理与行动的协同闭环；(2) 工程深度：死循环、上下文压缩、自愈机制等具体坑和填坑方案；(3) 方案广度：Reflection 和 Plan-and-Solve 展现对 Agent 演变架构的认知。三层递进证明你是真正做过大模型工程落地的。
