IA-20 · 字节 Agent 平台高频题

提问：字节 Agent 平台主要考察什么？

核心观点

核心结论：这类二面不再考单点概念，而是考你能不能把模型接入、状态管理、工具调用、租户隔离和 SSE 流式协议串成一套可落地的平台方案。

视频覆盖的五条主线

主线考点考察意图
模型接入层统一协议、适配器、智能路由网关看你是否具备多模型平台抽象能力
配置与发布配置热切换、双缓冲更新看你是否考虑线上稳定性
运行时状态无状态服务、Session ID、JWT、Redis看你如何承载多用户并发
工具调用闭环tool_calls、观察结果回灌、失败恢复看你是否理解 Agent 真正的执行链路
流式输出协议SSE、text/event-stream、X-Accel-Buffering看你能否做在线产品级交互

高分回答方式

这题最容易答散。正确方式不是一问一答式背术语，而是主动把平台拆成几层：模型接入层、路由层、会话状态层、工具执行层、流式协议层。只要能把这几层讲清楚，很多追问都能自然展开。

高频问答

Q1: 多模型接入为什么要做适配器层？

因为不同模型厂商的协议、参数和返回格式都不一致。适配器层的作用是把外部差异收敛成统一内部协议，上层运行时才能稳定复用路由、记忆、工具调用和监控逻辑。

Q2: Agent 服务为什么通常设计成无状态？

为了横向扩容和多租户并发。会话状态放到 Redis 或数据库，服务实例只负责处理请求，这样才能做弹性扩缩容、限流和故障转移。

Q3: 工具调用链路怎么描述才像工程回答？

可以按“模型产生 tool_calls → 执行器调用工具 → 结果写回 observation → 模型继续推理”这条闭环来讲，并补上失败重试、超时、幂等和日志追踪，体现你不是只会说一个 API 名字。

Q4: SSE 这块为什么常被追问？

因为它能直接区分“会调模型 API”和“能做在线产品”的人。回答时可以带上 text/event-stream、保持连接、逐块推送、代理层关闭缓冲等细节，说明你做过真实流式链路。
