答题策略总纲

  • 先给 30 秒结论，列出 2~4 个关键词，然后停下来等待追问，不要一口气背完
  • 关键结论带数字：Chinchilla 1:20 配比、7B 全量微调需 80GB+ 显存、INT4 掉点约 1%
  • 把话题引向自己的项目："我们当时评估了 LoRA 和全量，最后因为多租户热切换选了 LoRA"
  • 主动暴露边界与代价："这个方案的前提是……代价是……"，展示 trade-off 思维
  • 名词堆砌式背诵：一连串术语却不解释机制，一问细节就崩
  • 绝对化结论："DPO 完全替代 PPO"、"INT4 一定够用"——工程问题几乎都有前提
  • 不懂硬答：宁可说"这块我了解到 X 层级，更深的没实践过"，再补相邻知识救场
  • 只谈效果不谈成本：不提显存、延迟、token 开销的答案在工程面里不值钱

一、认知与架构基础（Q1-Q5）

Q1 · 什么是大语言模型（LLM）

LLM 是用「下一个 token 预测」（next-token prediction）目标在海量文本上训练出来的自回归概率模型。它通过数十亿到万亿级参数把语言规律与世界知识压缩进权重，再经过 SFT 与对齐学会遵循指令、安全对话。它本质上是一台续写机器，而不是数据库或搜索引擎。

理解 LLM 要抓住一条主线：预训练决定能力上限，对齐决定行为形态。预训练只做一件事——给定前文，预测下一个 token 的分布；这个看似简单的目标迫使模型学会语法、常识乃至推理的统计结构。规模跨过某个门槛后，还会自发出现 In-Context Learning（给几个例子就会做新任务）和思维链等涌现能力，这些能力在小模型上不存在。

架构上，现代 LLM 几乎清一色选择 Decoder-only：CLM 目标让每个 token 都参与损失计算，数据利用率远高于 BERT 式 MLM（后者只有约 15% 的掩码 token 产生梯度）；单层堆叠结构更简单，训练与推理基础设施只需优化一种 block，更容易 scale。

同时要清楚它的先天局限：知识有截止日期、没有内置事实核验机制（这是幻觉的根源之一）、输出是概率采样而非确定性计算。这些局限直接引出后面 RAG、幻觉治理、CoT 等所有应用层话题。

追问问题回答要点
LLM 和传统 NLP 模型的本质区别？统一范式：一个生成式基座 + prompt/微调适配所有下游任务，不再为每个任务设计结构和标注；能力随规模涌现
为什么"预测下一个 token"能训出智能？要在开放语料上把预测做准，模型必须隐式建模因果、常识与推理结构——压缩即理解
为什么 Decoder-only 胜出？CLM 数据利用率高（全部 token 算损失）、结构简单易扩展、规模上来后涌现 ICL/CoT
LLM 为什么会一本正经地胡说？训练目标是概率续写而非事实检索，权重里是压缩的模糊记忆，没有真值核验环节
❌ 典型错误答法："LLM 就是背下了整个互联网文本的超大数据库。"
✅ 正确表述：LLM 是把语料的统计规律压缩进参数的概率生成模型，知识是有损压缩的模糊记忆，无法精确检索，这正是幻觉的来源，也是 RAG 存在的意义。

Q2 · Transformer 架构

Transformer（2017，Attention Is All You Need）完全抛弃循环结构，用自注意力一步完成全局依赖建模，天然支持并行训练。核心配方：Q/K/V 三个独立线性投影 + √d_k 缩放点积注意力 + 多头 + FFN，每个子层配残差连接与 LayerNorm，位置信息靠位置编码注入。现代 LLM 采用它的 Decoder-only 变体。
追问问题回答要点
为什么要除以 √d_k？Q·K 点积方差随维度 d_k 线性增大，值过大导致 softmax 趋近 one-hot、梯度消失；缩放把方差拉回 ~1
为什么要多头？不同头在不同子空间学不同关注模式（语法/语义/位置），参数量与单头相当，表达力更强
FFN 的作用？引入非线性 + 充当"知识仓库"：约 80% 参数在 FFN，事实知识主要存在这里
残差连接为什么关键？反向传播时梯度有一条 +1 的直通路径，深层（96~126 层）才训得动；Pre-Norm + RMSNorm 是主流搭配
对比 RNN 的优劣？训练可并行、任意两 token 路径长度 O(1)；代价是注意力计算 O(N²)，长序列贵——引出 FlashAttention、滑窗等优化
❌ 典型错误答法："注意力层完成了模型的主要计算和特征提取。"
✅ 正确表述：Attention 负责 token 之间的信息混合（where to look），FFN 负责对单个 token 做非线性变换与知识检索（what to do），两者分工互补，缺一不可。

Q3 · MHA / MQA / GQA / FlashAttention

这四个名词分两层：MHA/MQA/GQA 是结构层优化，决定 KV Cache 有多少份；FlashAttention 是实现层优化，不改变数学结果。MHA 每个头独占 K/V；MQA 全部头共享一份 K/V，KV 显存降到 1/H 但质量掉 2~5%；GQA 折中为按组共享，损失通常 <0.5%，是 Llama2/3、Mistral 等现代模型的标配。
方案KV 份数KV Cache 相对大小质量影响代表模型
MHAH 份（每头一份）100%基线GPT-3、Llama-2 7B
MQA1 份（全头共享）1/H掉 2~5%Falcon、StarCoder
GQAG 份（按组共享）G/H<0.5%Llama2/3 70B、Mistral
追问问题回答要点
MQA 为什么掉点？K/V 容量被压缩到 1/H，各头看到的是同一份表征，注意力多样性下降
FlashAttention 是近似算法吗？不是。分块（tiling）+ 在线 softmax 只是重排 IO 顺序，结果与标准 attention 严格一致
它优化的是什么？HBM 读写次数：避免物化 N×N 分数矩阵，显存 O(N²)→O(N)，实测加速 2~4x；计算量仍是 O(N²)
KV Cache 大小怎么估？2(K/V) × 层数 × KV头数 × d_head × 序列长 × 字节数——GQA 的 KV 头数远小于注意力头数，这就是它省显存的原因
还有更激进的方案吗？MLA（DeepSeek）：把 KV 投影到低秩潜空间再压缩；注意结构层与实现层优化可叠加而非互斥
❌ 典型错误答法："FlashAttention 用近似计算换速度，把复杂度从 O(N²) 降到了 O(N)。"
✅ 正确表述：FlashAttention 是精确计算，只优化内存访问模式；计算复杂度仍是 O(N²)，降为 O(N) 的是显存占用。

Q4 · 位置编码

自注意力本身是置换不变的——打乱输入顺序输出只跟着打乱，模型分不清"猫追狗"和"狗追猫"，所以必须显式注入位置信息。原始 Transformer 用固定的 sin/cos 绝对编码，外推能力差；RoPE 把位置编进 Q/K 的旋转角，点积后只剩相对位置，是当前主流（Llama/Qwen/Mistral）；ALiBi 则直接在注意力分数上加距离惩罚。长文本外推靠 NTK-aware、YaRN、位置插值（PI）等改造 RoPE 的方案。
追问问题回答要点
RoPE 为什么能表达相对位置？位置 m、n 的 Q/K 各自旋转后做点积，绝对角度抵消，只剩相位差 (m−n)，注意力天然感知相对距离
什么是长度外推问题？推理长度超过训练长度时，困惑度陡增甚至崩溃——位置信号进入未见过的区域
PI / NTK / YaRN 的区别？PI 线性压缩位置索引；NTK 调旋转基频做非均匀缩放（高频少动、低频多动）；YaRN 组合 NTK + 注意力温度 + 分段插值，长文效果最好
ALiBi 的优势？不引入任何向量，只在分数上按距离加线性惩罚，训练短测试长也能平稳泛化
❌ 典型错误答法："sin/cos 位置编码是训练出来的可学习参数。"
✅ 正确表述：原始 sin/cos 是固定公式、不含可学习参数；可学习的是 GPT-2 式位置嵌入，但它有最大长度硬上限，外推更差。

Q5 · 分词器（Tokenizer）

分词器把文本切成模型词表里的离散 token，直接决定上下文成本、多语言能力与代码/数字处理质量。主流算法是 BPE：从字符出发反复合并最高频相邻对，得到子词词表，兼顾词表大小与未登录词。GPT-2 词表 50257，Llama3 扩到 128000；粗估 1000 个汉字约消耗 1000~1500 个 token，英文约 1000 token ≈ 750 词。
追问问题回答要点
BPE 和 WordPiece 的区别？BPE 按频率贪心合并；WordPiece 按合并后语料似然增益选对，思路略不同，工程效果接近
为什么不用字级或词级？字级词表小但序列极长、语义稀疏；词级词表爆炸且未登录词多；子词是折中甜点
词表大小有什么影响？词表小→同文本 token 多→上下文与算力成本高；词表大→embedding 与 LM head 参数多；非英语场景分词效率直接决定 API 账单
特殊 token 有哪些？结束符、chat 模板里的角色标记、工具调用标记；微调时新增特殊 token 需要扩 embedding 并继续训练
❌ 典型错误答法："1 个 token 大约等于 1 个英文单词或 1 个汉字，各语言通用。"
✅ 正确表述：token 与文字没有固定换算：英文约 0.75 词/token，中文常见 1~2 字/token（视词表而定），数字、URL、代码常被切碎，成本估算必须按语言实测。

二、训练全景与微调对齐（Q6-Q11）

Q6 · LLM 训练三阶段

现代 LLM 训练是三段流水线：①预训练——在海量语料上做 next-token prediction，学语言规律与世界知识（GPT-3 约 300B tokens，Llama3 达 15T）；②SFT——用高质量指令数据教会模型"怎么好好回答问题"；③对齐——用 RLHF/DPO 教会模型"什么样的回答更好更安全"。三阶段缺一不可。
追问问题回答要点
预训练数据的关键是什么？质量 > 数量：去重、过滤低质与有害内容、配比多语言与代码；数据决定能力上限
SFT 是数据越多越好吗？不是，质量远比数量重要，几千条高质量指令就能显著改变行为（LIMA 用约 1000 条示范）
跳过对齐会怎样？模型只是"续写器"：不遵循指令、格式混乱、安全性差，无法直接作为助手产品
训练资源量级怎么记？7B 全量微调需约 8×80GB 级别显存（权重+梯度+优化器状态）；预训练则是千卡级、以月计的集群工程
❌ 典型错误答法："给模型注入新的领域知识，做个 SFT 就行。"
✅ 正确表述：SFT 主要对齐行为与格式，知识注入更可靠的路径是 RAG 或领域继续预训练；用 SFT 硬灌知识效率低且易引发灾难性遗忘。

Q7 · Scaling Law

Scaling Law 描述 loss 与参数量 N、数据量 D、算力 C 之间的幂律关系，让训练大模型从玄学变成可预算的工程。Kaplan（2020）主张参数优先；Chinchilla（2022）修正为参数与数据按约 1:20 配比同步扩展；而 Llama3 时代又反过来大幅过训练，用小模型吃超量数据换推理侧的低成本。
数字案例①：Chinchilla 70B 按 1:20 配比吃 1.4T tokens，效果超过按 Kaplan 思路训练的 GPT-3（175B 参数、仅 300B tokens）与 Gopher（280B 参数）——证明此前的大模型普遍"数据没喂饱"。
数字案例②：Llama3 8B 用 15T tokens 训练，参数数据比高达 1:1875，远超 Chinchilla 最优——因为 Chinchilla 优化的是训练成本，而实际部署优化的是推理成本，小模型过训练让每次推理更便宜；Qwen3-0.6B 更是用到 36T tokens。
追问问题回答要点
Chinchilla 推翻了 Kaplan 什么？Kaplan 未控制好 LR schedule 与训练步数，低估了数据收益；修正后最优分配从 N⁰·⁷³/D⁰·²⁷ 变为 N⁰·⁵/D⁰·⁵
既然 Chinchilla 最优，为什么还在过训练？Chinchilla 最优针对"训练花多少钱"；模型训完要服务亿万次请求，推理成本占大头，小模型 + 更多数据总体更划算
涌现能力是真的吗？有争议：部分"突变"是指标选择造成的测量假象（Mirage 论文），但 ICL、CoT 等能力确实随规模出现，工程上按"规模是能力的前提"理解即可
实践中怎么用？用小模型集群拟合幂律曲线，外推目标规模的预期 loss，再决定预算是否值得投
❌ 典型错误答法："Scaling Law 说明只要无限堆参数和数据，性能就会无限提升。"
✅ 正确表述：幂律下降非常缓慢且边际收益递减，还受数据总量上限与质量约束；它给出的是可预测性，不是免费午餐。

Q8 · 微调方案选型

微调选型要在两个正交维度上做决策：改哪些参数（全量 / LoRA / QLoRA / 冻结调参）× 学什么目标（SFT / DPO / PPO），两者可自由组合。全量微调上限最高但 7B 需 80GB+ 显存且有灾难性遗忘风险；LoRA 只训约 0.1% 的低秩增量参数，推理零开销、可热插拔；QLoRA 在 NF4 量化的底座上训 LoRA，单张 24GB 卡即可微调 7B。
追问问题回答要点
什么时候选全量，什么时候选 LoRA？领域/风格迁移大、数据充足、资源富余→全量；常规适配、资源有限、需要多适配器服务→LoRA
为什么 LoRA 推理零开销？ΔW = B·A 可在部署前合并回原权重（W' = W + BA），推理图与原模型完全一致
"两个正交维度"怎么理解？参数选择与目标选择互不绑定：LoRA 可以做 SFT 也可以做 DPO；全量可以做 PPO——按约束独立决策
LoRA 的 r 和作用层怎么选？r 常用 8~64，任务越偏离预训练分布取越大；注意力投影与 FFN 全部加通常最稳
❌ 典型错误答法："LoRA 是预算不够时的妥协方案，效果一定不如全量。"
✅ 正确表述：大量任务上 LoRA 与全量效果接近，还额外带来抗遗忘、存储便宜、多适配器热切换的工程优势，很多时候是主动选择而非妥协。

Q9 · LoRA 原理

LoRA 冻结原始权重 W，旁挂一个低秩增量 ΔW = B·A：A 把 d 维输入压到 r 维，B 再升回 d 维，r≪d。以 d=4096、r=16 为例，可训练参数从全量的约 1677 万降到 2×4096×16 ≈ 13.1 万（约 0.8%）。训练时 A 随机初始化、B 置零，保证起点增量为零不扰动原模型；部署时合并权重或按需热插拔。
ΔW = B·A，B∈Rd×r，A∈Rr×d，r ≪ d
4096×4096 矩阵：全量 16,777,216 参数 → LoRA(r=16) 仅 131,072 参数，降幅 99.2%。
追问问题回答要点
低秩假设的依据？研究表明微调权重的内在秩很低——任务适配只需要在一个低维子空间里移动，不需要动整个参数空间
QLoRA 如何再省显存？三板斧：底座量化到 NF4 + 对量化常数再做双重量化 + 分页优化器把峰值显存卸载到 CPU
多 LoRA 服务怎么做？底座常驻显存，不同业务的 LoRA 适配器按请求热切换或加权融合（LoRA Merging），多租户成本极低
LoRA 什么时候失效？需要大规模注入新知识的继续预训练、跨度极大的领域迁移——低秩增量容量不够，应回到全量或预训练
❌ 典型错误答法："LoRA 直接修改原模型的权重矩阵。"
✅ 正确表述：原 W 全程冻结，改动只在旁路的 B·A 上；可随时合并进原权重，也可随时卸载恢复原模型。

Q10 · Post-Training（后训练）全景

Post-Training 指预训练之后的全部工序：SFT 打底，再用偏好优化做对齐。技术族谱有五支：RLHF（PPO 驱动，需 4 个模型）、DPO（闭式偏好损失，2 个模型）、GRPO（砍掉价值模型的组内相对优势）、拒绝采样（只学好样本）、RLAIF（用 AI 反馈替代人工标注）。总体趋势是从复杂在线 RL 走向简化稳定，并按任务特化。

GRPO 展开（高频追问）：GRPO（DeepSeekMath/R1 系列采用）的核心动作是砍掉 Critic/Value Model：对同一个 prompt 采样 G 个回答，各自打分后在组内做归一化，A_i = (r_i − mean) / std，用相对排名代替绝对价值估计。省掉一个与策略同规模的模型，显存直降约四分之一。

它特别适合可验证奖励的任务：数学题有标准答案、代码有测试用例，规则打分器即可给出奖励，不需要训昂贵的 RM。这也是 R1 式推理模型把 RLVR（可验证奖励的强化学习）作为主路线的原因——奖励信号干净，组内对比就能提供稳定的学习梯度，再配一个 KL 约束防止策略跑飞。

追问问题回答要点
RLHF 为什么要 4 个模型？Policy（被优化）、Reference（KL 锚点）、Reward Model（打分）、Critic（价值估计）——每个都有不可替代的角色，这也是它贵的原因
DPO 的核心思想？把 RL 目标闭式变换成偏好对上的分类损失，隐式定义奖励，训练过程像监督学习一样稳
GRPO 适合什么任务？奖励可规则验证的数学、代码、格式约束任务；开放式主观任务仍需 RM 或 AI 反馈
怎么选方案？数据少求稳→DPO；有可验证奖励→GRPO/PPO；需要精细人类偏好建模且团队有 RL 工程能力→完整 RLHF
❌ 典型错误答法："对齐就是后训练加一层过滤器，把坏答案拦掉。"
✅ 正确表述：对齐是改写模型输出分布的训练过程，伴随能力回退、过度迎合等代价，必须配评测持续迭代，而不是一个过滤步骤。

Q11 · DPO vs PPO

一句话：PPO 是在线 RL——策略模型现场生成、RM 实时打分、按优势更新，强但难训；DPO 是离线方法——直接用静态偏好对优化一个闭式损失，像监督学习一样稳。DPO 省掉了采样与 RM，代价是受限于偏好数据的分布与质量，探索能力弱。
维度PPO（RLHF）DPO
所需模型数4 个（Policy/Reference/RM/Critic）2 个（Policy + Reference）
数据来源在线采样，边生成边学离线静态偏好对
训练稳定性低，超参敏感，易 reward hacking高，接近监督学习
工程复杂度高（多模型协同 + 调度）低
适用场景需在线探索、可验证奖励、精细偏好通用对话对齐、快速落地、资源有限
追问问题回答要点
PPO 的不稳定来自哪？reward hacking（钻 RM 空子）、KL 失控偏离参考分布、价值估计误差传播
DPO 为什么简单？不需要 rollout 采样和 RM 推理，一个交叉熵式损失直接反传，显存与工程都省一半以上
DPO 的局限？离线数据与当前策略存在分布失配；无法利用规则可验证奖励；探索弱、上限受数据质量钳制
生产上怎么组合？常见路线：DPO 快速对齐打底，再用 GRPO/PPO 在数学代码等可验证任务上做 RLVR 提上限
❌ 典型错误答法："DPO 是 PPO 的升级替代，全面更优。"
✅ 正确表述：两者是在线与离线的取舍：需要探索、有验证器信号的场景在线 RL 仍占优；求稳、求快、数据是静态偏好对时 DPO 是更优工程选择。

三、推理与生成优化（Q12-Q15）

Q12 · 解码策略

贪心每步取概率最大的 token，确定但短视、易陷入复读循环；Beam Search 保留 top-B 条路径搜近似全局最优，是机器翻译时代的王者，但在开放生成中因同质化与 B 倍开销在 LLM 时代失宠；采样引入随机性，配合 Top-K（截断候选个数）与 Top-P（截断累计概率）控制质量。生产环境通常是 temperature + Top-P 组合。
追问问题回答要点
贪心为什么会复读？无探索机制，一旦进入某个高频短语的吸引子就出不来，且每步只看局部最优
Beam Search 为什么在 LLM 上失宠？开放生成要的是合理且多样，不是概率最大；beam 之间高度同质，开销随 B 线性增长，还更容易重复
Top-P 和 Top-K 的关系？Top-K 硬性限定候选个数；Top-P 按累积概率动态截取——分布尖时候选少、分布平时候选多，可叠加使用
推测解码是什么？小草稿模型连续猜多个 token，大模型一次并行验证，接受一致部分；输出分布与直接采样等价，纯加速（常见 2~3x）
❌ 典型错误答法："Beam Search 的 beam width 越大效果越好。"
✅ 正确表述：开放生成中增大 beam 会让输出更趋同、更重复，且推理成本线性上升；它只适合翻译等"唯一解"型任务。

📎 深入：解码策略深度解析

Q13 · Temperature / Top-P / Top-K

Temperature 在 softmax 前对 logits 除以 T：T<1 分布变尖（更确定），T>1 分布变平（更随机），T→0 退化为贪心，但它不改变排序只改变分布形状。Top-K 截断到概率最高的 K 个，Top-P 截断到累计概率达 p 的最小集合。经验配置：代码/事实类任务 T≈0~0.2，通用对话 T≈0.7 + p≈0.9，创意写作 T≈0.9~1.2。
追问问题回答要点
Temperature 的数学作用？softmax(logits/T)：不改变 token 排序，只缩放头尾概率差距；它是"确定性 vs 多样性"的总旋钮
Top-P 相比 Top-K 好在哪？自适应分布形状：模型有信心时候选自动收窄，不确定时自动放宽，避免固定 K 一刀切
生成为什么需要随机性？人类语言本身多样，确定性解码会塌缩到少数模式；适度随机提升多样性与鲁棒性
T=0 就完全可复现吗？逻辑上确定，但浮点非确定性与批处理差异仍可能造成偶发分歧；可复现≠正确
❌ 典型错误答法："输出胡说八道就把 temperature 调到 0，保证准确。"
✅ 正确表述：T=0 只消除采样随机性，不改变模型的知识状态与置信分布，幻觉与错误在 T=0 下照样稳定复现。

Q14 · KV Cache 与 Prompt Caching

自回归生成时每步都要对全部历史 token 算注意力，KV Cache 把已算好的 K/V 缓存复用，使单步生成从 O(N²) 重算降为 O(N)（总生成从 O(N³) 到 O(N²)），代价是显存：7B 模型（32 层 × 32 KV 头 × 128 维，FP16）+ 32K 上下文的 KV Cache 约 17GB。Prompt Caching 进一步把同一前缀的 KV 跨请求复用——系统提示与 few-shot 前置固定，可省约 90% 的前缀读取费用。
KV 显存 ≈ 2 × 层数 × KV头数 × d_head × 序列长 × 每参数字节数
示例：2 × 32 × 32 × 128 × 32768 × 2B ≈ 17.2GB（7B，FP16，32K 上下文）。GQA 把 KV 头数从 32 降到 8 即可省 4 倍。
追问问题回答要点
PagedAttention 的原理？借鉴操作系统虚拟内存：KV 按 16 token 一块分页、按需非连续分配，消除碎片，显著提高可并发 batch 数（vLLM 核心）
Prompt Caching 的触发条件？前缀逐字节一致 + 达到最小长度（如 1024 token）+ 在 TTL 内（如 Claude 默认 5 分钟）；命中后读取约为原价 10%，写入约 1.25 倍
怎么设计 prompt 提高命中率？稳定内容前置（系统提示、工具定义、few-shot），动态内容（用户输入、时间戳）放最后，顺序一字不改
长上下文的主要瓶颈？prefill 计算随 N² 增长 + KV 显存随 N 线性增长；优化手段：GQA/MLA、KV 量化、滑窗、offload
Prompt Caching 命中与失效：为什么「顺序」决定成本 ✅ 命中（稳定前缀在前，变化内容在后） ┌──────────────────────────────────────────────┬─────────────┐ │ System Prompt │ 工具定义 │ few-shot 示例 │ 本轮用户输入 │ │◄───────── 逐字节一致的可缓存前缀 ───────────►│◄─ 每次不同 ─►│ │ 第 1 次：写入（约 1.25 倍价） │ 按原价计费 │ │ 后续次：命中（约 0.1 倍价） │ │ └──────────────────────────────────────────────┴─────────────┘ ❌ 失效（在前缀里插了一个每次都变的值） ┌───────────────┬──────────────┬───────────────┬─────────────┐ │ System Prompt │ 当前时间戳 ✗ │ 工具定义 … │ 用户输入 │ │◄─ 仍可缓存 ──►│ 一字之差 │◄── 全部失效，按原价重新计算 ──►│ └───────────────┴──────────────┴───────────────┴─────────────┘ 前缀一旦在中间发生变化，其后所有内容的缓存全部作废 三个命中条件缺一不可：前缀逐字节一致、达到最小长度（如 1024 token）、 在 TTL 内（如 5 分钟）。所以「把动态内容放最后」不是风格建议， 而是直接决定账单的工程约束。
❌ 典型错误答法："Prompt Caching 是语义缓存，相似问题会命中之前的答案。"
✅ 正确表述：它是前缀 KV 的精确复用：逐字节匹配、缓存的是中间计算而非最终答案，前缀改动一个字即失效。

Q15 · 量化

量化把 FP16 权重（及/或激活）压到 INT8/INT4，显存近乎减半/四分之一，推理带宽压力同步下降。经验：INT8 接近无损，INT4 是甜蜜点（多数任务掉点约 1%）。主流算法：GPTQ 训练后逐列量化并用二阶（Hessian）信息做误差补偿；AWQ 基于激活分布识别约 1% 的显著权重通道做缩放保护；NF4 是 QLoRA 用的 4bit 数据类型。注意 GGUF 是 llama.cpp 的模型文件格式，不是量化算法。
追问问题回答要点
为什么不能所有权重一视同仁地量化？激活分布高度不均，约 1% 的 salient weights 对输出影响巨大，平等粗量化会直接打崩这些通道
GPTQ 与 AWQ 的核心区别？GPTQ：量化当前列后把误差补偿到未量化列（靠 Hessian）；AWQ：不逐列补偿，而是按激活幅度缩放保护显著通道，更快更友好
权重量化和激活量化有什么不同？权重静态、可离线精细量化；激活动态、分布随输入漂移，难量化——所以纯 INT8 推理（W8A8）的瓶颈常在激活侧
INT4 能上生产吗？对话/RAG 等容错场景普遍可行；对数值敏感、长链推理类任务必须用业务集实测后再定
❌ 典型错误答法："我们用 GGUF 算法做了 4bit 量化。"
✅ 正确表述：GGUF 是文件格式（承载权重与元数据），Q4_K_M 之类的才是量化方案；部署时文件格式与量化算法要分开表述。

四、应用与 Prompt 工程（Q16-Q18）

Q16 · Prompt Engineering

Prompt 是 LLM 的编程接口，一条好提示包含五要素：角色（Role）、任务（Task）、背景（Context）、格式（Format）、示例（Examples）。常用手法：结构化模板、few-shot 示范、分隔符隔离用户输入、显式输出约束（JSON/表格）。工程上要把 prompt 当代码管理：配业务测试集迭代、版本化、回归验证，必要时用 LLMLingua 之类做压缩。
追问问题回答要点
为什么 prompt 改一个词结果差很多？prompt 是条件输入，措辞变化即分布偏移，会改变注意力的聚焦方式与模型的"角色代入"，输出随之漂移
什么时候上 few-shot？输出格式复杂、判断主观、边界情况多时——示例比描述更能锚定行为；注意示例顺序与标签平衡
如何约束结构化输出？明确 JSON Schema + 示例，配合 function calling / 受限解码（grammar）从机制上杜绝解析失败
如何系统化迭代？建 50~200 条业务评测集→改 prompt→跑回归→看 diff→灰度上线；没有测试集的调 prompt 是碰运气
❌ 典型错误答法："Prompt 工程就是调试话术，算不上工程能力。"
✅ 正确表述：prompt 是软件接口：需要版本管理、测试回归、成本优化（压缩/缓存）与评测闭环，是 LLM 应用工程师的核心工程能力之一。

📎 深入：Prompt 工程指南

Q17 · CoT（思维链）

CoT 让模型先输出中间推理步骤再给最终答案，相当于给自回归模型一张"草稿纸"。形式上有 few-shot CoT（示范带推理过程的例子）与 zero-shot CoT（一句"让我们一步步思考"触发）。对数学、符号推理类任务提升显著（GSM8K 上曾带来数十个百分点的跃升），代价是 token 开销增大与错误沿链传导。现代推理模型（o1/R1）已把"展开推理"从提示技巧内化为训练目标。

机制：自回归模型每一步只能做 O(1) 的"思考"，且只能把自己生成的 token 当作工作记忆。CoT 的本质是用生成换思考时间——把一个多步难题拆成一串单步生成，每一步只需依赖上文刚写出的结论，单步难度大幅下降，等效于把模型的"思考深度"从固定层数扩展到 token 序列长度。

局限要讲全：①错误传导——链条上一步错，后续步骤大概率将错就错；②token 成本——推理链让输出长度膨胀数倍，延迟与账单同步上涨；③简单任务反效果——一步能答对的题强行 CoT 反而引入不必要的出错机会；④CoT 是生成出来的解释，不是形式化证明。缓解手段是 Self-Consistency：采样多条推理链、对最终答案多数投票，用冗余换鲁棒。

演进：CoT 最初只是 prompting 技巧（Wei 2022 / Kojima 2022），R1 时代则通过 RL 直接奖励"产生有效推理过程"，让模型自己学会何时展开、何时收起推理链——回答这道题时点出这条从"提示技巧"到"训练目标"的演进线，能显著加分。

追问问题回答要点
CoT 为什么有效？把多步推理拆成多次单步生成，每步只依赖上一步结论，绕过模型单步算力上限；写出的中间步骤成为后续的工作记忆
Zero-shot 怎么触发？"Let's think step by step"（Kojima 2022）即可在大模型上显著激活推理行为，无需示例
Self-Consistency 是什么？同一问题采样多条 CoT，对最终答案多数投票，抑制单链错误，是 CoT 的标准增强
CoT 什么时候不该用？简单事实/抽取类任务：链条只会增加 token 成本与出错概率，直接作答更优
❌ 典型错误答法："CoT 输出的推理链是可靠的证明，结论因此必然正确。"
✅ 正确表述：CoT 是概率生成的解释性文本，每步都可能出错且错误会沿链放大；需要投票、验证器或测试用例兜底。

📎 深入：CoT 思维链详解

Q18 · 幻觉（Hallucination）

幻觉是模型输出自信流畅但与事实或给定上下文不一致的内容。三个根因：训练数据本身含噪声与过时信息；训练目标是"续写"而非"检索与核验"；对齐阶段奖励自信完整的回答，变相鼓励"编也要编完整"。可分三类：事实幻觉（编造事实）、上下文不一致（无视给定材料）、推理幻觉（中间步骤错）。缓解要三层联动：训练数据治理、推理时控制、系统层 RAG + 引用核验。
追问问题回答要点
RAG 能根治幻觉吗？不能。RAG 提供正确材料，但模型可能无视或改写检索内容（上下文不一致型幻觉），还需引用对齐训练与引用强制
幻觉为什么难根除？目标函数里没有"事实正确"这一项监督；流畅性、完整性与事实性并不天然对齐，只能在数据、训练、系统层持续压制
有哪些检测手段？自检/多采样一致性、跨模型交叉验证、与知识库比对、NLI 蕴含判别；高风险场景加人工抽检
工程上怎么兜底？高风险回答强制走 RAG + 引用来源；设置拒答与低置信兜底话术；关键结论走人工审核；监控线上幻觉率指标
❌ 典型错误答法："幻觉是采样温度太高，temperature 设 0 就解决了。"
✅ 正确表述：温度只控制采样随机性；幻觉源于知识状态与训练目标，T=0 下幻觉照样稳定输出，治理必须从数据、对齐与系统层入手。

五、架构演进与部署（Q19-Q20）

Q19 · MoE（混合专家）

MoE 把 FFN 拆成 N 个并行专家，由 Router 对每个 token 做 Top-K 路由，只激活少数专家——总参数与激活参数从此解耦。DeepSeek-V3 总参数 671B、每 token 激活仅 37B（约 5.5%），容量像超大模型、单 token 算力成本接近小模型。代价：需要负载均衡损失防止专家塌缩、训练受 All-to-All 通信制约、推理显存仍按总参数规划。
数字案例③：DeepSeek-V3 总参数 671B / 激活 37B ≈ 5.5%；FP16 下全部专家需约 1.3TB 显存才能完整驻留——"激活小"省的是计算，不是显存。
追问问题回答要点
为什么必须加负载均衡损失？Router 天然赢家通吃：少数专家被反复选中越强、其余饿死，容量浪费；辅助损失强制 token 在专家间均匀分布
MoE 推理省显存吗？不省。所有专家都要驻留（或做专家并行/换页），显存按总参数算；省的只是每 token 的 FLOPs
Top-K 怎么选？K 越大表达力越强但算力与路由难度上升；常见"8 选 2"或"256 选 8"一类配置，配合共享专家兜底通用能力
训练与推理的瓶颈各是什么？训练：All-to-All 通信与负载均衡；推理：显存容量、批处理与带宽——MoE 对推理框架的调度能力要求更高

Q20 · 推理部署框架选型

五大主流框架各有定位：vLLM（PagedAttention + Continuous Batching，高并发通用服务首选）、SGLang（RadixAttention 前缀树，多轮/Agent/共享前缀场景最强）、TGI（HuggingFace 生态开箱即用）、llama.cpp（GGUF 格式，CPU/边缘设备/混合推理）、TensorRT-LLM（NVIDIA 极致优化，工程门槛高）。选型看四维：硬件约束、并发与延迟 SLO、功能需求（量化/推测解码/结构化输出）、生态与维护。

两大核心技术要讲透：①PagedAttention 把 KV Cache 切成 16 token 一块的"页"，像操作系统管理虚拟内存一样按需分配，消除预分配造成的碎片，让同一张卡能塞下更大的 batch——这是 vLLM 吞吐跃升的根本。②Continuous Batching 打破静态批处理：请求在迭代粒度上随到随进、随完随走，GPU 不再空等最长序列，利用率大幅提升。SGLang 的 RadixAttention 则用前缀树自动管理 KV 复用，多轮对话与 Agent 的公共前缀被天然共享缓存。

选型经验矩阵：高并发 API 服务→vLLM；多轮对话/Agent/复杂编排→SGLang；HF 生态快速验证→TGI；CPU/Mac/嵌入式/隐私本地化→llama.cpp；NVIDIA 大集群压榨极限吞吐→TensorRT-LLM。容量规划记住：显存 = 权重 + KV Cache（随并发与长度增长）+ 激活开销；7B FP16 权重约 14GB，prefill 是计算受限、decode 是带宽受限，瓶颈不同优化手段也不同。

追问问题回答要点
PagedAttention 解决什么？KV 碎片与预分配浪费：分页按需分配，提高 batch 上限与显存利用率，吞吐提升数倍
Continuous vs Static Batching？静态批要等最长请求结束才能换批；连续批在迭代级插拔请求，GPU 始终满载
SGLang 凭什么适合 Agent？RadixAttention 前缀树自动命中多轮共享前缀，工具调用与分支搜索场景缓存命中率远高于逐请求重算
TTFT 与 TPOT 分别卡在哪？TTFT（首 token 延迟）主要由 prefill 计算决定；TPOT（每 token 延迟）由显存带宽与 KV 读取决定，二者优化方向不同
❌ 典型错误答法："跑分吞吐最高的框架就是最好的选择。"
✅ 正确表述：压测吞吐不等于真实流量模式，必须结合自身延迟 SLO（TTFT/TPOT）、并发分布、前缀复用率与硬件生态综合选型。

六、评测与选型（Q21-Q22）

Q21 · 评测指标

评测分两层：学术 benchmark 给横向参考——MMLU（通识知识）、GSM8K（数学）、HumanEval/SWE-bench（代码）、GPQA（高难问答）、MT-Bench/LiveBench（对话与抗污染）；业务评测集给真实答案——50~200 条覆盖核心场景的黄金测试集。三个大坑：数据污染（题目进了训练集）、分数饱和（对齐刷榜）、benchmark 与业务目标错位。可信结论只能来自自建测试集 + 线上 A/B 的闭环。

学术分数为什么不能尽信：①数据污染——静态 benchmark 的题目可能出现在后续模型的训练语料里，分数虚高；对策是用动态更新的榜单（LiveBench 定期换题）与时间切割；②目标错位——RLHF 对齐过程本身会提升"人类偏好式"评分，榜单涨幅未必等于真实能力；③涌现争议——同一能力换一种连续指标度量，"突变"可能消失（Mirage），说明阈值式结论要小心。

业务评测怎么建：先按场景分层抽样构造黄金集（50~200 条起步，覆盖高频、边界与高风险 case），人工标注答案或判定标准；用 LLM-as-Judge 批量打分并做人工抽检校准（注意裁判模型的位置偏好与冗长偏好）；离线评测通过后走灰度 + 线上 A/B，看真实业务指标（解决率、采纳率、幻觉投诉率），形成"离线评测→灰度→线上指标"的闭环。

追问问题回答要点
Leaderboard 为什么普遍虚高？数据污染 + 针对性调优 + RLHF 偏好刷分三重叠加；看榜要看题目时效与评测协议
怎么检测/规避数据污染？canary 水印题、时间切割（只用发布时间晚于训练截止的题）、动态题库（LiveBench 模式）
LLM-as-Judge 有哪些坑？位置偏好（先出现的答案占优）、冗长偏好、自我偏好（偏袒同族模型）；靠交换顺序、人工校准缓解
业务侧该定义哪些指标？任务级准确率、引用命中率、幻觉率、拒答恰当率、延迟（TTFT/TPOT）、单次调用成本——与业务 OKR 直接挂钩
❌ 典型错误答法："选型直接看榜单，选分数最高的模型就行。"
✅ 正确表述：榜单分数≠业务效果，且存在污染与饱和风险；必须在自建业务测试集上实测，再叠加延迟与成本约束做决策。

Q22 · 模型选型

选型按四维框架层层过滤：合规（国内 ToB 的数据出境与行业监管有一票否决权）→ 成本（API 单价 vs 自部署 GPU 摊销）→ 延迟（TTFT/TPOT 是否满足 SLO）→ 能力（自建业务测试集实测）。策略上先以小模型建立基线，再用 Model Routing 把简单问题分给便宜模型、复杂问题升级旗舰模型，并固定模型版本 + 回归测试防止静默退化。
追问问题回答要点
自部署 vs API 怎么选？数据敏感、流量大且稳定、需要深度定制→自部署（长期边际成本低，但要团队养）；快速验证、弹性流量→API 先行
Model Routing 怎么做？用意图分类器或置信度分层：简单问答走小模型，复杂推理升级旗舰模型，常见能省 30~70% 成本，关键是路由错判的兜底
为什么合规排第一？金融、医疗、政务等行业的数据出境与合规要求是否决项，能力再强过不了合规也上不了线
模型版本更新怎么管？固定版本号、升级前跑业务回归集、灰度切流；警惕供应商静默更新导致能力漂移
❌ 典型错误答法："关键业务直接上最强的旗舰模型就对了。"
✅ 正确表述：最强≠最合适：要在延迟 SLO 与成本约束下看性价比，很多场景 7~14B 微调模型 + RAG 就能达标，旗舰只留给真正困难的长尾。

Q&A

被问"介绍一下 Transformer"这类开放题，怎么控制深度？
先给 30 秒总览（自注意力 + Q/K/V + 多头 + FFN + 残差归一化），列出 3~4 个可以展开的关键词就停下，把主动权交回提问方。切忌一口气讲 10 分钟：既容易跑偏，也失去了让追问落到进自己准备区域的机会。
被问到完全没准备过的题目，如何救场？
三步：①坦诚边界——"这块我没有深入实践"；②迁移相邻知识——从最接近的概念出发推导，展示推理过程而不是结论；③给出学习路径——"我会从 X 论文/文档入手验证我的推断"。考察的往往是面对未知的思维方式，而不是全知。
数字要背到什么程度？
记少量高价值锚点数字即可：Chinchilla 最优配比 1:20、GPT-3 175B/300B tokens、Llama3 8B/15T、DeepSeek-V3 671B/37B、INT4 掉点约 1%、Claude 缓存读价 10%。重点是数量级和比例关系，精确数字说错反而减分，可以用"大约""量级上"来表述。
如何把问答引导到自己的项目经验上？
在每个答案的尾部挂一个"钩子"："我们当时在 X 场景就遇到了这个问题，最后用 Y 方案解决，权衡点是 Z。"提问方大概率会顺着钩子追问，战场就转移到了你最熟悉的区域。注意钩子必须真实，细节经不起追问的钩子是陷阱。
没有生产经验，实践类问题怎么答？
讲清楚"原理 → 复现路径 → 预期坑点"三段：先说机制，再描述你会怎么搭实验环境验证（哪个框架、什么配置、观察什么指标），最后主动指出实践中会踩的坑（显存峰值、数据质量、评测口径）。这能证明你有动手推演的能力，比假装有经验安全得多。
如何体现 trade-off 思维？
套用固定结构：场景约束 → 候选方案 → 各自代价 → 选择理由 → 已付出的成本。例如"GQA 省了 4 倍 KV 显存，代价是不到 0.5% 的质量损失，在我们长上下文场景下完全值得"。任何只讲优点不讲代价的答案在工程面里都不及格。
问答中最忌讳什么？
四件事：①背书腔——流利但没有理解，一问变体就崩；②绝对化结论——工程判断几乎总有前提；③追问两三层后断崖式失语——说明第一层在背；④全程不谈成本——显存、延迟、token 费用是工程岗的基本语汇。保持"结论 + 机制 + 代价 + 边界"的答题节奏，就能避开绝大多数坑。
