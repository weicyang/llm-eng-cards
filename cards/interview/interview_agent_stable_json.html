IA-11 · Agent 稳定输出结构化 JSON

提问：如何让大模型稳定且确定地输出结构化结果（如 JSON）？

核心观点

终极回答公式：让模型稳定输出，不能靠模型的灵光一闪，而要靠确定的软件工程防线去包裹非确定的生成模型。四层防御：提示词控制 → 生成控制层（Structured Outputs / Logic Masking）→ 推理引擎约束 → 工程校验与自修复。组合拳做下来，格式错误率降至 0.1% 以下。

四层防御架构

Layer 1: 提示词控制

技巧说明
Schema 注入 + Few-shot把 TypeScript 接口或标准 JSON Schema 甩模型脸上，给 2-3 个真实填充范例
近因效应"只能输出 JSON，禁绝废话"放在 prompt 最后 100 token，用 XML 标签框住输出区域

Layer 2: 生成控制层

方案适用场景原理
Structured Outputs闭源 API（OpenAI 等）schema 预编译到引擎里，像给火车铺死铁轨，遵循率接近 100%
Logic Masking（概率掩码）私有化部署开源模型生成 token 时拦截，按 JSON 语法该写双引号就强制其他字符概率为负无穷

Layer 3: 推理引擎约束

基于有限状态机或正则约束的解码，从物理层面彻底杜绝幻觉。哪怕 7B 小模型也能输出完美格式。

Layer 4: 工程校验与自修复

  • Pydantic 强校验：模型吐出结果后程序先拦住，挨个检查字段全不全、类型对不对
  • 闭环自修复：把 Pydantic 报错信息原封不动反馈给模型，"年龄字段缺失，请参照报错重新修改"
  • 流式解析：边吐字符边检查，发现错一个键名立刻中断重来

终极武器：SFT 微调

对极致追求速度或 schema 极其复杂的场景，做监督微调（SFT），给模型做"肌肉记忆训练"——只要看到特定指令就条件反射出特定格式。

高频问答

Q1: 模型开头来一句"好的，这是你要的 JSON"怎么办？

利用近因效应：(1) 把"只能输出 JSON，禁绝废话"放在 prompt 最后 100 token（模型对尾部记忆最深）；(2) 用 XML 标签或特殊定界符把输出区域框起来；(3) 给 few-shot 范例，让模型看到开头就是 { 而不是文字。

Q2: Structured Outputs 和 Logic Masking 有什么区别？

Structured Outputs：闭源 API 提供，schema 预编译到解码引擎里，遵循率接近 100%，但只能在 API 层面使用。Logic Masking（概率掩码）：私有化部署时使用，在模型跳下一个字符时拦截，按 JSON 语法强制只吐出合法字符。基于有限状态机实现，物理级杜绝幻觉。

Q3: Pydantic 校验失败后怎么自修复？

闭环自修复：把 Pydantic 的具体报错（如"年龄字段缺失"或"日期格式不符"）原封不动反馈给模型，像教学生一样告诉它"这个地方写错了，请参照报错重新修改"。大模型最擅长纠错和改写，通常反思一次就绝对准确了。超长 JSON 还可以引入流式解析，边吐边检查。

Q4: 组合拳怎么打？

提示词给范例 → API 开 Structured Outputs 约束 → 推理端加 Logic Masking → 工程端加 Pydantic + 带反馈的自修复重试。这套方案做下来格式错误率降至 0.1% 以下。极致场景再加 SFT 微调做肌肉记忆训练。
