IL-02 · FlashAttention 显存优化原理

核心问题

标准 Attention 的显存瓶颈：

  • 注意力矩阵 - N x N 的矩阵，长文本时显存爆炸
  • 中间激活 - Softmax 前后都需要完整存储
  • 读写瓶颈 - GPU HBM ↔ SRAM 的数据搬运成为性能瓶颈

例如：序列长度 8K 时，注意力矩阵需要 ~512MB；128K 时直接爆到 ~128GB。

FlashAttention 的目标：显存占用降低 80%，同时速度更快。

标准 Attention 的问题

先回顾标准 Attention 的计算流程：

# 标准 Attention 计算
Q, K, V = linear(X)          # 形状: (B, N, d)
S = Q @ K.T / sqrt(d)        # 形状: (B, N, N) ← 这里爆炸
P = softmax(S)               # 形状: (B, N, N) ← 这里也爆炸
O = P @ V                    # 形状: (B, N, d)

问题所在：

  1. 矩阵 S 和 P 的大小是 N²（N=序列长度）
  2. 这些中间结果必须存储在 HBM（显存）中
  3. 反向传播时还需要这些中间值计算梯度

FlashAttention 的核心思想

两大关键技术：Tiling（分块计算） + Recomputation（重计算）

技术1：Tiling（分块计算）

不在 HBM 中构建完整的 N×N 矩阵，而是分块在 SRAM 中计算：

传统方式：

HBM: [完整的 N×N 矩阵] ← 显存爆炸

FlashAttention 方式：

SRAM (快速但小):
  ┌─────────┐
  │ block 1 │ → 计算完写回 HBM
  │ block 2 │ → 计算完写回 HBM
  │ block 3 │ → 计算完写回 HBM
  └─────────┘
  
HBM: 只存储最终输出 O

关键：每个 block 只在 SRAM 中计算，不存储中间矩阵。

技术2：Online Softmax（在线 Softmax）

标准 Softmax 需要完整数组才能计算，但 FlashAttention 使用增量式计算：

# 标准 Softmax（需要完整数组）
def softmax(x):
    max_val = max(x)          # 需要先看完所有元素
    exp_x = exp(x - max_val)
    return exp_x / sum(exp_x) # 需要再遍历一次

# Online Softmax（增量计算）
def online_softmax_stream():
    m = -inf  # 当前最大值
    d = 0     # 当前分母和
    
    for block in blocks:
        m_new = max(m, max(block))
        # 修正之前的计算
        d = d * exp(m - m_new) + sum(exp(block - m_new))
        m = m_new
    
    return d  # 最终的分母

核心洞察：维护两个统计量 (m, d)，就能增量计算 Softmax，不需要存储完整矩阵。

技术3：Recomputation（重计算）

反向传播时不存储中间激活，而是重新计算：

方法 前向 反向 显存
标准 计算并存储 S, P 直接用 S, P O(N²)
FlashAttention 只存储 Q, K, V, O 重算 S, P O(N)

为什么重算反而更快？因为省去了 HBM 的读写，而 SRAM 计算极快。

FlashAttention 算法流程

输入: Q, K, V (分块存储在 HBM)
输出: O (注意力输出)

初始化: O = 0, m = -inf, d = 0

for each Q_block (从 HBM 加载到 SRAM):
    for each K_block, V_block (从 HBM 加载到 SRAM):
        # 在 SRAM 中计算
        S_block = Q_block @ K_block.T / sqrt(d)
        m_new = max(m, rowmax(S_block))
        P_block = exp(S_block - m_new)
        
        # 更新统计量
        d = d * exp(m - m_new) + rowsum(P_block)
        
        # 更新输出（修正之前的计算）
        O = O * exp(m - m_new) + P_block @ V_block
        m = m_new
    
    # 归一化
    O = O / d
    
    # 写回 HBM

返回 O

GPU 内存层次

理解 GPU 内存层次是理解 FlashAttention 的关键：

┌─────────────────────────────────────┐
│  HBM (High Bandwidth Memory)        │  ← 大 (80GB)，慢
│  - 存储模型参数、完整激活           │
│  - 带宽: ~2TB/s                      │
├─────────────────────────────────────┤
│  SRAM (Static RAM / Shared Memory)  │  ← 小 (20MB)，快
│  - FlashAttention 的主要工作区       │
│  - 带宽: ~19TB/s (10x faster)       │
├─────────────────────────────────────┤
│  Registers                          │  ← 极小，极快
│  - 单个线程的临时变量               │
└─────────────────────────────────────┘

FlashAttention 的精髓：把计算从 HBM 搬到 SRAM，减少 IO 次数。

标准回答思路

第一步：说明问题 - 标准 Attention 的 O(N²) 显存瓶颈

第二步：核心思想 - Tiling 分块计算 + Online Softmax 增量计算

第三步：GPU 内存层次 - HBM vs SRAM，减少 IO 是关键

第四步：Recomputation - 重算中间激活，用计算换显存

第五步：性能提升 - 显存 O(N)，速度 2-4x，精确非近似
