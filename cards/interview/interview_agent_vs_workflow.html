IA-03 · Agent vs Workflow 核心区别

提问：大模型应用中 Agent 和 Workflow 的核心区别是什么？

核心观点

一句话总结：控制流的决定权在谁手里。Workflow 是"铁轨列车"（路径预设），Agent 是"自动驾驶汽车"（自主规划）。行业趋势是 Agentic Workflow（智能体工作流）：Workflow 框住下限 + Agent 提升上限。

核心区别对比

维度WorkflowAgent
比喻铁轨列车 🚂自动驾驶汽车 🚗
控制流开发者预设路径，死锁在代码里模型结合环境反馈自主规划
模型角色听话的执行工具有思维链和自我反思能力的决策者
确定性高（人定胜天）低（启发式推理）
灵活性低高

Agent 的三大工程痛点

1. 间歇性发疯（死循环）

Agent 反复调用同一错误工具，token 狂烧，输出胡言乱语

解法：设最大迭代次数 + 人类在环（高风险操作前暂停）+ 强校验节点

2. 工具调用失败率高

挂载超过 5-10 个工具时，模型极易选错或参数格式混乱

解法：工具分层（多智能体协同，每个小Agent只拿1-2个工具）+ few-shot 示例

3. 业务选型：看容错率

场景选择原因
财务报表、合同审核Workflow零容错，确定性逻辑保命
代码辅助、创意调研Agent路径不确定，需要灵活性

行业大趋势：Agentic Workflow

架构思路：用 Workflow 的刚性框架框住下限（保证大流程不跑偏），在具体节点植入 Agent 提升上限（让它自己查库、反思、回复）。就像给列车的某些车厢装上无人驾驶螺旋桨——既有轨道保证方向，又有引擎解决复杂问题。

高频问答

Q1: Agent 和 Workflow 最本质的区别是什么？

控制流的决定权。Workflow 的控制流是开发者预设的（代码里的 if-else），大模型只是执行工具；Agent 的控制流是模型根据环境反馈动态生成的，具备规划、拆解、行动、观察的能力。

Q2: Agent 有哪些工程落地的痛点？怎么解决？

三大痛点：(1) 死循环 → 设 max_iterations + 人类在环 + 强校验节点；(2) 工具调用失败率高（>5-10个工具时）→ 工具分层 + 多智能体协同 + few-shot 示例；(3) 业务选型困难 → 看容错率，零容错选 Workflow，路径不确定选 Agent。

Q3: 什么是 Agentic Workflow？为什么是行业趋势？

Agentic Workflow = Workflow 的确定性 + Agent 的灵活性。具体做法：用 Workflow 的刚性框架保证大流程不跑偏（如客服先解析意图），在关键节点植入 Agent 处理复杂问题（如自动查库、反思、生成回复）。这是目前最稳健的架构，兼顾可靠性和灵活性。

Q4: 怎么回答这道题能拿高分？

三层递进：(1) 理论高度 — 控制流的决定权是预设的还是动态生成的；(2) 工程深度 — 主动抛出死循环、工具幻觉等真实坑，并给出托底方案；(3) 架构视野 — 强调 Agentic Workflow，证明你在设计可商用的生产级系统，而非简单 demo。
