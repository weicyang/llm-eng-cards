IA-09 · Multi-Agent 动态派生 Subagent

提问：在 Multi-Agent 系统中，主 Agent 如何动态派生 Subagent 协同工作？

核心观点

核心原则：构建百万级并发的多智能体系统，靠的不是让模型自由发挥，而是克制的工程约束。三句话：收敛重于发散、扁平优于嵌套、状态必须中心化。

运转逻辑

1. 动态大纲

主 Agent 不动手干杂活，先生成一个动态大纲（计划书），实时记录哪些查过了、哪些正在查、哪些还没分下去。是整个系统的灵魂。

2. delegate_task 工具

主 Agent 发现大纲里有子任务要分发时，调用 delegate_task 工具，砰砰砰派生出多个独立 Subagent 实例。这些小机器人领了任务就并行去干活了。主 Agent 像指挥家——不拉琴，只看谁拉错了、谁还没开始。

三大工程挑战与解法

挑战问题解法
上下文爆掉子 Agent 把几万字原文全发回给主 Agent强制压缩机制：子 Agent 回报时只带回提炼后的结论和事实，过滤所有噪音
无限繁衍Agent 碰到难题就疯狂"生孩子"，指数级爆炸扁平化管理（只有主 Agent 有派生权）+ 物理限流（代码锁死最大并发数如 20）
状态冲突两个子 Agent 查同一家公司，或互相覆盖结论动态大纲是全局唯一真相源，主 Agent 分发时做严格边界划分

评估方式

动态系统每次跑的路径都不一样，传统单元测试失效。最前沿方案是 LLM-as-Judge：请一个更牛的模型当裁判，给主 Agent 产出的最终报告打分。

高频问答

Q1: 为什么子 Agent 不能直接把原始结果返回给主 Agent？

两个问题：(1) 上下文爆掉：几万字原文全发回来，主 Agent 的上下文窗口瞬间爆满，陷入"看了后面忘前面"的尴尬境地；(2) token 费用：每轮都带着大量噪音计费，老板看账单脸都绿了。解法：强制压缩机制，子 Agent 回来之前必须自我压缩，只带回提炼后的结论和事实。

Q2: 怎么防止 Agent 无限递归派生？

两个硬性约束：(1) 派生权隔离：只有主 Agent 有派生权，子 Agent 严禁"生孩子"（扁平化管理）；(2) 物理限流：代码里直接锁死最大并发数（如 20），管模型怎么想，系统说只能开 20 个就派生不出第 21 个。用工程的刚性去限制模型的随机性。

Q3: 动态系统怎么评估好坏？

传统单元测试失效（每次跑的路径不一样）。最前沿方案是 LLM-as-Judge：请一个更牛的模型当裁判，给主 Agent 产出的最终报告打分。通过规模化的自动评测来量化系统是否真的变聪明了还是在乱跑。

Q4: 三句核心原则是什么？

(1) 收敛重于发散：子节点必须负责压缩信息；(2) 扁平优于嵌套：严禁递归派生，防止系统失控；(3) 状态必须中心化：大纲才是最高统帅。能设计出稳健可控的工程架构，才是拿高薪的底气。
