R03 · 策略梯度与 PPO

从 REINFORCE 到 PPO：策略优化的完整进化路径 | 掌握 Actor-Critic、GAE、TRPO 核心思想与 RLHF 应用

一、策略梯度定理

策略梯度定理真正给出的东西是：你不需要知道环境怎么运转，只要能算出"这个动作的对数概率"的梯度，再乘上它带来的回报，就得到了一个可用的上升方向。

直接优化策略参数

与 Value-based 方法（如 DQN）不同，策略梯度方法直接参数化策略 πθ(a|s)，通过梯度上升优化累积回报目标函数 J(θ)。

  • 策略 πθ(a|s)：一个以 θ 为参数的神经网络，输入状态 s，输出动作概率分布
  • 目标函数：J(θ) = Eτ~πθ[R(τ)]，即在策略 πθ 下的期望累积回报
  • 优化方式：梯度上升 θ ← θ + α∇θJ(θ)

策略梯度推导

策略梯度定理的核心公式：

∇θJ(θ) = Eτ~πθ[ Σt ∇θ log πθ(at|st) · R(τ) ]

推导关键步骤：

  1. J(θ) = Στ P(τ;θ) · R(τ)，对 θ 求导
  2. 利用 log-derivative trick：∇P(τ;θ) = P(τ;θ) · ∇log P(τ;θ)
  3. 轨迹概率 P(τ;θ) = p(s0) Πt πθ(at|st) · p(st+1|st,at)，取 log 后环境动态部分与 θ 无关，消掉
  4. 最终只需对 log πθ(at|st) 求梯度，不需要知道环境模型（model-free）

REINFORCE 算法

最基本的策略梯度算法，由 Williams (1992) 提出：

for each episode:
    采样轨迹 τ = (s₀, a₀, r₀, s₁, a₁, r₁, ...)
    计算累积回报 R(τ) = Σₜ γᵗ rₜ
    for each step t:
        θ ← θ + α · ∇log π_θ(aₜ|sₜ) · Gₜ
        其中 Gₜ = Σₖ₌ₜ γᵏ⁻ᵗ rₖ  (从 t 开始的未来回报)

直觉理解：如果一个动作带来了高回报（Gt 大），就增大该动作的概率；反之减小。这就是 "好的行为被强化" 的核心思想。

REINFORCE 的局限

  • 高方差：使用完整轨迹的蒙特卡洛估计，方差很大
  • 采样效率低：每次更新需要完整 episode，on-policy 方法不能复用旧数据
  • 收敛慢：高方差导致梯度估计不稳定，学习率难调
  • 核心公式：∇J(θ) = E[∇log π(a|s) · R]，log-derivative trick 是推导关键
  • 无需环境模型：策略梯度是 model-free 方法，只需采样轨迹
  • REINFORCE 问题：蒙特卡洛采样带来高方差，这是后续所有改进的出发点
  • 与 Value-based 对比：策略梯度能处理连续动作空间，能学习随机策略

二、基线 (Baseline)

基线的作用不是让梯度变得更"对"，而是让它变得更"清楚"——回报全是正数时所有动作都在被鼓励，减掉一个平均水平后，好坏才终于有了符号之分。

方差问题的根源

REINFORCE 中梯度估计为 ∇log π(a|s) · Gt，当 Gt 总是正数时（比如所有奖励都为正），所有动作的概率都会被提高，只是好动作提高得多、差动作提高得少。这导致有效的梯度信号被淹没在高方差的噪声中。

引入基线减少方差

将梯度中的 Gt 替换为 Gt - b(st)：

∇θJ(θ) = E[ Σt ∇θ log πθ(at|st) · (Gt - b(st)) ]

关键性质：任何只依赖状态 s 的基线 b(s) 都不会引入偏差（bias），因为：

Ea~π[ ∇log π(a|s) · b(s) ] = b(s) · Ea~π[ ∇log π(a|s) ] = b(s) · ∇θΣaπ(a|s) = b(s) · ∇θ1 = 0

State Value 作为基线

最常用的基线是状态值函数 V(s)：

  • b(s) = Vπ(s)：当前状态下的期望回报
  • Gt - V(st) 衡量的是 "这个动作比平均水平好多少"
  • 正值 → 动作优于平均 → 增大概率；负值 → 动作劣于平均 → 减小概率
  • 这本质上就是 Advantage Function 的雏形：A(s,a) ≈ Gt - V(st)

方差减少的直觉

假设某状态下所有回报都在 [90, 110] 范围。不用基线时梯度都是正的；用 V(s) ≈ 100 作为基线后，梯度变成 [-10, +10]，信号更清晰，方差大幅降低。

  • 基线不引入偏差的证明：E[∇log π · b(s)] = 0，因为 Σπ(a|s) = 1 的梯度为零
  • 最优基线：V(s) 是最常用的基线，但理论最优基线需要加权（实践中影响不大）
  • 方差来源：主要来自蒙特卡洛回报估计的随机性和不同轨迹间回报的差异

三、Actor-Critic

Actor-Critic 是拿一点偏差去换大量方差：Critic 的估计肯定不完全准，但它让每一步都能立刻给出反馈，不必等一整条轨迹跑完。

架构设计

Actor-Critic 是策略梯度的重要改进，使用两个网络协同训练：

  • Actor（策略网络）：πθ(a|s) — 负责选择动作
  • Critic（值网络）：Vw(s) 或 Qw(s,a) — 负责评估动作的好坏

Actor 根据 Critic 的评估来更新策略，Critic 根据实际回报来更新自己的估计。

Advantage Function

A(s, a) = Q(s, a) - V(s)

Advantage 表示动作 a 在状态 s 下相对于平均水平的优势：

  • A > 0：这个动作比平均好 → 增大概率
  • A < 0：这个动作比平均差 → 减小概率
  • A = 0：这个动作恰好是平均水平

实践中的 Advantage 估计

直接估计 Q(s,a) 和 V(s) 两个网络成本高，通常用 TD 误差作为 Advantage 的近似：

A(st, at) ≈ δt = rt + γV(st+1) - V(st)

这样只需维护一个 V 网络作为 Critic。TD 误差是 Advantage 的无偏估计，但方差低于蒙特卡洛方法。

Actor-Critic 训练流程

for each step:
    根据 π_θ(a|s) 选择动作 a
    执行 a，观察 r, s'
    
    # Critic 更新（TD 学习）
    δ = r + γ V_w(s') - V_w(s)
    w ← w + α_c · δ · ∇_w V_w(s)
    
    # Actor 更新（策略梯度）
    θ ← θ + α_a · δ · ∇_θ log π_θ(a|s)

减少方差同时保持无偏

相比 REINFORCE 使用完整轨迹回报（高方差），Actor-Critic 使用 TD 误差（低方差），同时利用 Critic 的引导（bootstrapping）来减少对完整轨迹的依赖。代价是引入了 Critic 近似带来的 少量偏差（biased but lower variance），整体训练更加稳定。

  • 双网络协同：Actor 产生策略，Critic 评估好坏，两者共同训练
  • Advantage 含义：A(s,a) = Q(s,a) - V(s)，衡量动作相对于平均水平的优势
  • TD 误差近似：δ = r + γV(s') - V(s) 是 Advantage 的低方差无偏估计
  • 偏差-方差权衡：MC（高方差无偏） → TD（低方差有少量偏差）

四、A2C / A3C

A3C 用"多个 worker 在不同地方各采各的"替掉了 Replay Buffer——On-policy 算法用不了旧数据，那就靠并行环境来凑出样本的多样性。

A3C — Asynchronous Advantage Actor-Critic

由 DeepMind 于 2016 年提出（Mnih et al.），核心思想是多线程异步并行采样：

  • 多个 worker 各自拥有环境副本，独立与环境交互
  • 每个 worker 计算本地梯度后异步更新全局参数
  • 不需要 Experience Replay Buffer（不同 worker 本身就提供了去相关性）
全局网络 (θ_global, w_global)
                    ↑ 异步更新
    ┌───────────────┼───────────────┐
  Worker 1       Worker 2       Worker 3
  (环境副本1)    (环境副本2)     (环境副本3)
  采样→计算梯度  采样→计算梯度   采样→计算梯度

A3C 的优势

  • 高效利用多核 CPU：不依赖 GPU，多线程并行
  • 自然去相关性：不同 worker 采集的数据天然不相关，替代 Replay Buffer
  • 更好的探索：不同 worker 在不同状态空间区域探索

A2C — Advantage Actor-Critic（同步版本）

A2C 是 A3C 的同步简化版：

  • 所有 worker 同步采集一批数据
  • 汇总梯度后一次性更新全局参数
  • 实现更简单，调试更方便
  • 在 GPU 环境下通常更高效（batch 操作可以充分利用 GPU 并行）

A2C vs A3C

维度A3C（异步）A2C（同步）
更新方式各 worker 异步更新全局参数所有 worker 同步后统一更新
梯度一致性可能使用过时参数计算梯度梯度基于最新参数
硬件适配多核 CPU 友好GPU 批处理友好
实现复杂度需要线程同步机制更简单直接
实际表现A2C 通常与 A3C 持平甚至更好（更稳定）
  • A3C 核心创新：异步多线程替代 Replay Buffer，自然实现数据去相关性
  • A2C 更主流：同步版本更简单、更稳定，GPU 上效率更高
  • 趋势：现代 RL 框架（如 PPO 的实现）多采用同步并行采样

五、GAE (Generalized Advantage Estimation)

GAE 不在"信 Critic"和"信实际回报"之间二选一，而是用 λ 把两者按几何权重混起来，让你在同一个旋钮上调偏差与方差。

TD(λ) 思想在 Advantage 上的应用

GAE 由 Schulman et al. (2016) 提出，本质是把 TD(λ) 的思想应用到 Advantage 估计上，通过指数加权平均不同步数的 TD 误差来平衡偏差与方差。

不同步数的 Advantage 估计

  • 1-step TD：Â(1) = δt = rt + γV(st+1) - V(st) — 低方差、高偏差
  • 2-step TD：Â(2) = δt + γδt+1
  • n-step TD：Â(n) = Σk=0n-1 γkδt+k
  • MC (∞-step)：Â(∞) = Gt - V(st) — 高方差、无偏差

GAE 公式推导

GAE 对所有步数的 TD 估计做指数加权平均：

ÂGAE(γ,λ)t = Σk=0∞ (γλ)k δt+k

其中 δt = rt + γV(st+1) - V(st) 是单步 TD 误差。

λ 参数控制偏差-方差权衡

λ 值行为特点
λ = 0Â = δt（单步 TD）低方差、高偏差，依赖 V 的准确度
λ = 1Â = Gt - V(st)（MC）高方差、无偏差，等价于蒙特卡洛
0 < λ < 1加权平均偏差-方差的灵活权衡

实践中：λ 通常取 0.95–0.99，在偏差与方差之间取得良好平衡。PPO 默认使用 GAE(λ=0.95)。

高效计算（递推公式）

GAE 可以从后向前递推，不需要显式求无穷和：

Ât = δt + γλ · Ât+1

从轨迹末尾开始，ÂT = 0，向前逐步计算即可。

  • 核心思想：用 λ 参数在 TD（低方差高偏差）和 MC（高方差无偏差）之间平滑插值
  • 公式：Ât = Σ(γλ)kδt+k，递推形式 Ât = δt + γλÂt+1
  • λ 选择：实践中 0.95–0.99，PPO 默认 λ=0.95, γ=0.99
  • 重要性：GAE 是 PPO/TRPO 的标配组件，几乎所有现代策略梯度方法都使用它

六、TRPO (Trust Region Policy Optimization)

RL 里步子迈大了不是"这次更新差一点"，而是策略变差 → 采到的数据变差 → 再也爬不回来；信任域约束的就是这条不可逆的下坡路。

策略更新的问题

策略梯度方法的一个根本问题：步长太大会导致策略崩溃。与监督学习不同，RL 中数据分布依赖于策略本身——策略变化 → 数据分布变化 → 可能进入糟糕的区域 → 无法恢复。

信任域约束

TRPO（Schulman et al., 2015）的核心思想：每次策略更新限制在一个信任域内，确保新策略不会偏离旧策略太远。

maxθ Es,a~πold[ πθ(a|s) / πold(a|s) · Â(s,a) ]
s.t. Es[ DKL(πold(·|s) ‖ πθ(·|s)) ] ≤ δ

其中 r(θ) = πθ(a|s) / πold(a|s) 是重要性采样比（importance sampling ratio）。

KL 散度约束

KL 散度 DKL(πold ‖ πθ) 衡量新旧策略分布的差异：

  • KL = 0：新旧策略完全相同
  • KL 越大：策略变化越大，越可能导致性能下降
  • 约束 KL ≤ δ（通常 δ = 0.01）确保更新幅度受控

为什么能保证单调改进

Kakade & Langford (2002) 证明了一个关键定理：

J(πnew) ≥ Lπold(πnew) - C · DKLmax(πold ‖ πnew)

其中 L 是旧策略下的替代目标函数，C 是常数。只要我们在 KL 约束下最大化 L，就能保证性能单调不下降（理论上）。TRPO 用这个下界来约束更新。

计算复杂度问题

TRPO 需要求解带约束的优化问题：

  • 使用 共轭梯度法 近似求解 Fisher Information Matrix 的逆（避免显式计算二阶导数）
  • 使用 线搜索 确保满足 KL 约束
  • 计算复杂度远高于普通 SGD
  • 实现复杂，调试困难
  • 核心动机：限制策略更新步长，防止性能崩溃（策略改变 → 数据分布改变）
  • KL 约束：用 KL 散度约束新旧策略的距离，而非参数距离
  • 单调改进：在 KL 约束下最大化替代目标函数，理论保证性能不下降
  • 局限：需要二阶优化（Fisher 矩阵），计算成本高，实现复杂 → 催生了 PPO

七、PPO (Proximal Policy Optimization)

PPO 的聪明之处在于把"别走太远"这件事从约束条件挪进了损失函数：一旦重要性采样比越界，那一项的梯度直接变成 0，用一阶优化器就实现了信任域的效果。

PPO 的设计目标

PPO（Schulman et al., 2017）的目标：获得 TRPO 的稳定性，同时只使用一阶优化（普通 SGD/Adam），实现简单、调参容易。

Clipped Surrogate Objective

PPO 的核心创新——截断的替代目标函数：

LCLIP(θ) = E[ min( r(θ)·Â, clip(r(θ), 1-ε, 1+ε)·Â ) ]

其中 r(θ) = πθ(a|s) / πold(a|s) 是新旧策略概率比，ε 通常取 0.1 或 0.2。

Clip 机制的直觉

情况Â > 0（好动作）Â < 0（差动作）
r(θ) 太大（>1+ε）clip 住，阻止过度增大概率不 clip（自然减小概率是好的）
r(θ) 太小（<1-ε）不 clip（自然增大概率是好的）clip 住，阻止过度减小概率
r(θ) ∈ [1-ε, 1+ε]正常更新，不受限制

核心思想：取 min 操作确保我们只在安全范围内优化。当策略变化超出 [1-ε, 1+ε] 时，梯度被截断为零，自动停止更新。

PPO 的两个变体

PPO-Clip（主流）：使用截断目标函数 LCLIP，简单高效，几乎所有 PPO 实现的默认选择。

PPO-Penalty：将 KL 散度作为惩罚项加入目标函数，自适应调节惩罚系数 β：

LPENALTY(θ) = E[ r(θ)·Â - β · DKL(πold ‖ πθ) ]
  • 如果 KL 过大 → 增大 β（惩罚更重）
  • 如果 KL 过小 → 减小 β（允许更大更新）

实践中 PPO-Clip 更常用，因为它不需要额外调节 β，且效果稳定。

PPO 完整目标函数

L(θ) = LCLIP(θ) - c₁ · LVF(θ) + c₂ · S[πθ]

三部分组成：策略损失 + 值函数损失 + 熵正则化（鼓励探索）。

PPO 训练伪代码

for iteration = 1, 2, ...:
    # 采样阶段
    用 π_old 在 N 个并行环境中采集 T 步数据
    计算 GAE advantage Â_t 和回报 R_t
    
    # 优化阶段（多个 epoch 复用数据）
    for epoch = 1, ..., K:  # 通常 K=3~10
        for each minibatch:
            r(θ) = π_θ(a|s) / π_old(a|s)
            L_clip = min(r·Â, clip(r, 1-ε, 1+ε)·Â)
            L_vf = (V_θ(s) - R_t)²
            L = -L_clip + c₁·L_vf - c₂·entropy
            θ ← θ - α·∇L
    
    π_old ← π_θ
  • 核心公式：LCLIP = E[min(r·Â, clip(r, 1-ε, 1+ε)·Â)]，用 clip 替代 KL 约束
  • ε 的作用：控制策略更新幅度，通常 0.1~0.2
  • 为什么取 min：悲观下界 — 在好动作上不过度乐观，在差动作上不过度悲观
  • 多 epoch 训练：PPO 可以在同一批数据上多次更新（clip 防止策略偏离过远）
  • 三部分损失：策略损失 + 值函数损失 + 熵正则

八、PPO 在 RLHF 中的应用

RLHF 里的奖励是一个学出来的模型，不是环境的客观反馈——所以必须挂上对参考策略的 KL 惩罚，否则优化器会去找 Reward Model 的漏洞而不是去变好。

RLHF-PPO 的四模型系统（显存的大头在这里） ────────────────────────────────────── prompt x │ ├──────────────────────────────────────────────┐ ▼ ▼ Actor π_θ （训练，需梯度 + 优化器状态） Reference π_ref 生成回复 y （冻结，SFT 权重） │ │ │ 逐 token 的 log π_θ(y_t|·) │ log π_ref(y_t|·) │ │ └──────────────┬───────────────────────────────┘ ▼ 逐 token KL 惩罚：−β·( log π_θ − log π_ref ) │ ┌──────────────┴───────────────┐ ▼ ▼ Reward Model（冻结） Critic V(s)（训练，需梯度） 只在序列末尾给一个标量 r 逐 token 估计期望回报 │ │ └──────────────┬───────────────┘ ▼ r_t = −β·KL_t （t < T，中间步只有 KL 项） r_T = R_RM(x,y) − β·KL_T （末步才加上 RM 打分） │ ▼ GAE ──▶ Â_t ──▶ PPO clip 更新 Actor + Critic 和标准 RL 的三处不同： 1. 奖励极度稀疏——整条回复只有末尾一个 RM 分数 2. 奖励是学出来的，会被 hack；靠 KL 惩罚把策略拴在 π_ref 附近 3. 四个模型同时在显存里，Actor 和 Critic 还各带一份优化器状态

示例场景：7B 模型上做 RLHF，Reward Model 由 5 万条偏好对训练得到，PPO 阶段 β（KL 系数）沿用默认 0.02。

问题：训到约 300 步时 RM 打分从 0.6 一路涨到 2.3，看起来很成功；但人工抽检发现回复平均长度从 180 字涨到 620 字，大量"首先/其次/需要注意的是"的空话堆砌——RM 的冗长偏差被 PPO 精准放大了，这就是典型的 Reward Hacking。

方案：三件事一起做：β 从 0.02 提到 0.1 把策略拴紧；在总奖励里加长度惩罚项；把 KL(π_θ‖π_ref) 作为一等监控指标，超过 12 就触发早停回退到上一个 checkpoint。

效果：RM 分数稳定在 1.1 附近不再无限上涨，回复平均长度回落到 240 字，人工胜率从 41% 提到 63%。关键教训是：RM 分数涨得太顺，通常说明它正在被绕过，而不是模型真的变好了。

  • Â 一定在 minibatch 内做标准化，否则奖励量级一变学习率就得重调
  • 用 KL(π_old‖π_θ) 做早停：单轮 K 个 epoch 中一旦超阈值立刻停，比死调 ε 有效得多
  • Critic 和 Actor 的学习率分开设，Critic 通常可以给大一些（值函数是纯回归）
  • 把 熵正则系数、KL、Â 的均值/方差、clip 触发比例全部打到监控里，崩之前它们会先动
  • 不要把 K（复用 epoch 数）调得太大，同一批数据反复拧，clip 也拦不住策略跑偏
  • 不要用 γ 去调偏差-方差——那是 λ 的活，改 γ 等于偷偷改了任务目标
  • 不要只看奖励曲线判断 RLHF 成功，必须同时盯 KL 和输出长度分布
  • 不要忘了 GAE 递推里的 done 掩码，跨 episode 边界继续累加优势会污染整批数据

RLHF 的整体流程

Reinforcement Learning from Human Feedback（RLHF）使用 PPO 将 LLM 与人类偏好对齐，包含三个阶段：

  1. SFT（Supervised Fine-Tuning）：在高质量标注数据上微调预训练模型
  2. Reward Model 训练：用人类偏好数据训练一个打分模型
  3. PPO 强化学习：用 Reward Model 的反馈来优化 SFT 模型

PPO 在 RLHF 中的角色对应

Reward Model 作为 Critic

Reward Model 本质上起到 "环境奖励" 的作用：

  • 输入：prompt + 模型生成的完整回复
  • 输出：一个标量分数（越高表示越符合人类偏好）
  • 这个分数作为 PPO 的奖励信号，指导策略更新

KL 惩罚防止偏离

RLHF 中 PPO 的目标函数包含一个关键的 KL 惩罚项：

Rtotal(x, y) = RRM(x, y) - β · DKL( πθ(·|x) ‖ πref(·|x) )

其中 πref 是 SFT 模型（参考策略），作用：

  • 防止 Reward Hacking：模型可能找到 Reward Model 的漏洞，生成得分高但质量差的回复
  • 保持语言能力：确保模型不会为了高分而丢失基本的语言生成能力
  • 控制偏离程度：β 控制 KL 惩罚的强度，通常需要仔细调节

RLHF + PPO 的挑战

  • 训练不稳定：同时训练 4 个模型（Actor、Critic、Reference、Reward），内存和计算开销大
  • Reward Model 质量：RM 的偏差会被 PPO 放大
  • 超参数敏感：KL 系数 β、clip ε、学习率等需要精细调节
  • 替代方案：DPO（Direct Preference Optimization）绕过 RM 和 PPO，直接从偏好数据优化
  • 三阶段流程：SFT → Reward Model → PPO 对齐
  • KL 惩罚：防止模型偏离参考策略太远（Reward Hacking + 保持语言能力）
  • 四模型系统：Actor + Critic + Reference + Reward Model，训练成本高
  • DPO 替代：跳过 RM 和 PPO，将 RLHF 转化为分类问题，更简单但可能不如 PPO 灵活

九、Value-based vs Policy-based vs Actor-Critic 对比

这张表最后能压缩成一句话：动作能枚举就先考虑 Value-based 吃它的样本效率，枚举不了就上 Actor-Critic，而 PPO 之所以成为默认答案，是因为它在"稳定"和"好实现"上同时不吃亏。

示例场景：一个 7 自由度机械臂抓取任务，动作是连续的关节角度增量，仿真器可以开 64 个并行环境。

问题：先把每个关节离散成 11 档试 DQN，组合动作空间是 11⁷ ≈ 1949 万，输出层根本建不出来；改成只动单关节的简化动作集后能训，但成功率卡在 23% 上不去——离散化把精细控制的能力砍掉了。

方案：换成 PPO，策略头输出每个关节的高斯分布均值与 log 标准差，GAE(λ=0.95)、γ=0.99、ε=0.2、K=10，64 环境 × 512 步一轮。

效果：成功率提到 81%。同时试了 SAC 作为对照，样本效率明显更好（约 1/3 的交互量到同等成功率），但对超参更敏感、调了三轮才稳。规律是：能大规模并行采样时 PPO 更省人力，采样昂贵（如真机）时值得花时间调 SAC。

选择建议

  • 离散动作、需要高采样效率 → Value-based（DQN 系列）
  • 连续动作空间 → Actor-Critic（PPO、SAC）
  • 需要理论保证和稳定性 → PPO（一阶优化、简单稳定）
  • LLM 对齐 → PPO + KL 惩罚（RLHF 标准方案）
  • 三类方法本质区别：学什么 — V/Q 函数 vs 策略 vs 两者都学
  • Actor-Critic 是主流：结合了两者优势，PPO 是当前最广泛使用的算法
  • 动作空间决定选择：离散 → DQN 可以，连续 → 必须 Policy-based 或 Actor-Critic

十、Q&A

Q1：策略梯度定理的核心公式是什么？为什么不需要知道环境模型？

策略梯度定理：∇J(θ) = E[Σt ∇log πθ(at|st) · Gt]。

不需要环境模型是因为在对轨迹概率取 log 并求导时，环境动态 p(s'|s,a) 的部分与参数 θ 无关，求导后自然消失。我们只需对策略 πθ(a|s) 求导，而这完全由我们的神经网络定义。这就是为什么策略梯度是 model-free 方法 — 只需要采样轨迹，不需要知道环境的状态转移函数。

Q2：为什么 Baseline 不会引入偏差？最常用的 Baseline 是什么？

数学证明：Ea~π[∇log π(a|s) · b(s)] = b(s) · ∇Σaπ(a|s) = b(s) · ∇1 = 0。

关键是 b(s) 只依赖状态不依赖动作，可以提到期望外面。而 Σπ(a|s)=1 是归一化条件，对 θ 求导恒为零。因此任何只依赖 s 的基线都不改变梯度期望，只改变方差。

最常用的基线是状态值函数 V(s)，因为它是 Gt 的条件期望 E[Gt|st]，使得 Gt - V(st) 的均值接近零，方差最小化。

Q3：Actor-Critic 中 Actor 和 Critic 分别做什么？为什么要分开？

Actor（策略网络 πθ）：输入状态 s，输出动作概率分布，负责 "选择动作"。

Critic（值网络 Vw）：输入状态 s，输出该状态的价值估计，负责 "评估好坏"。

分开的原因：如果只有 Actor（REINFORCE），需要用蒙特卡洛采样来估计回报，方差很高。Critic 提供了一个低方差的回报估计（通过 TD 学习），作为基线或 Advantage 的一部分来指导 Actor 更新。这样 Actor 决策更稳定，训练效率大幅提升。

实践中 Actor 和 Critic 可以共享底层网络（共享特征提取），只在最后一层分叉。

Q4：GAE 的 λ 参数如何影响偏差和方差？实践中怎么选？

GAE 通过 λ 在 TD（低方差高偏差）和 MC（高方差无偏差）之间平滑插值：

  • λ → 0：Advantage 退化为单步 TD 误差 δt，方差低但高度依赖 V 的准确性（偏差大）
  • λ → 1：Advantage 退化为 MC 估计 Gt - V(st)，无偏但方差高
  • 0 < λ < 1：折中，越大越接近 MC（更低偏差、更高方差）

实践选择：λ = 0.95 是 PPO 的默认值和社区广泛采用的经验值。γ = 0.99, λ = 0.95 是最常见的组合。如果环境奖励信号非常稀疏，可以尝试增大 λ（如 0.97~0.99）；如果 Critic 很准确，可以适当减小 λ。

Q5：TRPO 的 KL 约束是怎么保证策略单调改进的？

基于 Kakade & Langford 的理论结果：新策略的真实性能 J(πnew) 有一个下界，即替代目标 L(πnew) 减去一个与 KL 散度成正比的惩罚项。

TRPO 的逻辑：只要我们在 KL ≤ δ 的约束下最大化替代目标 L，那么下界就一定不低于当前策略的性能 J(πold)。因此每次更新至少不会让性能变差（最坏情况 θ 不变，KL=0，L 不变）。

实际上 TRPO 不是严格的 "单调改进"（那需要精确优化），而是 "不会大幅恶化" — 但这在 RL 中已经是非常有价值的保证。

Q6：PPO 的 clip 机制具体是怎么工作的？为什么要取 min？

PPO 的 clip 目标：LCLIP = E[min(r·Â, clip(r, 1-ε, 1+ε)·Â)]，其中 r = πnew/πold。

当 Â > 0（好动作）时：r 被上限在 1+ε，即使新策略大幅增加了这个动作的概率（r 很大），目标函数也不会因此继续增大。这防止贪婪地过度增大好动作的概率。

当 Â < 0（差动作）时：r 被下限在 1-ε，防止过度减小差动作的概率。

取 min 的原因：构造一个悲观下界（pessimistic bound）。不管策略怎么变，目标函数值总是取两者中较小的那个。这意味着优化器不会得到虚假的 "改进信号"，只有在安全范围内的更新才会真正改善目标。

Q7：PPO-Clip 和 PPO-Penalty 有什么区别？为什么 PPO-Clip 更常用？

PPO-Clip：用 clip(r, 1-ε, 1+ε) 直接截断概率比，隐式限制策略变化。ε 是固定超参数。

PPO-Penalty：将 KL 散度作为惩罚项加到目标中，自适应调节系数 β。如果 KL 太大就增大 β，太小就减小 β。

PPO-Clip 更常用的原因：

  • 更简单：不需要计算 KL 散度，不需要调节 β
  • 更稳定：clip 提供了硬限制，不会因 β 不合适而失效
  • 效果一样好甚至更好：原论文实验表明 clip 版本在大多数任务上表现更优
  • 计算更快：clip 操作比 KL 散度计算便宜
Q8：RLHF 中为什么需要 KL 惩罚？如果不加会怎样？

KL 惩罚 DKL(πθ ‖ πref) 有三个关键作用：

  • 防止 Reward Hacking：Reward Model 不完美，存在分布外的漏洞。没有 KL 约束，模型会学会生成 "得分高但无意义" 的文本（比如重复特定短语获得高分）
  • 保持语言能力：SFT 模型已经具备良好的语言能力，KL 惩罚确保优化过程不会破坏这些能力
  • 正则化效果：类似于权重正则化，防止过拟合到 Reward Model 的偏差上

不加 KL 惩罚的后果：模型会迅速找到 RM 的漏洞，生成 RM 给高分但人类觉得很差的回复（Goodhart's Law — 当指标变成目标时，它就不再是好指标）。实践中这是非常常见的失败模式。

Q9：PPO 和 DPO 的区别是什么？各自的优劣？

PPO（RLHF 中）：SFT → 训练 RM → 用 RM 的奖励信号做 PPO 强化学习。需要 4 个模型（Actor、Critic、Reference、RM）。

DPO：跳过 RM 和 PPO，直接从人类偏好对 (chosen, rejected) 优化策略。将 RL 问题转化为一个简单的对比学习 / 分类损失。

Q10：从 REINFORCE 到 PPO 的演进路线是什么？每一步解决了什么问题？

完整的演进路线和每步解决的核心问题：

  1. REINFORCE：最基础的策略梯度，用蒙特卡洛采样 → 问题：高方差
  2. + Baseline：引入 V(s) 作为基线 → 解决：降低方差，不引入偏差
  3. Actor-Critic：用 Critic 网络估计 V(s) 替代 MC → 解决：进一步降低方差（TD 替代 MC）
  4. A2C/A3C：并行采样 + Advantage → 解决：训练效率（并行环境）
  5. GAE：λ 平衡 TD/MC 的 Advantage 估计 → 解决：灵活的偏差-方差权衡
  6. TRPO：KL 约束限制策略更新 → 解决：更新稳定性（防止策略崩溃）
  7. PPO：clip 替代 KL 约束 → 解决：TRPO 太复杂（一阶优化、简单实用）

这条路线的主线逻辑：降方差 → 提效率 → 保稳定 → 简实现。每一步都是在前一步基础上解决最突出的问题。
